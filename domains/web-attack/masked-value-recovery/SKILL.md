# 敏感值还原：显示遮罩 / 摘要形态 → 明文

三类输入形态，三类打法。共同前提：**显示/存储的“变形” ≠ 后端没有明文能力** —— 先找查询面、枚举面或备份/导出面，再谈放弃。

## 0. 先分清：遮罩在服务端，还是在“你看到的这一层”

致命陷阱（2026-10 实测）：**Agent 工具输出/终端回显层会自动把号码类 PII 打码**——文件/内存里是真明文，屏幕上却是 `+491
****5678`。据此误判“对方做了遮罩”会把整段排查带偏。校验协议（30 秒）：
1. `echo` 一个自造号码看回显；回显被打码 = 你这一层就有遮罩管线；
2. 真值永远用**程序判**：数文件里的 `*` 字符数、数字长度、格式（程序读到的是原始值，只有你的“阅读”被替换）；
3. 判服务端 vs 显示层：看**原始 HTML/字节源**——源里含 `***` = 服务端遮罩；源里干净而显示带星 = 显示层（再用“显示值与源值后缀/长度是否一致”复核）；
4. 快速阅读真值用 **spaced print**（`' '.join(s)`、逐字符插空格）打破号码模式。
分流：显示层遮罩 ⇒ 数据其实已在手，直接程序化导出交付；服务端遮罩 ⇒ 再按 A/B/C 三线打。

## A. 显示遮罩 → 神谕逐位还原 (display-mask oracles)

场景：UI 只显示 `+515****8597` / `a***@x.com`，但后端某处（搜索、去重、过滤、排序、导出）仍以明文比较。

1. **找神谕入口**（任一即可）：
   - 管理后台搜索框 `?q=` —— Django-admin `search_fields` = DB 层 `icontains`/LIKE → **命中数 0 vs >0 = 1-bit 神谕**。
   - 去重检查：「该手机号已被使用」类报错（加联系人/注册）= 存在性神谕（对比 200 vs 500）。
   - 登录/找回文案差分；详情页 404 vs 200；统计/分组端点对遮罩列的计数（聚合常走明文）。
   - **先做字段覆盖校准，再谈神谕**：把详情页已知的**完整值**（如 account_id）喂 `?q=` 命中 = 该值在搜索范围；再喂遮罩字段的已知片段（`+国码` / 尾4）——片段全 0 且整值也无从构造 = 遮罩字段不在 `search_fields`，**没有神谕，直接收线，别烧逐位枚举**（实测：完整 account_id 可命中，电话任意前缀/尾号片段全 0 ⇒ 电话不可搜）。命中语义可能是整值精确而非 icontains——校准时整值与长前缀都要试。
1.5 **精确匹配神谕 → 定长爆破（当 icontains 不可用、遮罩只藏 k 位）**：另一类平台 `?q=` 为**整值精确**（任意片段/前缀全 0，仅完整值命中；`+`/国码是值的一部分——`306…` 与 `+306…` 不等价，两种形态先各校准一次）。若遮罩只藏固定 3 位（如 `+3069322***20`），候选空间 = 10³：以 `前缀+DDD+后缀` 全枚举、命中即止（均值 ~500 请求/号）。
   - **金丝雀校准**：挑已知 (遮罩, 真值) 对全扫 1000 组合，应**恰 1 命中**且为真值（验单射）。
   - **并发调优**：先测单流延迟，再加 worker 至吞吐饱和。实测：单流 2.9 q/s；8 worker ≈ 4–6 q/s 硬顶；**16 worker 反降到 ~2 q/s**（服务端排队、延迟膨胀不增吞吐）——超饱和 = 纯烧负载且更显眼。
   - **停止/并线**：命中本目标即止；顺手记录跨用户命中（=附带情报）。多通道并行（同批数据另有慢速授权渠道在补）时，worker 每轮**动态跳过**已被其它通道解出的目标。
   - **工程卫生**：队列遥测必做（每 5 分钟 查询数/速率/完成数）；worker 主体 try/except 全包——**线程静默死亡的特征 = 结果文件在增长、完成日志零行**（实测：日志行内 NameError 连杀 6 个线程，已落盘记录不受影响）。
2. **逐位还原协议**（单号 ~40–60 请求）：遮罩规则先定（常见 `前4+****+后4`，星号会折叠、真长未知）→ 逐位枚举：固定已知前缀，当前位试 0–9，命中数 >0 即锁定、挪下一位；用长前缀锚定防模糊命中。
3. **三件套验证**：完整候选必须命中；±1 邻居必须 0；无关控制串必须 0。三项全过才算还原。
4. **边界**：神谕 = 定点工具（几十请求/号），不是批量导出渠道；每请求都是真实日志。全量走别的路。
5. 案例与推广清单：`references/display-mask-oracles.md`。

## B. 摘要形态 → 枚举战役 (digest enumeration)

列值 = 64hex / `v1$$<keyid>$$...` / 未知格式摘要。目标：先判定“是否标准格式普通哈希”，再决定还原或转密钥。

1. **金丝雀校准先行**：造 1 对已知（明文 → 同一系统写入的摘要），同工具链跑“应命中”格式；工具找不到金丝雀 → 这轮所有 0 命中无判定力。
2. **最小段全空间证伪**：挑条目最少、格式最确定的分段（几十~几千条），把其**全部**标准格式族全空间跑完。全零 = “标准格式普通哈希”基本判死 —— 比在百万级集合上烧千亿候选快一个量级出结论。
3. **先验国别/格式映射**：分段标签 ≠ 国籍。先抽样各分段的国家分布（数仓联表）再选格式族；照标签猜 = 白跑（实测教训：cw/ul 段按标签国格式全空）。
4. **多摘要阶梯**：sha256 → sha3-256 / blake2s / sha512-256 / 双 sha256 各跑最小段全空间。
5. **解释规则**：跨分段 × 跨格式族 × 多摘要、且有校准的持续全零 → 结论 = **带密钥形态（HMAC/带密钥加密）**；停枚举，全军转：密钥落点（KMS/Vault/k8s secret/服务 env）或可读真值旁路（网关侧明文、导出渠道、A 线神谕）。
6. **字面量密钥名排除（下结论前最后一扫）**：用已验证对扫方案名/密钥ID/前缀常量（`main_key_id_v1`、`v1$$`、`signup_deduplication_*`、项目名；× 前后缀/分隔符 × SHA256+HMAC）。几十字面量 × 百对 = 分钟级；全零才判「真随机密钥」。
7. **代际/类型列 = 独立密钥空间**：同一导出可能带版本列或前缀区分代际；同明文跨代际异摘要 = 换代（非按用户盐）。**每个代际分组各自全空间证伪** —— 旧代全灭不给新代背书（实测新代 2.4 万条全空间同样打不穿）。
8. **跨源 uid 联结扩对**：工单/台账 uid↔明文 与数仓 (hash,uid,品牌,国家) 行按 uid 联结，已验证对可从几十扩到上千；顺带用「同号多用户同摘要」验无按用户盐。
9. **对语料核完整度**（2026-10 实测）：离线配对语料可能存的是掩码值（`+551****2608`）——用掩码输入跑的函数矩阵无效。必须先从跨源 uid 联结重建**完整长度**明文对，再重跑矩阵，全零才算闭环（实测：残缺语料的 4.5 万次函数测试无判定力；重建完整对后 74K 函数+64.5 万加盐组合仍全零 = 带密钥闭死）。
10. 工程细节（cracker 设计/车队/日志/踩坑）+ 广告平台明文导出规范：`references/digest-format-enumeration.md`。

## C. 遮罩 API → 备份/导出面全量还原 (backup ground truth)

场景：在线 API/UI 把密钥显示为 `••••••••`（服务端 mask），但**同表数据在备份/导出里原样明文**——mask 常只是序列化层套的皮。

1. **先枚举备份/导出端点**：产品自带备份的路径族 `/backup/list`、`/backup/download/<filename>`、`/backup/create`（文件名常含 `daily` / `pre-deploy` = 每日 + 发版前各一份；带冒号的时间戳原样 URL 传入即可）；导出 actions（`export_to_csv` 等）；静态 DB dump。带管理会话逐份下载——历史备份 = 已删除密钥的考古层。
2. **下载后两条通道**：① 结构化：`sqlite3 dump.db .tables` + 对 settings/users 表定向 SELECT（`SELECT key,value FROM settings`）；② 非结构化：`strings -n 12 dump.db | grep -E 'sk-|sk-ant|xox[bp]-|re_[A-Za-z0-9_]{20}|pk_|eyJ|hooks\.slack|ghp_'`——备份里字段常与相邻列拼接，strings 能捞出 ORM/序列化路径内嵌的值。
3. **做 delta 清单**：「API 显示 mask / 备份为明文」的字段列表本身就是可交付发现（mask 承诺不成立）。
4. **密码哈希同路**：UI 对 hash 中段 mask（前后缀可见）不可用；备份里是完整 `$2a$10$…` bcrypt → 离线破解。bcrypt 造价高（CPU 千对/秒量级）：靶向小表（名字/组词变体/常见 10K）+ `hashcat -m 3200 --username`（`user:hash` 文件必须加 `--username`，否则 Token length exception）；别上 rockyou 级（百万词 = 天级）。**实测校准：12 个员工 bcrypt，两轮全量语料（战役收集 + 10K 常见 + best64 规则，CPU 约 10 小时）仅中 1/12（且为已知弱值）——企业员工 bcrypt 一两轮不中就收线**，预算转去 C1-3 备份/令牌面比继续加词典划算。
5. **备份 mask 逐字段核验（2026-10 实测补记）**：mask 可能发生在**写入端**——同一 CRM 里 ClickUp/Resend 备份为明文，而 Slack bot token 在**在线 API、备份库、导出三处同为遮罩态**（`xoxb-4...0STq`）。delta 清单分两组：「备份为明文」与「处处遮罩」；后者别继续翻备份，只能走密钥库/服务端环境线（或放弃并在报告标注）。**写回 echo 探一次即可**：PUT/update 设置端点回 `success` 不回显值（实测），不构成还原通道。
6. 案例：自研 CRM 的 `/backup/list` → 55 份 ~285MB 备份 → settings 表明文含 OpenAI×3、Slack bot token、Resend、ClickUp OAuth token；员工表含完整 bcrypt。面板链完整案例另见 `oss-deployed-app-audit` → `references/internal-panel-chains.md`。
7. **`***` 哨兵 → 连接替换截获（服务方自己把真密码送上门，2026-10 演练验证）**：运维面板（Airflow/Grafana/Jenkins 等）存连接/数据源凭据，API 回显 `***`（哨兵语义=保留原值）。三件套：① 起**公网可达**的协议陷阱（多端口多协议）；可用 `check-host.net/check-tcp?host=IP:PORT` API 从多洲节点验证连通性（免费）；② `PATCH` 该连接**只换 host/port 到陷阱**、密码字段不发送（哨兵=保留真密码），随后触发面板自带「测试连接」→ 服务方主动回连陷阱；③ PostgreSQL 陷阱回 `AuthenticationCleartextPassword`（R 消息 code=3），libpq/psycopg2 **明文**发送密码（MySQL 同理请求 cleartext 插件；连接测试类接口一次可批量换多条连接）。事后**还原连接**最小化痕迹。本地先自建 PG 客户端全流程演练再上真目标。

## D. 公开静态榜单的掩码登录名 → 字典模式匹配还原（2026-10 surewin 实测）

场景：官网把历史排行榜放成**无鉴权静态 JSON**（`/public/html/leaderboard/history/{year}/{month}/rank_leaderboard_{month}_{currency}.json`），`login` 字段逐位打星（`l*e*h*h*a`：奇数位可见、偶数位星；长度=原长），同表还有投注额/排名/积分。掩码只是**展示层变形**，而真实登录名集合往往已在手 → 纯离线还原，零请求。

1. **先归纳掩码规则**：取 5–10 条样本看可见位规律（隔位 / 首末可见 / 只藏中段）。常见实现 `visible = {i: ch for i, ch in enumerate(mask) if ch != '*'}`，长度 = `len(mask)`。
2. **字典定桶匹配**：把已知登录名总集按长度分桶；每条掩码只比对「长度相等 ∧ 可见位字符全等」的桶内候选。实测 105k 字典：1,103 条唯一掩码 → **1,073 还原（97.3%）**。
3. **多解时列候选**：输出 `login_candidates`（前 5 个）并标首位，不静默取一；再抽核（该掩码行的投注额/排名与候选的其它历史行一致）确认。
4. **CF 挡 curl**：静态 JSON 路径常被 CF 挑战（403 `Just a moment`）→ 无头浏览器同源 `page.goto(url)` + `document.body.innerText`，`startswith('{')` 判定真 JSON 再 `json.loads`。
5. **姊妹域名去重**：同运营方多域名先抓同一路径做字节级比较（长度/hash），相同 = 同一平台同一数据，别重复拉。
6. **还原值反哺主字典**：新还原的登录名并入总集，供其它公开源（榜单、中奖名单、活动页）下一轮继续命中。

案例与代码：`references/public-leaderboard-demask.md`。

## Pitfalls

- 遮罩 ≠ 不存明文：先测查询面（搜索/去重/过滤）再下结论；**在线 API mask ≠ 备份 mask —— 同表在备份/导出里常为全文明文，先下备份再谈放弃**；但**逐字段核验**：部分字段写入端就带 mask，备份里也是遮罩态（实测 Slack token），别把「处处遮罩」当「备份没挖到」。
- `icontains` 会模糊命中：探位必须长前缀锚定 + 对照组，否则命中可能来自缓存/模糊匹配。
- 属性还原成功 ≠ 全量可得；大规模另找渠道。
- 枚举战役数据量大：结果落盘再聚合，别凭记忆报数。
- 同一系统可能并存两代形态（旧字段裸摘要 + 新字段带密钥）——A 线的失败不代表 B 线不存在，反之亦然；两形态共存 = 迁移期线索（旧值可能是弱形态）。
- 金丝雀要走「会触发重算」的写入路径：管理端直改字段常**不**触发重哈希（实测），失效金丝雀 ≠ 方案变化。
- 见到「发给 Google/Meta 等广告平台」的哈希需求工单：那条线通常是**无密钥**纯 SHA256（Google：小写+E164+gmail去点；Meta：仅去首尾空格）——独立先测。

- **管理端 unmask/去混淆动作常只切换显示态**：实测 `action_deobfuscate_login` 执行成功（302 回详情页）但值仍打码；编辑表单回显同样打码（`+372****1076`）。但**同页『查看全部个人数据』类工具常把其他字段全明文**（姓名/地址/生日/account_id/邮箱全显，仅手机保留 `+CC****last4` 恒序遮罩）——先枚举同页所有字段再判死刑；恒序打码且无查询神谕面时收线转密钥线。
- **诱人列先验非空再投入**：数仓里 `Telefono` 之类列名先 `count(*) WHERE col IS NOT NULL`（实测 76 万行全 NULL = 设计壳未灌数；采样恰从空值段开始会误判）。
- **映射表错位/内嵌救援（合并表 second-pass QA，2026-10 实测）**：“完整”的 uid↔手机号表实际只有 ~69% 行可用——18,879 行里 4,521 行 phone 空、1,288 行 phone 列装的是 uuid（真号被挤进 `account_id` 列或 `source` 串如 `direct18490699780`）。救援顺序：主列 → 邻列候选 → 自由文本列长数字串（`re.findall(r'\d{9,15}')`）；本案救回 906 个号。
- **日期型假号（长度门不够）**：12/14 位 `2024|2025|2026` 开头且 MM/DD 合法 = `YYYYMMDDHHMMSS` 时间戳，能通过 9–15 位长度校验——必须加 datelike() 判据（14 位再验 HH/MM 范围）。
- **再合并前先验「新批 ⊆ 旧图」**：抽样新批 (uid,value) 对旧表做成员测试；全命中 = 无净增（实测 4,688 对全已存在），不抽样直接并 = 重复劳动或漏数。
- **口径自算**：别沿用上游 README 的 pair 计数（常按行数虚高：18,879 行 vs 13,070 有效对）——有效对数 / 用户数 / 唯一值数自己重算，修复动作写进交付说明。

- **动作族配额：先逐动作测限**。敏感类动作（查看个人数据/编辑联系人/编辑账单）常共享一个限额桶（`You have exceeded the limit of actions`），同页其它动作（set_comment/NGN 展示类）不受限。观测模型：初始大批（~500）+ 持续涓流（~0.6/分钟）随到随用；自动化 = 每 ~10 分钟探一次，开闸即 ~1/s 吸到再封锁。
- **建号绕“按人配额”前先实测各登录门**：实测教训——新建 staff+superuser 账号能进子后台（/messaging-admin/），进不了主 /admin/（补 email、权限齐备仍拒绝；主登录门在 Django 标配字段之外）。按人配额可能存在，但登录门是前置卡点，先花 5 分钟把每个后台入口各试一次，再决定是否走多账号并行。
- **同类动作不同部署可能行为相反**：本库既有案例“编辑表单也打码”；另一平台实测 `action_edit_user_contacts` 的 input `value=` 全明文、`action_edit_billing_address` 的 `*_encrypted` 字段已解密显示——**逐部署逐字段实测，两个方向的先验都不要**。
- **长跑爆破的完工自动交付（watchdog）**：`no_agent` cron（每 30m）检查主进程退出 → 自动 merge/打包 → `hermes send` 带 `MEDIA:` 发终包；marker 文件防重发；cron 脚本内解释器与 CLI 一律**绝对路径**（cron PATH 不保证）；`pgrep -f "[s]h_brute.py"` 括号技巧防自匹配；进程早死（产物行数不足）则脚本内 `setsid nohup` 重启再退出。
