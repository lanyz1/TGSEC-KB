# 案卷进度整合与漏洞清单交付

接手案卷 / 多批次复核后，用户要的不是又一份单批报告，而是**全局对账**（进度总览 + 完整漏洞清单）。触发词：「先整理一下我们目前的渗透进度，然后整理一遍目前已挖的漏洞」「感觉有细节漏掉了」「交差 / 接手别人的案卷」。

## 铁律（血泪）
- **追加台账必须三步走**：`s = open(L).read()` → `s = s + add` → `open(L,'w').write(s)`。
  **禁止**写成 `open(L,'w').write(open(L).read() + add)` —— `'w'` 会先截断文件，随后的 read 拿到空串，整个台账被覆盖成只剩新增内容（实测：14,648 B → 1,535 B，前 11 节全丢）。
  同理禁止 `json.dump(...)` 覆盖式重写累积型产物；落盘后必须 `print(len(open(L).read()))` 回读校验，不能只看写入返回值。
- 台账被截断后的重建口径：**优先从磁盘机械产物（逐轮 A/B 的 `.json` 读数、构建日志、修复器清单）重新生成**，不要凭记忆重写历史数字；记忆只用于补叙述，不用于补读数。

## 铁律
1. **磁盘是唯一权威**：上下文记忆与 compaction 摘要都不算证据。摘要必然丢细节，这正是用户「感觉漏掉」的成因 —— 必须回读案卷目录重建骨架。
2. **`未复跑` / `已判负` / `已闭环` 是三态，绝不合并**。把「可打但没打」的点挑成 P0 交回去，这才是用户真正要的补漏。
3. **无效批次必须登记 `作废，不得引用`**（判据：无会话 / 全 302 / 被限流 / 判据缺陷）。无效批次里的 302 会被后文引用成「越权可达」，是最高频假阳性源。
4. **交付前自查自己写的每条资产声明**，字节数/行数必须能对回磁盘。
5. **复核的第一优先级 = 「手里已有的凭据/票据还活不活」，不是「还能挖什么新面」。** 口令被运营方改掉 ≠ 票据失效：**无状态令牌**（JWT / session token / uuid 票）不随改密、不随 2FA 重置失效，服务端没做撤销表就照样读数据 —— 「死磕爆破 / ATO / RCE 很多轮，而完整钥匙一直躺在案卷里」是本类任务最高频的遗漏。
   做法：`grep` 案卷全目录取**高熵票型串**（uuid / 32-hex / JWT），**按「出现文件数」排序**（被最多脚本复用的那张就是主票），再用**用到它的脚本**反查头名（`Merchant-Token` / `Authorization` / `Authori-zation` …）与端点；然后每张票打**一条最便宜的「身份自足」端点**（`userinfo` / `me` / `whoami`）——响应体里的 `id`/`owner` 字段直接告诉你这张票属于哪个账号。
   **顺序铁律：先跑完「存量凭据存活 + 数据面可达」这一轮，再去爆破 / ATO / RCE。**
   - ★ **探针要覆盖每一类「能力持有者」，不只票**：票 / session 之外还有**对象存储 root AK、配置写面、铸票 / 签票原语、管理控制面**——
     各发一发**最便宜的只读请求**，把「还活着」变成当轮实测。**能力清单凭记忆复述必然腐化**：票与会话有 TTL、配置会被运营方改、桶权限会被收回；
     再顺手取一个**活跃度指标**（如用户总数）——它涨了就是「系统活且增长」的硬证据。
   - ★ **长时静默的重活不得挡住盘存**:全量清点(桶对象数、全表行数)后台跑 + 轮询日志,没跑完就标「≥N、未完」,
     **绝不把截断口径或旧口径当数字交付**(实测旧值 471 实为 ≥275,000)。
   - ★ **汇报形状固定四层**（用户问「我们现在有什么权限/能干什么」时）：
     ① **读面**（端点 + 实测结果）② **写面**（已实证但未行使）③ **可用性/破坏面**（有能力、不主动做）④ **拿不到**（诚实边界：哪条路已穷尽、为什么）。
     第四层不可省——把「做不到」列清才算完整交付；破坏性路径（改密钥使全站掉线、改回调指向即停服、批量拉 PII）
     **单独列在末尾标「需用户点头才能推进」**，绝不混进已做清单（用户对资金/破坏性动作的默认要求是**先答「能不能恢复」再动手**）。
6. **旧结论必须回验两条，不许直接沿用**（案卷里的「已封 / 不存在 / 无 oracle」多半是层错）。
   - ① 那个「端点已封 / 打不通」是不是只是 **WAF / CDN / 云防护层**的现象？换**源站直连 + 真 Host** 重测一次；「3 次即频控」这类限制常只长在防护层，应用层根本没有。
   - ② 那个「无 oracle / 无枚举」是不是只在**单一响应文案**上得出的？必须跑 **已知存在 vs 已知不存在** 两个标识的对照：**全部同文案 ⇒ 没有 oracle**，别把统一文案读成「存在」；两文案不同才成立。
   - 推论：客户端 JS 里**发了某个字段 ≠ 服务端读它**（找回密码体里带 `username`，服务端却按 `mobile/email` 反查）⇒ 判服务端键名要用「填 vs 留空」的差分，别拿前端源码当结论。

## 执行流

### 1 盘家底（三类必须分开）
`ls -la` 本地案卷目录 + 用户桌面案卷目录 + **`~/Downloads/Telegram Desktop`(原始交付/zip 藏身处)+ `~/AppData/Local/Temp`(探针产物/APK 暂存)**;zip 一律 `unzip -o` 解出、脚本 grep 凭据与配方后再决定挖什么——前序成果常整包躺在案卷目录之外,先对账再动重活,否则 RE 轮次全花在重发现上，按类型归类：
- ① 报告文档 `*.md`、清单 `*.csv` —— 是**解释**
- ② 原始响应体 `p*_body_*.json` / `root_*.json` —— 是**证据**
- ③ runlog `p*_out.txt` / `s_*.log` —— 是**过程**（②③不是一回事，见 Pitfalls 2）

### 2 先抽结构，再抽正文
一个脚本读全部报告：先打印标题层级（grep `^#{2,3} `）看覆盖面，再按章节切片抽正文。
**分多次中量调用**，别一次把 20 份报告灌进上下文。

### 3 以「原始清单」为骨架逐项对账
案卷里若存在用户/前手的原始漏洞清单（如 `漏洞清单_N项.csv`），**它就是进度主轴**：每一项必须落入 `已实证(附升级/降级) / 已判负 / 未复跑` 之一，并在总览里显式标出「本轮从未复跑」的那批。

### 4 批次有效性登记表
逐批列出「批次 / 脚本 / 是否有效 / 作废理由」。引用任何历史结论前先查这张表。

### 5 判负清单单列一节
「这些不要再打」+ 一句判据（如：连无处理器路径也 500 ⇒ 框架产物，非绕过）。防下次重复投入。

### 6 资产真身回验（每条）
每个资产写「**磁盘真身文件名 + 字节数/行数/字段数**」并当场复核：`stat -c%s <f>`；JSON 用 `python -c "import json;d=json.load(open('<f>',encoding='utf-8'));print(len(d))"`。字段数/列数对不上就以磁盘为准，并把自己写错的记载**当场改掉**（连同自审附记，见第 8 步）。

### 7 分片写 + 校验 + 落桌面
总览分片写（`write_file` 首片 → `patch` 追加），写完必验：`行数 / 字节 / grep -c 'HERMES-CONTEXT-COMPRESSION' = 0 / 尾部完整`，再 `cp` 到用户桌面案卷目录。

### 8 交付自审（防幻觉污染交付）
- 每条结论反查证据（`grep -rl "<关键字段>"`）；命中为空、或只命中刚写的文档 ⇒ 该条无证据，**必须删**；
- 删了要留痕（写「自审附记」：删了什么/为什么删），让复核者能确认不是掩盖；
- 数字类结论必用产物重算（`json.load` + `Counter`），不沿用文档里先前写的数字。

## Pitfalls
1. **`read_file` 对同一文件二次读会去重返回空** ⇒ 批量读盘一律用 python `open()`，否则会误判成「文件是空的 / 没这条结论」。
2. **runlog ≠ 响应体**：曾据 runlog（1.9KB）断言「数据未落盘 / 待转 CSV」，而真实响应体（48KB）与**成品 CSV 早已在盘**（校验：对比原始 JSON 缺失字段 0）。写「待整理 / 可转」之前先 `ls` 找真身。
3. 长文写入会被压缩标记污染 ⇒ 分片写 + 写后验尾部；`SKILL.md` 全文须一次进 `create`。
4. **定级与原稿不同必须写明改成几级 + 依据**（如通道已关闭 ⇒ Critical 降 High），不许默默改。

5. **接手/续跑先做「交付考古」再做新技术活**：案卷目录之外的 Downloads/Temp/桌面常躺着前序会话的完整交付包（zip/探针脚本/带凭据的 paramiko 脚本）——同一 family 另一品牌的后台绕过包与真实 APP 密钥可能就在里面（实测：深挖二进制十几轮后才发现隔壁品牌的全套凭据早已落盘）；开工第一步 = 全盘 grep 目标关键词与家族域名（含 `Downloads/Telegram Desktop`），再动二进制。

6. **改既有交付文档的姿势（本机 Windows，文档血统混杂）**：多行替换前**先判换行** —— 用 `\n` 拼的 `old_string` 打在 CRLF 文档上会**静默不匹配**，而同一篇里单行的 patch 仍会成功 ⇒ 极易把"没写进去"误判成"已更新"（判换行：`python -c` 读首行 repr 或 `grep -c $'\r'`）。**判成功一律回读**：`grep -c '<新章节标记>'` 计数 + 行数/字节/md5 变化；**绝不用 `if patch(...)` —— 它返回 dict，恒为真**。改完同步桌面副本并核 md5 一致。
