# 无 bundle 时的服务端源码取证（PHP / ThinkPHP 系）

拿不到前端包、或包只给了「路径 + 方法名」而服务端要的**字段名/参数序/签名算法**仍在服务端时，
不要退化成猜。框架的 **include 机制**与**异常渲染**本身就是源码读取通道。全套在无 shell 下完成。

## 何时用

- API 由服务端框架直接渲染（TP/Laravel/CRMEB 派系），SPA 只有一半信息（甚至只给路由）。
- 需要**字段名/构造体/签名输入序**的硬证据：猜字段名 = 假结论来源（见主铁律 1–2）。
- 目标开了 debug/trace 页、有丰富报错页、或存在任意 include 之一。
- 与 `debug-page-oracle-recon` 互补：那边讲「错误页当预言机」，本文讲「错误页/包含机制当**源码读取器**」。

## 通道 1：语言包加载器 = 任意本地 include

```
Lang::get($msg, [], $request->lang)   # 第 3 参 = range
  -> switchLangSet($range)
  -> include $range                    # 任意本地包含
```

- **载体三级都要试**：query 的 `lang` 常被 URL `detect()` 过滤器剥；**body 的 `lang=`** 能到第三参；
  **cookie `think_lang`** 是第三条且**最干净**（不抛错，能把一个任意 `.php` 返回的数组装进 range 域）。
- **基址与深度（TP6 实测）**：range 基址 = `vendor/topthink/framework/src/lang/`，
  向上 **5 级**（`../../../../../<path>`）= **应用根**；**`.php` 自动补**，写 `../../../../../app/common` 即可命中 `app/common.php`。
- ★ **深度校准是硬要求，不是可选步骤。** include 一个**不存在**的路径**不会报错**，返回空数组 ——
  所以「干净加载」**不能**作为「路径正确」的证据（真实教训：一整轮把假路径当真，白烧数小时）。
  校准法：指向一个**已知已被加载**的类文件，逼出 `Cannot declare ... already in use` —— 报错即深度正确。
- **静默性**：include 成功也不吐内容；值只在**异常消息恰好等于数组键**时外带。
  点目录 `connections.*` 这类点号查找理论可读嵌套 config，但前提是存在**请求派生**的异常消息；
  固定中文文案永远不命中 config 键 ⇒ 先找「消息可控」的抛错点，再投入。
- `open_basedir` 把可读集合钉在 webroot + `/tmp`。

## 通道 2：源码窗口（两个原语，窗口形状不同）

1. **重声明致命错** —— include 一个类/函数**已被加载**的文件：
   `Cannot declare class A\B` / `Cannot redeclare fn()`，随后打印该文件**头部约 19 行**（到声明处）。
   适合抽**文件的 `use` 导入**与文件级 helper。
2. **类型混淆错误窗** —— 只有**目标方法内部**的调用抛错，才会吐那个方法的源码。
   做法：把数组喂给期待字符串的调用（`base64_decode(array)`、`trim(array)`、`md5(array)`）。
   错误落在**那一行**，HTML 页打印其周围 **~±9 行**。换「哪个参数喂给哪个调用」即可**滑动窗口**、
   逐段拼出方法体 —— 控制器、签名 helper、验证器规则数组都是这样拿到的。

按行号拼接窗；中间一段（如 564–610）只有找到**能执行到那一行**的分支才会补上。

★ **`Accept: text/html` 是硬前提**：JSON 分支只给 trace 骨架（`data.file` / `data.line` / frames），
**不带源码行**；HTML 分支才渲染带代码片段的 ~20KB 页。不带这个头就会误判「这个报错没泄漏源码」。

## 通道 3：trace 页当仪表盘

| Tab | 价值 |
|---|---|
| 基本 | **已加载文件清单 + 大小** = 应用类结构的免费清单（按入口分别 dump 再 diff） |
| 文件 | 抛错行的源码窗 |
| 流程 | `data.file` + `data.line` 逐帧 —— 行号预言机的来源 |
| SQL | 每条语句 + 绑定值 + `CONNECT:` DSN |
| 调试 | `$_SERVER` / cookie / env |

- **让干净路由也吐 trace**：正常返回业务数据的路由上，用一个**深 `lang=` 或类型混淆参数**制造 PHP warning，
  框架就会画 trace/SQL 面板 ⇒ 拿到那些「从不出错」的路由的 SQL 与加载文件表。
- **SQL 面板三读法**：
  ① **列名**来自应用自己的 `SELECT`（面板只给语句、不给结果集）—— 登录语句就能吐出整张账号表的列；
  ② **`CONNECT:`/DSN 要逐查询读**，不要只读一次：一个应用常同时连**多个库**（账号库 + 主库）；
  第二个库往往才是要紧的；
  ③ 登录链里的**配置表键值查询**（如 `SELECT [CfgValue] FROM T_GameConfig(nolock) WHERE [CfgType]='1302'`）
  = 白送**配置表名 + 真实配置键号**，随后去找「把 CfgType 当参数」的路由。
- **参数化批量判定（比时序/布尔盲测便宜一个量级）**：对未授权面**每个路由每个参数**发一个 `'`，
  与基线 SQL 文本 diff。回显 `'zz\''`（转义）= 该 sink 判死；回显裸引号 = 立即命中。
  一次请求一个判定，可一次批量收掉整个路由清单。

## 常踩的墙

- **兄弟主机可能是纯 catch-all**：所有路径回同一句桩文案（如 `server is running...` + trace 页）。
  判路由真伪要**与 catch-all 的 body diff**，不能看状态码（都是 200）。
- 开发实例的应用（`projectName: "dev"` 类）接口全都「通」但数据全空 —— 别在空库上继续搭链。
- 多应用 TP 常见两套 DB（管理库 / 游戏主库），且**同一控制器族各连各的**：见 ②。
- 报错页里出现的「函数名/类名」是**调用点上下文**，不等于被执行过 —— 别当执行证据写报告。
