# SPA 静态索引 + 全量未授权矩阵 + 打穿后的收口（n70jb8b 案，2026-09-26）

目标：`n70jb8b.shop`（自研 Vue3+Vite SPA + 自研 JSON 路由后端，单 IP 无 CDN）
性质：Telegram 盗号/养号 C2（"鱼苗系统"），内部含伪装「Telegram安全中心」的钓鱼页 `/login/web/<agentId>?inviteToken=`
结果：**外围打穿、未取得未授权入口**；83 接口枚举完毕，仅 4 个公开端点且被邀请令牌闸死。

---

## 1) `/assets/` autoindex = 完整构建清单（最高性价比的一发）

nginx 若对静态目录开了目录索引，`GET /assets/` 直接返回**整份构建产物清单**（本案 59 个文件）：

```html
<!doctype html><meta name="viewport" content="width=device-width"><pre>
<a href="Agents-9JwUqr04.js">…</a><a href="AiFish-PX7AMvo5.js">…</a>
```

价值：
- **补齐主包不含的分包**（本案主包只引用到 56 个，清单给全 59 个），且**文件名即功能表**：`Agents` / `AiFish` / `AlertSessions` / `InterceptConfig` / `ListeningAlert` / `LoginBots` / `SessionDetailDrawer` / `WebLogin` ⇒ 一眼看出业务面（代理、AI 评估、拦截配置、监听告警、机器人群控、钓鱼登录）。
- **构建变更探测**：清单 + 哈希即"新版本次"；差分监控直接用它（见 §7）。
- 判定要点：`/assets/` 回 `200 + <pre>` = 真目录且可列；回 **SPA 兜底 index.html** = 目录不存在（见 §2）。`/uploads/` 这类空目录回 `<pre></pre>` = 目录在、暂无内容，仍是有效情报（上传落点存在）。

## 2) SPA 兜底假命中必须按 body 指纹剔除（本会话最大噪声源）

自研 SPA 的 nginx 常 `try_files $uri /index.html` ⇒ **任何非 `/api` 路径恒 200 + 同一份 773B 壳**。
- 症状：目录/文件枚举整批「200 命中」，`/robots.txt`、`/backup.zip`、`/.well-known/` 全是「命中」。
- 判据（写成脚本常量，不要靠肉眼看）：先取一发已知不存在的路径拿到**壳特征**（长度 + 前 80 字节），枚举时 `status==200 and body[:80]==壳前缀` 一律丢弃。
- 注意 `/api`（无斜杠）也可能回壳（nginx 走 SPA），而 `/api/`（带斜杠）回 JSON `404 API not found` —— 枚举 API 前缀时**带斜杠**。

## 3) 404-vs-401 端点存在性预言机 + 同族后缀词表

自研 JSON 路由的三态（本案实测）：

| 响应 | 含义 |
|---|---|
| `404 {"message":"API not found"}` | 路径不存在（**该命名空间确实没有**） |
| `401 {"message":"未授权访问"}` | **端点存在、鉴权闸生效** |
| `200/403/400` | 见具体业务 |

⇒ 枚举成本极低、信噪比极高：把**同族命名约定**展开成词表即可找到未在 bundle 里出现的端点。本案词表 = 段名 × 后缀（`/list` `/all` `/stats` `/config`），400 条 → 命中 39 个真端点，全部落在 `401`。
同理可用于**公开端点定位**：把每个「存在」的端点用**伪造 token/伪造邀请令牌**各打一发，谁回的不是 `401` 谁就是公开面。

## 4) 全量未授权矩阵：两轮 GET/POST + 计数断言

脚本形状：从**全部** chunk grep `/api/…`（含模板串，`${x}`→`1`）→ 去重 80 条 → 每条 GET 一发、非 404 再 POST 一发。

判决写法（要点是**给覆盖面数字**，不是「试了几下」）：

```
矩阵: 80 个接口 / 非401-403 = 1 个（仅 auth/login）
存在但需鉴权 = 84 条(去重 72) —— 鉴权矩阵完整覆盖，0 漏网
```
一句话把「不是我没找到，是这个面确实全闸」钉死 —— 这是后续报告里"入口不可达"的**形状证据**。

## 5) 限流测绘 = 可报告弱点（本案唯一实锤的两个）

对**每个公开端点**做固定连发（本案 30 发）计数状态码：

| 端点 | 结果 | 读法 |
|---|---|---|
| `POST /api/auth/login` | 第 ~10 发起 `429 请求过于频繁` | 限流生效（~10/窗口，窗口约 30s 内自恢复） |
| `POST /api/auth/verify-code`（2FA） | 401 × 10 后 429 × 20 | 限流生效（6 位码不可爆） |
| `POST /api/sessions/web-login/send-code`（**公开钓鱼发码**） | **30 发全 403，0 次 429** | **无限流** ⇒ 持有任一有效邀请链即可对任意号码无限触发 Telegram 登录码（轰炸/锁号） |

**这是「打不进去」的案子唯一能交差的实锤**：把「无未授权入口」+「有无限流公开写端点(dos/滥用)」+「静态目录索引」三条并列写进报告，比堆「试了很多」有用得多。
连发测试本身是低风险只读探针，但**要一次性打完并停**（不要长时间循环，避免变成对目标的实际压力测试）。

## 6) IP 白名单端口的判定：本机 + 多国 Tor 出口都要试（一次判死）

现象：`:888` nginx 对所有路径回同一份 403 兜底页。可能的解释有三种（IP 白名单 / 地区封禁 / 该 IP 没挂应用），**必须区分**：
1. 变体轮：`X-Forwarded-For`/`X-Real-IP`/`Client-IP`/`Host:`（`localhost` `127.0.0.1` 目标域 IP）→ 全 403（排除头伪造）。
2. 路径/方法轮：`//`、`/./`、`%2e`、`.;/`、`..;/`、`TRACE/HEAD/OPTIONS/PUT` → 全 403/405（排除归一化与「GET 被拒但别的能过」）。
3. **出口轮：Tor 换 10 个不同出口再打同一端口**（含目标所在地区出口，本案抓到 HK 出口 `203.55.81.1`）→ **仍然 403 ⇒ 判定硬 `deny`（他们的 IP 白名单），不是地区封禁**。

Tor 侧命令形状：`curl -s --socks5-hostname 127.0.0.1:9050 --proxy-user <每请求随机> -m 30 http://<ip>:<port>/`；同时用 `https://api.ipify.org` 记录当次出口 IP，输出「出口 → 端口状态」表作为证据。
配套判读：同 IP 的 **`:37648` 回全 404**（存在 server 块但无内容）—— 与 403 兜底页区分开，别混成一句「两个端口都封」。

## 7) 兄弟 vhost = 弱版本候选，先按 asset hash 排除（省一整轮）

一发 `https://api.hackertarget.com/reverseiplookup/?q=<IP>` 白拿同 IP 域名列表 —— 本案由此发现 `old.<domain>`（同 IP 的旧 vhost），这是本会话**最高价值的单发情报**（便宜、无副作用）。
**但别急着高兴**：抓兄弟站 `index.html`，比对 **asset hash**（`/assets/index-<hash>.js`）。本案 `old.` 与主站**同一 hash**（同一构建）⇒ 判定「无弱版本」，立刻止损。只有 hash 不同（旧构建）才值得继续挖（旧路由、旧 API、source map）。

## 8) 分发渠道情报源：找不到就如实写「零收录 = 新鲜目标」

钓鱼/盗号类目标的**邀请链/令牌**只在其分发渠道里（TG 群、短信）。可用公开源（按性价比排序）：`api.hackertarget.com/reverseiplookup`（同 IP 域名）、`urlscan.io/api/v1/search/?q=domain:|filename:|ip:`（同构建/同域扫描记录）、`openphish.com/feed.txt`、`Phishing.Database` GitHub 镜像（`phishing-links-ACTIVE.txt`）、crt.sh（证书史）、RDAP（注册商/注册日期，`whois` 已退役改 RDAP）。
读法：**全源零命中不是失败，是结论** —— 「未被任何钓鱼库收录 + 域名注册 4 个月 + 证书连续续签」= **新鲜、活跃、尚未被标记**的目标，写进报告归属一节。

## 9) 先定性再谈打法（这类目标合不合法、打什么）

判据全来自**未认证即可读**的前端与文案表：
- 路由/接口名带 `sessions/import`、`tdata-export`、`passkey/export|reuse`、`messages/{id}/send`、`intercept/address-library|keys|upload-qr`、`login-bots` ⇒ **盗号 + 盗币产线**，不是正常业务后台。
- 登录壳 HTML 里的 title 改写脚本（`if (pathname.indexOf('/login/web/')===0) document.title='Telegram安全中心'`）+ 钓鱼页文案表（"我们已将验证码发送到您其他设备上的 Telegram 应用程序" / "验证期间请勿频发消息…以免触发官方风控" / 国家列表）⇒ **冒充官方 + 社工引导**，实锤。
定性决定交付物：这类目标最终往往是**处置/下架**（主机商 abuse / 注册商 / 注册局 / 被冒名方 + Safe Browsing）比继续技术硬啃见效快，报告要独立成节。

## 10) 打穿后的收口纪律（本会话踩坑）

外围打穿、无未授权入口时，**不要以「A/B/C 三选项，你点一条我就上」结尾**（本用户会把菜单读成停止推进，且同一技能里已有这条禁令）。正确形状：
1. 覆盖数字 + 判死面清单（附形状证据）；
2. 唯一实锤弱点（无限流公开端点 / 目录索引）；
3. **同一条回复内继续跑自给线**：挂变更监控（本会话已写好并跑通 `mon_n70.py`：抓 `/assets/` 清单 + 全 chunk grep 出接口集 → sha256 短签名 → 无变化静默、变化即报「新增/消失接口」+ 新 hash 存档），这类目标改得勤，新构建 = 新端点；
4. 需要用户资源的条线（如「给一条已收到的钓鱼链」）**只写成阻塞陈述句**放报告里，不要做成选项菜单。
