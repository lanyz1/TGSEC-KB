# 外部平台 API 面：头路由网关、gin schema 预言机、sign 判死

适用：白标/SaaS 产品，**自家 SPA 的调用点挖完之后**，真正值钱的写接口在**上游平台 API**上（代理商↔平台↔白标多租户）。
本文补 SKILL.md §5 的对称面：那边讲「从调用点拿契约」，这边讲「**调用点根本不在客户端时怎么定位与判死**」。

---

## 1. 自定义头路由网关：路径枚举全废

**症状**：SPA 的 `baseURL="/"`（所有 API 打自身 origin），但同一路径在别处行为不同；路径字典扫平台主机全是 `404 page not found`。

**真相**：网关按**自定义头**选后端。实测包里出现固定头 `key:"p"`，值即「平台」通道 → 平台 API 主机与商户主机是**同一批路径、不同后端**。

**定位法（顺序执行，别跳）**
1. grep 该头常量在包里的**赋值点**与**取值表**（`"p"` / `"m"` / `"a"` 这类单字值常对应 平台/商户/管理）。
2. 在**全部**前端产物里抽主机名候选：正则 `[a-z0-9-]+\.aig[0-9]+\.com` 式（换成目标的根域），得到 `api.` `gate.` `merchant.` `system.` 一组。
3. 若还有**公开的对象存储桶 / CDN 备份**（见 `tg-miniapp-wallet-pentest` §9.6 同级打法），桶里的**历史版本包**会带出**当前包已删掉的主机名与凭据** —— 实测 prod 桶备份名「新增 agent002 之前」直接提示了后续白名单 agent。
4. 对同一 IP **用 `Host:` 头逐个对撞**（`curl -H 'Host: api.x.com' https://<ip>/...`）。同 IP 多 vhost 是常态。

**判读**：某个 vhost 回**结构化的框架错误**（gin 的 `404 page not found` 纯文本、或 JSON 错误体）= 真应用；回**统一长度的 HTML 403** = nginx 兜底（见 §4）。

## 2. Go gin 逐字段 schema 预言机

gin `ShouldBindJSON` 绑定失败时会把**结构体类型名 + 第一个缺失字段 + 校验标签**直接吐进响应：

```
*model.MemberLoginReq | timestamp | is required
```

⇒ 等价于 PHP debug 模式的 `Undefined array key "<name>"`：**循环补字段、看报错点前移**，一个脚本把输入契约枚举干净。

- 拿到类型名后**先解出字段全集**再发请求，别逐字段瞎试。
- 报错点前移 = 上一个字段已通过；报错停在同一点 = 该字段**值**不合法（不是名字错）。
- 与「猜错路径」区分：gin 的路径不存在是纯文本 `404 page not found`，**不是**这个 schema 文案。

## 3. 白名单 oracle：枚举合法租户/agent（0 成本正信号）

多租户平台常有 `agent_id` 这类租户字段 + 一个前置白名单闸。逐个喷**已知租户名**：

| 结果 | 含义 |
|---|---|
| `408003 not-whitelisted`（同形拒绝） | 该 agent 不在白名单 |
| 穿过白名单、推进到下一道闸（实测 `600100 invalid sign`） | **该 agent 是白名单成员** |

实测 `agent002` 穿过，`agent001 / anony / jwl77 / ufaprod / admin` 全被拒 ⇒ 白名单成员枚举完成。
下次遇到同类闸，先做这个 oracle，再决定往哪个 agent 上投弹药。

## 4. sign 判死：公式在、调用点零

**最贵的坑**：包里 grep 到 `sign` 公式 `MD5(path+"&"+排序参数)`，看起来无盐、像是可复算 → 花整整几轮爆常量。

**正确判据 = 调用点，不是公式**
- 主包 + 全部懒加载分包 + 商户分包（实测 239+12 个）全量 grep 该函数名。
- **定义在、调用点零** ⇒ sign 由**代理商/网关服务端**计算，密钥不在客户端。
- 判死条件三条写全：`定义在 / 调用点零 / 公式输入含服务端下发或未公开 secret`。

**结论口径**：「真钱写路径关闭（客户端不可复现合法 sign）」写进攻击面矩阵的**判死行**，别只写「sign 难算」。

---

## 5. 同 IP vhost 齐平 403 = 兜底，不是「后台存在但被拒」

逐个 vhost（`h5.` / `admin.` / `www.`）对同一 IP 打过去，全部回**同一长度、同一文案**的 403（实测 162B nginx 兜底页）⇒ 该 IP 上**没挂**这些应用。

- 别写成「后台存在但被拒绝访问」——这是把兜底读成闸门。
- 真应用对照特征：自己的 404 / Swagger UI / JSON 错误体 / 框架签名头。
- 顺带一把打全 `/debug/pprof/`、`/debug/pprof/heap`、`/metrics`、`/swagger/index.html`：全 404 = 该部署没挂。**但注意** gin/echo 等自定义 engine 通常**不含** net/http 默认 mux 的 pprof ⇒ 404 不等于「不是 Go」。

---

## 6. 报告落点

- 平台 API 面的**正面发现**（活接口、schema、白名单成员）与**判死面**（sign、vhost 兜底、pprof）都要进同一张攻击面矩阵，判死行注明**判据**（定义在/调用点零、齐平响应长度、410 耗时差分等）。
- 本例归档：`/root/cases/tmqb/REPORT-tmqb-v2.22-mqtt.md`（V-16 平台 API 面 + 攻击面矩阵判死行）。
