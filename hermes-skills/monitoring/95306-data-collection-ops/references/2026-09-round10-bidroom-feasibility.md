# 2026-09 round10: 竞价室实时监控可行性(bidRoom/initProjInfo)

日期:2026-09-05。用户需求:**指定项目(非批量)竞价过程中监控出价/当前价/成交**。可行性查证结论与定点方案。

## 1. 通道与权限墙(实测结论)

- 竞价室入口:`/business-proxy/business/bidRoom/initProjInfo?projId=<pid>`(GET,头 Authorization=bfwz ST,Referer bfwz-view)
- **权限校验:只对该项目的报名企业且审核通过的 ST 放行**。非报名企业票调用 → 500 业务错"您没有该功能的操作权限"(该错误串含"请联系技术支持"→ 曾误触发风控冷却,已从 _COOL_MSG 排除)
- 出价执行在独立域 `bid.95306.cn/api/execute-server/`(与 cg.95306.cn/business-proxy 分开);出价 JWT(bid JWT)过期快(8/24 一批全死,竞价当日企业重新签发)
- 成交结果:竞价结束后从公开结果公告拉(通道已有,无需竞价室)

## 2. 现存代码缺陷(为什么从未成功)

collector_v9.py `try_fetch_bids()`(L648):
- 触发:targets 里 bidStarttime-5min ≤ now 的项目;频率 30min 一次(state bid_fetch_ts 1800s)
- **缺陷:用手里任意一张 ST(any_st)碰运气调 initProjInfo** → 几乎永远不是该项目报名企业 → 全 500 → v9.3 加 bid_skip 1h 跳过
- 实证:8/27 修复后至 9/5,8 台采集机 `/tmp/targets/*/bid_live.json` **零成功样本**,日志零行"💰 出价数据已抓"
- 成功路径写 targets/<pid>/bid_live.json(rsync 回主服),不推送 bot

**结论:不是平台不给看,是票没用对(没做"票↔项目"配对)。**

## 3. 定点监控最小方案(用户指定项目,待 9/9-9/10 实弹验证)

```
① 票↔项目配对:审计抓到企业票时已知其 buyed(报名项目清单)→ 建"项目→报名企业票池(含审核状态)"
② bot 项目详情"🔴 盯竞价" → /opt/v6/bidwatch.json 名单
③ 竞价窗口(开始前5min~结束):从该项目的票池取审核通过活跃票 → initProjInfo,20-60s 轮询(单项目,风控安全)
④ 解析返回(当前价/报价轮次/剩余时间/状态)→ 变化推 bot
⑤ 结束后:结果公告对账成交价/成交人
```

- 票源保障:竞价日报名企业必登录出价 → 审计必抓新票(TTL>2h);我们手里有该项目 16/25、12/18 家票池
- 风险点:审核"通过"判定(报名期抓的审核状态可能未定稿;竞价开始时审核已定)→ 配对时以最新 pack_map 审核状态为准
- 实弹窗口:沈阳铁道97次 9/7 09:30(2家报名,小白鼠)/ 北京局13次 9/9 19:00 / 漯阜A(报废机车批)9/10 10:00

## 4. 通用教训

- **权限墙接口(500 业务错)先验证"身份是否配对"再怀疑接口**:any_st 批量试=100% 失败且烧掉跳过集;目标明确的少量配对调用才有意义
- 系统里"尽力而为"的探针模块长期零成功时,查它用的身份/参数是否满足接口前置条件,而不是调频或加大重试
