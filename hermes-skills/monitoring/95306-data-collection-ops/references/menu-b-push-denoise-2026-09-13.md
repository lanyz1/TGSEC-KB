# 菜单B推送降噪(2026-09-13,已上线 pix_bot_server.py mb_monitor_loop)

## 语义(定稿)

- **净变化 ≥2 才推**;±1 抖动静音。基线 = 上次【已推】状态(静默轮不推进基线)→ 282↔283 反复横跳自然归零,永不触发
- **保存守卫**:仅 `chg or not old` 时写 `mb_monitor.json`(基线=上次已推;首次 or 无文件时初始化写)
- **明细不丢**:静音期"审核变化项目"明细累积到 `pend`(≤8 条),下次推送合并带出(前 4 条 + "等N个项目"),推后清空
- 旧 v9.7 明细块以 `if False and prev_detail:` 禁用保留(不删,便于回查)
- 调参锚点:`mb_monitor_loop` 内三处 `_d(...) >= 2` 阈值 + `got` 类守卫同款模式
- 静音轮日志:`仅±1级抖动已静音,不推送(待发明细N条)` → 用于确认降噪在干活

## 部署 / 重启约定(本 bot)

- **重启静默**:版本号未变时启动不推公告(`_skip` 机制)→ 改代码后重启即可,无需清 CHANGELOG、无需 bump
- kill 用括号技巧防自匹配:`pkill -f '[p]ix_bot_server'`;kill / start **分两次 exec**;启动后 `pgrep -f '[p]ix_bot_server' | wc -l` 防多实例(python + 父壳=2 为正常,数 python)
- **后台启动假超时(大坑)**:`setsid nohup ... &` 之后 paramiko/ssh 读流会 TimeoutError——**命令其实已成功,严禁盲目重试**(会多实例);一律 pgrep + 日志验证
- 换血流程:备份 `.bak913` → sftp 上传新文件 → `mv` 换血 → `py_compile` → 重启 → 验证 alive + 用户操作日志正常

## 改动验证法(先仿真后部署)

把改动逻辑抽成小仿真脚本本地跑通再部署:抖动 +1→静音 / 净 +2→推 / 多轮累积→推到阈值 三场景断言。

## 效果基线

日均 ~65 条 → ±1 抖动全灭,真实变化攒批推;静默期明细不丢。

## 用户可见症状:推送明细与表格"相位相反"(2026-09-21 取证)

症状族:推送"新增2个拒绝"但表格当时是通过 / 下一次推送"拒绝没了"而表格里通过又变成拒绝 / 再推一次又是"新增2个拒绝"而表格没有任何变化 —— **每 ~3 分钟(监控轮询)在两个版本间翻一次**。

两条独立成因,别混为一谈:

1. **明细(pend)是逐轮内存 diff,不是推送时刻的快照**:`mb_monitor_loop` 每轮拿 `detail` 与上一轮 `prev_detail` 比,把翻转写进 `pend`,在下一次真推送时才带出 ⇒ 发出去时明细里那对 (x→y) 可能早已翻回,与"看表格那一刻"必然可能相反。**判读铁律:推送明细描述过去某轮的值,表格描述当前值;两者不一致 ≠ 计数错。**
2. **聚合基线 = 上次【已推】状态(设计如此)**:`if chg or not old: json.dump(mb_monitor.json)` 只在推送时推进基线;若池内值本身在两版本间交替,则每次推送都相对"上次已推"反着报 ⇒ 呈现无限翻烧饼。**修法方向 = 消掉池内的两版本交替(单一事实源),不是改阈值。**

## 读数链路与排除项(先看这条省一轮)

- `check_status_summary(pid)` 只读 `get_proj_dir(pid)` = `/data_pool/<pid>`(**硬编码单路径**,无多副本切换 / 无 shard 解析)⇒ "文件稳定但读数在变"时,定因只能落在写入方,别在路径解析上绕。
- 池 vs 机器副本会**结构性分叉**:merger 是保底累积式,池会保留机器副本里根本不存在的终态("通过"可能只在池里有)。机器副本 = `/data_raw/<机名>/<pid>_pack_map.json`(平铺,`<pid>_` 前缀);**其 mtime 常是数日前 —— 内容未变不重写,不能用 mtime 判"数据陈旧"**。
- 同企业两套键并存:池用**账号键**,机器副本用**单位名键**;`merge_ents_by_unit` 按单位合并去重(同 packId 保首条)⇒ 翻转实体通常是"某账号的某两个 packCode"。

## 捕翻器(定死"另一个版本"的产源)

- **窗口必须 ≥15 分钟**:4 分钟窗会给出"文件根本没翻"的假阴性(翻转是间歇/周期性触发,不是每轮必翻)。
- 采样 6–10s;**只在 `(mtime,size,md5)` 变化时打一行**,并把当前内容 `cp` 成版本快照(留最近 10 份)。
- 事后对相邻两版做**字段级 diff**(重点 `审核状态/审核码/审核时间`),拿"通过版本"的**精确时间戳**反查同刻写入方(merger cycle / audit_changed / 8515 回写)⇒ 定罪唯一写入方。
- 现成脚本:`scripts/menuB_flip_catcher.py`(改 `PID` 即可;输出 `/tmp/flip_log.txt` + `/tmp/flipv_N.json`)。
