# 报名总表导出对账：三口径不符 / 联系方式缺号

客户说「平台显示 59、采集 58、表格 60，数对不上」时，先认口径再动代码 —— 这三个数字是三种
不同口径，能互相验算出来，通常一行数据都没丢。

## 一、三个数字各是什么（先认口径）

| 口径 | 取处 |
|---|---|
| **平台 N** | `/data_pool/plat_enroll_map.json` → `projs[projCode]`：`企业数` + `企业[]`（全称列表）。权威基底。 |
| **采集 N** | 该项目池目录 `pack_map.json` → `enterprises` 的**键数**。 |
| **表格 N** | 导出行按企业去重后的家数 = `✅已采` + `⏳待补` + `🔹平台外` 三类并集。 |

**验算闭环（三式全通 ⇒ 只是口径不同，不是丢数据）：**

```
平台 = 已采命中平台的家数 + 待补家数
池内 = 已采命中平台的家数 + 平台外家数
表格 = 已采 + 待补 + 平台外
```

行数交叉验证：每家企业按包件数出行（同项目常见 **10 行/家**，待补家只有 1 行）⇒
`Σ行数 = 已采家数×10 + 待补家数×1 + 平台外家数×10`。用行数能反推家数，快速自证。

- 表格比平台名单**多出来的那 1 家**通常是 `🔹平台外` 行（池里有报名记录、平台名单里没这家企业）。
- 表格里的 `⏳待补` 家 = 平台名单有、池里还没采到包件 ⇒ 属补漏腿的任务，不是导出错。

## 二、字段/维度陷阱（算差集前先核字段名）

`pack_map.json.enterprises[<账号>]` 单条的字段：

- `账号` = 登录账号（**这才 = enterprises 的键**）
- `用户` = 注册人姓名或企业简称（**不是企业全称**）
- `单位` = 企业全称（做企业级差集必须用这个）
- `包件` = 包件列表 · `ST` = 状态 · `_obs` = 观测时间戳 · `来源` · `报名时间_平台` · `时间`

规矩：**先打印一条样例的字段名和值，再决定用哪个字段做键**。拿 `用户` 去和平台企业名单做差集
会得到「池内 58 全部不在平台、平台 59 全部不在池内」这种全错位结果，白跑一轮。

其他两条：

- 池内 `单位` 可能是简称（如「帆辰」）而平台是全称 ⇒ 导出侧 `norm_ent_name` 会把它并成全称。
  对账前跑同款归一，否则会得出「平台缺 1 家 / 池内多 1 家」的**假差集**。
- 池目录名 ≠ `项目信息.json` 的 `projId` 是常态（也有恰好相同的时候）⇒ 定位项目目录要扫
  `*/项目信息.json` 的 `projCode`，不要拿目录名当主键。

## 三、联系方式从哪来（缺号诊断）

- 源 = `pool_dir/企业档案/<名>.json` 与 `pool_dir/供应商/<名>.json`；`_find_one` 按
  「文件名（lower）包含关键字」匹配，kw = 归一后的**企业全称**。
- **`pool_dir` 是全局池根 `/data_pool`，不是该项目目录**。项目目录里只有
  `pack_map.json` / `包件清单.json` / `项目信息.json` / `企业包件表_18列_*.csv` 等，**没有**
  `企业档案/`、`供应商/`。先在项目目录 `ls` 一次确认，别顺着错路径下"源里没有"的结论。
- 合并语义：`sup_profile` 只在源字段为**真值**时覆盖（`null` / `""` 都不覆盖）⇒ 空串不覆盖是
  正确设计，不是取数 bug。
- **`企业包件表_18列_*.csv` 不含联系方式列**，别指望它补号。

缺号两类根因（**先分类，再回答"能不能补"**）：

| 类 | 表现 | 判定 | 能否补 |
|---|---|---|---|
| A 源里没这家企业 | 联系人/法人/手机号三项全缺 | `企业档案` 与 `供应商` 两侧都无同名文件 | 只能引新源（平台企业信息接口），现有链路长不出来 |

**A 类的最强判据（2026-10-08 实证，一步定性、免再查链路）**：直接打开该项目目录里的
`企业包件表_18列_<projCode>.csv` —— 那是**平台原始返回的落表**，它**根本没有联系方式列**
（同批行的「统一信用代码」也普遍空）⇒ 平台对这些企业的报名数据里本就不含联系人 ⇒ 归因
「源侧缺」结案，**不要再去改匹配键/正则**（改也长不出来，属假修复）。
再叠一层：对缺号企业按**账号**与**全称**在两个档案目录各做一次探测（本轮 369,416 条档案池
里两条路都 0 命中）⇒ 双侧零命中 = A 类坐实。
⚠️ 缺号常呈**批量分布**（本轮同一份导出 582 行里 40 行三字段全空，且集中在小数几家企业、
每家按包件重复多行）⇒ 报数时说清「涉及 N 家企业 / M 行」，别只报行数或家数之一。
| B 源里有档案但字段为空 | 常见"仅缺手机号"，联系人/法人已取到 | `企业档案` 那份三项 `null`，`供应商` 那份手机号 = `""` | 源侧就没有，改代码无解 |

探针要点：对每家缺号企业在两目录各做一次文件名探测，并**打印命中记录的字段原值**，把
`null` 与 `""` 区分开 —— 两者对「能不能补」的结论不同。

## 四、归因与省时手法

- 拿 `/data_pool/汇总/报名总表_<projCode>.csv`（历史同名导出）与客户手上那份逐项对比：
  一致 ⇒ 是既有状态，**不是新版回归**，可以立刻排除"新代码写坏了"。
- `/data_pool/*/pack_map.json` 是**每池目录一份**（上万份）⇒ 只读目标 pid 那一份；
  `glob('*')` 会把上万条路径打进输出，刷爆上下文。
- 未授权/未确证的免凭据面不要碰：对账全过程只读 `/data_pool` + 本地 CSV，零平台请求。

## 五、呈现（用户要的口径）

- 数字要**一眼自洽**：给「平台 59 · 已采 57 · 待补 2 · 平台外 1」这种分解，别只甩一个总数。
- 明确点出"表格比平台多的那 1 家 = `🔹平台外` 的哪家"，和"待补 2 家是谁"。
- 缺号要**逐家给根因**（A 类：源里无此企业；B 类：源里手机号为空串），并说明是数据源缺口
  还是取数 bug。
- 改呈现（表头/卡片标口径、过滤 `🔹平台外`）与改数据是两回事，改呈现在发布前仍需用户点头。

## 六、可直接跑的对账脚本

`scripts/regcsv_recon.py` 两模式：

```
python regcsv_recon.py csv  "<导出的报名总表.csv>"        # 本地：行数/分档/去重企业/缺号名单
python regcsv_recon.py pool <projCode> [--pid <目录名>]   # 主控：三口径对账 + 差集 + 缺号探测
```

## 七、`🔸平台名单未含` 的定性判据 + 名录会误删真成员（2026-10-08 实证）

客户说「怎么导出还是写着平台名单未含」时，**先判真伪再动码**，三步足够：

**① 钉时间线（不改码就能解释一半现象）**：比 `报名总表_<projCode>.csv` 的 mtime 与
`plat_enroll_map.json` 的写盘 mtime。本轮实测导出 **20:21:30.68** / 名录写盘 **20:21:34.48**
⇒ 导出读的是**上一版**名录，同一个成员可以「导出里 ✅已采、名录里已没了」——不是匹配 bug。

**② ★`findList` 的日期过滤字段是「公告日」，不是报名时刻**（这是最容易踩的坑）：

```
单日 2026-09-16 → 命中 OT002026091515039252 的 152 行（公告日=2026-09-16，报名时刻=09-25）
同一项目按「报名时刻 ±1 天」开窗 → 0 行  ⇒ 假「确无」！
```

按报名时刻开窗复核 = 会把**真在册**成员判成「平台确无」⇒ 据此删成员 = 误删。
判据/复核一律用 **`公告日单日`** 窗（首页约 300-600 行，1-2 页）：
`params=[{startDate: 公告日, endDate: 公告日}]`。

**③ 判「真未含」**：在该项目**公告日单日**窗里数「含关键字」的行 —— 0 行 ⇒ 该主体确实
不在平台供应商名录（它只是出现在平台包件明细里，如个人/自填主体）⇒ 标注**语义正确**，
别去改匹配逻辑；有行 ⇒ 是我方名录丢了它 ⇒ 是真 bug。

**名录误删机制（v15 及以前）**：`sync_plat_enroll.py` 的「连续 2 轮接受减少」分支只**记账**、
不核验——链路抖动连续两轮（同一成员被同一路径连丢两次）就把成员**删掉**，随后该窗口内
任何导出都把真在册企业标成「平台名单未含」。本轮实例：`宝鸡市众旺物资回收有限公司`
（04:21:34 那轮被删；平台 30 天全量双轮 22 页/10553 行**两次都返回它**，公告日单日窗也命中
⇒ 纯抖动）。

**修法（v16）**：删成员前**定点复核**（公告日单日窗）：仍在 ⇒ 判抖动、并集保留 + 复位计数 +
6h 备忘；确无 ⇒ 才删并落 `plat_dropped.json` 台账；**窗口无数据 / 没见到该项目 ⇒ 无法核、
保守保留不删**。离线夹具三态 + 窗口语义用例 4/4 PASS（`test_v16_pin.py`）。

**量化「一共丢了多少家」**：双轮 30 天全量扫（各 22 页）取并集，与现网 map 逐项目 diff
（`plat_repair.py`，dry-run 零写入 / `--apply` 只增不减 + 备份）。本轮全域 605 项目、
双轮各 10422 行完全一致 ⇒ **只缺 1 个项目 1 个成员**（众旺），其余项目与平台一致。

**回退**：`cp -a /opt/v6/sync_plat_enroll.py.bak_<日期> /opt/v6/sync_plat_enroll.py`
（改该脚本 = 下一轮 10 分钟即生效 = 发布，故落盘前必须备份 + md5 核对「落盘物 == 沙箱被测物」）。
