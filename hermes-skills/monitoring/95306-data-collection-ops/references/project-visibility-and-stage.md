# 项目可见性 / 分组归属排查（用户问「某某项目为什么没有他 / 不在某组」时读本卡）

## 数据分层：判「平台没给」vs「我们丢了」的唯一办法

| 层 | 位置 | 性质 |
|---|---|---|
| 项目原始文件 | `/data_pool/<pid>/{项目信息.json, bid_status.json, 包件清单.json, 公告全文.json}` | 采集落盘原文，最接近平台 |
| 主控索引 | `/data_pool/index.json` → bot 的 `info` | **派生层**：merger 周期写，字段名/格式/家数都在这一步被加工 |
| bot 渲染 | `bot/menus.py::groups()` / `cat_items()` | 只读索引 |

**铁律：索引字段空 ≠ 平台没给。** 先把项目目录原始文件的同名字段打出来，再谈定因。缺 `公告全文.json` ⇒ 报名截止结构性不可得（见下）。

## stage 判据链（`master/merge.py::derive_stage`，自上而下先命中先返回）

1. `sell` = 报名截止（`_fmt_ts` 格式化后）；为空则 `_parse_reg_end(pid)` 从 `公告全文.json` 抠
2. `sell` 非空且 now ≤ sell ⇒ **报名中**
3. ★**`sell` 为空 且 status==open(19) ⇒ 报名中（直接 return，后面全不看）**—— 短路点
4. status==14（终态）⇒ 已结束
5. 包件结束时间 `max_end` ⇒ 已结束 / 竞价中 / **待竞价**
6. 竞价开始时间 `bt` ⇒ 待竞价 / 竞价中
7. 都没有 ⇒ 历史

⇒ 症状：**实际报名已截止、竞价未开始，却停在「报名中」**；🟡 组只剩平台自己翻过状态的那几个。

## 时间字段格式坑（`_fmt_ts` 与全部同族解析器）

`_fmt_ts`（`master/merge.py`）**原只认**纯数字 ≥14 位（补秒/毫秒）或 **8 位**，其余**一律返回空串**；已在源码树放宽（见末节「修法」）。**线上是否已生效，一律读现场树的原文核对当次发布，不要假定。**

**同字段多字形（实测值域 —— 平台各处写法不统一）**：

| 载体 | 写法 | 备注 |
|---|---|---|
| 项目级 `项目信息.json` | `YYYY-MM-DD HH:MM`（**12 位，无秒**） | 老 `_fmt_ts` 打空 ⇒ 索引全空 |
| 包件清单 | `YYYYMMDD HH:MM:SS`（14 位） | 正常 |
| 公告正文 | `2026年09月06日 16时00分`（中文年月日 + 时分） | **不是** dashed / compact |
| 索引与展示（期望口径） | `YYYY-MM-DD HH:MM:SS`（dashed-19） | 放宽输入，**输出口径不变** |

- **只认单一字形 = 静默空值**：解析不中时返回空串/`None`，下游一律当「平台没给时间」⇒ 排序退化成随机、阶段判据整条不命中、`max()/min()` 全失效。**放宽输入是安全动作（只多认、不少认）；绝不顺手改输出格式** —— 那会把下游的 dashed 解析器集体打瞎。
- **改前先建「生产者 × 消费者」清单**：全树 grep `strptime|mktime|fromtimestamp|_fmt_ts|_deadline_dt|deadline_dt`，逐点记录「谁产出什么字形 / 谁消费什么字形」。同族解析器（实测 ≥6 处：`merge._fmt_ts`、`merge._parse_reg_end`、`menus._deadline_dt`、`pool.deadline_dt`、`writer._ts`、`derive._time_bucket`）**一次改齐** —— 只改一个函数会留下同样会静默丢时间的第二处。
- **别据调用点行为反推产出格式**：断言「谁产出什么字形」必须读该函数的 `return` 原文。实测据此误判过一次（把 dashed-19 的产出当成紧凑格式，又据此断言两处不兼容），两次当场撤回。
- **抠取类正则必须用真实样本定形**：`_parse_reg_end` 原本按想象写 dashed / compact 两条正则，拿池内 223 份真实公告回测 ⇒ **0 命中**（真实写法全是中文年月日）⇒ 该功能自上线**从未生效**。**任何新写/改写的提取正则，先抽样 ≥100 条真实值回测命中率**再落码。
- **覆盖率也是判据**：`公告全文.json` 全池 223/53,941（**0.4%**）⇒ 即便正则正确，也只替 0.4% 的项目解出报名截止。诊断「字段为什么全空」要同时报**解析成功率**与**输入文件覆盖率**；要补抓时按「阶段 ∈ {报名中, 待竞价} 且缺该文件」定范围（实测该集合 424 项里 325 项缺）。
- 一行诊断：对原始值 `re.sub(r"\D", "", v)` 数位数；**12 位即命中本坑**。

## `groups()` 四组判据（`bot/menus.py`）

候选集 = stage ∈ {报名中, 待竞价, 竞价中}：

- **报名中**：`rd = _deadline_dt(info.regEndtime or info.sellEnddate)`
  - `rd` 存在且 `rd < now` ⇒ **🟡 报名结束未竞价**
  - 否则 `enterpriseCount > 0` ⇒ **🟢 报名进行中**；再否则按平台家数 ⇒ 🟢 / **🔵 未开始报名**
- **待竞价 / 竞价中** ⇒ 🟡（⇒ 🟡 里的内容只能来自平台自己翻状态；时间推导那条路一空就永远空）
- **✅ 采集完成** = 🟡 ∩ (`src=='平台' and plat and 家数>=plat`)
- **竞价观察窗**（另一格）用 `bidStarttime` + live 过滤（`if not bs or not live: continue`）⇒ 索引时间字段空 ⇒ 该项目在这格**直接消失**。
- 四组都是「候选集上的过滤」，**没有硬 cap**；「看不到」的成因是**归错组 + 排序键空**，不是分页截断（历史上的 `collect_complete_projects(limit=30)` 截断类已废）。

## 排查三步（只读探针；脚本 `scripts/probe_project_visibility.py`）

1. **池里有吗**：关键词/项目名子串扫 `all_projects()`（或该树自带的搜索方法），命中即贴 pid + 项目级字段。
2. **落哪组、第几位**：**逐字复刻 `groups()` 判据**（别调渲染层），打印各组规模 + 目标在组内位次 + 该组排序键非空计数 ⇒ 位次 + 空排序键共同解释「肉眼翻不到」。
3. **字段真值对比**：索引 `info` vs `项目目录/项目信息.json` + `bid_status.json` 同名字段 ⇒ 分出「平台没给 / 合并丢了 / 格式丢了」。

## 探针铁律（本类任务踩过）

- **先拿被调模块的方法表再写探针**：`search_files pattern='^    def '` 列函数清单（复杂正则会被 rg 拒，尤其以尾部 `\(` 结尾的模式），或照抄既有探针（`tools/_probe_hist.py` 之类）。**不要猜 API 形状**——一次「`all_projects()` 当模块函数调」白跑一轮。
- `Pool` 是**类**：`from collector.conf import Conf` + `from bot.pool import Pool` → `p = Pool(Conf(os.path.join(T, "conf", "master.ini")))`；`p.all_projects()` 返 `{pid: info}`；`p._bj_now()` 返 **datetime**（不是字符串）；`_deadline_dt` 从 `bot.menus` import。
- **大语料上的「全 0 / 全空」先怀疑键名与调用式**：一次「处置/废旧/车轴/上海局 全 0」实为读错字段，换正确 API 后同一关键词立刻命中。任何汇总结论先用**一条已知存在的样本**自证键名。
- 探针一律只读：不写盘、不发消息、不联网；远端跑法 `T=/opt/v6/lib/<rel>; cd $T && PYTHONPATH=$T python3 -u /tmp/v6mplan/<probe>.py > out 2>&1`，**落文件再读**，别直连 `| tail`（管道会吞已打印内容）。

## 修法（形态已定，源码树已落码；**发布/激活仍是生产闸，须用户点头**）

1. **放宽输入、锁死输出**：各时间解析器加一条「抽数字按长度试 compact」兜底（14/12/8 位 ⇒ `%Y%m%d%H%M%S` / `%Y%m%d%H%M` / `%Y%m%d`），保留 dashed 分支并补 `%Y/%m/%d`；输出仍是 dashed-19。索引 stage 每轮全量重算 ⇒ **存量条目由下一轮合并周期自动回填，不要手工改数据**。
2. **兜底不得盖过强证据**：`sell` 缺失时的「平台状态 = 发布 ⇒ 报名中」必须加附加条件 —— 竞价已开始（`bt` 已过）或包件竞价已结束（`_max_end` 已过）就**不许**判报名中，交给时间规则定 竞价中 / 待竞价 / 已结束。**兜底只在「无任何时间证据」时生效**，否则它短路整条下游判据链。
3. **从源头补输入**：采集端补抓 `公告全文.json`（报名截止的唯一来源）；写点在 `collector/targets.py` 的公告保存分支（只在「拿得到 noticeId 且正文非空」时写）⇒ 放宽抓取条件前先核该分支。
4. **分组侧强制下界**：`groups()` 里报名截止缺失但**竞价已开始** ⇒ 该项目报名必然已截止（逻辑必然，非猜测），直接归 🟡，不要留在 🟢。
5. **列表排序显式化 + 空键沉底**：`sorted(key=lambda x: (值 or "~", 次级键))` —— `"~"`(0x7E) 排在所有数字之后 ⇒ 空键沉底，次级键取 `projCode` 保稳定；组内行补显该组真正关心的时间（报名/待竞价组显「竞价开始」）。**列表组无排序 = 顺序随字典序漂移 = 目标项永远翻不到**。
6. **验收**：改前后**对同一快照复算 `groups()`** 各组规模 + 目标项目位次，逐项对照；只报总数不算验收（数字变化可能是「变准」，须点明）。落码后走常规链：离线回归闸 → 现役树真数据探针（staged 树同跑）→ 打包 → **报批** → activate。
