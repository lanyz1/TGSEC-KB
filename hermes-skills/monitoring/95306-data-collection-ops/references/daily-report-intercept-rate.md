# 每日拦截战报·两条拦截率(用户问「拦截率 / 拦截度 / 昨天拦截率」时的战报口径)

姊妹篇:`intercept-coverage-measurement.md`(覆盖率/缺漏口径)。本篇专讲每日 20:00「每日拦截战报」里的**两条拦截率**。

## 口径(即 `pix_bot_server._intercept_stats()`,战报实现本体)

- 📈 **报名期即时拦截率 = c1/a1**:G1 组 = 报名中且未到报名截止;a = 平台权威名单企业数(plat_enroll_map),c = 已采(交集)
- 📈 **竞价前拦截率 = c2/a2**:G2 组 = 报名中已截止 + 待竞价 + 竞价中
- 参照:终局(竞价前)≈83–85%(15% 双盲结构缺口);报名期即时数天然更低、随收敛上升
- 战报另含:漏采清单(昨日→今日净收敛)、漏采分层(≤4h 自愈 / >4h 待票)、今日已结束、orch 补采、采集机健康

## 战报只推送不落盘(TG 消息)——服务器的还原手段

1. **`/opt/v6/miss_snap.json` 只存漏采名单(非比率)**;mtime = 最后调用时刻 → mtime 若是某日 20:00,其内容即当晚战报的漏采清单(实例:9/12 20:00 = 181 家)
2. **复算当前值**:主服 `python3` import pix_bot_server → 调 `_intercept_stats()` → r = c/a(与当晚战报同函数同口径)
3. ⚠️ **复算有副作用**:该函数会**覆写 miss_snap.json** → 跑前 `cp -a miss_snap.json{,.bakcalc}`,跑完还原(否则破坏次日"昨日对比"语义)
4. **汇报格式** = 实算值 + 快照 mtime/家数铁证 + 一句"战报原文不可调出";2026-09-13 实测:R1 59.0%(239/405,108 项目)/ R2 85.8%(831/969,98 项目),漏采 昨 181 → 今 188(>4h 存量 180 = 待票/冷却通道类)
5. 解读锚点:R1 缺口大头是 >4h 存量(锁票/冷却通道),与当日 403 等主服侧事故基本无关;别把结构存量当新增退化
