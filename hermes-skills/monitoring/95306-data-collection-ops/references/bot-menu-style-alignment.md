# 菜单/文案样式对齐(重写版 bot ↔ 老正本)

**何时用**:用户说「菜单样式(和之前)不一样了」「整理成和之前一样的」——bot 换代重写后,把面板文案/排版/键盘逐面板对齐老正本。也用于任何「两个版本 UI 对齐」诉求。

## 顺序(先出差异清单,再动手)

1. **老正本侧取证(机械,不靠眼看)**:
   - `tools/_old_style_dump.py` —— 老正本 AST → 每面板文本骨架 + inline 键盘标签规格书(面板数 = 老 `callback_data` 分支数)。
   - `tools/_old_cb_style.py` —— 老 `handle_callback` 每分支的文本模板逐字原文(分段 `sed -n 'a,bp'` 读,别一次全打)。
   - 目标面板再 `read_file`/`awk` 取逐字原文(标题行、分隔线、引导行、按钮标签与行序全要对上)。
2. **新侧取证**:`tools/_probe_style.py` 只读 dump 新树全部 `ui_*` 面板实渲染文本。**四路发送器全换记录器**(`menus.tg`/`router.tg`/`cmds.tg`/`push.sender` 缺一路就会真发到用户 TG)。
3. **逐面板比对 → 清单 → 才改**。用户对「先改后对」零容忍;差异清单要能逐条指着老正本行号说。
4. 改完跑离线回归(`offline_ui` / `offline_groups` / `offline_tg` / `offline_integration` / `coverage_vs_old` 应仍 100%)**再谈发布**;发布+重启属生产闸,须用户单独点头。

## 老版样式锚点(对齐目标)

- 标题 `**粗体**` + 紧随一行 `━━━`(13 个)分隔线;尾行同样 `━━━` + 引导语。
- 引导行:`👇 选择功能:`(主界面/设置类)。
- 计数行千分位 + **双空格**对齐:`🔵 可拦截项目·未开始报名      89 个`。
- 列表条目两行式:`1. 名称` / `📅日期 | 🏢N/M家`;页眉 `{标题} | 第p/n页 (共N个)`;数字键行;尾行 `⬅️ p/n ➡️`。
- 项目卡:`{🔥|📚} **名称**` / `状态: X | 时间: Y` / `📦 包件: N | 🏢 企业: a/b` + `**包件预览:**`(`• 包件号 名称 ¥保证金`,`... 共 N 包`)。
- 按钮:单列老序、标签带动态后缀(计数/状态/「(生成中...)」),不要隐藏按钮。

## 落码规矩(踩过的坑,每条都有机制)

1. **列表类面板只改中心渲染器一次** —— 所有列表都过同一个 `page_out`/`render_mb` 等价函数,改它比逐面板改省一半工作且不会漏。数字键标签用纯数字,回调用该行**原生打开键**,别搬老别名键(前缀匹配/别名表在两边不同,别名键=死键风险)。
2. **老版里写死的陈旧数字(如「历史全量(221,661行)」「7,399 家企业」)一律不许照抄** —— 能实算就实算,算不出就把该行去掉;写死的数字在数据变化后就是错误信息。
3. **数据源缺失的老字段安全返空,不编造** —— 例:老列表条里的审核计数在新池没有等价源 ⇒ 该段返 `""`,并在交付里点名「池里没有等价数据源」,不要用近似字段顶替。
4. **改公共 UI 方法签名前先看调用点位置传参顺序** —— `ui_xxx(self, cid, edit=None, fname=None)`:把 `edit` 写在后会把回调传的 edit 错绑到 fname(静默改错对象)。
5. **按钮要双向对账:死键 + 孤儿** —— ① 新写/改写的按钮键,落码后 grep 回调注册表验证非死键(老名/近似名常只剩 1 处引用,真名可能不同);② **反向**:老正本每个 `callback_data` 都要有渲染器**发出**它 —— 「**有处理没按钮**」是移植最常漏的形态(别名接了、`act_*` 函数写好了,就是没人画那个按钮 ⇒ 对用户等于功能不存在)。孤儿检查的 grep 目标 = **键盘构造处**(`inline_keyboard` / 按钮文本行),不是 `cb_handlers`/别名表。
6. **列表渲染器里禁止逐项调读盘/重算函数**(性能) —— 只用已存字段;老函数语义与新树不同时,宁缺勿慢。
7. **老助手里有死代码**:如 `wide_center(..., 14)` 定义了从没调用 ⇒ 先 grep 调用点再拿它当宽度/补宽规范。
8. **大块 patch 的 `old_string`/`new_string` 会被上下文压缩器省略** ⇒ 拆小片 patch + 落地后回读全文核对;`write_file` 写大文件同理。
9. 文案/样式改动**只改代码树**,不改线上;`current` 软链指向的仍是上一版,要生效需重新打包 + stage/plan/activate + 手动停起 bot。
10. **★按钮类回归断言必须测「渲染出的键盘里含该回调」(emission),不能只测「老回调点了有反应」** —— 只测可点性的闸门对「按钮没渲染」这一类**永远绿**:老回调一直是合法键、点了也有反应,缺的只是没人画它。闸门姿势 = 触发该面板渲染 → 断言 keyboard 的 `callback_data` 集合含目标键;翻页面板再补「页码文字 + 正文页码 + 翻页键带 pid」三条。
11. **断言键盘时分清两个字段**:`callback_data`(路由)与 `text`(显示)。页码指示器是**文字**挂在 `listnoop` 之类占位回调上 ⇒ 在 `callback_data` 里找 `2/3` 必然失败,会去追一个**不存在的产品 bug**。断言前先确认取值域。
12. **在既有回调后追加参数段(如 `<id>:<page>`)之前,先看解析器怎么写** —— 若用「取尾段」(`_tail`)解析主参数,追加后新参数会被当成主参数(静默串号,翻页即崩);须先改成按 `:` 分段 `split`。新增回调键要同步 `_h_*` 解析 + 闸门断言。
13. **别按记忆里的换行约定断言** —— 同一文件在本机发布源树与线上部署副本可能换行不同(实测 `bot/menus.py`:本机源树 LF、记忆记的是 CRLF)。补丁脚本**逐文件实测 `\r\n` 计数**并保原样(全 bytes 读写),落地后回读核对尾部;不要拿「某文件是 CRLF」当先验。
