# v9.25: 已结束项目「包件审核状态」刷新链路修复(2026-09-10)

## 症状
已结束项目的包件报名审批状态(审核状态: 通过/拒绝/未审批)拉取更新停滞,久不收敛。

## 三层根因(全部实锤)
1. **8515 增量是"假增量"**:
   - 采集机 fetch_8515_snapshot 用日期窗 `[T-7, T]`,但 **end 被平台按当日 00:00 解读**(同天窗 start=end=空);8 页×100=**800 条封顶** → 每 6h 反复抓"7 天窗里最老的一批",**当日数据永远进不来**(index 冻结证据: mtime 停在 10:50,机器快照却每 6h 稳产 800 条)
   - 下游 audit_diff 检测不到变更 → audit_changed ts 冻结 → audit_refresh 定向刷新整条闲置
2. **审核状态刷新名单缺口**: bk 补漏只管"缺漏企业"(名册差集);已采到但审核=未审批/空的企业没有任何刷新路径;audit_refresh 受"8 项目/批次、只消费一次(缓存 8/40)、库存 ST 失效即哑"三重限制
3. **bid_status.json 从未并入池**: 机器侧写得正确且新鲜,主服 merge_all 只搬 _pack_map/_项目信息 → bot 竞价状态显示/推送读取池内文件全空(0/500)

## 修复(v9.25,全部免重启)
- **主服侧增量抓取** `/opt/v6/fetch_8515_inc.py`(cron `*/30` + flock): datetime 窄窗按"内部更新时间"切片 + 全页拉取 + 首跑 7 天回补(6h 片);输出 `/data_raw/m_snap/8515_快照_m*.json` → merge_8515_snap 自然消费
  - **⚠️ 时区铁律: 主服=UTC,平台按 BJT 解读 datetime 窗 → 必须 `datetime.utcnow()+8h`**;state 用 BJT 字符串
  - 窗口语义: `["YYYY-MM-DD HH:MM:SS","…"]` 按内部更新时间过滤(输出行看不到该字段);日期-only 的 end = 当日 00:00(空同天窗根因)
- **merger**: merge_all 尾部把 `{pid}_bid_status.json`(取各机最新 mtime) copy 入池(验证: 1032 项目一次补齐)
