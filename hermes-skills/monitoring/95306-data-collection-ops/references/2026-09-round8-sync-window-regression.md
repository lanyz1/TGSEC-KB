## 4. 类级规则

- **时区"统一"修复会移动窗口/过滤边界**:round7 把 sync 窗口改北京时(方向正确)却收窄了 8h。任何窗口/过滤改动上线前,先核对目标集在旧/新边界的分布(如"公告日恰好=旧边界 8/21 的项目有多少")。边界批次项目(37 个)整批消失是强烈的回归信号,不只是数据抖动。
- **权威数字归零先查快照覆盖,别断言平台无数据**:菜单/展示"平台权威 0"三种可能:①平台真无报名(漯阜 B 案例)②快照回退(round7)③**窗口切掉整批(本 round)**。排查顺序:项目公告日 vs 快照 start → sync 日志项目数序列 → 多窗口实测命中。
- **"待补 0 + 权威 0"是公式崩坏的假象**:待补=权威-已采;权威 0 时永远显示待补 0,掩盖采集缺口。看到"共N家=权威0(采N+待补0)"直接怀疑窗口/快照,不要信。
- 接口分页参数坑:pageSize 上限 500,proj_code 过滤参数会被**静默忽略**(不报错,返回全量)→ 想按项目查就全量拉后 grep,别依赖过滤参数。
- sync 日志 /tmp/plat_enroll_sync.log 保留每轮"OK: N 项目"——N 序列是排查窗口/截断/漏行的第一证据(本项目 456→419 即铁证)。
