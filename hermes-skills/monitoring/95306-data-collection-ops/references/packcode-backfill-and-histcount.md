# 包件缺编号回填 + 历史采集完成(累计) 一轮记录（2026-10-05）

## ② 18列CSV「行数差 4,656」= 非 bug（已终判）
- 真因：**字段内换行**。样例 `包件名称='齐齐哈尔车辆段\n重废钢'`；全池 **4,343 条记录含 `\n`**。
  ⇒ 文件物理行 > 逻辑记录数，**合法 CSV**。以后再遇到"行数对不上"先数含 `\n` 的记录，别再当缺陷追。

## ① 包件缺 packCode/packName（数据完整性缺口）
- 影响面：全池 **1,136 条记录 / 1,898 个包件条目缺 packCode**、**553 缺 packName**、**涉及 128 个项目 / 369 家企业**（全部有企业名，无 uid 键）。
- **空编号含故意的 `PROJ_LEVEL`（项目级报名）——统计必须排除，不是缺陷。**
- 两类形状：**形状1** 清单自带 packId+编号+名 ⇒ 可机械回填；**形状2**（来源=`8515链接`）清单无 packId、`平台侧_8515.json` 只有 `pack_id` ⇒ **只能权威源重取**。
- 权威链路（老脚本 `backfill_pack.py:60-158` 实证）：`dataplatform/api/findList funcId=tokenrailquery`（活票，含 `login_status=1`）→ `business/user/info`（取 `dwhz` 企业官方全称）→ `supplierPackage/getBuyPackageList?projId=`（取 packId→编号/名称/保证金/报价模式/物资条数）→ 按 packId 写回。
- 工具：`tools/_fix_packcode.py`（分片写，`--selftest/--scan/--apply`；`--acct-map` = `acct_map.json` 企业→账号快路）。
- **★★第 0 遍 = 纯本地 `包件清单*.json`（实测 494/553 = 89%，零联网）**：项目目录的 `包件清单*.json` 里
  递归能找到 `packId → (packCode|包件编号|编号, packName|包件名称|名称)` ⇒ 直接喂 `fill_entry(ev, pm)`（只补空）。
  **顺序铁律：先本地遍、再用 `rest` 重建 `byent`、最后才联网** —— 否则网络遍会把本地已补的再算一遍（假增）。
  只剩 59 条要联网 ⇒ 活票天花板（本轮 6h 窗口仅 11/369 家）只影响这 59 条。
- **★★本轮实绩（2026-10-05 `--apply`）**：本地遍落盘 **494 记录 / 722 条目 / 1,444 字段**（每份写前留 `pack_map.json.bak_codebk`，共 **99 份**）
  ⇒ **独立复扫（另写实现，非工具自证）真缺口：553 记录 / 811 条目 → 59 记录 / 89 条目**。
  **★端到端对账（同一根数，两个来源）**：18 列汇总里「空包件编号」行 1,898 → **1,176**（正好少 722 ✓）；
  分解 = **1,087 行 PROJ_LEVEL（项目级，故意空，非缺陷）+ 89 行真缺口**（无 packId 行 = 0）——CSV 的 89 与池的 89 一字不差。
  ⇒ **口径铁律：报缺口一律报「有 packId 但编号空」那一档（811→89），绝不把 PROJ_LEVEL / 无 packId 的算进缺口**（否则数字会凭空大十倍）。
  网络遍对剩 59 条：命中 1/44 家但 `packs_of` 返空 ⇒ **0 写入**（宁缺不猜）；剩 59 条全在形状2项目
  （`024c7fb8`=9、`7fe085a0`=5、`a6adc70c`=5、`b2448907`=4…），须等这些企业账号近期登录出活票，工具幂等可反复跑。
- **★取账号的正解 = 本地 CSV（零网络、首选）**：每个项目目录自带的 `企业包件表_18列_*.csv`，表头就是
  `企业全称,统一信用代码,登录账号,…` ⇒ 就地建 **企业全称→登录账号**，再和活票 `userid` join（`casefold`）。
  **★不要指望记录键**：`pack_map.json` 的 `enterprises` 键是内部 `lk_<hex>`（不是账号）⇒「记录键↔userid」直路实测命中 0。
- **★`--deep`（逐票 user/info 反查 `dwhz`）会撞 timeout**：活票 3,338 只 × ~0.5s ≈ 28min > `timeout 1500` ⇒
  只在企业数很少时才用；正常走「本地 CSV 映射 + acct_map」两条快路（纯内存 join，分钟级）。
- **铁律**：只补空、绝不覆盖非空、`PROJ_LEVEL` 永不动、按 packId 对齐、每份写前 `*.bak_codebk`、原子写、幂等（二次 0/0）。
- **覆盖天花板（诚实边界）**：活票只有"近期还登录过的企业"才有 ⇒ 单窗口只能补一部分（实测 `acct_map` 命中 144/369 家、12h 活票 3,342 只命中 11 家 ⇒ 19/553 条）。**幂等可重复跑，窗口一换自动多补一批** ⇒ 想快就挂周期任务，不重置数据。
- 票池 `priv_tokens.json` 已失效（`p2_loadmenu:401`）⇒ 别走它，只走 `tokenrailquery`。

## ③ 「历史采集完成(累计)」落码
- 口径：**名册齐的「已结束/历史」项目数** = `stage ∈ {已结束,历史}` ∧ 平台侧有权威家数 ∧ 池内实体家数 ≥ 平台家数。
- 实现：`bot/pool.py` `hist_done_count()`（**纯内存**：只吃 `index.json` 的 `stage`/`enterpriseCount` + `plat_enroll*.json`，**绝不逐项读 projects 目录**，300s 缓存 `_hd/_hd_at`）；`bot/menus.py` `ui_home` 一行 **`🗄️ 历史采集完成(累计) N 个`**。
- **为什么必须与 `✅ 可拦截项目·采集完成` 并存**：后者是**瞬时窗口值**（只在 pb 窗口内，天然掉到 0~4），客户看到"采集完成只剩两个"就是它；累计行才是大盘。两行并排一眼消除误解。
- 回归断言：`tools/offline_ui.py` H1–H4（行存在 / 值 =1（夹具 P006 名册齐算、P007 家数不足不算）/ 两行并存 / 总览行没被挤掉）。**★夹具 `FakePool` 必须同步加 `hist_done_count`，否则闸红。**
