# 2026-09 Round5: 榨干队列机制 / 已结束项目补全 / 成效统计口径

## 1. 竞价结束 ≠ 断供:已结束项目补全靠"榨干队列"(collector v9 drain)

用户高频疑问:"竞价结束的项目也会自动拉数据补全吧?""已结束不是能直接从平台拉完整信息吗?" — **答案:能,靠榨干队列**。完整图景:

- **在网采集链**(collector 发现/orch8b 补漏/gen_gap 审计联动):只覆盖平台在网项目(报名中~竞价中)。项目切终态(14)从 selectSelfSellList 消失 → 这三条线停更
- **榨干队列**(collector_v9 drain,补已结束/历史项目的主通道):每次审计拦到某报名企业新 ST → 该企业 buyed **全部项目(含已结束/历史的)入队** → 分轮用 ST 调 `supplierPackage/getBuyPackageList?projId=` 拉包件+审核状态。**平台对终态项目照样返回数据**——这就是数据池 20,719 个已结束项目带包件明细的来源
- drain 结构(state.json):`{acct: {st, tm, all:[全项目id], done:[], ent, full_ts}}`;每轮 ≤3 票 × 每票 ≤10 项目;done 满 24h 移除;ST 死票/dead_set 清理;产出写 `/data_raw/_ent_full_<epoch>_<acct>.json` 回主服
- **ent_coverage 死数据差集**(跳过已覆盖):结构 `{账号: {projId: {"end": true}}}`;跳过条件=项目已结束 且 cov.end=True;铁律 **活数据永不跳过**(进行中项目无条件拉)
- orch8b/gen_gap 的补漏清单不含已结束;已结束只走榨干队列(存量 ST)与名册 14 天窗口(权威企业数核对)
- **物理边界**(不可消除):每家企业包件细节要用**该企业自己 ST** 拉,平台无免鉴权项目级全量报名明细接口 → 从未被审计拦到的报名企业(从不登录/不走跳转)无 token = 黑洞,结束前后都补不上 → 进 🏁 标 ⚠️部分数据(名册 N/已采 M)。竞价要登录,所以"竞价前"是企业出现的最后窗口
- 向用户表述口径:结束前的票 ST 存活期内持续榨干;补不动的是无 token 黑洞,与管道无关

## 2. 榨干成效统计/采集机诊断方法(2026-09-04 实测口径)

- **8 台清单源 = orch8b.py BOXES**(沪0 8.133.188.178/杭1 121.43.97.73/穗2 8.138.236.124/蓉3 47.108.152.60/沪4 8.133.212.134/蓉5 47.108.173.230/青6 47.104.139.212/深7 47.107.124.62 + 口令两组 Ppikesi101-104./Ppikesi0001.);jumpers.json 只存 4 台默认且可能不存在
- **本机直连采集机不可靠**(部分 IP 直连超时 WinError 10060)→ 统一**经主服中转**:统计脚本 sftp 传到主服 /tmp → 主服 paramiko 循环连 8 台(密码登录,timeout 15)
- ent_coverage.json 每台采集机一份(/opt/v6/)——2026-09-04 发现 **8 台+主服全是 99B 空壳、mtime 相同(某定时任务统一重置?)** → 死数据差集从未生效 = 榨干队列对已覆盖项目重复劳动(不丢数据,浪费额度;待查谁在重置)
- **回传台账 = /data_raw/<城市>/_ent_full_*.json**(主服只读即可统计,无需连采集机):8/29 起 313 个文件,每文件=1 企业 1 轮(1-10 项目包件);文件名 `_ent_full_<epoch>_<acct>`;**按日分布不能用 find 匹配 YYMMDD 子串**(文件名是 epoch,无日期子串)→ 用 `-newermt 'YYYY-MM-DD'`
- 采集机 collector 日志路径不定(遍历 /opt/v6、/root、/tmp 下 *.log,看 ps -ef fd 指向);主服 pixbot.log 是 bot 日志不是 collector
- 数据池落库口径:index stage=已结束 20,719 中带 pack_map.json = 6,122(29.5%);历史 83/83 全带(2026-09-04 基线)

## 3. 远程统计脚本防翻车(本会话再踩)

- **多层 base64 + 嵌套 r''' 必崩**(外层字符串被内层 r''' 提前截断 → NameError);**本地 write_file 两个独立小文件 → sftp 上传 → 远程只执行**,不要在 ssh 命令串里嵌 python
- 采集机 ps 输出非 UTF-8(locale)→ 远程脚本里 `subprocess.check_output(["ps","-ef"])` 处理 bytes,别 os.popen().read() 裸 decode
- 审批护栏:批量连 8 台+嵌套 SSH 的长命令易触发审批超时被拦;拆小、单台样例先行
