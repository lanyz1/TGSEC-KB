# ST 票 TTL / 活性判据 / 退出(logout)契约 —— 实测档案（2026-10-08）

目标 `cg.95306.cn`（授权）。执行机主控 `root@207.57.167.92:12971`（TZ=UTC，平台时间北京 +8）。
全程只读/零写/串行限速 2.5 s。

## 1. 判据表（v3 校准后，可用）

| 观测 | 判读 |
|---|---|
| `200 + success:true` | 票**活**，读到数据 |
| `200 + code=100 系统服务异常，请联系技术支持！` | **鉴权通过**、账号侧异常 —— **≠ 票死**；且**会抖动**（同一枚票前后两次可不同） |
| `401 未登录或已退出登录` | **票失效**（唯一可信的「票死」判据） |
| `500 您没有该功能的操作权限` | **路径不在路由表**（校准基线，非票问题） |
| `OPTIONS` 任意路径 → `204` 无 `Allow` | **不可作路由存在性判据**：该网关对 OPTIONS 通配 204（假阳性） |

**铁律：判票死只认 HTTP 401。** 采集侧若拿 `success:true` 当唯一活性判据，会把 `code=100` 的活票误杀、白清票池、重复刷票。

## 2. TTL 实测

按票龄分档采 8 枚（<1h / 1-6h / 1-3d / >7d）：**8/8 鉴权通过、0 失效**；
最老票 `hnfc888888`（9-27 10:19，**11.36 天龄**）打 `GET /user/info` **仍 200**。
⇒ **ST 票不会短期失效**；「6 小时」是采集/刷票节奏，**不是票寿命**。
⇒ 池内**采不到真死票** ⇒ 任何依赖「已死票样本」的探测在当前环境**跑不成**。

## 3. 退出(logout)契约（实验 B，单枚活票、命中即停）

- **`POST /user/logout` 真实存在**：HTTP 200 + `{"code":"","success":false,"msg":"远程调用退出登录失败"}`（业务层响应，非 500 缺功能）。
- 其余 7 个候选（`/user/loginOut`、`/user/logOut`、`/user/exit`、`/user/quit`、`/user/offline`、`/user/loginout`、`/login/logout`）GET+POST 全 `500 您没有该功能的操作权限` ⇒ **路径不存在**。
- 该端点实现是**「远程调用」上游认证/SSO** 去执行退出 ⇒ **ST 票不足以驱动退出**。
- **副作用实测为零**：打完 logout 后用同一枚票 `GET /user/info` 仍 `success:true`，账号未掉线、票未作废。

**结论：ST 票＝能读、不能写、不能踢下线、不能退出。** 任何「用捡到的票让真实账号掉线/作废会话」的设想均不成立。

## 4. 副产品：`/user/info` 回吐第二凭据

`GET /user/info` 响应体含 `"token":"57c259fc…"`（32 位）＋ `id`(UUID) ＋ `roles:["supplier"]`。
该 32 位 token 疑似就是 `/user/logout`「远程调用」所需的凭据类型 —— **未验证，且验证带真实副作用（会让真实企业账号掉线）**。
对采集任务无业务收益，**默认不做**。
