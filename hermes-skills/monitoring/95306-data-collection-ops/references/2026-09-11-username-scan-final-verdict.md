## 用户纠正(重要):平台根本没有密码登录

登录方式全集 = **手机号+短信验证码 / 口令卡(动态口令) / 证书 CA**。没有账号密码登录。
对 tokenrailquery 语义的修正:
- login_mode 三值(证书/随机码/手机号)就是**登录方式全集**,不是"增强认证子集"——"随机码登录"=口令卡(或短信随机码),memo 里"随机码或密码错误"=口令卡输错
- 修正先前表述"普通账号密码登录 0 记录"——不存在密码登录;平台供应商每次登录(任一方式)都该留 tokenrailquery 行
- 推论:批量报名用户(崇锐类)9/5-9/9 全域零认证事件 = **SSO 长会话静默操作**(登录一次活数天,期间操作不重新认证),不是"登录方式没被记录"

## memo 字段 = 认证事件全集(锁的痕迹)

tokenrailquery 行 `memo` 字段记录结果,status 1/0 对应成功/失败:
- status=1: memo="登录成功"
- status=0 失败样例:"用户名、随机码或密码错误" / "手机号、验证码或密码错误" / "证书校验失败"
- 安全策略:"当前账号因安全策略限制,今日已无法通过随机码方式登录"
- **风控全锁:"当前账号因触发安全风控策略,今日已限制所有登录方式"**(=账号级冻结,正是用户记的"隔天才能用"档)
- 实测被锁账号全是 user_type=02(采购方内部账号,工务段/车间类),03 供应商零失败尝试 → 缺口企业连失败都没有 = 长会话无认证事件,坐实
