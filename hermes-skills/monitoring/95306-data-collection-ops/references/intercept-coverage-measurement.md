# 拦截度/覆盖率 实测口径(用户问「拦截度怎么样 / 盲区多少 / 点名批拦到没」时)

## 铁律
- **别背旧数字**(12-16% 等历史口径仅作结构性参照);被问 = 现场拉一遍再答。
- **两个口径必须分开说,勿混**:
  1. **精确缺漏回写**(miss_map 配对): 名册有/我们无 → 机会式回填;`0/69` 是"等触发",不是退化。
  2. **活跃捕获**(全池痕迹): 企业在池内有近期新写入(backfill8 等) ≠ 其缺漏项目被回填。名字全池有名 ≠ 精确回写成功——分开报,别互相冒充。

## 数据源(全部可经 本地→主服 中转读取)
1. **ent_coverage.json** `/opt/v6/ent_coverage.json`(gen_gap 每 10min 重生成, ~4.6MB): keys=企业全称/账号(~3900); value={pid: {cov: 覆盖时间, end}}。
2. **drain 监控窗**(本机): `AppData/Local/hermes/profiles/123/cron/output/e93ac7f7b11a/monitor_last_output.txt` — 最新 10min 窗: 新票广播/榨干明细 + 各机 DRAIN/SEEN 账本(cron `e93ac7f7b11a` 每 10min; 广播模式下各机 SEEN 有重叠, 求和数是覆盖上界口径)。
3. **点名批精确缺漏**: 主服 `/tmp/bk8_ctx.json`(orch8b 每轮写) 的 `miss_map`(names→[miss pids]) → 逐 miss pid 查 `/data_pool/<pid>/pack_map.json` 里该名且 `来源` 含 backfill → 计"已回写/未回写"。23 家名单见本机 `profiles/123/scripts/b23_check.py`(NAMES 数组; 监测 cron `130dc5e54674`, 30min 静默)。
4. **活跃捕获笔数**: 单遍扫 `/data_pool/*/pack_map.json`(约 7000+ 文件, ~1–2min): 名匹配=全称精确 or 前 4 字双向包含; 统计 `来源` 含 backfill 且 `时间` ≥ 昨日的条数(按名分组)。
5. **审核刷新**: 机器 `journalctl -u v6collector | grep '审核刷新'`(老8台; 新4台用 `/opt/v6/v6_run.log` tail 时间戳过滤); 解析 `本轮N项目 / X家拉取 / Y家更新 / 队列剩M`。
6. **merge/批次态**: 主服 `/tmp/v6_merge.log` 尾部; `/data_pool/audit_changed.json` 的 ts+n。

## 回答框架(用户认可的版式)
① 一句话总判 → ② 实时链路(今晨新票广播闭环实证 + DRAIN/SEEN 数字) → ③ 点名批两面真相(精确缺漏 X/Y vs 活跃捕获笔数) → ④ 最近修复的过夜表现 → ⑤ 结构性盲区(不变项, 单独列)。

## 结构性参照(不变项, 记账口径)
- 报名期 SSO 长会话双盲 **~15% 结构缺口**(票已死、不可补; 8/28–9/9 全域扫描终局) → **竞价日强制认证收敛 97%+**; 僵尸 2–3%。
- 风控冷却风暴(账号级冻结到次日 00:10 北京时)只影响**时机**、不丢数据; "缺口企业连失败记录都没有" = 长会话静默的坐实证据。
- 陕西晨易阳: 全渠道零痕迹(23 家中唯一顽固项)。

## 诊断分型(平台调用异常, 先分型再修)
- **HTTP 403 + HTML 拦截页** = 该出口 IP 被平台封(WAF) → 换采集机出口重挂。
- **HTTP 200 + code=-1** = 查询语义/权限问题(非网络)——该查询姿势本身需重做。
