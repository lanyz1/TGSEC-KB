## 1. 平台权威归零排查("平台权威 0" 先查这三层)

用户报某项目"平台权威 0"时,按顺序排查(不要断言"平台没数据",也不要先改 bot):

1. **快照窗口切掉整批**(round8):项目公告日 < plat_enroll_map.start → 接口按公告日(bulletin_reldate)过滤,报名动作日期在窗口内也没用,整项目消失。看 sync 日志(/tmp/plat_enroll_sync.log)"OK: N 项目"逐轮序列——456→419 类骤降 = 窗口/截断铁证。窗口曾 14 天切掉 8/21 公告批 37 个(含西安75次,权威 64 家被遮成 0);已扩到 30 天(实测 1.29 万行 < 1.5 万行上限 30页×500;probe 可拉 60 页)。
2. **快照回退**(round7):sync 全量覆盖 30min + 平台接口偶发漏行 → 企业数"回退"(25↔24),CSV 融合匹配失败出现假"🔹平台外"行。修复:sync 对比上轮,某项目企业数减少 → 30s 后整轮重拉确认,两轮并集兜底(宁可多不可少)。
3. **批次双 code 幽灵**(round9):同 projName 双条目(沈阳铁道系高频:平台对同批重发公告,旧 code 作废但 index 残留,竞价常差 1h 08:30 vs 09:30),旧 code 不在接口 → 权威必然 0。修复:bot blockable_projects 前加 _ghost_filter:①不在快照且有快照兄弟 → 藏 ②在快照但权威0+采集0+兄弟有数据 → 藏。兰州式双活(双权威>0)/广州式双权威0 → 不误杀保留。

## 2. 症状辨析与接口坑

- "共N家=权威0(采N+待补0)" = **公式崩坏假象**:待补=权威-已采,权威 0 则待补恒 0,掩盖真实采集缺口(西安75次真权威 64、采 32、缺口 32,修复前被显示成"采 32 权威 0"遮住)。看到此形态直接怀疑窗口/快照/幽灵;修复后缺口现形并自动进 orch8b 补采。
- 接口分页坑:pageSize 上限 500;proj_code 过滤参数被**静默忽略**(不报错返回全量)→ 按项目查 = 全量拉后 grep。
- 多窗口实测法是判定接口过滤语义的决定性手段(同 code 在 14/16/30 天窗口的命中对比)。

## 3. 平台时间 vs 主服 UTC(本系统反复咬人)

主服系统时区 = **UTC**(date 确认);平台所有时间(公告/报名/竞价/截止)= **北京时**。任何 `datetime.now()` 与平台字段比较必须统一北京时:

```python
from datetime import datetime, timedelta, timezone
def _bjnow():
    return datetime.now(timezone(timedelta(hours=8))).replace(tzinfo=None)
```

- 曾致两起回归:ent_coverage 已结束判定错位 8h(基线 1→3405 修复的根因之一);sync 窗口起点"统一北京时"时收窄 8h 切掉整批 8/21 公告(round8)。
- **改动含"时间"的过滤/窗口/判定时,第一步先查服务器时区**(`date`),上线前核对目标集在旧/新边界的分布(公告日恰好=旧边界的有多少)。

## 4. ent_coverage 覆盖基线(safe 判定语义)

- 死数据差集:进行中项目永不进基线(活数据永不跳过,用户铁律);已结束项目才可 cov.end=True。
- 已结束项目 pack_map 企业"时间"= 首次登录(多在报名期)< 竞价开始 → 旧规则 tm≥bst 拒掉 99% 覆盖(基线 1 企业)。
- 修正后的安全判定(任一):①tm≥bst ②**项目竞价结束 >48h = 平台定稿,存量包件即终稿** ③榨干回传文件 _ent_full_*.json mtime ≥ bst(拉取时刻在竞价开始后 = 审核定稿;竞价开始后平台审核不再变)。文件内 bidStarttime 字段常为空 → 用 index 的 bidStarttime。
- 效果:基线 1 → 3405 企业 / 51502 条可跳过,重复榨干消除。
