# 包件重复治本 + 导出按钮找回（`ai` 那一轮）

两个 bug 的定性、修法、验收数字与坑。下次遇到「数字虚高」「按钮不见了」直接照这张走。

## 一、包件数组重复快照（18 列汇总虚高的**第二个**根因）

行数虚高有两个根因，别混：①同名企业多账号（`ah` 已治，`count_units`）②**同一 packId 在单条记录的 `包件` 数组里被 append 多份**（本轮治，最多见过 249 个元素里 228 份是重复）。

- 源头 = `master/writer.py` `merge_ent` / `apply_named`：**只按 packId 建 `have` 表防「新增」重复，从不清理 `old` 里已存在的旧账** ⇒ 老 merger 时代写的份数永久存活（实测分布：已结束 5,238 / 历史 15 / 报名中 1 ⇒ 全是历史遗留）。
- 三处一起治（缺一个都会复发）：
  1. `collector/entcount.py` 纯函数 `norm_packs`/`norm_units`：同 packId 只留**最新**一份（时间最大 → 字段更全 → 更靠后；缺字段互补；**空值不许覆盖非空值**）。
  2. `dedup_units` 对**每条**记录都归一化（含「单条直通」那条路径 —— 54 份就是从这漏的）。
  3. `master/writer.py` 写入侧自愈（清老账必须放在建 `have` 表**之前**）。
- 边界铁律：**不同 packId 不许并**（冻结的 P5/P9 反例断言）。
- 一次性清扫 `tools/_fix_packsweep.py`（默认 dry、`--apply` 落盘）：真池实测 **扫描 53,134 份 pack_map ｜ 命中 992 文件 ｜ 修 2,631 记录 ｜ 丢 37,273 份 ｜ 异常 0**；自检「除 `包件` 外一字未改 + 家数不变」；落盘走 `writer.write_json`（原子写 + `.bak_bkch`）。
  - **跑 APPLY 前先 `pgrep -af 'v6m\.py [m]erge'`**：正有一轮在飞时清理会被它的内存副本写回。跑完**必须复扫**（应 0 命中）+ 等一轮「出表完成」。

### 验收数字（`ai` 生效后实测）

| 项 | 前 | 后 |
|---|---|---|
| 池内包件重复记录 / 多余份数 | 2,631 / 37,273 | **0 / 0** |
| 18 列汇总（出表日志「汇总 N 行」） | 310,389 | **273,116**（正好少 37,273） |
| 18 列唯一(项目,企业,账号,包件) | 272,354 | 272,354（不变 ✓ 只删重复） |
| 全池家数 / 在办家数 | 70,388 / 1,955 | **70,388 / 1,955**（口径未动） |

**「正好少 37,273」= 最硬的证据**：少掉的 == 清扫丢掉的 ⇒ 没误删任何合法行。

### 残留 517 组的定性（别当成没修干净）
判据：**组内 `包件ID` / `审核状态` / `包件名称` 各不同** ⇒ 是 N 个真包件各占一行，只是 `包件编号` 为空（包件结果按 packId 回流、编号/名称没映射上）⇒ **这是数据完整性问题，不是重复写入**。写探针按 `(项目ID,企业,账号,包件编号)` 分组时会把它们看成重复 —— 粗键假象。

## 二、导出按钮「不见了」

- 丢的是**企业列表页页脚的 `enscsv:<pid>`**（老正本 = 项目卡「📋 报名总表」→ 表底「📥 下载总表CSV」）。铁证 = bot 日志 `CB: projents:<pid>` → `CB: entscsv:<pid>`（老板点了）。
- 真因：`act_entscsv` 实现、别名、派发**全都在**，**唯独没人渲染那个按钮**（移植时漏）。修法：`act_projents` 页脚渲染导出 + `⬅️/页码/➡️` 翻页 + `page_out` 渲染 + 工坊结果页补 `qrydl:`/`qrycsv`。
- `aiexp`（老正本「AI 结果导出」）**没有对应数据可补**：AI 问答本身没搬进新版 ⇒ 别去补按钮。
- **闸的教训（最值钱）**：旧 UI 闸只断言「老回调点了有反应」⇒ 回调一直在、按钮没了 ⇒ **bug 溜过闸**。现在 G 组 6 条断言专测**按钮存在性**（G1 报名总表页脚必须有 `entscsv:`），翻页断言要看**按钮 text**（`2/3`）而不是 callback_data。

## 三、本轮踩到的坑

1. **出表是周期末的慢步骤**：`write_csv_18()` 要写 7,875 个项目文件 + 100MB+ 汇总 ⇒ 晚于「并库完成/阶段推导」几分钟。**判「生效」必须看 `出表完成：… 汇总 N 行` 这行日志 + 汇总 CSV 的 mtime**，只看并库完成会误判「没生效」。
2. **汇总 CSV 不在并库阶段写** ⇒ 清扫完不立刻生效；等一轮出表（或手动触发）再验。
3. **在服务器上跑树内闸**：闸的自举靠 `__file__` ⇒ 复制到 `/tmp` 跑会去找 `/tmp/bot/menus.py` 炸掉。**正确做法 = `cd /opt/v6/lib/<rel> && python3 tools/<gate>.py`**（闸随发布包一起发出）。
4. **`F2` 正本键数阈值是夹具口径**：线上 `/opt/v6/pix_bot_server.py` 是更早修订（61 键）而基准快照 80 键 ⇒ 在服务器上会假红。已改成**记 skip 并打出来源**（不静默放行、不判红）。
5. 大内容一律分片写 + 写后回读；`ssh -n … "bash -s" < 脚本` 首次会返空 ⇒ 去掉 `-n`。

## 四、同类改动的固定动作（照抄）

1. 定性：真池只读探针拿数字（两条独立实现互校）。
2. 本地落码：补丁脚本带「锚点唯一 + compile + 幂等 + 保换行」四闸，改前备份。
3. 加断言：正例 + **反例（不许并/不许改家数）** + 幂等。
4. 跑闸：`offline_ui` / `offline_entcount` / `offline_packnorm` / `offline_bot` / `offline_groups` / `offline_tg` / `offline_integration` 全绿。
5. 发布链：`build_release --stamp <s>` → 两端 sha 一致 → `--stage --tar/--sha` → `--plan` → 未割接新树只读预演（含 DRY 清扫）→ `--activate --yes` → `--verify` → **串行**停旧起新 bot。
6. 生效后：跑 `_probe_final_*` 总账 + 复扫 + 等出表 + 看 bot 日志（`ROUTE-ERR=0`、异常 0、单实例、offset 在写）。
