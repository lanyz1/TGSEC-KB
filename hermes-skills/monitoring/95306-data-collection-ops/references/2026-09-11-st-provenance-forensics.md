# 2026-09-11 记录溯源: 「这批数据是哪条ST/哪个通道抓的」(常规请求类型)

用户会直问「某某新增企业记录是哪条ST抓出来的」——按此法在主服直查, 全程只读。

## 一、字段=通道身份证 (pack_map 条目 schema)

| 写入方 | 特征 | 说明 |
|---|---|---|
| 采集机 collector (`collector_v926b_stage.py`) | `{"账号","用户","单位","ST","时间","包件"}` — **无"来源"字段, ST=拉取时使用的企业会话票(32位hex)** | 写点实证: `ent={"账号":t["acct"],"用户":uname,"单位":dwhz,"ST":st,"时间":t["time"],...}` |
| 补漏 worker | `来源="backfill8"`, ST 通常为空 | bk 系写入 |
| 历史导入 | `来源="01三态+映射链"`, 时间=历史真实时间(可能是往年) | 别把老项目误当新批次 |

- merger 不改写这些字段; 同记录可能出现**"账号键+名称键"双条目**(展示层按单位合并), 统计家数要去重。
- 显示端 ST 常被截断, **完整32位 hex 必须从原 JSON 取**。

## 二、直查步骤

1. **项目定位**: 读 `/data_pool/index.json` → projects → 按 projName 关键词筛。
   - 坑①: 名称匹配易撞**往年同名项目**(漯阜"第3次"横跨2024/2025/2026)→ 用年份+特征词双重限定。
   - 坑②: 存在**同名重复壳**(如 `93732d58` = 同题 0 条空壳)→ 以有数据的 pid 为准。
2. **读条目**: `/data_pool/<pid>/pack_map.json` → `enterprises` → 逐项打印 `(时间, 账号key, 单位, ST全值, 来源)` 倒序。
3. **出处机判定**: `/data_raw/<机名>/<pid>_pack_map.json` = 采集机上传落点(机名: 上海/上海2/河源/乌兰察布/武汉/深圳/成都2…); `/tmp/bk_pool/<pid>/pack_map.json` = 补漏 worker 主服暂存。
4. **ST 全局反查**: `grep -rl '<ST前12位>' /data_raw /tmp/bk_pool /opt/v6 2>/dev/null` → 还原落盘链路。
5. **更深(哪台机、几点、哪条审计事件)**: 采集机侧日志不在主服 → 需连对应采集机翻 `/tmp/v6_run.log` 按 ST 字符串 grep(未做时如实告知用户, 别装出来)。
