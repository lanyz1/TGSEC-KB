# 净化导出：把家当打成可分发副本

完整备份（带 `.env`/密钥/活体战果）与可分发副本是**目标相反**的两种打包。本文只讲后者：密钥、PII、活体目标身份全部剥掉，方法与流程完整保留。
参考实现：`scripts/sanitize_export.py`。

## 打码规则表（按此顺序执行，顺序不能换）

| # | 规则 | 作用对象 |
|---|---|---|
| 1 | `.env` 真值字面量 | `*_KEY`/`*_TOKEN`/`*_SECRET`/`*_PASSWORD` 的实际值 |
| 2 | 密钥/token 正则 | `sk-` `xai-` `AIza` `ghp_` `github_pat_` `AKIA` `hf_` `BQ` `glpat-`、TG bot token、JWT、`key=<hex>` |
| 3 | 代理节点凭据 | `public_key`/`short_id`/VLESS UUID |
| 4 | 口令值 | `password|passwd|paypassword|pwd|pass|密码` 后跟的字面量（含 `label (value)` 括号形式） |
| 5 | 长 hex | `[a-f0-9]{32,64}`（验签密钥、哈希） |
| 6 | 截断 hex | `[a-f0-9]{8,31}` 紧跟 `…` / `...` |
| 7 | ~~行内上下文~~ | **已废弃**（命中面过宽 + 吃换行，必坏代码，见坑表） |
| 8 | PII | 邮箱、`1[3-9]\d{9}` 手机号 |
| 9 | 钱包地址 | TRC20 `T…`(33)、BTC、`0x`+40hex |
| 10 | 活体目标身份 | 实战 references 里出现的目标域名/公网 IP（白名单之外的） |

## 坑（每条都真踩过）

- **顺序固定：字面量 → 窄正则 → 目标身份。** 占位符先产生就会截断后面的字面量/正则匹配。
- **别用「行内上下文」兜底无标签密钥——它就是坏代码的元凶。** 早期为了抓无标签形式（`string pass = "…"`、`ngx_string("…")`、`pass == "…"`）加了一条「本行含 pass/key/token → 打码整行引号字面量」，结果两重灾难：① 把 `passenger`/`openresty` 这类普通单词打成占位符；② 正则用 `\s` 当分隔符，而 **`\s` 会吃换行** —— 源码 `if password:` 换行缩进后的标识符被当成「password 的值」打掉，`cmd += [...]` 变成 `[PASS-REDACTED] += [...]`，一次打坏 13 个脚本。正确做法：只留「标签+分隔符+值」的窄规则，分隔符一律 `[ \t]` 绝不用 `\s`；无标签真值靠「已知真值字面量清单」精确替换。
- **截断显示的密钥要单独一条规则。** 文档常写 `17cf2f98…`（8 位 hex + 省略号），够不到 32 位阈值 —— 而这类截断值恰恰是「已在线上实例验签通过」的真钥，漏掉代价最大。
- **扫描清单不能只喂 `.env`。** 硬编码在示例代码里的真实口令 `.env` 里没有，只有把「从代码里挖出来的真值」也写进清单才验得出来。
- **占位符必须在打码前先「摘出来保护」，光靠白名单放过不够。** `[XXX-REDACTED]` 形式统一了，但打码规则仍会咬到自己生成的占位符，两种实测咬法：① **标签紧贴占位符** —— `key=[KEY-REDACTED]` 里值类允许 `-`，于是 `KEY-REDACTED` 被当成口令值再打一遍，行变 `key="[PASS-REDACTED]"KEY"`，**语法当场暴毙**；② 值本身是 `"[XXX-REDACTED]"` 形态时被当字符串字面量吃。修法：`sanitize()` **开头**先用 `\[[A-Z0-9_\-]+-REDACTED\]` 把所有既有占位符替换成哨兵串（`\x01<i>\x01`），全部规则跑完后再还原、最后统一摘哨兵 —— 哨兵同时挡住「本轮新生成的占位符被后续规则再匹配」。
- **口令规则的值字符类不能含括号。** 值类写成 `[A-Za-z0-9!@#$%^&*._\-+/()]{3,64}` 再加收尾引号 `\3` 时，正则会**跨过相邻字符串字面量**：`"key="+PH.format("KEY")` 中的 `+PH.format(` 全在值类里、后随的 `"` 又满足 `\3` → 整段被吃成 `"key="[PASS-REDACTED]"KEY")`，直接语法错。括号从值类里去掉即可（真实口令极少被引号包着还同时含 `(` `)`）。注意这类暗伤**打码邻接自检抓不到**（占位符前是 `"` 不是 `[`/`(`），只有语法门禁能兜住 —— 再次说明门禁是硬性步骤。
- **保留段/文档段 IP 必须进豁免表，否则是内容损失。** `169.254.169.254`（云元数据）、`100.100.100.200`（阿里云元数据）、`100.64-127.x`（CGNAT）、`192.0.2.0/24`/`198.51.100.0/24`/`203.0.113.0/24`（TEST-NET 文档示例）、组播 `224.`/`239.` 都是公知地址，被当活体目标抹掉会让技能里的云元数据/SSRF 讲解直接失能（实测 `"169.254.169.254"` 变成 `[TARGET-IP-REDACTED]`）。豁免判据写成「私有段 + 保留段 + 元数据地址」前缀并列（`192.168./10./172.1|2|3/127./169.254./100./192.0.2./198.51.100./203.0.113./224./239./0./255.`），别只写内网段。
- **占位符必须自识别。** 统一用 `[XXX-REDACTED]` 形式，并把 `[` 开头的串放进白名单，否则二次运行会把占位符再打一遍。
- **`{32,}` hex 会连 md5 示例一起打掉。** 分发副本上「宁可多打」是对的取舍，但要预期哈希示例的可读性损失。
- **目标域名黑名单：采集要宽，入库要严，替换要精确。** 采集正则太宽（把 `.ph`/`.sh` 当 TLD）会让 `wp-login.php`、`crt.sh` 进黑名单、精确替换时照样打坏代码；太窄（只留 `.com/.cc`）会漏真目标（实测漏了 `tgop.me`/`iredcap.cn`/`vjryc.cn`/`lauxanh.us`）。三件套：① 采集用较宽 TLD 表；② 入黑名单前剔除文件名样式（以 `.sh|.py|.php|.js|.md|.json|…` 结尾直接丢）；③ 工具/服务端点（`[FOFA-MIRROR-REDACTED]`、`t.me`、`ifconfig.me`）放白名单，别把**自己用的服务**当目标打掉。
- **口令/密钥标签要分两档：宽标签不能带 `key`/`token`。** `password|pwd|secret_key|apikey` 这档可以直接跟裸值；但 `key`/`token` 只能在**值被引号包着**时才打码 —— 否则 Python 里的 `key=lambda x:`、`.sort(key=...)` 会被打成 `[PASS-REDACTED]`（实测一次打坏 12 个脚本）。
- **值后面必须加词边界守卫。** 光有 `label[:=]value` 不够：`pass = ngx_string("…")` 会把**函数名**当值打掉（口令反而留在括号里）；`key = os.environ[` 会把 `os` 吃掉。加 `(?![A-Za-z0-9_.])` + `(?![ \\t]*\\()` 双重守卫，并靠「已知真值字面量清单」兼容异形值（如含 `()` 的口令 `tgJt2ol!^E)E8(%P`）。
- **别把「自己用的工具/服务端点」当目标打掉。** `[FOFA-MIRROR-REDACTED]`（自家 FOFA 镜像 API）、`t.me`、`ifconfig.me` 这类要进白名单，否则记忆里的“FOFA 测绘 API: [TARGET-HOST-REDACTED]”会变得无法使用。同时把文档占位域名（`t.com`/`x.com`/`target.com`/`example.com`）白名单化。
- **`\b` 是 Unicode 感知的 —— 中文旁边的主机名会被漏采。** `日志<子域>.<目标域>` 这种紧贴中文的写法，中文与字母之间没有词边界，`\b` 不匹配 → 只采到短截 `<子域>.<目标域>`，而正文里是全名，边界守卫又正确地拒绕短截替换 → **整条真目标原样漏出**。修法：采集正则加 `re.ASCII`（中文变非词字符，边界成立）；IP 正则同理。
- **边界守卫不能把 `.` 算进左边界。** 写成 `(?<![A-Za-z0-9_\-.])` 会连 `*.xxx.com`、`${randomSubdomain}.xxx.com` 这类**通配符/模板写法**一起挡掉（它们前面也是 `.`）—— 而防封轮换域名常这么写。正确：`(?<![A-Za-z0-9_\-])(?<![A-Za-z0-9_\-]\.)`，只看紧邻字符和「标签字符 + `.`」两种情形。
- **云厂商域名不能进白名单。** 把 `digitalocean|amazonaws|aliyuncs|oss|s3` 当「知名公共域」放过，就等于放过了**目标自己的 bucket**（实测漏了 `globe-asset.sgp1.cdn.digitaloceanspaces.com`、`vtzi1f-1656-ppp.oss-accelerate.aliyuncs.com`）。这类桶名就是目标身份，必须打。
- **技能库是移动靶：打包前后必须对比快照。** 后台 curator 会在你干活时改写技能（实测 tar 完成后 9 秒源文件又被改了，包里内容比源少整整一节）。构建时对源树做 mtime 指纹、前后不一致就报「快照可能不一致」并重跑；交付前再 `find <源> -newer <tar>` 确认无源文件比包新。
- **构建后必须做「黑名单残留自检」，fail-closed。** 打码代码本身不会错，但**你写的文档/教训文本可能自己引用了真域名**（实测：把真目标墙写进本文件的坑表 → 它自己成了漏网的那一条）。所以写完文件后要再扫一遗：任何黑名单主机若仍在树里出现（带边界），**直接 `exit 1` 不产出**。文档举例子一律用 `<子域>.<目标域>` 占位。 子串匹配会把 `googleapis.com` 判成 `apis.com`、`company.com` 判成 `any.com`、`chinaz.com` 判成 `z.com`；官方示例值（AWS 文档的 `wJalrXUtnFEMI/...EXAMPLEKEY`、`md5('password')`）与自赋值口令（`password=password`）、变量名占位（`token=USER_SESSION`）都不是泄露。用 token 边界匹配 + 白名单把噪声压掉，否则真雷会淹没在假警报里。

## 出厂语法门禁（硬性步骤，漏了就发出坏包）

打码是**静默改坏代码**的（引号/换行/标识符），肉眼看目录完全看不出来。打包前对全树跑，**任一不过就 `exit 1` 中止构建**：

- `.py` → `py_compile` ／ `.sh` → `bash -n` ／ `.json` → `json.loads` ／ `SKILL.md` → frontmatter（`---` 开头且含 `name:`）
- **JSON 一定用 `utf-8-sig` 读**：技能库里真有带 BOM 的文件，用 `utf-8` 解会误报成门禁失败。
- **门禁自己会污染包**：`py_compile` 在每个 `.py` 旁生成 `__pycache__/*.pyc`。顺序必须是「先跑门禁 → 再删 `__pycache__`/`*.pyc` → 最后打包」，否则包里凭空多出上百个 .pyc。
- **改完当场自证**：对「源可编译」的脚本逐个对比「打码后是否仍可编译」，报出「新增语法错误 vs 源本来就坏」，别把源的锅赖给打码、也别放过自己打坏的。

## 验证（不跑就是没做）

1. 已知真值逐条 `grep -rIl` → 全 0（含从代码挖出的口令、`.env` 真值、被打码的目标域名）。
2. 通类正则反向扫：`sk-`/`ghp_`/TG token/JWT/手机号/邮箱/钱包/`[a-f0-9]{32,}` → 全 0。
3. `.env` 每个真值 `grep -rF` 包内 → 0 命中。
4. 人格件、冗余快照、私密主机表 → 包内 0。
5. `gzip -t` + `sha256sum` + `tar tzf | wc -l` 对比源计数。
6. 报告 `REDACTIONS.md`（规则 + 计数，不含被打码的值）随包下发；被打码值清单只留本地。
