# 机械拆段（把超限函数/文件拆到结构闸限内，且不改语义）

## 适用
- 结构检查器/棘轮报「函数 >N 行 / 文件 >N 行 / 嵌套 >N 层」，要求**真降到硬限内**（不是压回基线、不是加白名单、不是删文件）。
- 函数体是大段顺序代码，允许在**语句边界**切开、用显式参数在段间传状态。
- 也适用于：自己写「拆段工装」这件事本身。

## 铁律（每次都适用）
1. **不抑制、不抬基线、不删文件**：判据是 `--fresh` 打出零超限。删文件藏超限会被打回（打包器可能并不按 `_` 前缀过滤「内部脚本」）。
2. **正文逐行搬运、一行不改**。唯一允许的重写是「返回值贯通」（见步骤 4）——任何随手改写都会把回归藏进自测桩的盲区。
3. **拆不出来就拒绝产文件**：单条语句本身超过段上限、带装饰器的函数、类内无 `self/cls` 的方法 ⇒ 直接拒绝，留人工。产出超限片段 = 自己制造新违规。
4. **每拆一条都要过该树自身的自测桩**，不是只过编译。编译过 + 棘轮条消失 ≠ 行为没坏。
5. **每条判定四合一**：拆分成功 ∧ 编译过 ∧ 目标棘轮条消失 ∧ 无新增超限 ∧ **对应自测桩通过**；任一不过 ⇒ 立刻回滚该文件。
6. **工装一改，全部重生成**：修好的工装只影响之后的拆分；先前「已接受」的拆分可能早已静默坏掉 ⇒ 还原 pristine 后全量重拆，不挑不拣。
7. 工装脚本放 scratch 目录，不进发布树。
8. **每条被拒/被回滚的候选都另存一份**（`rejected__<rel>.cand`），验尸必须看真码。
9. **签名原样搬**（手工拆同样适用）：替身/新函数的 `def` 头必须**从原文按字符取回**，默认值、注解、`*args`/`**kwargs` 一个不丢；段函数只用纯参数名。绝不 `", ".join(params)` 重建签名。
10. **靶清单取全量**：结构检查器的 CLI 输出**可能截断**（见坑），靶集合要直接调它的判据函数拿，不能拿它的打印结果当全集。
11. **改文件之前先自检**：候选源码一律先 `compile(cand, path, "exec")` 通过，再落盘（同目录 tmp + `os.replace`）；不过就**一个字节都不写**，候选另存 `<file>.cand` 后退出。「先改源、后自检」= 自检失败也留残骸（半条语句被删、装饰器悬空），比不动更糟。
12. **自检用 `compile()`，不用 `ast.parse()`**：后者不做 symtable 检查，`continue` 不在循环里、`return` 在函数外它一律放过 ⇒ 坏文件照样落盘，只有 `py_compile` 或运行期才炸。

## 步骤
1. **先读判据**，逐条记清：行数按裸行（含空行/注释）还是有效行？嵌套怎么算（`elif` 尾巴算不算、`for/while/with/try` 算不算）？哪些树只查 IP 字面量？只拦「新增/变大」还是也拦存量？工装必须与判据同口径，否则白干。
2. **整树快照**：拆前 `tar czf` 一份；之后所有「这个文件我到底动没动」都用它 `diff` 回答，别靠记忆；拆到全绿再补一份**绿态快照**（后续任何失败都不会吞掉已验收的成果）。
3. **写拆分器（AST）**，形状：段函数 + 替身函数（保留原函数名与签名）+ 调用点。
   - 只在**顶层语句边界**切；段跨度上限 = 函数上限 − **包装开销**（段头 `def …():` 行 + 段尾 `return locals()` 行，签名换行再留 1–2 行）。
   - 段与替身都用**原函数缩进**（类内方法就是 4 格），否则类体被截断 ⇒ `unindent does not match`。
   - 段尾 `return locals()`；调用点 `__S__.update(<段>(…))` 收集；读取一律 `__S__.get('name')`。
   - 段间传递的名字按**关键字**传；替换件把自己的形参也按关键字传下去（方法用 `self.<段>` 调用、形参表不再塞 `self`）。
   - `def` 头用**原文签名文本**（从源码行里从 `def` 抠到配平的 `)`，连 `-> 注解` 一起），段函数用纯名参数表。
   - 调用点**每个实参都惰性传**：`x=__S__.get('x', x)`（`self`/`cls` 直传）。这一条同时解决两件事：条件绑定的名字不会被提前求值，**段内对这些参数名的重绑也能传到后段**。
4. **返回值贯通**（最易漏、后果最隐蔽）：段内 `return EXPR` ⇒ `__ret__ = EXPR` + `return locals()`；裸 `return` ⇒ `__ret__ = None` + 同名两行；只处理**段自身作用域**的 return（不进嵌套 def/lambda/推导式）；跨多行的 return ⇒ 拒绝。替身每段调用后加 `if '__ret__' in __S__: return __S__.pop('__ret__')`。
5. **算准「此段绑定了哪些名字」**：函数级局部名 = **含 `if/for/with/try/except` 块内赋值**、`import`、`except … as`、顶层遇到的嵌套 `def/class` 的名字；**不含**嵌套函数体、lambda、推导式内部（别的作用域）。
6. **批量驱动**逐条跑：拆 → 编译 → 复核棘轮 → **跑对应自测桩** → 过则留、否则回滚到 pristine 并存候选。按路径前缀选自测桩（如 `master/`→master 桩、`bot/`→bot 桩、`collector/`→采集桩）；该树没有桩的，只做前四项，留给最终全量门禁兜。
   - **自测桩的覆盖 ≠ 你改的那棵树**：被改函数的调用方/受影响的产物可能住在**另一棵**树的桩里（改 `master/` 却是 `bot/` 桩报「夹具缺失」）。见到 `NoneType` / 夹具缺失一类症状，先**把全部桩都跑一遍**定位哨兵，再二分：把**单个** pristine 文件还原回去，谁变绿就锁定谁。
   - 工装**拒拆**的条目（单条语句超上限、`return` 跨多行、拆出的段自身仍超限、带装饰器的函数、无 `self` 的类内方法）转**手工拆** ⇒ `references/hand-split-into-new-module.md`。
7. **失败就验尸，不猜**：把候选装回树里，直接跑那条自测桩，**读完整 traceback**。
8. **收尾**：全量门禁（编译/导入/落盘纪律/自测桩/时区封闭/割接机制）全绿 + 结构闸 `--fresh` 零超限，再打包/上线；上线前把「发布/重启」当作独立闸，单独确认。
   - **发布链定序**：打树 → 上传（两侧 sha256 对一遍）→ **`--stage` 先解包**（不做它，`--verify` 直接报「树不存在」）→ `--verify` → `--plan` →（点头后）`--activate`。
   - **配置读的是「被调用脚本自己那棵树」**：要验证**新树**的配置，就用新树的脚本跑（`lib/<rel>/deploy/…`）；用 `current/…` 跑验证的是旧树那份，两者不可互相背书。
   - **割接器把「未归类 crontab 行」当拒绝条件**（`unknown` 非空 ⇒ `★拒绝割接`）⇒ 新加的手工 cron 行必须在割接配置的保留清单（`keep_scripts` 之类，按**脚本名子串**匹配）里登记；受管角色仍走 `new_entries`，别顺手把受管行也塞进保留清单（会逃出割接管理）。
   - **动过测试/桩 ⇒ 必须重打树**：树是按整目录打包的（含 `tools/`），旧树里的旧测试/旧配置会被一起带上线。

## 坑（附机制）
- **`return` 被切进段** ⇒ 它只从**段**返回，替身拿不到返回值而返回 `None` ⇒ 症状出现在**别的**用例夹具里（`NoneType` 下标失败 / 类型不符），你会先去查夹具。⇒ 先按步骤 4 查返回贯通。
- **调用点用 `__S__['x']` 立即求值** ⇒ 原函数里**条件绑定**的名字被提前读 ⇒ `KeyError`；原函数只在该分支里读它，本不会报错。⇒ 一律 `.get`。
- **把「段需要用的名字」并回「此前可绑定集合」** ⇒ 造出幻影依赖、后段 `KeyError`。⇒ 只有前序段真的绑过的名字才进集合。
- **段产出长度只算切片行数** ⇒ 加上段头/段尾/换行签名就超限 ⇒ 自己造新违规（棘轮会以「冒出新超限」的形式当场点出来）。
- **漏算块内赋值** ⇒ 段去读**同名模块全局** ⇒ 静默错值（类型不对才报错，报错位置离病灶很远）。短名（`d`/`n`/`x`）最容易撞全局。
- **工装修完不重生成旧拆分** ⇒ 带病的旧拆分继续留在树里，编译和棘轮都查不出来，只有自测桩能查到。
- **靠记忆回答「我动过这个文件没有」** ⇒ 会把「基线本身陈旧」（基线值 < 现树行数）误记成自己的改动。⇒ 用拆前快照 `diff` 说话。
- **重建签名**（`sig = ", ".join(params)`）⇒ 默认值/注解/`*args`/`**kwargs` 全丢 ⇒ 调用方照旧省略参数就 `TypeError: missing 1 required positional argument`。⇒ 签名从原文取，别拼。
- **段内重绑了参数名**（`cls_dir = os.path.join(pool, cls_dir)`）而调用点写死 `cls_dir=cls_dir` ⇒ 后段拿到的仍是**原参数值** ⇒ 路径算错、写到别处（症状是别的树的桩报 `FileNotFoundError`）。⇒ 调用点一律 `__S__.get(name, name)`。
- **把检查器的打印结果当全集**：显示层可能按类 `[:14]` 截断 ⇒ 标题写「超限 56 条」而正文只列 35 行；驱动拿两次输出做差，看到的是**截断窗口抖动** ⇒ 报「新增超限」假阳性，并且有靶一直隐身没被打到。⇒ 输出条数与标题数不符就先怀疑截断，读原文找 `[:N]`，改成直接调它的判据。
- **就地加 helper 把主文件顶穿**：棘轮对**文件**行数也只看「新增/变大」⇒ 在贴着上限的文件里拆长函数，等于拿一条新违规换一条旧违规。⇒ 外移到新模块（见参考）。
- **先例侥幸**：上一批拆分「过了」不等于方法对，可能只是那些函数恰好没有返回值、或自测桩没查返回值。⇒ 每批都用桩复验，别用上一次的绿灯给这一次背书。
- **循环体抽成 helper ⇒ 循环出口语句失效**：`continue`/`break` 出循环后非法，计数语句（`got += 1`）语义也丢。⇒ 逐条改写成 `return <默认值>` / `return 1` 交回调用方，并把有意改写**逐条列成白名单**做「原文一行不丢」机械对账；`compile()` 只报第一处，白名单对账才抓得全。
- **反缩进必须按「层差」数出来**，不能凭感觉：少一格 `IndentationError`，多一格块提前结束或语法错。搬进新函数前先数该块的嵌套层数，再定减几个空格。
- **`str.replace()` 别当「挪代码」用**：8 空格的针会命中 12 空格行内的**子串** ⇒ 拼接错位（新行插进去了、原行缩进也变了）。⇒ 候选按「原文切片 + 新行」显式拼装，不用子串替换。
- **行数增量对不上就 diff 拆前备份，别推理**：差额可能来自工装行为，也可能来自**被截断/压缩后误读的输出**。一条 `diff 备份 现文件 | grep -c '^<'` 抵十分钟推理。
- **外移产物（零件模块）自己也会超限**：搬运器每搬一个方法多写 ~2 行接线（别名 import、类体别名赋值）⇒ 配额按「每方法约 2 行」留余量，并加「零件模块自身超限即拒收并只回滚本批」守卫。
- **单条巨型字面量语句（99 行 dict 之类）按语句边界切不动** ⇒ 按**条目边界**切片 + 合并壳 `{**a, **b, **c}`，并对账 **key 集合**（条数、无改名），行数不是证据；合并壳里各片的顺序必须与原文一致，否则键的迭代序变、依赖顺序的派发/前缀匹配会错。
- **批量驱动判坏名用确定性逐名判定，不用二分探针**：同参数两次 `rc` 不一致 ⇒ 报「无坏名」把真因盖住。⇒ 逐名跑 + 落日志 + 「只回滚本批 + 打印完整错误」。
- **段边界切在「累加器初始化行」之后** ⇒ 段内 `fired += 1` 的 `fired` 变成段内未绑定的局部名 ⇒ `UnboundLocalError`。`compile()`、结构棘轮、甚至该树的自测桩**可能全绿**（桩不覆盖那条路径、或夹具为空 ⇒ 循环体根本没跑），只有**真调用**才炸。⇒ 抽段时把「段首紧邻的初始化赋值」一起带走；**抽完必须真调用一次**——有原版就做「新旧双模块差分」：同一用例矩阵分别喂旧版/新版，逐字节比结果（本轮 `route` 17/17 一致才算过）。
- **锚点别用 `read_file` 的行号**：显示层行号可能与磁盘漂移（实测漂 1 行，锚点当场失配）。⇒ 锚点按**内容定位 + 唯一性/邻接断言**（`I_IF == I_ROUTE + 1`、块内必须含某特征串），失配即拒写、留 `.cand`。**块边界按 AST 实测重算**（`f.lineno`/`f.end_lineno`）—— 手数行号会差一，把**下一块的 `def` 行**卷进候选块（实测两处这样翻车）；候选块的**首尾特征断言用 ASCII 短尾巴**（`endswith('nid_from_search"]))')`），全角期望串手打易错、错了就是假拒。
- **抽「分支体」时不要把外层 `if` 一起搬走**：搬走后调用点丢掉「未命中则继续往下判」的**落空（fall-through）语义**，原代码不是 return。⇒ helper 落空返回 `None`，调用点 `r = helper(...)` + `if r is not None: return r`，其余分支原地不动；再用新旧差分证明用例矩阵一致。
- **自写的「一行不丢」对账器要对齐判据**：白名单条目与新增行都要 `.strip()` 归一、空行不计入「新增」，否则自己写的 checker 会把自己正确的改动误判为越界，白跑一轮。（实测会连着踩两次 ⇒ 别再手搓：统一在写盘闸里对白名单集合做一次 `.strip()` 归一。）
- **「长度超限」和「嵌套超限」双标的条目不能只切段**：按语句边界切函数会把最深层**原样带进新 helper** ⇒ 新函数继承同一深度 ⇒ 当场判「新增深度违规」（实测：`offline_bk.py::main` 函数 268 行 + depth 6，切出 `_p_watch_b` 后立刻报 `❌ 新增超限 depth`）。⇒ 正确顺序是 **先压平（把最内层块抽成 helper + 缩进整体左移）再切长度**；只做后一半等于拿一条新违规换一条旧的。
- **`try` 体内的最深层不能靠「搬出去」压平**：把 try 体里的语句移到另一个函数，异常就不再被原 `except` 捕获（防御性 `except Exception: print(...)` 会变成向外抛）⇒ 行为变了。⇒ 改**折叠守卫层**：把 `if os.path.exists(x):` 折成 `_existing(*paths)`、把 `g = d.get(k) / if isinstance(g, dict): / for k, v in list(g.items()):` 折成 `_dict_items(g)`，而**业务调用（`add(k)`/`scan(v,1)`）原地留在 try 里**。实测 `collect_tokens` d6→d4 且捕获面不变。
- **切段后 helper 可能引用「原调用者的局部名」，共三种形态**：① 前一函数里 `import` 出来的别名（`import base64 as _b64` ⇒ 不再是同一局部作用域）；② 上一段创建并累计的变量（`tmp`/`old`）；③ 被切段紧跟的初始化赋值。⇒ 三种都必须**显式参数注入、回传，或 hoist 到模块级**；`bind_audit` 能一次把三处静态抓全（本轮报 `_b64`/`tmp`/`old`）。
- **`tools/` 下的脚本/桩按「脚本模式」跑（`python3 tools/foo.py`）⇒ `sys.path[0]` 是该脚本所在目录，`from tools.bar import x` 当场 `ModuleNotFoundError: No module named 'tools'`**。⇒ 照树里既有范式写**同目录裸名导入**（`import foo_parts as _alias`），并且**放在文件尾**（在 `sys.path` 设置与模块级名字定义都完成之后、`main()` 之前），带 `# noqa: E402`。
- **把方法拆进新模块时顺手自造了「零件模块」⇒ 失败回滚要连同它一起删**（它属于工装产物，不是树里的正品文件；「绝不删文件」红线只保护原始文件）。半截 parts 模块留在树里会被打包收进去。

- **helper 文本的基准缩进必须为 0，插入时再按目标 `def` 的 `col_offset` 统一加缩进**：把已带 4 格缩进的 helper 文本再喂给 `at_indent(text, 4)` ⇒ 变成 8 格 ⇒ **helper 被插成「目标函数内部的嵌套函数」**（实测：三个方法全插进 `Worker.probe` 体内）。`compile()`、`bind_audit`、结构棘轮**全绿**（嵌套 def 合法、深度只加 1 层），只有真调用 `self._record_pkgs(...)` 才 `AttributeError: type object 'Worker' has no attribute '_record_pkgs'`。⇒ ① helper 文本基准缩进 0；② **写盘前必须加 AST 结构断言**：新 def 名字能在「目标类/模块的 `body` 直接子节点」里按名字找到，且 `col_offset == 目标 def 的 col_offset`，否则拒写。
- **插入点按 AST 定位，不要按签名子串**：`src.replace("    def pull_packs(self, ", …)` 遇上无参签名（`def pull_packs(self):`）就 **0 命中** ⇒ helper 根本没插进去，而「一行不丢」对账会把被它调用的正文判成「丢失」而拒写（闸挡住了，但白跑一轮）。⇒ 一律 `ast.walk` 找 `FunctionDef` + 用它的 `lineno`/`col_offset`，并对重名断言唯一。
- **折「记账体」压平深度时，外层的 `if` 必须一起折**：只把 `if` 的 body 搬进 helper、`if` 留在原处 ⇒ 那个 `if` 仍是第 5 层 ⇒ 深度一点没降。⇒ helper 首行写 `if <反向条件>: return`，调用点变成裸调用（等价改写、列入白名单）。
- **同构条目批量落地**：5 条「只被标嵌套」的条目可以一个脚本一次做完（每文件独立闸 + 独立 pristine 备份 + 独立写盘）——**某一段失败不影响其它段**（本轮 bk 段被拒时 1/2/5 已落地）。但失败原因必须**先 dry-run 打印完整对账 diff** 再改，别猜（本轮真因是「插入点 0 命中」而非白名单）。

- **压平之后要 `--freeze` 收紧基线**：棘轮默认只拦「新增/变大」，修好的条目会一直挂在「基线内超限」里 ⇒ 每批修完立刻 `--freeze`，下一批的「已修好 N 条」才是真读数（本轮 17 → 12）。
- **真调用冒烟要覆盖每个抽出的 helper**：本轮 10 项断言（`_overlay` 只并入有效值 / `_pid_cmdline_has_guard` 异常不抛 / `_record_pkgs` 空列表不落库 / `_acct_promote` 两分支 / `_record_hit` 幂等 / `_merge_st` 忽略非 int）；★`self` 未被使用的 helper 可以传 `None` 当 self 直接调用，需要属性的用 `types.SimpleNamespace` 造假 self。
- **方法归属要先查**：同一文件里 `probe` 与 `pull_packs` 可能属于**不同的类** ⇒ 冒烟里用「按方法名找类」而不是拿一个类套全部方法。
- **外移「嵌套闭包」时只搬函数体、剥掉 `def` 行**：把整块（含 `def gap():` 那一行）塞进新 helper 体内 ⇒ helper 变成「定义一个嵌套函数、然后隐式 `return None`」⇒ 它**什么都不做**（实测：间隔/休眠 helper 被架空、取值 helper 恒返 `None`，所有调用点静默走空分支）。`compile()`、结构棘轮、`bind_audit` 全绿。⇒ 候选先 `splitlines(True)[1:]` 去掉 `def` 行再 dedent/indent，并加 AST 断言「helper 体内无嵌套 def」。
- **`ast.walk(fn)` 把函数节点自身也算进来**：`[x for x in ast.walk(fn) if isinstance(x, ast.FunctionDef)]` 恒非空 ⇒ 「体内不得有嵌套 def」这条守卫对每个函数都假报，你会先去查代码而真因在断言。⇒ 断言写 `x is not fn`。
- **替换与插入的顺序：先在源文里替换掉原地的旧块，再插入 helper 文本**：反了 ⇒ `replace(…, 1)` 命中的是 **helper 自己那份**副本 ⇒ helper 变成**自调用**、原块仍留在原函数里，而「一行不丢」对账因**行多重集不变**照样全绿。⇒ 除对账外再加结构断言「新 helper 存在 ∧ 原函数行数确实下降」。
- **改写与计数一律「缩进无关」**：`str.count("            return x")` 是**子串**匹配 ⇒ 更深缩进的行也命中、docstring 里出现同串也计入 ⇒ 假数（据此写的断言会假拒/假过）。⇒ 改写用 `re.compile(r"^(\s*)return x\(", re.M)` + `sub(lambda m: m.group(1) + …, …)` 保留各行自身缩进；计数走 AST（`ast.Return` + `ast.Constant.value == …`）。
- **helper 把失败返回从 `return 1` 改成 `return None` ⇒ 调用方必须「先判空、再解包」**：写成先解包再 `if p is None:`，在「无输入/无票」路径就是 `TypeError: cannot unpack non-iterable NoneType`。同族：返回**哨兵值**（`"stop"` 之类）的 helper，调用方要「收到哨兵才收尾」，冒烟也必须断言**等于哨兵**——写成「不等于哨兵」是把语义写反。
- **抽「`except` 处理块」切段/压平时，失败返回必须留在 `ExceptHandler` 体内**：pristine 里 `return None, []` 只写在 `except` 里、成功路径一路往下走；抽成 helper 后写成**无条件** `return None`（落在 `if` 体内而非 `except` 体内）⇒ 正常路径恒空转、下游整条链废掉，而 `compile()`、结构棘轮、绑定审计**全绿**。⇒ ① 失败 `return <空值>` 写在 `except` 体内，成功 `return <结果>` 写在函数末；② 写盘前加 AST 断言「该 helper 至少一个 `Return` 落在 `ast.ExceptHandler` 体内，且函数末尾存在成功路径 `Return`」；③ 冒烟必须**成功/失败双路径**都断言——只测失败路径会把这颗雷留到线上。
- **冒烟断言失败先按原文核语义，优先怀疑夹具**：夹具常按直觉写，而真代码有阈值/截断/记账语义（`depth > 2` 才算、少一个输入文件就换分支）⇒ 症状像代码坏、真因在夹具期望。⇒ 先 `sed` 读被测量函数的原文再决定改哪边，**不要为迁就夹具去动被测代码**。
- **撞文件行数上限 ⇒ 宿主 + `<name>_parts` 模块 + `bind` 注入宿主函数**：宿主把新拆出的 helper 全放 `_<name>_parts.py`，自己只留 `import <name>_parts as _P` + 瘦身后的 `main`（逐行 `_P.<helper>(…)`）；parts 反向需要的宿主函数（`fill_entry`/`packs_of`/`scan` 这类用宿主模块常量与连接池的）**不 import 宿主**，由宿主机在**所有 def 之后**调 `_P.bind(sys.modules[__name__])` 注入。⇒ ① 别写 `import <宿主名>` 或 `sys.modules.get("<宿主名>")`：脚本模式下模块名是 `__main__`，这两种写法会把整个文件**再执行一遍**成第二个模块对象；② `bind` 放模块级（`if __name__` 之前）⇒ 当模块被导入时也自动绑定；③ parts 侧用 `fill_entry = None` 模块级占位 + `bind` 里 `global` 覆写 ⇒ 调用点保持原文、绑定审计也不报未绑定名。详见 `references/hand-split-into-new-module.md`。
- **白名单要防腐化**：机械对账里每条白名单都要回查「实际是否仍缺」，**已不缺的条目当场报错**（白名单尘封），否则它会随原文演变成橡皮章、把真丢失一起吞掉。⇒ 对账器分三列输出：缺口（未被白名单覆盖）/ 违规 / **尘封白名单**，三列全空才允许落盘；每条白名单都必须写「原行 ⇒ 新写法」的理由注释。
- **先沙箱装配、再写树**：拆分器加 `--out <dir>`，把宿主 + parts 先写进 scratch 沙箱 ⇒ 在沙箱里跑完备套「新旧差分 + 真调用冒烟」再 `--write` 落树。写树前的任何失败只脏 scratch，不脏树（也就不必回滚树）。
- **冒烟桩按「真实请求路径」匹配，别按裸路径**：传输层会给路径加前缀（如 `/business-proxy/business`）⇒ 桩按 `startswith("/notice/…")` 一律落空、整批场景走兜底分支 ⇒ 集体「失败」，真因却在夹具。⇒ 桩改用**后缀/子串**匹配，并先打印一条真实路径核对。
- **改工装/脚本别用「heredoc + `str.replace` + `\n` 精确匹配」**：文件是 CRLF ⇒ 一处不匹配 ⇒ **整批编辑一处都没生效**（白跑一轮）。⇒ 用模糊匹配的 patch 工具，或 `re` + `re.M`/`\r?\n`；每处替换都先 `assert s.count(old) == 1`、替换后 `compile()`。
- **跨平台假红三族（本地 Windows 跑 Linux 侧闸时先查这三样，别先怀疑自己的改动）**：① **路径分隔符** —— `os.path.join("/opt/v6","v6m.py")` 在 Windows 出 `\`，于是「自家行」判定（`LAUNCHER in 行` 这类子串匹配）**永不命中** ⇒ 受管块识别 0 行、多行误判 `unknown`、连锁一片红，而真机 Linux 本来就是绿的；② **行尾** —— 夹具快照被 Windows 写成 CRLF，`read` + `split("\n")` 读出的行尾带 `\r` ⇒ 块标记/模板比对失配（读夹具一律 `rstrip("\r")`）；③ **`PYTHONPATH` 分隔符** —— Windows 是 `;`，写 `PYTHONPATH=.:deploy` 会被当成**一个**条目 ⇒ `ModuleNotFoundError` 看着像代码坏、其实是跑法（本地固定写 `export PYTHONPATH="D:/<树>;D:/<树>/deploy"`）。修法一律是**只在比较前归一化**（真机是空操作），**不要**去改生产侧的路径拼接。
- **拆分出的 parts 模块各持一份模块级常量副本**（`LAUNCHER`/`BLOCK_B` 这种模块级 `os.path.join` 结果）：桩/mock 只覆写**宿主**那一份**无效** —— 每个 `import` 它的模块都按自己的全局名解析 ⇒ 必须遍历同族全部模块（`<name>*`）逐个覆写。这是「外移成 parts 模块」的结构性副作用，拆完写桩时必踩一次。
- **陈旧的闸断言要「重新点名」而不是删**：断言常把常量写死（`"return -1" in src()`），生产侧重构后（改成 `return 0 if run() >= 0 else 1`）它变红但**意图仍成立**。⇒ 先读生产代码确认语义（失败仍给调用方非零退出码？），再按**真实契约**重新点名（`">= 0 else 1" in src() and "raise SystemExit(main())" in src()`）保持严格；删断言、放宽成恒真、或直接判「测试陈旧」放着不管，都是把闸变成橡皮章。
