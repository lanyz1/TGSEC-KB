# 权威字段源与补丁差分

> 落盘时逐字段取真值、在野洞抠真根因。铁律：只写这些源里真实存在的字段；拿不到写「未取到」。

## 1. 字段源（按可信度）

| 要什么 | 源 / 形态 | 注意 |
|--------|-----------|------|
| 描述 / CWE / 参考 / CPE / 受影响版本 | 官方 CVE 数据库 API（如 `cveawg.mitre.org/api/cve/<CVE-ID>`） | 比详情页早，且带 CNA 原始字段 |
| 严重度 / 向量 / 来源 | API 的 `metrics[]` | CNA 口径（厂商自评 / CVSS-B）与权威库口径常不一致 → **两个都记**，别只留一个 |
| 概率评分（EPSS） | 评分方批量端点（逗号分隔、无鉴权、不占测绘配额） | 新条目常无分；命中率 3–5/10 正常；未评分**留空**不填 0 |
| 在野 / KEV | KEV 目录 + API 里的引用 | 日期取不到就留空，并在 tags 写「KEV」，不在日期字段编值 |
| 发行方影响面 / 状态 | 发行方 bugzilla REST（单 bug JSON） | 字段：summary / severity / status / component；`NEW` = 尚无公开补丁 |
| 真根因 | 公开修复 PR / commit | 见 §2 |
| 影响面 / 修复级别 | 厂商安全通告页 | 路径形态举例：`<厂商安全站>/…/security-advisories/<年>/<通告号>/`、`helpx.adobe.com/security/products/<产品>/<apsb 编号>.html`、公告 node 编号页 |

## 2. 补丁差分：在野洞必做

1. 抠线索：`PR #` / `commit <sha>` / 版本更新级别（Update Level / patch level）。
2. 拉素材存 `tmp/patches/`：GitHub PR → `<PR 链接>.diff`；commit → `<commit>.patch`。
3. **只读三处**（其余是噪音）：
   - catch 分支：`catch (X) { log; return; }` → 异常被吞、请求继续走 = **fail-open**，真根因多在此。
   - 校验失败后是 `return`（放行）还是 `throw`（拒绝）。
   - **回归测试断言** = 探针判定基准（照抄，不自创）。
4. 产出三处：手法卡「根因（补丁实证）」段 · 报告表格真根因一行 · 探针判定基准注释。
5. 类级化：把结构模式记成可横向试的试法，而不是记住单个编号。

## 3. 拿不到 PR 时的替代素材

- 只有版本号：下修复前后制品逐行 diff（插件类常有约定下载路径可取任意版本）。
- 只有 bugzilla 且 `status=NEW`：**无公开补丁** → 不编 PoC，走类级变体表，交付写明「无补丁」。
- 桌面/解析库类：修复 commit 的 `.patch` 通常就是根因（如「未校验长度字段 vs 帧数」的越读）。
- 滚发布、无版本号的产品：退回指纹 + 写法定性，不硬套版本区间。

## 4. 证据分级（写进交付时）

1. 本机实跑（探针输出 / 命中日志）
2. 官方通告 + 补丁 diff
3. 官方 CVE 数据库字段
4. 二手转述 —— 不写

跑不通的只做结构校验并标注「未执行」。
