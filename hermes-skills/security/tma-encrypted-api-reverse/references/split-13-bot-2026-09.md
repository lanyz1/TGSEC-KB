## ★★ bot 内联键盘状态机 + 业务限制「四组对照」测绘（2026-09 实战增补）

- ★★ **支付密码/金额类输入是 bot 侧【内联数字键盘】，不是文本**：`fp_set` 后页面回「请设置 6 位数字支付密码…○ ○ ○ ○ ○ ○」+ `pin_d:0..9` / `pin_back` / `pin_clear` / `pin_ok` / `pin_cancel`。**发裸文本会被忽略**（bot 回「请使用下方数字键盘输入支付密码。」），而探测端若不读回显，极易把「已发送」误判成「已输入」⇒ 必须按序点 `pin_d:<digit>` × 6 → `pin_ok`，随后**再重复一遍确认** → 「🔒 支付密码已设置」（此时才可由文案确认成功）。键盘消息 **id 不变、原地编辑**，所有点按都发往**同一个 `msg_id`**。
- ★ **设置类动作先导航到入口再点子键**：入口链 `个人中心`→`pf_fp`→`fp_set` 三步不可省；漏掉 `fp_set` 那一步 ⇒ 键盘根本不存在，之后发多少文本都无效（错误现象 = bot 答非所问）。
- ★★ **业务限制必须做「四组对照」才可坐实为漏洞**：取 `下限以下值 / 0 或负数 / 下限值 / 超余额值` 四组打同一接口。实测余额宝声明 `10 ~ 500000`：`0`、`-1` ⇒「金额格式不正确」（格式校验在），`10` ⇒「可用余额不足」（余额校验在），而 **`0.5` 与 `1` 直达确认页**（带 `yb_ok`）⇒ **下限校验缺失坐实**，缺口区间 = `0 < 金额 < 10`。★ **单发一个值命中不算漏洞**：必须靠 `0/负数/超限` 三组排除「通用放行」，并**用同类接口做对照组**（同站闪兑 `sw` 对 1 USDT 正确回「未达起兑金额，单笔最低 2 USDT 等值」）—— 有对照才排除「业务设计如此」。
- ★ **确认键 = 资金闸门,也是探测边界**:所有 `*_ok` / `*_confirm` / `pin_ok` 一律**不点**（脚本里用 `BLOCK` 前缀硬拦）。「能走到确认页」= 前置校验全过（可作闸门与缺陷证明），「按下确认后是否真入账」= 需**明确资金授权**；报告必须写**未坐实**,不得写成「已入账」。`pin_cancel` / `sw_cancel` / `yb_cancel` 是零成本复位键，收尾必点，每轮无条件回 `menu_home`/`/start` 复位。
- ★ **账号安全类设置必须查并写清「可还原性」**：设置后**回入口页看按钮** —— 实测只有 `fp_chg`（修改），**无关闭/重置/删除** ⇒ 「恢复原状」只能改成别的值、无法移除（用户偏好恢复原状 ⇒ 这条必须提前告知）。设定值**绝不落档**：走 env 注入，脚本与日志只打印长度/状态，不进档案。
- ★ **误发到会话里的敏感明文必须清掉**：探测期间若把 PIN 之类明文当文本发出去，收尾用 `iter_messages(BOT)` 过滤 `m.out and text==PIN` → `delete_messages` → **再扫一遍复核 0 条**（实测清掉 6 条）。
