## ★★ 领取链(open → verify-segment×N → claim) + 图形挑战自动秒解
> 完整可复用细节(字段表/实测分数/TTL/脚本形态/业务层证据三通道)见 `references/claim-chain-and-challenge-solver.md`。
- ★ **解锁类端点回 `40671`/`40670` 先当「我方 body 缺字段」查,不记「目标防住」**：`open` 的真实 8 字段里**服务端唯一能独立核验的是 `client_ipv4`**(与请求源 IP 对账) —— 缺失⇒`400/40671`,补齐⇒**`200 success`**;其余(指纹/UA/反自动化声明)皆客户端自证。**去 bundle 抄真 body,别猜 start_param**。
- ★ **会话 TTL ~60–73s ⇒ `open→verify×N→claim` 必须同一进程一条命、挑战必须机器秒解**：人工看图必经 `400/40705 会话已失效`。远端 `setsid nohup … </dev/null &` 长驻跑全链,本机只 `poll`/兜底喂答案。
- ★ **图形挑战(目标图标 vs N×N 网格)求解三坑**：① 格掩码要**洪水填充剥掉贴边框线 + 取最大连通块**,❌ **不可盲目内缩**(72px 目标格里图标几乎填满,内缩会切残 ⇒ IoU 全跌到 0.1–0.2、求解器「装死」);② 掩码**保长宽比**填充 128×128(直接 resize 会压扁长条图标);③ 门槛 **`best≥0.62 && margin≥0.15`**(实测 0.945/0.867/0.702/0.671 均判对;门槛定 0.70 会把 0.671 这种判对的答案丢掉)。
- ★ **钱到手只认业务层三通道对账**:API 状态机(`detail` 领前 `remaining_amount 1/active` → 领后 `0/finished` + `claims[]`) + bot 账单流水(`+1 USDT · 红包 · <时间>`) + 钱包余额(首页 `USDT 1.00`、`pf_bal` 可用/冻结/余额宝)。三条一致才算闭环。
