## ★★★★ POST 体必须加密 —— 「安全信道未建立」的真凶（2026-09 增补，踩了 4 轮）

- ★★★ **症状 `40710 安全信道未建立，请重新打开` 几乎总是「POST 体没加密」**：拦截器在 `encryptionEnabled` 时会把 `config.data` 整个替成 AES-GCM 信封 `{iv,data}`（12B IV、无 AAD、紧凑 JSON），**签名对象就是这个密文串**。GET 无体 ⇒ 签空串。
- ★★ **一眼判信道状态：响应是加密信封 = 信道 OK；响应是明文错误 JSON = 服务端没用你的会话密钥）。**
- ★★ **解密要兼容两种信封形态**：裸 `{"iv":…,"data":…}` 与 包在业务码里的 `{"code":…,"data":{"iv":…,"data":…}}`（两个都实现，否则把密文当业务错误体报出去）。
- ★★★ **报「安全信道未建立」时先查三件事，别先去改握手**：① POST 体是否加密 ② 签名对象是否=密文 ③ 载荷字段是否齐全（**从 bundle 抄调用点，不要按记忆背**；本族 open = 8 字段，漏 `user_agent`/`automation_suspected`/`automation_hits` 一样能过，但字段不齐时的负结论无效）。
- ★★ **公开面/会话面分开建模**：本族 `GET rp/detail?token=<裸载荷>`、`GET media/bg?token=<裸载荷>` **无需会话**就能吐 `sender.user_id`、包状态、`cover_url`（常含云存储桶名 ⇒ 资产/供应链线）。先榨公开面，再去开加密会话。
- ★★★ **载荷 token 结构可对账**：`rpl_` + base64url(6×0x00 ‖ uint16 BE packet_id ‖ 10B 随机)。实测解出 `0x1D6D == 7533 == detail 里的 packet_id` ⇒ 格式对、**不可伪造**；而“枚举 token 抢他人包”是第三方资金红线，不做。
- ★★ **错误码新两枚**：`40673 红包已被抢光`（业务层前置闸门，会遮住后置字段校验 ⇒ 拿它当负结论无效）· `40710 安全信道未建立`（体解密失败/会话未建）。
- ★ **TG 枚举必须算预算(否则烧掉整个号库账号)**:`contacts.ResolveUsername` / `contacts.Search` 是 Telegram 反爬重点对象。累计几十次(short-name oracle 144 名 + bot 用户名两轮 + 全局搜索 8 查询)后,该账号会收到 **`FloodWait 74,800s(≈20.8 小时)`** 的账号级惩罚 —— 解不开、不会随重试缩短,**继续敲会升级为账号永久限制**。处置:① enumeration 前先规划总量并**写入账本**(每个账号上限 ~30–50 次查询);② 同一账号的 `.session` 副本**共享**惩罚(惩罚在账号不在文件),所以**不能让多个副本并行刷**;③ 被罚后**立即停手等 ~21h**,改走无需 TG 的向量。
- ★ **同路径两个 md5 ≠ 有两个前端**(1095B vs 728B 之谜):先做**头部差分**（同一随机路径 × 无 UA/浏览器 UA/curl UA/`Accept: application/json`/cookie)。**差别仅 Cloudflare Insights beacon 注入**（带 `Accept: application/json` 时无 beacon、体积小 ~350B）是常见真相 —— CF 按 Accept 注入 beacon。**先排掉这种噪声再谈「另有一个 SPA/管理端」。**
