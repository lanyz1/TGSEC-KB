## ★★★ 路由面「穷尽」判定：方法矩阵 / 异常码 / 主机名 oracle（2026-09 实战增补）

- ★★★ **任何「路径不存在」的结论都必须过方法矩阵**：Go/Gin 对**方法不匹配默认回 404**（不是 405）⇒ 只发 GET 的扫描**结构上漏掉全部 POST-only 路由**。实测同一前缀下 `handshake`/`rp/open`/`rp/claim`/`rp/verify-segment` **全是 POST-only**，GET 下全部表现为 `404 18B`（与「不存在」完全同款）；换 POST 立刻回 `401/40701`。**同一坑一轮内踩了三次** ⇒ 收尾扫描一律 **GET+POST 双轮**，并**用已知端点当正控**（正控全中才允许下「只有 N 个端点」的结论）。
- ★★★ **`520` / `404-0`(空 body) / `000` 一律不得单发定论**：这三种读数都可能伪装成「路由存在但 handler panic」。判读三步：①**同窗口随机路径对照**（同时段随机路径也出现同款 ⇒ 噪声）；②**同路径 ×3 复测**；③**换 body 形态**（空 / `{}` / 带假 token）。实测 8 条「疑似命中」(520/404-0) 三法齐下后**全部回落 404/18** ⇒ 全是 CF 瞬时错误，零真端点。**⚠️ 反例教训：把 520 当「存在性信号」上报 = 假阳。**
- ★★ **CF 错误码即主机名存在性 oracle**：向 CF 发**未注册的 Host 头**一律回 **`530` / body `error code: 1016`（17B）** ⇒ 这是干净的「该主机名不在 CF」判据（比 DNS 爆破更可靠，且能发现**没有 DNS 记录但被 CF 代理**的名字）。**自检**：落盘后统计「真 1016」比例（实测 193/194，唯一非 1016 即真实主机）⇒ 负结论才成立。**局限：仅对橙云（代理）记录有效，灰云 DNS-only 记录测不到** ⇒ 灰云必须另跑 DNS A 爆破。
- ★★ **CF 不强制 SNI = Host**：`SNI=a` + `Host: b` 会按 **Host 头**路由到 b 的 origin（实测 `SNI=mch` + `Host: redpack` → 回 redpack 的 app 响应）。⇒ ① 这是**伪造 Host 头打 origin** 的原语；② 但**任意未注册 Host 会被 1016 挡死** ⇒ 无法用它枚举 origin vhost，只能探「已知存在的名字」。**附带**：`Host: localhost` → origin nginx `403`（显式默认 vhost 拒绝），说明该 origin 无绝对重定向泄 IP。
- ★★ **DNS 解析器只取 Answer 段的 `type:1`(A)**：DoH 响应的 **authority 段 SOA** 会被宽松 grep 当成记录 ⇒ 造出假子域（实测把裸词 `ws` 当 TLD 查出 `.ws` 顶级域 IP）。更稳的写法是**只提取 IPv4 字面量**（A 查询的 Answer 才有 IP，SOA 段只有域名+序列号）。**且必须带正控**（已知主机 → 期望 IP；不存在的名字 → 空）。
- ★★ **A 记录过滤器结构上看不到悬垂 CNAME**：目标不解析的 CNAME **没有任何 IPv4** ⇒ 在「只报有 IP 的候选」里**完全隐形**，会漏掉**子域接管**候选。⇒ DNS 收尾必须**单独跑一轮 CNAME/NS 扫描**（零 CNAME/零 NS 委派才可断言「无接管候选」）。
- ★★ **服务端端点集 = bundle 函数集，是「证明闭环」而非「猜测」**：按 bundle 里发起请求的函数个数（5）定「服务端只有 5 个端点」，再用 **GET+POST 双轮前缀扫描 + 5 端正控**在全网侧证伪一切隐藏端点（130+ 词 × 2 方法 = 0 命中）⇒ 这是比「bundle 只调用 5 个」**硬得多**的闭环证据。
- ★ **只读扫描的负结论必须同时给「工具有效性自检」**：每个 oracle 都要有落盘统计（如「194 件里 193 真 1016」「正控 5/5 命中」）⇒ 否则「全 0 命中」只能记**不可判定**。
- ★★★ **`xargs -P N -I@ sh -c '... "@" ...'` 会把词表内容二次展开**：路径里含 `${data.id}` 这类 **shell 展开语法**的条目会让 `sh` 抛 `bad substitution` 并**静默跳过**（日志只有一行报错，探针总数照记「跑完」）。实测 487 词里藏了 **40 条从未被探过的词** —— 不做盘账，「0 命中」就是假结论。⇒ ① 收尾必经**按内容哈希盘账**（`bd/<md5(word)[:8]>_<method>.txt` 逐条反查，不依赖日志）；② 补齐时**不经 shell 传参**（subprocess 数组，或 `sh -c '... "$1" ...' _ "$w"`）；③ 同样按内容哈希做「探针总数 vs 有响应数」对账。
- ★★ **`000`（curl 无响应）= 通道失败，不是「不存在」**：探测机/代理/CF 边沿抖动会让**已知存在**的端点也回 `000`（实测同一已知端点连打 3 次：`401/63 · 401/63 · 000/0`）。⇒ 收尾必须**逐轮幂等补齐** `000` 条目，并用**同窗口正控**证明 `000` 属通道问题；最终把「未命中」升级为「**N/N 覆盖率下 0 命中**」才算可判定。
- ★ **本机 Windows git-bash 的 curl 是原生程序**：`-o /tmp/x.txt` **写不进文件**（MSYS 路径不转换，`md5sum` 取空、body 取不到，但 `%{size_download}` 仍有效）⇒ 落盘一律用**相对路径**；`000` 行的 body 不是本次响应（curl 失败不写文件）⇒ **永不作为证据**。
- ★ **「无路由的 Go 服务」也是结论**：某主机（如 `mch.*`）487 词 × GET/POST 全 `404/18`、随机路径对照同款、异常码全部证伪 ⇒ 判**纯 API vhost / 服务端到服务端 webhook 接收端**（路径含密钥不可枚举），停止投入，别当「还没扫到」。
