## 可攻击点(拿到合法身份后)
- **反自动化字段常全部客户端自报**:`automation_suspected`/`automation_hits`/`device_hash`/`client_ipv4` → 直接伪造声明「非自动化」,平台不可检测。
- **验证与领奖分离**(`verify-segment` 与 `claim` 两接口)→ 测跳过验证直接领、金额篡改、同 session 重放。
- ★ **claim 类端点的「前置顺序」判别式**:送 invalid / drained / **缺字段** / **类型错** 四种载荷,若**全部回落同一错误码**(实测 `40709 请先完成验证`)⇒ ① 服务端**强制**先过验证段(非前端拦)、② token 校验排在验证**之后**、③ **该面无 oracle**,不要再堆探针;要打必须先拿到真实挑战态(`challenge_id`/`index`/`answer`)。
- ★ **无效对象还分「无区分度 / 有区分度」**:`open` 对 `token:12345(int)`、缺 token 字段、空 body、无效串 **全回同一码**(`40671`)⇒ 实现是「先查存在性、后校验」两段式,类型/空值混淆打不进。
- **token/MAC 型解锁链接不可枚举**:批量改 ID/后缀若返回**同一错误码**即服务端 MAC 校验成立,立即收手换面(有 oracle 才会出现差异码)。
- **IDOR 差分法(判「有无对象级授权」的干净手法)**:同一 handler 送**不存在的 id** 与**已知真实 id**,再叠加参数改名/无参共十余种变体。**若全部变体错误码完全一致 ⇒ 服务端忽略一切 id、只认 MAC token ⇒ 无 IDOR**,一次关闭该面,且不必触碰真实对象(零资金/状态副作用)。
