# OCR 摘要正则与清洗规则（实战定型）

第二遍 digest：扫 `ocr_out/*.json` 的 `lines` 拼接文本，抽取 + 清洗 + 溯源。

## 抽取正则
- **电话（国际前缀族）**：`\+\s?(?:52|51|258|212|57|30|225|380|44|49|54|55|91|7)[\d\s\-\\(\\)\.]{8,16}`
  - 归一化：只留数字；国家码族按长度白名单（MX 12 或 13 位、GR 12/13、MZ 12、PE 11、IN 12 等），其余丢弃。
- **标签邻近式**：`(?i)(?:tel|telefono|teléfono|cel(?:ular)?|whatsapp|wa\.me|phone)[\s:\.]{1,6}(\+?[\d\s\-\.\(\)]{10,16})`
- **CLABE（墨西哥银行账号）**：`\b\d{18}\b`（18 位连号；注意先剔除电话族命中避免重叠）。
- **CURP（墨西哥身份证）**：`\b[A-Z]{4}\d{6}[HM][A-Z]{5}[A-Z0-9]\d\b`
- **邮箱**：`[\w\.\-]+@[\w\.\-]+\.[a-z]{2,}`（小写化）。

## 伪影过滤（必做）
- 长度不合国家族规则的直接丢。
- 连续 0 段：`0{6,}` 或国家码后 `^0{2,}` = 面板碎片，丢。
- **同尾号重复**：同一个 9–10 位尾串在不同前缀下反复出现（如 `X907100900`）= 长串被按不同窗口截断的碎块，整族丢。
- 明显的 UI 坐标/时间戳串（全同数字、`000...`）丢。
- 保留策略：宁缺毋滥——进入交付件前人工抽看头部若干条。

## 输出结构（溯源映射）
- `{ 值: [来源文件basename或工单ID, ...] }`，每类一份 JSON（phones/clabes/curps/emails）。
- 合并进总表时按「值」去重，来源并集；报告中数量按去重后口径。
