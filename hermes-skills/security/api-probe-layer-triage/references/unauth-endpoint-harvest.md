# 从公开页面 JS 榨出"登录前动作集"(未认证面高产地)

登录/注册/落地页是**公开静态资源**,无需任何凭据即可收割。它们内联的 JS 里写着业务上"设计成登录前可调"的动作名与**逐字参数形状** —— 这是命中未认证面的最高产地,优先于枚举。

## 步骤

1. **抓页面并确认栈**:`GET /register.html`(或 `/login`、首页)存盘。看 `<title>` 与引用栈(jQuery/Vue2/Vant/vue-resource ⇒ 遗留 Thymeleaf 式站点;`/assets/entry/*.js` ⇒ Vite SPA),决定下一步抽哪种调用点。
2. **抽调用点**:用 **Python 读文件 + 正则**,**不要用 grep**:
   - 模式:`\$http\.post\('(/[^']+)'`、`\.(post|ajax|get)\(['"](/[^'"]+)`、`fetch\(['"](/[^'"]+)`、`axios\.(post|get)\(`
   - 每个命中打印**前后各 250~300 字符**上下文。grep 的 `.` 通配在 UTF-8 长行上会失配、直接返空输出,别据此判"没有调用点"。
3. **记下逐字参数形状**,不要另起字段名穷举:
   - `post(…, {})` 空体 ⇒ 设计为**无上下文调用**,未认证命中的概率最高。
   - 带固定值的字段(`{businessType:'register', areaCode:'0091', smsType:'otp', needIp:'1'}`)直接复用 —— 这些固定值是服务端分支的入口,比猜字段名快一个数量级。
   - 页面里被**注释掉**的调用点常留着老路径/老前缀(如 `/pfv2/…`)⇒ 新命名空间线索。
4. **测试矩阵**:每个候选 × **3 轮** × **2 变体**。
   - 变体 A:**完全不传 Cookie 头**(不要用 `-b <空文件>`,二者实测不等价)。
   - 变体 B:同 A + `Referer: <该页面 URL>` + 移动 UA —— 有些口按来源校验;**变体 B 命中 = 可绕过的来源校验**,单列一条。
   - 每组必须带对照:一个**已知需登录**的口 + 一个**已知未认证**的口。
5. **判据**:只有**有 body 的响应**才算证据。分类用业务文案:`success:true`/有 `data` ⇒ 未认证可读;`please sign in`/`code:999` ⇒ 需会话;业务校验错(`xxx cannot be null`/`not exist`)⇒ **已穿透到业务层 = 未认证可达**;`0B` 记**第三态**,不可判阴性。⚠️ 若该栈的会话是 **body 字段**(如 `sessionKey`),"未认证可达"必须用**显式空凭据**(空串,不是缺字段/null)复测一发再落栏 —— 缺字段会走判空 NPE 兜底、可能短路在凭据检查之前;通用兜底码(`系统繁忙` 类)一律记**不可判**,不得记"无认证"(详见 SKILL.md《空体全表扫》)。
6. **绝不实测的**:带真实手机号/邮箱的发码口(会真发短信/邮件)、提交/任务完成类写操作 ⇒ **只登记参数形状,不调用**。

## 反面清单

- **不要拿"jar 里没有 cookie 行"当无票证明** —— jar 会被复用污染,且限速潮会让整批返 0B;无票对照只认"不传 Cookie 头"。
- **签名算法通常不在这类页面 JS 里**:前端只负责发字段,签名在 App/网关侧(自研 MD5 盐类)。扫过页面 JS 与公共 `common.js` 无命中即可负向结案,别继续在这里耗轮次;要签名就去 APK/客户端。
- **同族动作名跨域不可混用**:A 侧管理端 bundle 里的动作名不等于 B/C 侧(`/zf/…`)动作名;两者命名空间、cookie 名、会话都不同,结论不可互推。
