## 让探针自证失败(下阴性结论的前提)

整批探针统一报同一个错时,**先怀疑自己**:

1. **整批必须留一个已知-good 端点作对照**。它没返 200,就是探针 bug 而不是目标防护。
2. **路径拼接单一来源**:统一 `BASE + path`,禁止逐行手写路径。漏拼 base path 前缀(`/v3`、`/api/v1`)会让整批假性 401/404 —— 补上前缀后常直接翻出免鉴权面。**前缀必须从客户端 bundle 取**(`window.baseURL='/api/'` 赋值、`_app.config.js`、请求构造函数里的字面量),不要靠猜;一大批 404 先怀疑前缀,再写"路径不存在"。
3. **Header 名 / 字段名逐端点核实**,不跨端点套用。
4. 修正前缀、方法、字段名后**重跑同一批**再下结论。
5. **自检谓词本身,不只自检响应**:整批阴性时必须怀疑"判据有没有真的触发过"。实测一次事故:请求器把状态码返回成**字符串**,脚本写 `if c == 200` ⇒ 恒假 ⇒ 一整个页面族枚举报"一个都没有",**看起来像一次干净的阴性**,真因是类型契约。规则:①状态码进判据前先 `int()` 化;②脚本里对**已知-good 端点**跑一次判据并 `assert`(不成立就 `sys.exit(1)`),把"比较逻辑坏了"变成**批次中止**而不是"全阴性";③"整批 100% 阴性"与"整批 100% 阳性"同等可疑,先验证谓词再信结论。

6. **传输形态也是一个载体,响应不随载荷变化时先换传输方式**:页内**同步 XHR 发 POST 会被浏览器弄崩** ⇒ 服务端只回框架默认 500
(`timestamp`/`error`/`path` 的体、**无 `msg`**),与"参数不对 / 密文被拒 / 未授权"完全同形,能骗过整轮字段探测。
判据:同一端点同一载荷,把同步 XHR 换成 `fetch` 再发一份 ⇒ 结果翻转就是传输层问题,不是目标防护。
**读体区分两类 500**:带 `timestamp`/`error`/`path` = 请求在控制器之前就崩(传输/形态/过滤器);带 `msg`/`code` = 已抵控制器(纯业务语义)。
配方见 `webapp-api-crypto-reverse` 及其 `references/x-encrypt-gcm-envelope.md` §5/§6。

7. **★★ 参数的【位置】也是载体，且比 content-type 更容易骗过你**:handler 读 `$_POST`(或 `req.body`)而你发在 **query string** 时,
**你明明传了参数,它照样回「缺少必要参数 / 参数为空 / XXX不能为空」** —— 与「字段名不对」表现**完全一样**,会把你引到错的候选名上反复试。
   - 判据:同一端点、**同一组参数**,query 与 body 各发一发(`?a=1` vs `-d a=1` / `--data-urlencode`),**文案一变即定位置**;
     顺带用 `-X POST` vs `-X GET` 各发一发 —— 方法错与位置错同形。
   - 同族坑(自研 PHP 站高频):同一文件里**不同动作读不同位置**(如 `cache_*` 类读 `$_GET`、业务动作读 `$_POST`)。
     ⇒ **不要用「一个动作通了」推断其它动作的载体**;载体三要素(**路径前缀 / query vs body / form vs JSON vs multipart**)每个动作各自定一次。
     ⇒ 用「一个动作通了」当全族已定载体的证据,是本类任务里最常见的整批假阴性来源。
8. **★ 三类回包必须先分诊,再决定信不信**:同一个「不干活」的响应至少有三种成因,它们的下一步完全不同:
   | 回包 | 成因 | 下一步 |
   |---|---|---|
   | 特征鉴权文案(`无权访问受保护接口` / `not authed`) | **该动作存在且在鉴权层被拦** | 找票/找漏挂,别改参数 |
   | 通用缺参兜底(`缺少必要参数` / `invalid params`) | **动作可能不存在,也可能只差载体/参数名** | 先跑第 7 条的位置/方法 A/B,再跑第 3 条的线上 bundle 反查,**两发都不过才判不存在** |
   | **0 字节 / 空体**(与同批受保护动作的文案不同) | ★**处理函数真的跑了**,只是没拿到输入而静默退出 ⇒ **它是免鉴权可达的** | 补上最小合法输入复测,别写成「无权访问」 |
   |——|——|——|
   ⇒ 归错栏的代价是双向的:把 0B 写成「受保护」会丢掉免鉴权面;把兜底缺参写成「动作存在」会为一组不存在的动作白烧轮次。

### 按头值分流的路由/鉴权闸:批量扫前先做「头值扫描」

`Host` 之外,`X-Forwarded-Host` / `X-Real-IP` / 租户头 / 站点标识头的**取值本身**常直接决定请求走不走应用。典型形态:头值为 `无` 或 `<本站域>` ⇒ 正常处理(免鉴权端点照常回业务体);头值为**任何其它值**(`example.com`/`127.0.0.1`/历史域)⇒ **整站一律回同一句鉴权拒绝文案**,连已知免鉴权端点也一并挡死。此时整批读数长这样:每一行都是"鉴权层",看上去像"全站防护到位"。

- **扫之前先做头值扫描**:拿**一个已知免鉴权端点**,把 `无头 / 本站域 / 兄弟 vhost(admin.<域>) / 陌生值` 四种取值各发一发,把读数写进批次登记,再选**放行值**跑全批。
- **阳性对照必须与被扫批次同头值**:对照端点也回闸门文案 ⇒ **是头值选错或探针 bug,不是"全站收紧"** ⇒ 整批作废重跑。实测代价:一整批 64 个写/执行向端点的豁免扫描因用了陌生 XFH 值而全废,换放行值重跑才得出"只有 1 个端点漏挂中间件"的真结论;若不复查就会把"无免鉴权写原语"这个**真结论**写成"全部被闸"的**废结论**交给用户。
- **同一头字段在不同 vhost 上是不同上下文**(站点 vs `admin.<域>` 后台):两套上下文各自单独扫,结论**不互推**;只在站点域下测得的豁免名单,不得外推到后台上下文。
- **同一平台常有两种闸门文案,各指一件事,不许混读**:`请使用正确的后台路径访问` = **vhost/路径不对**(在站点域上打后台 API);`系统未授权或已过期` = **缺/无效票,或头值不在白名单**。
- 报数三栏:`免鉴权 N / 被闸 M / 无路由 K` + 逐条端点。

### 凭据产物卫生:整批 401 先查「你用的是哪份票」

**整批整齐回框架的「认证失败」文案时,真因大概率不是权限、不是 WAF、不是出口被封,而是你手里的凭据产物过期了** —— 而且是脚本里某个 helper 替你挑的那一份。

- 实测代价:工作目录里同时存在**两份票**(旧 `*_userinfo.json`,被 helper `token()` 读;新 `tok_fresh.txt`,刚铸),整批 `401 认证失败` 被写成「权限不足 / WAF 封杀 / 出口被拉黑」烧掉十几轮;换新票后**同一请求立刻 200 真数据**。
- **规则**:整批 401/认证失败的第一动作 = `ls -l --time-style=full-iso` 列出工作目录**全部**疑似凭据产物(jar / `*token*` / `*userinfo*.json` / `*session*` / cookie 文件)按 mtime 排序 + `grep -n "def token" -A 12` **读 helper 实现**,确认它到底读哪一份;再对**同一请求**发「旧票 / 新票」两发做 A/B。
- **helper 是单点故障**:封装过的 `token()`/`auth()` 把「读哪个文件」藏起来,过期后的症状与「无权限」同形 ⇒ 每轮开工先打印 helper 实际读到的**文件路径 + mtime + 字节数**,而不是只看它返回的字符串。
- **拿不到新旧对照前,401 只算第三态(未知)**,不进「已排除」栏,不得写成结论。

### 空体的第四个成因:反爬/机器人过滤 ⇒ HTML 面一律用真浏览器复核

`200 + Content-Length: 0` 除了「未注册路由」「Host/SNI 选错」「限速潮」,还有第四个成因:**目标前置了反爬/机器人过滤,对脚本客户端一律回空体**(或统一 200)。它与前三种的区别在于:换个客户端就活了。

- **判据:同一个 URL,curl(即便带完整浏览器 UA + Cookie)回 `200/0B`,而真浏览器(CDP 驱动)回完整 HTML** ⇒ 是过滤层,不是应用故障。实测代价:据此把后台登录页写成「应用 HTML 空转、该面关闭」,直到用 CDP 真浏览器打开才拿到 8.8KB 真登录页 —— 整个后台面被误判关闭了一整轮。
- **HTML 页面面的存在性判定,curl 的读数不作数**:页面路由、后台入口、挑战页都在过滤层背面;凡要下「该页不存在 / 该面为空」的结论,先跑一次真浏览器。API(JSON)面通常不受此影响,仍可用 curl 判。
- **对照组必须包含「站点根 `/`」与「一个绝不存在的路径」**:整批(含根与假路径)同为 `200/0B` ⇒ 读数来自过滤/传输层,**该批存在性结论整批作废**;只有真路径有内容、假路径空,才可判读。
- **别把这条读成「无 UA ⇒ 全 404」**:实测另一批「加 UA 后仍全 404」的真因是**扫描清单里根本没有那个唯一存在的路径**(清单里没放 `/`),不是 UA。**扫描清单必须自带一个已知存在的路径作阳性对照**;否则「全 404」既可能是过滤,也可能是你自己的清单错了。
- 拿到真浏览器通道后,**此前所有 curl-only 的「空体 / 404 / 未鉴权」结论一律标「作废 / 需重估」并重跑**,不得继续引用。

### 批量空体 ⇔ Host 头 / 虚拟主机路由(最贵的一类假阴性)

同 IP 多域名的目标按 **`Host`** 选路由。请求不带 `Host`(或带错域名)时,网关与后端**不报错、只回空体** ⇒ 扫描脚本把每个 key/对象都记成"不存在",整批阴性结论全是假的,而且看起来非常干净(全 200/空),最容易被当成"这条线已判死"而永久关掉。

- 每批探针**必须带双对照**:① 已知**存在**的对象 → 必须返非空;② 已知**不存在**的对象 → 返空。正对照返空 ⇒ 这批**全部作废**。
- 换脚本/换批次时对照要重建:同一目标上不同脚本各自漏头,会让同类假阴性反复复发。
- 补头重跑后,此前据空体下的阴性结论一律标 **"作废 / 需重估"** 并写进交付,不得继续引用。

**★TLS 下光有 `Host` 头不够,还要对齐 SNI。** 按**源站 IP** 直连、SNI 仍是那个 IP 时,握手落到**默认 vhost**,它对**任意路径**一律回 `HTTP 200 + 0 字节 + 无 Content-Type`。此时整批探针每一行都长这样:判据若只是"把特征 401 文案剔除",就会得到"730/758 个端点非 401"这类假丰收(实测两轮全量扫描都栽在这,整批作废)。唯一可信取数方式:

```
curl -sk --resolve <vhost>:443:<源站IP> -H "Host: <vhost>" https://<vhost>/<path>
```

- **每批必须夹两根对照针**:① 已知**免票/放行**路径(如 `/captchaImage`)→ 必须返**真业务 JSON**(实测 56B `{"msg":"操作成功","code":200,...}`);② 已知**受保护**路径 → 必须返出**该站特征 401 体**(实测 86B `{"msg":"请求访问：/getInfo，认证失败，无法访问系统资源","code":401}`)。②拿不到特征 401 ⇒ 你根本没连上目标 vhost,**整批作废**,而不是"防护到位"。
- **允许进判据的只有两类体**:真业务体 / 特征 401 体。**整批同一 HTTP 码且体为空 = 传输伪影**,数字再好看也一律作废重跑。
- **body 与状态码分开取**(`curl -o <文件> -w "%{http_code} %{size_download} %{content_type}"`),不要在**同一条 stdout 流**里用标记符切分两者:实测标记切错时整批输出退化成一堆 `??`(379 条全 `??`,可读性为零),而 `rfind` 取最后一个标记在 body 自身含该标记时会**静默**切错。脚本对两根对照针跑**同一个解析函数**并 `assert`,解析器坏了就中止,不要产出几百行垃圾。

### 非 HTTP 响应 = 第三态"未知",严禁并入存在/不存在任一栏

**存在性 oracle 探针**(靠报错文案区分,如 ``no such api`` / `"不存在"` / `资源未找到`)最贵的一类假阳性:出口劣化时 curl 拿不到 HTTP 码(`000`/`TO`),**body 为空**。若判定写成 `if 不存在文案 not in body: 记存在`,那么**每一个样本都会被记成"存在"**,而且看起来像一次大丰收。

- 实测教训:一批动作名枚举返回 **100% 全"存在"**(连明显荒诞的名字都在),真相是整片出口返回空体+超时 —— 该批**全部作废**。
- **铁律**:`000`/`TO`/空体一律归 **"未知"** 栏,**不进存在栏也不进不存在栏**。汇报必须给出"命中 / 未知 / 已排除"三个数。
- **未知率闸**:未知率 > 5% ⇒ 该批作废,先修通道再重跑,不得挑"未未知"的那部分下结论(选择偏差)。
- **对照组升级为三态**(存在性探针的强制前提):① 必定**不存在**的样本 → 必须命中"不存在文案";② 必定**存在**的样本 → 必须返非空真实体;③ 出口自身自证 → 必须能返出 HTTP 码。三条任一不成立 ⇒ **整批作废**,且这个判定必须写在脚本里(不成立就 `sys.exit(1)`),不能靠人看。

### 出口劣化指纹:GET 首页通、POST 业务 API 全超时

**不是目标封禁**。前者的响应常有 CDN 边缘缓存/静态兜底,所以同一条坏通道上"GET 根 = 200"与"POST API = 超时"可以并存。

- 诊断顺序:① 直连(`curl --noproxy '*'`)打同一 API → 通 ⇒ 出口问题;② 抽 20~30 个出口打根路径 → 只留能返 HTTP 码的进池;③ 池内再抽打真实 API 作对照 —— **根路径通 ≠ 该出口能打 API**,筛选必须以真实 API 为准。
- 目标在高频突发后会对单一出口**瞬时限流**(数十秒~数分钟自恢复):表现为短窗口内 `000`,随后同出口恢复正常。**别据此写"目标已封禁"**,那是假结论;批量探针必须限速+重试,突发上限控制在单出口几十次量级。
- **整面扫描(上百条)一律后台跑 + 逐行 append JSONL**,不要挤前台:前台会撞工具超时上限,半截输出既不能续跑也不能当结论;每 N 条插一组已知-good 对照并在 JSONL 里落痕,才能区分"真的扫完"与"被截断/限速".

### 报错文案会骗人:字段名按文案照抄可能永远不过

服务端报 ``Txid cannot be null`` 时,实际绑定名可能是 ``txid``(小写)/``txId`` —— **报错里的显示名不等于框架层的字段名**。

- 遇到"字段明明填了却仍报 cannot be null" ⇒ 立即做**大小写/别名穷举**(`Txid`/`txid`/`txId`/`txID`/`TXID`/`txHash`),用"报错是否换题"作为命中判据(换到下一个错 = 该名对了)。
- 定名后再看**下一个错**:错误推进的顺序本身就是服务端校验顺序,能直接读出"先校验什么、后解码/落盘什么"(例:参数 → 订单状态 → 才到 base64 落盘),据此判“任意文件写入”是否真可达。

### 无票响应第四态:业务层 JSON = 该路径在 `permitAll` 白名单内(无票即用的白名单发现 oracle)

前面三态之外补第四态,这是**不需任何凭据就能测绘白名单全集**的最强 oracle:

| 无票响应 | 判定 |
|---|---|
| **业务 JSON(`code:200/500` + `msg` 文案)** | ★**该路径在 `permitAll` 白名单内且路由已注册** |
| `{"msg":"Request method 'GET' not supported","code":500}` | 路径在白名单内且路由存在(仅方法不符) |

用法:拿**全部已知路径清单**逐条无票 GET 一遍,凡回业务 JSON 者即白名单全集。实测一次跑出 5 个 permitAll(含一个此前完全未知的 `/register`),同时把 102 个“必须认证”的路径一次性定性。**每批必须夹带已知阳性对照(已知白名单口)与已知 401 对照**,否则整批不可信。

配套三条:
- **中间件/actuator 必须带业务前缀再测一遍**:根路径 `/actuator/*` 404 不代表 `/zf/actuator/*` 不可达(平台常只在业务前缀下开 actuator)。
- **模块不决定认证,逐动作决定**:同一模块下 `...SendSmsCode` 可以无票可达,而 `...GetUserSummary` 不可达 ⇒ 权限绝不跨动作外推。
- **`_app.config.js` 里的 `VITE_GLOB_*` 变量可能是死配置**:必须回 bundle 搜该变量名确认是否被读取(命中数 0 = 死配置,不可当漏洞写)。
- **模块段决定错误处理与认证空间,不是被忽略** —— 实测同一动作换模块结果不同:模块 A 未知动作回自定义 `no such api`,模块 B 未知动作回 **Spring 默认 404 JSON**(带 `status`/`path`)。⇒ **报错体必须读全字段**:`{"status":404,"path":...}` 是 MVC 层 404(不存在),不是业务命中;把 404 体当“命中”是典型假阳性。
- **动作名优先级:前端显式调用点 ≫ 模板组合名 ≫ 盲枚举** —— 从 JS 里机械榨出的 `api<模块><动词>` 组合(上千个)实测全为 `no such api`;只有 bundle 里真实出现调用参数的名字才存在。
- ★ **从「第三方/同族产品源码语料」挖出的动作名必须拿【线上】产物验一遍再建矩阵**:离线语料里的 action/路由名属于**那份源码**,
  不等于本目标部署了它 —— 哪怕是同族产品、同模板、同厂商、甚至同一套模板名。
  判据 = 拿**线上** bundle / 路由表 grep 这些名字:**0 命中 ⇒ 不属于本应用**,从目标矩阵里删掉并把已跑出的读数标记作废。
  否则会为一组**根本不存在**的动作反复调参,而「缺少必要参数」这类**兜底文案**恰好最容易被读成「动作存在、只差参数」(实测因此白烧多轮,
  直到发现线上 bundle 里这批名字 0 命中)。**同族源码是找面的线索,不是存在性证据** —— 与《部署树 ≠ 版本索引》同一条纪律。
- **弱标识 ≠ 可伪造**:登录响应把 `token` 直接返回为**用户 id 明文**时,先验证“怎么送进去”:① cookie 值常是服务端签发的随机值(≠ token);② 手工构造 cookie 文件即使填入真值也可能被前置层丢弃(回 `0B`);③ 真会话 + 额外 `token:` 头可能被直接忽略(仍返回自身数据)。⇒ 只有能实际打穿才写漏洞,否则记【不可判定】。
- **存在性 oracle 必须先用"已知存在值"验证它测的是同一个命名空间**:"用户名不存在"这类文案看着像可枚举的 existence oracle,但**不同命名空间的标识会被同一句话拒掉**。实测:拿自己**刚登录成功**的账号名去查,同样回 `username_not_exist` ⇒ 该口查的是**上游/另一套账号体系的用户名**,与登录名不同空间 ⇒ 此前所有"不存在"判定**全部作废**,不得用于枚举或收敛结论。规则:启用任何文案型 oracle 前,先喂一个**你确知存在**的值(自己的身份、你刚创建的资源);它没命中 ⇒ oracle 测的是别的空间,标死,别再枚举。
- **模块全动作枚举:报计数,不报结论**:整模块枚举时给出 `N 个被登录墙拦 / M 个业务 JSON(permitAll)` 两个数。实测某模块 104 个动作里 **103 个 302 登录墙、唯一 1 个免票可达** ⇒ 白名单是**逐条精确路径**配的,那条例外本身就是发现;而其余 103 条在墙内**无法判存在性**,不许写成"该模块只有 1 个动作存在"。
- ★★ **白名单正证据的第三形态:参数绑定报错 = 白名单 + handler 已注册 + 控制器签名泄露** —— 对候选路径发**空体 / `{}`**(带齐信封头),
  回 `400 Required request body is missing: com.<厂>.<模块>.controller.common.CommonController.verifyAuthToken(com.<厂>.<模块>.domain.bo.VerifyAuthBo, javax.servlet.http.HttpServletRequest)`
  ⇒ ①**它必须过了鉴权过滤器才能走到 MVC 参数绑定**,比 `404`(只证白名单、不证 handler 在) 强一档,是"该路径可无票直调"的最强正证据;
  ②响应体**逐字给出控制器全限定类名 + 方法名 + DTO 全限定类名** ⇒ 拿 FQCN 去反查源码/厂商仓/同族部署,或按 DTO 类名推字段清单,
  是**零成本的契约来源**(比猜字段名快一个量级);③零副作用(空体到不了业务逻辑)。
  ⇒ 操作顺序固定:**先白名单扫有没有该路径 → 再用空体取签名 → 最后才拼 body**;别一上来就猜字段名。
- ★ **框架"默认白名单路径"回 404 不代表该实例没有这个功能 —— 只说明入口被改过** —— 实测 RuoYi 默认 permitAll 的 `POST /login` 回
  `404 Not Found`(框架 JSON,带 `path`),据此曾写下"POST 物理不可达"的**错误结论**;同一实例的登录面真实位置要从**页面 bundle 的调用点**取
  (登录页 JS 里的 URL / `skipUnauthorizedLogin` 类标记 / 前端 config 的 baseURL)。
  ⇒ 判据:白名单内的路径回 **404 框架 JSON** = **放行但 handler 不在此处** ⇒ 去别处找该功能,不是"功能不存在"、更不是"目标打不动"。

### oracle 语义按【实例】标定,不是按产品名(跳实例套用 = 成批假阳/假阴)

同一个产品的两个环境/实例,同一个门禁字段的**校验顺序可以相反**,于是同一句文案 oracle 的含义完全不同:

- 实例 A(先查账号): 错码 + 不存在的用户名 → `账号不存在` ⇒ 可枚举;
- 实例 B(先校门禁): 错码 + **从没人注册过的名字** → 照样 `验证码错误` ⇒ **该实例零账号 oracle**,
  全站账号在门禁上不可区分。实测一批 20 个候选(含明显无人注册的名字)**20/20 全回同一句门禁错误**;
  若照实例 A 的读数写,这批会被记成"20/20 账号全部存在"。

**规则**:①任何文案型 oracle 上线前,先用一个**你确知不存在的值**标定一次,那才是该实例的读数;
②标定失败(不存在的值也回"存在"侧文案)⇒ oracle 在此实例**作废**,不是"发现了一大片账号";
③换环境/换主机(哪怕同一套产品、同一份前端)都要**重新标定**;
④标定结论连同实例一起写进批次登记,**不与上一个实例的结论串用**。

### 多实例(生产 / 预发 / demo)判独立:三发差分,别假设「测试环境鉴权更松」

- **判独立实例的判据** = 同一请求在 A/B 两 host 上**错误文案逐字同源,但凭据不通用**(A 的票在 B 回 `401 请重新登录` / `not authed`,而同一接口在 A 是 `200`)⇒ **同代码、独立库/独立密钥的平行部署**。此时两边的账号体系、数据集、鉴权强度**各自都要测一遍**,不许把 A 的读数搬到 B。
- **"预发/测试环境鉴权更松"是未经验证的假设,只能逐条差分证实**:实测一个预发实例(版本号反而更高)其 `/admin/*` 族与生产**逐字一致**(`not admin`),**没有任何宽松** ⇒ 对预发的整族扫描照样要跑,但要按"独立实例"重跑,不能拿"它是测试环境所以能进"当推理跳板。
- **版本号差 = 唯一的"新面"线索**:预发 `app.version` 高于生产时,去比**后端接口面**(新端点/新字段),不要比鉴权强度;若两侧前端 bundle **hash 一致** ⇒ 前端无新页,新面只可能在后端,那就穷举后端行为差异。
- **配置端点(如 `/v3/config` / `task_config`)是环境的身份证明**:版本号、测试站域名、客服/运营联系人常在里面 ⇒ 判实例归属先拉它,再决定往哪打。

### 重复提交防护会污染参数差分(把"差异"变成噪音)

服务端带防重放时,同参数快速重放会回一句明确的拒绝(实测 RuoYi 系 `不允许重复提交，请稍候再试`)⇒
差分/IDOR 实验里**参数与基线完全相同的那部分会被拦**,你测到的"差异"来自防重放而不是业务逻辑。

- 差分实验**每次必须动一个无害字段**(或改无关的序号值),让请求不被判重。
- 把这句拒绝文案归入"**不可用**"样本栏(与 `302/0B/000/405` 同栏计数),**不计入差异数**。
- 基线**先单独打一发**再跑变体,否则基线自身就在重放窗口内,整组差分从第一行就不可信。

### 无票对照的三条污染源(会凭空造出假阳性)

**硬规则:只有阳性响应(`200` + 有 body)才算证据;`0B` 永远是第三态,不可用于判阴性。**

1. **复用的 jar 被污染**:脚本用 `curl -b jar -c jar` 时,jar 文件会**累积同名 cookie**(实测一个 jar 里 11 行同名 `xsuperFgC`),你把它当“无票对照”用的那批请求其实**带着一条(可能有效的)会话 cookie** ⇒ 产出“未认证可读”的假阳性。**办法:对照组每次新建空 jar 并断言 0 条 cookie 行**,或干脆走“完全不传 Cookie 头”的路径,并把两种口径分开写结论。
2. **“无 cookie”与“空文件 jar”不等价**:实测同一端点,`-b <空文件>` 回 `0B`,**完全不传 Cookie 头回 `200/771B`** ⇒ 不要用空 jar 冒充无票对照。
3. **限速潮伪装成端点行为**:“整批全 0B”(哪怕 60~80 个连续同族)通常是**中间层对该出口的瞬时限流**(数十秒~数分钟自恢复),不是“该族路由未注册”。**办法:换出口或隔 1~2 分钟串行复测,恢复真响应即证明是抖动**。

**手工复制会话 cookie 时**:同一 cookie 名在 jar 里可能有多条(新旧/path 不同),必须取**最新一条**,否则会得到 `0B` 并误判“会话失效”。

### 写类端点零副作用测鉴权:框架 405 = 过滤器已放行

只有写方法(POST/PUT/DELETE)的端点,不必为了测鉴权真发一次写。改发 **GET** 看响应来源:

| 响应 | 判读 |
|---|---|
| **框架级 JSON** `405 Method Not Allowed` / 参数 `400` | 请求已进应用 dispatcher ⇒ **过滤器放行 = 该端点未鉴权**,再用缺字段/类型错的请求坐实 |
| 网关/nginx 的 405、容器 HTML 错误页、`404` | 只是代理层或 URL 解析层 ⇒ **对鉴权问题无判读价值** |

写类端点真要打时:发**缺必填字段**或**类型错**的请求 ⇒ 走不到业务写入,但足以证明鉴权层放行。

**★创建/新增类端点探参数名(零副作用)**:探 `addXxx`/`createXxx` 的字段名时,候选键的**值**一律填一个**已存在**的实体名
(已注册用户名 / 已知单号)—— 命中只会回「已存在 / 重复」,**永远不会真的建出对象**。
反例:值填随机新串 ⇒ 一旦命中就凭空落库一条真实记录,而你还以为只是在探字段名。
流程:先空参拿基线「不能为空」⇒ 再用已存在值灌满候选键 ⇒ 文案从「不能为空」切到「已存在」即为命中。
若自家已有账号可当靶,优先拿它当键值 —— 这样整个探测过程产不出任何新对象。

**★角色/权限类字段的探法相反**:候选键是 `role`/`roleId`/`isAdmin`/`authority`/`level`/`tag` 这类时,
**「已存在的合法值」本身就是提权** —— 填 `admin` 就是真的把自己改成管理员,
而“已经回 200/变生效了”会被当成“探测成功”写进台账。⇒ 这类字段只能发 **空串 / 缺字段 / 类型错 / 畸形体**,
用「报错是否换题」判字段名与存在性,**永不用真实角色值试探**。
**自查清单**:探针脚本里出现 `{"role":"admin"}`、`{"isAdmin":true}` 这类字面量 = **把提权写操作当探测**,删掉重写。
同一条也适用于审批/状态机类字段(`status`/`audit`/`verified`):只能发**非法值**让校验报错,不发合法目标态值(`"approved"`)。

### 空体全表扫: 按「报什么错」给端点三分(认证缺失 oracle)

对已测绘的全量端点,带齐信封/头各发一发(缺字段到不了业务,零写入;注册类端点例外 —— 空参真建号,跳过),按回包三分。
★ **同上「无参≠零写入」**：动作分发型端点里，缺字段/无参可能被解释为「对全部对象执行」(`clear`/`flush`/`reset`/`purge`/`rebuild` 类无参即全量执行)，
这类动作**不发空参**，改发「必然非法」载荷 —— 见《特权路由族漏配猎捕》第 2 步。**下发形态有讲究:判鉴权必须用「显式空凭据」,不能只发缺字段 `{}`。**

★ 凭据是 body 字段(`sessionKey`/`loginKey` 类)的栈里,`{}` 与 `{"<凭据字段>":""}` 走**两条不同代码路径,读数可能相反**:

- `{}` / `{"sessionKey":null}`(缺字段或 null)→ 取值为 `null` → 后续判空 NPE → 全局兜底(`系统繁忙` 类)—— **短路发生在凭据检查之前**,整站鉴权都能被它盖住,看起来像"参数无效";
- `{"sessionKey":""}`(**空串**)→ 过了 null 判空 → 抵达会话查询 → 确定性拒答(`登录已过期`/`30018` 类)—— **这才是该端点的鉴权读数**;null 按缺失处理,标定必须用**空串**;
- ⇒ 定栏读数以**空串发**为准,`{}` 仅作辅助。

| 回包(以空串发的读数为准) | 判读 | 动作 |
|---|---|---|
| 统一登录失效率(`登录已过期`/`未登录`/`30018` 类) | 有认证检查 | 排除,不浪费轮次 |
| **参数校验/业务存在性文案**(`<字段>不能为空`、`不存在此数据`) | **认证检查缺失** —— 已执行到业务层;带显式空凭据字段仍同文案 = 实锤 | 补有效样例值 = 未授权原语,逐条复测后出结论 |
| 通用兜底码(`系统繁忙`/`操作失败`/`10000`) | **不可判** —— 多为判空 NPE 兜底,可能短路在凭据检查**之前**;既不证有认证,也不证无认证 | 换**显式空凭据字段**重探:翻出登录失效 ⇒ 进"有鉴权"栏;仍回兜底 ⇒ 换有效业务样例再判 |

实测代价:一批端点曾因缺字段探测回兜底码被记"无认证检查",补发空串后**全部翻成鉴权端点**。⇒ 凡"认证检查缺失"结论出自缺字段探测的批次,一律用空串**重测定栏**、旧结论作废重写。此招同时是全量鉴权面最快的**定栏工具**:全量端点各发一发 `{"<凭据字段>":""}`,回登录失效率的进"有鉴权"栏、回业务校验/存在性文案的进"无鉴权"栏(实测一趟把 40+ 端点一次分清),两栏都不进才需继续探。

第二类是本 oracle 的产出面(实测一趟翻出资金账单/抽奖用户/内定中奖/群列表 5+ 条);与「无票响应第四态」互补:第四态找白名单路径,本表找**根本没挂认证**的业务端点。三分类计数进批次登记。

**编号型出数端点(补有效样例之后)**:先用"不存在"回码建**廉价候选验证 oracle**(如 `1019`),任意候选编号到手先验证再投入;编号熵若与系统其它随机码同族(实测 12 位 `[a-z0-9]`,36^12)⇒ **放弃枚举,转找编号泄漏点** —— 后台"复制链接/分享"类交互生成的深链常内嵌编号(实测格式 `t.me/<bot>?start=invite-<sn>`),深链是公域分享物,就是随机编号的主要泄漏面。

> 与《三态对照》一节的 `token: ""` 注记不冲突:那节讲 **header 凭据**、目的是"证明本该受保护"(对照用非空无效值);本节讲 **body 凭据**的判层标定(缺字段与空串路径不同),两场景各自成立。

## 302 的三种成因:差分组实验才敢下结论

同一条 `302 → /login` 可以来自三件完全不同的事,**只看一次响应无法区分**:

| 成因 | 触发条件 | 判别方法 |
|---|---|---|
| ① **未认证访问受限路径**(登录墙) | 无票 / 会话失效 | 带上有效会话复测 ⇒ 变 200 |
| ② **账号级(×端点)风控** | 该账号在此端点上的失败次数超阈值 | ★**固定端点+载体+参数,只换用户名**,同一批内:被风控账号 302 / 未触碰账号 200 业务 JSON |
| ③ **该路径不在白名单前缀内** | 匿名访问非白名单前缀 | 用**同前缀已知不存在路径**做对照:同为 302 ⇒ 该前缀整族在墙后,此响应**不携带存在性信息** |

**实战翻车**:一批探针测得"149/149 出口的 `/pfv3/resetLoginPwd` 全 302",据此写了"permitAll 被收回(约 20 分钟窗口)";20 分钟后**同一端点换另一个用户名**发一发就回 `200 otp_wrong` ⇒ 真因是该账号先前被连打 27 次错验证码、进了**账号×端点风控**,路径从来没关过。

四条必守:
1. **"放行被收回"这类结论必须做跨账号同批对照**才允许写 —— 单账号的 302 只有成因 ①②③ 三种可能,证据力为零。
2. **"仍开放 / 已关闭"必须带时间戳**(UTC + 目标时区双标),因为窗口期与风控状态都会变。
3. **攻击次数实验会污染后续判读**:做 N 次错值实验的账号**立即进风控**,此后该账号在同端点的一切响应(含"存在性 oracle")全部失真。⇒ 次数实验前后都要用**没被实验碰过的账号**重测基线。
4. 次数实验本身就是**风控存在性的量测**:错值 N 次后由业务 JSON 转为 302 ⇒ 得到"有账号级尝试计数"的正面证据,这是**给 ATO 链收口的关键结论**,比"未爆破成功"强得多。
5. **★参数差分(IDOR/越权判据)必须把 302/0B/000 归入"不可用",绝不记成"差异"**。实测事故:一批参数级 IDOR 差分共出 **75 行"差异"标记,100% 是 `code=302 len=0`** —— 基线在批内健康段测到 `200/2832B`,随后会话被风控顶掉,所有变体全 302;若按字面读就会写出"加 userId 触发差异 ⇒ 存在越权"。
   ⇒ 判据必须是:
   ```python
   USABLE = (200, 500)          # 业务 JSON 才算可用样本
   if base_code in USABLE and var_code in USABLE:
       diff = (var_len != base_len) or (var_body != base_body)   # 真差分
   else:
       void += 1                # 302/0B/000/405 = 不可用,不计入差异
   ```
   且**先验条件**:变体命中必须在**同一会话生命周期内**(基线与本组变体都非 302);作废样本数必须报出来(与命中数并列),"差异 0 条"只有在**有效样本数达标**时才能当阴性。

## 认证态批量探测的会话卫生(轮换型出口池)

用轮换型代理池(同一 `IP:port` 每次请求可能换真实出口)做**认证态**批量探测时:同一会话内交替使用多个出口 ⇒ 会话不可用 ⇒ **整批全是 302/登录墙**,极易被误读成"站点故障/鉴权收紧"。

- 实测:34 个动作同一批全 302,而同出口**重新登录后立刻**读同一端点 ⇒ `200 / 5394B`。
- 规则:**一个出口一个会话** —— 登录与全部请求走同一出口,不要在批内切出口重试认证请求(切出口只用于解 CF 挑战/匿名探测)。
- 每批开头先请求一个**已知-good 的受保护端点**自证会话;它若不是 200 ⇒ 整批作废重来,不得写"目标变了"。
- **★单设备登录(请求体 `getSystemSetting` 常带 `singleDeviceLoginFlag`)**:同一账号第二次登录会**顶掉**第一个会话(实测:脚本首版写"两次登录做兜底",第二次登录后整批 302)⇒ **一批只登录一次**,禁止并行用同一账号跑多个脚本。
- **★账号级 24 小时限流(风控原因明文写在 body)**:连续 302 时**回读登录响应体**,实测 `HTTP 200` + `{"code":500,"msg":"Request is limited, please try again after 24 hours"}` ⇒ 是**账号被风控**,不是目标变更、不是站点故障。触发量级参考:单账号 ~5 分钟内连开 4 批(百余请求)即触发,代价是 24h 内该账号全废 ⇒ **认证态探测按"账号预算"排期**:优先复用一条长会话,把"新登录次数"与"请求总数"当配额管理。
- **★风控只作用在账号×端点,不改变路径结论**:同一时刻另一个未被实验触碰的账号在同端点照回业务 JSON ⇒ 凡"仍开放/已关闭"结论都要附**账号 + 时间戳**,单账号状态≠全站状态。
- **★票与出口绑定(与“会话不绑 IP”相反的那一半)**:WAF/挑战类 token、一次性 ticket **常绑定铸它的那个出口 IP** ⇒ 铸票与回放**必须同出口**(把出口用环境变量固定进每次运行,如 `XVIP_SOCKS=host:port python probe.py`),跨出口回放会整批 401,极易误判成「票失效/权限不足」。同族的**页面域与接口域可能各自只有不同出口可达**(实测:页面源域仅经本机代理出口可达,接口域经跳板出口可达) ⇒ 为「页面源」与「接口」**分别固定出口并分别验证**。

## 判层三铁律(实战代价换来)

1. **永远读 body,不要读 HTTP 码**。大量 Java/RuoYi 系目标把 HTTP 码固定 200,把真实状态放在 body 的 `code`/`msg`;用 `%{http_code}` 判层会把 405(存在+放行)归进 200 组,白丢正向证据。
2. **命名空间决定 0B 的含义**。同一目标上 `/sys/**`、`/mer/**` 与 `/login`、`/common/**` 可能走**不同应用/上游**:前者无注册路由回 `200+0B`,后者无 handler 也回 401 JSON ⇒ 先用“真路径 + 同前缀假路径”两组对照确定该命名空间内 0B 是否可判阴性,再统一判读。**判读颗粒度是"具体路径",而"有没有 oracle"是前缀级的**:同主机上有的前缀真路径 401 / 假路径 0B(有区分度),有的前缀(认证中心 catch-all)连**绝不存在路径**也回同款 401(零区分度 ⇒ 该前缀内存在性不可判)⇒ 每批必须跑**该前缀自己的**假路径对照,不跨前缀套用。
3. **后端可能比前端契约小**。前端 bundle 编出的路径可能含**已下线/未部署**的死链;命中“同前缀假路径 = 0B”的族应判为**未注册**,不能计入攻击面(报告里不得把死链写成“69 个导出接口”这类可打面)。

## 401 零区分度时:用三态测绘白名单边界

当目标对**任意路径**都回同一个 401(含绝不存在路径)⇒ 401 组内部**零区分度**,该批端点存在性**不可判定、整批作废**(实测:103 个候选中 82 个零字节 + 19 个 401,对照组 `/zzz_no_such_ep_9x7` 回同款)。补救办法是找**能穿透过滤器层**的响应形态:

| 响应 | 含义 |
|---|---|
| `401` + 业务 JSON | **该前缀被认证中心 catch-all 接管** ⇒ 端点是否存在**判不出**,不写阳性 |
| `404` + **框架 JSON 错误体**(如 Spring Boot `{"timestamp":…,"status":404,"error":"Not Found","path":…}`) | **白名单内但资源不存在** ⇒ 与 401 可分,用来反推白名单前缀覆盖范围 |
| **`200`/`500` + 业务 JSON 文案**(如 `{"msg":"当前系统没有开启注册功能！","code":500}`、`{"msg":"Request method 'GET' not supported","code":500}`) | ★**白名单(permitAll)内且路由存在** ⇒ **无票能进业务层就是放行**;这是最强的**白名单发现 oracle** |
| `200` 真内容 / `405` / `302` | 白名单内且端点存在 |

**用这个 oracle 主动找白名单**(不是只用来判读已知端点):把契约全路径**无票 GET** 跑一遍,凡返**业务层文案**(非 401/0B/404)的即 permitAll 路径。实测据此翻出此前未知的 `/register` —— 路由在白名单内、注册开关由服务端关闭(`当前系统没有开启注册功能！`),但**开关是配置项**:换环境/换租户可能开着,必须写进报告而不是"功能已关闭"一笔带过。

- 实战:后端把**文档组件的静态资源**放进了 permitAll(`/swagger-ui/index.html` → 200 / 3,129B),而**数据源端点 `/v3/api-docs`、`/v2/api-docs`、`/swagger-resources` 全部 401** ⇒ 结论只能写"装了 API 文档组件但文档端点未放行",**不能**写"存在 Swagger 未授权"。
- 同理 `/swagger-ui/swagger-initializer.js` 回 `404 框架 JSON` ⇒ 证明放行的是**部分路径**而非该目录整片;别由静态资源可读推断文档可读,**逐路径测**。
- **白名单候选的产地(按命中率排序)**:①**登录/注册/落地页的页面内 JS**(见 `references/unauth-endpoint-harvest.md`)②动作名自带 `NotLogin`/`WithoutLogin` 的 ③页面 onLoad 阶段以**空体** `{}` 调用的。这三类是业务上"设计成登录前可调"的口,命中未认证面的概率远高于枚举。

## 代理池/出口:协议用错会伪装成"池子全坏"

- 条目形如 `IP:port:user:pass` 的池子**协议不定**:`http://` 全 `000` 时先换 **`socks5h://`** 再判池子死活(实测同一池:`http://` 全超时 → 换 `socks5h://` 后 4 个出口可用)。**`socks5h`(h=远端解析)**,别用 `socks5`。
- 池子可用性必须以**真实业务 API** 作对照(根路径通 ≠ 能打 API)。
- 换出口是解 CF 挑战的正解:同一站点、同一时刻,某些出口稳定拿真响应,另一些拿挑战页。

## 站点级 CDN 挑战页 = 第三态,先排除"是不是我方问题"

- 整批返回 Cloudflare 挑战页(数千字节 HTML、`Attention Required` / `Just a moment` / `cf-error`)⇒ **不得记阴性、不得记不存在**,该批归"未知"。
- 判定方法:**换多个口径的独立出口复测同一 URL**(本机直连 + 不同机房跳板机 + 代理池);**全部被挑战 ⇒ 站点级策略**(非我方出口问题),标未知并换通道;**只有部分出口被挑战 ⇒ 出口信誉问题**,换出口重跑。
- **每批必须带控制组端点**(已知会返回真数据的那个):控制组拿挑战页 ⇒ 该批全废;控制组 200 ⇒ 出口有效,后续样本才可信。

## 三态对照:证明"本该受保护"(最强论证)

只证"不带凭据 → 200"会被反驳成"这接口本来就公开"。补一发**非空无效凭据**:

| 请求 | 结果 | 推论 |
|---|---|---|
| 不带凭据头 | **200** | 放过 |
| 无效凭据(`token: 1` / `token: null`) | **401**(如"请重新登录" / "not authed") | 服务端明确要求身份 |

两条并存 ⇒ 这是**"只在凭据存在时才校验"的装饰器缺陷**,不是公开设计。这条比裸的"未授权 200"高一个数量级,必须写进报告。

注意:`token: ""` 常等同于"缺失"(拿不到 401)—— 对照必须用**非空无效值**。

## 服务端自报字段名,别急着跑候选词表

Python 栈的 422 响应体**逐字列出缺失字段名**:

| 栈 | 响应体 | 字段名 |
|---|---|---|
| marshmallow/Flask | `{"code":422,"msg":{"json":{"phone_number":["Missing data for required field."]}}}` | `phone_number` |
| FastAPI/Pydantic | `{"detail":[{"loc":["body","phone_number"],"type":"missing"}]}` | `phone_number` |
| 值域越界 | `{"msg":"Invalid value."}` | 参数已被识别且值域有限 ⇒ 用它二分值域 |

**字段名逐端点**:同族 `send_sms_code` 收 `phone`,`phone_login` 却收 `phone_number`。套错 schema 会让整批探针停在 422,得不出任何鉴权结论。

**Java/RuoYi 栈用 `500` 自报字段名,同一手法的另一形态**:写类端点缺必填时回 `500` + 文案逐字给出绑定名(实测一批 7 个 `500` 里 6 个是这类:`bankShortName`、`amountType`、`authId`、`apiType`、`receivingFlag`,第 7 个是伪动作的 `no such api`)。这批 **不是"疑似报错",是服务端亲手交付的参数名清单**:

- **★把这些自报名当作参数级 IDOR/越权差分的首选候选,而不是盲猜 `userId`/`accId`/`agentId`**。实测对 7 个资金端点做差分,盲猜名(含 `userNo`/`agentId` 共 7 个 × 2 值)在变体上零效果;而自报名里 `authId`/`apiType`/`receivingFlag` 本身就是**主体标识**,命中越权的概率高一个量级。
- **差分时保留一组盲猜名做对照**,否则无法区分"该端点无越权"与"我测错了参数名"。
- 报错**顺序 = 服务端校验顺序**(先校参数 → 再查库 → 才落盘),能直接读出前置条件链;`UNKNOW ERROR` 表示该端点有非参数前置条件(缺前置状态),不是参数名问题。
- 同一批里 `no such api`(伪动作)与 `cannot be null`(真动作)**必须分栏计数**:前者是存在性阴性,后者是"真实动作 + 参数名泄露"的正向情报,合并计数会把情报一起丢掉。

## 登录门的第二道参数:验证码/TOTP 字段名与锁定口径(零消耗真实账号)

口令对的账号仍会卡在门禁(图形码/短信码/TOTP/GA)。**门禁字段名与锁定策略都能只用不存在的用户名测出来**:

- **字段名 oracle 两步法**:① 只发 `{用户名, 口令}`;回「验证码不能为空 / 谷歌验证码不能为空」⇒
  门禁存在,且**校验跑在口令之前**(口令错也先报门禁)⇒ 该口的字段名探测**不必过口令**。
  ② 逐个候选字段名 + **错值**:唯一让文案翻到「验证码错误 / 谷歌验证错误」的那个就是真绑定名,
  其余候选恒回「不能为空」。⇒ **猜错名 ⇒ 文案不变;猜对名 + 错值 ⇒ 文案变**。
  把「文案没变」读成「该字段不参与校验」是这里最常见的错(与本卡「报错文案会骗人」同型;只发猜错名永远测不出字段名)。
- **免门禁账号判别器**:同一字段名 + 错值,回「验证码错误」= 该账号绑了门禁;回「用户名或密码错误」
  = 门禁被跳过。⇒ 用它挑**免门禁账号**,这是"口令对但缺动态码"的正路,而不是去猜动态码。
  三条判据全用**不存在的用户名**即可完成,真实账号的尝试计数零消耗。
- **锁定口径先测再打**:先分清锁定是**账号级还是 IP 级**、阈值多少,再决定发几发。**作用域有三种,第三种最容易漏**:
  ①账号级（键=用户名）②出口级（键=真实 IP）③**端点/站点级全局封锁**（换用户名 + 换出口 + 换会话仍回同一拒绝）。
  判法 = **单变量对照,一发一个变量**:固定出口换用户名 → 固定用户名换出口 → 两者同时换。命中 ③ ⇒ **立即停手**
  （换 IP、换账号、换 UA 全无用）,记下时间点,等自愈窗口（分钟~小时级）后**单发复测**再谈续打。
  ★**拒绝体形态突变本身就是信号**:应用正常错误体之外的**裸码响应**（如 `{"code":403}`,HTTP 200、无 `msg`、
  无业务字段）通常是**网关/风控闸门**回的,不是账号校验失败 —— 别把它读成「口令错」继续烧次数。
  ★**拿同宿主的非登录端点做对照**（首页/静态资源/另一业务口）:它正常返回 ⇒ 服务活着、只有登录被闸 ⇒ 印证全局封锁,
  同时排除「站点挂了」这一误判。
  ★**尝试预算**:作用域未判明前 **≤4 发**;连喷 6+ 发常把可自愈的窗口锁升级成硬封锁,并把仅有的高价值账号窗口一起烧掉。
  RuoYi 系实测形态:**仅 IP 级 / 阈值 ~3 / 连不存在的用户名也计数** ⇒ ①候选名枚举会
  **自己把出口 IP 打成 30 分钟封禁**(必须换出口 + 候选名串行);②「六位动态码爆破」可**数学排除**
  (10^6 × 阈值 / 出口数);③「只按 IP 记账」本身单列一条报告项(可被代理池 / XFF 绕过,与本卡限流绕过同源)。
  ★**同产品另一实例的相反形态(必须现场标定,不得套用上式)**:实测另一台 RuoYi 二开主机是**账号级**计数 ——
  用**不存在的用户名 + 非空错码**打一发**不消耗任何计数**(文案推进到门禁),而对**真实存在的账号**每试一次真实扣减,
  且响应体直接回显**剩余次数**(`谷歌验证码错误，还剩N次机会`)⇒ 该实例把配额读数白送给你。
  标定三步固定:①不存在的用户名 + 空门禁值 ⇒ 只回「不能为空」(零鉴别力,但确认了门禁先于口令);
  ②不存在的用户名 + **非空错码** ⇒ 文案推进到门禁计数 = **账号级**;若怕 IP 也被记账,用两个出口各发一发看谁被扣;
  ③把回显的剩余次数**当预算**用。
- ★★ **门禁计数是别人的真实资源,试错即扣减,可能短暂锁掉运营账号 —— 收手纪律**:对**存在的账号**每发一次错码都真实扣减其配额,
  ⇒ 只对**候选小列表**一次一测,对 admin / 超管 / 运营类账号**绝不反复打**;需要多测时优先拿**自己注册的账号**当主体(命中只锁自己);
  实测把两台主机的 `admin` 配额打到剩 1~3 次后**立即停手**,并把"打了什么、剩多少"向用户如实披露 ——
  这类副作用不进漏洞台账,但必须进汇报(用户会拿它当"要不要继续"的输入)。
  锁定随窗口自恢复,但**别去验证"它恢没恢复"** —— 验证动作本身就再扣一次。
  ★与"三条判据对真实账号零消耗"不矛盾:零消耗的前提是**名字不存在**;名字存在就会扣它的配额。
- **串行纪律**:换候选名、换账号名、换出口三个变量一次只动一个,否则分不清哪一行算命中。
- **★闸门之间有顺序,先读一次再动手**:同一端点用空参 / 错参名各发一次,若**先报角色/授权**(`用户不存在或角色错误`、`无权限`、
  `xxx 不存在`)**再**报门禁(验证码),则门禁**不是当前瓶颈** —— 是我方身份不够,再怎么试动态码也不会推进。
  判据:文案里出现「角色 / 权限 / 不存在该用户」这类词 = **授权层**,不是门禁层也不是参数名层。
  把"角色不足"误读成"只差一个验证码"会让整轮工作烧在门禁上。
- **★门禁/动态码类端点常"每调一次就轮换一次密钥"**:`create`/`bind` 型端点(GA/TOTP 绑定)每次调用都签发新 secret,
  旧的全部失效 ⇒ **连调 N 次后只有最后一次有效**,而中间任意一次失败**不能**证明"密钥不对"。
  纪律:调一次 ⇒ 立刻用它算码并当回写完绑定,别攒着批量试(否则每次试的都是已作废的 secret)。

### 前置闸门短路口令时:「账密有效」必须有错密码对照撑着

认证链上任何**前置闸门**(IP 白名单 / 人机验证 / TOTP / 租户匹配 / 设备指纹)都会**短路掉**口令校验,
⇒ 同一个文案会同时出现在「账密正确」与「账密错误」两种请求上。**从这种响应里读「账号存在 / 账密有效 /
只差 TOTP」是假的** —— 实测据此把「某默认号已过账密、只差白名单」写进案卷,直到补发对照才推翻。

- **铁律**:宣布「凭据有效 / 只差门禁 / 白名单是唯一障碍」之前,对**同一个账号**补发一发
  **错密码对照**(口令换随机串,其余字段不动)。**文案不变 ⇒ 该闸门在口令之前 ⇒ 凭据真伪未知**;
  只有文案切成「密码错误」才证明口令校验真被执行过。
- **配额归属跟着顺序走**:`还剩 N 次` / `账号已锁定 M 分钟` 是**前置闸门的配额**,不是口令错误次数;
  顺序未定就拿它做爆破预算 ⇒ 次数算错、号被锁。
- **两档文案完全不同,别混**:`ip不在白名单范围内:<IP>` = 真做了范围比对,**可伪造越过**;
  `白名单未配置` = 库侧该租户名单为空,**硬配置死路**(换任何 IP 都不动)⇒ 立刻换账号/换实例,
  别在这个号上继续换头烧轮次。
- **★IP 回显 = 白名单与头信任的免费 oracle**:错误文案里出回显 IP 时,把候选值(`1.2.3.4`)分别塞进
  各候选头,**回显变成该值 ⇒ 这个头就是被信任的**;成员候选用 `127.0.0.1`/`::1`/`192.168.0.1`/
  `10.0.0.1`/`172.17.0.1`(**白名单常含环回 + 内网段**,别只试 `127.0.0.1` 就收工),
  文案从「不在白名单」进阶到下一阶段即命中。让脚本按「回显 == 预期」自动判,别人工读。
- **按 IP 记账的封禁跟着伪造值走**:锁定文案点名 IP ⇒ 配额记在**那个头值**上 ⇒ 换一个新 XFF 值即得
  全新配额桶(实测按 IP 封 30 分钟,换值后立刻恢复);反面是篡改 IP 会一并重置限流与锁定状态,
  读到的锁定态不可归因于真实出口。
- **数值字段类型 oracle(Java/Jackson)**:给疑似数值字段发非数字串 ⇒ 回
  `Cannot deserialize value of type int from String` ⇒ 该字段是数值型,`"000000"` 实际以 **`0`** 参与比对
  (前导零丢失)、`1.5` 被截断、溢出/布尔/数组各有独立报错 ⇒ 先定类型再拼 payload,
  别把带前导零的串当敏感字符串用。

## 同一 handler 挂多套路径时:测一套推不出另一套

鉴权常在**路径前缀**上配白名单。同一 handler 常同时挂在带前缀与裸路径两套 URL(`/pc/<family>/**` 与 `/<family>/**`、`/api/<mod>/*` 与 `/pc/api/<mod>/*`)⇒ **只有一套在名单里,另一套整族匿名**。

- 把契约全 path 按**一级前缀聚类**,找出共享后缀段的孪生对,**两套各自单独测**。
- **带前缀那套 401 推不出裸路径那套也受保护** —— 这条推论是错的,而它会把真面判成"已排除"。
- 网关闭前缀名字也要穷举(`/dev-api`、`/prod-api`、`/stage-api`、裸路径)× 多个 `Host`,逐组合测。
- **不是整片开关**:同一前缀下,框架自带管理面可能仍 401,而同前缀下的自定义控制器全匿名 ⇒ **逐控制器族测**,用契约枚举自定义控制器,别按框架默认路径猜。

## 业务规则层 = 漏检证据

同一族端点里,某口返 `403 "请先开通会员"` / `"额度不足"` / `"未实名"`,而列表/详情口**没有这道检查** ⇒ 服务端**自证**该功能需受保护,而另一口漏检。这是可报告的对照,不是噪音。

## 限速要发送侧与校验侧分开探

同一功能两端的限速**通常不对称**,必须分开测,否则严重度会判错:

- 发送侧带 `每60秒一次` ⇒ 轰炸类严重度**下调**
- 校验侧连续错误码**无锁定/无失效/无递增延迟** ⇒ 暴力破解类严重度**上调**

判据:同一请求连发 N 次(如 12 次),观察是否出现锁定、验证码失效、封禁、递增延迟。

## 整面低价值的识别(及时收手)

拿到一堆端点后先判断"这整面是不是业务面":

- 消息/字段命名是 `appId` / `os` / `step` / `time` / `user` / `platform` 这类 ⇒ **客户端行为埋点 / analytics SDK**,不是业务 API。其 403/404 是**正常来源校验**,不是漏洞 —— 记一笔定性结论即可收手,别在签名上耗轮次。
- **前端 config 里的角色/类型开关**(`USERTYPE`、`role`、`isAdmin` 之类)先 grep 它在 bundle 里的**命中数**:命中 0 ⇒ **死配置**,前端从不读取 ⇒ 别为"篡改它提权"耗轮次(角色由服务端按账号判定)。
- **同族多端可能是同一份构建**:判据是**比 bundle 字节数 + 比 config 读取函数的解构字段**;同尺寸且读取模式逐字相同 ⇒ 单一构建多部署,差异只在 `_app.config.js` ⇒ 多端只审一份,别重复逆向。

## 什么时候才能下阴性结论

三条全满足才能写"该面防护到位":

1. 每个端点都发过**合法形状**的请求(正确前缀 + 正确字段名 + 正确方法)
2. 整批带了已知-good 对照端点且它正常
3. 至少发过"无凭据"和"无效凭据"两态

不满足就写"探针未验证",不要写"已排除"。

**否定原因必须分类标注(不许一律写"已排除")**——三类否定的可信度完全不同:

| 类别 | 成立条件 | 写法 |
|---|---|---|
| **无触发面** | 路由/功能本身不存在(候选路径全 404、站点无对应组件、无上传/无 URL 参数消费) | "不可测 / 无触发面" |
| **已排除** | 测过且无差异,或**版本/代际指纹**证明不落在受影响区间 | "已排除(附指纹依据)" |
| **未测** | 缺前置条件(无会话、无凭据、无回调) | "未测" — **无 token 时整批 401 不等于打过** |
| **不可校准** | 端点对**任意载荷**(含空体)回同一句业务文案,**不报 schema 缺字段** ⇒ 没有参数名/存在性 oracle | "不可校准" — **命中与未命中不可区分**,该端点上的弱口令/枚举阴性结果**不成立** |

★ **第四类「不可校准」最容易冒充「已排除」**:端点**完全不报 schema 缺字段**(空体即回业务错误,如 `密码错误`)时,参数名 fuzz 永远零信号 —— 你无从知道"没命中"是密码错、参数名错、还是账号不存在。
⇒ 判据:同一端点发「空体 / 缺字段 / 类型错 / 多组参数名」——**四发全同句** ⇒ 该端点无 schema 层,收线换面。
⇒ 这类端点上跑出的字典结果**一律写「不可校准」**,不得写「已排除(N 组无命中)」;要解锁必须先找到一个**随输入变化的读数**再谈命中率。

拿到会话/凭据后,一切此前标"未测"的应用层面**必须重打一遍**再下结论——这是拿会话后第一个动作,不是可选项。

**注入面的阴性判据与 `500` 的成因判别**:

- **同族 payload 全 `422` 且耗时恒定**(如 9 组注入 payload 全 ~0.15s、文案"信息填写有误")⇒ **格式/类型校验前置于数据层访问**,该注入面判死;耗时随 payload 变化或错误题面推进 ⇒ 才值得继续跟。
- **`500` 未必是注入命中**:重复同形请求恒 `500`、无 SQL 特征、无布尔/时间差异 ⇒ 记**未捕获异常/健壮性缺陷**(低危可报),不要写成"疑似注入"。
- **参数类型污染打守卫 → 500 也是健壮性缺陷,不是绕过**:字符串参数发成数组(`token[]=1`、HPP `token=1&token[]=1`)常令守卫/比较逻辑抛未捕获异常(500)⇒ 记 robustness(低危可报)后**收线**,不要在数组形态上继续找"绕过" —— 它连正常分派都到不了。
- **命令/模板注入的首选证明是无害算术预言机**(提交 `a*b` 看回显或响应头是否等于乘积):可证执行且零副作用,优于反弹或写文件。

"可拖全库""影响严重"这类断言必须带实测数字。列表端点的产出测量方法见 `references/list-endpoint-enumeration.md`。

## 交付

结论分栏写:**已验证 / 探针未验证 / 已排除 / 已作废(需重估)**。已排除的面也要写进报告 —— 负面结论能替后续轮次省下重复探;**已作废**那栏必须附作废原因(通常是补了 `Host`/前缀/占位符后结论翻转),否则后续轮次会把作废结论当既成事实,既重复浪费又漏掉真面。

**计数纪律**:报"放行 N 个 / 裸奔 N 条"之前,先从计数里剔除**容器 HTML 错误页**与**代理层响应** —— 它们不代表鉴权放行。混进去的数字虚高,事后必须在报告里撤回,可信度代价远大于数字好看。

### 交付自审:派生数字必须**重算**,grep 反查不到

关键词反查(逐条结论 grep 命中原始终端日志)只能验**引文**,验不了**你自己算出来的数**:百分比、比例、条数、字节数这类派生值写错时,grep 查不出来(它去查的是源头文件,不是你的算式)。实测事故:给一批探针写有效性判定时凭记忆写下"未知率 18%(6/33 为 302)⇒ 该批降级",而原始日志的统计行原文是 `统计:302 数=0 / 总 33` ⇒ 未知率 0%、**该批其实有效**,降级理由全错(还白白作废了一批好数据)。

- **规则**:凡写进交付的派生数字,自审时**用脚本从原始产物重算并打印**(`code=NNN` 计数、`len` 求和、比例、去重后动作数),重算输出留痕;grep 只负责引文与文件名。重算与文中数字不一致 ⇒ 以重算为准并改文。
- **写批次质量判定时直接引用原始统计行的原文**(如 `统计:302 数=0 / 总 33`),不要转述成百分比 —— 转述就是引入错误的那一步。
- **审核脚本自身也要自检**:审核报 `FAIL` 时,**先证明这条检查能命中一个已知阳性样本**,再去改文档。实测一条检查因正则把行内顺序写反(行里 `code=302` 出现在标记 `★差异` 之前)而误报失败 —— 若照它"修文档",就会把**正确**的内容改错。凡判定"文档写错了",先排除审核脚本自身的错误。

### 批次有效性登记表(交付必带)

多批实测后,交付里必须有**批次有效性表**,否则作废批次会被后续轮次当既成事实复用:

| 栏 | 内容 |
|---|---|
| 批次 | 脚本 + 输出文件对(可回查) |
| 判定 | ✅ 有效 / ⚠️ 降级 / ❌ 整批作废 |
| 依据 | **原始统计行原文**(如 `302 数=0 / 总 33`、`★差异 75 行 100% 为 code=302`) |
| 可用性 | 可引用 / 只可写"单批观测" / **不得引用其存在性结论** |

判定口径:未知率(`302`/`0B`/`000`) > 5% ⇒ 降级;某区块**0 有效样本** ⇒ 整批作废;同账号并行脚本互相顶号 ⇒ 后跑的那批作废。**作废批次要写清被哪批取代**,否则下轮会对着作废批复盘。

**"单批观测" ≠ 已确认**:某动作只在一次批次里测到 `200`、又未在任何洁净批复测过 ⇒ 只能写"单批观测"并列入待复测清单,**不得写"已确认"**;交付要附"已复测 / 未复测"动作清单,让下轮知道哪些结论可以直接用。
