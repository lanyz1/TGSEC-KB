# API 探针判层与自检

> 探针返回的状态码只说明**你处在哪一层**,不说明目标安不安全。下任何"受保护 / 未授权"结论前,先确定自己在哪一层,并让这批探针具备**能自证失败**的能力。

## 触发场景
- 一整批端点探针回来全是同一个错(全 401 / 全 422 / 全 404 / 全超时),要决定是不是收口
- 想写"该端点未授权"或"该面防护到位"的结论
- 请求发出去了但服务端像没听见(报的错和预期完全不是一个话题)

## 判层表:状态码决定你在哪一层

| 响应 | 所在层 | 含义 | 下一步 |
|---|---|---|---|
| 连接失败 / 0 / 超时 | **网络层** | 跳板机/隧道/出口/代理问题 | 先修通道,此时任何应用层结论作废 |
| `404 资源不存在` | **路由层** | 路径不存在(注意区分业务 404 文案 vs 框架 404) | 换路径 / 补 base path 前缀 |
| `405` + **框架 JSON**(`{"msg":"Request method 'GET' not supported","code":500}` 类) | **路由层** | 路径存在、方法不对 ⇒ **该端点真实存在** | 换方法重探,这是有效情报 |
| `405` + **HTML**(`<!doctype html>` / nginx `405 Not Allowed`,**无业务体**) | **前端/代理层** | 请求被**静态前端兜底**接走 ⇒ **不携带任何路由存在性信息** | 与同批 JSON 响应**分层登记**;**不得**据此写"该端点存在" |
| `302` → `Location: /login`(body 0B) | **鉴权层(formLogin)** | 端点真实存在,只是未带会话被重定向登录页;⚠**302 有三种成因**,见下《302 的三种成因》 | 与同批**真放行**端点对照(后者回 `200` 而非 302);⚠**只换用户名**再做一组,别把账号风控当成路径收回 |
| **HTTP 恒 `200`** + body `{"code":401,"msg":"请求访问：<path>，认证失败，无法访问系统资源"}` | **鉴权层** | 该框架 HTTP 码恒为 200,否则信号全在 body 的 `code`/`msg` 文案 | **判层禁止用 `%{http_code}`**,必须读 body 文案(否则 405 会被当成 200 放过) |
| **HTTP 200** + body `{"msg":"Request method 'GET' not supported","code":500}` | **路由层** | 405 语义藏在 `code:500` + 文案里 ⇒ **真实存在且已放行** | 这是**最强的存在性正证据** |
| **HTTP 200 + `Content-Length: 0`** | **第三态(默认)** | 可能是无注册路由,也可能是**中间层限速潮**(数十秒~数分钟自恢复);**“整批全 0B”几乎必是后者** | **0B 一律先记第三态必须复测**;仅当“同前缀假路径”与“真实路径”在同一次干净复测中同为 0B 才可判阴性 |
| 全部动作口同时回同一句 `"please sign in"`/`code:999` | **会话层** | 会话失效(**⚠️ 不要把死因归为“换出口 IP”** —— 实测同一会话跨多个出口 IP 连续正常,**IP 绑定假说已被否证**);真因通常是**复用的 jar 里 cookie 已过期** | 重新登录生成新 jar;**勿用旧 jar 的“无票”结论**;★但**票据型凭据(WAF/挑战 token、一次性 ticket)** 可能**真绑出口 IP**,跨出口复用得 401 —— 换过出口必须补一组 A/B 再判,参见下《凭据产物卫生》 |
| `422` + 字段错误 | **schema 层** | 字段名/类型不对,**还没到鉴权** | 读报错体拿字段名 |
| `401` / `403` | **鉴权层** | 真到了鉴权判断(**先分流**:纯文本 `Forbidden`(Spring 默认页) = **请求形态/信封缺失,origin 自己拒**,不是权限;带业务 `msg` 文案的才算鉴权层) | 做三态对照(见下);403 Forbidden 先**补加密信封**重发 |
| `200` + 业务错误 msg | **业务规则层** | 鉴权过了,被业务规则拦(会员/额度/状态) | 这是漏检线索(见下) |
| `400` + **容器 HTML**(Tomcat/Jetty `HTTP Status 400 – Bad Request`) | **URL 解析层** | 请求没进应用(最常见:路径里的 `{id}` 占位符没替换成实值) | 替换占位符后重发 —— 当前响应**无判读价值** |
| `200` + **空体** | **路由/传输层嫌疑** | 很可能 Host 或前缀选错了(见下节) | 先补对照再判,别直接记成"不存在" |

**铁律**:`422` 不等于测过鉴权边界 —— 你连合法请求都没发出去,此时任何"受保护"结论都无效。
**铁律二**:容器级 HTML 错误页 = 请求**没到应用**;任何"状态码说明鉴权"的读法对它都不成立。批量扫描前第一件事:把路径里所有 `{param}` 占位符替换成实值,否则一批"放行"里混的全是假信号。

### 两种框架 404 必须分栏:绑定层 404 = 无鉴权存在性 oracle

同一框架内 `404` 至少两个层次,**文案/字节数不同 —— 按 response body 校准,不看状态码**:

| 404 体 | 所在层 | 含义 |
|---|---|---|
| 「資源未找到」/「资源未找到」类**资源**文案(~44B) | **绑定层**(route-model binding) | 路由**存在**、记录**不存在** —— 且该判定**先于鉴权中间件执行** |
| 「頁面無法找到」/「页面无法找到」类**页面/路由**文案 | **路由层** | 路由不存在 |
| **404 文案报的是「参数实体」而非「路由/资源」**(如 `用户id不存在` / `该用户不存在`) | **路由层 + 参数层** | **两种成因,先按下面《空基线判据》二分**:真 = 路由存在且该参数是必填标识(喂**合法**值后文案推进);假 = **前缀兜底文案**,整族端点根本不存在 |

### 空基线判据:先证明那句文案是「参数 oracle」还是「前缀兜底」

`<参数>不存在` 类 404 **不必然是参数 oracle**。同一 `/v3/<前缀>/*` 下的**通用 router 兜底**会回你逐字相同的文案。判据只有一发:**完全不带任何参数的裸路径基线**。

- **空基线也回同一句** ⇒ 该文案是该前缀的**兜底文案**(路由不存在),**不是**"鉴权已过、只差参数名"。再叠加「候选参数名 × 多标识形态(短码/数字 id/别名)全返同句」⇒ **整族判死,停手别再猜参数名**。
- **空基线回的是另一句**(缺参/必填文案),补真实值后文案推进 ⇒ 才是真 oracle,继续按本卡推进契约。
- 实测代价:一族 5 个端点带票恒回 `404 用户id不存在`,连发 **9 种参数名 × 3 种标识形态全同句**,差点写成"鉴权已过、只差 user_id 参数"(假阳性)。补发**裸路径空基线** —— 同样一句 ⇒ 兜底文案 ⇒ 该族端点根本不存在。
- **兜底文案是前缀级的**:`/kol/*` 回「资源不存在」、`/v3/user/*` 回「用户id不存在」是**同一机制的两个前缀**。**一个前缀的 404 文案判读不可跨前缀套用**(呼应本卡《命名空间决定 0B 的含义》)。
- **顺序铁律:`空基线 → 传输载体 → 参数名候选`。** 颠倒顺序就会把"端点不存在"写成"参数名没找对",白烧一整轮。

★ 由此得到**无需任何凭据的存在性 oracle**:带 binding 的 `{id}` 路由 —— id 存在 → 走到鉴权 → `401`;id 不存在 → 绑定层直接 404(资源文案)⇒ `401 vs 404` 差分可**无损枚举任意 {id} 是否真实存在**,再用二分/步长采样估表规模(实测 …500 全 401、800 回 404 ⇒ 表 ≥500 行)。
校准前置:一个必不存在的 id(如 `99999999`)+ 一个已知存在的 id 各打一发,确认两档文案/字节数可区分再批量;两档同体 ⇒ 该实例零区分度,oracle 作废,别硬跑。

### 422 的两种成因必须「无参 → 补合法参数」两发分辨

`422` 既不能一律当"参数问题"排掉,也不能一律当"已过鉴权"。**同一个 422 有两种成因,补参一发即可分开**:

| 两发的结果 | 判定 | 动作 |
|---|---|---|
| 无参 `422 缺字段` → 补上**合法**参数后翻回**鉴权层任一文案**(`401 not authed` / `403 无授权信息` / `请使用…App扫码登录` / `not admin`) | 参数闸只是**先于**鉴权跑,**该路由没有漏配** | 判死这条路径,别再补参数 |
| 无参 `422` → 补参后仍停在**参数级**文案(`Invalid value.` / 又报另一个缺字段) | **已越过鉴权层**,该路径未挂鉴权 | 继续拿报错文案当进度条推进契约 |

实测代价:某特权路由族里两条路径无参都回同类 422,读数一样;补参后一条回落 `401 not admin`(真受保护),
另一条继续报 `Invalid value.`(真漏配)。⇒ **凡"该路径未鉴权"的结论,必须出自补参之后仍停在业务/参数层的读数**;
只凭无参 422 写"绕过"就是假阳性。
**同一个 `422 <参数>信息填写有误` 会让整族端点看起来"未鉴权"**:实测某公司族三条端点无参各回同一句
`422 code信息填写有误`(存在性 + 缺参 oracle,文案与参数名都给全),拿**真实值**补发后三条分别翻回
`403 无授权信息` / `403 请使用…App扫码登录` ⇒ 全是受保护的,此前"未鉴权"的读法是错的。
⇒ 规则:**422 必须用真实值补一发才能进任何栏**;"缺参"与"未鉴权"不是同一件事,前者是你自己没发对请求。
参数名已由文案白送,补发成本是常数,别省这一发。

### 参数被忽略的判据 = 常量返回(换标识形态重测,别只换值)

同一资源常有**两套标识命名空间**:对外的短码(`code`,如 `4ak1x2e5d`)与**内部数字 id**(如 `3203039`)。同一路由的两个参数名,读数可以完全相反:

- `GET /user?code=<他人码>` → 恒返**自己**的数据 ⇒ 该参数被服务端忽略;
- `GET /user?id=<数字>` → `200` 换到了目标。**换的是标识形态,不是值。**

规则:
1. **"参数被忽略"的判据是常量返回三发自证**,不是"看着像我的数据":传两个**已知不同**的值 + 一个**不存在**的值,三次响应逐字节一致 ⇒ 参数被忽略。工单里"参数名无效"这四个字必须有这三发读数撑着,否则就是猜。
2. **参数名读数为"忽略"时,先换另一个参数名 + 另一种标识形态(数字 id / 短码 / UUID / 业务单号)各发一发,再判死路由**。把"该参数无效"直接写成"该路由无 BOLA"是这一层最常见的漏检。
3. **数字 id 的产地是列表/流水响应里的图片路径**:头像 URL、对象存储 key、快照路径常内嵌内部数字 id(如 `wx_avatar_p/12643381.jpg`),它比 code 更值得拿去当 BOLA 的 key —— 而列表接口本身可能被字段裁剪(只回 6~9 字段、无联系方式),数字 id 照样在里面。
4. 公开详情接口**按字段裁剪**时,统计一次「取全字段后仍缺哪几个敏感字段」并列表记死(实测某详情口 58 字段全取仍无 `creator_wechat`/`contact_qrcode`)⇒ **该字段不在这个接口**,它必然有独立接口,下一步是找那个接口,不是在这个接口上继续做参数穷举。

### 特权路由族漏配猎捕

后台路径族(如 `/admin/*`)的鉴权**逐条挂在路由上**,于是族里必然混着没挂的。做法固定:

1. 从**后台自己的 bundle** 取特权路径全表(见 `spa-request-contract-extraction` 的《管理端 / 多端 bundle》),不要靠路径词典猜。
2. 每条路径发 **GET** 一发 + **空体 POST** 一发(空体到不了业务 ⇒ 零写入;注册/新增类端点例外,它们空参真建对象,跳过)。
   ★★ **「无参」≠「零写入」，必须先按动作名分栏**:动作分发型端点(`?action=<name>` / `/api/<动词>`)会把**缺参**解释成**「对全部对象执行」——
   `clear`/`flush`/`purge`/`reset`/`rebuild`/`reload`/`delete`(-all)/`truncate`/`backup`/`restore`/`install`/`activate` 这类动作**无参一发就全量执行**
   (实测代价:盲枚举一批未知 action 时,空参打中的缓存清除动作当场清空**全站 30 万条缓存行 + 160 个 Redis 键**,并连带触发全量重建)。
   ⇒ **只有「读形状」动作**(`list/status/get/query/info/config/preview/test`)**允许空参基线**;**写/破坏形状一律发「必然不合法」的载荷**(缺必填、类型错、不存在的 id),
   让**参数校验先失败**、业务动作不执行 —— 这才是「摸到契约但零副作用」。**破坏性动作恰恰常常没有参数校验**,所以「空参安全」的直觉在这里是反的。
   ⇒ 枚举前先给这批调用**记账**(动作名 + 载体 + 实际发出去的参数),报告里要能说出「我对哪些动作发过什么」。
   ★**凭据矩阵必须是三态,不是两态**:`无票` / **普通用户票(非特权)** / `特权票`。
   只跑「无票 / 带票」两态时,**必须在记录里写清带的是哪一种票** —— 否则两类完全不同的结论会撞成一条:

| 凭据 | 读数 | 结论 |
|---|---|---|
| 无票 | `401 not authed` | **不是免票**(别写"免票") |
| **普通用户票(非特权)** | `200` 真业务数据 | ★**只校验登录、未校验角色** = role 漏配 |
| 特权票 | `200` | 与前一行同读数,无法区分 |

⇒ 实测同一路径曾被记成「免票 200」,复核发现无票是 `401`、带上自己(非 admin)的票才 `200`。
前者让人以为"任何人都能打"(错),后者才是可用结论:**手上任意一个已登录账号的票就能直接打通整个特权数据口**。
role 漏配比免票**更常见也更好用** —— 免票要求目标恰好没挂认证,role 漏配只要求它没挂角色校验。
⇒ 已注册/已登录的**普通账号本身就是资产**,先用它把整族重扫一遍再宣布"要 admin 票打不动"。

★**但三态表里的 `200 真业务数据` 必须再过一道「self 还是全站」的闸,否则会把"读到自己"写成"越权"**:
同一批带票 200 的端点里,相当一部分是 **self-scoped** —— 它们返回的只是**当前登录用户自己**的资料/会员/订单/反馈。
实测:一轮全端点差分扫出 8 个"普通登录可读"端点,逐条读体后 **6 个是 self**(`/user` 回自己资料、`/membership` 回自己会员状态、
`/merchant/info` 回 `id:0` + 自己的昵称、`/ps/orders` 与 `/feedbacks` 回空数组),看着"非 401"很激动,实为**零越权零价值**;
只有 2 个是 admin 命名空间下的真·全站数据面。
- **判据(必做)**:换一个**归属已知不同**的账号(或第二账号)打同一端点 —— **数据随账号变 = self(无价值);不变 = 全站(真发现)**。
  没有第二账号时,退而查返回体里有没有**归属字段**(`id:0` / `nickname` 与登录账号一致 / 数字 `id` 恒等于自己的)。
- ⇒ 只凭"普通票 200"就写"role 漏配"是这一步最常见的假阳性;**结论必须写清是 self 还是全站**。
- **同源陷阱:`dashboard` 类端点的 `count` 字段只是展示计数**。实测某 `vip/dashboard` 免鉴权回 `count: 21124`,
  旁边配套的 `feedback`/`recent_avatar` 数组却**恒定只给 3 条预览**,且 `page_no`/`page_size`/`page` 等 8 种分页写法**全部被忽略**(读数逐字相同)。
  ⇒ **看到大 `count` 先别写采集器**:先确认该端点存在**分页入口**(meta 里的 `total`/`size`/`start_index` 是否随参数变化),再谈拉全量;
  恒定返回的"计数 + 3 条预览"通常只是首页展示用,全量列表在别的(可能已判死的)命名空间。
3. 按读数三分:
   - `401/403` 带业务文案(`not admin`/`权限错误`)= 受保护,**同时是路由存在的正证据**;
   - `405` / 框架参数 `400` = 过滤器已放行(见《写类端点零副作用测鉴权》);
   - **`200` 真业务数据 / `422` 参数级文案 = 该条漏挂鉴权** ⇒ 立刻定栏并补一发复测坐实。
4. **报计数,不报结论**:给出「族内 N 条:受保护 M / 漏配 K」,漏配的逐条列端点 + 回包样本。

实测一个 `payment/…/query` 系路径:同族其余全 401,它两条 GET 直接回**全站账单**(每条含付款人 `user{id,nickname}`)与开票申请实名。
这类漏配是「整族扫一遍」的产出,不是运气 —— 拿到一个新后台族,先机械榨路径表再整族扫,是第一动作。
