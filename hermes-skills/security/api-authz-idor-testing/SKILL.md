# API 越权(IDOR)系统化测试与全库数据获取

目标"用户信息/资金数据"时**别逐接口瞎撞**。流程:接口全集(见 `spa-api-discovery`)→ 合法测试账号 → 按本节分类测越权 → 多机编排全量拉取。全部方法论经抖啦咪(doumvips.com,69 万用户)实战验证。

## 1. 先分类鉴权中间件(看报错格式,一票定族)

同一后端常叠两代/三代鉴权,报错格式 = 中间件类型:
- **新中间件(强绑)**:换 uid 立即拒,报错如 `{"status":100004,"msg":"用户参数异常"}` / 带 `"request"` 回显 — uid 必须==token 用户。
- **老中间件(只验 token 存在性)**:任意有效 token 即过,接口内部信任 `user_id/uid/id` — **伪造参数即越权**(IDOR 主战场)。
- **owner 校验中间件**:报 `9999 系统错误` 常 = `uid参数 == 资源owner` 校验失败(非真错误)— **试传资源 owner 的 uid**。

分类法:同一接口换 uid(自己 vs 他人)看返回;不报"参数异常"=弱。老接口常无 `/api/` 前缀(get_user_info/tiktokIncome/withdraw/agent_whether/searchUser…),先批量打这批。**参数污染(别名/重复/大小写/浮点/数组)对强绑接口基本无效,别耗时间。**

**会话票先做"结构伪造 4 连测", 再当它是不透明随机串**: 票形如 `<平台ID>_<userID>_<uuid>` 时, 用**自己账号**的票逐段变异各打一次自证端点 ——
① 原票(基线) ② 换 uuid(保留自己 userID) ③ 换 userID ④ 截断 / 多接一段。
**全 401 ⇒ uuid 参与服务端校验, 票不可伪造, 该路判死、不再死磕**; **任一非 401 ⇒ 票可伪造 = 直接横向/纵向接管, 优先打**。
前提: 基线端点必须**回显身份**(返 nickname/uid), 否则无法区分"票被接受"与"该端点本来就不看票"。

**用别人的身份拿不到数据时, 别急着怀疑票 —— 也可能是「字段按身份裁剪」而非「鉴权」**: 见 §10 末条字段集差分。

### 1.1 判定「参数被丢弃」的三值差分(结论粒度到端点, 不到族)

判一个越权读端点是否成立, 标准动作是**三值差分**, 而不是「传了目标 uid 返空 ⇒ 无越权」:

| 发法 | 真越权应有的表现 | 参数被丢弃的特征 |
|---|---|---|
| 不带该参数 | 报缺参 / 返自己 | 正常返自己 |
| 目标值 | **目标的数据** | 返自己 |
| 随机垃圾值 | 不存在 / 空 | **与上一行逐字节相同** |

- **必须核对响应体里回述的对象标识字段**(`uid`/`userID`/`thirdPartyUserId`)是否等于你投进去的值 —— 只看"载荷非空"会把「服务端按会话身份返了我自己的数据」读成「拿到了目标数据」。
- **结论粒度 = 端点, 不是族**: 同族(资产族 / `*ForThirdParty` / `getUser*`)里 A 丢弃参数而 B 认参数并返目标数据是常见共存形态 ⇒ 只能写「该端点无越权读路径」, 写「该族无越权」会被兄弟端点推翻。
- **⚠ 差分结论必须标注它是在哪个「请求配方版本」下取得的**: 签名算错 / 漏必需头 / body 没过信封层时, 中间件会用**同一个错误码**、或**按会话身份回的默认载荷**盖掉全部入参差异; 那个逐字节一致是**请求被挡出来的**, 不是 handler 忽略参数的证据。配方一改, 旧差分结论降级为待复证(判据与挖坑记见 `signed-api-gate-oracle-hunt` §7 末两条)。

## 2. IDOR 批量测试要点

- 参数名随接口变:`user_id / uid / id / child_uid / member_uid` — 逐个换目标 uid 看返回变化。
- 优先测资金/绑定/身份返回类(getXxxIncome、getBindXxx、user_account、agent_whether)。
- **★ 同一个参数名 ≠ 同一个 ID 命名空间**: 一个后端常用 `uid` / `id` 一个名字指三层标识(对外 prettyID/短号、内部雪花用户 ID、第三方案件号)。喂错命名空间的典型失败态是**返回全零/空记录**而不是报错 ⇒ 与「该对象不存在」**不可区分**, 结果是把「我喂错了」写成「这条数据没有」。**先用已知真实样本(配置接口泄露的 id、审核号、自测对象)把该参数吃的命名空间标定出来, 再对目标判存在与取值**; 标定前的一切"不存在"结论作废。
- 采样 uid 全段(1/1000/50000/max-1)证明可遍历 + 数据因人而异 → 影响面实锤写报告。
- **★ 逐条枚举 ID 区间之前, 先算「ID → 时间」把空间缩成窗口**: 详情接口的 ID 常是可反解时间的编码 —— 雪花 ID `ms = (id >> 22) + EPOCH`(Twitter 系 `1288834974657`; 先拿两条已知时间的记录反解 epoch 与移位数), 或 `时间戳×倍数+序号` 的自增主键。建“id → 时间”映射后, 用目标**已知的活跃时段**(上新日/下单/公告/发布日)反推目标所在区间, **只在窗口内定点扫**。百万级表逐条枚举既慢(~0.7s/条 ⇒ 数小时)又会把出口打进挑战态。**先分清同一响应里的 `id`(自增主键, 无时间信息)与 `messageId`/`snowflake`/带时间戳后缀的 orderNo(才是雪花)** —— 拿错字段算出的时间是垃圾, 算完先与响应里的 `createTime` 对一条自证。实战: 百万级通知表盲扫 2000 条 0 命中; 按雪花映射把窗口缩到 ~900 条后一次命中目标全部资金流水。
- **批量端点判越权: 用「两个自有账号各自合法出票」对账, 而不是只换参数值**。同一批只读端点(A 票打一遍 / B 票打一遍)
  逐项比对返回里回述的身份字段与条目集: 每条都只回本会话的数据(下级列表 A=1条 / B=0条, 团队报表 2条 / 1条, 自助信息各回自己 uname)
  ⇒ 该批**批量判为无越权**, 一次写进台账判负区(下一轮不再重复投入); 任一接口回出**另一方账号**的数据 ⇒ 越权成立, 单独立案。
  **负结果与正结果同等登记** —— 不登记就会在下一轮被当成"没测过"整批重打, 这是长跑里最大的重复劳动源。
- 写接口(提现/改资料/绑卡)只验证校验缺失,不真动账;资金操作先征得用户同意。

## 3. 业务归属校验陷阱(最难发现也最值钱 = PII 明文出口)

接口校验 `uid参数 == resource.owner`(如 uid==teacher_uid)**却不校验 token 归属** → uid 参数改成任意 owner uid 即拉其名下全部资源(学员/订单/审核列表可含**完整手机号+微信号明文**,展示接口打码但数据层明文)。

发现路径:页面渲染明文 PII(phone/wechat)的"导师/审核/学员/订单列表"管理页 → 反向定位数据接口 → 自己当 owner 验证基线 → 伪造 owner uid 拉全量。

## 4. 枚举资源 id:参数名陷阱 + 下架资源

- 页面跳转 URL `?id=` **原样传接口**(常是 `id`,不是 course_id/user_id;如 course_detail?course_id=20 报 9999、?id=20 成功)。先还原前端页面 `onLoad` 取参逻辑。
- 顺序枚举 id(1..N)可挖**下架/隐藏资源**(列表接口 status 过滤,直查 id 仍返回数据)。

## 5. nginx 403 ≠ 接口不可达(路径级访问控制绕过)

- 目录页(`/legacy/`、`/douxingbang/`)403 常只挡静态/HTML 入口;**真实框架入口 `public/index.php`(ThinkPHP)可能直接 200**。
- 403 后先试:框架入口文件、`?s=/api/controller/action` 兼容路由(登录/注册表单常可 POST);再试路径编码/大小写/IP+Host 直连/XFF 伪造/UA 伪装/HTTP/1.0。WAF 挡"机房 IP 访问目录页"时 API 入口往往裸奔。
- 老活动/打榜/投票类 TP 站(index/user/login.html、api/sms/send、api/user/login)常有**独立用户库**,可测主账号能否直接登老系统(同库判定:同一手机号+密码双站可登 = 同库,重大发现)。

## 6. 前端构建泄露 → 新旧版本 diff

- 站点根 `/web.zip` `/admin.zip`(nginx 静态 root 直出)。可能是纯静态前端(48MB 也常见,**不含 DB 配置,别高估**)。
- 解包与线上 chunk 对比接口全集,旧版独有接口 = 后端可能仍存活的老功能(弱鉴权/未下线数据)。版本 diff 是标准动作。

## 7. 多机全库拉取编排(跳板机/云主机)

- 分段 `start..end` + 每台独立 JSONL + 断点文件(定期写 `min(queue)-1`),重跑跳过已做。
- **单实例铁律**:paramiko `exec_command` 启 nohup 后台任务读 stdout 会超时——**"超时"≠失败,进程可能已启动**;用 SFTP 传 start.sh + `exec_command("nohup bash start.sh >/dev/null 2>&1 & echo PID=$!")` 立即返回,启动后 `ps|wc -l` + `tail run.log` + `wc -l out.jsonl` 验证单实例(重复实例并发写同文件 = 脏数据 + checkpoint 竞争,曾致 3 实例事故)。
- 8 workers ≈ 6-16 uid/s(每 uid ~6 请求),连续 N 次 token 失效自动熔断;先 smoke 60 uid 验证 token 存活+结构,再放全量。
- 本环境审批护栏:批量循环脚本无人值守常被拦;拆"单条命令探针"(一条一查)可过;重大批量先列清单等用户放行;登录尝试单独触发护栏。

## 8. WordPress 插件层"参数即身份"三连(2026-09,批量 ATO 面)

WordPress 站点的真实攻击面在**插件**(每年数千条 CVE,多为**未认证可达**);共性根因 = 插件把**客户端可控参数当作身份/归属依据**:

- **Frontend Admin by DynamiApps CVE-2026-75816**(≤ 3.29.12)——认证绕过 → **账号接管**;缺陷点在插件处理 user-email 字段的类(`.../frontend/fields/user/class-user-email.php`),即"资料字段被当凭证"
- **HivePress Authentication CVE-2026-18056**——`access_token` 参数即认证绕过;NVD 引用链接指向 Facebook Login manual-flow,即插件**把外部 OAuth token 当本地信任凭证**
- **MemberDash CVE-2026-16310**(≤ 1.8.5)——`id` 参数 IDOR(会员/订阅对象越权读写)

批量打法(类级):
```
1. 指纹插件版本: /wp-content/plugins/<slug>/readme.txt 的 "Stable tag"、静态资源 ?ver=<版本>、页面 HTML 注释
2. 插件 slug + 版本 → 映射 CVE(NVD keyword "WordPress plugin <slug>";WPScan 数据库)
3. 优先打"未认证 + 参数即身份"的洞: access_token / id / email / user_id / uid 传参即信任
4. 验证标准 = **最终业务状态**(用目标账号读到私有数据 / 改掉密码成功),不是只看 200
```
审计任一 PHP CMS 插件时先 grep 这三类参数当凭证的位置;同族通用形态见 §1 鉴权中间件分类。
来源: NVD CVE-2026-75816 / CVE-2026-18056 / CVE-2026-16310(2026-09 NVD 新增,均为 WordPress 生态)

## 9. 源码侧越权审计(白盒): 差异法 + 两层都要看

黑盒靠报错格式分类(§1);**有源码时更快的路是差异法** —— 一个模块的防护模式是统一的: 先证明模式存在, 再找违反它的那几个。

1. **先立对照组**: 同一批同类 handler 里大部分都调了权限检查(如某服务层文件一个文件里调了 5+ 次 `CheckPermission(..., 资源ID)`) → 证明"设计上要求检查"。
2. **再找例外**: 同文件/同级模块里一次都没调的那些。
3. **两条缺一不可**: 模式存在 + 个别遗漏 = 漏洞; **若整个模块都不检查, 更可能是设计如此**(Login/Signup/健康检查本就不需要鉴权)。

**两层都要看, 只查一层会漏**:
- **路由层**: 功能组的 `Group` 是否挂了权限中间件。漏的那组往往**只挂了认证**(如 `JWTWithConfig`), 而权限组挂的是 `SuperXxxGroup()` 这类角色校验 —— 同文件里两相对照, 一眼可辨。
- **Handler 层**: handler 是否**取用户身份**。**不取 `c.Get("auth")` / 不解析 token 的 handler, 物理上不可能做归属校验** —— 这是最硬的信号。

批量执行: `scripts/audit_perm.py <项目根>` 出候选清单(函数粒度统计调/不调, 正则要卡在调用形态 `Check[A-Za-z]*Permission\(` 而不是关键词 `[Pp]ermission` —— 后者会把"只引用了权限常量名、根本没校验"的也算成有检查)。

**⚠️ 别把"许可证拒绝"当成"有鉴权"**: 看到 `CodePermissionDenied` / `PermissionDenied` 先追它的来源 —— 若来自 `licenseService.IsFeatureEnabled(...)` / plan / subscription 服务, 那是**付费功能开关**, 与权限无关。**误判的代价是漏掉一个真实越权。**

**上报前的信任边界自检(两条都过才算)**:
1. **这个变量的写入者是不是受害者本人?** 例: CI 平台注入的 `CI_API_V4_URL`、跑该代码的就是使用者自己 → 访问自己的资源 = 预期功能。**静态扫描器给出的 HIGH/HIGH 发现同样要过这一关** —— 工具能给数据流, 给不了信任边界判断。
2. **权限是否不对等?** 只有"平台持高权连接/高权服务账号 + 攻击者只有低权账号"才构成提权; 两者权限相同则不成立。二阶注入类尤其如此 —— 变量来自数据库读回的对象名(`rows.Scan(&name)`)而非直接输入时, 还需先确认**目标数据库是否允许该标识符含 payload**(Oracle 标识符限制严格、基本不允许; MySQL/PG/MSSQL 通常允许)。

## 10. 表级接口全封时: 衍生表合成(旁路拿"用户表/商家表")

目标不总给你 `/user`、`/merchant`、`/company`、`/admin/*` 的越权。当**表级接口全部 401/404** 时, 不要收手写"拿不到用户表"——
**已拖到的业务记录里通常内嵌了身份对象**, 可以合成衍生表。

1. **穷举后再下结论**: 把路由清单里含 `user|merchant|company|member|kol|invite|order|admin` 的路径批量打一遍(无 token), 按 401/404/405/200 分类。
   **405 的用 POST + 缺字段体补测**——鉴权一般挂在装饰器上、**与请求方法无关**, 补测才能把它定性为"已鉴权"而不是"路由不存在"(空表单体可用于导出/查询类路由; 注册类端点空参真建号, 一律用缺字段体)。
   - **命中信号（非 404 才算命中）**: `405`(`Allow: POST`, 路由已注册、方法绑定层才拒 ⇒ 鉴权与请求方法无关, 对该方法同样漏挂, 补测缺字段体)、`422`/参数校验错误(已穿过鉴权直达框架校验层 ⇒ ★漏挂确认, 且校验层免费吐出参数名契约)、业务错误码 —— 三者都算命中。只有 `401/403/302→login` 判负, 但**端点存在**这一点要记进清单(下一轮可能靠别的路径到它)。
   - **免票命中常是整族里的少数几条, 且集中在"后加的独立模块"**: 实测一个整族 `401 not admin` 的 `/v3/admin/*` 里,
     只有支付/开票(`/admin/payment/fapiao/{query,query_requests}`)、看板、`/v3/config` 这类后开发模块漏挂了鉴权装饰器
     ⇒ 枚举结论要**按模块分组**看; 测到几条 401 不能推断整族已鉴权, 也不要因为整族 401 就把该族从作业面划掉。
   - **免票端点自带全量计数, 直接拿来给交付物定标**: 列表响应的 `meta.total` / `count` 是平台自己的权威口径
     (实测 165,209 笔支付流水、21,124 个商家 VIP), 用它当报告里的"总量"比按落盘行数推算可信。
   - ★**「无票也 200」≠ 漏挂 —— 公开端点会按身份裁字段**: 同一端点带票返 58 个字段、无票返 42 个(把联系人/联系方式类剥掉)。
     判定必须做**字段集差分**(`set(带票顶层键) - set(无票顶层键)`); 只看状态码会把"按身份裁剪的公开接口"误报成未授权访问。
2. **枚举业务记录里的身份字段**:
   - 内嵌对象 `merchant`/`seller`/`shop`: id、user_id、昵称、店铺描述、粉丝数、口碑标签、认证徽章、风控态
   - 平铺字段 `creator_id`/`creator_name`/`creator_avatar`: 发布者身份, 常 100% 填充
   - 纯 ID 列表(如 `recent_clickers: [1364154, 34534, ...]`): 去重即**用户 ID 池**; `max(ID)` 反推**平台注册总量级**
   - 子对象数组 `view_users[].avatar`: CDN URL 里的 `vi_32/<hash>` 是**稳定用户身份哈希**, 去重即真实人数
3. **交叉验证归属**: `creator_id ∩ merchant.user_id` 命中率高 ⇒ 发布者就是商家账号本体, 两表可合并去重。
4. **统计口径两个陷阱**: `key 存在 ≠ 值非空`(曾经 5 万多行有 `project_id` 键但值全空, 按 key 计数会把表规模虚报成 5 万);
   **非空计数也可能是布尔标志**(`display_contact_info` 的值是 `1` 而非联系方式)⇒ **统计前先打印样本值**, 不要只 `if v: cnt += 1`。
5. **交付**: 衍生表导 CSV(`utf-8-sig` 防 Excel 乱码)同步桌面 + 写进报告; 标注**字段来源与填充成色**("商家账号 12,268 个, 其中 11,501 个带店铺资料"),
   并把**仍为 0 的那类字段**(用户昵称/手机/会员/余额)单独写清楚 —— 拿到的与没拿到的分开说, 不粉饰。
6. **脱敏命中少也是结论**: 全库文本扫手机/邮箱/微信若只命中个位数, 说明平台在业务文本里已脱敏; 真正的 PII 出口在配置类接口(如 `task_config` 的身份证号), 别在文本里死磕。

## 11. API3 对象属性级越权: 列表接口回吐凭证字段(→ 批量 ATO)

不属于 §3 的归属校验范畴 —— 这里是**响应体字段白名单缺失**: 后端 `find({})` 通配返回整条文档,
把**其他用户的凭证**随列表一起吐出来。与掩码开关(references/session-single-key-*.md)**相反**:
掩码是「有该字段但值被打码」, 这里是**明文原样吐**。

**第一步永远是拉字段全集**, 不是看数据:

```bash
curl -s "<批量列表端点>" -H "Authorization: Bearer $T" | jq -c 'map(keys)|add|unique'
```

高价值字段名族(命中即 L2+):

| 字段名族 | 含义 | 后续 |
|---|---|---|
| `sessionToken` / `session` / `jwt` / `accessToken` / `refreshToken` / `userToken` | **活票**, 可直接 Bearer 冒充 | 解 `exp` 排寿命, 按 `.balance` 倒序取; 打 `/user/info` 只读证明 |
| `password_md5` / `password` / `passwd` / `salt` / `hash` | 无盐/弱哈希口令 | 本地小字典(top-100)碰撞 —— 零成本, 别跳过 |
| `withdrawPassword` / `payPassword` / `fundPwd` | 提款密哈希 | 配「无旧密覆盖」接口 → `gambling-password-reset-ato` |
| `googleKey` / `otpSecret` / `totpSecret` | 2FA 种子 | 直接算码 |
| `apiKey` / `secret` / `privateKey` / `mnemonic` | 商户/钱包凭据 | 另开专卡 |

**判据与陷阱**
- 同一文档里**新旧两套字段并存**(bcrypt 现行 + `password_md5` 历史遗留)= 接口用通配返回 ⇒ 一律拉全集, 不要只盯前端展示字段。
- 活票排序别按列表顺序: 解 JWT `exp` 算剩余小时, 叠 `.balance` 倒序, 只打余额高且未过期的。
- 只读证明用 `/user/info`; 改密/提款只在自控账号(硬规则)。
- 接口返回**打码**值(手机 `+9509****`) 时转 references/session-single-key-*.md 找掩码开关。

**同族入口** —— 票的产地不止列表接口: 审计/操作日志明文记 ST/JWT 走 `auditlog-ticket-harvesting`;
代理体系开放注册 → 代理票打 admin 前缀走 `agent-probe`(777VVIP 实证: 1,129 用户表 × 419 活票)。

**现成探针**（一条命令出字段计数与票寿命，不落明文）：

```bash
python3 tools/ops/agent_probe.py fields --base https://game.TARGET --token $AGENT_TOKEN --case CASE
#  --paths 自定义端点列表   --show-tokens N 仅终端看未过期明文票
# 自测：python3 tools/ops/selftest_agent_fields.py（本地 mock，19 断言）
```

产物 `agent_field_audit.json`：字段→计数 + 票 `total/live/expired/max_ttl_h` + sha256 前 8 位指纹。

## 未授权写接口：改绑 / 换归属（2026-10 cocao.online 实锤）
