# 先打作用域探针,再决定要不要全量拉取(2026-09 实测)

配套 SKILL.md §1「鉴权中间件分类」与 §7「多机全库拉取编排」。
这份只记一个**白花几万次请求**的教训,和它换来的一条一请求成本的判读规则。

---

## 一、事故复盘

**需求**:「统计一下多少个账号、每个账号多少台设备」——典型的跨账号统计。

**我的做法**:手里有一个中台账号(代理管理员 / 9100 档)的合法会话 →
直接拉全量设备列表(`GET /deviceAdmin/getDeviceList?page=N&pageSize=100`)→
12 并发分页,`total=35479`,翻了 2.5 万条落 JSONL → 聚合。

**聚合结果**:
```
agent分布: {'2': 23200}          ← 全部同一个 agentId,就是我自己那个
在线状态: {'offline': 20997, 'online': 2198, ...}
```

**这 3.5 万条设备全是自己账号名下的。** 需求要的「每个账号多少台设备」一条都没拿到,
而 2.5 万次请求 + 十几分钟全白花。

## 二、一次请求就能得到的答案(作用域探针)

事后补做的探针,成本 = **每条一次 GET**:

```
GET /deviceAdmin/getDeviceList?page=1&pageSize=1&agentId=1  → total: 0
GET /deviceAdmin/getDeviceList?page=1&pageSize=1&agentId=2  → total: 35479   ← 自己的
GET /deviceAdmin/getDeviceList?page=1&pageSize=1&agentId=3  → total: 0
GET /deviceAdmin/getDeviceList?page=1&pageSize=1&agentId=5  → total: 0
GET /deviceAdmin/getDeviceList?page=1&pageSize=1&agentId=8  → total: 0
```

判读:

| 观察 | 结论 |
|---|---|
| 传**别人的** id 返回自己的数据 / `total:0` | 服务端硬隔离,**无 IDOR**,别再横向试 |
| 传别人的 id 真的返回了别人的数据 | IDOR 成立,可以横向拉全量 |
| 组织树接口(`/org/agents`、`/org/subAccounts`)只返回 1 条 | 同一结论的更廉价证据,**优先打这个** |
| 调明显需要超管的接口(`/autoCode/getTables`、`/system/getSystemConfig`)回「权限不足」 | 当前账号不是顶层,跨账号统计做不了 |

**把探针放进流程的第一步**:任何「跨账号 / 跨租户 / 按账号分组」的需求,
先发 1~3 次作用域探针定层级,**再**决定采集规模。顺序反了就是几万次无效请求。

## 三、两条推论(可迁移)

1. **隔离维度 = 你的聚合维度。**
   设备记录的 `agentId`、订单的 `merchantId`、工单的 `tenantId`……
   中台账号看到的一切都带**同一个值**;所以「按该字段 GROUP BY」的结果必然是**单行**。
   **看到单行就该立刻停手** —— 那不是「目标只有一个账号」,那是你被隔离了。

2. **跨账号统计只有两条路**:上顶层账号(888/超管),或**落库聚合**(SQL `GROUP BY`)。
   在中台账号上做分页全量拉取,永远拿不到别人的数据,越拉越亏。

## 四、同日踩到的旁证:多服共用账号库 ≠ 共用业务数据

同家族多台服务器(`boss.qavlor.vip` / `boss.taskira.top`)的 `sys_users` **id 完全对得上**
(af00001=5、panghu=26 两服一致)→ 账号库共用,一台登录成功就能在另一台换到会话。

但**业务数据各自独立**:在 A 服登录成功 ≠ 能在 B 服看到 A 的/跨账号的数据。
要统计哪台服务器的数据,就必须拿到**那台**服务器上的会话;别用一台的结果推断另一台。

## 五、检查清单

- [ ] 需求里出现「所有账号 / 每个 X 多少 Y / 全量统计」→ **先发作用域探针**
- [ ] 探针用了**别人的** id 参数(不是自己的)
- [ ] 结果里该维度只有**一个值** → 判定为硬隔离,停止横向拉取
- [ ] 确认层级:`/org/*` 返回条数 + 一个超管接口的权限报错
- [ ] 拿不到就如实写「受权限层级限制,需顶层账号或落库聚合」,**不要**把单账号数据包装成全量统计
