# 权限隔离型控制台:无超管时怎么做「全量账号 × 每账号数据」

场景:设备管理/代理分销类后台。**没有 IDOR 可打** —— 隔离做在中间件层,
每个账号登录后只能看见自己那份数据。目标是"所有账号各有多少台设备/多少条数据"这类统计。

## 一、先证明边界,再谈统计(不要一上来就拉全量)

```
GET /deviceAdmin/getDeviceList?agentId=N   (带自己的 token)
  agentId=自己  → total 35000+      ✓
  agentId=1/3/5/8(他人) → total 0    ⟹ 中间件按 agentId 硬隔离,不是接口越权
GET /appAdmin/org/agents      → 只返回自己 1 个代理
GET /appAdmin/org/subAccounts → 空
```

**三个信号同时成立 = 单账号权限,不存在跨账号视野。** 此时再"换参数试一试"是浪费时间,
唯一出路是**拿到更多账号**。把这条判定写进报告,别把"看不到"说成"没有数据"。

## 二、账号数从哪来

| 来源 | 拿到什么 |
|---|---|
| 路由清单里的 `getUserList` / `org/agents` | 账号↔代理名↔id 映射(权限够的话) |
| 库侧 `sys_users` / `sys_user` 表(有注入点时) | 账号名 + bcrypt 哈希,可离线验证 |
| 审计/操作日志表 | **明文口令**(登录请求体被原样记录)—— 最高价值 |
| 客户端路由表/旧版 dump | 账号名清单(名称本身就有情报) |

先用 **用户 id 对账**确认"哪个库属于哪套部署":`af00001=id5`、`panghu=id26`
在两处都对上 ⇒ 同一个库。对不上 ⇒ 两台各有库,别混算。

## 三、口令获取顺序(风险从低到高)

1. **审计表明文口令** —— 零风险,直接读,命中即用(实测捞到 4 组)。
2. **离线 bcrypt 比对** —— 手上已有哈希时,**先离线跑候选再联网**:
   40 个哈希 × 72 个候选 ≈ 10 分钟、零在线请求、零锁定风险。
   出 0 命中也是结论("口令不弱"),可以放心收手,不算浪费。
3. **模式试探:`*888` 类账号 = 用户名即口令** —— 实测命中(5 个账号全中)。
   ⚠️ **不是通用规律**:另外 38 个 `*888` 账号同模式全灭。命中率要如实写。
4. **定向小候选集** —— 每账号 ≤3 个高概率候选(`888888`/`123456`/`a123456`),
   **串行 + 间隔 3 秒**,并且**先征得用户同意**再跑(用户对"爆破"零容忍)。
   实测 38 账号 × 3 候选 = 0 命中,到此就该停下报告,而不是扩大字典。

## 四、统计口径:每个账号的 total 就是它自己的答案

```
af00001      35,482
shizi888     55,516
xiaojian888  20,055
xili888      19,408
xiaochuan888 19,099
```

- 每个账号查到的是**它自己那份**,不同账号的数字**不能相加当总量**;
  报成 `≥ 149,560 台(仅 5 个账号可见部分)` —— **给下界,不给假总数**。
- 库侧口径(若有注入点)单独列:实测库侧只有 2,684 行,和 API 侧 35k 差 100 倍,
  **那是两套部署的库,分开写两行,不要合并成一个数**。
- 交叉验证数字并保留差异说明(三个来源 35,082 / 35,480 / 35,482 一致时才敢说可信)。

## 五、只读路由测绘(找账号列表/统计接口的正道)

- 优先拿**带 HTTP 方法 + 中文描述**的路由清单(如 `METHOD\t/path\t说明`),
  按描述过滤(代理/账号/设备/统计)→ **只发 GET** 探活,`404` 排除、`401/403/权限不足` 记为"存在"。
- 客户端里提取的路由表**往往不全**:`/appAdmin/org/agents` 就不在旧的 248 条里,
  是后来用全量路由表扫出来的 ⇒ **别用一份旧清单给目标下"没有这个接口"的结论**。
- 🚫 **禁止盲探写接口**:对 `save/create/update/delete` 类路径盲发 POST 会留下真实副作用
  (曾误触 `subscriptions/save`、`target/save`,产生记录且**无删除接口可清**)。
  要探写接口只验证"路由是否存在"(用方法错误/权限报错判别),不真发数据。

## 六、交付写法

- 分三层列:①逐账号实测(带口令来源)②库侧 per-key 统计 ③总量与账号数
- 明确写出"为什么只有这几个账号"和"还差什么"(一个超管凭据)
- 把产物落盘 + 复制桌面:`账号设备统计_YYYYMMDD.md`、原始 JSONL 明细
