# 越权判读与扫描自证有效(2026-09 白标赌场平台实测补充)

> 补充 SKILL.md §1–§3。两个主题:(a)「身份参数被接受」不等于越权; (b) 整轮扫描必须自证有效,否则拿到的是一批假数据。

## 1. 接受但忽略 ≠ IDOR —— 必须先建基线再比对

读接口对 `userId / uid / user_id / id / mobile / phoneNumber / inviteCode / shareCode`
**全部回 200** 时,极容易误判成越权点。正确做法是**逐字段加参数、与自己账号的基线返回逐字节比对**:

| 现象 | 判读 |
|---|---|
| 加身份参数后返回与基线**完全一致**(仍是本人手机号、空卡列表) | 接受但忽略 → **无 IDOR,判死** |
| 返回值/条目数变化 | 真差分 → 继续深挖 |
| 报 `"X" is not allowed` | DTO 白名单 → 架构级封死(见 `dto-whitelist-and-route-inventory.md` §2) |

实测:该平台 `getUserInfo` / `getUserCard` / `get_team_info` / `get_ranking_list`
对全部身份别名**接受但忽略**,仅按 token 作用域返回本人数据;`get_ranking_list` 另回
`Evento fechado`(活动关闭)无数据 —— 均**非** IDOR。

## 2. 零基线账号法(最省数轮的作用域判据)

注册/使用一个 **余额=0、订单=0、团队=0** 的测试账号,然后打读接口:

- `find_recharge_order` / `find_withdraw_order` → `{"data":[],"total":"0"}`
- `get_team_info` → 成员 0

**判据**:该账号任何**非空列表返回必然是他人数据**。比"猜哪个字段属于别人"省好几轮,
也天然给出报告所需的"数据因人而异"对照面。

## 3. 分页列表读接口是首选目标

`find_*_order`、`list`、`search` 类接口 = 铁律里的「资金/订单吐数据点」:

1. 先 `{"page":1}` 建**基线**(确认只回自己的、条数与业务预期一致)
2. 再逐字段注入身份参数(`page` 必填先满足,否则拿到的是 `"page" is required` 而非白名单判决)
3. 被白名单拒绝 ⇒ 该平台**不存在参数注入型 IDOR**,整批别名测试可整体作废

同时注意 `limit` / `pageSize` 这类分页参数常**不在白名单内**(报 `"limit" is not allowed`),
不要把它当成"找到了可绕过的参数"。

## 4. 整轮扫描必须自证有效(别拿假数据下结论)

一次扫描若**整批返回同一状态码 / 同一文案**,先怀疑扫描本身:

| 症状 | 真因 | 修法 |
|---|---|---|
| 全 405 | 路由清单**漏 `/api` 前缀** → 打到默认 vhost | 补前缀重打 |
| 全 405(Go/Laravel) | 只测 POST,而目标是 **GET 路由** | GET/POST 双测 |
| 全 8888「用户身份失效」 | token 已失效(被 `reloadToken` 轮换) | 重新登录取新 token |

**三选一排除后才允许写进报告。** 本轮曾有一整批 95 条路由的结果因"缺 `/api` 前缀 + token 已失效"
而全部作废 —— 属于必须自我更正的假数据,不能当结论交付。

## 5. 限流纪律(429 = 停,不是加代理硬顶)

该类平台对高密度请求会返回 **429**(登录面则回 `Too many login attempts`):

- 小批量 + **≥1s 间隔** + 批间退避;**429 出现即停**
- 触发后不要靠换出口继续压 —— 先退避,再小步复测
- 账号口令/TG 等高频动作与目标站的限流是**独立**的,别混为一谈
