# 页内注入 oracle 纪律（CDP / 真浏览器）

适用：直连 Python 打不通（恒回挑战页 / 恒 401），只能借真浏览器页面上下文发 XHR、跑判读或做加解密代理的场合。

## 1. 通道选择

- 挑战型 WAF 常**只 patch `XMLHttpRequest`，不 patch `fetch`**（或反之）⇒ 先用一发已知请求测出哪条通道被自动签名/放行，再用它。
- 页面请求要**同源**：tab 落在目标同源域再发。跨源 XHR 在部分主机上会触发挑战页导航（页面被 reload ⇒ 注入上下文丢失、结果全空）；
  另一些主机允许跨源（有 CORS）。**逐个实测，别一刀切**。
- 直连（无浏览器）在挑战 / 加密信封面前恒失败 ⇒ 不要在这条路上反复烧预算，早换通道。
- 两个抢同一 Chrome 的 CDP 脚本**不要并行**（`/json` 端点互踩）⇒ 串行跑，各自独立 tab。

## 2. 注入纪律（踩过就浪费一整轮）

1. **注入串压成单行**。多行 / 超长注入串在传输中被改写，报 `SyntaxError: Unexpected token ')'`，
   且**报的行列与模板对不上** ⇒ 见到「列号远大于该行实际长度」直接判定为传输改写，改单行 / 分段。
2. **先自检注入是否生效**：注入后立刻取 `typeof window.__MY_RESULT`（+ 一个哨兵值）确认变量存在、函数可调，再发包。
   自检不过时**不要读结果**——变量为空看着像「查不到」，实际是注入被吞（模板串未展开 / 语法错 / 越界）。
3. **结果按 tag 存 keyed 对象**，别用一个全局变量存整批结果：单全局变量会**响应错位**，
   让 A 请求的响应挂到 B 请求上，制造「一次得手、次次复现不了」的假成功。
   形如 `window.__RES = {}; ... window.__RES[tag] = {status, body}`，最后一次性 `Runtime.evaluate` 取回。
4. **一轮一变量**：path / suffix / method / header 分轮跑；每轮先跑基准（已知存在、已知不存在）。
   一批探针「全灭」或「全过」时，先怀疑通道坏了（页面被导航 / 注入被吞），**不要据此下结论**。
5. 长脚本优先**落文件 + `Page.addScriptToEvaluateOnNewDocument`**，而不是反复构造长串 `Runtime.evaluate`；
   页面被挑战页 reload 时后者整批失效。
6. 抓到的页面真实请求头（`X-Encrypt-Key` / `Iv` / `Nonce` / visitor 指纹）可**整组复用**
   ——但注意 **token/挑战常绑出口 IP** ⇒ 浏览器与脚本回放必须走同一出口。

## 3. 结果可信度分级（写结论时按这个）

现场运行行为 > 抓包流量 > 服务端当前返回 > 运行中配置 > 持久化状态 > 生成产物 > 已提交源码 > 注释/死代码

- 只出现过一次的响应（哪怕内容很诱人）**不计战果**，记「待定论」+ 原始响应 + 复现条件。
- 「复现失败」要如实写进交付，**不许把一次性命中包装成已确认漏洞**。
- 展示层数据可伪造；业务层（流水 / 枚举差分 / 订单资金）才算脱库证据。
