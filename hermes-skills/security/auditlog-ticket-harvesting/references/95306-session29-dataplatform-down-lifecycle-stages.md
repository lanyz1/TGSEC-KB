# 95306 实录:数据平台业务表全空 + 生命周期分类 + live 修复(2026-08-31)

## 数据平台业务表全面受限(重要环境事实)

- **现象**:`bid_xxx_business23` / `aggregation_business_bidpackage` 等**全部业务表 findList 返回 0 条**(枚举 372 个相关表实测)。
- **定性**:平台侧限制,非数据缺失——换跳板机/补拉/时间窗参数全无效。
- **仍活的通道**:① auditlog(审计,ST 主链路)② sysfunc(1,957 表地图,findList 无鉴权)③ bfwz 供应商接口(需 ST)④ ES 公告接口 `proxy/portal/elasticSearch/scrapSuppliesQueryDataToEs`(无鉴权,约 19,961 条公告元数据)。
- **死的通道**:bid JWT 通道(execute-server)401(招投标体系,竞卖不认)。
- **影响**:8515 快照增量/已结束包件表/历史核对兜底失效;主链路(审计 ST → bfwz)100% 健康,报名期拦截不受影响。
- **处置**:采集机 `fetch_8515_snapshot()` 停用(每 6 小时无效轮询白费请求,防 WAF);历史 8515 数据保留。已结束项目补全改走:竞价后企业登录 → 审计 ST → buyed → 包件。

## 生命周期五状态(stage)分类

用户业务流程 9 步 → 五状态:
```
报名中(公示~报名截止,可报名) → 待竞价(报名截止~竞价开始)
→ 竞价中(竞价室打开~关闭) → 待发布(竞价室关闭~审核员发布结果) → 已结束(结果公示)
```
- **判定优先级**:sellEnddate(join 接口字段,仅 join 内项目有)→ now<=sell = 报名中;status=="14" → 已结束(终态);包件最大结束时间 max_end → now>=max_end = 待发布 / bt<=now<max_end = 竞价中 / 否则待竞价;无 max_end 时 bt 未来 = 待竞价。
- **status 语义**:14=终态(20,747 个,全库历史)、19=进行中(报名中+待竞价+竞价中,69 个)、22=流标/招投标(391 个)、空=12 个。**status 不随报名截止更新**(8/26 截止后仍 19),所以"已结束"只能靠 status==14 或 max_end 判定,不能靠 status==19 反推。
- **时间归一化 `_fmt_ts`**:`2026-09-01 09:23:00` 和 `20260901 09:23:00` 两种格式并存,比较前统一去 `-`/`:`/空格。
- **用户确认**:已发布 == 已结束,状态文案统一用"已结束"(用户原话"直接改成已结束,这样更好理解")。
- **改名后要强制重算**:build_index 补 stage 时 `if not oinfo.get("stage")` 只补空值,旧命名("已发布")残留——**必须无条件重算全部条目**。

## live 判定两个坑

1. **live 硬编码 True**:merger 原代码全部项目标 live → "实时项目"显示全部 142 个(含 2021-2023 老项目)。修复:有 max_end 时 `max_end > now` = live;无 max_end 时 `bt > now` = live(待竞价/报名中);其余 dead。
2. **无包件清单的历史项目误判"竞价中"**:bt<now 且无包件时间 → 不能判竞价中(2021-2024 老项目全中招)。修复:**有包件清单文件(_has_packlist)=监控项目才判竞价中;无清单 = 历史**。

## patch 函数边界陷阱(严重)

用 patch 工具在函数后插入新函数定义时,**后续代码段缩进仍为 4 空格 → 被吞进新函数体,成为 return 之后的死代码,永不执行**。
- 案例:merge_all() 的 index 更新段被吞进 _is_live() 函数体 → index.json 根本不更新,live/stage 全不生效,但 py_compile 通过、进程正常跑。
- **发现信号**:merger 日志 `完成: None 个项目已更新`(merge_all 没有 return,返回 None);或"部署了但行为没变"。
- **修复**:把被吞段拎出来为独立模块级函数(如 build_index(projs)),merge_all 尾部显式调用 + `return len(projs)`。
- **验证纪律**:不仅 py_compile + grep 函数名,还要**跑一轮看行为变化**(stage 分布/日志输出)。

## 竞价室 WebSocket(实时出价动态)

- URL:`wss://cg.95306.cn/business/msg/websocket/<SM4加密packId>/01/<SM4加密packId>`,SM4 key = `日期(YYYYMMDD)+"$e9s20@2o4u^r2"[:16]`,base64 密文 `/` 替换为 `jingjia`。
- **鉴权:必须带登录态(活 ST)**——无 ST 裸连被服务器关闭(close 1000/被拒),这是西安局69次"竞价室黑盒"的根因(报名期在部署前,没拦截到登录)。
- 消息 SM4(key) 解密,msgType: offer(出价)/monitorOffer(监控出价)。
- **拿钥匙组合**:packId(buyed 接口)+ 活 ST(审计拦截)→ 竞价开始后连 WS 录实时出价。
- 实现形态:采集机集成 WS 客户端,竞价窗口自动连、断线重连、出价落盘(计划 9/1 郑州13次/10次竞价实测)。
