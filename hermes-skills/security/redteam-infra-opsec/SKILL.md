# 红队自建基础设施：部署 / 暴露面自检 / 收尾

只管**我们自己那台机器**上跑的东西：代理池、payload/文件托管、面板、保活服务。
目标是把「自己人不出事」变成固定流程 —— 战役打得再漂亮，一个服务把战果挂到公网就全废。

## 1. 部署：默认只绑本地 + 专用目录

- **禁止** `--bind 0.0.0.0` + `WorkingDirectory=/tmp` + `Restart=always` 这个组合。
  `/tmp` 是历轮战役的默认落盘地（token / cookie / session / 抓包 / 字典 / 中间产物全在里面），
  把它的目录列表挂到公网 = 把账号钥匙挂门口，而且目录列表默认就是全开的。
- 正确姿势：
  - 绑 `127.0.0.1`。需要外网可达时**单独**加认证/反代，`--bind 0.0.0.0` 永远不是默认选项。
  - `WorkingDirectory` 指向**专用目录**（如 `/root/<campaign>_payload`），只把要分享的放进去。
  - 用 `Restart=on-failure` 而不是 `Restart=always` —— 否则日后一次故意 `kill` 会被自动拉起，
    让你误以为没杀干净（见第 3 节）。
- 需要活过当前 agent 会话的东西，一律用 systemd 托管，不要 `nohup ... &`：
  会话/tool 进程被回收时会连带 SIGTERM 掉子进程。加固模板见 `templates/payload-http.service`。

## 2. 部署后立刻自检暴露面（三步，缺一不可）

1. `ss -lntp | grep <port>` —— 看**绑定地址**是 `127.0.0.1` 还是 `0.0.0.0` / `*`。
   注意 `*:<port>`（无地址族前缀）同样是全接口监听，别当成「只监听某类地址」。
2. `ps -o pid,ppid,etime,cmd -p <pid>` —— 是什么进程、跑了多久、父进程是谁（父进程=1 说明已脱离终端常驻）。
3. **从公网视角复验**：`curl http://<公网IP>:<port>/`。
   本地能访问 ≠ 没暴露；`0.0.0.0` 会静默敞开，只有外网 curl 能证伪。

自己不记得那个端口/服务是干什么的，本身就是危险信号 —— 先查清归属再决定留关。

## 3. 收尾：kill 不够，必须 stop + disable + 外部复验

- systemd 托管 + `Restart=always`（或 `WantedBy=multi-user.target` 开机自启）时，
  `kill` 后**秒级自动复活**，看起来像「杀不掉」。正确动作是
  `systemctl stop <svc>` **和** `systemctl disable <svc>`，再确认 `is-active` = inactive、`is-enabled` = disabled。
- 关完必须**外部复验**：公网 `curl` 应得 `Connection refused` / `HTTP 000`。
  只看本地 `ss` 不够 —— 同名进程可能已被另一个守护拉起来接管。
- 关服务之外还要看一眼：被暴露过的目录里是否有**活凭据**（token / refresh token / cookie / session）。
  有就是真实泄露，要按泄露处置（轮换），不能只关服务了事。

## 4. 破坏性操作前先核实对象身份（用户可能记错）

用户点名「关掉 8080」这类动作时，**先查该端口/资产到底是什么再动手**。
端口号、主机名、服务名极容易记串，而盲从关掉的可能正是用户自己的生产工具（面板 / 助手 / 代理）。

固定顺序：`ss -lntp`（谁在听）→ `ps -o pid,ppid,etime,cmd`（是什么、跑多久）→ `systemctl status/cat`（谁托管）
→ **报告归属 + 与用户说法的出入**，然后再执行。
发现不一致时先摆出来问一句，比先执行再解释便宜得多。

## 5. 战役产物治理（长任务收尾）

- 长跑后台任务收尾时，把所有产物**落盘汇总成一个总账文件**再一次交付：
  后台任务终态表（命中类 / 无果类**各自原因**）、交付物路径清单、新增线索、待决事项。
  用户说「先把手里产物弄完」＝收口，不是继续开新战线。
- 后台任务的完成通知会**重复回放**（同一脚本可能被报多次），不要逐条复述；
  汇总一次即可，否则刷屏把用户真正要看的东西顶掉。
- 无果项也必须写清原因（如「已用其它接口绕过，不影响链路」），
  否则下次会重复投入同一件无效工作。

## 6. 别把战场打扫错地方

以上规则针对**攻击方自己的主机**。目标侧的痕迹处置是另一回事，不要混用同一套命令。
本地加固（只绑本地、收敛权限、关掉不用的监听）永远不会误伤战役本身，
所以拿不准时优先做本地收敛，而不是先动远端。
