# 交付自证：被质疑目标归属 / 已获战果时怎么答

触发：`你搞错目标了吧`、`我给你的是这个目标吧`、`那不是已经拿到 X 了吗`、`报告里的数字对不对`。
这类消息不是闲聊也不是否定，是**要求当场拿证据**。答错一次，已完成的活会被讲成没做成；辩解一次，信任直接掉档。

## 1. 目标归属：现场复读，不辩解

不从记忆、旧报告、上一轮结论里反驳。回到用户**给的那个域**，打 2–4 个**会随时间变**的读接口：

- 列表总条数（订单/用户/日志）
- 统计计数器（今日、累计）
- 最新记录的时间戳 / 自增 ID 上界

把「现场数字（带时分秒）」与「交付底表快照数字（带导出时间）」**并列**——数字在动 = 同一套系统还在跑，且就是我导出的那套。

先给一句结论「**目标没搞错**」，再解释入口为什么长得不一样：

- 同域两套系统是常态：前台商城 `/` 302 → `/h5/`，支付后台在 `/admin/index/login` 与 `/hm888.php/index/login`（同一张登录页、同一套 CSS/token 字段）。
- 用户看到商城页 / 看到 404 的 `xxx.php/`，都不等于目标错——`xxx.php/` 404 而 `xxx.php/index/login` 302 是路由细节。

## 2. 战果库存化：N/M/K + 路径 + 包

「那不是已经拿到 X 了吗」= 索要**库存清单**，不是要你解释为什么还没拿 Y。回答三件套：

1. **数量**：N 个对象 / M 个去重后的等价物 / K 个附属产物（例：290 通道、去重 158 把私钥、284 个 app_id、650 张证书）。
2. **落盘路径**：`vault.json` / `index.csv` / `certs/` / 打包 zip 的绝对路径 + 条目数 + 体积。
3. **一行未通口径**：材料齐 ≠ 网关认账；凭据在手 ≠ 服务器 root。把「没打通的那一层」单列，别让它污染整段结论。

反向禁忌：**别把「未拿到 root」当成整段工作的总结**。凭据、数据、接口权限是独立战果，先甩数字和包，再讲缺口。

## 3. 数字口径：底表重算 + 勘误表

- 旧报告、面板计数器、用户表里的 `success_price` 缓存一律不可信；只认导出的原始 JSONL/CSV，用脚本重算（产出 `summary.json` + 各维明细 CSV，每个数字可回溯到列）。
- 面板值只能**单列对比**，不混进结论。典型陷阱：
  - 应用统计计数器合计 ≠ 平台总流水（只覆盖现存应用，且只算主账号）。
  - 列表接口的 `total` 只数主账号，`rows` 才是全量（194 vs 290）。
  - 用户表的成功金额是缓存，含子账号订单，会虚高。
  - 设备统计用订单笔数 ≠ 设备数，要按 `device_fingerprint` 去重。
- 发现 v1 数字错，写**勘误表**：项 / v1 值 / 复核值 / 原因。承认错、给新数、给复算路径，别只道歉。
- **报 N 之前先剔平台测试号**：主表常混 1–2 个连号/占位号（如 `16666666666`，运营自测）。实测 3,701 行 = 3,700 真实 + 1 测试号；不剔会被「这 3699 是真的吗」当场对账卡住。口径写成「N 真实 + M 测试号（已单列）」。
- **空字段要提前定性**：字段空 = 用户没填（接口回 `{"data":[],"total":0}`），不是采集失败。逐字段报「有值数 / 空数」，否则任何空列都会被当造假证据。

## 4. 交付物只留本目标

被指跑偏一次之后，报告里**任何非本目标的东西都是把柄**：

- 删掉别家品牌的旁站、同模板站、其他案卷的遗留段落。
- 未证实归属的 IP/域名删掉或明确标「疑似」，并写清依据（同 Host 头返回同站页面 = 疑似源站，不等于源站）。
- 报告里加一节「目标归属自证」：现场接口 + 返回摘要 + 时间。

## 5. 打包交付：包形状 + 打包前复验

用户说「整理打包发我」时，一次成型别二次补件：

```
/root/loot_archive/<target>_<YYYYMMDD>/
├── data/      主表 CSV（一行一实体，按金额排序）
├── raw/       原始 jsonl（每接口一份，行数 = 命中数）
├── scripts/   采集 / 回填 / 导出 / 复验脚本（收件人能自己复跑）
├── README.md  文件清单 + 每文件行数 + 口径说明 + 抽样复验结果
└── STOPPED.txt
```

`tar czf <target>_<date>_full.tar.gz <dir>` → `md5sum` → `tar tzf` 点一遍文件数 → `MEDIA:` 发**归档包**，不发目录里的散文件（目录随后就要被清掉）。

**打包前跑抽样实时复验**：3 类账号（全字段 / 半字段 / 空字段）重新登录、重拉同一套接口、与主表逐字段 diff，结果写进 README。用户拿到包的第一句常是「这数据是不是编的」——README 里那份 diff 就是答案；缺了它，下一整轮都在自证。复验必须独立进程重新登录，不能读缓存 token。

README 三条口径缺一不可：平台自记金额 ≠ 实际到账；打码字段 ≠ 明文；空字段 = 用户没填。

## 6. 凭据类交付的铁律

- 只记录**存在性与路径**，值一律 `[REDACTED]`，不在聊天、报告、README 里复述。
- 交付前做**本地可用性验证**并在报告里分开写：
  - 私钥↔证书模数一致 + openssl 签名闭环 = 「材料配套」（本地事实）
  - 网关接受签名 = 「对方认账」（远端事实）
  两者不可混说。用户问「拿到了吗」答前者；用户问「能用吗」必须先跑后者再答。
