# 中式 PHP 建站系统：会话票解密 与 配置真值提取

适用：服务端渲染 PHP 的中式建站/支付/发卡/CMS 系统（Discuz `authcode` 血统），
无论原版还是二开。目标是把「抓到的 cookie 票」和「库里的配置」变成可推演的已知量，
而不是先花几百发去猜签名公式。

**触发词**：authcode、user_token、admin_token、序列化 config、缓存配置键、
`.git/objects` 403、二开加固版、`sid` 伪造、票解密。

**产品家族的具体打法在各家族卡**（如 `epay-admin-pentest`）；本文只管**跨家族复用的逆向原语**。

## 0. 决策顺序（顺序错了就白烧轮次）

```
抓到 cookie 票
  → 先 DECODE（绝不要先伪造）        ← 拿 uid / sid / exp
  → 量 sid 长度                       ← 定哈希家族
  → 算 exp vs now                     ← 未过期就直接复用该会话干活
  → 用现成会话找写面 / 密钥页 / 自己可控账号 → 拿「真 token 当已知明文对」
  → 只有在公式被真 token 验证过之后，才谈铸新票 / 铸 admin 票
```

任何一步失败就**换下一步**，不要回头堆公式组合。

## 1. 先解密，再伪造

票是 Discuz `authcode`：`密文 = keyc(4字符) + base64(RC4(明文))`，明文 = `uid \t sid \t expiretime`。
可直接跑 `scripts/authcode_decode.py <密文> <SYS_KEY>`。

- ⚡ **总长度就是格式指纹，先量再猜**：`len = 4 + ceil((26+N)*4/3)`（4 字符 keyc + **无 `=` 填充**的 base64）。
  例：146 ⇒ 载荷 `N=80` = `uid\tsid(64)\texp(10)`；115 ⇒ `N=57` = `admin_user\tsid(32)\texp(10)`。
  长度对得上就是 authcode ⇒ **别判成「AES 信封 / 自定义密文不可解」而把整条路丢掉**
  （本库踩过：一个 146B 票被记成 AES 密文，连带把签名反推整条放下，事后才发现它本可解）。
- ⚡ **实现自校验是硬门槛**：先解一把**自己经正常流程拿到的票**，结果必须与已知明文逐字节一致，
  才算实现与密钥都对。**未通过自校验的实现不许拿去铸票** —— 铸出来必然落到「未登录基线」页，白烧一轮。

- ⚡ **keystream 只用 `keya`，md5 完整性校验用 `keyb`** ⇒ **校验失败不等于密钥错**。
  判据：**明文头 10 字节恰为 `0000000000` 即 keystream 正确**（随机字节撞上的概率 10⁻¹⁰）。
  此时**直接取 `明文[26:]` 当载荷**，别因为校验失败就换密钥或判死。
- 解密结果落盘成 `(uid, sid, exp)`：`sid` 是后续一切公式推导**唯一的已知输出**，
  没有它就不要开始枚举。
- 密钥常来自站点配置的 `syskey` 类字段（见 §3 取真值），不是 `.env`（`.env` 通常只有 DB 凭据）。

## 2. 量 sid 长度 → 定哈希家族（省的功夫最大的一条）

| 长度 | 家族 |
|---|---|
| 32 hex | md5 |
| 40 hex | sha1 |
| 64 hex | **sha256**（`hash('sha256',…)` / `hash_hmac('sha256',…)`）|

**先量长度再写爆破脚本。** 用错家族时几千万组合全空、且完全看不出原因。
长度与期望不符 ⇒ **公式里还有未知材料**，此时正确动作是回 §0 取「真 token 做差分」，
**不是扩大枚举**（盐/拼接顺序/算法三重循环是最容易白烧十几个小时的方向）。

## 3. 配置真值：读重建后的缓存键，不读原始配置行

中式 PHP 系统普遍是「配置表行 → 重建进缓存表某键 → 全站读缓存」：
**直接读原始配置行拿到的不是生效值**（登录比对、验证码开关、密钥、RSA 密钥对全在重建值里）。

该重建值是 **PHP 序列化串**，解析必须**成对**抓 `s:N:"...";`：

```python
pat = re.compile(r's:(\d+):"((?:[^"\\]|\\.)*)";')
# 先 match 到 key，再从 end() 起 match 一次拿 value，成对入表
```

⚠️ **按 `:` 切分会在 `";s:` 边界错位**，静默漏字段 —— 实测漏掉过整条口令字段，
导致其后所有公式推导都基于错值。**自检动作是「数键数」**，键数明显偏少 = 解析器有问题，不是配置缺项。

⚠️ 缓存表的值可能被**截断**存储；正则解析前先确认拿到完整串，否则同样静默少字段。

值得单独捞的键类别：票/接口密钥、定时任务密钥、RSA 公私钥对、口令字段、
验证码开关与 id/key、注册开关与相关价格、结算配置。

## 4. `403` / `404` / 「200 空体」必须分开读

| 响应 | 含义 |
|---|---|
| 404 | 不存在 |
| 403 | **存在但被访问控制挡住**（别当成不存在而漏整条面）|
| 200 空体 | PHP 被执行了（是可执行代码，不是可读文件）|
| 200 + 内容 | 可读 |

- **`location ^~ /前缀` 的 deny 不可绕过**：服务器在 location 匹配前已做路径归一化 ⇒
  `%2f` / `//` / `/./` / `/../` / 大小写 / 分号 / `PATH_INFO` 全数失败。
  见到 403 **先读部署配置确认 deny 前缀**，确认是 `^~` 就别再发编码变体（每次都是白流量）。
- **deny 清单常漏目录**：部署脚本只 deny 几个「敏感」前缀，而**测试目录常在 web 上可执行**
  （具体文件 200、目录列表 403）⇒ 跑测试脚本能把加固版的**行为特征**从 PASS 文案里反推出来。
  ⚠️ 测试**不吐源码**，别当 LFI 反复试；且**部分测试会写回生产库**（测试名含
  `updates the active value` / `rehashes ... and updates`）⇒ 只跑只读的，拿不准的不跑。

## 5. `.git/` 部分暴露：index 当文件清单 oracle

`objects/` 被 deny（`info/packs` 404 / `pack/` 403）**不等于** `.git` 没用：

| 文件 | 价值 |
|---|---|
| `.git/index` | **全量线上文件路径 + 每个 blob 的 SHA1** ⇒ 文件清单 oracle |
| `.git/logs/HEAD` | 提交历史 / 部署机主机名 / 操作者 |
| `.git/packed-refs` / `.git/FETCH_HEAD` | 分支清单 + 完整 commit 链 |

用法：①解析 `index` 拿全路径 ⇒ **驱动静态资源收割**（枚举所有可达的非 PHP 文件：模板 / json / txt / 部署配置）；
②与本地同名项目比 blob SHA1（本地 `git ls-files -s` 取）⇒ 未命中的就是**线上独有的二开产物**，重点读这一份；
③拿分支名 + commit 链去上游找同源仓，或本地 `git fetch` 试取。

- ⚡ 二开仓常是私有的（上游 404/private、本地 fetch 取不到、blob 全 `NOT_IN_LOCAL`）
  ⇒ 三条都死时**别再换仓库来回试**，转线上面（§1/§3）。
- ⚡ 收割静态资源要**增量落盘 + 只打高价值前缀**；`execute_code` 里一次打全清单会超时
  ⇒ 写成后台脚本、逐批追加 JSONL（键名固定），跑完再汇总。

## 6. 加固版识别：见到就停止盐枚举

二开加固版会把「票生成」逻辑整体重写。典型特征文件：会话签名模块、独立鉴权模块、
口令模块（`password_hash`/`verify` + legacy 明文兼容 + 一次性 rehash）、登录限流器、
CLI 重置管理员口令脚本、`tests/security/` 一整套测试。

**判据（来自测试输出文案）**：出现
`password-aware session signatures` 或 `password and key changes invalidate session signatures`
⇒ **经典公式与盐枚举全部作废**。此时「再换一个盐试试」不是推进，是烧时间。

另外：加固版常把每个入口文件开头加统一登录门且**全树无变量覆盖** ⇒
「免票打后端接口」这类假设先证伪再投入。

## 7. 零痕迹优选：dump 到的 hash 本地离线验证

拿到比对原语和口令字段（bcrypt / md5 / 明文）后，**先读原语、再本地验，最后才考虑在线试登录**：

- ⚡ **比对原语是 `$input == $stored`（老式 PHP 直比），或加固版 `verify()` 里留了 legacy 明文回退分支
  （`hash_equals($stored,$input)`）⇒ 存储值本身就是可直接提交的凭据**：`$stored == $stored` 恒真，
  **不需要知道明文**。⚠️ 属待验候选 —— 先读到比对代码才动手（同族 fork / 泄露源码 / 反编译）；
  命中判定以最终业务状态为准；失败与命中常回**同状态码不同长度**的 JSON ⇒ 必须读 body。
  登录会写审计日志 ⇒ 记下尝试次数，写进报告的痕迹与恢复章节。**这一路优先于爆破——能直登就别烧 GPU。**
- 无直比路时走本地离线验证：

```python
from passlib.hash import bcrypt as _b
_b.verify(candidate, dumped_hash)      # 或 bcrypt 库 / hashcat -m 3200
```

- **零流量、零登录尝试、不触发登录限流器、不写审计日志** ⇒ 符合「爆破优先离线」纪律
- 小靶向词表（运营方密码习惯 + 品牌名 + 常见弱口令）；大字典先问授权
- **弱兄弟字段是强信号**：另一个字段是 `123456` 级 ⇒ 说明运营方用弱口令，
  据此为未破字段**定向扩表**，比盲扩有效得多
- ⚠️ bcrypt 同明文不同盐 ⇒ **字段间互不可推**，破了一个不代表另一个，别把命中值套用

## 8. 别空手爆破公式 —— 用真 token 当已知明文对

拿一个**自己可控账号**的真会话（注册 / 密钥登录 / 复用未过期票），
再**改密钥或改密码后重新登录**取第二把 ⇒ 两把真票做差分，锁定公式输入集，再谈复刻。

- 很多系统的登录开关表里有「密钥登录」开关 ⇒ 打开时**用密钥免密登录**，无需口令
- **只在公式被真 token 验证过之后才铸新票**；未验证的公式铸票 = 落到「未登录基线」页面，白烧一轮
- 铸票前先记下「未登录基线」的响应体积，用作后续判据的基准值
