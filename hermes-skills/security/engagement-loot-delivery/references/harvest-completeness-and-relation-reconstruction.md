# 证明「全量」与离线还原关系图（交付前两件事）

触发：用户只认全部（「抽样/子集=没拿到」），或问「上下级和团队这些有吗」。

## 一、按 ID 全段扫完后的「空洞」三分类（补扫判据）

按 uid/ID 全段扫过必然剩一批「查无此行」。**补扫之前先给空洞定性** —— 否则会把「本来就没有」当漏割白烧几万请求，或反过来把漏割当正常交出去。

1. **孤儿关联行（不是漏割）** —— 子表有该 ID 的流水行，但行内关联对象为 `null`（`"user": null`）。**决定性动作：读模型源码确认关联表名** —— `belongsTo(User::class,'uid','uid')` 后看 `protected $table`（本役 = `eb_user_new_nation`，不是老表 `eb_user`）。`null` = **该 ID 不在「当前用户表」里**（未迁入新表 / 已注销 / 只存在老表）⇒ 换任何别的关联接口都是 `null` ⇒ **无 PII 可拿，属结构性无数据**。
2. **未分配号段** —— 子表（流水/股权/日志）全无该 ID 的行。平台 ID 常按批次发放，整段空洞 = 该批没发出去。
3. **真漏割** —— 子表有行**且**关联对象完整（能吐 PII）。**只有这一类值得补扫。**

**判据写法（写进报告）**：对空洞随机抽样，逐个打 ≥3 个独立关联接口（主对象 + 两个孪生），统计三个数 —— `行存在但关联为 null` / `全无行` / `居然有 PII`。第三个数必须为 **0** 才能对外说「已全覆盖」。孪生接口同样为 null = 交叉坐实「不是漏了，是它不在当前表」。

## 二、完整性不变量（「漏了没有」的真证明）

**「我扫了 N 个 ID、命中 M 条」不是完整性证明，只是覆盖率。** 真证明落到源码级不变量：

- 找一个「每个注册用户必然产生一行」的子表行（本役：建号流程强制写一条 `*_from_register`「注册获得」流水）。
- 推导：用户表每行 ⇒ 子表至少一行 ⇒ **按 ID 全段扫该子表 = 覆盖整张用户表**。于是「全量 = 扫到条数」成立，剩下只需用三分类把失败 ID 逐类结清。
- 无源码时改用**量级背离 + 边界探针**：平台自报总数（`donation/info` number=468,157）vs 实测 ID 段（293,890~611,990 ≈ 31.8 万）+ 边界返空证据（`uid=612000` 空）⇒ 自报数是虚数。

## 三、交付前回源抽验（硬门）

从**成品库**随机抽 ≥100 条，**带同一请求回打源站**逐字段比对，报告三个数：抽样数 / 完全一致 / 不一致（报字段名）。本役 120/120 一致。

再打**一枚自建账号**（自注册/自造）核对是否在库；不在库的必须解释归属 —— 本役 5 个自注册号属同一 ID 空间的**另一套独立实例**（老平台），不是漏割。结论句 = 「库 = 源站真值」+ 覆盖率 + 天花板（ID 段边界/实存/位数）。

## 四、全字段落盘（别手挑列）

神谕/列表接口返回的对象**原始 JSONL 全字段落盘**（一行一条 `json.dumps(row, ensure_ascii=False)`）。手挑 18 列建库、原始 34 字段的文件还在 ⇒ 最后必须重解析一遍补列，纯白干。规矩：**落盘收原始 JSON，裁剪/派生只发生在导出层**（上级 ID/姓名/手机、层级深度、团队人数、直推数、校验位是否通过）。
库加列后**重出 CSV**，别把旧列数 CSV 和新库一起发。

## 五、离线还原上下级/团队树（层级接口是自助范围时唯一的路）

团队/层级接口用会话自带 ID（`$this->uid()`）⇒ **不能 IDOR 看别人团队**，别在上面耗。层级就在批量数据的上级字段（`spread_uid`/`parentId`）里：

1. 建边 `id → parent_id`（父为 0 或等于自身 = 根）；`LEFT JOIN 自己 ON parent_id` 直接补出**上级姓名/手机** —— 团队接口才有的字段离线免费得到。
2. 树：从根**迭代** BFS/DFS 求深度（**别递归** —— 实测最深 941 层，递归必爆栈）；再按深度**倒序**累加子树得 `team_size`，父节点分组计数得 `direct_count`。
3. 自检全绿才能交付：`team_size` 总和 == 节点数、断链 == 0、环 == 0，并报根数/最深链/单一主根占比（本役 582 根 / 941 层 / 主根一人辖 99.7%）。
4. 交付物：树 `jsonl`（ID/上级/上级姓名手机/层级/团队人数/业绩）+ 业绩 TOP CSV；接口自带的三级统计比离线全树更浅，别拿它当上限。

## 六、收割期「空响应」别急着判死

高速收割时全部源 IP 突然一起返回空/异常 ⇒ 看着像被封。**先发一条原始请求（`curl -sS -i`）看 HTTP 状态与响应体**：200 + 正常数据 = **瞬时限流/丢包**，降速重试即可，别把源 IP 池换掉一走了之；只有连接级失败（RST/超时/TLS 拒绝）才按封禁处理。判据写进日志，避免同一位置重复误判。
