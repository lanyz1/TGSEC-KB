# 九宫格/点选图标验证码：求解器判据标定

## 铁律

1. **判据必须由「相对领先度 margin」主导，不能只看绝对相似度阈值。**
   同一形状的绝对相似度上限与「图案细节量」强耦合：细节少的形状（花/星）IoU 可达 0.92，
   细节丰富的形状（如钻石切面，样例小格缩放到大格损失大）只有 ~0.65。
   固定 `thr=0.70` ⇒ 系统性误拒细节丰富的形状，失手率≈50%（由图案决定），
   表现为「有时全中、有时全 null」的**伪随机**。

2. **症状识别：`argmax` 就是正确答案但被判 null ⇒ 是判据问题，不是掩码/分辨率问题。**
   先把 `argmax / argmax_sc / margin` 打进日志，才能在日志层面区分「排名错」与「阈值拒」。

3. **标定方法：肉眼 ground truth + 小样本回归。**
   取失败样本与成功样本各若干，目视确定正确答案，打印求解器完整打分向量，
   逐样本核对 `argmax` 是否等于肉眼答案。若全部一致 ⇒ 只调判据（thr/margin），不动算法。

4. **不要把「提高分辨率 / 加模糊 / 平移容差」当默认修法。**
   实测 160 画布 + 高斯模糊抗锯齿 + Otsu 自适应二值化 + ±3px 平移容差，
   仅带来 **+0.002** IoU 增益而算力约 ×9 ⇒ **收益近零**。先证明误差源，再改算法。

5. **题型先看清再写求解器。** 常见抗自动化设计 = 「**同形异色**」（颜色随机化）：
   顶部样例与正确答案形状相同、颜色不同 ⇒ 掩码必须**颜色无关**
   （以「与背景色的色差」做前景掩码），绝不能用颜色直方图/颜色模板匹配。

6. **落地判据（9 宫格）**：`ok = sc[best] >= 0.60 and margin >= 0.06`，
   并把 `argmax` 一并落日志。绝对项只作下限保护，相对领先度作主判据。

## 反面教训

绝不为了让某张样本通过而调阈值：必须先用肉眼 ground truth 确认「**argmax 正确**」，
再以 margin 为主判据 —— 否则等于把求解器调成「猜」，实战中会在伪造样本上翻车。
