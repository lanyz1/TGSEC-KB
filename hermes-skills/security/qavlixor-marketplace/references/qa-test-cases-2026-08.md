## 编制流程（可复用）
1. **子代理并行提取交互清单**：3 个 leaf 子代理（买家=app/ 根路径 + components/buyer/；卖家=app/seller + components/seller；管理端=app/admin + components/admin + 关键 API）。任务书要点：
   - 明确路径范围与排除（买家端排除 /seller /admin 前缀）
   - 输出格式固定：`### 页面路径` + `- [元素类型]「文案」：行为描述；边界/异常`
   - "不要写测试用例，只提取真实存在的交互元素（以源码为准，不要臆造）"——提取与编制分离，防子代理臆造
2. **读完整清单**：子代理汇总被截断，用 read_file/execute_code 分页读全（三份各 12-13K 字符）
3. **人工转用例**（不能脚本机械转换，需理解语义）：
   - 每条交互元素 → 1 条主用例（正常操作+预期）+ 边界派生 1-3 条（非法输入/空态/禁用态/未登录/终态锁定/并发 409/权限 403）
   - 编号体系：`端字母-序号`（C/S/A），表格列：编号|用例|步骤|预期
   - 表单类按控件逐条拆（必填拦截/格式校验/上限/联动清空/成功反馈）
   - 状态机类补终态锁定与重复操作用例
   - **跨端联动用例**单列章节（发品→审核→上架→下单→付款→发货→收货→售后→退款→提现→打款）
4. 配套总览文件：分工/红线（资金安全：提现只驳回不真打款）/反馈模板/验收标准
