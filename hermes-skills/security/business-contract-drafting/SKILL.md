# 商务合作合同草拟（分成/带教类）

用户场景：跨境电商带教模式 —— 甲方(用户)教乙方注册店铺+投流，推厂家资源，乙方独立经营，甲方抽乙方纯利20%，**不收学费，只赚盈利后分成**。学员可能转介绍/A带B，规模可能扩大(涉众风险)。用户偏好：正式合同文件 + 直接技术输出(不啰嗦) + 主动提醒风险点。

## When to Use（何时使用）
- 用户要草拟/修改 合作、分成、带教、代理、供货类合同
- 用户咨询合同法律风险：能否被追责、刑民界限(诈骗 vs 合同纠纷)、传销风险、涉众风险
- 用户要把条款落成 .docx 文件（配合 docx skill 生成）

## 核心原则（防坑条款设计，写合同时按此清单核对）
每一条防一个具体风险：

1. **关系界定**：明写"不构成劳动关系/合伙/代理关系"，乙方独立经营自担盈亏 → 风险隔离(封店/罚款/亏损追不到甲方)
2. **纯利润公式写死**：纯利润 = 当期收入 − 平台佣金/手续费 − 投流费 − 采购成本 − 物流仓储 − 退款/售后损失 − 其他书面确认支出 → 防扯皮
3. **查账权**：乙方按月交报表(如每月5日前)，甲方可看平台/广告后台只读权限或截图；**拒不配合 = 视为认可甲方按合理估算确定应付款项** → 收款保障
4. **防跳单**：协议期+终止后2年，乙方不得绕过甲方直接与甲方推荐的厂家建立供货/合作关系；违约金+损失赔偿 → 保护核心资源
5. **不承诺收益**：免责条款写明甲方不对经营收益作任何承诺或保证 → 防欺诈定性
6. **款项定性为服务费**：明写"系指导服务对价，并非投资款/加盟费/保证金，不取得任何股权/债权/收益权" → 防诈骗与非吸
7. **收益与经营结果挂钩**：甲方收益仅来源于乙方**盈利后**的分成，乙方无纯利则甲方无分成 → 排除非法占有目的的**最强民事证据**
8. **风险告知确认书**：独立签字页，乙方确认知悉亏损风险、甲方未作任何收益承诺
9. **服务交付确认**：每次指导后确认/签收，未在约定期限内异议视为接受 → 履约证据("收了钱有没有真干活")
10. **退款机制**：解除时退还未实际交付部分对应费用 → 无非法占有目的的证明，给乙方合法退出通道
11. **对等权利义务**：双方都有义务与解除权，禁一边倒合同(会被认定"以合同为名行诈骗之实")

## 行为红线（比合同更重要，公安/法院查的是行为）
- 宣传/私聊**零承诺**："稳赚""保本""月入X万""包回本" 绝不能出现——聊天记录就是证据
- 履约留痕**永不删**：指导记录、课程文档、答疑 = "真干活了"的铁证
- 绝不碰学员账号/密码/资金/厂家合同(碰了=事实合伙/委托经营，亏损需分担)
- 不跑路不拉黑；纠纷先协商退款(未交付部分必退)，别让不满攒成集体报案
- 收款对公/实名 + 备注"指导服务费" + 开发票(金额大了要报税)
- 不教违法玩法(刷单/盗图/售假/违禁品)——教唆共同侵权责任

## 转介绍/A带B 的安全设计（防传销）
传销红线(刑法224条之一)：**发展人员30人以上 且 层级3级以上**即追诉组织者、领导者。判断核心：计酬依据是"实际经营利润"还是"发展人头数"。
- **转介绍**(A介绍B，B直接签甲方)：✅ 最安全。A拿**一次性感谢红包**(固定金额，不按比例、不持续)
- **A带B抽成**(A抽5%，甲方让利到15%)：3个硬条件——①A对B有真实指导交付(不是拉人头) ②A只抽**自己直接带的人**(禁跨级/禁从间接下线获利) ③**层级封顶2级**(顶→中→底；B带C只能C直接签甲方，B拿一次性红包)
- 资金流：A与B独立签《指导合作协议》，A的5%**不经过甲方**(甲方只抽自己直接签约的人，角色永远是"旁观者"不是"顶层抽水机")
- 合同金额与实收一致：合同写15%就收15%，别写20%私下少收(合同与流水对不上留把柄)
- 禁用词："团队/体系/下线/团队计酬/管道收益/代理费/加盟费(=入门费)"

## 刑民界限（摘要，细则见 references/legal-risk-framework.md）
- 诈骗 vs 合同纠纷 = 非法占有目的 + 虚构事实；真实履约+亏损只是市场风险 → 民事
- 诈骗数额(多学员累计)：3千-1万(3年以下)/3-10万(3-10年)/50万+(10年以上)
- 立案扳机：**10人+联名报案 → 公安基本必须立案初查**
- 涉众升级：公开宣传+承诺回报+吸资 → 非吸；层级返利 → 传销

## 工作流（生成 docx）
1. 加载 docx skill，确认 python-docx 已装：`pip install python-docx`
2. 写 JSON spec（模板见 templates/cooperation-contract-spec.json，含11条+月度结算表附件）
3. `python docx_create.py spec.json out.docx`，再用 `docx_read.py --text` 验证全文(头尾都要看)
4. 交付：MEDIA: 路径 + 合同设计说明(每条防什么坑) + "签前需填空"清单(编号/双方信息/指导频次/违约金金额/期限/天数)
5. 主动提议变体：分成比例调整/批量多学员版/附件(风险告知书、服务交付确认单、转介绍规则、指导者合作协议模板)

## Pitfalls
- **docx_create.py 样式名冲突**：内置样式已占用 'Title'(及 Heading 系列)，自定义样式名会抛 `ValueError: document already contains style 'Title'` → 用独特名(ContractTitle/ClauseHead/SignHead 等)，spec 里 blocks 引用的 style 名必须同步改(注意映射 dict 别写反)
- 中文合同正文宋体12pt，条款标题加粗；签署页留足空行
- 附件加"月度结算报表"表格(收入/成本明细/纯利/甲方分成/应付合计)让乙方签字确认
- 大额/多学员场景，交付时提醒用户：建议执业律师过最终稿(本技能是框架性法律分析，非法律意见)
