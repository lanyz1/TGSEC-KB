# 探针脚本与新模板：实现层约定 + 自检协议

策略层（范围管控、六门闸、案卷产出目录）见 `pentest-methodology`；本卡是它的**实现层**：
写 `tools/ops/*_probe.py`、加 `custom-templates/*.yaml` 时必须遵守的 API 事实与自检顺序。

## 铁律

1. 探针一律 `import scope_lib` 走闸门，**禁止自写 scope 判断** —— 自写的在 scope 配置缺失/解析失败时会 fail-open。
2. 越界即 `exit 2`，不许吞异常继续跑。
3. 模板与 oracle **只指纹/非破坏**，不塞 exploit、不写远端文件。
4. 新探针「跑通」三件齐：① 越界域名 → `exit 2`；② 池内目标 → 真实 HTTP 请求 + JSON 落盘；
   ③ 能本机复现的组件（官方二进制可下）→ 真起服务打 L1/L2，验完立刻收尾。
5. **长脚本落盘后先语法自检再跑**：正文较长的脚本经工具写入时可能被上下文压缩器截断，
   落地成「第 N 行字符串未闭合」的 SyntaxError。⇒ 分片写 + **写后回读尾部确认最后一行完整**，
   再 `python -m py_compile <脚本>` / `bash -n <脚本>` 自检，通过才执行。

## 落盘字节与转义（改文件工具自带的坑）

1. **含 `\r`/`\n`/`\\` 转义字面量的行禁止用 patch 直改**：`old_string`/`new_string` 里写 `b"\r\n"` 这类字面量时，工具会**把转义解成真字节**（`\r` → CR），把 `b"\r\n"` 写成「字面 backslash-r + 真 CR + LF」——断言与字节常量被静默改写，**脚本照样编译、夹具照样跑绿**，语义已经错了。
   ⇒ CRLF/反斜杠要先写成常量（`CR=chr(13); LF=chr(10); B=chr(92)`）再拼，或用 `python - <<'PY'` **heredoc 字节级替换**（heredoc 内容逐字不转义）；改完必须「回读现场 + `py_compile` + 跑夹具」三连，因为这类破坏不报错。
2. **CJK/引号密集的现场脚本别走 `python3 -c` 单行**：内层双引号未转义就 `SyntaxError: invalid syntax. Perhaps you forgot a comma?`，且外层已部分执行。⇒ heredoc 落盘脚本（`/tmp/<name>.py`）再跑；SSH 侧用 `ssh host 'bash -s' <<'OUTER'` 嵌套 heredoc（外层加引号防止本地展开）把脚本原样送上去。
3. **沙箱验证过的东西必须回核「落盘物 == 被测物」**：发布/部署后对活树与被测副本做 `md5sum` 比对，再在活树上跑一次真数据复算——部署脚本报 success 不等于生效。

## scope_lib API 事实

| 调用 | 必须知道的 |
|------|------------|
| `require_in_scope(target)` | 收 URL 或 host；**只返回裸 host（不带 scheme）** → 拿它当 base 会 `No scheme supplied`，base 必须另建（`https://` 补回） |
| `write_probe_json(res, case=…, out=…, case_subdir=…)` | `out` 是**文件路径**：传目录 → `PermissionError`；要给目录就自己拼文件名。只给 `case` 时落到 `exports/bot-recovery/<案>/测绘/<subdir>/` |
| 证据内容 | 无论命中与否都要落盘：`host`/`base`/`check`/`levels`/`verdict`（未测 ≠ 阴性） |

## scope 配置事实（"不在 scope" 排错顺序）

1. `config/scope.company.json` 的匹配**只读 `targets` / `domains` 两个键**；`sites` 块（人类可读的台账条目）
   **完全不参与 `in_scope` 判定** ⇒ 只往 `sites` 加域名，所有探针会一直拒绝「不在 scope」，看起来像闸门坏了。
   **新授权目标必须写成通配进 `targets`**（如 `*.example.com`），`sites` 只当档案。
2. 改主文件前先备份（`.bak`），追加后**回读校验命中**；仍然不要改 `scope_lib`。
3. **在跳板机/远端跑引擎工具要按布局放**：`<ENGINE>/tools/ops/<probe>.py` + `<ENGINE>/config/scope.company.json`。
   `repo_root()` 从 `__file__` 反推 ENGINE：探针平铺在 `/root/` 下会让 ENGINE 解析成文件系统根，
   读不到 scope 配置 ⇒ fail-closed 全量拒绝，**症状像闸门失效，实际是部署布局错**。
4. 用户直接给 URL = 已授权：把它补登记进 `targets` 再跑，别因为登记表里没有就绕开探针手打。

## 载荷拼接

- 载荷里含 `%占位%` 之类模板标记时,**禁止 `%`-格式化拼接**(`ValueError: unsupported format character`)→ 用字符串拼接 / `.replace`。
- **同一坑的第二种形态(curl 计量):** 命令行里嵌 curl `-w '%{http_code}|%{size_download}'` 再用 `%`-格式化塞 host/路径必然崩(`%{` 被当格式符)。
  ⇒ 一律 `+` 拼接,或把 `-w` 模板写成单独常量。写 curl 计量行时先自查有没有 `%`-格式化。
- **同一坑的第三种形态(curl 计量:解析侧):** 计量标记若以 `|` 起头(形如 `||200||1234`),用 `m.split("|")[0] == "200"` 判 HTTP 码**恒为假**(首段是空字符串)⇒ **所有成功响应被静默过滤,表现为「目标没数据 / 整批零命中」**,而不是报错。
  ⇒ 解析计量标记一律按**字面分隔符**切分(`rsplit('||', n)` 或 `re.split(r'[|]{2}', …)`),或把标记格式改成不以 `|` 开头;并且**每批必须夹一条已知必通的对照端点**——没有对照,这类解析 bug 会被写成目标的负结论(见 `qqlink-wallet-pentest` §11「请求器自证」)。
- 上传类探针：部分组件**上传被拒仍渲染 filename** → 用算术 oracle（提交 `a+b` 看回显是否等于和）判定模板注入，不要依赖「写文件成功」才敢判。
- **curl 把 URL 里的 `[ ]` 当 glob 范围 → 静默零请求**：URL 含 `post_data[1]=`、`a[0]=` 这类方括号参数时，curl 尝试范围展开并**直接报错退出，一个字节都不发**（`-o` 不建文件、`-w` 无输出、`$http_code` 为空），下游极容易被读成「目标无响应 / 被 WAF 拦」。⇒ 探针 curl 一律加 `-g`（`--globoff`），或对参数先 URL 编码。
- **远端 bash 脚本别在双引号内嵌单引号**：`grep -oiE "...[^\"'< ]..."` 会让 bash 报 `unexpected EOF while looking for matching '`，**从该行起整段不再执行**（前半段输出保留、后半段静默丢失，看起来像「只有一半被测」）。⇒ 用 `write_file` 分片落盘再执行，模式里避开 `'`（改用 `[^\"< ]`），写完用 `bash -n` 自检。

## 闸门自检

用随机非池域名（`zzz-not-in-scope-<rand>.test`）验 fail-closed。
**样例域可能正当在池**（授权池 5800+ 条含 `*.example.com` 这类通配）→ 它被放行是正确行为，
不要据此判定闸门失效，更不要去改 `scope_lib`。

## 模板 + 路由

- 新 `custom-templates/<id>.yaml` 写完**必须挂 `tools/ops/nday_route.py` 的 ROUTES**（指纹 + probe + 期望 needle），
  否则模板写得再好也不会被任何流程调用。
- `od_kit.py validate` 需要可执行的 nuclei 二进制；跑不动时**不要跳过校验**，用 python 校结构：
  `python -c "import yaml;d=yaml.safe_load(open(r'<t.yaml>',encoding='utf-8'));print(d['id'],d['info']['severity'],list(d['http']))"`
- 路由改完做语法自检（`ast.parse`）并打印路由总数 / 新加的 id，确认真的挂上了。

## 扫面类探针：控制组 / 失败计数 / 负结论门槛

1. **每个扫描脚本必须内置控制组，且正控要「有效」**：正控 = 同基址下**已知存在**的端点（未鉴权视角用**应用层 401**、已鉴权视角用**业务错误码**）；正控自己回 404/405 时，**整批零命中只能记「不可判定」**，不得写成负结论。负控 = 同窗口**随机路径**，须与待测条目**逐字节比对**，一致即该批零判别力。
2. **失败计数落盘并在收尾核对**：`000`/超时/连续失败要**逐轮幂等补齐**，把「未命中」升级为「**N/N 覆盖率下 0 命中**」才可判定；`fails > 0` ⇒ 结论未闭。
3. **每发请求前清空正文文件**（`open(BODY,"wb").close()`）：超时回 `000` 时 curl **不写文件**，复用同一路径就会读到**上一次的正文** = 假读数。
4. **同一 URL 的结论不允许跨出口混用**：本机与跳板机的指纹（`remote_ip`/关键头/落盘 md5）先对齐再谈证据；不一致批次标注不可用。
5. **同族/兄弟前端挖来的词表，先在靶上打一轮并判归属**：0 命中常是「不是同一后端」，不是「目标没有端点」。
6. **判命中的比较必须先把响应解码再比字段值**：响应是 `\uXXXX` 转义的 JSON 时，直接对原文子串匹配中文（如「商户密钥错误」）**全部判未命中**——整批真命中被当成零命中写进档案当作死路，比没跑更坏。一律 `json.loads` 后取字段比较；解码失败再回退 `text.encode().decode('unicode_escape')`。
7. **多变量探针必须输出「响应差分组」而不只是逐行原文**：同一 oracle 的 n 个变体跑完，按完整响应体做分桶打印（`{响应: [变体名…]}`）——目标回文案只有几种时，分组把「与基线同响应」和「真变化」一眼分开，避免在几十行相似输出里漏掉那一条不一样的。
8. **经代理/SOCKS 出口的 connect-only 扫描不可作证据：出口可以对任何目标端口回握手成功** —— 表现为「整机几乎全端口 open」
   （含 `3306/6379/27017/2375` 等数据库、注册中心端口），这是**出口在撒谎**的指纹，不是目标暴露面。
   判定必须推进到**协议层**：发该协议的真实请求并读回包（6379 `PING` → `+PONG`；3306 等对端先发握手包；
   5432 发 `SSLRequest` 回单字节；HTTP 类 `GET /` 读首行 + `Server` 头；`9100/9090` `GET /metrics` 读正文）。
   **`connect 成功但协议层零字节/超时` = 探测无效（第三态），既不进 open 也不进 closed。**
   ★**对照组要换一种打**：拿「不存在的端口」做对照在本类**无效**（出口对任何端口都说成功）；有效对照是
   **用同一出口去打已知有服务的端口**（目标 80/443/监控口能读出真 banner/正文）⇒ 证明该出口的取数路径本身是通的，
   此时「其余端口协议层零响应」才能写成负结论。
9. **开扫前先拉「公开契约面」，再做免签普查**：`/swagger`、`/api.json`、`/swagger.json`、`/openapi.json`、`/v2|v3/api-docs`、`/docs` 命中即拿到全量端点 + `securitySchemes`。有 spec 之后按「无 security」分组**只测那一组**，不要逐路径枚举（枚举是 spec 不可得时的退路）。
   同一个 404 只说明**这台实例**没该路径，同族另一台常开着 ⇒ 判「文档面不存在」前逐实例各试一次，别用一台的 404 给全族定性。
10. **凭据判活/判失效必须三态，且判据要校准**：凭据类探针(token/会话/票)的"成功响应"会**抖动** —— 同一枚凭据数分钟内可从
   `success:true`(读到业务数据)变成通用错误码(如 `系统服务异常 code=100` + `data:null`)，且与凭据龄期**无关**(新凭据、11 天老凭据都出)。
   ⇒ 状态分三态：**读到业务数据** / **鉴权通过但业务异常** / **鉴权层显式拒绝**。
   **只有第三态(HTTP 401 + 「未登录或已退出登录」这类统一拒绝句)才算失效**；把中间态写成失效 ⇒ 活凭据被误清
   (票池被白清、重复登录补票)。中间态在采集侧**不得当失效判据**。
11. **「某端点是否存在」的零副作用基线**：一组候选端点**全部返回同一句鉴权拒绝**时，无法区分「路径不存在」与「鉴权先拦」。
   零副作用解法 = 用**同一枚有效凭据**打一个明显不存在的路径(如 `/user/__no_such_ep__`)取**基线响应**，再与候选**逐字节比对**：
   ①候选与基线**一致** ⇒ 该批对该层**零判别力**，只能写「未测定」；②候选与基线**不同** ⇒ 才是有信息量的差异。
   但差异**不等于路径存在** —— 还须排除「前缀级/网关级特殊鉴权规则」，结论只写「**弱正向线索**」。
   与第 1 条负控同源：基线必须**同凭据、同出口、同窗口**，换凭据或换出口都要重取。
12. **时间/时效类探针：龄期符号与「周期≠寿命」**
   - **时区符号**：平台时间戳多为**本地时区**(北京 +8)，采集机/主控常为 **UTC** ⇒ `time.mktime(strptime(平台时间字符串))` 在 UTC 主机上**把该字符串当 UTC**，
     epoch 偏 +8h。龄期公式须补回(`(now - t + 8*3600)/86400`)。**龄期算出负数、或与文件 mtime 明显矛盾 ⇒ 先查这个符号**，不要当成目标异常。
     服务器时区要先取证(`date -u` 与 `TZ=Asia/Shanghai date` 各打一次)，别按本地习惯假定。
   - **不要用采集/刷新周期推断凭据寿命**：「每 6 小时刷一次票」是**采集节奏**，不是票的 TTL。寿命只能实测 —— 按时间戳分档采样，
     对每档打**只读**端点。实测常远长于预期(本例 11 天 vs 认知 6 小时)，据此可放心复用老凭据，也解释了「老脚本里的老票还能用」。
13. **需要「目标状态样本」的对照实验，先证明样本存在**：「用**已失效**凭据探退出契约(零副作用)」这类设计，前提是池里**真有失效样本**。
   开跑前先做一次状态采样：若 N 枚**全为有效**(本例 271 枚全过鉴权)，该实验**不成立** ⇒ 如实写「零副作用路径不可行，需活凭据(有真实副作用，须用户点头)」，
   **不要空跑一轮再声明无样本**，更不要把「没跑成」写成「已做」。

## 沿用旧探针 / 跑前自审（血泪）

磁盘上翻到的探针脚本**不能凭文件名或「看起来跑过」就直接跑**：先整篇读，再对照**当前这一轮**的纪律逐条查 ——
① 有没有**资金/状态邻近端点**（`claim`/`open`/`confirm`/`pin_ok`/`withdraw`）；② 有没有**伪造服务端可核验的字段**（如 `client_ipv4` 与请求源 IP 对账）；③ 签名/载荷字段序是否与**已验证可用**的实现一致；④ 有没有 `os.remove(__file__)` 之类自删（产物取不回）；⑤ 有没有 `BLOCK` 硬拦。
**判据：纪律以当前轮为准，不以旧脚本的存在为准** —— 与当前纪律冲突的一律判「不跑」，用合规版本覆盖，并在档案里记明原脚本缺陷（别静默删掉）。

## 出口/限速纪律(探针自己的流量)

- **同一出口连续发同类探针有上限，别当无限池用**：实测某些站按出口累计计数，先回拦截页，到阈值后**升级为 TCP 层直接断连**（客户端表现为 `RemoteDisconnected`/连接重置，不再有任何 HTTP 响应）——此时**只能换出口，重试无用**。按「每 ~100 发换一个出口」规划批大小，把批拆成可中断的分片。登录类低速口令轮标定：**6–8s jitter** 下 100+ 组可全程无 429；429 一出即判该出口桶翻 → 换出口或错峰续打，别原地硬续。
- **拦截要分清「单发」与「高频」**：某些规则是「敏感词 + 短时高频」的**组合规则**，同一敏感词**单发不触发**——同一批里连发几次才弹拦截页时，先降频重试再判「该词被黑名单」，别把速率问题写成关键词黑名单（会误导后续所有人换 payload）。
- **关键词 WAF 查 URI 还是也查 body，必须用对照实测定，不能沿袭旧结论**：同一站可能两边都查（带 `AND`/`OR`/`union` + 引号的 POST body 一样被封）。**先找免关键词等价写法**再谈绕过：MySQL 的 `||`（OR 同义）往往不被关键词规则拦，可做首轮注入探针；被拦再上内联/版本注释形态。

## 调用输出纪律(防压缩器降级/orphan)

- **单次调用的 stdout 控制在 ~1–2 KB**:打印聚合结论行,不要逐文件/逐路径样例行。大段输出会被压缩器降级为
  「demoted / orphan recovery」——结果取不回,只能重跑。
- 一次调用只做一件事:**扫全仓先只打「命中计数表」**(`PAT=n`)最不易丢;样本行留给第二次小调用单独取。
- 被 orphan 后:**纯读脚本**(只 walk/read/grep)可安全原样重跑;**含发包/写盘/改配置的脚本不要盲重跑**,
  先确认前一次是否已生效(看产物 mtime / 服务端状态)。
- 长证据一律**先落盘再分片小读**(`> out.jsonl` 后按行范围读),不要在 stdout 里灌全量。

## 假阳性/假阴性两频陷阱(先证伪再写结论)

- **200 + 通用错误页 ≠ 存在后台/接口**：`<prefix>/<任意>` 都回同一页时，通常只是 nginx 伪静态兜底（如 `location /pay/`）。**判真假：同前缀加脚本后缀（`.php`）再试**——真脚本路径回 404，能一次证伪，避免堆几十条路径枚举。
- **入口级统一 403 先查必需请求头，再判「未授权」**：同族 AJAX 入口（`/ajax.php?act=`）缺 `Referer` 会一律回 `{"code":403}`，补上与业务一致的 `Referer`/`Origin` 即正常返回业务 JSON ⇒ 403 可能是**缺头**，不是权限结论。
- **先定参数来源层再写循环**：老入口（`/api.php` 类）可能**只读 `$_GET`**，POST body 传参回 `No Act!`。同一个 act 先用 GET/POST 各打一次定下参数源。
- **校验链可以当 oracle 逐级推进，不必一次凑齐参数**：逐条补参让服务端依次吐出下一个缺失项（`未传任何参数` → `X字段不能为空` → `缺少签名参数` → `签名校验失败`），即可把校验顺序与各参数校验方式完整测出，还能附带判定哪个参数走 `intval()`、哪个是真字符串比较。

## 收尾（必做）

验证服务必须收尾并**双核验**：`netstat -ano | grep ":80 "` 无 LISTENING + `tasklist | grep -i <name>` 无进程。
git-bash 里 `taskkill //F //IM x.exe` 会被 MSYS 挡掉（报「无效参数 '//F'」）→ 用
`powershell -Command "Stop-Process -Name x -Force"` 或 `cmd //c "taskkill /F /IM x.exe"`。
