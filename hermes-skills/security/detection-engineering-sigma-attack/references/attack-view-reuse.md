# 攻击视角复用（反向推导自 `attck-purple-hunting.md`）

> 来源：本文件由同目录 `attck-purple-hunting.md` 的采集/检测结论逐条反向推出；技术号与事件号沿用该文件的版本前提（ATT&CK v19.2）。
> 标注：**【实测】**=已核对官方文档（如 Sysmon 事件默认状态）；**【上游】**=上游卡原文；**【未验证】**=需在目标环境实测确认。
> 用途边界：仅限**授权靶场 / 红队书面范围**内做「检测空缺验证」；不得用于修改或删除生产日志、不得用于规避合规处置。每条建议的产出物是「一条检测补测项」。

## 1. 默认未采集的事件源 = 免检面

| 事件源 | 默认状态 | 防守方看不见什么 | 进攻可复用点 |
|:---|:---|:---|:---|
| Sysmon 3 NetworkConnect | **官方文档明示默认关闭**（量太大）【实测】 | 无「进程 → 远端 IP」关联 | T1071.001 直连信标不落主机侧；检测只剩代理/DNS/NetFlow |
| Sysmon 22 DnsQuery | 默认关闭 | 主机侧无解析记录 | T1071.004 隧道/域名回连只在 DNS 服务器端可见；DoH 或纯 IP 可再降一层 |
| Sysmon 10 ProcessAccess | 默认关闭，需显式配置 | lsass 等进程句柄访问无记录 | T1003.001 只剩 EDR 内存检测；无 EDR 即免检 |
| Sysmon 19/20/21 WMI | 多数基线未开 | 永久 WMI 订阅不可见 | T1546.003 持久化免检 |
| Sysmon 23 FileDelete（归档） | 常开 26、未开 23 | 有删除记录但无文件副本 | 删除载荷无副本，取证方无法还原（当期也无告警） |
| Sysmon 2 FileCreateTime | 多数配置未开 | 时间戳改写无痕 | T1070.006 只影响取证，不影响当期检出 |
| PowerShell 4104 ScriptBlock | 需显式开启 | 脚本逻辑不可见，只剩命令行 | 用编码命令/反射加载/内存执行（T1620）绕开命令行特征 |
| 4688 含命令行 | 默认策略常不含 | 只剩进程名，无参数 | 换参数形态、滥用白名单二进制（LOLBin）即绕 |
| 4656/4663 句柄审计 | 需配 SACL | 文件/进程句柄访问无记录 | 敏感文件读取、内存访问类操作免检 |
| 4662 目录服务访问 | 需开 DS Access 审计 | 复制权限调用无记录 | T1003.006 DCSync 免检 |
| 5140/5145 共享访问 | 需开详细文件共享审计 | SMB 横向只留 4624 Type3，无路径 | T1021.002 判不出访问了哪个共享 |
| Linux auditd execve | 未配则无 | 命令执行只剩 `bash_history`（可清） | T1059.004 免检 |
| CloudTrail / GuardDuty 未接 SIEM | 云审计存在但无人看 | 云侧动作与 T1685.002 云日志篡改 | 云上操作无告警，落地检测需先接采集 |

## 2. 日志投递断裂点（主机有日志 ≠ SIEM 有事件）

- **订阅错通道**：agent 只订阅 Security，未订阅 `Microsoft-Windows-Sysmon/Operational` —— 主机装了 Sysmon 但 SIEM 收不到，等价于没装。探针：执行一条必然产生 Sysmon 1 的命令，看 SIEM 有无对应事件。
- **转发链断裂**：WEF/转发器证书过期、队列满、采集代理崩溃 → 事件延迟或丢失；这类窗口期内动作不落库。
- **本地留存滚动**：Security 日志默认容量小（约 20MB 口径【上游】），写满即覆盖最旧事件。**大量高噪声操作可把早期事件自然挤掉**——效果等同清痕，却不会产生 1102。反过来说：出现 1102 一定是高优先告警（T1685.005）。
- **时间源错配**：Sysmon 记 UTC、规则按本地时写 → 时间窗查询漏事件；已知偏移可让操作落在查询窗口外。
- **字段未映射/未索引**：`CommandLine`、`ParentImage`、`GrantedAccess` 未建索引或未做 ECS 映射 → 规则存在但永不命中。探针：直接按该字段检索，看是否有值。
- **采样/去重**：高流量下 SIEM 采样或只留首尾记录 → 中间动作不出现在检索结果里。

## 3. 告警阈值绕过（先逆向阈值，再做 N-1）

上游与常见规则形态多是「计数/速率/熵/变异系数」阈值，逆向后做量级拆解：

- **次数类**（同 IP >5 账号、>10 次 RDP、同账号 dc(ServiceName)>5）：拆成 (N−1) 次/窗口、换源出口平衡计数、让滚动窗口不重叠。跨主机分摊可绕 `stats by host` 类聚合。
- **字节类**（单会话出站 >100MB 口径【上游】）：分片到阈值以下、压缩后再传、错峰到业务高峰。
- **周期类**（信标间隔方差小 → CV<0.5 告警）：加 jitter 使 CV 抬高，破坏「固定间隔」特征。
- **熵/长度类**（子域熵 >3.5、长度 >30 告警）：改 base32 + 低熵填充标签、单标签压到阈值内、TXT 记录规则缺失时优先 TXT。
- **单账号单主机横向**：避开 `dc(AccountName)`、`dc(src_ip)` 类规则，是绕聚合类检测最稳的形态。
- **白名单/基线是最大绕过面**：复用环境已知的运维/更新进程名与父进程链（LOLBin）、复用已观测过的外连目的地（CDN/域前置）、用受信任签名二进制侧加载（T1218.011 类）。
- **告警疲劳**：制造大量低价值告警埋掉真实动作 —— 但**不要碰 1102/4719**（清日志、改审计策略几乎零误报，必进 P1 处置）。

## 4. 靶场内的探面顺序（先探可见性，再选技术号）

1. 探采集：跑无害探针（一次 DNS 解析、一次测试文件删除、一条带参数的命令）→ 回查 SIEM → 得到「哪一路可见」清单。
2. 探阈值：同一动作做 N−1 与 N+1 两档对照，标出告警边界。
3. 探字段与时区：确认 `CommandLine`/`ParentImage` 是否入索引、事件时间基准是 UTC 还是本地时。
4. 再选技术：只从「不可见集合」里挑技术执行；可见面仅在需要验证检测能力时触碰。
5. 归档：每条探针结果回填 `attck-purple-hunting.md` §6 的覆盖级别与缺口清单（这是本文件唯一交付目的）。
