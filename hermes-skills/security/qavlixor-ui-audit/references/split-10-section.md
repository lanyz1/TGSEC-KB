### A8 校验订单补充（续 2026-08-06）：删批次号 + 时间范围随机生成
- **删批次号（cf3323e，用户"批次号直接删了，有真实订单号就行了"）**：全链路删干净——① 组件 `batchNo` state ② 预览临时 id 前缀 `${batchNo}-...`→`PREVIEW-n-m` ③ body 参数 ④ 生成成功消息"（批次 xxx）" ⑤ `rerollOrders` 函数 ⑥ 表单"批次号"字段（form-grid 里与预计生成总数同格的那个 label）⑦ "刷新批次号"按钮 ⑧ translations 键（zh+en） ⑨ API `body.batchNo` 解析 + 日志 detail 的"（批次 xxx）"label。**通用：删 UI 附属功能（批次号/编号/辅助标识）= state/渲染/按钮/API 参数/日志/翻译键 六处一次清；真实业务标识（19 位订单号）保留不动**。验证：tsc EXIT 0 + 页面只乘"每店生成数量/订单状态/预计生成总数"+"生成批量订单"
- **⚠️⚠️ 时间范围 + 订单时间随机分布（6795fdc，用户"框选一个时间范围（8/5 17:11~8/8 17:11 三天）随机生成五单，每单时间在范围内随机但按时间顺序，不是一步到位直接生成到卖家端"）**：**需求本质** = 订单的 `createdAt` 分布在时间范围内（随机但有序）——卖家端订单列表看 5 单时间分散（像真实用户陆续下单），不是同一秒冒出 5 单。**实现三件套**：① **前端 UI**：生成配置区加"下单时间范围（可选）"2 个 `datetime-local`（开始/结束，hint"订单创建时间随机分布在此区间，按时间顺序出现；不填则立即生成"）② **API**：解析 startTime/endTime（校验 end>start）→ `spreadTimes = Array.from({length: totalOrders}, () => start + Math.random()*span).sort(升序)`（totalOrders = 各店 count 之和，跳过无商品的店）→ 每单 `order.createdAt = spreadTimes[created.length].toISOString()`（created.length = 已创建数，随循环递增）→ `PaymentTransaction.paidAt` 同步用 `order.createdAt ? new Date(order.createdAt) : new Date()` ③ **数据层**：`Order` 类型（lib/sample-data.ts）加 `createdAt?: string`（ISO）+ `syncOrderToPrisma` 的 create 加 `createdAt: order.createdAt ? new Date(order.createdAt) : undefined`。**⚠️ 时区坑（实测踩中）**：datetime-local 的值是**用户本地墙钟时间**（无时区后缀），后端 `new Date('2026-08-05T17:11')` 按**服务器时区**解析——服务器是 UTC 时区时订单时间整体偏移 8 小时（实测 5 单中 1 单超范围 2 小时）。**修法：前端提交前 `startTime ? new Date(startTime).toISOString() : undefined`**（浏览器按本地时区解析再转 ISO UTC，后端 new Date(ISO) 正确）——**任何 datetime-local/datetime input 传后端必须前端先转 ISO UTC，裸字符串传必踩服务器时区**。验证：dev.db 查 `Order.createdAt`（毫秒）转 +8 后全部在范围内且升序（实测 08-06 18:18→08-07 04:30→08-08 01:55→03:31→08:46）。**通用：批量生成数据带"时间分布"需求（订单/日志/工单按时间散布）= 随机点升序 + createdAt 字段写入 + paidAt 等关联时间同步；本地库旧数据（时区修复前生成的）会残留范围外时间戳，验证时只数新批次**
