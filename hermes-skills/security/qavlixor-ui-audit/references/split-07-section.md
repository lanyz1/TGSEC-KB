  - **运费模板**：写 `Store.shippingTemplatesJson`（一店一 JSON 数组，零新表）。结构 `{id, name, scope, pricing: 'free'|'qty'|'weight', firstFee, addFee, freeOver, regions: ['global','na','eu','sea'...], isDefault, enabled}`——**全店必须恰好一个 isDefault:true**（repository 的 normalizeDefault 会自动纠正但别依赖）。模板 id 用 `TPL-AS01` 这种可读前缀。示例：全球包邮(free, default)/北美按件(qty 首5.99续2.99)/欧洲按重(weight 首8.5续3.5)/东南亚满49包邮(free+freeOver 49)。`UPDATE Store SET shippingTemplatesJson=?, updatedAt=? - **双态验证**：页面审核不能只看当前态——空态（无数据）和有数据态都要测。dev.db 直接插测试记录即可（例：AfterSaleCase 表 id/orderId/buyer/buyerEmail/storeName/reason/status='seller_reviewing'/deadline/refundAmount，createdAt/updatedAt 毫秒时间戳）。rma 状态机速查：seller_reviewing(商家处理中)→seller_refund(商家已退款)/force_refund(平台强制退款)/已拒绝；72h 未处理可申请平台介入。测试记录可留库供用户演示（量测报告注明 id）
- **⚠️ `AfterSaleCase.orderId` 存的是 `Order.id`（不是 orderNo）**（2026-08-05 C15 实测）：rma 页按 `orderId` 反查订单时必须 `prisma.order.findMany({ where: { id: { in: caseOrderIds } } })`，**不能按 orderNo 匹配**（会查空 → 商品信息渲染不出来）；展示\"关联订单\"要用 `orderNoById` Map 把 id 映射回 orderNo，直接渲染 `item.orderId` 会显示乱码 id（cmsgavzar... 那种）。同理 `titleI18n` 的 key 拼 `${order.id}::${title}`（不是 orderNo）。
- **售后卡片商品信息块（C15 用户要求\"卡片上能看到买的是什么商品\"）**：在卡片 header 下加 `.bac-rma-product` 行（52px 缩略图 + 商品名 600 纯黑 + SKU/数量灰字），整行 Link 到商品页。查询链：AfterSaleCase.orderId → Order（items 带 `productId/productTitleSnapshot/skuSnapshot/quantity`）→ Product（`i18nJson` + **`images` 首图**）。⚠️ **Product 图片字段是 `images`（复数）**，写 `image` 会 TS2561 报错；`images: { select: { url: true }, orderBy: { sortOrder: "asc" }, take: 1 }`。demo 商品无图时用占位 span（标题前 2 字，浅灰底 52px 圆角）。多商品订单（quantity>1 或拆多件）每个 item 一行，SKU 后拼 ` × N`。
