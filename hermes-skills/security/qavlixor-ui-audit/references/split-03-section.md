## 核心坑（几乎每页命中，务必先扫）
1. **重置块特异性**：`.buyer-portal button,.buyer-portal .button{border-radius:8px !important}` 等重置块——同 important 同特异性时**靠文件顺序赢**（重置块在文件更靠后）。胶囊按钮必须 `button.类名`（0,2,1 提特异性）+ 背景/字色/边框**全属性 !important**。`<a>`（Link）用 `a.类名`。
2. **乱入字重**：850/950/800/900 是 AI 生成乱入值（wholesale-primary-action 950、bct-head h1 850、bac-primary-button 800 都中过）。巡检扫字重白名单（只允许 400/500/600/700），见 probes.md。
3. **浅粉/浅橙残留**：饱和色探针（max-min>45）会放过近白浅粉 `#fff0f3/#fff8f9/#fff7f5/#fecdd6/#ffe3e9`。必须加浅粉系专项探针（r 高、g 居中偏低、b 低、r-b>8）。
4. **共用类禁全局改**：`.button.secondary`、`.wholesale-primary-action`、`.pill` 等被多端/多页共用——必须 buyer-portal 作用域 + 高特异性覆盖，不动基类。
5. **全局旧类残留**：`.main`（padding 34/56px 撑高卡片）、`h1{clamp(38px,6vw,68px)}`、`.sap .page-head h2{700}`、**`.buyer-page-head h1{clamp(32px,4vw,48px)}`**（C17 搜索页标题 48px/700/深蓝即此来源——买家端多处页面标题共用该全局类，buyer-portal 作用域覆盖 32px/600/纯黑即可）等旧布局残留，局部覆盖。
6. **`.sap .page-head h2` 赢 buyer-portal 覆盖**（文件序更靠后同重要）→ 需 `!important`。
7. **文字符号图标**（`▤▣▱▭♡♥` 等）是旧式占位图标，用户会觉得粗糙——用 **SVG 线性图标**（stroke=currentColor、strokeWidth 1.6、viewBox 24）包进圆形浅灰容器（48px、`#F5F5F7`），hover 图标容器黑底白图（`.类名:hover .类名-icon{background:#000;color:#fff}`）。图标 JSX 定义在组件文件顶部 `const statusIcons: Record<string, ReactNode>`。
8. **破坏性操作必须加确认弹窗**：用项目现成 `components/seller/Modal`（A2 苹果风基座，注释明示"取代 window.confirm"——460px 白卡/16px 圆角/Esc+遮罩关闭）。模式：state `confirmDeleteId` → 按钮 onClick 只 set state → Modal 内"取消"(btn)+"确认"(btn danger)。地址删除原用英文原生 confirm、收藏移除原无确认，均已升级。不要用 window.confirm（英文原生弹窗、不美观）。
9. **付款/订单文案不写死支付通道**：支付方式已支持 USDT/PayPal/Wise/信用卡/Apple Pay/Google Pay 六种，"完成 USDT 转账/付款"应改为"完成转账/付款"（用户 2026-08-05 明确要求）。下单成功页、订单详情页、下单通知消息 3 处都改过——后续新增文案避免写死通道名。
10. **`replace_all` 误伤多页面**：patch 的 old_string 若含重复的通用块（如 `.xxx-grid{...}` 样式块），`replace_all=true` 会把它替换到**其他页面同构的类**（cart-layout/auth-market-page/bac-status-grid/bct-page 都被误改成 bod-grid 过）→ 页面样式全毁。规则：**CSS patch 必须带唯一上下文**（相邻选择器/注释行一起匹配），绝不用 replace_all；万一误伤立即 `git checkout app/globals.css` 回滚。
11. **`:first-child` 穿透嵌套容器**：`.bod-actions button:first-child` 的 `:first-child` 会命中**包裹 SPAN 内**的第一个按钮（如取消订单被误染黑底）——`first-child` 匹配"父元素的首个子元素"，不限于直接子。必须写 `.bod-actions > button:first-child`（子选择器限定层级）才只命中直接子元素。
12. **间距类拥挤修复**：用户反馈"太拥挤"→ 用 vision-api.py 分析截图确认具体拥挤点（按钮 gap/左右栏 gap/卡片间距/金额字号突兀），批量调 bod-* 系列的 gap/padding：`.bod-status` gap 28px 左列 260-320px、`.bod-actions` gap 10px 按钮 7px 18px/13px、`.bod-grid` gap 20px、`.bod-main/.bod-side` gap 18px、`.bod-amount-total strong` 20px/700/纯黑（勿 900/玫红）。订单详情页类前缀 `bod-`。
13. **⚠️ 全局 `.sap *` 通配重置压卡片 padding（2026-08-05 C14 第二轮实测，"还是太挤"的真正根因）**：全局 reset `.sap *{padding:0px}`（0,1,0）与 `.panel,.card,.stat{padding:18px}`（0,1,0）**同特异性靠文件顺序赢，而 `.sap *` 在文件更靠后** → 所有卡片 padding 实际为 **0px**，标题/内容全部贴死在卡片边框上，怎么调 gap 都"挤"。**诊断**：CSSOM 枚举 padding 规则会同时看到 `.panel,.card,.stat{padding:18px}` 和 `.sap *{padding:0px}`，实测后者赢。**修法**：提特异性 `.buyer-portal .panel.bod-card`、`.buyer-portal .bod-grid .panel`、`.buyer-portal .bod-status.panel`（0,3,0）显式 `padding:24px`，同块顺便把边框中性化（`#DFE0F2`→`#E8E8ED`）。**⚠️ 选择器形态**：`<article className="panel bod-card">` 是同一元素双类，写 `.panel.bod-card`（连写），**不是** `.bod-card .panel`（后代）；`.bod-status` 同理是 `.panel bod-status` 双类。**教训：用户说"页面挤/内容贴边"先 CSSOM 枚举卡片 padding 来源（可能被全局通配 reset 压成 0），别只调 gap**。
14. **金额锁定 USDT 用 `data-currency-lock`（2026-08-05 C14 用户要求"实付款统一 USDT"）**：`components/LanguageSync.tsx` 的 `applyBuyerCurrency` 会遍历 `.buyer-portal` 下所有文本节点，把含 USDT 标记的金额**按用户语言换算成当地货币**（中文态 `12 USDT` 变 `12 CNY`、英文态变 `$12.00`），除非节点在 `moneyExcludeSelector` 内——该选择器**已内置 `[data-currency-lock]` 豁免**。**修法**：需要固定 USDT 的区域加 `data-currency-lock` 属性（表格/金额汇总/付款信息容器各一个即可，子节点自动豁免）。实测：订单详情页 3 处（`bod-items` 表格、`bod-amounts` 汇总、`bod-rows` 付款信息）加锁后，中英文态均保持 `12 USDT`。**业务规则（用户 2026-08-05 拍板）**：订单详情页"实付款"无论支付方式/货币一律以 USDT 显示；支付方式行按 `payment.method` 动态显示（paypal→PayPal、wise→Wise、manual→线下转账、默认 USDT·TRC20），勿硬编码。
15. **改 CSS 前先确认真源类名（2026-08-05 C16 消息中心教训）**：消息中心组件（ChatWorkspace）的类名是 **`cl-*` 前缀（chat-list 缩写）**——搜索框在 `.cl-search input`、tabs 在 `.cl-tabs button`，**不是** `.chat-search`/`.chat-tabs`（那是旧死 CSS，改了无效）。且 tabs 激活类名是 **`on`**（`button.on`）不是 `active`。**流程**：先 `document.querySelector` 元素后沿 parentElement 链（3 层）打印 className 确认真实容器，或 CSSOM 枚举 `el.matches(r.selectorText)` 看实际生效规则，再写覆盖——不要凭类名猜。**⚠️ 取层级要取到目标容器本身（2026-08-05 订单页 page-head 误判）**：`h2.parentElement` 可能命中**中间包裹 div（class=""）**而非 `.page-head`——那次实测误以为 `.page-head` 的 CSS（display:flex）没生效（computed 是 block），实际是取到了空 class 的中间层。正确姿势：`querySelector('.sap .page-head')` 直接取目标类，或沿链打印后**数清楚层级**再量。同页还踩：**input 边框继承 `currentcolor`**——`border-color: currentcolor` 时边框色=文字色，搜索框"黑边"其实是文字色 `#1D1D1F` 透出；修边框色必须同时设 `color` 或边框加 `!important`。
16. **`.sap X` 同特异性靠文件序压 buyer-portal（C16 tabs 激活态变浅灰）**：`.sap .cl-tabs button.on{background:var(--gray-soft)}`（0,3,0）与 `.buyer-portal .cl-tabs button.on`（0,3,0）同特异性，sap 域在文件尾部**靠后赢** → buyer-portal 覆盖需全属性 `!important`（bg/border/color 都要）。与坑 #6 同族：sap 域规则只要特异性持平就赢。
17. **聊天页样式在 `app/seller-proto.css`，不在 globals.css（C16 工单卡片重设计）**：消息中心/聊天窗的 `.msg-line`、`.order-card`、`.oc-top`、`.oc-row`、`.oc-t` 等类定义在 **`app/seller-proto.css` 的 `.sap` 作用域**（globals.css 里搜不到——先 grep 所有 css 文件再动手）。结构：system 消息 = `ChatWindow.tsx` 的 `.msg-line` div（原为灰块时间线 `#F2F2F4` 底+左灰条+方角，内含 `DynamicText` 描述 + `MessageCard` 渲染的 order-card）。
