# SPA 请求契约反推(从 bundle 取真实调用点)

端点已知可达、但构造不出合法请求体时用。产出物 = **真实字段名 + 必填伴随字段 +（如需要）本地可复现的请求体加密**。

## 触发场景
- 端点报错笼统(`参数错误` / `100010` / `Invalid parameter`), **不按缺哪个字段细分**
- 需要构造"能过参数闸门"的请求(登录/签约/绑卡/校验类)
- 已抓过主包但 grep 不到某个方法的调用方

## 铁律
1. **同码不变 = 前置闸门, 不是候选名不对。** 当 N 种形状(候选字段名逐个、`params`/`data`/`encryptData` 整体密文、逐字段密文、明文混密文)返回**字节相同**的错误时, 立刻停止候选喷涂 —— 差异化探测只在"服务端逐字段各自报错"时有效, 同码时是纯浪费。改去读调用点。
2. **字段名只在调用点, 定义与端点常量表都没有。** `api.x=function(n){return http.post(C.XUrl,n)}` 零字段信息; 端点常量对象只有 URL。必须找到组件里构造实参的那一行。
   ★ **端点 URL 全局只出现一次(grep 只命中免加密白名单数组)时, 调用点不在 URL 旁**:
   调用方把**解析结果对象**直接当参数传(`const {fileid,orderid}=wt(x); u(url,{fileid,orderid})`), URL 由封装函数拼
   ⇒ 改 grep **解析/解构那个函数**(`function wt(` / 解构花括号里的键名), 不要顺 URL 找调用行。
3. **抄整个对象字面量, 不抄看得懂的那两个键。** 登录类载荷常是 `{主标识, code, nonce, channel}` 这类四件套, 且验证码键名可能就是 `code` 而非 `smsCode`; 只猜一半永远过不了闸门。
   ★ **键名的"近似"陷阱: 候选喷涂必败。** 真实键常是 `loginpasswd` / `drawpwd` / `agentname` 这类**非直觉拼写**; 用 `loginpwd`/`password`/`adminPwd` 等 20+ 近似候选合并发一发, 服务端照样回同一句 `<字段>不能为空`(它只认精确键) ⇒ **别把候选喷涂当参数发现手段**, 直接读调用点的实参对象字面量。
   ★★ **文案点名的字段不在你发过的 key 集合里 ⇒ 唯一结论是「键名没对上」, 由它推出的「闸门顺序」一律作废。**
   实测代价: 用 `googleCode` 打登录口, 服务端回「谷歌验证码不能为空」, 于是断定「验证码闸门排在密码之前 ⇒ 密码/账号面测不了」并整轮收线;
   真键是 `code`, 换成 `code` 后同一端点立刻回出密码层与账号层文案(账号存在性 oracle 一起到手)。
   机制: **「缺字段」文案无法区分「该闸门确实前置」与「你没发这个键」** —— 两者字节相同。
   ⇒ 凡文案点名的字段是你**没发过**的键, 先回调用点取键名再谈闸门顺序; 否则会把一个可打的端点判成硬墙。
4. **错误码当进度条。** 先按"闸门阶段"给错误码归类, 阶段跃迁才算契约打通(如 `100010 参数错误` → `100003 认证失败` = 已越过参数闸门进入凭证校验)。仍在参数闸门阶段就别讨论绕过/爆破。
5. **伴随字段用"空 vs 假值"两发定位。** 同一伴随字段送 `""`/`null` 与送 `"0"*32`/`"1"` 常分属不同闸门; 两发即可判它是否参与闸门。
6. **明文参数打加密 API = 假成功, 不是「无权限/无数据」。** 若前端把参数塞进 `?encryptParams=<密文>`(GET) / 请求体=密文(POST), 你用裸明文参数打同一路径会拿到 **HTTP 200 + 空 data / `操作成功` 无 data** —— 极易误判成「服务端有 owner 过滤」而白弃整个面(实测把这套面写成"IDOR 已证伪", 实际是参数从未被解密)。复核法: 同一端点用**前端自己的方法**发一次, 有数据即证明明文请求无效。凡见「200 但无 data」, 先按本条复核再决定是否判死。
   ★★**反向也已实测(别把这条读成「参数必须加密」)**:标识参数**留在明文 query、信封同时在**时**真能读到他人数据**(实测 `GET /app/user/serUser?accId=<他人>` 搭配 `encryptParams=AES({})` 回他人 `uname`);而**同一路径完全不带信封**回 **Spring 纯文本 `403 Forbidden`**。
   ⇒ 判据是**信封在场**,不是「参数必须密文」;遇纯文本 `Forbidden` 先**补信封**重发,不要读成「无权限」。
   ⚠️ 空对象 `{}` 也是真值 ⇒ **空参请求同样会带 `encryptParams`**(包装器里写的是 `if(params)` 而非「参数非空」)⇒ 别以为「没参数就不用信封」。
7. **同码闸门的字段里,必有一条是服务端「能独立观测」的 —— 先补它。** 一包自报字段(`user_agent`/`device_*`/`automation_*`/`client_ipv4` 之类)中,其余都可缺省或伪造,但**服务端能自己测出来的那个(常见是 `client_ipv4` = 请求源 IP)是真闸门**:漏它 ⇒ 端点永远回同一个笼统码;补成**自己的真实出口 IP**(经代理/跳板时是跳板的出口,用 ipify/icanhazip/ip.sb 探测) ⇒ 首打即通。判定法:把候选字段按「服务端能否独立观测」分两相,**从可观测的那一个开始逐条补**,而不是从「看起来最像」的开始。
8. **不触碰真实用户。** 短信/验证码登录的 `nonce` 由发码接口签发, 而发码接口会**真实触达手机** ⇒ 不调用、不爆破真实验证码。只做零副作用探测(空值/假值/不存在的 id), 以回包差异当 oracle; "唯一缺服务端签发的 nonce"作为卡点如实上报。

## 0. 先定 base 与系统身份(不定就整批 401 白打)

**运行时配置文件是唯一权威来源**,优先级高于任何从 bundle 里 grep 出的 `baseURL` 字面量:

- 抓 SPA 根目录的 `/_app.config.js`(或 index.html 内联的 `window.__PRODUCTION__<HASH>__CONF__`),
  明文给出 `VITE_GLOB_API_URL`(真实 API 前缀)、`VITE_GLOB_APP_TITLE`、`VITE_GLOB_USERTYPE`、
  `VITE_GLOB_APPID`、`VITE_GLOB_ENABLE_ENCRYPT`。
- **逐域各抓一份**:同族站点里不同子域常是**不同系统/不同前端**(管理端 / 商户端 / 测试环境);
  靠 `USERTYPE` 区分的两个前端可能共用同一后端 ⇒ 配置文件与 bundle **只需审一份**,别重复逆向。
- **★前缀必须逐域确认,绝不跨域套用**:实测一族站点并存 `/prod-api`、`/test-api`、`/xvip-api` 三种前缀,
  各挂不同系统;拿一个域的前缀去打兄弟域 = 整批整齐 401/404,而那**不是"未授权",是打错了系统**。
- **裸 GET 前缀根路径 = 产品身份指纹**:`GET <prefix>/` 常回欢迎语 + 版本
  (形如 `欢迎使用X后台管理框架,当前版本:v3.9.0`)⇒ 一句话确认这个前缀属于哪套产品,比猜路径便宜得多。
- **旧构建的 base 可能只差一个路径层**:向分析副本索要 base/契约前先做线上对账,否则错一层就是"路径全 404"。
- ★ **绝对服务基址在「配置对象」里, `*Url` 键一次全拿**:bundle 里的相对路径(`/v1/user/getUserInfo`)离开基址就没有意义,
  而基址常写在**另一个 chunk 的配置对象**里,形如 `walletUrl:"https://api.<域>/"`、`baseFileUrl:"https://file.<域>"`、
  `tImageUrl:"https://<第三方>/"`、`wsUrl:"wss://…"` ⇒ **钱包端 / 文件端 / 图片端 / WS 端各是一个独立 host,不是一个后端**。
  ⇒ 对**全部落盘 chunk** 用 `grep -oaE '[A-Za-z_]{2,20}[Uu]rl[[:space:]]*[:=]'`(以及 `VITE_[A-Z_]*URL`)先定位键名,
  再按字节偏移开窗读值(单行 minified 开窗法见「坑位」),然后把每条绝对基址**挂上路径各打一发**;
  **绝不要假设相对路径归属当前页面所在的域** —— 那会得到整齐 404/兜底页,并被读成「接口不存在」。
  ★ 拿到的每个 host 都要**独立验活**(DNS + TLS + 未知路径响应体署名):基址写死 ≠ 可达(判据见 `recon-discriminators` §43)。
  ★ 同一份配置对象还顺手给出**业务线前缀**(如 `honeybee*` / `efw*` 这类)⇒ 那是独立的攻击面清单,别当字段看完就丢。

**线上 vs 本地构建漂移(必做对账)**:入口文件名 hash 不同 = 不同构建,前缀/契约/密钥常量都可能不同。
规则:**以线上文件为准**再静态分析;**不要向本地旧副本索要密钥、契约或 base**。
对账方法(便宜且决定性):线上/本地各抓一份入口,先比 hash,再比**关键常量的字面量本身** ——
"hash 同 + 常量同"才算同一档;hash 不同但常量逐字相同 ⇒ 契约仍可用(漂移在无关代码)。

## 流程
1. 抓 SPA 入口 HTML → 正则取 JS 资产(`main`/`polyfills`/`runtime`)。
2. 从 runtime 取 **chunk id→hash 映射**, **批量抓全量 lazy chunk 并落盘**。
   ★ Vite 构建直接给**功能命名**的清单: `__vite__mapDeps([...])` 数组里是 `js/<功能名>-<hash>.js` ⇒ 按功能名只抓你要的那几个(商户/担保/收款/后台页)，不必解析 id→hash 表；hash 变、名不变。
   同源注意: 主包 hash 会变而 lazy chunk 名可能跨版本相同 ⇒ 先在 CDN 上按名试抓, 200 的即当前版本。
   ★★ **静态分片可能只在「同族的另一个域」上有**: 实测同一路径 `/js/<页名>-<hash>.js` 在门户/营销域回 200、在 App 自身域与后端域回 404
   ⇒ **拿不到分片时把候选域逐个试同一路径**, "入口域 404" 不等于该分片不在。反过来说: 用相对路径抓会落在你当前所处的域(见图标检测类坑), 一律**写绝对 URL 逐域试**。
   ★ **认亲法(比逐个域猜便宜且决定性)**: 逐域 `curl -s -m 12 -o /dev/null -w '%{http_code} %{size_download}'` 取根 HTML, 与**本机已存的入口 HTML 字节数一致**的那个域 = 站点 host(实测 API/后台域根路径 404、站点域回 2235B = 本地同版 ⇒ 该域按 runtime 映射表 76/76 chunk 全中)。
3. 在落盘件(而非只主包)上 grep **调用点**取实参对象字面量 ⇒ 真实契约。
   ★优先 grep 请求封装键名:**`urlName`**(`request({urlName,method,data})` 封装)、`baseURL`、`axios.create`、`request(`;
   命中形如 `b.login=e=>S({urlName:"/v1/auth/login",method:"POST",data:e})` ⇒ **路径 + 方法 + data 形状一次确定**,
   比 grep `/api` 命中率高得多(路径多为拼接, 正则易漏)。
   chunk 分三类读:**配置类**(几百字节, 环境名/域名/开关/超时)、**页面类**(body 拼装字段 + 流程码)、**vendors**(跳过)。
4. 分层验证: 完整字段集发一次 → 逐字段置空/置假 → 看错误码是否跨阶段跳变。
5. 若请求体是密文: 识别前端加密模块, 用其硬编码密钥在本地复现加密后再构造请求。
6. **鉴权头 + 凭证存储从请求拦截器一次读出(自动化前置)**: grep `interceptors.request.use` / `withCredentials` /
   头名赋值(`e.headers["<X-Token>"]=t`)⇒ **头名、token 存储键、包装形状**一次到手,别用 `Authorization` 盲试
   (头部名错时回统一句 401,极易误判成「token 无效/越权不可打」)。
   ★★ **未登录/注册流同样有拦截器头, 且多半是「设备指纹会话」而不是票**: 登录前流的拦截器会给每请求追加
   `visitorId` + `lang`(`visitorId` = 指纹 SDK 的产物, 常见 FingerprintJS Pro;SDK 的 `apiKey` 与初始化调用点就在 bundle 里可挖)
   ⇒ **只复刻 URL + query + body 去打注册/登录前端点, 会整齐回同一个笼统码**(形如 `1053 非法请求`),
   而这极易被读成「签名算法不对」, 回头白做一轮 crypto/签名复现。正确顺序: 先把拦截器**该加的头全列出来**
   (`visitorId` / `lang` / `suidvisitorid` / `Authorization`…)再发。
   ★ **参数↔头是配对关系**: 形如 `suid` 参数必须配 `suidvisitorid` 头(反之亦然) —— 只送其一照样回笼统码;
   读拦截器时把「哪些头由哪个参数驱动」一并读出。
   ★ **app 层可能另设「入口来源闸」, 且常直接用中文业务文案告诉你**: 页面能开、静态资源全能下, 但所有业务端点回
   `请用 <某通道> 入口进入平台` 这类文案 ⇒ 这既不是参数问题也不是鉴权问题, 是**会话来源**门(必须经目标 App/小程序入口自带的自证数据
   `initData` 之类建会话) ⇒ 照它说的通道把会话建出来再谈契约。
   **凡拿到语义明确的中文业务文案, 一律优先当方向指示读, 不要继续穷举参数。**
7. **全量 chunk 榨「端点表」→ 免鉴权扫描**: 对**全部落盘 chunk** 跑 `grep -oaE '[A-Za-z_]+Api/[A-Za-z_/]+' | sort -u`
   ⇒ 该端的真实端点表(实测 73 个 chunk 榨出约 200 条)。★ **只扫主包会严重低报**(实测主包 5 条 / 全量 200 条)
   ⇒ 拿这张表逐条免鉴权探测、比对统一句,产出白名单/oracle 清单(见 `gateway-authfilter-whitelist-oracle`)。
   ★★ **命名空间不是 `XxxApi` 时换「封装键 + 反引号模板」正则, 否则整批零命中**: 现代 Vite + axios 封装站
   (如 Go/Kratos 式的 `/app/v1/*`、`/admin/v1/*` 双前缀)端点不写在命名空间常量里, 而是写在**调用点的模板串**里,
   形如 `` url:`/app/v1/auth/login` `` / `` url:`/admin/v1/files/${e}` ``;
   用 `[A-Za-z_]+Api/` 扫全部 chunk **0 命中**, 改扫 `` grep -oaE 'url:`[^`]{2,80}`' `` 一次拿全(实测一套 App 面 32 条端点)。
   ⇒ 铁律: **先看调用点的键名形态再选正则** —— `url:` / `urlName:` / `path:` 三选一, 选错就是整批零命中,
   而零命中极易被读成「前端不构造载荷」(与「只扫主包」是同一个坑的两种面貌)。
   ⇒ 两条前缀(`/app/*` 与 `/admin/*`)并存 = 同一后端的**两个身份面**: 同一张表在两个前缀上各跑一遍,
   免鉴权差异恰恰最常出现在管理前缀上(用户面前缀锁得严、管理前缀反而漏挂)。
   ⇒ 静态 grep 只给「路径 + 方法 + 字段名」; **信封形状 / 必带伴随头 / 真实 URL 多出的字段必须以运行时录制为准**(见下文 UI 驱动取证)。

## ★★★ 运行时接管: 直接调用目标自己的 API 模块（优于本地复现加密）

当参数/请求体加密叠着 WAF 令牌链、本地复现加密成本极高时, **不要在本地重造加密** —— 在活着的页面里 `import()` 目标自己的 API 模块, 直接调它的导出函数: 加密、令牌链、响应解密全部由目标代码替你完成(实测一步打开整片只读面 + 写入面的零写入探闸)。

1. 页内枚举已加载脚本: `performance.getEntriesByType('resource').map(r=>r.name).filter(n=>/\.js/.test(n))`。
2. 逐个 `await import(u)` 挑 API 模块(键数 > 10 且含特征导出); **模块 URL 常在根路径**(`/js/index-<hash>.js`)而非相对页面 baseURL, 用绝对 URL 试。
3. 反查压缩导出名: 主包尾部 `export{a as X, b as Y, ...}` 用 `grep -oE "[A-Za-z0-9_$]{1,4} as [A-Za-z0-9_$]+"` 一次拿到**方法名→压缩名**映射 ⇒ `await window.__A.J({...})` 即发对应端点。
4. 包装调用: 结果写全局 + `window.__R='PENDING'` 轮询(CDP evaluate 多数不支持 awaitPromise), `catch` 里取 `e.message||e.msg` —— **返回的错误文案就是字段发现**。
5. 先扫只读面(配置/费率/清单/位置): 自身即高价值情报(闸门阈值、费率、产品表), 且零副作用。
6. 写入面前做**零写入探闸**: 字段补全但 2FA 码缺失/填错 ⇒ 同时读出"闸门顺序"且不落库。★ 2FA 是否必需常是**条件性**的(服务端先回 `hasGA/googleEnabled`, 前端才拼 `googleCode`: `...(i.value?{googleCode:u}:{})`)⇒ 探针先判本账号是否启用。

完整 harness(CDP 钩子注入 / 导出映射解析 / 调用轮询 / 闸门探针)见 `references/runtime-api-module-invocation.md`。

## ★★★ UI 驱动取证: 让 App 自己把请求发出去（手工复刻恒被拒时的正解）

参数全对、仍恒回同一个笼统码（`1053 非法请求` / `参数错误` / 统一 `401`）时, **先假设「这一发必须由页面自己发出」**:
服务端常把闸做在**请求上下文**上（一次性挑战产物与会话绑定、来源自证数据、前端运行时头）⇒ 穷举参数收益为 0。
换做法（每一步都在本库有实测支撑）:

1. **装录制器**（XHR + `fetch` 都要 hook）: `open` 里记 `(method,url)` 并建 `this.__hd={}`,
   `setRequestHeader` 存头, `send` 把 `{method,url,hd,body}` push 进 `window.__L`。
   ★ 注入必须在文档加载前（`Page.addScriptToEvaluateOnNewDocument`）+ 每批复现前清空数组, 否则读到陈旧值。
2. **走真路由, 不走可见控件**: 组件里的弹窗/`$emit("changeDlg")` 常无法让子组件真正实例化（调了方法、DOM 无变化）。
   先把框架路由表 dump 出来（Vue: 递归 `$router.options.routes` / `getRoutes()`）找**独立真路由**直接 `nav` 过去。
   实测同一站点「注册」在登录页里只是个 dialog, 而 `#/registry` 是可直达的真路由。
3. **驱动真 UI 到提交**: 填表 → 勾人机校验 → 处理挑战（滑块走真鼠标拖拽, 见下）→ 点**站点自己的提交按钮**。
4. **读录音拿契约**: 录音里的 URL + 查询串 + body 才是**真契约**。站点组件的 `data.form` 常与真请求不一致
   （实测真 URL 多出一个源码 form 里根本没有的伴随字段）⇒ **契约以录音为准, 不以源码 form 为准**。
5. **框架实例内省**（与录制器互补, 常一步到位）: `document.querySelector('#app').__vue__` 递归 walk
   （限深/限节点数, 否则爆）⇒ 读组件 `_data`（一次性挑战产物常就存在 `form.<challenge>`）、`$options.methods`
   （可**直接调用站点自己的方法**让它发请求）、`$router`（真路由表 = 攻击面地图: 代理面/资金面/安全面/业务面一眼分完）。
   React 等价物 = fiber 树 / 全局 store。
6. **拿到的凭证立刻用**: 注册/登录类端点常直接把会话令牌写进响应（`suid`/`token`/`uid`）⇒ 落盘再用;
   叠加邀请码/上级参数（`?upcode=`/`?hbid=`）即可**自建账号池**（后续 IDOR/越权的账号来源）。
