## ★★ 管理端 / 多端 bundle:角色裁剪对象与「第二后端」

后台类 SPA(UMI / Ant Design Pro、各类 vue-admin)一次能给你三样东西,比逐个猜端点省一个量级:

1. **hostname 切换行 = 环境基址 + 额外后端清单。** grep `location.hostname` / `hostname ===` / `hostname!==`:
   形如 `var r = location.hostname !== "admin.<域>"; baseUrl = r ? "https://demo.api.<域>/v3" : "https://api.<域>/v3";
   merchantUrl = r ? "http://demo.mapi.<域>/v5" : "https://mapi.<域>/v5"`
   ⇒ ①一次拿到**生产与 demo 两套基址**(demo 常同后端,可直接沿用生产契约);
   ②同一行旁边常坐着一个**此前完全未知的第二后端**(商户端/商家端/放单端 API)。
   ⇒ 见到就对新后端**单独**做存活与判层(挑一个已知词打一发:401/422 = 活、404 = 死),**绝不假设它与主后端同鉴权、同票**。
2. **同一实体按角色裁剪字段 ⇒ 目标字段名从「高权那一端」读,不从报错猜。**
   同一条记录在两个前端里字段不同:低权端被剥掉的部分(联系方式/手机/二维码之类),正是要拿的东西。
   ⇒ ①读**高权前端**的页面 chunk,里面直接消费这些字段(`ge(e.<字段>)`、`D(e.<字段>)`),字段名一次到手;
   ②同一 chunk 里的调用点(`x.default("/admin/task/"+e.id+"/creator",{method:"GET"})`)就是**承载这些字段的端点**;
   ③用低权票打那个端点,拿 `not admin`/`403` ⇒ 得到「路径存在 + 受角色门控」的**存在性正证据**(不是 404,别当死链丢掉)。
   ⇒ 推论:**两个角色的 bundle 之差 = 目标字段名表 + 承载它们的端点表**,这是最省的枚举方式。
3. **特权路径全表从 bundle 里机械榨。** grep 调用点形态(`x.default("/admin/…`、`request({urlName:"/admin/…"})`)远强于路径词典:
   得到的是该控制台**真实会打的完整端点表**(含 `xxx/{id}/creator`、`payment/…/query` 这类非直觉路径),整表拿去测漏挂鉴权(见 `api-probe-layer-triage` 的《特权路由族漏配猎捕》)。

4. **反向查字段名 = 定位特权 chunk 的最短路(先算命中集合,再决定读哪个)。** 不要把高权端 chunk 逐个读完:
   先在**全部已落盘 chunk** 上 grep 目标敏感字段名, 命中集合直接告诉你是哪几个 chunk、哪一端消费它。
   实测 `creator_tel` 只命中 **2 个** chunk(一个审核页 + 一个此前未读的 chunk), 而 `creator_name` 还额外命中**另一族** chunk(企业/商家端 `js_web/p__Project__…`)
   ⇒ ①逐个读命中件的调用点即可拿到承载该字段的端点;②**同名字段跨端命中 = 该字段在多个前端被消费**, 两端各有一条取数路径, 都要试(一端是 admin 前缀、另一端可能是无前缀的相对路径)。
   ★ **chunk 文件名本身就是功能地图**: UMI / AntD-Pro 的 lazy chunk 名形如 `p__<目录>__<页面>__index.<hash>.async.js`(如 `p__Project__talents__index…`),
   **名字即页面路径** ⇒ 先按名筛(`*project*`、`*Tasks*`、`*view-contact*`), 再决定读哪个, 别按 hash 顺序硬啃。
   ★ **相对路径的 base 不在调用行**: 同一批 chunk 里相对路径(`/project`、`/kols`、`/export`)与绝对路径(`/v3/admin/…`)混着写
   ⇒ 相对路径的 base 在**该端自己的请求封装/webpack 配置**里; 把每条相对路径按**每个候选 base 前缀**各试一发再判死
   (实测同一批相对路径在某前缀下 404、换一个前缀后 200/403)。这是「前缀必须逐域确认」在**单个 bundle 内部**的同一条规则。
   ★ **敏感字段不在这个接口 ≠ 该字段拿不到**: 把详情口取全字段后仍缺的字段列表记死(实测 58 字段全取仍无联系方式类字段),
   **该字段必然有一个独立接口**——下一步是找那个接口(回 bundle 按字段名反查), 不是在这个接口上继续穷举参数。

**Next.js 静态导出的前端**(另一侧前端常见形态):`/_next/static/<buildId>/_buildManifest.js` 给出**全路由清单**;
页面数据里出现 `__N_SSP` ⇒ 该页数据在**服务端**取(客户端凭据/变量常是空串),
所以「页面里 grep 不到 token/鉴权头」**不能**读成「无鉴权」,那只是取数发生在服务端。
同一平台两个域常是**两侧 App**(`www.` = 接单/需求侧,`m.` = 放单/供给侧):页面里微信 JS-SDK 的 `appid` 直接把两侧分开 —— **两个 appId 不同 = 两套登录、两套票,不可互换**。

## ★★ Next.js App Router: Server Actions 作为「调用点」形态（$ACTION_ID）

现代 Next.js 站的表单提交 = Server Action ⇒ **每个 action ID 就是一条可直接调用的端点**（无 URL 可言）；前端全部校验都在提交前,直提即绕过。

- **枚举**: ① 页面 HTML `rg -o '\$ACTION_ID_[a-f0-9]{40}' pages/*.html`（原生表单含 `<input type=hidden name="$ACTION_ID_<hex>">`）;② 全量 chunk `rg -o 'createServerReference\)?\(?"[a-f0-9]{40}"[^)]{0,120}' js/*.js` —— 收尾参数常带函数名(如 `logoutUserAction`),**名字即用途**(登出/注册/查单一次认全)。
- **直调**: ① 表单式 `POST <表单所在路由>`,urlencoded 或 multipart,body = `$ACTION_ID_<id>=&字段=v…`(隐藏域 key 无值);② RSC 式 `POST <路由>` + 头 `Next-Action: <id>`,body 为序列化参数数组。先 urlencoded 再 multipart——服务端 `formData()` 两者都解。逐字段测参数篡改。
- **路由存在性 oracle(404 差分)**: 404 但渲染**完整站点壳**(自定义 not-found)= 路由在 app tree、组件内 `notFound()` 伪装(隐身后台/未授权) ⇒ 有身份后回探;404 为默认 `__next_error__` 页(无壳) = 路由不存在。**跟随重定向读 final URL**(跳转泄露真实路由,实测 `/agent/` 302 → `/admin/agents`)。
- **产品认同纪律**: 重写版站常保留旧产品路由模板而旧端点已 404 ⇒ 定性以实测响应为准,别凭 URL 模板断「无此面」。

## 坑位
- **只看 main.js 会漏**: 登录/短信/签约组件常在 lazy chunk, 主包 grep 0 命中 ≠ 前端不构造载荷、不算签名。
  ★★ **下「客户端明文透传 / 零加密」这类结论前必须 BFS 抓全分片，且先证明抓取器本身有产出**：以入口 HTML 的 `src` 为种子，对**每个已落盘文件**再挖新的 `…js` 字面量迭代入队（懒加载链常 3–4 层）。
  产出数 N 就是结论的硬度：**N 只有 1、或「全量 grep 后只有入口命中」时，先怀疑提取正则写错** —— 实测同一站分片挂在 `/js/<名>-<hash>.js` 而非 `/assets/*.js`，正则按 `/assets/` 写就抓 0 个文件，而「0 个文件」极易被读成「没有分片 / 主包不引用」；换 `/js/` 后一次抓到 268 个。
  ⇒ 只有 **N 为数百量级**且全量 grep 后仍只命中入口，才配写「该字段由客户端原样明文发送」。
  ★ **主包 grep 端点整批 0 命中时,先抽「分片文件名字面量清单」再逐片抓** —— 它与 `__vite__mapDeps` 是两种形态:实测主包内直接以 `[\w\-]+-[A-Za-z0-9_\-]{6,12}\.js` 列出清单,`auth-<hash>.js` = 登录契约、`<Layout>-<hash>.js` = 菜单/路由、`r2-<hash>.js` = 存储面 ⇒ **分片名即用途**;主包自己只留 axios `baseURL` 与相对短路径(如 `/login`),把它当端点表会**低报为零**(实测 24 条端点全在分片里)。
  ★ **自研 Node/Express 后台的路径 oracle**:`Cannot POST /<path>`(Express 默认 404 体) = **路径不存在**;`{"status":401,"message":"用户名或密码错误"}` = **路径正确、凭据错**。前缀对 ≠ 子路径对 —— 实测打 `/admin-api/v1/system/auth/login` 回 `Cannot POST`,真路径是 `/admin-api/v1/auth/login`;先用这对判据校正路径,再谈口令/绕过,别把 404 读成「该面已封」。
- ★ **SPA 兜底路由下「非 200 码」≠「端点存在」**: 前端接管的站，`try_files` / `index.html` 兜底会让任意 `GET /xxx` 回 **405 或 200 但响应体是整份 index.html**。判端点一律**看响应体**（HTML 壳 = 假端点；框架默认 404 页或业务 JSON = 真路由），只看状态码会把不存在的回调/接口写成「已确认存在」。同理，该站的真回调路径要**从前端下单/支付流程反推**，别用路径词典硬猜。
- ★ **登录守卫只拦 API,不拦静态分片**: 业务代码全在懒加载 chunk 而 chunk 是静态资源 ⇒ 全量 chunk 可**不登录直下**(webpack: `grep -oE '\.e\([0-9]{3,6}\)' <main>.js | sort -un` 枚举 id;Vite: `__vite__mapDeps` 按功能名抓),任一 `200` 即证不鉴权 —— 界面进不了登录态 ≠ 拿不到登录后代码与端点表。
- ★ **钩子要同时 patch XHR**: 相当多 SPA 的业务请求走 XHR（axios 的 XHR adapter / 自研），只钩 `fetch` 会得到「零业务请求」而 `performance.getEntriesByType('resource')` 里明明有 ⇒ **别读成「前端没发请求 / 端点不在本页」**，先补 XHR 钩子（open/send/setRequestHeader）再复现。
- ★ **钩子必须在文档加载前注入**: 用 `Page.addScriptToEvaluateOnNewDocument(source=...)` 装钩子再 `Page.reload()`; 在页面里临时 `t.ev` 打补丁的钩子**一刷新全丢**, 之后捕获到的是"零业务请求"。
- ★ **小程序页「零业务请求」先补运行环境垫片**: TG mini app 在普通浏览器里能渲染但**一条请求都不发**时,先注入 `window.Telegram.WebApp` 垫片(`initData`/`initDataUnsafe`/`ready()`/`expand()`)并重载再谈其他 —— 缺 WebApp 上下文时 SDK 直接不启动。判据:注入前 0 请求、注入后有请求 ⇒ 不是「前端不发请求」。
- ★ **`setRequestHeader` 早于 `send`**: 只在 `send` 里记日志 ⇒ 捕获到的请求模板**头全是空的**(后续照抄模板的请求整齐 403, 而你看不出原因)。正确: `open` 里建 `this.__hd={}`, `setRequestHeader` 里 `this.__hd[k]=v`, `send` 里连 `__hd` 一起 push。
- ★ **注入脚本里一个语法错 = 读到上一轮的陈旧值**: IIFE 抛异常时结果全局变量**保持旧值**, 于是整批响应"一模一样"而你毫无察觉(实测把上一轮的旧响应当成新结果解读了整批)。铁律: 每批前 `window.__R='PENDING'` 复位 + **先发控制组并断言 200**, 控制组不过即宣告本轮无效, 不得解读结论。
- ★ **端点先做来源归属核验再当情报**: 把路径在「目标自身 bundle」与「我自己的脚本/产物」之间分类统计; 只出现在我自己产物里的路径是**早期枚举脚本猜出来的**, 端点并不存在(实测 178 个此类路径在目标 bundle 里 0 命中)。把 404 读成「接口被禁用」之前先做这一步。
- ★ **同码不变也可能是"我打错层"而非前置闸门**: 先把「本站对该路径有响应」与「该路径存在」分开取证(不同 HTTP 方法打同路径 / 换 vhost), 再谈绕过。
- ★ **通配规则会吃掉同族字面路径 ⇒ 存在的端点被误判成不存在**: `/x/filter`、`/x/full` 这类字面路径会被 `/x/{id}` 匹配(id="filter")
  ⇒ 回的是**那条通配规则的**方法集(405 + `Allow: PUT, DELETE`)或**业务 JSON 404**(而非框架默认 HTML 页)。判据两条:
  ① 看响应体是框架默认页还是**业务 JSON**(后者 = 已被业务路由接住,不是路由不存在);
  ② **`OPTIONS`/405 读 `Allow` 头**, 字面路径与 id 形态路径各读一次, 再**按 Allow 里的方法各打一发**(路由常只在某个方法下才回业务错误)。
  真路径一律从**调用点**取全, 别按语义猜: 实测语义猜的 `/signuper/filter` 被 `/signuper/{id}` 整个吞掉, 真端点是 `/task/{id}/signuper/filter`(POST-only)。
  ⇒ 由此得到一张**真实路由表**(路径 × 方法 × Allow), 比路径词典枚举便宜且不会漏掉 method-only 的端点。
- ★ **UI 驱动 + 懒加载 chunk = 一步拿「端点 + 全部字段名」**（比全量 grep 主包省轮次）：驱动 SPA 路由到目标功能页 → 从 `performance.getEntriesByType('resource')` 取该路由的 chunk（`/js/<功能名>-<hash>.js`，功能名清单在 `__vite__mapDeps`）→ 抠出提交函数里的**实参对象字面量**（字段名与语义一次到手）→ 回主包按 `export{a as X}` 映射定位端点常量。
  ★ **功能模块名从「活页面的 response 日志」收集，别只信 index 里解析出的 chunk 清单（会不全）**：Vue composable 常按功能命名 `use<Domain>-<hash>.js`（`useRegister` / `useCheckout` / `usePayment`），**名字即用途** ⇒ 抓到名后按名直取 `/assets/<name>-<hash>.js`，请求体字面量就在里面（形如 `sendVerifyCode({email, purpose, captcha_payload})`）。
- ★ **服务端字段校验文案 = 免费进度条**：空体 → `<字段>不能为空`；补全字段但缺前置状态 → 前置类文案（如「支付密码尚未设置过」）；补齐前置 → 资金/风控类文案 ⇒ 四层闸门一目了然，不用猜。但**字段名仍必须从调用点取**，文案只告诉你缺什么。
- ★★ **加密凭证字段在阶梯上多两层,且探针必须是「自加密密文」**: 密码/凭证字段被前端加密的接口, 校验顺序 = `解密层`(「密码解密失败」= 服务端已在解密) → `格式层`(「密码格式错误」= 解密前的格式校验; 平文/乱串都停此层) → `字段层`(「请输入正确的11位手机号码」类 = 该字段值为空 ⇒ **字段名没对上**) → `用户层`(密码错误/次数超限/门禁)。⇒ 平文探这类接口**整轮假阴性**(永远到不了解密层): 先把前端加密复刻成可复用模块(加密+解密双向), 再用**自加密的合法密文**当载荷。
  ★★★ **反向同样成立 —— 源码证明明文透传时，别去造加密器：服务端行为却像在解密密文 = 契约矛盾，判该面口令层结构性不可达，收线。**
  实测：全量分片 grep 后该字段定义只有 `{email,pwd}` 一项、**零变换**（无拦截器、无字段级加密、平行「加密版」方法都调用不到），
  而服务端对同一字段分两级报错（**非合法 base64** = 格式层 / **已解密但值不符** = 比对层）⇒ 服务端在 base64→RSA 解密，客户端却发明文。
  两者不可能同时为真 ⇒ **服务端存的值 ≠ 客户端发出去的值**（该账号及同机制下的全部自建号都登不上），此时改客户端没有意义，换面。
  代价形态：把它读成「客户端加密还没复刻」去写加密器，就是「同码不变就继续喷涂」的变体，白烧整轮；**契约矛盾本身就是一条结论，不是待修的缺口**。
- ★★ **同一 App 内字段名【不跨端点复用】—— 每个端点的键名只认它自己的调用点**: 实测同一平台的 `addAgent` 用 `drawpwd`、而 `security/google/create` 要的是 `paymentPassword`;
  拿已命中的 `drawpwd` 去推隔壁端点 ⇒ 恒回同一句「支付密码不为空」(服务端只认精确键, 你把候选名一个一个试都只会加深"这里需要密码"的错觉), 而回调用点读一次对象字面量即过。
  做法: 先定位 **API 层模块**(形如 `c=(e,t)=>o("/app/x/y",e,t); export{p as b,c as d,...}` 的一张导出别名表), 用它拿到 `别名→路径` 全表;
  再对**承载该功能的那一个页面 chunk** grep 别名的调用点(`Ne({...})`), 读它传的实参对象 ⇒ 该端点专属键名 + 伴随字段一次到手。
  ★ **主包只含 API 定义(无调用点)时的取法见 `references/webpack-chunk-mining.md` §8**: 反查「承载端点的 API 模块 id」时**回溯窗口要小**(±1.2KB) —— 开大到十几 KB 会先命中资源映射表里的 4-hex **资产 id**, 拿假 id 去 grep 导入者**全 0 命中**, 白一轮。导入者按赋值形态 `var = X("<id>")` 找(**模块内部**的 require 形参名不会出现在导入者里, 用它 grep 必 0); 调用点正则必须容忍 `]` 与 `(` 之间的 `)`(Vue-CLI 的 `(0,c["k"])({...})`) —— 写成 `\["k"\]\s*\(` 会**全 0 命中**。
  ⇒ 推论: **"这个平台用 X 作密码字段"是伪知识**; 平台的键名表 = 端点粒度, 不跨端点、不跨端(管理端/钱包端各一套)。
- ★★ **自我 2FA 重置路径先验「当前绑定态」+「unbind 端点是否存在」, 否则是死锁**: 想靠"重置我自己的谷歌密钥 ⇒ 自算 TOTP"通关时,
  先读状态端点的 `*Bound`/`*Enabled` 字段: 若**已绑(secret 未知)**, 生成式端点通常直接拒(`已绑定，不可重复创建`), 而解绑/关闭端点又要**那个你不知道的验证码** ⇒
  **自控 TOTP 结构性不可达**(实测该族仅有 status/create/bind/enable/disable 五个, 无 reset/unbind ⇒ 整条路判死)。
  判死依据是**端点全集**而非单点报错: 先把该功能族的全部端点列出来数一遍, 确认没有 reset/unbind 再收线, 别反复试 create 的参数名。
  ★★ **Go/Gin 后端：空体一发就给你整张必填表，且文案用结构体字段名（首字母大写 `Email 不能为空`）而 JSON tag 是小写 snake_case** ⇒ 逐字段补、文案会依次点名下一个；键名按小写送、照文案读，别把大小写差异当「字段不存在」。
  ★★ **闸门顺序决定 A/B 结论是否成立**：前置闸门（格式/验证码/条款勾选）排在你要测的那一层之前时，前置未过 ⇒ **后一层根本没执行**，此时的失败对它**零信息量**（实测拿「请先完成验证码」去推「邮箱白名单是服务端强制的」= 纯误判）。测试顺序 = 先让前置闸门当场通过，再看文案落在哪一层。
  ★ **一次性凭证（turnstile / 一次性票据 / 图片验证码）单次消耗，且常按动作分场景**（`scenes.<动作>`）⇒ N 发对照测试要 **N 个独立 token**，每发现取；复用同一 token 的第二发一律假阴性。
- ★ **「值一变、文案就变」不等于该参数被读到 —— 先排除客户端行为**: 值里含 `../`、`file://` 时,
  前端 URL 规范化/请求构造会先失败并产出"网络连接失败"类文案, **服务端根本没收到这条请求**;
  据此断言"服务端拿去发起了连接 / 存在 SSRF"是纯误判, 且会白开一条不存在的攻击面。
  三条判据并行: ① 同批其它请求是否照常(客户端问题会成片出现); ② 换**同类特殊字符但语义无关**的值是否同样切换;
  ③ **换纯 HTTP(S) URL 若回到基线文案 ⇒ 该参数名根本没被读取 = 判未命中**。
- ★ **全部候选名回同一条通用文案 = 参数名全错, 立即停手**: 服务端对未知参数**静默丢弃**后抛内部异常,
  所以"加 body / 换值 / 换方法"都无信号 ⇒ 回去读 bundle(见铁律 2), 不要继续喷涂。
- ★ **包装器函数反推 method 与参数位**: bundle 里成对的封装 `const u=(e,t,n={})=>P({method:'get',url:e,params:t,...n})` / `const _=(e,t,n={})=>P({method:'post',url:e,data:t,...n})` ⇒ **每个端点的 method 与「参数走 query 还是 body」由调用它的那个包装器决定**,读一眼包装器就能给整张端点表标上 method,不必逐个试;顺手把**豁免清单数组**(如免加密白名单 `ut=[...]`)一起抄下来。
- ★ **端点字面量可能被编码包一层**: 常量表里的路径可能是 `atob(...)`/自定义解码后的串,**别把不可读串当乱码丢掉** —— 先解码再当路径;也可直接 grep 路径前缀(`/app/`、`/api/`)反查调用点。
- ★ **页面 chunk 只给字段、URL 在共享模块里 —— 先追 import 链再报「全端点表」**: 功能页的请求常经共享模块发出(`import{r as p}from"./system_options-<hash>.js"`),URL 字面量全在被引模块;只扫页面 chunk 的 URL 正则必漏(实测功能页只贡献 `activity_*` 字段名,`admin/system/activity` 这类 URL 藏在共享模块)。做法: ① 从页面 chunk 抠 `import\{...\}from"..."` 列出被引模块; ② 逐模块抠字符串字面量找 `admin/`、`/api/` 前缀; ③ 端点表 = 页面 chunk 字段 ∪ 共享模块 URL,两半都收 —— 只做一半会把「没找到」误写成「不存在」。
- ★ **中文 UI 词典 = 功能面完整性上界(收尾找漏测端点的最后一张网)**: 对全部落盘 chunk 扫中文串(2–24 字)按功能词聚合(管理/卡/订单/充值/活动/日志/导出/标签…),得到功能清单后逐项反查对应端点,查无对应的拿候选路径发一发判层(404 路由不存在 vs 401/405 存在)。它能支撑「UI 全部功能均有对应鉴权路由 = 零遗漏入口」的完整性声明。先按体积/串数筛文件: 几 KB 的 `*-text-*.js` 常是文本工具组件而非功能文件,别按文件名硬读; 功能串散在各页面 chunk。
- ★★ **先查本地源码海有没有全套 page chunk, 再谈在线抓**: 线上入口 HTML 可能只引用 vendor chunk(实测 `/open/index.html` 只列 `chunk-elementUI`/`chunk-libs`, 页面 chunk 名在别处 ⇒ 在线抓不到)。源码海/本地副本的 `public/<app>/js/` 往往就是**全套页面 chunk**(实测 137 个) ⇒ **离线 grep 一次拿到 73 条真 API 路径**。线上/本地 hash 不同时契约以线上为准, 但路径命名几乎不变(实测离线取的 `/admin/open/check`、`/admin/open/payment` 线上直接命中) ⇒ 离线取候选集 + 线上逐条验, 比在线解析 chunk 映射便宜一个数量级。
- ★★ **DB 权限表 ≠ 路由表, 不能拿来猜 URL**: `admin_auth_rule.url`(权限 mark) 与线上真路由是两套东西 —— 实测 dev 权限表 717 条(PascalCase 两段式 `admin/Payment/index`)+32 条 +44 变体打线上**全 `10005 当前访问路由未定义或不匹配`**; 而 chunk 里的相对路径(`open/check`、`open/payment`)配 `/admin/` 前缀**全命中**。ThinkPHP `url_route_must=true` 时路由来自代码, 一律**从调用点取**, 不要从权限表/菜单 mark 推导。
- ★ **两条可用 oracle**: ① `类不存在: \\ns\\<module>\\controller\\<Name>` ⇒ 路由前缀已命中、控制器/类名不对(可枚举类名); ② `explode() expects parameter 2 to be string, null given`(500) ⇒ 参数缺失触发的真 PHP 报错 ⇒ 无鉴权参数/注入面。
- **别拿压缩后的 chunk URL 模板当映射**: `"e"+"."+{...}[e]+".js"` 形态多变易 0 命中, 直接正则映射表本身最稳。
- **抓到的 chunk 数 < 映射表条数属正常**(含样式/异步块), 以实际 200 的为准。
- **未授权存在性 oracle 的两种形态要分开判**: 回显入参的 `<实体><你送的id>不存在` = 免鉴权枚举面(成果, 可入报告); `<实体>null不存在` = 必填字段没解出来(待修的参数问题), **不代表业务逻辑拦住了你**。
- **前端硬编码加密密钥的识别**: `key: location.href.indexOf("https://<host>")>-1 ? "<hexA>" : "<hexB>"` + `AES.encrypt/decrypt(...,{iv:"",mode:ECB,padding:Pkcs7})` = 按域名切换的硬编码 AES 密钥。代码中出现 `decrypt(n.<field>)` 即证明**服务端下发的该字段就是这枚密钥的密文**(抓到即可本地解, 高价值发现)。与 CryptoJS 默认 base64 输出等价的复现: `openssl enc -aes-128-ecb -K <hex> -nosalt -base64`(默认 PKCS7 填充)。
- 契约拿到后仍进不去时, 先换宿主/环境复用同一契约(测试环境的 nonce/校验往往更松), 再考虑其他面 —— 不要回头继续猜字段名。
  ★ **同族白标站群是这条的最佳落点**: 同一源站/同一后端上常挂着一批**同构站**(命名族形如 `int.<品牌><NN>`、兄弟 `int.<品牌2><NN>`),
  契约与后端常共用而**各站配置松紧不一** ⇒ 一台被指纹/签名闸挡死时, 拿同一份契约横向打同族另一台, 比继续磨当前站便宜一个量级。
  扩族手段: 对已知源站 IP 做测绘反查, 一次拿到同 IP 的全部域名(见空间测绘类技能), 并留意**同族站的静态站域名往往另起一个短域**。
- **主包里的路由表可能只是壳**（`/`、`/xxx`、`/:pathMatch(.*)*`），功能路由**运行期动态注册**（`router.getRoutes()` 查名、`startAppRouter` 之类按 `?startapp=` 分派）⇒ 别把主包路由表当功能清单；功能清单在 `__vite__mapDeps` 或那个动态注册器里。
- **路由参数校验器 = ID 格式规范**: 动态注册器里的校验函数（形如 `if(!/^\d+$/.test(e)) return null`）直接给出 ID 字面格式（纯数字 ⇒ 可枚举；带前缀 ⇒ 得从别处取）与别名路由名；先读它再决定枚举策略，别拿错误格式连打、然后拿恒定空响应当"目标没这个对象"。
  ★★ **但同一个 bundle 里可能同时存在多套校验器/多个 ID 通道，别拿一套当全局格式**: 实测 App 侧 `ucode` 是 `^\d+$`，而深链 `startapp/tgWebAppStartParam` 侧走 `/^[a-zA-Z0-9_]{5,32}$/` ⇒ 用数字正则去卡字母数字 id 会在**本地**把合法 id 判死（连请求都发不出去）。读校验器时连**它挂在哪个输入通道上**一起读。
  ★ **校验器只在 bundle 里，另有 id 只存在于数据里 ⇒ 拿错命名空间的「整齐不存在」不是判死**: 同一实体常并存**导出里的 9 位数字字段**与**API 路径用的定宽 base36 短串**，两者是不同的键（实测按数字版枚举 `/signuper/{id}`，整批整齐回同一句「不存在」，换真短串 id 后同族口立刻 200）。
  真样本的最便宜来源是**自己已落盘的导出/历史响应**: 子对象表几乎总显式带 `xx_id` 列, grep 即得宽度/字符集/前缀, 别先写枚举脚本。判读纪律: **同一句「不存在」覆盖整批 ≠ 该面关闭**, 先核 id 命名空间再决定是否判死。
- ★ **路径变量端点：URL 字面量被 `${}` 切开，按前缀 grep**。形如 `Du=(e,t)=>GET \`/app/merchant/info/${e}\`、`Uu=(e,t)=>GET \`/app/merchant/balance/${e}\`` 的调用：
  ① 直接 grep 完整路径会漏（模板串被切碎）⇒ 改成 grep **斜杠前的前缀**（`/app/merchant/info`），再读旁边的正则校验器；
  ② 得到的是**路径变量契约**（`/端点/<id>`），把它写成 query/body 形状会回 404 或笼统参数错 ⇒ 会误读成「码无效」，实际是形状错（与「格式错 vs 不存在是两种响应」配合使用）。
- ★ **调用点集 = 后端「客户端可见面」的上界 ⇒ 拿它当封口依据**。提取时用 `\$\{[A-Za-z_$]{1,4}\}/` 抽**全部模板串**、与 base 常量拼回，再与每个 chunk 里的 `request(`/`urlName` 调用点取并集去重 —— 数出来的条数就是客户端会打的后端面（实测一个 Mini App 恰好 5 条）。
  这个数有两个用途：① 与历史轮次/其它产物数出的条数**一致 ⇒ 写「已封口（k 条）」**，停止对后端做路径词典枚举（边际收益为 0）；
  ② **不一致 ⇒ 说明还有 chunk 没抓全**，回去补抓，不要下「后端没这个功能」的结论。
- **签名带参 ≠ 支持改参(BOLA)**: 运行期送一个他人 id，若回包与你自己的记录**字节相同** ⇒ 会话绑定、入参被忽略，不要当 IDOR 原语上报。只有 bundle 里读出「标识取自 URL query / 请求入参」才是越权面（读调用点即可判死，比发请求便宜）。
  ★**退出条件(避免白烧轮次)**: 换过 **≥3 种语义不同的参数名/位置**（query / path / body 各至少一种）后响应**恒回你自己的身份** ⇒ 判定 **self-scoped 并停手**,不要再继续列候选名（实测在 `getUserPair` 上白烧整轮：任何名/值都只回 `{usertype,ucode=<自己>}`）。
- **抓 bundle 必须分片**: 大文件单次 GET 会被截断(cap), 用 `Range: bytes=N-M` 循环抓全再 grep;
  落盘名保留 `.js` 后缀, 否则后续 glob/ripgrep 漏命中。
- ★ **chunk 可能是 gzip 传输 ⇒ 直接 curl 抓到的是压缩二进制, grep 在整包上静默 0 命中**:
  服务端常不问你 `Accept-Encoding` 也回 `Content-Encoding: gzip`, 于是 grep 回空,
  而你会把「主包只有 5 条端点」当成事实(实测首轮全表空, 同一文件加 `--compressed` 后立刻榨出端点表)。
  判据 = 落盘首两字节 `\x1f\x8b`; 修法 = `curl --compressed`(或 `gunzip -c f > f.js`)。
  **凡「文件非空但 grep 零命中」, 先验它是不是压缩/二进制, 再谈符号存在性。**
- ★ **成功码从 bundle 读, 不要默认 200**: 同站不同 app 可以不同(实测一个 app `if(code===1)` 成功、另一个 `code===200` 成功)
  ⇒ 拿 HTTP 200 / `code:200` 通杀会把「真成功」判成失败、把「业务失败」判成成功。
  grep 调用点旁的 `===1` / `===200` / `switch(code){case...}` 一次定死。
- ★ **判死端点前必须回读调用点复核参数形状, 否则「参数错」会被写成「面已关闭」**:
  按 REST 习惯送 `page`/`limit`, 服务端回笼统业务文案(实测「商品不存在」「参数错误」) ⇒ 极易记成「该面已证伪」;
  而调用点实参是 `{goods_key, current, pageSize}` ⇒ 换形状后立刻得到**语义正确的**新文案(「商品未开启选号」= 参数已过闸、只是对象属性不符 ⇒ **换对象再打**, 不是关面)。
  ⇒ **两类拒绝长得一样, 只有回读调用点能区分**; 被写进「已判死」清单的端点, 复活成本远低于新开一个面。
- ★ **单行 minified bundle: 上下文窗口 grep 可能整批静默回空 —— 存在性用 `grep -ac`, 上下文用字节偏移开窗**:
  `grep -oE '.{140}pat.{140}'` 这类窗口正则在**大单行文件**上会因窗口越界/locale/实现细节**整批空**,
  而 `grep -ac 'pat' f` 明明有命中(实测 ~400KB 单行 bundle 上整批 ctx 段全空、偏移法一次解得)
  ⇒ **不要拿上下文 grep 的空结果当「符号不存在」**。取上下文: `grep -aob 'pat' f | cut -d: -f1` 拿字节偏移 →
  逐个开窗 `tail -c +$((off-200)) f | head -c 500`(`tail -c +N` 从 1 起算, 确保 off-200 ≥ 1; 一次开全部命中点的窗再筛)。
- **流程码的语义在 JS 里**: `switch(e.data.code){case"10004":case"10013":…}` 直接给出二次验证/跳转失败等分支含义
  ⇒ 把"未知错误码"变成状态机, 比反复试参数快; 缺了这段只能靠猜。
- **账号/租户格式常被日志语句泄露**: `console.log(u.indexOf("@<域后缀>"))` ⇒ 账号 = `xxx@<域后缀>`;
  同处的 `localStorage["<sys>-userInfo"]` + 角色映射(`{1:["admin"],2:["normalUser"]}`) = 前端权限模型。
  改它只影响前端菜单, **后端权限仍在** —— 记为提权面, 不得当成已提权上报。
- **免鉴权端点返回的"配置类数据"是扩面入口**: 客服/跳转/密钥分配类接口的响应里常带**同主体的新域名**
  (含仅 DNS 可见的内网主机) ⇒ 立刻对新域做子域枚举, 常比继续磨当前面收益大得多。

- ★ **格式闸封死比对层 ⇒ 该端点上的注入/爆破结构性无效（别写成「无此漏洞」）**: 同一端点喂两类值读校验顺序 ——
  格式非法值(`' or '1'='1` / `null` / 数组 / 布尔 / 超长超短)回 `…格式不正确` ⇒ 卡在**格式层**;
  格式合法值(`"undefined"` / `123456` / `aaaaaaaa`)回 `…次数过多` ⇒ 已过格式层、卡在**计数/锁定层** ⇒ **比对层根本不执行**。
  ⇒ 结论写「**被前置格式闸封死**」(后续动作 = 换字段/换端点), 不写「**不存在该漏洞**」(那才是关面) —— 两者后续动作完全不同。
  ⇒ 格式层存在还说明比对面在**规范化后的字符串**上做 ⇒ `0`/`null`/`true`/数组这类类型混淆在此端点打不动, 别反复试。
- ★ **计数/锁定层是全域共享的一次性预算**: 一旦摸到「次数过多」立即停手并记录 —— 该账号在这一族端点上的正确口令比对已打不到, 再发任何载荷都是纯白耗。
  (实测代价: 按**错误字段名**做的整轮 SQLi/绕过矩阵先已消耗计数并全部作废, 读会调用点拿到正确字段名后才发现计数早锁死。)
- ★ **参数名本身可能被 WAF 记账**: 实测小写 `suid=<值>` 在 query 里被拦(`Failed to fetch`), 而 **`Suid=` / `SUID=` / `suId=` / `suid%20=` / 放进 POST body** 全部放行并到达业务层。
  ⇒ 参数「送不进去」时先做**大小写 × 分隔符 × 参数位置**矩阵, 再怀疑鉴权或参数名错。
  ⇒ 反情报: **WAF 专门拦某个参数名 = 该参数就是鉴权/敏感位**。
- ★ **「加个凭证位就返回成功」先跑垃圾凭证负对照**: 网关只判凭证位非空即放行时, 真/假凭证回同一句成功 ⇒ 易误判「共享会话 / 鉴权绕过」。判据三件套与撤回纪律见 `pentest-finding-verification` 的「成功壳 / 安抚剂」Pitfall。

## 交付
- **参数名照抄调用点实参，连同大小写**: 同一路由写 `?orderid=&fileid=`(小写)，按 REST 习惯写成 `fileId` ⇒ 服务端落进"统一异常"分支回笼统文案(`发生异常，请联系客服`)，极易误判成"接口废弃/路由不存在"而弃面。**判路由是否真存在 = 换 HTTP 方法打同一路径**: `POST` 回 `Request method 'POST' not supported` ⇒ 路由真存在、GET 才对; 路由不存在时两种方法回的是同一 404/框架默认体。
- **对象标识的"来源"就是 IDOR 判据(读调用点即可判，不必真发请求)**: 标识取自 **URL query**(`v.query.ucode || v.query.startapp || v.query.tgWebAppStartParam`)而非会话/接口 ⇒ `#/<面板>?ucode=<他人>` 即换对象，后端不校验归属就是现成 IDOR 原语; 标识来自 `getUserPair()`/登录态 ⇒ 天然免疫。先把这条在 bundle 里判死，再去取有效 ID。
- 每个端点的**真实载荷对象字面量** + 阶段跳变的错误码对照贴进战报。
- 同一份 initData/一次性票据**只能握手一次**:多形态扫描若共用一份,除第一发外**全是假阴性**(handler 侧消费掉就拒)。要么逐发重铸,要么先看握手层是否已拒,别把假阴性写成「目标防住了」。
- ★ **会话 TTL 短到「人类不可能在环」**:带挑战(图像点选/滑块)的端点实测 `open` 后 ~60–75s 即 `会话已失效` ⇒ **握手 → 建会话 → 过挑战 → 领奖必须同一进程一气跑完**,且**答案必须在进程内自己算**(挑战图按形状匹配、颜色被服务端随机化 ⇒ 见 `captcha-gated-api-claim-chain` 的 `scripts/seg_solve.py`)。人机分跑(先存 session_id 稍后再用)必失败。
