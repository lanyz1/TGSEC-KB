# 服务端清洗器指纹化 → 载体选择 → 载体生命周期

配套 `payload-execution-verification` 的铁律 10/11/12。用于「写进去了、也过 WAF、但浏览器不执行」这一类。

## 1. 指纹化流程（先做，别先改载荷）

1. 发一条**可区分**的载荷：每个变体带唯一标记（`M1`/`M2`…），一次写完批量回读。
2. 回读**逐字节**与原文 diff，输出三类：`完整保留` / `被删` / `被改写`。
3. 只根据「被改写的那几个字符」定规则，再选载体；对比表如下。

## 2. 规则 → 载体决策表

| 清洗器行为（回读实测） | 含义 | 可用的载体 |
|---|---|---|
| `<script>…</script>` 整体消失（属性留空串） | 按字面 token 剥标签 | `<iframe srcdoc='&lt;script&gt;…&lt;/script&gt;'>` 实体走私；或纯属性型 JavaScript URL |
| `on<字母>` 变 `οn…`（希腊 U+03BF） | `on*` 事件处理器被判危险 | 放弃所有 `on*`；改用 `srcdoc`/`javascript:`/`<svg>` 内嵌等**非事件**执行面 |
| 属性名照旧存活 | 只查标签与事件 | `srcdoc`、`src`、`data-*`、`style` |
| 实体（`&lt;`/`&#60;`）原样存库 | 不清洗实体 | 一律用实体写敏感 token |
| 反斜杠原样存库 | HTML 层不解码 `\x27` | JS 字符串里单引号写 `\x27` |

要点：**过滤匹配的是字面 token，不是语义** ⇒ 任何「被拦的 token」都先试它的实体/大小写/嵌套近似形态，而不是换个洞。

## 3. 实体编码走私（`srcdoc` 形态）

```html
<iframe srcdoc='&lt;script&gt;…&lt;/script&gt;'></iframe>
```

- 存库字节里**没有** `script`/`on*` 字面量 ⇒ 过字面清洗器；WAF 层同理（非 chunked body 含字面量 `script` 会被 403）。
- 浏览器解析 `srcdoc` 属性值时会**解码字符引用**，于是 `<script>` 在 iframe 内真正生成并执行。
- iframe 与宿主**同源** ⇒ 载荷可 `parent.document.cookie` / `parent.localStorage` / `parent.fetch`（原生同源 fetch，不受 mixed content 影响，可回写自家对象当外带槽）。
- 自证时**记住上下文**：`parent.__x=1` 外层读得到才算 fire（只写 `window.__x` 会得到假阴性）。
- 属性值用**单引号**包裹：内层 JS 里的字符串常量改用双引号或 `\x27`，避免提前闭合。

## 4. 载体生命周期（被删之后）

1. **确认删除**：list 全空 + 回收站空 + 自己的读路径报「不存在」。
2. **找插入路径**：无 create/add 端点时，**保存/更新端点带不存在（或不带）id 往往就是 INSERT**；返回体里带新 `id`/`key` 即成立。
3. **补必填字段（错误阶梯）**：业务文案 `分类未选择` ⇒ 先建分类拿 id；再补 ⇒ `HTTP 500` 框架错误页 = 还缺必填（如 `goods_key`）；再补类型正确的枚举（`goods_type:"card"` 不是 `1`）与嵌套对象（`extend:{}`）⇒ 通过。
4. **同一发把载荷写进目标字段**，再回读校验实体形态是否存活。
5. **落库后读不回 ≠ 失败**：待审核态对商户/自己不可见、只在管理端队列 ⇒ 判据是写入响应里的 id。
6. **收线清单**：新建的对象（商品/分类/条目）、写入的联系方式/参数、迁移任务，全部登记为待还原项（客户要求无痕）。
