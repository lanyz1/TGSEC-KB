# API 用户面批量收割（App / 白标家族）

适用：目标的**物理库不可达**（in-cluster MySQL、公网只开 80/443、运营商钥匙全不通），但**客户端 API 面可达**。
目标 = 用**用户自己那套会话**把「用户信息 + 上线下级关系」成规模搬出来，而不是死磕数据库。

用户口径（硬）：只认**全部** —— 抽样/子集等于没拿到；报数前先算**覆盖率与天花板**；要的是**用户信息 + 上线关系**，不要媒体/内容面。

## 1. 侦察：把「域名」和「出口」都当成可轮换资源

- 从 repo / 配置 / H5 bundle / 兄弟品牌存量库里枚举**全部 API 域名**（同一后端常挂 3~4 个品牌域 + 几十个白标站）。
- 出口清单三类：自有云主机（可 `ssh -D` 做 SOCKS）、本机多源 IP（`curl --interface`）、**目标自己的机器**（拿下任一运营方主机后当出口）。
- 不要假设「同一批出口对所有域名等价」——逐对测，见 §2。

## 2. 通道矩阵 + 健康门（吞吐的最大杠杆）

**WAF 的封禁粒度是 (源 IP × 域名)，不是源 IP。** 被封 IP 换到同一后端的另一个品牌域常常直接 200。

1. 组 `出口 × 域名` 矩阵 → N 条通道。
2. 开跑前用**最便宜的接口**（通常是 captcha）逐组合验活，**只留返回 200 的通道**。
3. 运行时：403 自动翻域；同一通道连续两次 403 进冷却；全局 GAP 限速。
4. **「验证码取不到 / 参数为空」的一大半来自死通道（567 限流、隧道掉线），不是 OCR。** 实测把死通道剔掉后失败率从 60.9% 直接归零。先量通道成功率，再谈识别率。
5. 最省事的一条通道：**用目标自己的机器当出口** —— 它自己的 IP 打自己的 API 通常在白名单里，也不吃自建 WAF 的地域规则。

## 3. 登录三态预言机 + 两段式跑

- `RECORD_NOT_FOUND`（账号不存在）→ **立刻放弃该号**，不为它试第二个口令。试验池里 95%+ 是不存在的号，早退是最大的吞吐来源。
- 「口令错误」→ 账号**存在**，可换口令继续（进存在清单）。
- 禁用/冻结 → 存在但停用，单独记账。
- **两段式**：枚举阶段每账号只发 captcha + login 两个请求（FAST 模式），命中后再补拉数据面；比「每个号一次性拉全字段」快数倍。
- 验证码**单次有效**：一次提交消耗一个验证码，失败必须整对重取。复用旧验证码会刷出一片「验证码错误」，让人误判成口令错。

## 4. 口令字典：优先用运营方自己的

- 家族存量库里常有一张「**哈希 → 明文口令**」对照表 → 直接导成**群体高频口令**字典，命中率远高于通用字典（拿到的都是他们的家族习惯口令）。
- **加盐库别烧时间**：用户表带 `salt` 列时口令是 `md5(明文 + salt)`，那张明文对照表反查不了这批哈希。
- 只打 1~2 个主力口令就能覆盖大多数，且能把速度提数倍。

## 5. 命中率完整性（这条最容易被自己骗）

- **「对象不存在」不能计成成功**：只有解析出的会话/JWT 非空、且错误字段为空，才计 +1；凡 `_err`/`reason` 有值一律算失败。实测把「号不存在」计成成功后，日志「成功 1327」对应的真实命中只有 ~1.5%（虚高 60 倍）。
- 交付前用**落盘产物**复核计数（`grep -l '"token"' raw/*.json | wc -l`），不要信进程内计数器或日志尾行。
- 报数前抽验命中样本是**真用户**（真实姓名 / 身份证 / 余额），别把假命中当战果交出去。

## 6. 脱敏 ≠ 只能拿脱敏：旁端口 / 旁服务探测

客户端接口返回 `idcard: 5102****5722` 不代表数据只能拿到脱敏版。**把同一个会话 token 打到同一 host 的其他端口 / 其他服务 / 其他路由前缀**，常能拿到**未脱敏**版本：字段多为 `show*` 前缀（`showIdcard` / `showUsername`），还常带借记卡全码。

- 做法：拿到任一有效会话后，先做一轮 `端口 × 路由前缀` 的**字段形态比对**（看有没有 `****`），命中再用同一批 token 全量重拉。
- 这一步往往是把「脱敏数据」升级成「完整 PII」的分水岭，**优先级高于继续扩号池**。
- 判定：同一路径在 A 端口返回脱敏、B 端口返回明文 = 你有两个面，别把 A 的结论当成全貌。

## 7. 拿不到「全量列表」接口时怎么算盘子大小

- 分类/社区**聚合接口**逐类返回成员数 → 相加即全平台总量，比单点仪表盘更抗「按周期重算瞬时归零」。
- 有「姓氏/地区人数普查」类接口时做第二口径互证。
- 分页参数被完全忽略（一个 token 只吐它自己那条）时那不是越权，直接改走聚合口径，别在分页上耗。

## 8. 运行纪律

- **杀进程用具体 PID，不要 `pkill -f <关键词>`** —— 自己的命令行含该关键词会自杀（SIGTERM 143）。
- 改了脚本**必须重启进程**，否则跑的还是旧代码。
- 日志同时记「出口 / 域名 / 错误码」，通道退化时才能回看是哪条。
- 长任务 `python3 -u` 无缓冲跑 + 结果落盘，进程被杀不丢结果。
- 并发拉高后全线报错 = 被限流，降并发 / 加 GAP / 翻域冷却，不要硬顶。

## 9. 交付形状

- 以人为主键出 CSV：手机号 / 真实姓名 / 完整身份证 / 社保卡号 / 银行卡号 / 上级标识；关系另出一张「上级 → 下级」边表。
- 原始响应留一份 `原始证据/`。
- 报告里写清**覆盖率与天花板**：已拿 N / 总量 M / 命中率 X% / 还差什么（哪把钥匙、哪条通道）。

## 10. 物理库可达时：别收割，直取全库

API 收割是「库不可达」时的替代品，覆盖率天然打折。**只要在代码/部署物里摸到库的凭据，就切到直取全库** —— 同一目标两条路常同时存在。先花十分钟找凭据，比多跑几万号划算；用户只认「全部」时，这条是唯一能满足的口径。

**凭据从哪来（按命中率排序）：**
- 部署仓库 / 挂盘源码里的 `config.env`、`docker-compose*.yml`、`*.py` 配置段 —— 明文 DB 口令、对象存储 AK/SK、**网页版库管理器地址与口令**常同在**一个文件**里，读一个文件等于打通两条通道。
- 家族/兄弟品牌存量库 → 同一套口令复用（配置里的 `SHARED_PASSWORD` 类字段常就是面板口令）。

**两条直取通道：**

| 通道 | 拿法 | 覆盖面 |
|---|---|---|
| 对象存储备份桶 | 配置里的 AK/SK → 列桶 → 找 `<品牌>/<库名>/mysql/` 备份前缀 → 下载 dump（`mysqlsh`/`dumpInstance` 产物） | 全库，含未脱敏列 |
| 网页/API 型库管理器 | 配置里的面板地址 + 口令 → 登录 → 列连接 → 跑只读 SQL | 全库 + **实时**（比最近一次备份新数小时） |

**库管理器 API 形态（DBX 类，实测）：**
1. `POST /api/auth/login {"password":"..."}` → 成功回 `{"ok":true}`，会话落在 **HttpOnly cookie**。
2. **HttpOnly cookie 必须用 `curl -c/-b <jar>` 走** —— Python 的 cookie 容器会把它丢掉，症状是「登录成功但后续全部 401」。
3. `GET /api/connection/list` → 连接清单（主库 / 从库 / 缓存 / etcd 常同时暴露，且多为 root）。
4. `POST /api/query/execute {"connectionId":"...","database":"...","sql":"..."}` → `{columns, rows, truncated}`。**请求体字段逐个补齐**：少 `database` 直接 422，报错只告诉你缺哪个字段，补齐再发。
5. 有从库/只读连接就**走从库取数**，别压主库。

**全量导出怎么跑（单次查询有行数上限，实测 1 万行）：**
- **keyset 分页**：`SELECT * FROM t WHERE <pk> > <last> ORDER BY <pk> LIMIT 10000`，**不要 `OFFSET`**（深分页拖垮对方库，自己也慢）。主键从 `information_schema.columns` 现取，别猜。
- 每表落 CSV + `zstd -6 -T0`；把每表最后主键写进状态文件，断点可续。
- **增量**：拿上次交付的截点时间，按 `created_at`/时间列只拉新行（几十万行级，几分钟出结果），比全量重拉省一个数量级。
- **没有时间列的表回退全量分页**：关系边表（「上级-下级」这类）常只有 id 对、没有 `created_at` —— **别静默跳过**，记一行日志后全量拉，否则交付里会整整缺一张关系表。

**先判定「哪个库是现役」再看数据新不新**：家族命名常是 `<品牌><建库日期>`（如 `brandname20260621`），库名里的日期是**建库日，不是数据截止日** —— 别凭字面判成旧库。用三条互证：线上库列表里是不是唯一业务库 + 自建号在不在里面 + 与备份批次行数对账。

## Pitfalls 速查

| 现象 | 真因 | 处置 |
|---|---|---|
| 扫了几万号 0 命中、代码不报错 | 传输层改动（base64 前缀长度变了 / data URL / 外层 200 内层 401） | 手工单号逐层打印中间串，见 `references/transport-and-decoding.md` |
| captcha 取不到、`login: null` | 死通道，不是 OCR | 先跑 `出口 × 域名` 健康检查 |
| 「成功」很多但用户不认 | 把「号不存在」计成成功 | 按 token 落盘产物计数（§5） |
| 全部端口都 403 | 封禁按 (IP × 域名) | 换品牌域 / 换出口 / 建矩阵（§2） |
| 喷后台登录没结果 | 那是**用户端**手机号登录，不是后台入口 | 先确认在打哪个面 |
| 交付被要求「全部」 | 抽样 = 没拿到 | 报覆盖率与天花板，说清还差什么 |

传输层细节（双层 base64 / AES 帧 / 验证码字段名 / 用真浏览器钩子取登录报文）见 `references/transport-and-decoding.md`。
