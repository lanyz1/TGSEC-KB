## 十、整数溢出、精度与边界值攻击

### 10.1 整数溢出

```
quantity=9999999999 * price=100 → 超 int64 溢出为负数/0
- int32 最大值：2,147,483,647
- int64 最大值：9,223,372,036,854,775,807

POST /order {"product_id":1,"quantity":2147483648}   → 溢出为负数
POST /transfer {"to":"x","amount":99999999999999999999} → 溢出为 0/负数
POST /order {"quantity":9223372036854775808}          → 回绕

测试技巧：
1. 临界值：MAX_VALUE、MAX_VALUE+1、MIN_VALUE、MIN_VALUE-1、0、-0
2. 四则运算触发溢出：qty*price、amount*fee_rate、balance+bonus
3. 类型提升：字符串数字 vs 整型（"2147483648" → 强转溢出）
4. 无符号/有符号混用：UINT32 边界 4294967295
```

### 10.2 浮点数精度

```
1. 0.1+0.2=0.30000000000000004 → 利用精度差做金额误差窃取
2. 金额用 float/double 而非 BigDecimal/分 → 精度攻击
3. 极小值：0.0000001、1e-9、1e-10 → 下溢为 0
4. 极大值：1e308、1e309（infinity）→ 溢出
5. 货币换算：分↔元↔万↔千分位 → 单位混淆（见 2.5）
6. 手续费/税率/汇率精度：四舍五入方向（truncate vs round vs ceil）→ 累积差
7. 大量小额订单 + truncate → 每次少收 0.001 → 黑产"压榨分"攻击
```

### 10.3 负数/零值/特殊值

```
quantity: -100 → 总价为负，反向加余额
quantity: 0   → 0 元下单 / 免费商品
price: -999   → 折扣滥用
discount: 100% → 0 元
amount: NaN/Infinity → 某些语言解析异常直接跳过校验
amount: "" / null / "null" → 类型转换分支差异
amount: "0e0" → 科学计数法绕过数值范围校验（0）
amount: "  0.01  " → 前导空格 → 字符串比较绕过
uuid: "00000000-0000-0000-0000-000000000000" → 空对象绕过
time: 0 / -1 / 9999999999999 → 时间戳边界（永久有效/已过期逻辑反转）
```
