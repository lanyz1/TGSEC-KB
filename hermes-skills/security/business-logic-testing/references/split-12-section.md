## 十一、信息泄露与数据遍历

### 11.1 数据遍历/枚举

```
1. 顺序递增 ID 遍历：
   订单号/用户ID/工单号/发票号/流水号 → 批量拉取他人数据
   GET /order/detail/1001 → 遍历 1001-2000
2. 手机号/邮箱枚举：
   注册接口"已存在"反馈；登录错误信息差异；邀请码/兑换码有效性反馈
3. UUIDv1 可预测（时间戳+MAC）；短 ID/雪花 ID 顺序性 → 遍历
4. 批量导出接口：/api/v1/export?type=users → 越权导出全量
5. GraphQL 批量查询（Alias 批量拉取）：{a:user(id:1){..} b:user(id:2){..}}
```

### 11.2 响应信息泄露

```
- 错误堆栈/SQL 错误信息 → 技术栈指纹 + 进一步注入
- 调试字段：debug=true、verbose 参数、X-Debug 头
- 内部 IP/域名/端口 → 内网拓扑
- 第三方 API 密钥/token 在响应或 JS 中
- 敏感字段未掩码：完整手机号/身份证/银行卡/地址
- 越权字段泄露：他人订单接口返回额外字段（内部成本价/利润/备注）
- IDOR 响应差异：返回 404 vs 403 vs 200 → 判断资源存在性（枚举放大器）
```

### 11.3 业务侧信道

```
1. 优惠券/兑换码有效性探测：错误信息区分"券不存在/已使用/已过期/不适用"
2. 登录侧信道：验证码校验错误 vs 密码错误 → 分离爆破
3. 注册侧信道：手机号是否已注册 → 用户枚举
4. 时间侧信道：资源存在时响应更快（先查库 vs 先判权限）→ 枚举资源
5. 错误码差异：1001=余额不足、1002=订单不存在 → 数据存在性判断

## 十二、AI 大模型结合（AI 辅助业务逻辑测试）

**定位区分**：第八章讲"AI/LLM 应用是攻击目标"（防御方视角的 AI 漏洞）；本章讲"用 AI 作为攻击工具"（进攻方视角的 AI 辅助测试）。两者结合 = 攻防 AI 化的完整闭环。

### 12.1 AI 辅助生成业务逻辑 fuzz 用例

```
1. 参数语义 fuzz 用例生成：
   给 LLM 一段接口参数清单（从 Swagger/抓包导出），让它生成业务语义 fuzz 用例：
   Prompt："以下订单接口参数：product_id(int)、quantity(int)、price(decimal)、coupon_code(string)、
   status(string)。请生成 30 个业务逻辑 fuzz 用例，重点覆盖：负数/零值/溢出/精度/类型混淆/
   状态枚举/并发重复字段/隐藏参数猜测，并标注每个用例期望发现的问题。"

2. 状态值字典生成：
   让 LLM 枚举常见业务状态词汇（paid/failed/cancelled/refunded/pending...）
   及中文系统状态值（已支付/待审核/已完成...），生成状态篡改测试字典

3. 隐藏参数挖掘：
   给 LLM 一段请求示例，让它推测可能被后端信任的隐藏参数
   （如 is_free、verified、balance、role、discount、skip_validation）

4. 回调参数猜测：
   让 LLM 生成第三方支付回调可能校验的参数组合（sign/md5/notify_type...）
   辅助回调伪造测试

5. 提示模板（可直接用）：
   "你是资深业务逻辑漏洞测试专家。以下是接口 {接口描述/参数表}。
   请输出：1) 可篡改参数清单及篡改值；2) 可跳过的步骤；3) 可并发的操作；
   4) 可越权的对象 ID；5) 每个测试点的预期异常响应特征。"
```

### 12.2 LLM 辅助理解业务状态机并发现缺失校验

```
1. 状态机提取：
   把业务文档/接口列表/抓包会话喂给 LLM，让它还原完整状态机
   （状态集合、合法转移、前置/后置条件、角色权限矩阵）

2. 缺失校验发现：
   Prompt："以下是订单状态转移规则：待支付→已支付(校验:金额匹配/已回调)、
   已支付→已发货(校验:管理员)。请找出所有缺失的校验点：哪些状态可被非法
   转移？哪些前置条件未校验？哪些转移缺少角色校验？并发下哪些检查-使用非原子？"
   → LLM 给出候选攻击面清单 → 人工验证

3. 攻击路径生成：
   "根据该状态机，找出从'普通用户'到'资金损失'的最短攻击链路径，
   要求每一步都只调用合法 API 且尽量不触发风控。"

4. 组合链建议：
   给 LLM 列出一组已发现的中低危逻辑问题（IDOR、验证码不失效、金额不回查），
   让它设计组合攻击链并评估最终危害等级

5. 注意事项：LLM 输出只作为假设来源，所有发现必须人工复现验证；
   把 LLM 视为"超级实习生"，提供思路，不直接采信。
```

### 12.3 AI 驱动竞态测试编排

```
1. 竞态点识别：
   给 LLM 描述业务接口，让它标记可能的"检查-使用"窗口
   （提示词："哪些操作存在'先查后改'的非原子序列？哪些限额/一次性检查可能被并发绕过？"）

2. 并发策略生成：
   让 LLM 根据接口特征（会话锁、锁粒度、缓存、负载均衡）推荐并发数、
   请求同步方式（HTTP/2 单包 vs 末字节同步）、绕过策略（多 session/多 IP）

3. Turbo Intruder 脚本生成：
   Prompt："生成一个 Turbo Intruder 脚本：对 /api/coupon/redeem 做多端点竞态，
   1 个生成请求 + 50 个兑换请求，使用 Engine.BURP2 + gate 机制。"
   → LLM 输出脚本 → 人工校验后执行

4. 结果分析：
   把竞态测试响应批量喂给 LLM，让它聚类分析"哪些响应特征表明竞态命中"
   （重复成功、状态码分布、错误差异）→ 快速定位可利用的碰撞

5. 编排自动化（进阶）：
   用 Python 脚本 + LLM API 实现"探测→分析→调整并发→再探测"的自动闭环，
   减少人工干预（注意控制请求量，避免触发风控/影响业务）。
```

### 12.4 大模型应用业务逻辑攻击面（AI 作为被测目标的交叉检查）

```
结合第八章的漏洞分类，AI 辅助还可以做：
1. 自动提示注入测试：用 LLM 批量生成/变体化提示注入 Payload
   （翻译、编码、角色扮演、越狱模板自动组合）
2. 间接注入内容投放：让 LLM 生成"看起来正常但含隐藏指令"的文档/评论
3. 工具调用边界探测：让 LLM 枚举 Agent 的工具能力并设计诱导调用链
4. 系统提示词提取变体：自动生成 50+ 种提示词提取问法
5. 结果侧信道分析：LLM 回答的细微差异 → 推断知识库内容/防护规则

重要：对 LLM 目标测试时要格外控制节奏与深度（模型提供方/业务方
通常对高并发提示注入有限流与封禁，且涉及合规风险，先确认授权范围）。
```

### 12.5 AI 辅助审计与报告

```
1. 代码审计辅助：把疑似有逻辑缺陷的后端代码片段给 LLM 做静态分析
   （无锁扣库存、信任前端金额、状态无校验）→ 快速定位问题代码行
2. 报告生成：按"前置条件→攻击步骤→影响→修复建议"自动起草
   中英文漏洞报告草稿 → 人工核验事实后提交
3. 修复方案复核：给出修复建议后让 LLM 评审（锁粒度/事务边界/幂等键
   是否真能防住对应攻击路径），避免"修复了但没修全"
4. 安全基线比对：把接口清单与 OWASP BLA/API Top 10 比对 → 输出差距清单
```

## 十五、修复建议

- **服务端重新计算**：价格/金额/折扣/运费/积分抵扣一律服务端按订单号回查数据库计算，绝不信任前端提交的数值
- **事务+锁**：余额/库存/券/积分操作使用数据库事务 + 行锁/乐观锁（version 字段）；Redis 用 Lua/原子命令保证"检查-使用"原子性
- **幂等性**：支付/退款/转账/兑换等关键接口支持幂等键（Idempotency-Key/UUID），服务端持久化去重（BLA1 防御核心）
- **状态机严格化**：用状态机库/枚举白名单强制合法转移，禁止跳步/回退；状态变更写审计日志
- **对象级授权**：每个 API 端点独立校验"当前用户是否有权操作该对象"（owner 条件进 SQL），不信任前端传入的 user_id
- **金额类型**：金额统一 BigDecimal/整数分，禁止 float/double；负数、零值、范围边界显式校验
- **验证码安全**：验证码绑定手机号+会话、一次性使用（校验即失效）、短过期、频率限制、防爆破（次数+延迟）
- **Token 安全**：重置 Token 绑定用户、随机不可预测、短过期、使用后失效、旧会话失效
- **签名与回调**：第三方支付回调严格验签 + 来源 IP 白名单 + 金额字段服务端回查 + 幂等去重
- **限流/风控**：接口按 IP+用户+设备多维度限流；风控决策参数（指纹/行为）必须服务端验证来源，前端上报仅作参考
- **权限最小化**：每个接口/工具按最小权限设计；批量分配使用 DTO 白名单字段绑定（禁止直接 @RequestBody 实体）
- **LLM 应用加固**：工具调用做用户级+对象级授权、高影响操作强制二次确认、输出做参数化/白名单校验、RAG 检索加权限过滤、系统提示词做防提取加固（OWASP LLM Top 10 2025）
- **错误处理**：统一错误信息（不泄露内部细节/状态码语义），生产关闭调试信息
- **审计日志**：关键操作（支付/退款/改密/审批/转账）记录操作者+对象+前后状态，便于追溯与风控建模
- **安全测试左移**：将状态机/资金流检查纳入开发评审（ASVS 4.4 业务逻辑章节），上线前做业务逻辑专项测试

## 十六、注意事项

- **仅限授权测试/合规声明**：业务逻辑测试可能直接影响真实交易、资金与用户数据。**必须在获得书面授权的范围内测试**（测试环境优先），并严格遵守《中华人民共和国网络安全法》《数据安全法》《个人信息保护法》及《生成式人工智能服务管理暂行办法》等相关法律法规；未授权测试属违法行为，本技能仅用于授权渗透测试、安全研究与防御建设
- **避免真实交易**：支付测试使用测试金额/测试账户/沙箱环境，不产生真实交易；竞态/并发测试可能导致数据不一致，提前备份并在低峰执行
- **并发测试谨慎**：单包攻击/高并发请求可能触发风控封号、限流甚至拖垮服务，先小并发探测再逐步加大；明确记录测试时间窗
- **数据保护**：不读取/导出/修改真实用户敏感数据；测试中发现的他人数据立即丢弃并记录于报告
- **数据清理**：测试产生的订单/优惠券/积分/账户/测试数据及时清理或标记，避免污染业务数据
- **不破坏业务**：不执行删除/篡改真实数据、不干扰生产审批流、不滥用短信轰炸接口
- **LLM 测试合规**：提示注入/RAG 投毒测试需确认目标服务条款与授权，避免对外部 AI 服务造成滥用
- **报告质量**：每个漏洞按"前置条件→攻击步骤→影响评估（含资金/数据/合规维度）→修复建议"四要素完整记录；逻辑漏洞定级参考 OWASP BLA/API 框架按实际业务影响
- **情报持续更新**：业务逻辑漏洞高度依赖具体业务场景，跟踪 OWASP BLA Top 10、OWASP API Top 10、OWASP LLM Top 10、PortSwigger 研究（Smashing the state machine）等权威源，及时更新本技能
