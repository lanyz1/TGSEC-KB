## 五、积分/优惠/抽奖系统逻辑滥用

### 5.1 优惠券深度滥用

```
1. 优惠券叠加：同时使用多张优惠券（满减+折扣+店铺券+平台券可叠加到负）
2. 优惠券 IDOR：修改 coupon_id 使用他人/内部优惠券
3. 优惠券金额篡改：改 discount/type 字段（满100减50 → 无门槛减999）
4. 无限领取：领取接口无"每人一次"限制，或"每人一次"可被竞态绕过
5. 过期优惠券继续使用：修改本地时间绕过 / 服务端时间校验缺失
6. 测试优惠券/内部券泄露：前端 JS/接口响应中泄露的测试券码
7. 优惠券状态机：
   - 已用券 → 退款 → 券是否退回？退回的券能否再次使用？
   - 券领取后未使用 → 取消订单 → 券次数是否被消耗？
   - 券兑换码：生成-兑换竞态（第三章 3.4 多端点脚本）
8. 券面值负值：discount=-100 → 订单金额反而增加（配合退款）
9. 券适用条件绕过：改商品类目/地区/会员等级字段满足券条件
```

### 5.2 积分系统逻辑

```
1. 负数积分：积分抵扣为负 → 积分余额增加（反薅）
2. 积分兑换竞态：积分余额 1000 分，并发兑换 1000 元商品 N 次 → 余额为负
3. 积分入账重复：同一笔消费/签到并发触发多次积分入账
4. 积分过期绕过：改本地时间/服务器时区绕过过期校验
5. 积分转换比例：积分↔现金折算比例参数可改
6. 积分提现：积分提现无门槛/无风控 → 批量小号刷积分提现
7. 任务积分：任务完成判定由前端回调（"观看视频 30s" → 直接 POST 完成任务）
```

### 5.3 抽奖/盲盒/活动逻辑

```
1. 次数限制：抽奖次数在服务端？"每日3次"可否被并发绕过/重置（改时间/换账号）
2. 结果前端决定：抓包修改中奖结果（前端生成中奖 JSON，后端信任）
3. 概率参数篡改：rate/probability/luck/weight 参数在请求中 → 改成 100
4. 并发抽奖：连抽并发 → 超过次数限制多抽
5. 奖池逻辑：改奖品 ID 直接领取大奖（prize_id 遍历）
6. 活动资格绕过：会员等级/新老用户/地区限制 → 改资格字段
7. 库存独立：大奖奖品库存与抽奖记录不联动 → 无限抽大奖
8. 防刷失效：同一设备/账号重复参与 → 风控可绕过（见第六章）
```

### 5.4 邀请/推荐/裂变奖励

```
1. 自邀：注册小号邀请自己 → 循环刷奖励（邮箱/手机号可无限注册时）
2. 邀请码复用：同一邀请码多人使用/无使用次数限制
3. 修改推荐人：注册后修改 referrer_id/referral_code
4. 并发领取奖励：邀请成功后奖励领取接口可并发 → 重复领
5. 被邀请人判定绕过：新用户判定基于可伪造字段（注册时间/设备/IP）
6. AI 生成身份批量注册：绕过实名/设备指纹（配合第六章风控对抗）
7. 裂变层级：多级返佣比例参数可篡改（直推/间推比例）
```
