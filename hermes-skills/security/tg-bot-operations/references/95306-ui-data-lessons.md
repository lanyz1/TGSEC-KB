## 手机自适应项目列表(用户强需求)

TG 按钮宽度限制 → 手机上项目名截断。最终方案(用户接受):
- **文本列表 + 数字直达按钮**:每页 5 条,项目名纯文本完整显示(自动换行、长按复制)
- 按钮行:`[1][2][3][4][5]` 数字直达详情 + `[⬅️][n/m][➡️]` 分页 + `[🔙]`
- 用户也可**直接回复数字**打开对应项目:`handle_text` 开头 `if t.isdigit() and 1<=int(t)<=9 and LIST_STATE.get(cid): list_open(cid, int(t)-1); return`
- 状态:`LIST_STATE[cid]={"items":[pid...],"back":cb,"title":str}`,回调 `listopen:{idx}` / `listpage:{page}`
- 统一入口 `render_list(cid, title, items, page, per=5, back, note)`;数据池/竞价监控/搜索/最近浏览/订阅全部走它
- 项目编号不显示在标题;项目名不截断(所有 `[:N]` 全删)
- 详情页"📋 复制名称"按钮:点后单独发一条纯文本项目名消息,长按复制(TG 无原生点击复制)

- 实例:删 market/cat/stars 时误删了 `accel` 与 `settings` 分支 → 按钮在菜单里但点击无反应
- **删除后必跑回调体检脚本**:
  ```python
  # 提取 callback_data vs 处理分支,注意三种形态:
  #   elif data == "x" / elif data in ("a","b") / elif data.startswith("pre:")
  # 带 ":" 的 callback 靠 startswith 前缀处理;main 可能是 if 不是 elif
  ```
- 死代码(已删功能的残留函数/按钮)不渲染,体检时标注"无害"即可

## 公告推送纪律(用户两次纠正漏推 + 一次纠正重复推)

- **部署五步流程:改码 → py_compile → 部署 → 验证 → push_update**;漏推=流程事故
- 部署脚本必须内嵌 push_update 调用(单独跑一次,不要用 head/tail 分两次看输出——重复执行=重复推送)
- **去重**:`last_push.json` 存 `{"v": version, "t": time.time()}`,同版本 30 分钟内跳过;`manual=True` 强推
- 只推本次变更内容,不重复历史;bot 重启静默

## 95306 数据源局限(回答"为什么时有时无/幻觉")

| 数据源 | 覆盖 | 局限 |
|---|---|---|
| getBuyPackageList(实时) | 报名企业的 pack_id 级明细 | **必须该企业 ST(30min TTL)**;ST 过期=拉不到 → 报名截止早的项目实时全空 |
| 审计日志 ST | 当天活跃企业 | 只有"正在操作系统"的企业;历史 ST 全失效 |
| 8515.csv(官方快照) | 项目级(企业名/信用代码/时间) | 部分项目只有公告行无企业(真没数据/重复公告);无 pack_id |
| 08文件(615K) | pack_id 级全量(企业/包件/审核) | **只含已结束项目**,进行中项目不在 |
| 公告全文 | 包件清单(公告级) | 只有"包件是什么",没有"谁报了" |

- 企业名 = `user/info.dwhz`(企业自填,可能简称/"?",同账号不同时刻可能不同)→ 归一化到官方全称(供应商主数据 369K,去后缀核心名精确匹配+缓存,未命中含匹配);"?":账号→企业名补全(全库扫描缓存 5min,`resolve_acct_name`)
- 统计口径(用户定义):**已报名且未结束(status 非 14/22)= 进行中**;展示完整口径"已报名 N(进行中 X | 已结束 Y)"
- 8515 补导:proj_code→projId 匹配合并进 pack_map(项目级记录,无包件)
