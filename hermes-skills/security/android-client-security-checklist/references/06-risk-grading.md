# 06 风险等级评定全表 + 报告模板

源：Android APP渗透测试方法大全 附录三（人行/金融客户端安全评估口径）。
口径要点：**高** = 可获得密码等敏感信息、可篡改敏感数据；**中** = 仅不当导出且拿不到敏感信息，或需非常规前提；**低** = 防护不足但无直接危害。

---

## 6.2 报告模板

```
# <目标> Android 客户端安全评估报告

## 一、摘要
- 评估对象：<App名> <versionName> (<package>)，targetSdkVersion <x>
- 测试环境：<机型/模拟器> <Android 版本> <是否 root>，测试日期
- 结论：共发现 x 个高危 / y 个中危 / z 个低危；无需特权即可达成的高危：<列表>

## 二、发现（按风险降序）
### [高危] x.y <标题>
- 位置：组件/文件/接口（给到 Activity 全名、文件路径、URL）
- 复现（可复制粘贴，带设备与前置条件）
    $ <命令序列>
- 证据：<截图/logcat/输出/文件内容>（附路径）
- 影响：<攻击者能拿到什么/改掉什么，给可行场景不写理论>
- 修复：<具体改法，给代码级建议>

## 三、覆盖度声明
按 12 类清单逐项标注：已测且通过 / 已测且失败 / 未测（写明原因，如无 root 设备、需业务后台配合）

## 四、附录
- 工具与命令清单
- 原始数据/抓包/日志路径
```

**证据分级纪律（写报告时严格执行）**：现场运行行为 > 抓包流量 > 服务端当前返回 > 运行中配置 > 持久化状态 > 生成产物 > 已提交源码。
源码只用来解释运行时，不能推翻运行时（除非产物过期/缓存/诱饵）。
