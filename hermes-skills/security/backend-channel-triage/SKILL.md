# 多通道后端分诊（WAF / 网关 / 应用 / nginx 谁在答）

## 何时用
同族响应混在一起（一会儿 401、一会儿 502、一会儿 200 空 body、一会儿挑战页），或要判「这个管理后端到底活没活」。**先分清通道与层次，再谈漏洞**；判错层次会得出「端点不存在」的假结论。

## 0. 铁律
1. **一个渠道的结论不算结论**：同一路径在「WAF 域名 / 源站 IP / 另一个 Host / 加静态后缀」下可给出四种答案。宣称「端点不存在」前，通道矩阵必须跑完。
2. **200 不是成功**：挑战页是 200；「路由在、上游服务不在」也常是 200 + 0 字节。
3. **恒定响应没有判定力**：先跑对照（缺头/明文/别的路径）；对照与实验同字 ⇒ 该通道零信息量，换通道，别在它上面继续做参数差分。
4. **源站直连（IP + 真 Host）是第一优先动作**，不是最后手段。
5. **先判那个「源站 IP」是不是 CDN 边缘**：域名解析出来的独立 IP、证书里的 IP、前端配置里的 IP，都要先验一次它到底答什么，再谈端口面。边缘节点在一大堆端口上应答，**端口 OPEN ≠ 源站跑着 Redis/宝塔**——把边缘端口当中间件打，是本类任务里最贵的一次误判。
6. **三通道完全同形 ⇒ 判定闸的位置，而不是继续换 payload**：同一组 payload 在「域名 / IP+真 Host / IP:80」三条通道上返回**完全一致**的拦截码与拦截页长度，说明闸在边缘或源站自身，直连 IP 不构成绕过；此时唯一正路是**源站溯源**（历史 DNS / CT / 未被代理的子域 / 姊妹域共享源站），不要烧 payload 变体与编码。
7. **静默阻断 ≠ 路由不存在**：未编码的特殊字符（如 PHP 数组方括号 `[1]`、`file://`）会被 WAF **静默丢包（空 body / RST）**；**URL 编码后（`%5b1%5d`）即可穿过 WAF 直达应用**并拿到真实路由响应（404 或业务错误）。判「端点不存在」前先跑一个**肯定不存在的对照路径**：对照与目标同形 ⇒ 是 WAF 在挡，不是路由缺失，再用编码/变形重打一遍。（**query string 里的方括号常被拦，POST body 里的常不拦** —— 这就是绕过的着手点。）

8. **带 HTML 的 404 / `File Not Found` = 路由确实不存在，可以直接判死这个通道**；与「静默空 body」必须分开看。
   ★ **同族源码里有对应 controller ≠ 线上部署了该路由**：源码里的回调/接口清单只给算法与参数（权威、值得读），但能不能打要先发一条探针请求看它是否 404。基于源码就开的矩阵，可能一枪打在未部署的路由上。
   ★ **「特判」只拦它写明的字面形式 —— 前缀 404 ≠ 该前缀后端不可达**：站点用明文规则盖住某前缀（`/admin`、`/admin/...` 回 404，而 `/admin.html` 放行 = 规则只匹配带斜杠边界的形式）时，后端 API 常**同站仍可达** —— 依次试 尾斜杠变体、内嵌点段 `/prefix/./x`、编码斜杠 `/prefix%2fx`、大小写。**判层认「谁的 404」**：nginx 版 404 页 = 仍被门挡；后端框架自己的 404（Go 默认 `404 page not found` 裸文本 ≈19B、Kratos/FastAPI JSON 错误体）= 已穿过门到达后端 —— 同为 404 的两种 body 是完全不同的结论，不要用状态码判层。

9. **「空 body 全家桶」 = 出口 IP 被记账封禁（不是路由问题）**：防护层按 IP 记账，预算耗尽后**所有**请求都回空 body —— 不是 404、不是 502、也不是业务错，而且**连首页、`favicon.ico`、静态文件、以及此前实测可用的对照端点一起空**。
   - 判据：换一个**干净出口**发**同一条**请求，立即恢复（一条对照请求就能二分）。
   - 动作：判到就换出口，**不要在本机解析、重试、改脚本、改编码上耗时间**。
   - 变体：封禁可能只针对**客户端指纹**（同 IP 下 `curl` 通、`python-requests` 全空）——换客户端也算换通道；也可能按 TLS/JA3、按 Host、按 (IP×Host) 分别记账。
     - ★ **判到「客户端指纹」这一档时的既定修法 = 换引擎，不是换语言**：目标 nginx 对 `python-requests` 的 TLS 握手直接回 `EOF`（现象：requests 全灭、`curl` 同 IP 连续 200 且耗时正常）时，写一个 **curl 驱动引擎**——Python 组参数、`subprocess` 调 `curl -s -k -g -o <文件> -w "%{http_code} %{size_download}"`、再读文件；只包 `get/post/multipart` 三个薄函数，**上层业务逻辑一行不改**继续用 Python。别把整条工具链重写成 shell（解析/循环/落库立刻变难），也别在 requests 上试重试、降 TLS 版本、换 UA——那是在错误的一层调参。
   - ★ **突发配额与自愈**：出口被记账时，**同一轮里的批量请求会被中途掐掉**，症状是忽然**所有通道一起 000/超时**（连首页、`favicon.ico`、静态文件、此前可用的对照端点一起全灭），冷却后又自己恢复（实测量级：一批约百次请求后被切，数分钟后恢复）。⇒ 把「每轮请求数」当预算排（**≤1 req/s、单轮小批量、批间停顿**），批次大小做成脚本参数；**看到全通道 000 先怀疑「是不是我们自己打太密」**，不要急着改 payload、改脚本、怀疑目标宕机。
   - 反向纪律：**别把一个出口的额度当全局额度**；把「出口预算」当作参数，多出口轮换 + 低频，而不是把单出口打到死。

10. **挑战态按「通道」记账，不只按出口**：同一目标的「源站 IP + 真 Host」通道连续大量请求后被边缘判为机器人（全量 `418` / JS 挑战页，`curl` 与 `python` 同码），而**域名通道**在同一时刻仍回 200 业务响应（反向亦然）⇒ 两条通道的放行桶不同。**一条通道被挑战时，先 A/B 另一条通道**，而不是换出口、改 UA、加 XFF —— 那些动作在质询态零信息量。判据 = 同一条对照请求在两条通道上的「状态码 + body 形状」，一条挑战一条业务即定。

11. **整批字典 / 整批探针「同一个状态码」不是口令结论，先做出口 A/B**：对 Basic / 登录面跑完全部候选都回同一码（403 或 401）时，先换一条**干净出口**重发**同一条**请求再下结论。防护层按「出口」记账时会把代理/VPN 出口整批拦掉，表现是**假 403**（对该域下一切路径都 403，连正确口令也 403）；而跳板直连出口回的是带 `WWW-Authenticate: Basic realm="…"` 的**真 401**。判据 = 同一条请求在两条出口上的「状态码 + 是否有 realm/挑战头」；换出口后仍同码，才是「口令确实不是这些」。**把字典搬上跳板机本地跑**（推凭据+脚本、远端执行）最省事，报告里把「跑完 N 组、0 次防护拦截」当作出口可用的自证。

12. **小体积 HTML（<300B）先当挑战页，不当结论**：防护挑战对**客户端指纹**敏感 —— 同一 URL `curl` 默认 UA 回挑战页、`python urllib` 或真浏览器常规 UA 直接 200，是常态。拿到小体积 HTML 时**换客户端（UA / 客户端库 / 真浏览器）重发同一条请求**再判，比改 payload 有价值；判挑战页认特征串（`aliyun_waf_aa`/`acw_sc__`/`renderData`/`md5__1713`）。`/openapi.json`、`/docs`、`/actuator` 这类框架自描述路径是零成本对照。

13. **★ 正对照先于结论：判「文件/路径不存在」前，先取一个同前缀下**确定存在**的静态资产**。应用自身的兜底页会把**任意**未知路径都答成同一个 body（实测：某应用对所有不存在的路径回同一张 50556b 兜底页），只看 404/兜底会把**「静态服务整体不服务了」与「就这个文件没有」混成同一个结论**。
   - 判据：取一个已知存在的资产（同目录的 JS/CSS/图片）。它正常 ⇒ 静态服务是好的、那条兜底确实等于「这个文件不存在」；**它也不正常 ⇒ 你连通道都没打通，此前所有「不存在」结论全部作废**（本类任务里因此撤回过多轮结论）。
   - ★ **负对照（肯定不存在的路径）给出「缺失长什么样」，正对照给出「服务本身活不活」——两个都要跑，缺一个必误判。**
14. **★ 应用自己 DB 里记的文件路径 ≠ 盘上真有该文件**：应用常写「`file_path` + `file_size`」这类**意图记录**，而落盘那一步可能整体失败/被关（实测：库里一批缓存行都带 file_size，盘上一个文件都没有）。
   - ⇒ 任何「文件在不在 / 删没删掉 / 写没写进去」的结论，一律以**外部可观测的一次取用**（HTTP 取一次、STAT、列目录）为准，不信应用自述。
   - ⇒ **别用「库里有行」去校验删除/写入原语是否生效**（会得出「原语有效」的假阳性）。要证明删除/写入原语真的生效，先在**可控位置造一个自己取得到的对照物**再操作、再取一次——判据是那个对照物的状态变化，不是应用的返回值。

15. **★ 同站常有多台源站节点，每台一套独立封禁账本 ⇒ 预算按「节点」算，不按「站点」算。**
   - 溯源时**把案卷里出现过的所有源站 IP 都枚举出来**（历史 DNS / 证书 / 前端配置 / 旧脚本里的 `ORIGIN=` 常量 / 迁移回源配置），逐台独立自检。**历史上被引用次数最多的那台往往才是真正能用的那台** —— 案卷里最新、最显眼的那台可能早就被自己打封了。一台全空**不能**推出「站点不可达」；多节点交替等于把批量预算翻倍。
   - **批前自检（每批必做、写进批次日志）**：每条候选通道各发**一条**最便宜的读请求，记 `状态码 + 耗时 + 形状` 三元组。**`000` 且耗时 ≈0.1s ⇒ 该出口已在 TCP 层被拉黑（RST/丢包），不是应用拒答** —— 把这条通道从本轮台账里划掉，不要改 payload、不要重试。**空 body 但耗时 ≈超时上限 ⇒ 预算耗尽后的静默丢包，或出口本身烂**；两者都**不是**「端点不存在」。
   - **预算按「每出口几十~上千发」排**：把「通道 × 本批已发数」当脚本参数与日志字段，到量先换节点。单出口砸到死的结果是**批中段开始全空**，而前面已发的那批会被误当成完整结果。
   - **代理池当通道用时，先做池自检再上量**：① 拿池里一条打**外部基线** `https://api.ipify.org` —— 全灭就是**池凭据/端口已失效**（dump 出来的池文件常是过期快照），不是「目标打不到」；② 先量单发耗时与可达率 —— 住宅池可以「活但 ~0.5 发/秒」，少量验证够用、**撑不起几千发的批量**；③ 认证 SOCKS 池的调用形式以**历史上跑通过的脚本**为准（`--socks5-hostname user:pass@ip:port` 常才对；`http://` 前缀可能只是导出格式，写错的表现就是全灭）。
   - 自检脚本：`scripts/channel_preflight.sh`

## 1. 通道矩阵（四维正交，逐维展开）
| 维 | 取值 |
|---|---|
| 落点 | WAF 域名 / 候选源站 IP（历史 DNS、证书、姊妹域、前端配置里的 IP） |
| Host | 主域、别名域、各子域、内网名——**同 IP 不同 Host 常走不同后端** |
| 路径形态 | 原样 / 尾部加 `.json` `.txt` `.js`（静态后缀常被 WAF 放行且仍命中真路由） |
| 方法 | GET / POST（两种偏向都存在：有的网关**只放 GET**，也有的把 **GET 全拦、只放 POST** —— GET 全空时先拿 POST 打**同一路径**再判“端点不存在”） |

判定统一用「状态码 + 长度 + body 前 120 字」三元组，不看单一项。

## 2. 响应形状判别表（实测归纳）
| 形状 | 含义 |
|---|---|
| 200 + ~110KB + `_waf_bd8ce2ce37`/`renderData` | 阿里云 ACW 挑战页（未穿透） |
| 恒定短 body、与路径无关（如 46B `{"code":400,"msg":"Invalid encrypted request"}`） | **网关前置闸**（如 JFinal）⇒ 到了网关，没到业务 |
| 401 JSON 且 body **回显 path**（长度随路径长度变） | **活的应用 + 统一 catch-all 鉴权**（RuoYi 系典型） |
| 200 + 0 字节 | location 在、**上游服务不在**（不是鉴权拒绝，别误读成 401）。**判据是「只空这一条 location」** |
| **全站空 body**（含首页/对照路径/`favicon.ico`/静态文件一起 0 字节） | ★ **出口 IP 被记账封禁**（防护层预算耗尽），不是目标挂了也不是路由不存在。换干净出口同一条请求即恢复；不要在本机耗时间 |
| 502 | location 指向**死上游** |
| nginx 404 页 | 该 location 不存在 |
| `-ERR wrong number of arguments for '<cmd>' command` 等协议报错 | 端口上是**中间件本体**（Redis），HTTP 行被当协议命令解析 ⇒ 无 banner 也能定指纹 |
| **非 HTTP 端口回 HTTP**（如 6379 回 `400 Bad Request`）且带 `Server: Lego Server` / `Server: TencentEdgeOne` | 这个 IP 是 **CDN 边缘节点**（腾讯 EdgeOne），不是源站；它「开放」的 6379/8080/8443/8888 全是边缘自己的端口，**没有中间件也没有宝塔面板**。判定依据只认 `Server` 头 + 协议不匹配这两点 |
| 403 且**长度恒定**（所有 `/.env`、`/.git` 变体都回同一长 WAF 页）vs 某个变体长度**明显不同**（如 `/application/.env` 少几百字节） | 前者 = WAF 关键词拦截（恒定、零信息量）；后者 = **另一层在答**（nginx deny / 应用层），是路径存在性弱信号，值得继续换编码绕 |
| **小体积 HTML（<300B）且带挑战特征串**（`aliyun_waf_aa`/`acw_sc__`/`renderData`） | **WAF 挑战页**，不是应用响应、也不是「被拒绝」。先换客户端指纹（UA/客户端库）重发同一请求 —— `curl` 默认 UA 吃挑战而 `python urllib`/浏览器 200 是常态。**禁止拿它当「端点不存在/已排除」的证据** |
| **Spring Security 默认错误 JSON**（`{"timestamp","status","error","path"}`，400/403，且 body **回显原始 path**） | 已到 **Spring 应用**、被过滤器链挡下（不是路由自身 handler，也不是 nginx）。★`StrictHttpFirewall` 默认拒编码斜杠与双重编码（`%2f`/`%5c`/`%252e`），回 400 并回显**原始未解码** path ⇒ **路径穿越 / 编码斜杠类 payload 在 Spring 目标上从入口就死**，别烧编码变体，改走别的原语 |
| 缺某个 query 参数（如信封 `encryptParams`）时**所有**路径都 403，带上它就有业务响应 | 该参数是**前置过滤器**的入场券 ⇒ 这个 403 **没有鉴权含义**，不能作为「需登录」的结论；必须先补齐入场参数再判真实鉴权面 |

## 3. 统一 401 catch-all = 免票探针（高价值）
后端对**所有**路径回同一形状的 401（且回显 path）时，它同时是一台**完美的 permitAll 探测器**：任何**非**该形状的响应 = 漏配鉴权的端点。
- 先取基线：用一条肯定不存在的路径确认「标准 401 形状」。
- 再拿**真实端点清单**（从同产品前端 bundle / 另一套部署里提取，别靠猜）× GET/POST 双方法打一遍，只保留非标准响应的结果。

## 4. 登录闸门定性（决定后续能不能打）
按顺序判，别跳步：
1. **账号判定在 GA/验证码前还是后**：用**肯定不存在**的账号 + 错验证码试一次 ⇒ 回「账号不存在」= 账号先判（有账号 oracle）；回「验证码错误」= **验证码先判 ⇒ 无账号 oracle**。
2. **零消耗 oracle**：测登录流分流参数（`mode`/`grantType`/`usertype`…）一律用不存在账号 ⇒ 不消耗真实账号的剩余尝试次数。
3. **先测每-IP 熔断阈值**（不同部署差很多：有的 ~19 次封 30 分钟，有的 2-3 次即封），再决定如何换出口；换出口前别连打。
4. **登录契约从客户端产物取，不猜**：读登录 chunk（`LoginForm-*.js`）拿字段名与附加参数（形如 `{username,password,code,mode}`），再从发布配置取 build-time 参数（`VITE_GLOB_USERTYPE` 等）。字段名猜错会得到「账号不存在」的**假否定**。
5. 「账号不存在」要**跨部署**验：同一套自控账号在这套部署里不存在、在另一套里存在是常态，别用一个部署的结果否定另一个。

## 5. 前端发布配置 = 凭证与后端映射金矿
Vite/vben 系后台常明文下发 `_app.config.js`（或同名 `__CONF__` 文件）：`VITE_GLOB_API_URL`（真实后端）、`VITE_GLOB_USERTYPE`（客户端身份/多端共用同一后端的证据）、`VITE_GLOB_ENABLE_ENCRYPT`（明文 vs 信封闸的判定依据）、**`VITE_GLOB_RSA_PRIVATE_KEY`（信封私钥常与公钥一起明文下发）**。
- 公网取不到就用**源站 IP + 真 Host** 取。
- **解析坑**：文件形如 `window.__X__CONF__={...};Object.freeze(window.__X__CONF__);Object.defineProperty(...)` ⇒ 必须从 `={` 截到 **`};Object.freeze`**；用「第一个 `{` 到最后一个 `}`」会因尾随代码解析失败。
- **解析失败必须显式区分「没密钥」和「没解析出来」**：正则静默不匹配，看起来就像「这份配置没有密钥」。写完立刻回显解析出的键名自证。

## 6. 中间件面（端口扫到无 banner 端口时）
- 无 banner 端口先喂一行 HTTP（`GET / HTTP/1.0`）：回协议级错误即可定指纹。
- **版本靠未知命令推断**：`ACL` 不存在 ⇒ <6.0；`MODULE` 不存在 ⇒ <4.0 ⇒ `MODULE LOAD` 类 RCE 直接排除，别再试。
- `INFO` 回 `NOAUTH Authentication required` = 有 `requirepass` ⇒ 该面只剩「拿口令」一条路（`CONFIG SET`/`SLAVEOF` 都要先 AUTH）。
- **Redis AUTH 无锁定无计数** ⇒ 靶向小列表可行且安全。候选按「同一运维复用的随机 hex 风格」从案卷语料收割：**关键词邻接 + 高熵 hex 两类都要跑**，只跑关键词类会漏掉同源随机串。
- **口令小列表 vs 大字典**：靶向小列表（百量级、有依据）直接跑；百万级大字典先请示。

## 7. 汇报纪律
- 结论必须落到「哪个通道、哪一层、什么形状」，带状态码 + 长度 + body 片段。
- 打不动就明说**哪一层**挡住（挑战页 / 信封闸 / 验证码 / 无账号 oracle），不要用「端点不存在」掩盖「没打通那条通道」。
- 服务端/通道类结论先自证（回显路径、回显键名、回显长度），再往上报。

## 8. 代理透传面（下游服务把参数拼进上游 API 调用）
判据：发一个**肯定不存在**的 id，回的是**上游服务的错误体格式**（如 FastAPI `{"detail":"..."}`）而不是本应用文案 ⇒ 参数被**原样透传**，且下游是用**它自己的密钥/签名**调上游 ⇒ 该端点 = 上游的**签名代理**。三条用途：① 借它反推上游契约与错误语义；② 若路径拼接可穿越（Spring 目标通常不可，见 §2），可借它的签名触达上游其它端点（含下载类端点）；③ 拿真实上游 id 之前的唯一读面。
★ **透传证明只需一个不存在的 id**：先跑「真 id」与「假 id」两条对照，真 id 回 200 数据、假 id 回上游错误体 ⇒ 透传与签名链同时被证明，比读源码快。
★ **别盲枚举上游 id**：id 空间未知时枚举小整数是低效路径；先从前端 chunk 挖该 id 的**字段名与取值来源**（列表行字段、深链参数、详情响应、`orderId=` 查询参），或先制造一条自己的记录拿到真 id，再横向。
★ 只读纪律：这类「下单/取货」端点的参数契约可以探，但**触发真实下单即资金/状态写入**，须先把契约与 IDOR 假设讲清、拿到用户点头再动。
