# 窄通道批量外带(staged bulk exfil)

**何时用**:目标**能读数据但通道极窄** —— 报错回显只能拿单值(实测 ~200 字符/发)、UNION 被列数挡、
无文件写权限、`sp_configure` 能执行但 `value_in_use` 不变(xp_cmdshell/OLE/CLR 被服务器策略锁死)。
此时不要"多发几发慢慢抠",**把打包工序搬到服务端**:服务端聚合 → 写进一张现成表 → 页面数据面按批取回。

**适用面比 MSSQL 广**:任何"能执行任意查询 + 有一张可写的现成表 + 有一个能按 limit 读回的应用面"的组合都适用。
具体 SQL 形态与实测 Bug 表:`references/engine-bugs-and-payloads.md`。

## 铁律

1. **判胜口径唯一**:`落盘行数 == 服务端哨兵声称行数 == 目录 count`。三者一致才记 ok;
   只对长度/只看日志会放过静默丢行。落盘后本地**逐文件数行数**验收,不信日志。
2. **每单元读回后立即擦除**。读侧若"读回整张暂存表",响应体积 ∝ 已暂存量(实测 12MB 挺住 / 27MB 断 / 72MB 断)。
   暂存量做恒定后,单发响应与总规模无关。
3. **写权限要证不要猜**:`has_perms_by_name(...)`;"INSERT 不报错也不落行"时去响应里读真实报错正文,别急着换表。
4. **痕迹与拿数据同级**:每表起止各擦一次自有标记行(回读核对残留 = 0),删掉引导会话新建的临时账号。
5. **可续跑**:状态文件按 `<db>.<表>` 记 ok/行数/缺块;重启跳过已 ok。长跑进程会被外部回收,
   可续跑是零损失的唯一保证。
6. **并行实例四独立**:标记前缀 / 产物目录 / 状态文件 / 表清单。共享标记命名空间 ⇒ 两实例互擦暂存行,
   表现为"无休止缺块重试",误导成目标不稳定。

## 执行流

### 0 量级 + 权限(不量就选错通道)
`count(*)` 逐表、`db_name()`/`suser_sname()`/`@@version`、`is_srvrolemember('sysadmin')`、库列表一次 `string_agg(name)` 拿全、
逐库列目录(表名 + 列名类型 + 行数)。**表目录别只看 `sys.partitions`/`dm_db_partition_stats`** —— 无 `VIEW DATABASE STATE` 权限时它返回**空**,
会把"有数据的表"误判成"这库 0 张表";走 `sys.tables` + `sys.columns` + `sys.types`。

### 1 选暂存表
硬:① 有 `nvarchar(MAX)`/`text` 列(单行装大文本) ② 当前账号 INSERT/DELETE 权 ③ 有一个**只被本作业使用**的自我标记列。
软:④ 该表**自有数据面可读**(某个后台列表页能按 `limit` 回读) ⑤ 优先挑**别人的日志表** —— 不触发 DDL、不新增对象、痕迹只是几行自有记录。

### 2 分块数学
```
per = CHUNK_BYTES / max(avg(datalength(<拼接表达式>)), 24)
nch = ceil(rows / per)
每发推 3~6 块      # 单发载荷 ~0.5MB,别贪大
```
先用 SQL 算 `avg(datalength(...))`,别猜行宽(同库内可从 20B 到 650B)。拼接表达式逐列 `isnull(cast([col] as nvarchar(max)),'')`,
用 `char(9)` 连接,拼前 replace 掉列内 `\t`/`\n`。

### 3 payload 形态
```
1 or 1=1;<batch>--
```
末尾 `--` **必须**:注入点后面常挂着原生 SQL 尾(`ORDER BY ... OFFSET ... FETCH NEXT n ROWS ONLY`),
不收尾就是 `Invalid column name` / `Incorrect syntax near the keyword 'ORDER'`(看着像权限/表不存在)。
先发一个良性值触发一次报错把尾巴原文看清,再拼 payload。每条 INSERT 带 `IF NOT EXISTS(...)` 幂等守卫
(数据面读回本身可能再触发一次同一批 ⇒ 无守卫会重复落行)。

### 4 自校验哨兵
```sql
select string_agg(v, char(1)) + char(2) + cast(count(*) as nvarchar(20)) from (<块>) q
```
记录分隔 `char(1)`、尾标分隔 `char(2)`;回读后 `len(records) == 尾标声称行数` 才算这块成功;不符**擦掉重推**(最多 3 轮),
仍不符则记 partial —— **照样落盘**,别把已跑的白丢。

### 5 排序与分页
`%%physloc%%` 分页**不稳**(实测丢块)⇒ 退首列 ⇒ 再退**全列排序**(并列行值相同,漏取/重取不改变结果集)。
分页条件 `rn > off` 时 `off = i*per`;**写成 `i*per + 1` 会让每张表第一行永远丢**(正好少 1 行,极易被当成"目录 count 不准")。

### 6 续跑 + 痕迹
状态文件 + 一表一 TSV(首行列名)+ 独立产物目录;每表读完立即擦除标记行、跑完再清一次。

## 变体:应用面模糊搜索参数 = 全表读 oracle(不是注入)

公开的「查询/验证/搜索」端点把入参拼进 `LIKE '%'+p+'%'` 时,常只转义 `%` 而漏 `_` —— `_` 仍是**单字符通配**
⇒ **不发一个注入 payload、不靠任何写入权限,就能把整表读出来**;这类端点常是免鉴权或仅需任意有效票。

诊断顺序(每步一发,互斥判定):
1. `p="%"` —— 被转义 ⇒ 命中 0 或与原文同;未转义 ⇒ 命中全部(这一步先分清转义写得对不对)。
2. `p="_"` —— 命中多条且跨记录 ⇒ **`_` 未转义,直接进枚举**;只中 1 条 = `_` 也被转义,该面丢弃。
3. `p="_"*n`(n=1..18) —— 命中数按长度分桶 ⇒ 证明真能枚整表。
4. 单字符集扫(0-9 a-z A-Z + 中文常用字) —— 覆盖真值集;**每发原样落盘一份响应**(后续可重放/核账)。
5. 匹配语义三项自证:**子串 vs 前缀**、**大小写是否敏感**、**命中哪些字段**(只命中名称列还是也含域名/账号列)
   —— 用已知真值反推,别假设。命中字段越多、越短的真值(如目录里已见过的 5 字符名)越好使。

纪律:
- 命中集先去重,再用**业务字段**核账(余额/时间戳/上级 id),不要只数条数 —— 通配命中常带重复行。
- 这种通道**是宽的**(单发就回整页)⇒ **不需要 staging**,成本在「判通配」不在「搬运」,别把本卡的 MSSQL 工序搬过来。
- 需要登录时先用最小成本自签会话(如可自签的 initData / 开放注册);这类端点常对**任何**有效票开放(未做对象级授权)。
- 端点名字具迷惑性(「verify/check/exists」)⇒ 把它归档为**数据面**而不是验证码面;同理,只要某入口回的是**多字段记录**而不是布尔,它就是数据面。

## Pitfalls

- **失败"快而整齐"= 本地 bug;"慢而零散"= 目标侧问题。** 每项耗时几乎相同、秒级失败 ⇒ 先查自己的调用
  (实测:复用旧脚本的辅助模块时按记忆传了不存在的关键字参数,结果每张表 2 秒内整齐失败,看着像"目标全表不可读")。
  **接旧模块前先读它的真实签名。**
- 大表必断、小表全过 ⇒ 先怀疑**回读响应体积 ∝ 已暂存量**,别怀疑限速(单发延迟其实没变)。
- 只见"字段数翻倍的怪记录"或"每表固定少 1 行"这种**规律性畸变** ⇒ 一定是自己的拼接/分页数学,
  不是目标丢数据(见 references/engine-bugs-and-payloads.md 的真实 Bug 表)。
- 长跑日志按**工作单元**打:一张大表只在跑完打一行 ⇒ 中途十几分钟无输出,会被误判卡死。
- 长跑作业用平台原生后台跟踪启动(直接跑常驻脚本),不要用包装 shell;包装 shell 被回收会连带杀掉子进程,
  症状是日志停在某工作单元中途且**没有异常栈**。
