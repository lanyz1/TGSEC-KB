## 卡密/检测面自卫纪律(动样本/动端点前必读)

此类目标常内置**机器侧反逆向检测**(扫 Cheat Engine / OD / 易语言 / 调试器 / 可疑进程),命中即**封卡 + 按机器码/硬件标记**(产品帮助文档明示:检测到可疑软件即封卡);服务端与客户端还可能带设备锁(改密/登录仅限最后一台机器)。卡 = 消耗品、封停不可逆、常与硬件绑定 ⇒

1. **用户的真卡绝不用于探测**:验证端点、样本、登录流程一律不碰真卡;任何“先试一下”动作只用伪造卡号/占位符,缺真实卡就静态或停(用户会主动给卡时再动)。
2. **绝不去触发“机器验证/IP 验证”类机制**:先假设存在惩罚动作(封卡/标记/静默降级),再决定是否动;不确定就不动。
3. **静态优先**:解包/反编译/脱壳全程离线不运行;必须动态时在**无 RE 工具的干净隔离机**上跑,动态会话越短越好(注入崩溃/自毁见下文 Pitfalls)。
4. 拿到样本先测绘「检测面 × 惩罚动作」(扫哪些进程/窗口/注册表;罚什么),再定动态方案。
5. 买试用卡/短时卡涉及用户资金 ⇒ 执行前先要用户拍板;买到后走既有 fakeserver 转发流程抓成功响应。
