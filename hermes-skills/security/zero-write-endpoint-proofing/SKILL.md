# 零写入取证：证明「动钱/写库端点」未授权可达，而不触发副作用

## 触发
- 待测端点的调用会产生**订单/扣款/退款/发货/发券/改状态**类副作用
- 需要在**不写库、不动资金**的前提下回答三问：端点在线吗？鉴权在哪一层？未授权可达吗？可影响到什么程度？

## 铁律（先念再动手）
1. **不执行资金动作**：验证到「门闸存在且可算通」为止。正确签名/key **绝不提交**，只报告。退款、扣款、回调入账、批量转账一律只读或只报告。
2. **只用自有身份**：自有商户号/订单号/设备号；绝不用真实顾客付款码、银行卡号、他人订单。
3. **不落产物**：不传文件、不投反序列化 payload、不写缓存/日志/配置、不造后门。
4. **一次只改一个变量**：先拿基线（缺参），再逐个补参，观察错误从哪一档跳到哪一档。
5. **★★ 「没参数」不等于「零副作用」（本类最贵的一条直觉错位）**：
   动作分发型端点（`?action=<name>` / `/api/<动词>` / `router.php?c=…&a=…`）把**缺参**解释成「**对全部对象执行**」——
   `clear` / `flush` / `purge` / `reset` / `rebuild` / `reload` / `delete`(-all) / `truncate` / `backup` / `restore` / `install` / `activate` 这类动作
   **无参一发就全量执行**（实测：盲枚举一批未知 action 时，空参打中的缓存清除动作当场清空**全站数十万条缓存行 + 整个 Redis 键空间**，并触发全量重建）。
   ⇒ 开工前先按名字把候选端点分两栏：「**读形状**」(`list/status/get/query/info/config/preview/test`)与「**写/破坏形状**」（上列动词）。
   ⇒ **只有读形状允许用「缺参」当基线**；写/破坏形状一律发**必然不合法**的载荷（缺必填、类型错、不存在的 id）让**参数校验先失败**——
   而破坏性动作**恰恰常常不挂参数校验**，所以「缺参会被校验挡住」这个前提在这里不成立。
   ⇒ 批量探测前先给这批调用**记账**（端点 + 载体 + 实际发出去的参数）；事后要能说出「我对哪些端点发过什么」。
   ⇒ **真打掉了就如实报**：把非计划副作用写进报告的「测试影响」，并给出**自愈性判定**——派生/可再生数据（缓存、索引、聚合）⇒ 说明影响面；
   原始数据 / 资金 / 用户状态被改 ⇒ **立即停手并通知**。写「无影响」比打掉本身更糟。

## 零写入三档（按服务端校验顺序构造，保证在 `INSERT`/`UPDATE` 之前返回）
| 档 | 构造 | 证明什么 |
|---|---|---|
| ① 缺参 | 空 body / 缺必需字段 | 基线：回缺参错误 ⇒ 请求确实进了 handler（⚠ **仅对该端点确有参数校验时成立**；动作分发型端点缺参 = 全量执行，此类端点按铁律 5 改用「必然非法」载荷）|
| ② 身份不存在 | 不存在的设备号/商户号/订单号/UUID | 身份查找这一层在线且可枚举（SQL 实跑但取不到行）|
| ③ 关键字段为空 | 付款码字段空 / sign 空 / 金额非数字 | 已越过身份层进入解析校验层，且仍在写库之前 |

**先读服务端源码确定档位顺序**（家族典型顺序：身份查找 → 字段解析 → 金额校验 → `INSERT` → 调起第三方）。取证只走到「写库那一行」之前，并在交付里写明该行号。

### 第四档：门闸状态 oracle（两分支都报错、且报的错不同）

前三档证明的是**可达性**；要判「角色/权限门闸是否已打开」（决定下一步该拿什么票）不需真做一次特权写 —— 让**两条分支都在写库之前报错、且报错文案不同**即可。

- 构造法：给「只有特权分支才会走到的下一个校验」喂**必然非法**的值。实测注册类端点：`userID=<管理员UID>` + `account="!!!"`（违反 alphanumeric）
  ⇒ 闸关：`only admin can set user id`；闸开：推进到 `account must be alphanumeric`。两答案都在 `INSERT` 前返回 ⇒ **零写入读出闸门状态**。
- **前提（不满足则整轮白跑）**：先确认请求真的走到那句校验。若**所有变体回同一句**（典型是绑定/解析层缺字段文案）⇒ 你连目标分支都没进，该 oracle **无效**，**不许把「同句」读成「闸关」**（判层表见 `api-probe-layer-triage`）。
- 产出是**方向而非定级**：闸关 ⇒ 火力转去拿特权票/找特权面，别在参数契约上继续穷举；闸开 ⇒ 目标分支可达，继续推进契约（并回头过一遍定级闸）。

## 门闸定位（三种结论，别混）
- 回**业务错误**（业务码/人民币文案）⇒ 真业务分支可达（未授权面成立的前提之一）
- 回**缺参/格式错误** ⇒ 只证明路由可达，**不是**未授权
- 回**验签/密钥错误**（`密钥错误`/`sign check fail`/`invalid signature`）⇒ 保护仍在；若该门闸是唯一认证，改走「签名可算通吗」路线（见 `references/master-key-derived-auth.md`）
- 回**404 / SPA 兜底 / `接口方法不存在`** ⇒ 未部署或路由未命中，判负

## 白名单/分发器免鉴权 ≠ 未授权（高频过度定级点）
- 形态：分发器 / `ApiHelper` 的 `$exclude_list` 跳过外层 `verify()` 直调 handler
- **必须读被调处理器自身**是否有独立校验（家族里 `Pay::submit()`/`Pay::create()` 内部各自调 `api_verify()`）
- 判据：把参数补到「非缺参」，看回的是**业务错误**（真面）还是**验签错误**（保护仍在）
- 把「缺参报错」当「未授权可达」交付，是这一类任务最常见的过度定级

## 找面顺序（fork / 二开目标）
1. 读分支名与提交史（`.git/logs/HEAD`、`.git/index` 与本地/上游源码树**差集**）⇒ 得到「改集」与「新增集」。
2. **看 fork 的性质**：若分支名/改集显示它是**安全加固 fork**（如 `codex/config-db-security`、批量修 `password_verify`/会话安全），则**洞在它「忘改」的存量文件里** —— 攻击面优先扫**不在改集/新增集内**的存量入口（老 `api.php`/`getshop.php`/`cashier.php`/`submit2.php` 一类），而不是 fork 新增的那批文件（那批才是被加固过的）。
3. 差集只能**排序候选**：命中仍以活体响应为准（见下一节）。

## 部署树 ≠ 版本索引
`.git/index` / 源码仓里存在的文件与类，线上可能 404 或未部署。索引只用来**找面**（差集推理），结论必须由**活体响应**给出。

## 定级闸（交付前必过）
1. **先量化再定级**：数一遍可利用基数（例 `<prefix>user` 里有多少行绑定了 `voice_devid`：`SELECT count(*) ... WHERE voice_devid<>''`）。结果为 0 ⇒ 定「**潜伏面（条件触发）**」，不当「已可利用」交付。
2. **单实例失真**：用户表只有 1 行 / 只有自己的探针账号时，**跨租户/跨商户**结论无法抽样证明 ⇒ 交付写「构造推断」，不得写「抽样实证」。
3. **主密钥派生签名**：签名只覆盖单字段时，能否越权取决于服务端有无归属校验；没拿到第二方样本就按构造推断写。
4. **两句话交付**：分开写「已确认（实测响应）」与「未证实（推断/受限于身份不可枚举/功能未启用）」，不允许只写前者。

## 内部视图开关的只读取证（2026-10）
- `type=1`/`view=internal` 拉全量时只需 GET + 分页，天然零写
- 取证三层：①未带参 → total 小；②带 `type=1` → total 突增；③抽样 `GET /detail?id=` 单条验证
- 报级：能读到他人数据即高危，不依赖任何写操作；不提交、不回写、不删改
- 如必须验写权限，用自建对象（自己注册的账号/自己的记录）做写入目标
