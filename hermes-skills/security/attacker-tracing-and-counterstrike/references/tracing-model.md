# 溯源模型与设备清单

## 五段模型

```text
① 捕获   边界/WAF/态势感知/全流量/EDR/堡垒机/蜜罐/Web 日志/邮件网关/云审计
② 提取   样本(webshell/木马/宏/脚本) → 编码器、密钥、密码参数、C2、证书、编译路径
③ 定位   IP → ASN/归属/反查/威胁情报/端口反扫/被控机日志关联/证书与域名复用
④ 身份   蜜标投递 + JSONP/XSS 前端漏洞取社交账号；付款/注册信息；样本内联系方式
⑤ 时间线 把 ①-④ 对齐到统一时区，输出攻击者画像 + 攻击链报告
```

## 各设备取什么

| 设备 | 关键字段 |
|------|----------|
| Nginx/Apache | `$remote_addr $time_local "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"`；上传接口的 POST 体长度、`$request_body` |
| WAF/态势感知 | 命中规则名、攻击类型、payload 原文、源 IP 与 XFF |
| 全流量 | pcap（文件上传、C2 心跳、下载行为）；会话重组 |
| EDR | 进程树、命令行、父进程、落地文件哈希、外联 IP |
| 堡垒机 | 登录账号、来源 IP、操作命令录像 |
| 蜜罐 | 交互命令、上传样本、登录凭据、扫描器 UA、社交身份（JSONP/XSS 回连） |
| 云审计 | AK/SK 调用记录、控制台登录 IP、创建的资源（`cloud-credential-leak-exploitation` 同源） |

## 单条 IP 的固定动作

```bash
# 归属与画像（只读，别打）
whois <ip>; curl -s "https://ipinfo.io/<ip>/json"
# 反查同 C 段/同组织资产（测绘引擎语法见 space-mapping-engine-recon）
# 端口反扫：只探 22/80/443/3389/8080，慢速
nmap -Pn -sT -p 22,80,443,3389,8080 --max-rate 20 <ip>
```

被控机（攻击者跳板）拿日志是**高价值**：跳板机上常留全量扫描记录与真实出口。
拿下跳板机后走 `host-ir-check` 先固定证据（哈希/只读副本）再分析。

## 时间线铁律

- 全部时间统一 UTC（服务器常 UTC，日志常 +8，对齐错 8 小时会得出错误因果）。
- 先定"第一个成功写入/上传/登录成功"的点，再往前找探测、往后找横向。
- 每个结论标注证据来源（设备 + 日志行号/文件哈希），无来源的不入报告。

## 交付

攻击者画像报告：工具与版本指纹、C2/域名/证书、被控资产、时间线、影响面（哪些数据被读取/外带）、
以及**可复现的取证命令**。样本与日志进案卷 `测绘/`，保留原始哈希。
