# 反制 playbook（客户端 / 管理端侧）

反制 = 把执行点搬回**攻击者机器**。只有三条路：

1. **客户端软件自身漏洞**（管理端 GUI / 内置浏览器 / Electron node 集成）
2. **依赖链**（扫描器内置 Chromium/JDK/插件更新通道）
3. **恶意基础设施**（假服务端主动喂 payload：见 `counterstrike-server-side.md`）

## 通用前置评估

| 项 | 要答的问题 |
|----|-----------|
| 版本 | 从样本特征推断工具与版本（能否触发已知 CVE） |
| 边界 | 只反制"正在打我"的实体；不扩大、不无差别投毒 |
| 可恢复 | 反制载荷是否会连带影响正常用户/自有监控 |
| 定向 | 反制页面必须**只对攻击者指纹生效**（UA/源 IP/交互特征） |
| 证据 | 回连日志、文件哈希、时间线全部留档 |

## AntSword 反制

```text
原理：老版蚁剑把 webshell 返回的内容按 HTML/JS 处理（列目录/读文件时），
      且 Electron 版开启 node 集成 → 客户端侧 XSS 直接升级 RCE。
做法：保留被上传的后门，按工具期望的响应格式返回一段 JS（动态加载外部资源）；
      载荷挂在你的取证服务器上，只对该后门/该 UA 返回。
前置：蚁剑 ≤2.0.7 一类的老版本；新版默认禁用相关能力 → 直接放弃，转溯源。
成功判据：攻击者机器主动外连你的监听（DNS/HTTP 回连日志）。
```

## Cobalt Strike 客户端（CVE-2022-39197）

```text
原理：CS 客户端用 SWING + 内置 HTML 渲染展示 beacon 元数据（进程名/用户名等），
      未过滤 HTML → 注入 SVG → 加载远程 jar → 客户端 RCE。
步骤：① 起 web 服务放 evil.svg（内部再加载恶意 jar）
      ② 用 POC 把样本元数据字段指向该 svg 地址
      ③ 攻击者上线后在会话里查看进程列表即触发
影响：CS ≤ 4.7（4.7.2 修复）。
要点：攻击者不一定点进程列表 → 进程名起得显眼一点提高点击率（社工化）。
```

## Goby / AWVS 等扫描器

```text
原理：扫描器为渲染 SPA 内置了浏览器内核，目标页返回的 JS 在其内核里执行；
      老内核可打已知 Chromium/组件漏洞 → 扫描机 RCE。
旁路：部分扫描器把本地 API 暴露在 127.0.0.1（如 AWVS/Acunetix 的本地接口），
      页面里的 JS 可借助攻击者浏览器上下文请求本地端口（CSRF 面）。
做法：对扫描器指纹 UA 返回 exp 页；正常用户与自有拨测返回正常页。
成功判据：扫描机回连；失败多为内核已更新 → 记录版本，别硬打。
```

## Burp / 高级工具使用者

```text
可打面窄（使用者是专业人）：插件更新通道劫持、假 BApp 仓库、
Collaborator 域名被抢注/污染、代理日志泄露。
现实收益更多来自"取资产"：暴露的 Collaborator/代理配置/证书 → 直接进溯源。
不建议为反制而反制：拿不到就转 ③ 恶意基础设施与画像。
```

## 反制纪律（血泪项）

- 反制载荷**绝不能对正常流量生效**：以源 IP + UA + 只对该后门路径为条件。
- 你自己的监听与载荷服务器也要留日志，反制过程本身可能被审计（自证清白）。
- 版本不符/无回连就**如实记录失败**，不要写成"已反制"。
- 反制后若拿下攻击者机器：先取证（`host-ir-check`），再谈清理与上报。
