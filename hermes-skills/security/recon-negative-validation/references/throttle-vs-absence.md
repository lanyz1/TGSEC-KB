# 零命中/满屏失败 ≠ 目标死——先做「限速 vs 空号」判别

触发：扫号/批量探测返回整片失败（超时、悬挂、自定义状态码），或用户问「是不是打不了/没数据」。
实战教训：扫号中途「全线失败」= 出口 IP 被 WAF 限速（案例是自定义码 `456`），降速/换出口后全量 200；同一时间「单发健康」与「批量全挂」共存——批量挂不代表目标没数据。

## 判别流程
1. **停批量负载**，休眠冷却（至少 30–60s；按 IP 冷却实测可达数十分钟）。
2. **单发慢速探针**：同路径、新连接、浏览器 UA、无并发。单发 200 → 你被限速了，不是空号、不是封站。
3. **换出口复核**：跳板/第二 IP 打同一请求。它通 = 按 IP 限速（本机被烧）；它也挂 = 共享封锁或两边都被烧。
4. **按响应语义分桶**：显式 400/404（同一 id 稳定复现）= 实体不存在；自定义码/429/403 突发/超时悬挂 = 限速信号，**不是**结论证据。
5. 只有「低速单发 + 换出口 + 等完冷却窗口」三种手段都拿不到 200，才可怀疑真封；即便如此也先记为 RETRY，不写 ABSENT。

## 设计后果
- 三桶输出：OK / ABSENT(显式4xx) / RETRY(其它一切)。**RETRY 永不落入 ABSENT**。
- 覆盖对账：OK + ABSENT 应等于区间总数；RETRY 桶必须用 gap-fill 跑清零才算「扫完」。
- 限速后重跑用 skip 集幂等续跑，不重扫已确认的 OK/ABSENT。
- 报告措辞：严格区分「确认不存在」「暂被限速未取到」，绝不把限速写成「目标没有数据/打不动」。

## 附带坑
- 进程活着、0 CPU、输出空、无报错：先查自己的限速器实现 bug（令牌桶时钟推进错误会把所有 worker 睡死），别先怀疑目标。
