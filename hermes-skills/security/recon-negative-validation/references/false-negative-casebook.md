# 假阴性案例簿（探针自检 + 控制组）

**原则**：负结果（NotFound / 全失败 / 0 命中）先怀疑**探针本身**，再下结论。两个动作：①输入格式自检；②已知-good 控制组跑同管线。

## 案例 1：AK 截断前缀 → 全员「假死」（2026-10，鑫鹿案）

- 现象：一批阿里云 AK 测 GetCallerIdentity 全部 `InvalidAccessKeyId.NotFound`，连案内已证实有效的钥匙都「死」。
- 根因：提取时只抠了 11 位前缀；阿里云 AK ID 固定 **24 字符**（`LTAI[A-Za-z0-9]{20}`）。截断串配密钥必然 NotFound —— 假阴性，冤枉死钥匙。
- 修复：改用全 24 位串 + ±1200 字符窗口配密钥段，全部命中。
- 教训：**测凭据前先验凭据字符串格式**（长度/字符集）；格式错 = 结果无效，不是「钥匙死了」。

## 案例 2：协议层错误伪装成「钥匙全死」（2026-10）

- 现象：同批钥匙（含有效的）同一接口全失败。
- 根因：阿里云 STS 强制 HTTPS；SDK 未设协议 → `InvalidProtocol.NeedSsl`。
- 修复：`r.set_protocol_type("https")`。
- 教训：**全量失败先分组归因** —— 控制组（已知有效钥匙）挂 = 环境/协议层（协议、超时、区域、时钟）；控制组活而目标死 = 真负结果。

## 通用自检清单（0 命中 / 全失败时）

1. 输入格式对吗？（长度、字符集、编码、被截断、引号/转义弄脏）
2. 控制组样本跑同管线 → 排除环境/协议层。
3. 传输层对吗？（HTTP vs HTTPS、方法、Content-Type、代理）
4. 错误码语义分开了吗？——「参数/格式错」 ≠ 「不存在」，两者常被同一句 NotFound 混着返回。
5. 有旁路吗？（换接口/协议/区域/直接读响应细节）
