# 登录锁定/限速的记账键绕过(lockout key rotation)

**一句话**:限速/锁定不是"有没有"的问题,是**按什么键记账**的问题。键选错,防护等于不存在。

---

## 1. 先诊断"记账键",别先放弃

遇到 `429 登录尝试次数过多` / 账号锁定,不要直接判定"有防护、不可爆破"。
**用同一个出口、在不同请求头维度各打一发,看哪一发被放行**:

```bash
# A. 原样重放(基线):确认真被锁
curl -s -o /dev/null -w "%{http_code}\n" -X POST $URL/api/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"x"}'
# → 429  真被锁

# B. 每发换一个唯一 X-Forwarded-For,同一出口 IP 重复打
for i in $(seq 1 8); do
  curl -s -o /dev/null -w "%{http_code} " -X POST $URL/api/login \
    -H "X-Forwarded-For: 203.0.113.$i" \
    -H 'Content-Type: application/json' -d '{"username":"admin","password":"x"}'
done; echo
# → 401 401 401 401 401 401 401 401   ⇒ 记账键 = XFF,不是对端 IP
```

**QXXT 案例实测**:真实出口 IP 已被锁成 429,同一时刻带唯一 XFF 连续 8 发**全部 401 放行**;
随后 1200 组字典(25 用户 × 48 密码)**零 429**跑完。
上一轮报告写的"限速 9min/轮,20+ 登录失败"是把"未换记账键"当成了"打不动"。

---

## 2. 候选记账键(逐个试,命中一个就够)

| 头 | 说明 |
|---|---|
| `X-Forwarded-For` | 最常见(反代/框架默认取它) |
| `X-Real-IP` / `X-Client-IP` / `X-Originating-IP` / `X-Remote-IP` / `X-Remote-Addr` | 老框架/nginx 配置常用;**与 XFF 同时带同值更稳** |
| `Forwarded: for=1.2.3.4;proto=https` | RFC 7239,常**绕过只认 XFF 的限流器**(两条解析路径) |
| **重复同名头** | `X-Forwarded-For: <真实IP>` + 第二条伪造 —— 让限流器与日志器取值不一致 |
| `X-Forwarded-Host` / `X-Forwarded-Proto` | 记账键是"源IP×Host"这类组合时,换 Host 即换桶 |

**注意(实测)**:记账键可能是**组合键**。已知有一类 WAF 按 `(源IP × Host)` 记账,
每桶约 30–50 发后自动恢复 → **换 Host 或等冷却即可,不必换机**(见 `waf-ban-bypass-host-rotation`)。

## 3. 配套手法(记账键之外)

- **路径变体**:`/api/login%2f`、`/API/LOGIN`、尾随 `%20` / `%09` / `%00`
  —— 限流中间件与后端路由**规范化不一致**时,限流计数被绕过。
- **TOCTOU 并发**:同一时刻并发同发 N 发,计数读-改-写竞态会漏计。
- **验证码复用 / 空 token**:验证码与 token 分离校验时,同一个有效验证码常可反复用。
- **锁定粒度**:先确认锁的是**账号**还是**IP**。锁账号 → 换密码维度(枚举);锁 IP → 换记账键。

---

## 4. 纪律(用户明确要求,必须遵守)

- **先在靶向小字典上验证通路**(几十~几百组),通过后再决定是否扩大;
  **百万级大字典要先问,不要自己开打**。
- **授权后仍要低频限速**、可随时停;用户可能随时喊停。
- 命中即**立即停**(不要跑完字典),记录"哪一组 + 响应体差异"。
- 自研小后台(Go `404 page not found` 风格、单一 `/api/login` 返回 JWT)常见
  **登录接口零锁定 + 仅按 XFF 记账** —— 这类系统值得优先用本手法测一遍。

---

## 5. 顺带:用户名枚举 oracle

登录失败文案**区分"用户不存在"与"密码错误"**时,先枚举用户名,再只对存在的账号打密码:

- 例:`{"msg":"record not found"}` = 用户不存在(可枚举);
  存在但密码错会返回另一种文案。
- 反过来,**文案统一**(如都返回"用户名或密码错误")= 无枚举面,直接双维度打。

QXXT 案例:自研 Go 命令服务器文案统一(无枚举面),但**无限速**;
同网段的 Next.js 面板(FRP-Panel)文案区分(`record not found`)**且有枚举面**,
两条路都值得各测一次文案。
