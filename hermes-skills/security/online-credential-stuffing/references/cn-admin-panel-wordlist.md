# 国产后台/白标代理后台:靶向口令字典与在线核查

适用形态:后台是 **layui** 皮肤,API 基址形如 `/api/<app>/proxy/login`,
表单字段 `userName` / `password` / `captchaId`;
失败体 `{"msg":"用户名或密码错误","status":103}`(但 **HTTP 200**),
成功体含 `token` / `perms` / `roleNames` / `proxyType` / `minBet` / `maxBet`。

> **不要因为签名没解开而卡住**:前端 `sign = md5( sort(params + "&appKey=" + project) + "&key=" + <常量> )`
> 只挂在**登录后的**请求上;登录表单本身不签名。投影参数 `project` 取不到不影响口令核查。

---

## 1. 可行性三发判据

| # | 测什么 | 怎么测 | 结论 |
|---|---|---|---|
| 1 | 验证码是否真校验 | 用**首页 JS 里写死的 `captchaId` 常量**提交任意错口令 | 回"用户名或密码错误"→ 服务端不校验验证码,**可打**;回"验证码错误"→ 先破验证码 |
| 2 | 锁定策略 | 同一用户名连错 3–5 次,看第 4/6 次是否变锁定文案 | 始终同字节 → 无锁定 |
| 3 | 枚举 oracle | 必然不存在的用户名 vs 很可能存在的用户名,失败体**字节级**比对 | 完全相同 → 无 oracle,**靠命名规律构造用户名** |

**失败体必须留档** —— 它是后面所有判定的基线。

## 2. 用户名字典(按命中概率排序)

1. **品牌前缀族** —— 品牌 2 字母前缀 + 数字/角色后缀:
   `la` `la1`–`la99` `la001`–`la020` `la888` `la666` `la168` `la518` `la999`
   `laadmin` `lala` `lalala` `lavip` `laagent` `lastaff`
2. **站点域名族派生**:`<brand>t`(面板) `<brand>client`(分发站) `<brand>let`(对象存储)
   `<brand>com` 数字官网域 —— 运营商自有域名族**同前缀**;随机串域名一般是第三方 SaaS(别打)

   `owner` `operator` `op001` `service` `kefu` `kf01` `agent` `agent001` `agent888`
   `daili001` `houtai` `guanliyuan`
4. **纯数字代理号(国产后台高发,最常被漏)**:
   `1001` `10001` `100001` `800001` `88888` `66666` `11111` `2025` `2026` `520520` `1314520`
5. **备案主体** —— 查工信部备案主体(个人主体尤其),取姓名拼音全拼/缩写 + 数字:
   `guotao` `guotao123` `Guotao@123` `gt123456` `taoge123`

## 4. 规模与分梯队

- 总组合 **2–3 千**(向用户报备后执行)。**靶向小列表(百级)是默认授权;百万级大字典会被否。**
- **梯队A**:高概率 10–16 个用户名 × **全量**口令 → 2000+ 组合,期望值最高,先跑。
- **梯队B**:其余 80–100 个用户名 × **前 40–50 条**高频口令。
- **梯队C**(纯数字代理号 / 大小写变形 / 主体拼音变体):**必须另存脚本与独立列表文件**,
  否则会改动梯队A/B 列表下标,把续跑打错位。

## 5. 运行纪律

| 纪律 | 原因(机制) |
|---|---|
| **开跑前冻结列表** | 续跑按 `--start` 下标;增删行/改序 → 序列错位,重测 + 漏测,结论不可复现 |
| **第一发就低频**(≈2 req/s,6 线程) | 突发几十发即触发**按出口 IP 的长窗口封禁**;触发后 60 秒/发也被拒十几分钟,只能换出口 |
| **`HTTP 000`/空响应重试 2 次** | 代理/TLS 抖动;直接记异常会让熔断器提前触发 |
| **连续 8 次非预期响应即熔断落盘** | 区分"口令全错"与"已被封";不熔断会白跑并把结论写错 |
| **命中即停,落盘完整响应(含响应头)** | 后面要用返回的 token 打管理端点验证最终业务状态 |
| **进度 JSON + 追加式日志** | 父 shell 被杀后仍能续;`nohup ... &` 会随父 shell 死 |
| **速率/线程数写进报告** | 授权范围内的节流证据 |

## 6. 请求样板

```bash
curl -skS --compressed -m 20 -X POST \
  'https://<panel-host>/api/<app>/proxy/login' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -H 'Origin: https://<panel-host>' \
  -H 'Referer: https://<panel-host>/' \
  -H 'X-Requested-With: XMLHttpRequest' \
  --data-raw 'userName=<U>&password=<P>&captchaId=<首页JS写死的常量>' \
  -D - -w '\n@@%{http_code}'
```

- **命中**:体含 `"token"` / `"status":200` / `"perms"` / `"roleNames"`。
- **失败**:体含 `"status":103` 或 `用户名或密码错误`。
- **其它一律 `unknown`**,记档不判定。

---

## 7. 命中之后

- 用 `token` 调管理端点验证**最终业务状态**(报表/列表接口返回真数据)—— 不是"页面进去了"。
- 平台常分层(`perms`/`roleNames`/`proxyType`):低权代理 ≠ 总后台,继续找权限更高的角色端点。
- 改口令 / 建超管 / 改库**有痕且可能不可逆**;用户偏好无痕时动手前先答"能不能恢复"。
- "验证码不校验 / 无锁定 / 无枚举差异"各算一条独立漏洞写进报告。
