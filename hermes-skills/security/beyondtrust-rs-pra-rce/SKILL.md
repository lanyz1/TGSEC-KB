# BeyondTrust Remote Support / PRA 预认证 RCE（CVE-2024-12356 + CVE-2025-1094）

**CVSS 9.8**，**CISA KEV 2024-12-19**，在野利用后才披露，公开关联 2024 年 12 月那起事件。影响 **≤ 24.3.1**（所有未打补丁的本地部署；披露时云实例也中）。修：**BT24-10**（自托管 `BT24-10-ONPREM1` / `BT24-10-ONPREM2`）。

源：`skraft9/CVE-2024-12356`（含非破坏检测器）。

## 为什么值得单列

RS/PRA 是「**把特权会话代理进内网**」的跳板设备。拿下一台，就等于拿到它背后每一条被代理链路的入口。设备常年挂在公网，单发匿名请求就能进。

## 两条洞叠起来

1. **CVE-2024-12356 — 参数注入（CWE-88）**，位置在设备的 `thin-scc-wrapper` 脚本。注意：BeyondTrust 自己归 CWE-77，Rapid7 的分析认为 CWE-88 更准。差别有实操意义——不是把命令拼进 shell，是**把恶意内容当成另一个程序的参数**。
2. **CVE-2025-1094 — PostgreSQL 字符串转义绕过**。`psql` 对**无效 UTF-8 字节**处理不当，导致 SQL 字面量提前断开——编码校验层和解析层不一致。链上之后就是 SQL 注入，再落到命令执行。

到达路径完全在认证之前：**只要能连到设备的 WebSocket 端点**，就满足全部前提。无需凭据、无需交互、无需已有立足点。

## 检测（非破坏）

```bash
python3 bt_rs_rce_check.py <host>            # 时间差分：只让目标跑 sleep
python3 bt_rs_rce_check.py <host> --oob <collector>   # 带外 hostname/HTTP 回连
```

只驱动真实利用走的那条未认证路径，止步于「可达性证明」：从不开 shell、不写文件、不读数据、不持久化。

## 判据

- 版本 ≤ **24.3.1** 且没打 BT24-10
- 登录页/设备接口指纹是 BeyondTrust RS 或 PRA
- 检测器返回时间差分（sleep 生效）或 OOB collector 收到回连 → 链通

## 可迁移的两条

1. **参数注入优先于命令注入**：看到「包装脚本 / wrapper / 启动器」先想参数位（`--flag`、`-c`、`-o`），而不是引号拼接。参数注入往往不触发 shell 元字符过滤，WAF 直接失明。
2. **编码层与解析层不一致 = SQL 字面量提前断开**：无效 UTF-8 / 非法多字节序列送进任何需要「先转义再拼 SQL」的组件（`psql`、某些 ORM、日志入库链路），都可能让转义函数算的长度与实际解析长度不一致。这是可复用的绕过思路，不限于 PG。

## 坑

- 云实例由厂商打了，本地设备不会自动升——**看到 BeyondTrust 先查版本，不要看到云就打**。
- 补丁有两个包（ONPREM1 / ONPREM2），只打一个可能仍存在链上组件。
- 设备本身是跳板，拿下后默认位置就在内网边缘——先看它代理了哪些目标，再决定往哪走。
- 检测器只证可达性，不证利用；对外报「有洞」还是「已控」要分清。
