# Ops Review — 战后复盘回写(进化闭环 A:从实战中学习)

**定位**:每次渗透/逆向/破解任务结束后(成功或失败都算)自动触发,把本场经验固化成技能库增量。这是"自进化机器"的记忆写入端——没有它,每场战斗都是孤例;有了它,下一场自动更强。

**配套组件**:cyber-ops(指挥层,任务结束必调本技能)→ intel-ingest(外部情报,定期喂新打法)。

## 触发时机

- 任务按判胜标准收口(打穿/未打穿)
- 用户说"复盘/总结一下/这次学到了什么/把这个沉淀下来"
- 子 agent 报告了值得留存的发现但主会话没吸收

## 复盘五问(先想清楚再落盘)

1. **结果**:按业务层状态,这次到底成没成?(不粉饰:中间信号 ≠ 成功)
2. **新打法**:这次用了什么以前没固化的路径/技巧?能扩成"类"吗(不是记一个点,是记一条可横向替换的打法线:攻击面×漏洞形态×利用链)?
3. **新坑**:哪些东西浪费了时间?(环境陷阱/工具误报/误判/被诱饵骗)
4. **新指纹**:目标品类有什么可复用的识别特征?(框架指纹/接口规律/验证机制共性)
5. **可迁移性**:这套东西下次遇到什么目标还能用?

## 落盘规则(类级拓展铁律,防碎片化)

| 增量类型 | 去向 | 规则 |
|---|---|---|
| 新打法(可类级化) | **合并进对应家族技能**(patch 该 SKILL.md 增加路径段) | 绝不新建窄技能;一个打法扩成家族写法 |
| 新坑/环境陷阱 | 对应家族技能 Pitfalls 段 | patch 一行到几行,带触发场景 |
| 全新攻击面/目标品类(现有 197 技能无归属) | 先对比 auto-skill-installer 远程库 → 仍无 → **才**新建技能 | 新建前问自己:这是"类"还是"点"?点不建 |
| 目标档案/平台情报 | `D:\博彩通杀\实战案例集.md` 对应章节 | 不新建章节除非新主题(守 security-skill-library 规则) |
| 高价值教训(跨域通用) | memory(长期记忆) | 会反复用到的环境/纪律类,字符预算内 |

## 执行步骤

1. 跑 cyber-ops 的 `target_triage.py "<本次目标关键词>"` 确认归属家族技能
2. `skill_manage(action='patch')` 更新家族技能(带本次真实证据,不写空话)
3. 有目标档案增量 → 追加 `D:\博彩通杀\实战案例集.md`
4. 更新 security-skill-library 镜像(若新建技能:organize_skills.py 加 CATEGORIES → 重跑 `organize_skills.py` + `gen_docs.py`)
5. 回写后重建军械库并跑路由回归，确保新打法下一场能被检索到：
   ```bash
   python3 /root/.hermes/arsenal/arsenal_build.py
   python3 /root/.hermes/arsenal/vuln_build.py
   python3 /root/.hermes/arsenal/selftest.py
   ```
6. 输出回写摘要:改了哪个技能/diff 要点/为什么这么改(一句话)

## 反模式(禁止)

- ❌ 复盘写成流水账丢进会话,不落盘 = 白复盘
- ❌ 每次成功都新建一个技能 → 技能库爆炸(用户:精简直达,家族优先)
- ❌ 只记成功不记坑 —— 坑的复用价值常高于打法
- ❌ 把"这次目标特有"的细节写进通用技能(那该进实战案例集目标档案)
- ❌ 无依据拍脑袋写"发现"——回写必须带本次真实证据(请求/字节/输出)

## Pitfalls

- 技能分两类:USER-OWNED(用户装的 zip 技能,如绫波丽101)patch 需谨慎——先看 security-skill-library 说明;curator/自建技能可自由 patch
- 中文目录/路径:git-bash 用 `/d/博彩通杀/...`,Python 内用 `D:\博彩通杀\...`
- 家族技能可能跨分类重复(如 windows-exe-crack 系列 4 个重叠)——回写时选"语义最近"的那个,Overlaps 交给 curator 合并,不要自己再造一个
