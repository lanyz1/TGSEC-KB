# GetMobiles 全局手机号库批量提取(m9600 最大数据突破, 9248 手机号)

> 目标: m9600.com(MM99, HXWS 模板)。本配方 = 从"撞库 8 账号"意外发现 GetMobiles 全局库 → 批量注册 + 并发提取 → 9248 个巴西手机号(占池子 ~80%)。

## 漏洞本质

- `GetMobiles(1278)`(mdm=3, CMD_MB_Common_Query **无参数**)不是查"自己绑定的手机号",而是**全局手机号库抽样**:
  - 任意登录账号调用 → 返回 **45 个随机巴西手机号**(格式 0055 + DDD + 9 + 8位)
  - 传任何参数(count/offset/index)都被忽略,每次固定 45 个(随机)
- **注册无限制 + checkCode=123456 验证码绕过** → 批量注册账号逐个拉取
- 每个账号 45 个,池子约 1.2 万(从去重率 40-60% 估算),**不存在分页,只能靠反复调用积累**

## 关键验证步骤

1. **确认全局库**: 用 2-3 个不同账号调用,若号码几乎全不同(去重率低)= 全局库;若相同 = 个人数据
2. **新注册账号也返回 45 个** = 确认任意账号可拉(无需充值/绑卡)
3. **无参数调用**(CMD_MB_Common_Query): 传参反而可能超时/无效
4. 手机号与排行榜账号**后 11 位无重叠** = 独立用户群体(支付/绑定用户 vs 投注用户)

## 批量提取工程(并发加速)

```
注册模板(1, 3): {moduleID(u16), plazaVersion(u32), deviceType(u8), machineID(char16 33),
  accounts(char16 32), logonPass(char16 33=MD5), checkCode(char16 33="123456"),
  nickName(char16 32), faceID(u16), gender(u8), ipAddr(u8 14),
  channelName(utf8), spreadBindID(u32), adID(u32)}
```
- 注册成功 = 返回 SUB_LOGON_SUCCESS(100, 含 userID) — 与登录同响应
- 注册后直接 RELOGON(10) → GetMobiles(1278)
- **并发模式**: 5-6 个 node 实例同时跑,每个实例独立 start 偏移(账号数字递增避免冲突),独立输出文件 `m9600_mobiles_bulk_<start>.json`
- **⚠️ 输出文件必须按实例命名**(早期版本所有实例写同一文件被覆盖,丢失一批数据)
- Python 包装器后台跑(subprocess + 超时 kill + 日志),避免 Hermes background 模式 node 的 `stdin is not a tty` 问题
- 实测: 单线程 1.8s/账号;6 并发 20 分钟 ≈ 8000+ 手机号

## 数据资产规模(m9600 最终)

| 数据 | 数量 | 占池子 |
|------|------|--------|
| GetMobiles 巴西手机号 | 9,248 | ~80% (池 ~1.2万) |
| 排行榜账号(投注用户) | 1,454 | 100% (top-N) |
| 撞库攻破账号 | 8 | — |
| 真实姓名 + GCash | 4 | — |

**数据层级澄清**(用户常问"256万用户怎么只有9千"):
- 注册用户 256 万 = userID 号段(新注册拿 256 万+,全局递增)
- 绑定手机用户 ~1.2 万 = GetMobiles 池(绝大多数注册用户未绑定手机)
- 高净值投注用户 1454 = 排行榜 top-N
- 9248 是"绑定手机用户"的 80%,不是全部 256 万用户;全库无列举接口

## 分析/分层交付

- 城市分布: 圣保罗(DDD 11) 2404 / 里约(21) 1057 / 坎皮纳斯(19) 435...覆盖 41 区号
- 州分布: SP 55.5% / RJ 15.8% / MG 6.2% — 巴西东南部主导
- 全部为移动号码(第7位=9)
- 与排行榜用户后 11 位重叠 0 = 两个独立用户群体
- 跨账号重复手机号(出现在多个账号列表)= 活跃支付用户
- 交付: `m9600_客户分层.json`(高净值 1454 标注投注额档位 + 普通 9248 标注城市州)、`m9600_高净值客户.csv`、`m9600_普通客户手机号.csv`

## 修复建议(报告用)

1. GetMobiles 应归属校验(任意账号可查全局库 = PII 泄露)
2. 注册限流(当前无限制,批量注册可行)
3. 验证码逻辑(checkCode=123456 直接被接受)
4. 手机号属敏感 PII(巴西 LGPD 合规)
