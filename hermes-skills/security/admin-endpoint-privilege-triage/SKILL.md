# 管理端端点权限定级

## 适用场景
- `/api/<Module>/Get*` 匿名返 401，手里只有一个**普通会员**令牌
- 已经用低权令牌打进了一批「管理端」接口，要回答老板那句「你到底拿到后台没有」
- 要避免把「配置读权限」当「管理员权限」交上去

## 1. 401 不是终点，换令牌再打
`[Authorize]` 在 ASP.NET Core / Furion / 大量自研网关里**只校验“已认证”**，不校验角色——除非显式写了 `[Authorize(Roles=...)]` 或 policy。
**同一个 401，在无 token 和有低权 token 之间不是一个结论。** 无 token 那批 401 天然不能证明端点受保护。

第一动作：拿普通会员 token 重打同一批 URL。

## 2. 判据：只改 Authorization 头，比字节数
```
GET /api/Manage/GetX      无 token  -> 4xx
GET /api/Manage/GetX      低权 token -> 200 / 86,850 B
```
- **响应体大小变了（10,222 -> 15,362 B）= 服务端读了身份、返回了不同数据集、但没有判角色**——这比单看 200 更强，说明它会按身份裁数据
- 变 200 但字节数与匿名版**完全一致** → 先当「仅需登录」，别急着写越权
- 只改一个变量（Authorization），其他头/参数/方法全部固定，否则归因不成立

## 3. 方法不匹配陷阱（漏报的元凶）
Furion / 部分 ASP.NET Core 路由对**方法不匹配也返 404**，与「action 不存在」无法区分。
只跑 GET 枚举会系统性漏掉 POST-only action。**一律 GET+POST 双打**，否则 action 表永远不全。

判存在性用三条：`404 vs 非 404` + `响应体大小` + `解密后结构是否合法`。

## 4. 开了不等于拿到了后台（必须回头定性）
拿到全量 200 后逐条解包，给这个控制器贴一个**数据面标签**：

| 数据面 | 典型 action | 能不能交 |
|---|---|---|
| 站点配置 | 支付通道、银行名录、维护公告、菜单、版本、样式包 | 只能写「配置读权限」 |
| 用户面 | 用户表、实名、手机、银行卡 | 可交 |
| 资金面 | 订单、充值、提现、余额变更 | 可交 |

实盘：`Manage` 控制器全套 8 个 action 全是站点配置（88 条支付通道 / 676 条银行 / 82 维护项 / 84 字段站点配置），**零用户数据**。
**「管理端控制器」这个名字不等于管理后台。** 后台是独立部署的服务，不在主站、不在子域、不在主站所有端口上——这三条要用扫描数据写进报告。

## 5. 参数绑定覆盖：先证明 `?id=` 有没有进 SQL
想用 `?id=` 做跨租户 / 跨用户 IDOR 前，先做**宽区间字节比对**：
```
id=1 .. 300  → 全部返回同一租户配置，字节数完全相同
```
则 owner/tenant 是从 **token 或 Host 派生**的，`id` 没进查询条件。
报告写成「参数未参与查询，该面不可达」，**不要写成「IDOR 已试，不成立」**——后者会误导后续接手人以为只是没猜对 id。

## 6. 交付物对标（每次汇报强制）
老板给了明确交付物（例：后台权限 / 全站用户数据）时：
- **每次汇报第一段先对标两个交付物**：各自前进多少、还差什么
- 新打出的横向资产（租户矩阵、旁路主机、旧版本系统、CDN）标成**过程产出**，不得写成进展
- 只写「发现了 X」不写「X 是不是老板要的」= 会被问「你现在弄的是我给你的目标吗」
- 结论分三级：`OBSERVED / INFERRED / UNKNOWN`，不把推断当观测报

可直接套的汇报骨架：
```
交付物 A（后台权限）：已拿到 ___，未拿到 ___，差 ___
交付物 B（全站用户数据）：已拿到 ___，未拿到 ___，差 ___
过程产出（不计入交付）：___
被证伪的路：___ （证明穷尽，不是没试）
下一步唯一可行方向：___
```

## 7. 穷尽证明（让「没拿到」变成可信结论）
交不出去时，交付一份**「被证伪的路」表**，每条含：假设 / 实测 / 结论。这比堆砌新资产有说服力得多。
例：

| 假设 | 实测 | 结论 |
|---|---|---|
| `GetUserByUid?uid=` 可枚举 | 全部返回同字节数 self 数据 | 否 |
| `?id=` 跨租户 | id=1..300 字节完全相同 | 否 |
| 管理端在其它端口 | 27 端口全 302 到同一 nginx | 否 |
| 旧版系统无鉴权 | 仅 `Common/Activity`，全走 Session 返 `-2` | 否 |

## 陷阱
- 只拿匿名响应就下「需要管理员」的结论，漏掉真正的 BFLA
- 把序列化类型名当漏洞：`/Common/GetCompanyInfo` 返 200 + 37 B `Vendor.Models.X.CompanyInfo` = **方法执行了但 model 为 null**（参数缺失/无 Session），不是「无鉴权可读数据」。后续所有 action 全返空就能证实
- 拿到 200 就收工不分类数据面 → 交上去被问「这不就是配置吗」
