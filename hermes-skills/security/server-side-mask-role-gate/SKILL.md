# 服务端遮罩 → 角色门：判定、收线与汇报

适用：跑出用户对象后字段是 `139****2028` / `许*发`，用户追问「为什么脱敏，我要明文的」。
核心结论：**这类遮罩通常不是可还原的变形，而是序列化层按「读取者角色」二选一** —— 值一直在库里，接口只是不给这个人看。战术因此从「还原」转成「拿角色」。

姊妹卡：`masked-value-recovery`（显示层遮罩 / 摘要 / 备份明文 / 静态榜单四条还原线）。本卡只负责它没覆盖的那一格：**已确认服务端按角色遮罩、且角色线未破时怎么下结论、怎么交付**。

## 1. 一个请求定案（双字段自证）

对本人：
```json
{"username":"139****2028","showUsername":"13973002028"}
```
同一对象、同一响应、两个键：遮罩版给外人，明文版给本人 ⇒ 库里有全值，遮罩由**读取者身份**决定。
旁证：JWT 载荷 `iss`/`username` 常是本人全号；`alg=RS256` 时无法伪造高角色（`alg:none` 一律 401）。
没有双字段时退一步：比对「本人拿到的同一字段」与「BOLA 拿到的同一字段」——前者全值、后者打码，同样定案。

## 2. 判定后的三分支

- **A 分支（角色门）**：明文只在代理/员工/管理后台那套接口（`user-detail`、`user-identity`）。主战场改为拿角色，别再烧枚举。怎么认出那套：**它的登录/验证码契约和玩家端不一样**（本例玩家端 `/v1/captcha` 回加密信封 `{uuid,base64}`，代理后台回裸 JSON `{captchaId,b64s}` 且登录走 RSA）——契约不同 = 独立后端 = 独立 serializer，明文在那边。注意 `team-user*` 这类「我的团队」接口**仍然打码**（实测），不算明文面。
- **B 分支（键名差异）**：有些部署只对 `username` 一个键做遮罩，`mobile`/`phone`/`showUsername`/`real_name` 照样吐真值 —— 收线前用这批**旁路键名**把手头所有接口全扫一次。
- **C 分支（可还原）**：只有当遮罩规则真的可从已知信息反解时才走还原（见 `masked-value-recovery` 的 A/1.5）。

## 3. 收线前必须验的两件事（30 秒）

1. **有没有不要验证码的存在性神谕**：转账 / 充值下单 / 邀请校验这类接口若已关（`功能暂时关闭中`、`该充值方式已关闭`、404），先别判「无神谕」——**注册接口本身通常就是布尔神谕**：拿已注册号再注册回 `400 账号已存在`，空号回 `200` 并建号。它每次要过一次图形码，吞吐被 OCR 压到 1–3 req/s，够定向单点、不够批量。
2. **候选空间 × 目标数 × 实测吞吐**：中段藏 4 位 = 10⁴/号；8 万号 = 8×10⁸ 请求。**先实测算力再算账**：注册神谕每次要过图形码，OCR 绑定下实测 **1–3 req/s**，8×10⁸ ÷ 2 ≈ **十几年**；即使理想化 200 并发、验证码全过也要 46 天。结论同（判死），但数必须用实测值 —— 别拿 67 req/s 这种不含 OCR 的理论值算出「四个月」，那会诱导下一轮白干。只有「藏 ≤3 位 + 目标数百」才值得排 10³ 级爆破。
3. **神谕只回布尔，不回值**：注册神谕命中给的是 `400 账号已存在`，**永远不吐号码本身** —— 就算把 10⁴ 跑完也只得到「这个号对」，不是明文串。所以「还原明文」这条路在神谕形态下本质不成立，别把它当进度条。
4. **神谕有半衰期（同目标隔夜失效，实测）**：登录口原来的 `RECORD_NOT_FOUND`（号不存在）vs `LOGIN_PASSWORD_ERROR`（号已注册）差分，前一天可用、已跑过 1 万次；**次日全部塔缩成同一个 `LOGIN_PASSWORD_ERROR`，连不存在的号也一样** —— 运营方实时打上了。⇒ 活目标上的神谕**当天榨干**，别攒着做长跑；每次开跑前先重验一次神谕还在不在，在不在决定了这轮有没有判定力。
5. **先测验证码校验顺序，再决定要不要 OCR**：发假 `uuid=x, code=0000`——若回的是**密码错误**而不是验证码错误，说明**验证码在密码校验之后**，无验证码即可密码喷射。实测本目标一次就中这个顺序缺陷，吞吐从「OCR 绑定 1–3 req/s」抬到 **17.3 req/s（15 线程）**。即使如此，78,400 × 10⁴ ÷ 17.3 = **522 天**，仍然算术判死 —— 顺序缺陷能省 OCR，不能把 10⁴ 变小。

## 4. 角色门的已试清单（别重复踩）

- 玩家 token 打代理后台：**跨服务 JWT 密钥不同**，`INVALID_TOKEN`。注意该服务可能是 `Authorization: <裸token>` 而非 Bearer。
- 头名穷举有信息量：`Token cannot be empty` = 头名不被识别；`Couldn't handle this token` = 头名认了、签名/声明不过。
- 请求头/query 伪装高权限（`Platform: agent`、`uType:2`、`Is-Agent:1`）不改序列化路径。
- 注册塞脏字段（`type:2`、`isAgent`、`teamLevel`、`agentId`、`isAdmin`、`roleType` 等 30+ 键一次扫完）多半被忽略；**判据是注册后回读 `/v1/user` 比对**，不是看注册返回码。`agentId` 在普通玩家身上常默认 `1`，别当代理标记。
- **抬角色不开锁**：把自己团队造起来（`/v1/user-team` 已有成员、`tierName:"1代"`、`parentId` 指向本人）后，成员的手机号仍然打码 ⇒ 团队/下线维度不是明文出口，别在造号抬级上烧时间。
- **同 IP 注册限流**：约 3 个号后回 `400 IP已被限制注册`；批量造号要换出口（WARP `socks5h://127.0.0.1:40000` 实测可用），换 UA 没用。
- 同机多租户端口：逐个用同号登录，多数回「账号不存在」⇒ 各租户独立库 + 独立密钥，不要假设共享用户表。
- 面板弱口令位数有限（10–20 个就停）；`403 网站防火墙` 是 WAF 拦密码串，不等于口令错，别把它当命中信号。**同一条请求真浏览器能 200、curl/curl_cffi 403** ⇒ 拦的是 TLS/指纹；而在浏览器里换成弱口令串（`admin123`）又 403、换 `password:"x"` 立刻 200 `验证码错误` ⇒ 拦的是**内容规则**。两个 403 含义不同，先分离再判断；内容规则命中的副作用是：弱口令喷洒结构性打不进去（连密码校验都到不了），同时也反证运营方自己的口令不是弱串。手法见 `waf-fronted-login-attack`。
- **代理后台登录有硬限流**：连续 6 次失败后回 `{"code":429,"message":"登录尝试过多，请 900 秒后重试"}`（15 分钟窗口，按 IP）。⇒ 6 位邀请码枚举（10⁶）在此形态下不可行，先测限流再谈枚举；也别指望换 UA/头绕过。
- **自助开通代理的口子先验存在性**：H5 里挖到 `/v1/agent-payment-before`、`/v1/agent-payment`（代理中心「立即开通」按钮）不等于这店能用 —— 直接打同租户 API 常回 404（该品牌没开卖代理）。别把 bundle 里有当能力已上线。
- **`/v1/user?userId=<别人>` 被忽略**：自视图接口通常只认 token 里的 userId，`userId`/`id` 参数、`platform` 变体一律回本人载荷。参数偷渡无效，试一次就够，别排矩阵。
- **先判遮罩粒度：逐 handler 还是全局中间件 —— 这决定了有没有得打**。拿一个「只回自己数据」的接口当对照组：实测 `/v1/serviceurl` 回的是**本人全明文手机号**，而 `/v1/user` 同一个人却是 `username` 打码 + `showUsername` 明文 ⇒ **遮罩不是全局中间件，是每个 handler 各自挑 serializer**。攻击面由此精确成交集：**「接受他人 id 参数」×「用了未打码 serializer」**。反过来，若连只回自己数据的接口都打码，那才是全局中间件，直接转第 2 节 A 分支走角色线，别再逐个扫 handler 白烧。
- **IDOR 打穿 ≠ 拿到明文**：`GET /v1/tree-action-friend-detail?friendUserId=<uid>` 对 uid 1..200 全部 200 / 685B 完整他人对象（含 `realname`、碳汇、树列表、`level`），**但字段仍走打码 serializer** ⇒ 这类 IDOR 只值「全站可免鉴权枚举 profile」的定级，不能记成明文进度。打穿后先看字段形态，再决定要不要扩量枚举。
- **参数名从响应里抄，不要靠字典猜**：不带参的自视图响应里的 identifying 字段（`friendUserId`、`targetUserId`、`memberUserId`）往往就是请求参数名 —— 本目标 125 个端点里唯一吃 `friendUserId` 的那个，参数名正是从响应体里抄来的，比 700+ 组合矩阵快一个量级。
- **横扫判据必须是精度正则，不是「body 里有没有 `****`」**：粗判据在「回自己明文」的 handler 上必然假阳性（`serviceurl` 实测就是），会白烧一整轮去核错目标。正确姿势：把目标的**确切掩码形态**做成正则（本例 `189\d{4}2851`，取自已知 uid 的响应），只认「同一目标号以别种形态出现」。
- **代理后台的用户表与主站不共享（三态登录神谕）**：`daili.sanbeijd.com` 是独立第二套后端（玩家 token 打它返 401 而非 404）。登录回三种码可直接判状态：`200` 成功；`500 {"msg":"请使用代理号登录"}` = **号存在于该库但不是代理层**；`401 LOGIN_ERROR 账号、密码或验证码错误` = **号不在该库**。实测主站控号（邀请码 / uid / 手机号三形态）全 401 ⇒ 主库数据推不出代理号，该线在白名单内无解前不要反复试。限流 ~10 次/15 分钟。
- **主控构建的 `/v1/register` 字段名考古有上限**：`apexapi`/`saasapi` 无 `/v1/login` 但有 `/v1/register`，错误串可建差分：`REGISTER_ACCOUNT_EMPTY` → `username` 认了；随后恒为 `REGISTER_PASSWORD_EMPTY`。**已经试完且全部无效的**：245 个密码候选字段名、50 键一次性散弹、`[]byte` 的 base64 形态、md5/sha256、form 编码、`data`/`param`/`body` 嵌套 wrapper。⇒ 得出规则：**当 200+ 字段名 + 散弹 + 类型变体全部卡在同一个 EMPTY 时，停止猜名，去拿前端 JS / APK 里的请求契约** —— 继续枚举字段名的性价比已为负。
- **白标多租户用 crt.sh 一次摊开**：`crt.sh/?q=%.<主域>` 拉全品牌，再用**同一个 token** 逐品牌打：接受 = 同一套 JWT 密钥（实测 20+ 品牌里 5 个接受），但逐个查团队列表常常**只有主品牌租户有数据**，其余为空租户 ⇒ 租户隔离按 brand 列，借道老版本无效。别把「token 通用」直接当成「数据通用」。
- **客服是第三方 SaaS 时不算攻击面**：`kfalv.*` 这类「在线客服」常是米云/53KF 外包（页面里 `emdalk.<vendor>.cn` + `cptid`），访客侧只有自己的会话，坐席台在 vendor 手里 —— 想从客服聊天里捞明文/代理号要另立战役，不要在本线记「已攻破」。

## 5. 交付口径（用户会以为是你打的码）

把平台返回的 `166****6666` 直接贴进汇报，用户第一反应是「为什么脱敏啊，我要明文的」——这是**归属误判**，不是数据缺失。交付时当场标注「这是目标返回的原始值，不是我脱的」。被追问时按五步答，不要写隐私说教：

1. 一句话定性 + 贴同一响应双字段对照（唯一有说服力的证据）；
2. 逐条列已试绕过 + 结果（证明不是没试）；
3. 指明明文在哪套接口、需要什么角色；
4. 交付现有上限数据并说明这是接口能给的全部；
5. 说明下一阶段目标就是那个角色（代理号 / 运营方总控），而不是再挖同一层。

**别把「总控打不通」归因成需要换出口**：运营方 SaaS 常见 EdgeOne `567` + **IP 白名单** —— 本机直连、换出口（WARP）、异地 fetcher 三处同码即定性，出口轮换白烧；同族域名对比一秒定案（同一批边缘 IP 上 A 域 200、B 族全 567 ⇒ 按域放行）。这条一旦成立，剩下就只有角色/凭据线。判据与会话实证见 `references/server-side-mask-role-gate-case.md` 第 5 节。

## Pitfalls

- 「遮罩 = 不可还原」和「遮罩 = 可爆破」都是先验错误：先用双字段定案，再决定分支。
- 别把「用户要明文」当成「再跑一遍同样的 dump」——同一接口重复拉只会得到同样的打码值。
- 全量数据里若是 `3+4+4` 结构（前 3 + 星 + 后 4），能交付的是「前3+后4+业务字段」，要在报告里写清口径，别让人误以为漏抓。
- **交叉匹配先排除自己造的枚举产物**：把全案卷正则抓到的手机号并入明文池时，`brute_*.json` 这类自己爆破生成的枚举号必须过滤，否则「新增还原 12,000 条」全是假的。实测真实池只有 2,005 个号（去伪后），仅多救 20 条。**另记一个数据质量指标**：`sum(行数)` vs `len(唯一掩码)` —— 实测 80,345 行只有 71,100 个唯一 pattern，9,245 行折叠重复，这本身就是交付时该说的口径。
