## 白帽子职业操守（强制遵守）

允许对测试过程中由自己创建的数据、上传的文件和插入的记录进行删除、修改、恢复和清理，以验证相关安全风险。
禁止破坏原始业务数据、真实用户账号与会话、生产数据或超出验证目的的业务对象；禁止测试作用于生产数据或他人数据的 `delete`、`del`、`remove` 等可能删除数据的接口（包括空数组、不存在的 ID 等无害化探测），对自己创建的测试数据的删除、修改不受此限。
所有测试行为应遵循最小影响原则，在获得有效证据后停止不必要的重复利用和扩散操作。

### POC 无害化验证原则（强制遵守）

联网搜索到 POC 后，必须遵守以下原则：
1. **只验证漏洞是否存在，不进行漏洞深入利用**：验证目标是证明漏洞是否存在，不得执行植入后门、创建/删除/修改业务数据等超出存在性验证的操作。
2. **联网搜索到的 POC 必须先做无害性分析，再发包验证**：判断其 payload 与请求是否会影响目标系统业务运行或生产数据（如删除/修改/写入生产数据、重启或停止服务、执行破坏性命令、锁定账号、修改账号密码等）。
3. **禁止调用任何可能影响目标系统正常运行的 POC**：无法通过无害化改造消除影响的，不得执行，必须按规则 6 作为低风险提醒条目写入 findings，并在收尾校验文本中说明该 POC 因影响面原因跳过。
4. **有影响的 POC 必须先尝试无害化改造**：将危险命令或破坏性操作替换为无害 payload，可优先参考 `{SKILL_ROOT}/references/http-test-usage.md` 的"常用证据过滤模板"构造验证 payload（如回显唯一标识、`id`/`ipconfig` 等无害探测命令，或者读取 `/etc/passwd`、`Windows/win.ini` 等固定文件特征）；改造后必须保持原漏洞语义不变，能形成原 matcher 或等价 matcher 闭环。
5. **无法无害化回显验证时，优先使用 OOB 反连验证**：按前文"OOB / DNS 回连工具"章节执行 `dnslog.py` 闭环验证。
6. **未验证 POC 必须登记（强制）**：确认无法无害化验证（无害化改造与 OOB 反连验证均不可行）的 POC，不得静默丢弃，必须作为低风险提醒条目写入 findings：`severity` 固定为 `low`、`confidence` 固定为 `potential`、标题前缀 `【低风险提醒·未验证】`，`description` 写明跳过原因且漏洞可能真实存在、建议人工复验。这是唯一允许未经实际验证写入 findings 的情形。
