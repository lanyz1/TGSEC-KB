# ThinkPHP 3.x:报错页泄露 + 路由存在性 oracle

来源:2026-09 实测(某 MySQL 慢日志系统,ThinkPHP 3.1.3 + PHP 5.6.40)。配合 SKILL.md §5 使用。

---

## 1. 版本/路径指纹:一个不存在的路由就把部署信息全吐出来

```
GET /任意不存在的路径
→ 200  <title>系统发生错误</title>        (XHTML 1.0 Transitional 是 TP 默认错误模板)
   FILE: /home/wwwroot/slowquery/slowquery2-master/ThinkPHP/Common/functions.php  LINE: 112
   页脚: ThinkPHP 3.1.3
```

**一次请求同时得到三样东西:**

| 得到 | 用途 |
|---|---|
| 框架版本 | 直接对 CVE —— TP 3.1.3 → **CVE-2018-10225**(CVSS 9.8,`Model::parseSql` 不做过滤) |
| **应用绝对路径** | 暴露**部署目录名**;该目录名常常就是**上游开源项目名**(本例 `slowquery2-master` 正是 GitHub zip 解包名) |
| DOCUMENT_ROOT / 多实例判断 | 印证是否镜像部署,配合 phpinfo 判「两个域名是否同一后端」 |

**拿到「<项目名>-master」就去全网搜那个开源项目**(GitHub/Gitee),把源码拉下来审 ——
比盲测 payload 快一个数量级。本例据此确认该项目有 `dbinfo` 表
(`ip` / `dbname` / `user` / **`pwd`(明文)** / `port`)⇒ **读到它 = 拿全组织库凭据**,
而这类系统必须存下这些连接信息才能去拉慢日志,所以这张表必然存在。

> 这类错误页**不需要带任何参数**就能触发,是零成本和零风险的指纹,
> **优先级应高于任何 payload 尝试**。同理,Nginx/PHP 直接吐的 `X-Powered-By` 也先记下来。

## 2. 路由存在性 oracle(不用登录就能画出攻击面)

TP 3.x 的 `s=` 参数可直达 `模块/控制器/方法`,两种写法等价:

```
/index.php?s=/Home/<Controller>/<Method>
/Home/<Controller>/<Method>
```

**三分法判读:**

| 响应 | 含义 |
|---|---|
| `<h1>无法加载模块:Xxx</h1>` | **模块**不存在 |
| `<h1>非法操作:method</h1>` | 控制器存在、**方法**不存在(TP `_empty()` 的默认输出) |
| `200` + 真实页面 / 正常 HTML | 存在,**且无前置鉴权**(直接用) |
| `200` + 登录页 | 控制器存在,但**有控制器级/基类登录校验** |
| `200` + **0 字节** | 方法**存在且被执行了**,只是没有输出(空实现 / 仅供内部调用) |
| `302 → /Home/User/login.html` | 该入口要求登录 |

- **`非法操作:` 是最干净的 oracle** —— 逐个方法名判存在,不必读响应体全文。
  实测用它把 31 个方法名收敛到 2 个存活(`get` / `test`)。
- **`200 + 0 字节` 要单独归类**:它既不是「不存在」,也不是「可用的数据接口」。
  **别把它当突破口反复试参数** —— 实测对 GET/POST + `sql=`/`cmd=`/`id=`/`table=`
  等 15 组参数**全无差分**(零字节、零报错),那就是空实现。

## 3. 顺手可判的两件事

- **登录页表单字段与验证码端点从 HTML 直读**:字段名(`username`/`pwd`/`code`)和
  验证码路由(如 `/Home/Code/create_code`)写在页面里,**比猜靠得住**。
- **同一个站出现多个不同的系统名 ⇒ 是拼装/换皮**:实测同一站
  `<title>A管理系统` + `<h1>B管理系统</h1>` + 报错页标题 `C管理系统`。
  模板不是自研 ⇒ 更该去搜**上游开源项目**源码定位接口,而不是靠盲打。

---

## 4. 别急着把「登录注入」当捷径

实测 5 组经典绕过(`admin' or '1'='1` / `admin'-- ` / `admin'#` / `' or 1=1 limit 1#` / 密码位注入)
与**不存在的用户名**返回**逐字节相同**的 790B 提示页 ⇒ **零差分,判否**。

**判据是「差分校验」,不是「payload 长得对」。** 老 TP 站的登录处常已参数化或统一报错;
发现零差分就当场收手,不要换着花样重试同类 payload 烧配额(参见
`recon-discriminators/references/waf-403-vs-origin-403-and-rate-bucket.md` 的桶纪律)。
