# Oracle 证伪纪律(先证伪, 再采信)

**定位**: 渗透里大量判据是"用响应差异反推服务端内部状态"—— 锁定码判账号存在、404/500 判路由存在、参数换值判越权、时间差判归一化。这些全是 oracle。
oracle 失效的代价**不是多打一发请求**, 而是**整批结论反向**, 而且会写进报告/台账被后续轮次当事实复用(长跑里最难纠的错)。
本卡只管"采信前的证伪实验设计"; 具体打法在各家族卡(锁绕过 `password-spray-lockout-bypass`, 越权 `api-authz-idor-testing`, 加密信封 `webapp-api-crypto-reverse`)。

## 0. 铁律

1. **任何 oracle 先跑一次"必然为假"的对照**, 再跑目标样本。对照组不通过 ⇒ oracle 作废, 已产出的结论整批降级为"待复证"。
2. **判据要能区分失败态**: 只看"非空/非错"就下结论 = 把服务端按会话返的默认数据读成目标数据。
3. **结论粒度到端点/参数, 不到族**。同族里一个端点认参数、另一个丢弃是常态。
4. **截断即作废**: 批量扫描被 429/超时/中断打断, 截断点之后等于没测, 只能写"未测完"。

## 1. 锁定码 oracle(能不能判账号存在)

**失效模式**: 不存在的用户名一样计失败、一样锁 ⇒ `430/已锁定` 不含存在性信息。

**证伪协议(必做, 3 分钟)**:
```
生成 12 位随机串(小写字母+数字, 确认库里绝无)
同一随机串连打 6–7 发(每发换 XFF, 避开 IP 锁维度)
逐发记录响应码
```

| 观测 | 判读 |
|---|---|
| 随机串在第 N 发开始 430/锁定 | **oracle 失效**。锁定码与存在性无关, 此前所有"XX 存在"结论作废 |
| 随机串永远密码错误、从不锁 | oracle 成立, 可用"会不会锁"区分存在与否 |

**实测代价**: 靠 430 枚举出 4 个"存在"账号并据此排了一整轮定向爆破, 后拿随机串复测发现第 6 发照样锁 —— **全部误判, 全轮白烧**。

**同步标定阈值**: 换不同 XFF 打同一账号, 数到第一次 430 为止(实测 5 发/30 分钟, 第 6 发锁; 别信传闻阈值)。IP 锁与账号锁是**两个独立维度**, 换 XFF 只解 IP 维度。

## 2. 变体归一化(尾随空格/零宽/重音 能不能扩额度)

**错误判据**: "变体 `admin\u200b` 返回密码错而不是锁定 ⇒ 绕过了锁"。这只证明**变体有自己的计数**(锁 key 用原始串), 完全不证明它能命中真实账号。

**便宜版对照（零口令, 1 发, 先跑这个）**: 若原生账号**当前已处于锁定态**(430), 直接给变体发 **1 发**:

| 变体返回 | 判读 |
|---|---|
| 也是 430 | 变体归一化到锁定行 ⇒ 通道成立, 再跑下方完整实验 |
| 密码错(10002) | **不归一化** ⇒ 存储层是精确/binary 匹配, 变体永远碰不到真实行; 整条路当场判死 |

实测: 原生 `admin` 为 430 时, 22 个重音变体 + 组合符 + 9 种 Unicode 空格全部返 `10002` ⇒ `utf8mb4_bin`/Java `equals` 类精确匹配。注意 Java `trim()` 只剪 ≤U+0020, 所以 `admin\t` 继承锁而 `admin\u00A0` 不会。

**决定性实验(唯一可信)**:
```
1. 对变体 X_variant 灌满一整轮(如 6 发错密码, 换 XFF)
2. 立刻回头打原生 X 一发
```

| 第 2 步观测 | 判读 |
|---|---|
| 原生 X 变 430(之前非 430) | **归一化成立** ⇒ 变体是无限额度通道, 可放开打真实账号 |
| 原生 X 仍密码错 | **不归一化** ⇒ 变体碰不到真实账号, 整条路判死, 不要再枚举变体 |

**不要用时间侧信道判**: 查库与查不到的时间差常只 200–300ms, 与网络抖动同量级(两组样本 253~265ms 与 ~490ms 完全重叠, 结论为零)。

**时间 oracle 的最少样本数 = 12 发交错采样**。实测教训: 同一登录面 2–3 发就报出 `admin2026 +0.47s`、`admin888 +0.45s` 两个“信号”, 交错采 12 发后真号 0.238s / 幽灵号 0.239s —— 差值 1ms, 前两个“信号”是基线 250~600ms 抖动下的纯噪声。
规则: 每个候选用户名 **≥12 发**、与已知不存在的对照号**交错**发(不能先打完 12 发 A 再打 12 发 B, 基线会漂), 只认中位数差 > 3× 抖动幅度。不满足就写“时间面未测出”。

**「跑得很顺」不是证据**: 以“每发唯一用户名(插入组合符)”的方式跑 7,829 条口令, 全程 4.5 req/s、零 430/零 429 —— 看上去是一条无额度通道, 实际是 **0 次真实密码校验**(打的都是不存在的行)。判据: 健康吞吐只能证明你绕过了限流, **不能证明请求命中了目标行**; 后者只能由“原生账号被带锁/带响应”证明。

见 `login-lockout-profiling` 的 `references/collation-fold-control-test.md`(完整变体矩阵与限流键控实验)。

## 3. 端点存在性 oracle(404/500/400 多义)

**失效模式**: 把"统一兜底状态码"当成"路由不存在"。同一个 500 至少三种来源: ①路由确实不存在 ②加密/明文通道用错 ③签名过滤器抛异常。

**三态标定(扫字典前必做)**: 先选三条**已知**端点各打一发 —— ①存在+需鉴权 ②存在+免签/免加密 ③确实不存在 —— 把三者的(状态码, body 文案, 长度)记成基线表。扫描结果只有落在这三格里才有意义。

**方法维度不可互换**: 实测自定义签名族(如 `X-XL-Signature`)只对 POST/PUT/PATCH/DELETE 计算, GET 完全不签 ⇒ 同一路径 GET 返 400「未登录」、POST 返 500, 两个码分属**不同层**。顺序永远是: 先分方法 → 再分签名层/鉴权层/业务层。

**反面样本**: 128 条路径字典扫出"0 命中", 看着干净, 实际是兜底 500 被读成"不存在" —— 标定前三态之前, 这个 0 是噪声不是结论。

## 4. 参数丢弃 oracle(三值差分)

判"服务端是否忽略我的越权参数"要做三发, 不是一发:

| 发法 | 真越权表现 | 参数被丢弃表现 |
|---|---|---|
| 不带该参数 | 报缺参 / 返自己 | 正常返自己 |
| 目标值 | **目标的数据** | 返自己 |
| 随机垃圾值 | 不存在 / 空 | **与上一行逐字节相同** |

- **必须核对响应体里回述的对象标识**(`uid`/`userId`/`phone`), 而不是只看"载荷非空"。
- **限流截断作废律**: 参数扫描被 429 打断时, 截断点之后的参数**等于没测**。一次 26 参数扫到第 8 个被 429, 差点写成"参数全被无条件忽略" —— 实际只测了 30%。重跑按端点记 `已测/未测`, 未测项不许进结论。
- 差分结论要标注它是在哪个**请求配方版本**下取得的(签名错/漏头/信封错时, 中间件会用同一个错误码盖掉全部入参差异)。

## 5. 关系维度: 树/链类接口的越权判定

直系字段(`userId`/`phone`/`parentId`)被无条件忽略时, **关系接口仍可能是 PII 出口**。

1. **先自建一条真链再测**: A 注册 → 拿 A 的邀请码注册 B → 拿 B 的注册 C。空账号测 `level=2` 必返空, 无法判读; 只有真链能区分"参数被忽略"与"层级递归有效"。
2. **`level`/`depth`/`generation`/`includeChildren`/`recursive`** 逐个加。实测 `level=1` 出儿子、`level=2` 出孙子。
3. **越权边界判据**: 递归再深, 只要结果集 ⊆ 自己下线, 就是**设计功能, 不是越权** —— 定性写"PII 明文出口 + 展示层未打码", 别硬报 BOLA。
4. **先跑 PII 正则再谈别的**: 该类接口常回**完整手机号(不打码)**+ 实名状态 + 投资额, 是"A 拿名字 / B 拿 ID / C 拿证件"组合链里最容易白拿的一环。
5. 拿不到别人的树时**不要再刷同族参数**, 转上游(管理员侧 `team/relation`、导出接口)。

## 6. 报告口径

- 结论分**已确认 / 疑似**两栏, 疑似项必须写清"缺哪个证伪步骤"。
- oracle 未标定前得出的数字标注 `oracle 未标定`, 不许进"已确认"栏。
- 被推翻的旧结论要**显式作废**(写进台账), 否则下一轮读到当事实继续复用。
- **已经口头宣布过的“突破”也要撤回**: 绕锁/枚举类突破在证伪后必须主动向用户说明“上一条结论作废 + 实测证据”, 不能默默改口; 撤回成本 < 拿假突破推三天。宣布前先跑 §2 的便宜版对照(1 发)。

## 7. 实验完整性:别让测量动作把测量本身杀掉

铁律 4 的硬件副作用版:一次“什么都没输出就 exit -15 / SIGTERM”的工具调用, 不是结论, 是**实验没跑** —— 绝不允许拿它的空输出当“已测无差异”。

最常见的一例:同一命令里 `nohup python3 -u runner.py &` 启后台任务, 接着 `pkill -f "runner.py"` 停旧实例 —— **pkill 把调用它的包装 shell 一起匹配杀了**( -f 匹配完整命令行, `bash -c '... runner.py ...'` 里就含这个串)。现象就是 `exit_code: -15`、零输出。

固定写法与配套纪律见 `references/background-runner-start-and-kill-safety.md`。
