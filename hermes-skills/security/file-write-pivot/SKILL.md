# File Write → Execution Pivot

For platforms that expose a write path (upload service, bug-report/attachment endpoint, template or export upload, config write) with no read-back, and for upload-bypass work generally. A write primitive is a strong finding and a weak shell — this skill separates the two.

## Always-on rules

1. **Never report a write primitive as a shell.** RCE requires proving all three: the path is inside a docroot/executable path of a server you can reach, that server's runtime executes the extension you wrote, and the magic prefix does not break parsing. Prove with a marker request (`GET /<planted>.php?c=id` → command output). Otherwise the honest finding is "arbitrary file write as <user>, execution target not identified".
2. **The writer's filesystem is not the host you reached it through.** Map it, don't assume it.
3. **Every 200 is not your file, and "my write never shows up" has an ordered list of causes — walk it in order.** Catch-all SPAs answer 200 + index.html for any path; compare body hash and `Content-Type` before believing a fetch-back. When a planted file is never served, the cause is, in order of frequency: (a) you wrote outside the real docroot — very often the *parent* of a per-site docroot, so locate the true DocumentRoot first (a per-directory config write that takes effect while payload files 404 is that same fact seen from the other side); (b) the file is served but only on one vhost/IP — enumerate every `Host:` on every candidate IP; (c) genuine multi-origin divergence — pin the origin (unique tag only it answers, direct IP, `Host:` header) before trusting any result. An oscillating body length on a static asset is a *weak* signal for (c): vary the request path and re-check before concluding "several origins", because edge cache variants over a single origin produce the same wobble.
4. **A trigger that never fires has a cause — find it once, then stop.** Re-planting the same cron/scheduled payload is a loop, not progress.
5. **Keep the write and the pivot separate in the report:** primitive + mapped FS + gate bypass + proof path + the one missing leg.
6. **Config-class files outrank payload files when the writer is privileged.** A per-directory web config (`.htaccess`, `.user.ini`, `.htaccess`-alike) is *consumed as instructions* by the served host, so it takes effect even when payload files are never served — and it inherits from parent directories, so it works even when the real docroot is a subdirectory of what you wrote. Deep payload-file enumeration is wasted effort next to one config write; go config.
7. **You touched live config, so the restore runs first and is verified.** A leftover hostile directive (`DirectoryIndex disabled`, a broken handler, a bad `AddType`) 403s an entire site, and a script that times out mid-loop never reaches its cleanup, leaving the target down. Write a benign baseline before probing, keep the known-good payload in a variable, restore inside `finally`/atexit, and confirm with a fetch. On resuming after any kill or timeout of a config-writing script, the FIRST action is fetch-root-and-repair, never more probing.
8. **Writes are joined onto a writer-controlled base, so a leading `/` in your filename does not travel as an absolute path.** The service does `open(join(base, <prefix>, <uuid>, filename))`; only `../`×N escapes upward. Count the depth from the relative path the service itself leaks in its error text (or by testing `../`×N against the directory oracle in the Procedure step 1), then aim at `/etc`, `/var/www/...`, `authorized_keys`. Blind-guessing absolute names produces writes that silently succeed somewhere harmless.
9. **Gate on the write's own response before trusting the batch.** A quota or rate-limit rejection returns an error object while your loop happily continues, so every later probe in that run is a false negative — a whole round can be lost to it. Require the service's success field and back off when it is absent; assert it for every file, not once per script.
10. **Establish host vs container before planting triggers.** A root-owned writer is not host root. Probe directories that distinguish the two (`/usr/src`, `/srv`, `/opt`, `/app`, `/data`, and any sibling site dir under the web root), then plant exactly one trigger and watch for the callback. A writer whose FS holds only the mounted web root is a container: `/etc/cron.d` and `/root/.ssh` are dead ends there from the start, and re-planting them is the loop rule 4 forbids.
11. **A per-directory config write is also an egress primitive.** Once `Redirect`/`SetHandler`/`RewriteRule` answer, the origin can be made to fetch a URL you own — origin-IP discovery, SSRF into its private network, and cloud-metadata reads all come from the same write. Use `RewriteRule … [P]` when the backend routes on the URI — a bare `SetHandler "proxy:http://…"` forwards the local filesystem path as the request URI instead. An unsupported proxy sub-scheme (`|fcgi://` with no `mod_proxy_fcgi` loaded) silently falls back to serving the file, so source code echoed in the body proves the handler never ran — not that it executed. **Scope of the egress:** an HTTP proxy sub-scheme reaches HTTP/HTTPS endpoints only — loopback management APIs, HTTP node RPCs, `/status` pages — and it *does* carry POST bodies, so JSON-RPC services behind a `SetHandler proxy:` are genuinely callable. It cannot tunnel a binary wire protocol (Mongo, Redis, MySQL): the length-prefixed framing has no HTTP request to ride on, so "fetch `/` then speak the protocol" does not work and is a wasted round. It is also **origin-local**: it reaches what the origin host itself routes to (its own loopback, its own subnet), not the platform's other private segments — if the internal target is a database or lives on a segment the origin cannot reach, this primitive is a dead end for *that* target; pivot. Directive recipes, the UDS socket oracle, and write-budget/pacing rules: `references/write-primitive-pivot.md` §7.
12. **A redeploy removes the shell, not the vulnerability — re-plant before calling it fixed.** A JSP/PHP written into a
    servlet container's `webapps/` (any served executable dir) vanishes when the container redeploys or restarts, while
    the *upload traversal* that planted it is ordinary application code and stays. So a previously-working
    `/api/<shell>.jsp?c=id` answering 404 means "the file is gone", never "the bug is patched": re-create whatever
    parent object the attach-upload scopes to (`POST /api/createTicket` → id, order, contract, avatar slot), re-upload
    with the same `../` depth, retest execution. First confirm you are still on the same origin — after a redeploy the
    app often moves: an IP that used to serve it now returns the container's own 404, and the wrong IP for a vhost
    answers nginx **`421 Misdirected Request`** (SNI/Host mismatch — a routing verdict, not a WAF block, and not proof
    the app is down). Re-locate the origin from the case's recorded candidate IPs × the app's `Host:` values, then
    touch the upload path.

## Procedure

1. **Probe the error envelope for an oracle** — send a path whose parent you expect to be missing vs one you expect to exist, and diff the responses. Staging-then-rename writers (`<path>` → `<path>.part`) leak the staging path: ENOENT on `.part` = directory absent; a type/magic rejection = directory exists and is writable. Walk candidate roots (`/var/www/html`, `/opt/<app>`, `/etc`, `/root/.ssh`, `/var/spool/cron`) through it to map the writer's FS.
2. **Locate the writer** by planting a uniquely-named file and fetching it back from every candidate IP **and every `Host:` vhost** on each IP. Repeated absence for host-specific paths plus an existing `/root/.ssh` usually means a container with its own root FS.
3. **Bypass the content gate** — magic-byte checks are prefix checks. Prepend a real header (`\x89PNG\r\n\x1a\n`, `\xff\xd8\xff\xe0...`) and keep the payload after it. Check whether the gate validates the whole file or just the prefix, and whether it keys on extension, Content-Type, or both.
4. **Pick the header to match the consumer** — if the file must also parse as a line-oriented config (cron, systemd, sudoers, ssh config, `authorized_keys`), a PNG prefix breaks it; use a newline-free header (JPEG) and keep the payload on its own newline-terminated line intact.
5. **Find the executing consumer** — a writable directory is not a docroot. For each candidate, confirm the runtime executes your extension and then request it. For scheduled triggers, remember `/etc/cron.d/*` is ignored when the file mode is group/other-writable, and a container has no host cron daemon at all.
6. **When payload files are never served, pivot to per-directory config.** Before concluding the FS is disconnected, prove the config path: `Redirect 302 /<unique-tag> http://example.com/` returning a 302 whose `Location` is that URL is unambiguous proof of per-directory config control — no other mechanism emits it. Then test directive *classes* separately; mod_alias (`Redirect`, `RedirectMatch`, `ErrorDocument`, `DirectoryIndex`) frequently works where `RewriteEngine`/`RewriteRule` silently does not, and `AddType`/`AddHandler`/`Options +ExecCGI` cannot conjure `mod_php` or a `ScriptAlias` that the vhost does not load.
7. **Restore the config you touched, then verify** — benign baseline, `finally`/atexit restore, fetch-back confirmation; repair-before-probe after any kill.
8. **Report the primitive and the missing leg**, then keep hunting the leg (reachable docroot, the host that consumes the file, a working trigger).
