# 支付/出金闸门阶梯判读

用于：代付/代收/出金类 API 一发就被拒，需要判断“到底卡在哪一道门”而不是盲目换参数。
厂商专项细节见 `pentest-execution` 的 `references/fenghuang-fhsys-platform.md`、`references/daifu-platform-attack-chain.md`（均为用户自有技能，本技能不复制其内容）。

## 核心原则：错误文案顺序 = 校验代码顺序

**逐个读回显，就能定位自己卡在哪一门。** 把不同门的拒绝混成一句“打不动”，会在已经穿过的门上反复白费力气。

| 回显特征 | 卡在哪 | 处置 |
|---|---|---|
| `…ip不在白名单内` | 商户 IP 白名单 | 先看取 IP 的函数读的是 `REMOTE_ADDR` 还是 `HTTP_X_FORWARDED_FOR`：后者可控即可在头里填在册 IP 直穿；前者死 |
| `签名不正确` / `验证失败…` | 签名 | 排序 → `http_build_query` → **是否 `urldecode` 一次** → 拼 `&key=<密钥>` → md5 大小写；**body 必须 form-urlencoded，发 JSON 会得到各种诡异校验失败** |
| `…编码不存在` / `渠道不存在` | 下游通道码 | 通道码在库里（如 `pay_code.code` + `account_type_type='daifupay'`）；**枚举码段一轮就能画出台账**，有效码通常极少 |
| `…已日切` / `…维护中` | 日切 / 维护状态 | 这是**按商户 × 按通道**的，不是全站：同实例上 A 商户被切、B 商户可能没切；同商户换通道也可能没切 |
| `余额不足` / `账户余额…` | **前面各门全过，只差钱** | **最高价值信号**（详见下节） |

### 读法铁律

- **拿到 `余额不足` = 拿到“白名单/签名/通道/日切全部正确”的证明**。此时不要再调参数、不要再换商户试，直接去解决余额。
- **始终只看到第一门的拒绝 → 前面的参数还没对**。此时换通道/换商户/换实例全是白费。
- **每道门的取变量不同**：白名单看 XFF（可控则能穿），而回调类常常看真实 `REMOTE_ADDR`（不可穿）。**同一平台里两者并存是常态，必须逐接口看源码或实测，不能因为白名单穿了就假定回调也穿了。**
- **状态类拒绝（日切/维护）要当查询而非结论**：换商户号或通道号重试，同一实例的不同主体可能处于不同状态。

## 余额从哪来（按可行性排序）

1. **后台/代理侧上分接口**（如后台 `msqz` 一类）—— 需后台会话，通常是最终解。**按路由而不是按前端函数名找接口**：超管 JS bundle 里常给同接口另起别名。
2. **代理/码商登录后给下级加余额** —— 验证码常绑自身会话；同站可能有两套验证码端点（根级字母数字 vs `/api/` 下纯数字），**选错必回“验证码错误”**；换票据/换出口代理会毁掉会话，必须同一 session 内取图+提交。
3. **伪造入账/回调通知** —— **先确认回调的 IP 校验取哪个变量**：取真实 `REMOTE_ADDR` 的（`checkNotifyIp()` 类）头伪造无效，只有真白名单服务器能进，这条基本是死的；取 XFF 的才可能穿。**确认是前者就换路，别反复试。**

## 中转/收银台独立 PHP 前端 = 服务器侧 SSRF 跳板

支付平台常把中转/收银台拆成一批**独立 PHP 文件**（每个 `include_once './tools.php'`）部署在公开实例上，而共享的 `tools.php` 里硬编码着内网地址与加密密钥。

- **拿到源码 = 拿到钥匙**：有 AES 密钥即可自造密文，于是 `decrypt($_POST['key'])` 拼主机名、`curlPost(urldecode($_GET['notify_url']), $_POST)` 这类写法全变成**完全 SSRF**（任意 URL + 任意 body；`urldecode` 后可塞 `gopher://` 打本地 Redis 写 crontab/webshell）。
- **核心价值：请求由目标服务器自己发出，绕开你自己的出口 IP 封禁与网关白名单。** 内网地址外网直连必超时，这不是阻碍，而是必须走 SSRF 的理由。
- **专找“空判校验”**：`if ($sign !== $_GET['sign']) { }` —— 条件写了、块是空的 = 校验结果被丢弃，是未授权直通的常见形态。扫老 PHP 时固定动作就是找它。
- **改收款人类接口优先看“免锁码”同名兄弟**：同一功能常有两个文件，一个带锁码校验、一个没有。

## 封禁 vs 不存在（省时间的分辨）

公开实例被高频打过后会返回**统一大小的 403 页，且对不存在的路径也回同一页** = **IP 级封禁**（换出口 IP 即恢复）。
404 才是路径真不存在（如某接口根本没部署在该实例）。
**别把 IP 封禁读成“这个文件被挡”，也别去猜路径。**

## 作战节奏（长期任务）

- 用户说“只在目标达成后告诉我”/“等…成功了再说”时，**停发一切中间进度**：后台跑（`background=true, notify=true`），只在成功或真正需要决策的状态变化时开口。反复报“当前进度”会被当作噪音。
- 被打回时先反思是不是**节奏**问题（刷屏/空转），而不是马上换思路或写长道歉 —— **用沉默的硬活回应**。
- 可以并列展示多条攻击线 + 推荐其中一条，但**不能问“要继续还是换目标”然后等用户选**；展示完立即自己执行最高价值那条。
