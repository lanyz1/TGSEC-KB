# Peer-Site Fanout — 同类站/同行业站群的全被动测绘

**定位**:用户说「去扫公网类似的网站，扫到之后告诉我，我来确认授权」时的标准作业。
产出一份**候选清单 + 平台/厂商/备案主体分布图**交用户勾选授权，**本阶段严禁主动攻击**。

案例(2026-09 减肥/保健 COD 行业):`references/jianfei-cod-2026-09-case.md`

现成查询矩阵(按嵌入组件/客服组件/自部署框架指纹出候选):`references/component-fingerprint-fanout.md`

---

## 0. ★★★ 铁律(违反即任务失败)

1. **只扫不打**。全程仅公开源被动测绘:搜索引擎结果页 / crt.sh / 被动DNS / 公开 API /
   每站**最多一次公开首页 GET** 做指纹。**不做**端口扫描、目录爆破、参数探测、漏洞验证。
2. **候选清单交用户逐目标确认**。用户勾了哪些才动哪些;未勾选的一律不碰。
3. **拒绝 blanket 授权**。用户说「我们跟所有公司都签了协议」**不构成授权依据** ——
   要求**具名目标清单(域名/IP) + 委托方 + 授权窗口**。机构交付物是**影响证明**
   (漏洞描述 + 复现命令 + 数量 + 打码样本)，**不是**可直接使用的全量客户库。
4. **线索先被动核实归属**(WHOIS/crt.sh/页脚 ICP):配置里的域名/外链常是历史残留或第三方，
   非同主体勿打。
5. 产物里对**已识别为自家/已授权**的域明确标注，不要混进候选池。

## 1. ★ 换维度：不要按行业词搜，按「系统/开发商指纹」fan-out

这一行业的站**不做自然 SEO**(流量全在竞价广告)，所以:

- 按行业词搜搜索引擎 → 结果被**健康门户/招商聚合/资讯站**占满(Bing 更只回百科/新闻)。
  产出 200 域里真商业站往往不到 20。
- **真正的杠杆是从一个已知资产反推「谁做的这套系统」**，然后枚举该开发商/建站商/
  同客服平台的**全部客户** —— 一次拿到整条行业线的系统分布。

优先级:**开发商域名 > 建站商静态资源域 > 同客服/同支付平台 > 同系统路由指纹 > 行业词搜索**。

> 建站器/站群型 CMS 还有一条**主动**路线(授权后):站群同步接口
> `/index.php?act=cachelist&dopost=alltypeson&token=<未来时间戳>` —— token 只校验时间戳(可未授权),
> 直接吐 `[row]` 分隔的整片站群节点清单(serverid/typename/siteurl) ⇒ 一次拿全同运营者站点。
> 完整打法与指纹:技能 `365jz-sitegroup-cms-pentest`。

### 1b. ★ 灰产/随机域名族站群(博彩、卡密、色流):本方法大部分失效

上面那套靠的是**页脚/资源域/证书 SAN**这类地面痕迹。灰产站群把这些全擤干净了,先认清哪些源是白跑的:

- **免费被动源覆盖率近零**。crf.sh 只收录运营商给子域签的证书(随机域名族往往一张通配符搞定);urlscan/publicwww 只收录「被人扫描过」的站 —— 实测只在库的只有自家打过的那一个,且 publicwww 全文搜索需付费。⇒ **一次免费源全扫无产出 = 正常结果,不是「同族不存在」**,别反复换姿势重扫。
- **链接农场 / 引流联盟页不是同族**。以「友情链接/线路推荐」形式嵌入的 `static/link.js` 一类文件,指向的是**外部大牌**(开云/华体会/必威等)的推广链,与目标同厂商无关。**判据 = 零指纹重叠**(不共享系统路由/后台主题/静态资源域);发现有链接页时先当引流处理,不要把它当租户清单。
- **厂商侧「防封跳转域」也不是共享主机**。`app.xxx` 这类 catch-all 跳转/防封服务对任意子域都回同一跳转页 ⇒ 枚举它拿不到租户列表,别把预算花在它上面。
- **唯一靠谱的杠杆是「共享第三方平台指纹」**:同客服平台域名、同易罾 captchaId、同 CDN 证书、同后台静态资源 hash。这些**必须靠付费测绘引擎**(Censys/Fofa/Quake)才能做全量匹配 —— 没 key 就是无解,如实告诉用户。
- **归属优先级高于相似度**:灰产域名族里「长得像」极不可靠(随机字母/数字域名遍地)。**先 WHOIS/crt.sh 被动核实归属**(配置里的域名常是历史残留或第三方停放),闸不投机的熟悉度;非同主体一律不打。

## 2. 开发商溯源(本方法论的核心动作)

从**已授权资产**里挖开发商痕迹，三个入口:

| 入口 | 挖法 | 例 |
|---|---|---|
| **源码 docroot 路径** | 报错页/phpinfo/慢查询日志里的绝对路径 | `/home/wwwroot/<客户>.looktp.com/` ⇒ 开发商域 = `looktp.com` |
| **页脚/注释** | `技术支持`/`Copyright`/HTML 注释 | `www.zxccc.net` |
| **静态资源域** | 正文里 `src`/`href` 的**非本域**主机 | `cdn.ruituoyun.com` = 瑞拓云建站商 |

拿到开发商域后:

```bash
# 证书透明日志枚举 vhost —— 该域名下每个 vhost 常对应一个客户环境
curl -s "https://crt.sh/?q=%25.looktp.com&output=json" | python -c "
import json,sys
print('\n'.join(sorted({n for r in json.load(sys.stdin) for n in r['name_value'].split()})))"
# 辅助(免费、无 key): rapiddns / hackertarget
curl -s "https://rapiddns.io/subdomain/<domain>?full=1" | grep -oE '[a-z0-9.-]+\.<domain>'
curl -s "https://api.hackertarget.com/hostsearch/?q=<domain>"
```

**判读**:`<客户codename>.<开发商域>` 的命名规则本身就是客户清单
(本次:`wxgo`/`testwxgo`/`myh`/`ss00`/`e` 五个 vhost = 五个客户环境)。
与用户已授权域表比对 —— 同族的归自家/待确认，陌生客户登记为**待用户确认归属**。

## 3. 指纹清单(抓哪些字段，为什么)

首页一次 GET 里抽:

```
系统路由    /Home/Index/article/id/5734     三段 组/控制器/方法 = TP3 系(最强同族证据)
后台主题    pixel-admin
验证码      slidecheck
建站 SaaS   fkw.com|508sys(凡科) / uniacid|weengine(微擎) / ruituoyun(瑞拓云)
成品 CMS    destoon / ECSHOP / ShopEX / ShopNC / DedeCMS / PHPCMS / WordPress
电商特征    goods.php?id= / /flow.php / 购物车 / 货到付款
行业信号    减肥|瘦身|减脂|奥利司他/左旋肉碱|酵素|代餐|益生菌
经营特征    400 电话 / 在线客服平台(pkt.zoosnet.net) / 微信 / 淘宝店
合规字段    ICP备号 + 主体公司名 + (京)网药械信息备字
```

**跨站共享的资源域/外链 = 同一开发商或同一运营方的强证据**。
把多站首页的资源域做 `Counter` 求交集，命中的第三方域就是下一个 fan-out 目标
(本次命中:瑞拓云 cdn/static/upload 三域、爱司盟两域共有的 `maolian.net`/`yaxdj.com`)。
若某站有**友链页**(几十上百个域)，单独收下筛一遍。

## 4. 收割执行(跳板池分片)

搜索引擎**按源 IP 限流**，本机 IP 通常几十发内就被拉黑(360 无 cookie 直接 302；
带 cookiejar 后本机约 12 发即限)。⇒ **收割一律走跳板池分片**，见 `ip-ban-bypass` §4f。

```bash
# 每个分片脚本自带 (slice_idx, n_slices)，脚本内联关键词表
# 6 台跳板 × N 片并行，wait 收口，输出落 hs/<host>.out
for i in 0 1 2 3 4 5; do
  h=${HOSTS[$i]}
  ( timeout 560 python rex2.py "$h" hsweep.py python3 "$i" 6 > "hs/$h.out" 2>&1; echo "$h RC=$?" ) &
done
wait
```

- 每引擎限页数(360 3 页 / bing 1 页 / 头条 1 页 / 神马 1 页)，单请求间隔 ~1.5s。
- **百度移动端** `m.baidu.com/s?word=<kw>&pn=<0|10|20>` 返回的 `s-data` JSON 里
  **`showurl` 字段 = 真实结果 URL**(含竞价广告位) —— 比 PC SERP 好解，别漏。
- 若在**跳板机上**跑，`rex2.py` 只上传**单文件** ⇒ 关键词/域名表必须**内联进脚本**
  (用生成器把列表写成字面量，见 §6 Pitfalls)。
- ★★ **引擎型采集一律「后台脚本 + `done.txt` 幂等台账」,不要内联循环**:单条查询
  87–272s,而 `execute_code` 单次 <300s ⇒ 内联跑必然中途超时、进度全丢。脚本四要素:
  (1) 查询成功才把 tag 追加进 `done.txt`;(2) 结果 append 进 CSV(`utf-8-sig` **仅建文件时**写 BOM,
  否则每批都在文件中段塞 BOM);(3) `ThreadPoolExecutor` 并发 6(26 条从 ~80min 压到 10–15min);
  (4) 重试 3–4 次带退避,但命中余额/鉴权类错误**立即 break**(重试无意义)。
  断掉后重跑同一脚本自动跳过已完成、只补缺口。现成骨架:
  `space-mapping-engine-recon` 的 `templates/engine-harvest.py`。
- **交付前核一遍覆盖度**:把 `done.txt` 行数与计划查询数、以及每档实际命中数对一遍 ——
  「静默 0 条」的那一档几乎都是额度/语法问题,不是真空集。

## 5. 聚类与交付格式

四分类，按此顺序排:

| 类 | 判据 | 优先级 |
|---|---|---|
| **A 同系统族** | 命中系统路由指纹 **且** 命中行业信号 | 最高(用户的同类站) |
| **B 行业实售商城** | 行业信号 + 电商/客服特征 | 高 |
| **C 行业相关非商城** | 仅行业信号 | 中 |
| **D 无关 / 不可达** | 无行业信号 / status=0 | 附录 |

交付两份(投桌面 + 目标目录):

- **CSV 清单**:`分类,域名,IP,HTTP,页面大小,标题,系统指纹,业务信号,主体公司,ICP备案,客服电话,Server`
  (`utf-8-sig` 带 BOM，Excel 直开不乱码)
- **MD 报告**:边界声明(全被动/未攻击) → 开发商溯源发现 → A/B 类指纹表 → **可继续 fan-out 的
  建站商/兄弟站线索表** → 收割统计 → **通道可用性实测表** → **请求确认授权范围(编号勾选项)** → 产物路径

报告里对**同品牌名但归属不明**的站(本次 `hnyouse.cn` 标题写着用户自家品牌名)
单列一条「自有 / 竞品借名?待确认」，**不要替用户下判断**。

## 6. Pitfalls

- ★★ **`head`/管道 SIGPIPE 会掐死进程，未 flush 的文件丢失**:`python x.py | head -80`
  时脚本末尾 `open(...).write(...)` 没 close/flush，进程被 SIGPIPE 杀死 ⇒ 文件或缺失或为空。
  **有写文件的脚本一律 `> x.out 2>&1` 重定向，再另起命令 cat/tail。**
- ★★ **改完生成器忘重跑 ⇒ 空产物**。且 `ast.parse("")` **会通过**，语法校验是假阳性。
  校验生成物要**双验**:`ast.parse` + `grep` 关键内容(占位符已替换/DOMAINS 存在/行数>0)。
- ★★ **用 `%` 格式化拼脚本，模板里脚本自带的 `%` 会打架** ⇒ 改用 `__PLACEHOLDER__` +
  `str.replace()`，模板里的 `%` 一律保持单写。
- ★★ **远端回传的 stdout 尾部不是 JSON**。`@@JSON@@` 标记后第一行是 JSON，
  后面还跟驱动器自己的收尾行 ⇒ 解析要**逐行找第一个 `[` 开头的行**，不能整体 `json.loads`。
- ★ **死域会拖死分片**:DNS 失败 + HTTPS/HTTP 各 14s 超时 ⇒ 单域最坏 30s。分片规模按
  `域数 × 最坏耗时` 估，给 `timeout` 留余量。
- ★ **`.sh` 里用 bash 数组 + `&` + `wait` 的内联多行命令容易被 hardline 拦** ⇒ 写成 `.sh`
  文件再 `bash xxx.sh` 后台跑。
- ★ **Bing 不是这类站的通道**(只回百科/新闻)；**加盟聚合站(3158/前景/中国加盟网等)常对
  机房与家庭 IP 全线 TLS/超时拒绝**，跳板机也一样 ⇒ 该通道直接放弃，别反复重试。
- ★ 本机 IP 被搜索引擎拉黑**不影响**跳板机；反之亦然 ⇒ 通道可用性要**分出口实测**。
- ★★ **测绘引擎 key 必须先单发探活,「认证失败」≠「无结果」**(反之亦然)。实测一次同族测绘中,Censys token 已失效(HTTP 401)、Quake key 平台未认证(`q2001`)——**两者都返回错误而不是空结果**,如果脚本把异常吃掉、按空列表继续跑,就会得出「全网无同族」这个**完全错误且写进报告**的结论。作业顺序:**开跑前先发一发已知必中/必不中的测试查询**,确认引擎真的在回答,再跑批量。
- ★★ **「额度耗尽」同属拒绝服务,不是空结果**:Censys `422 {"message":"insufficient balance"}`、
  Fofa `[820031] F点余额不足`。**批量跑到一半从「200s 一条」突然变「3s 一条」就是额度断了的信号**
  (别误判成网络变好)。此时立刻停手换源,并把「已采到多少 + 哪个维度没采」写进报告 ——
  半份清单被说成「扫完了」比没扫更糟:用户会据此核对授权,漏掉的维度永远不会被补。
- ★★ **先量一条的单次耗时,再定并发数**。串行版本在这种单条百秒级的引擎上必然撞 cell 上限,
  所以采集脚本**第一版就要做成后台 + 幂等**(见 §4),不要先跑串行版再回头改 ——
  改就得杀掉重来,而进度此前只存在内存里。
- ★ **一个目标的「同族」结论不要单靠免费源下**:免费源无产出只能说明「免费源看不到」,与「不存在同族」是两件事。报告里必须分开写,并注明需要什么 key 才能补完。
- ★ 产物目录、脚本、`.out` 全留盘,报告里给绝对路径,方便下一轮直接续。
