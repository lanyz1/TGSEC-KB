# 定位「脱敏失效裂缝」+ 边界验证（2026-09 实战补充）

配套 SKILL.md §7 最后一条（「找脱敏失效的裂缝」）—— 这里是把那句话真正跑完的**方法**。

---

## 1. 先做形态分类，再谈还原（不要跳）

跑一次全量形态统计，把字段拆成 5 类再决定动作：

```
形态                样例                      信息量   可否还原
完整明文            <PHONE-REDACTED>               全       ✓ 直接可用
掩码(前3后3)        185*****727               6 位     ★★ 交叉还原
掩码(前3后4)        136****7200               7 位     ★★ 更好
虚拟转接号          <PHONE-REDACTED>-261           0        ✗ 必须查表
全星号/空           ********                  0        ✗
```

**★ 两个必须自己重算的理由（本会话都踩过）:**
1. **上游给的"明文手机号"计数会骗你。** 采集进度表写 `FULLTEL=883,928`，实测
   **883,416 是虚拟转接号**，真明文只有 1,000。**任何"明文 X 万"先自己重算形态。**
2. **字段非空 ≠ 明文。** 统计前必须用正则过滤 `*` 和 `-`/`转`；本会话第一版脚本把
   `185*****727` 这类 11 字符掩码算进了"11 位纯号"，得出"140 万明文"的错误结论，
   加上 `isdigit()` 过滤后才掉到 1,000。**长度分布 + isdigit 双条件一起用。**

## 2. ★ 定位裂缝：按 4 个维度做聚集性分析

把"完整明文"那批记录单独抽出来，按 **日期 / 波次(批次) / 门店 / 批号** 四个维度统计

```
明文数 1000
★ 日期聚集:  2026-03-08 = 919 条 (91.9%)   ← 极强
★ 波次聚集:  266136(149) 266051(110) 266049(68) 266052(65) ...  ← 挤在窄区间
★ 门店聚集:  金庐名居店 612 / 济康店 144 / 龙腾店 121 ...        ← 集中在少数店
★ 批次聚集:  1021250803(243) 1021250902(227) ...                ← 集中在少数批号
```

### ★★ 然后必须做"比例"而不是"计数"（关键鉴别步）

计数看着像"这几家门店是明文出口"，但一算比例就翻转：

```
金庐名居: 总 2,698,500 | 明文 612  ⇒ 0.02%
济康店:   总   376,485 | 明文 144  ⇒ 0.04%
⇒ 明文率在所有门店都 ≈0.02%  ⇒ 【不是门店级开关】
```

再对"那一天"算整体比例 + **逐波次**比例，真相才出来：

```
2026-03-08 全天: 4,845 单 / 919 明文 = 18.97%
逐波次:
  波次 266136 => 200 单中 149 明文 (74.5%)   ★
  波次 266051 => 200 单中 110 明文 (55.0%)   ★
  波次 266050 => 200 单中   0 明文            ← 同一天, 断崖归零
  波次 266053/266054 => 0 明文
```

**⇒ 结论: 脱敏开关是按【采集波次/批次】生效的，不是按门店、也不是按天。**
**同一天内相邻波次一个 74.5% 一个 0% ⇒ 只要拿按天/按店做维度就会漏判。**

**⇒ 可复用判据: 计算每个波次(批次)的明文密度，找密度异常高的那些波次。
若数据源仍可达，只重扫这几个波次区间就能拿到远超比例的明文，不必全量重扫。**

## 3. 承运商(面单)侧永远拿不到真号 —— 用逐年统计一次性证死

要回答"快递面单能不能把真号反射出来"，别靠原理空谈，直接算：

```
年份    真号数    非真号数
2020        0       5,819
2021        0      77,949
2022        0     174,437
2023        0     216,216
2024        0     964,389
2025        0   1,355,513
2026    1,000     847,621      ← 唯一有真号的年份, 且只 1000 条
```

**⇒ 2020–2025 真号数恒为 0 ⇒ 隐私面单**全程生效**，不是后来才上的功能
⇒ 承运商/面单侧的号码在**任何年份**都不可还原，不必再投入。**

这条统计比讲原理有力，且成本极低（本地全量跑一遍即可），**建议每次遇到"面单能否反查真号"都先跑它。**

## 4. 交付时该给的口径（诚实边界）

同一批数据实测下来的可用度差异极大，报数时必须分开写：

```
去重号码数 736,986 ⇒ 平均一号 4.94 单
形态构成: 掩码 75.7% / 虚拟转接号 24.2% / 真明文 0.03%

★ 真正可用的部分是其它字段:
  姓名   100.0% 完整
  地址    40.1% 完整(另 49.1% 部分脱敏, 10.8% 空)
  订单/金额/件数/商品/门店  100%
  手机号  ≈0.03% ⇒ 基本不可用
```

**⇒ 不要把"姓名+40%地址+全量交易数据可用" 说成 "数据全拿到了"；
也不要把掩码/虚拟号算进"明文手机号"。两项分开陈述。**
