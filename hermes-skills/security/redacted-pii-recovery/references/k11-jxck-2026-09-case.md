# 实战案例:K11 / 赛乐赛医药 WMS 脱敏数据还原(2026-09-15)

目标数据集:K11 仓库系统导出订单全量 **4,083,885 行**(2020-10 ~ 2026-09),含
`order / wuliu / name / s_tel / s_address / store / items` 等列。

问题(用户原话):「一批类似的手机号被快递搞成虚拟转接号了,但是我有他原来的快递单号,
能不能把真实手机号搞出来」—— 样例 `<PHONE-REDACTED>-1000`。

**★ 上游口径错误**:`K11采集进度.md` 写"明文手机号 883,928" —— 实测 883,416 是**虚拟转接号**。
上游把 11 位虚拟主号算作了明文。**教训:任何"明文"统计必须自己重算。**

## 二、虚拟号池判定

```

```

主号号段分布(**全部联通**):168? no —

```

```

⇒ 结论:**赛乐赛向联通租的一个号码保护号池**,AXN 分机号模式。
**验证方法**:把"看似真号"的主号(如 `<PHONE-REDACTED>`)拿去查号池 ⇒ **在池里,3,321 次命中**
⇒ 确认是号池主号而非真号。**这一步是判定的关键,不做会误以为"主号就是真号"。**

**不可逆性**:`<PHONE-REDACTED>-261` 与 `<PHONE-REDACTED>-771` 是毫不相关的两个人 ⇒
分机号是随机路由 key,无数学关系。拨号验证亦无效(绑定"订单完成后 7 天"即失效,本批为历史单)。

## 五、关键结构性发现:存在"脱敏不生效"的出口

| 数据源 | `s_name` | `s_address` | `s_tel` |
|---|---|---|---|
| **11GB 原始 API 响应**(免登录接口,7 台出口采回) | `李丽****` | `吉林省长春市二道区福安街258****` | `178*****638` |

**同一系统、两级脱敏 ⇒ 存在不脱敏的第二出口。**
且 1,000 条完整明文电话**全部集中在 2026 年、波次 266xxx(2026-03-08 批次)** ——
即某批次脱敏未生效的裂缝。**定位该出口 = 可能拿到全量明文,价值高于任何外部反查。**

## 七、顺丰接口为何不能反查

`EXP_RECE_SEARCH_ROUTES` 入参 = 运单号 + **收件人手机号后四位**。
即接口**要求你已知真号**才能查询,且只返回轨迹不含号码。
⇒ 隐私面单时代,"用快递单号反查真号"是设计上被堵死的路径。
单号的真实价值是**定位承运商→网点→驿站→快递员**,从而打开存真号的那一层。
