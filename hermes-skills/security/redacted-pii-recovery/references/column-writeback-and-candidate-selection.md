# 内嵌号 → 写回电话列（候选择优 + 过滤口径）

配套 SKILL.md §3、§3 的双校验法、以及 `references/embedded-number-field-scan.md`。
2026-09 K11（赛乐赛 WMS，408 万行订单 CSV）实战定型。

**触发原话**：
> 「把地址内嵌的手机号 **放到 E 列里面，做成明文手机号**，然后剩下的没内嵌的是虚拟手机号的给我排除掉」

这是 SKILL.md §3「双校验还原」的**下一步**：还原出来的号要**写回原文件的电话列**，
并按「拿不到明文号就剔除」过滤整行。口径不对会直接产出错表 —— 本节把口径固定死。

---

## 1. 多候选择优顺序（一条地址里常不止一个号）

真实地址样本里同时出现本人 + 代收人 / 驿站 / 店员 / 店家：

```
四川省自贡市荣县附西路279号，陈平<PHONE-REDACTED>                  ⇒ 本人（末尾）
广东省深圳市龙华区…前通工业园（老公吴刚收<PHONE-REDACTED>）          ⇒ 本人（括号内）
黑龙江省绥化市海伦市鑫淼缘服务社部B072站号<PHONE-REDACTED>          ⇒ ★ 服务社的号，不是本人
```

**择优顺序**（实现见 `scripts/embedded_number_column_writeback.py` → `pick_number()`）:

| 序 | 条件 | 取值 | 本轮命中 |
|---|---|---|---|
| 1 | 电话列本身已是完整明文（且不是号池主号） | 直接用原值 | 1,000 行 |
| 2 | 电话列是掩码（`1xx****xxx`） | 取**通过前 3 后 3 双校验**的候选；多个命中取**最后出现**的 | 11,244 行 |
| 3 | 无掩码 / 候选都不过校验 | 取字段里**最靠后**的号（用户习惯把自己的号写在地址末尾） | 917 行 |
| 4 | 地址列无候选 | 退 `j_address` → 姓名列 `name` / `s_name` | 769 行 |

**★ 为什么序 3 取"最后"而不是"最前"**：地址是「省市 + 街道门牌 + 收件人 + 电话」的书写顺序，
自己的号在末尾是绝大多数人的习惯；开头的号更可能是店家/服务社的。

**★ 序 2 与序 3 的差别要在交付里显式标注**（`真号来源` 列），
因为序 3 的 917 行是**未过双校验**的 —— 归属没被证明，只是"最合理的那个"。
用户随时可能要求剔掉它们，所以要一眼能筛。

## 2. 剔除规则（不做 ⇒ 数字虚报 70 倍）

裸 `1[3-9]\d{9}` 正则会命中**京东运单号**：`JDVE<PHONE-REDACTED>` 里的数字段。

| 形态 | 处理 |
|---|---|
| 号码前是**大写字母串** `[A-Z]{2,8}` ⇒ `JDVE` + 11 位 | **剔除**（运单号） |
| 号码前是中文/小写字母连写 ⇒ `马艳<PHONE-REDACTED>`、`litao<PHONE-REDACTED>` | **保留**（人名的拼音/汉字拼接） |
| 号码 ∈ 虚拟号池主号集合（`167/170/171` 段） | **剔除**（§SKILL.md §2 的号池） |

**收敛效果**：`680,743 → 9,617`（剔掉 670,808 处 `JDVE` 假阳性）。
**不剔 = 结果虚报 70 倍**，这是本案最容易翻车的一步。

号池主号集合从哪来：跑 `scripts/tel_shape_classify.py pool`，或读目标目录的
`_ext/all_mob.tsv`（格式 `号码\t次数\tvirt标志\t来源位图`，`virt=1` 即号池主号）。

## 3. 写回契约（用户的"格式"要求 = 不破坏原列序）

- **保留源文件原列序、原列数**，只把电话列（本例 E 列 = `s_tel` = 第 5 列 = 索引 4）**原位**替换成明文号。
- 额外信息（`真号来源`）**作为尾列追加** —— **绝不插在中间**。
  下游脚本按列号取值（`row[4]` / `row[5]` / `row[19]`），中间插列会把它们全部错位。
  尾列追加是唯一安全的位置。
- `csv.writer` + `encoding='utf-8-sig'`（中文表头带 BOM，见 `embedded-number-field-scan.md` §4 坑 3）。
- 源文件可能 1.4GB：流式逐行 `csv.reader`，**不要**先 `readlines()`。

## 4. 过滤语义（"把没内嵌的排除掉"）

只保留**能拿到明文号的行**；其余整行丢弃：

| 电话列形态 | 处置 |
|---|---|
| 虚拟转接号 `<PHONE-REDACTED>-261` / `…转647` | 剔除（号池，不可还原） |
| 掩码 `132*****530` 且地址/姓名内无候选 | 剔除 |
| 全星号 `********` / 空 | 剔除 |

**本轮实测**：扫描 4,083,885 行 → **保留 13,930 行** / 剔除 4,069,955 行；
唯一明文号 **8,902**；行数 == 唯一订单数（无重复行）；订单金额合计 **4,845 万元**。

---

## 5. 验收硬指标（不满足就不算交付）

1. 电话列 **100%** 匹配 `^1[3-9]\d{9}$` —— 零 `*`、零 `-` / `转` 后缀、零空值。
2. **行数 == 唯一订单数**（显式建 set 查重复行；源数据含多波次重复采集，容易重）。
3. 报出：唯一号数、金额合计、号出现频次 Top10、**来源分布**。
4. 抽样打印 ≥10 行 `订单号 | 姓名 | E列 | 地址 | 金额 | 来源`，肉眼确认地址里的号被正确摘出、
   运单号没被误配。

**★ 必报「来源分布」并主动给更严选项** —— 用户会想知道哪些行没经过双校验：

```
s_address                     11,244
s_address(未过前3后3,取末位)      917   ← 可剔（一句话切版）
name·s_name                      769
s_tel原值明文                   1,000   ← 不是"地址内嵌"，可剔
```
（「严格只留地址内嵌」= 12,161 行；「只留过了双校验的」= 12,244 行。）

## 6. Pitfalls

1. **先剔运单号再报数** —— 否则 9,617 会变成 680,743（70 倍误差）。
2. **号码前导大写字母是运单号判据**，但**中文/小写字母连写不是**（那是人名）—— 判据写严会漏真号。
3. **择优取"最靠后"而不是"最靠前"**（§1）。
4. **尾列追加，绝不中间插列**（§3）。
5. **掩码正则的 `1` 必须进捕获组**：`^1(\d{2})\*+(\d{2,4})$`，不是 `^1\d{2}\*+(\d{3})$`
   —— 后者 `178` 永远 ≠ `78`，会让全部候选"未过校验"（详见 `embedded-number-field-scan.md` §4 坑 1）。
6. **别忘 `re` 全字段 `finditer` 而非 `match`**：`match` 只认"独立成字段"的号，
   地址文本内嵌的一个都抓不到（本案曾因此把 9,434 误算成 9,075）。
7. **端到端跑完要投桌面**（用户偏好：交付件落桌面 + 对话里给 `MEDIA:` 路径），
   并保留源格式版本的中间产物在案卷目录。
