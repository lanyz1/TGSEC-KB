## 1. 陷阱:表观聚集会骗你

1,000 条完整明文散在 408 万行里,按常规维度分组后长得非常像"某天/某店脱敏挂了":

```
日期维度:
  2026年03月08日  919 条 (91.9%)   ← 看着像"这天的脱敏失效了"
  2026年03月09日   50 条
  2026年03月10日   13 条

门店维度:
  金庐名居店 612 / 济康店 144 / 龙腾店 121 / 华鹏帝景店 79 / 木里江店 44
                                   ← 看着像"这几家店脱敏关了"
```

**两个结论都是错的,必须用"该维度内部命中率"证伪:**

```python
# 对候选门店统计【全量】订单的形态占比
金庐名居: 总 2,698,500 | 明文 612 (0.02%) | 掩码 2,019,247 | 虚拟 401,592
济康店:   总   376,485 | 明文 144 (0.04%)
龙腾店:   总   252,764 | 明文 121 (0.05%)

# 对候选日期统计【全天】命中率
2026-03-08: 总单 4,845 | 明文 919 = 18.97%
```

- **门店不是开关**:那几家店全量明文占比仅 0.01%~0.05%,和其它店没差别
- **日期不是开关**:当天 81% 的单子仍是掩码/虚拟号 ⇒ 按日期判"这天都是明文"严重高估

**★ 判据**:某维度"命中条数多" ≠ "该维度是开关"。
必须算 **命中条数 / 该维度总条数**,不能只看命中条数的绝对分布。

## 2. 真开关:采集波次(逐次 API 调用)

按波次号分组,算每波的命中率 —— 断崖立刻出现:

```
波次 266136 => 200 单中 149 明文 (74.5%)   ★ 该波脱敏完全失效
波次 266051 => 200 单中 110 明文 (55.0%)   ★
波次 266049 => 200 单中  68 明文 (34.0%)   ★
波次 266050 => 200 单中   0 明文            ← 同日、相邻波次,直接归零
波次 266053 => 150 单中   0 明文
波次 266054 => 114 单中   0 明文
波次 266127 =>  71 单中   6 明文
```

**⇒ 脱敏是「按采集波次」生效的** —— 一次 API 调用(一个波次)要么整波明文、要么整波脱敏,
与日期、门店都无关。相邻波次命中率 0% ↔ 74.5%。

## 3. 操作流程(可直接照做)

```python
import csv, collections, re

形态 = []          # (波次, 是否明文)
with open(DATA, encoding="utf-8-sig") as f:
    for x in csv.DictReader(f):
        t = (x.get("s_tel") or "").strip()
        # 明文判据:恰好 11 位纯数字(掩码含 *、虚拟号含 -/转)
        is_plain = len(t) == 11 and t.isdigit()
        形态.append((x.get("wave"), is_plain))

by_wave = collections.defaultdict(lambda: [0, 0])
for w, p in 形态:
    by_wave[w][0] += 1
    by_wave[w][1] += p

# 泄露波次清单:命中率显著高于全局基线的波次
基线 = sum(p for _, p in 形态) / max(1, len(形态))
泄露波 = [(w, n, k, k / n) for w, (n, k) in by_wave.items() if n >= 20 and k / n > 基线 * 10]
泄露波.sort(key=lambda r: -r[3])
for w, n, k, r in 泄露波[:20]:
    print("波次 %s => %d 单中 %d 明文 (%.1f%%)" % (w, n, k, r * 100))
```

**产出 = 「泄露波次清单」**,三种用法:

| 情况 | 动作 |
|---|---|
| 数据源**还能访问** | **只重扫这些波次**(窄区间,本次约 266049-266052 / 266136-266139),不必全量重采 |
| 数据源**已下线** | 知道手里明文集中在哪几波,报告口径才准确(别写"某天全量明文") |
| 要给用户解释 | 说明是"逐波次生效的脱敏缺陷",不是"某天/某店问题" |

## 4. Pitfalls

1. **别用"日期"或"门店"当重扫筛选条件** —— 既漏(别的时间也有明文)又高估(同一天多数波次没有)
2. **别只算命中条数的绝对分布** —— 必须算该维度内部命中率(见 §1 判据)
3. **波次号要按原样保留**(本次是 `wave` 列,来自 API 的 `id` 参数) —— 它是找回原数据的唯一键
4. **全局基线要先算** —— 本次 1,000/408 万 ≈ 0.024%,所以"10 倍基线"即 ≈0.24%;没有基线就没法判异常波次
5. **样本太小的波次别下结论**(`n >= 20` 门限),否则一串 1/1=100% 会污染清单
