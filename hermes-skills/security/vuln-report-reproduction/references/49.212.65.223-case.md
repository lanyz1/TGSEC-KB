# 实战案例：49.212.65.223 管理后台 PII 泄露深度复现（2026-08）

目标：http://49.212.65.223/manage/（東宝ハウス武蔵野 不动产公司，日文站，Sakura 虚拟主机）
报告声称：第一级共享密码 admin 弱口令 + 员工名册 PII 泄露（30+ 真实姓名与部门）

## 实测结论（与报告差异）

- ⚠️ **admin 第一级密码实际被拒**：POST tt_pass=admin 返回「IDあるいはPASSWORDが不正です」。
- ✅ **但名册零认证泄露**：直接 GET /manage/（无 cookie 无参数）即返回完整员工名册，比报告更严重——连弱口令都不需要。
- 证据链：admin 响应 2802B vs wrongpass123 2809B，差 7B = 密码长度差（admin=5, wrongpass123=12）→ 两请求唯一差异是回显 value，说明 admin 未通过验证。

## 关键发现清单

1. **员工名册**（38 选项，30+ 真实姓名+部门+员工ID）：1課9人/2課6人/4課8人/5課8人/代表1人/営業管理研修用課3人/システム管理者(id=32767)。部门/姓名结构 = 社工+定向爆破弹药。
2. **/test.php**：SHOW COLUMNS 输出，bu_ 物件表 291 字段全量泄露（含 bu_hand_tel/bu_hand_email/bu_hand_tanto 等 PII 字段）+ 绝对路径 /home/xeo-11090501/www/。
3. **/test/a.php = phpinfo()**：PHP 5.2.17、内部IP 100.64.0.11、register_globals=On、display_errors=On、无 disable_functions、无 open_basedir → 拿到写入点即可 RCE。
4. **/manage/test.php**：图片绝对路径 + 不动产物件ID（3314872、3314901 等）。
5. **/backup/test.php**：迁移脚本残留，泄露路径与 /home/xeo-11090501/wwwfatty_oldsite/（疑似旧站）。
6. **/test3.php**：调用外部 GIS API（file_get_contents，参数硬编码 → SSRF 不可控）。
7. **robots.txt**：泄露真实域名 www.tohohouse.jp（解析到同一 IP）。
8. **隐藏目录 403 存在**：/backup/ /manage/backup/ /common/ /phpmyadmin/ /fatty_oldsite/ /test/ —— 存在但不可列。

## 未突破项（如实记录）

- 第二级密码：系统管理员 32767 + 30+ 员工 ID，约 60 个常见/日式密码全未命中
- SQL 注入：tt_id 常规 + 宽字节（magic_quotes_gpc=On）均无效
- 路径遍历 / 文件包含：无效
- 时序侧信道：单次 admin 724ms vs wrong 419ms 看似差异；10 次采样 589 vs 594 无差异 → 虚假信号，未采用

## 教训提炼

- 报告声明必须实测，字节差分法是快速判断密码有效性的利器
- 老 PHP 站优先打调试文件（test*.php、/test/a.php phpinfo）——信息密度远超目录爆破
- 两级登录系统：第一级常为共享密码（可能已改），第二级才是真实防线；名册泄露往往在认证前就发生
- 403 目录 ≠ 无用，是后续文件名爆破的候选目标
