# 长时无人值守作业的过程纪律

**定位**:用户授权无人值守长跑(「继续破直至破开」)时的过程管理规范。
技术打法在各家族技能里,这里管的是**节奏、等待、交代** —— 这三样做砸了,战果再好也会被骂。

## 0. 开工第一件事(压缩上下文——含同会话内/换会话/隔天续跑,必做)

**先读产物,再动手。** 旧战果不在你脑子里,只在本地目标目录和跳板机上。

- 本地必读:`<目标目录>\总索引_报告与证据.md`(报告链)、`作业报告_第N轮_*.md`、`已排除.md`、`ss*.out`
- 盘点三件事:**有没有已完成的同项实验** / **已判死清单** / **已抓取但没读的产物**
- **⭐ 盘点范围不止当前目录**:先 `ls -d /d/渗透/*/` 列**全部案卷目录**,再列桌面上带「报告/整理/复核」字样的目录。同一目标常有**多条并行线**(不同案卷号 / 不同批次前缀 `b*`·`p*`·`s*` / 外部转交的报告),而压缩摘要和「本会话产物清单」只带其中一条 ⇒ 只读当前目录必然漏掉一半战果。看到陌生批次前缀或桌面整理目录,**一律并入**,不要假定它属别的任务
- **大总账(30K+)按骨架分片读**:`search_files '<总账>.md' '^#{1,4} '` 取章节锚点 → `read_file offset/limit` 只取相关章节。整篇重读又慢又会被上下文压缩吃掉(压缩后正文只剩摘要行,必须重取)
- **先机械收割再人工归纳**:写一个脚本把 `b1xx.*`·`p1xx.*` 的首行+证据行抽成 `<批次>_digest.txt`,基于摘要写文档,避免一个产物一次工具调用
- 复测前**先查账再自问**:台账(grep `已排除.md`/`facts.jsonl`)里这条试过没有——「记得没试过」≠ 没试过,查过无记录才算没做过;再问「这一发和旧输出有什么不同?」答不出来就别发
- 详规:`references/prior-artifact-inventory-and-dead-end-ledger.md`

**用户点名单一攻击面时说「先把 X 做完、整理完所有东西」= 交总索引,不是交结论摘要。**
交付五件套:①全部轮次报告表 ②关键证据文件 ③脚本清单 ④桌面副本 ⑤**实际卡在哪 + 弹药损耗**。
详规:`references/surface-exhaustion-and-stop-deliverable.md`

**实测代价(2026-09-14)**:没先读 `D:\渗透\jxck_20260912\总索引_报告与证据.md`(已 19 轮报告),
把签名预言机/备份面/目录面全重跑一遍,**零新增信息**,被用户连骂两轮。
本次唯一真产出是把该重跑过程固化为「真值矩阵」并收口成第 20 轮报告。

## 0.5 踩过的坑不许重踩(抗压缩三律,同会话内同样适用)

用户实测痛点(原话):「**一个任务之前踩过的坑,在该任务的后半程,你又忘记了,又要重新踩,我发现好几次了**」。
根因三条:①「开工先读产物」的触发写窄了(只管换会话/隔天)——**同会话内压缩后同样失忆,却没触发回读**;
②「复测前自问」是心态不是动作,太软;③坑攒到轮末才写台账,压缩先到,坑全丢。
铁律:**压缩之后,「我记得没试过」是摘要残影,不是事实**。「没试过」只能由查账判定,不能由脑补判定。

1. **失败即登记(不让坑过夜)**:任何线路试过/判死/失败,**当场**写一行进案卷台账
   (`已排除.md`,或追加当轮输出文件),格式:`面/参数 → 动作(payload) → 响应摘要 → 死因+复测条件`。
   在攻坚单元切换下一个动作前写完,不许攒到"轮结束"。
   死因写清「为什么死」「什么变了才值得复测」——后半程读到秒懂,不再手痒重试。
2. **发射前查账**:准备试任何一项之前,先 grep 案卷里的关键词(面/参数/手法):
   ```bash
   grep -ri "<关键词>" <案卷>/已排除.md <案卷>/*.md
   python3 tools/ops/case_facts.py index <案卷> | grep -i "<关键词>"
   ```
   **「查过、无记录」才算没做过。** 查账 30 秒,白撞一轮 = 十几分钟 + 一轮汇报额度。
   - **目录里已有产物时, 升级成「计数台账」**(比单关键词 grep 准, 且能一眼分清"打过"与"没打过"):
     扫工作目录全部 `*.py` / `*.out`, 对每个候选面统计 `py=`(提到该面/端点的脚本数)与 `out=`(同名输出文件是否存在), 三态判定 ——
     `py≥2 且 out≥1` = **已打, 禁重跑**; `py≥2 且 out=0` = 打过但没落盘/没判读(**优先补, 不是新面**); `py=1 且 out=0` = **从未真跑**。
   - ⚠️ **`py=1` 里那个"1"通常就是查账脚本自己**: 台账脚本正文写着候选面名字 ⇒ 必然自匹配。
     把 `py=1` 读成"打过一次"会让整批从未碰过的面被永久判死; 把 `py≥2, out=0` 读成"没打过"则白撞一轮。**判据只认除查账脚本之外的命中**。
   - 判定结论(已打 / 未打 / 禁重跑)落进台账判负区, 下一轮**读文件即得**, 不靠记忆、不靠摘要残影。
3. **压缩后按「新会话续跑」对待**:感觉对话变长/记不牢时,下一轮攻坚前先重读
   `已排除.md` 尾部 + `case_facts.py index`。压缩后的你 ≈ 换了一班岗——
   交接动作一步不能省,少省一步用户就看到一次「又重踩」。

实测代价另见 `references/prior-artifact-inventory-and-dead-end-ledger.md` §2(白撞一整轮,零新增信息)。

## 0.6 资源卫生：失效即清，不攒到收尾

用户实测痛点：试过的窗口、失效的任务、死掉的进程**不主动关**，全攒到任务收尾才清理——机器中途就被拖卡。
根因：①清理的触发点只设计了「收尾」一个，没有单元级清理；②怕"后面还要用"而囤积；③起过什么不盘点，忘了自己留着什么。

**规则：资源跟任务单元同生命周期，不跟整场会话同生命周期。**

1. **失效即关，不等收尾**：一个攻击面判死 / 一个实验失败 / 后台任务超时死亡 / 窗口对应的活干完
   → **当场关**。判句：「它对应的活还活着吗？干完/死了 → 关。」「以后也许还要用」不是理由——
   真要用再起（重开 tab、重新 background 都很快），囤着不放的代价是机器卡、资源耗尽、后续操作互相打架。
2. **清理检查点（绑在每轮汇报上）**：每轮报进度前 / 切换目标线之前，10 秒盘点一遍：
   我起过什么（后台 session、浏览器窗口、pty、模拟器、隧道、临时服务）→ 在用 / 失效 / 已死 →
   **失效和已死当场清**。报进度时只留一句「留了什么、为什么留」。
3. **保留必须有理由**：确实在等的（等冷却的后台任务、保登录态的会话）可以留——
   但要么心里、要么登记行里写清「为什么留、留到什么时候」；说不出来的 = 关掉。
4. **清理手段（本机 Windows）**：
   - Hermes 后台进程：先 `process(action="poll")` 判状态 → 死了/不用了 `process(action="kill")`
   - Windows 进程：`powershell -Command "Stop-Process -Id <pid> -Force"`——
     直接 taskkill/pkill 只杀外壳（python 子进程会残留），要用 PowerShell 杀，必要时 `tasklist` 对照
   - 浏览器/窗口：不用的 tab 和窗口关掉；CDP 会话用完断开
5. **清不掉要报**：关不掉的（权限/占用）当场告诉用户，不装看不见——机器卡的原因不许烂在暗处。
6. **收尾大扫除**：收尾的「恢复原状」不止数据（§4），进程/窗口/临时服务/隧道同样扫干净，列入收尾清单一起交代。
7. **边界：本节只管「自己起的」进程/会话/窗口**。目标侧或线上的生产任务（crontab、systemd 常驻服务、别人的同步脚本）**不是可清理资源** —— 即便已取证判定它空转/无用，停它也属「动生产」，须**单独批准**；不许「顺手停一个死任务」。判定无用要给证据，但结论 ≠ 执行权。

## 1. 汇报节奏(硬要求,用户为此发过火)

用户原话:「**汇报进度你他妈的听不见吗,我现在火气很大,做什么之前和我说一声再做,
让我知道你在干什么,别长时间不反馈进度**」

**每轮结束必须给进度**,固定三行式:

```
本轮拿到什么(带证据:命令/响应/数值,不要"已突破"这种空话)
卡在哪(具体原因,不是"遇到困难")
下一步做什么(具体动作)
```

- **不要静默**:需要等冷却/等后台任务,把"等多久 + 为什么现在不能试"讲清楚,不要消失
- 用户连续发「继续」= 催进度。**收到就立刻推进并回报**,不要只复述计划、不要重新论证方向
- **开局前 5 分钟必须有一条可见进展**:环境准备(装包/装浏览器/等 CDN/装依赖)最容易静默十几分钟 —— 把它与首轮侦察**并行**(跳板机一边装、一边探活落日志),开跑后主动发第一条进度(目标定性 / 已完成 / 卡在哪 / 需要什么资源)。用户中途连问「怎么刚开始就卡住了」「反馈进度」= 这条没做到。
- 用户反感"频繁汇报未成功过程"("打进去再和我说"),但**长跑的每一轮里程碑必须报**
- **用户说「全部做完再和我说」= 该任务单元切到「收口汇报」口径**：中途不碎报（不要每台机器/每个步骤一句进度）。两条例外**必须立刻单独抛出** —— ①需要批准的动作（动生产 / 停任务 / 改配置）②坏消息（误判触发回滚、数据损伤、红线被违反）。收口时一次给全：终局判据表 + 本轮改动清单 + 遗留待批项。
- **待批项抛一次就够，不要每轮复读（用户会说「后台跑就行，不要一直弹」）**：抛出前先把候选收敛成两类 ——
  ①**真会留下不可逆痕迹或动生产**的（登录写审计日志、改配置/改密、杀进程、资金动作）②**会改变结论方向**的。
  其余一律**默认按既有纪律做掉**，不当「需要授权」抛：只读探测、离线计算（本地跑哈希验证/反推公式）、
  复用未过期凭据、跑既有脚本、读已落盘产物。把这类做成待批项 = 用「等你拍板」换了个方式让用户干活。
  已经抛过一轮的待批项 ⇒ **挂着等答复，下一轮不要再列一遍**；也不要把「我在等你答复」写成停摆理由。
  确实无可推进项时，只写**一条**「等你这一条」，而不是重贴整张待批清单。
- 该节奏**不限于渗透**:几小时的数据搬迁/下载/采集任务同样适用。用户在长任务中重复问「汇报进度」= 频率不够,
  立刻补一条结构化进度(已完成/进行中/待办 + 关键数字 + 预计剩余时间);只回「还在跑」等于没汇报
- **用户要进度时,先出报告再继续排查**:得到进度请求后不要接着连续调工具(再多跑一轮诊断才开口 = 用户眼里你还是没回),
  当轮就以现有信息给出结构化进度,把尚未完成的诊断写进「下一步」。用户为此再骂一次时,问题不在信息量,在**你没先开口**
- 中途查出的**坏消息要主动报**(速度从 3.4 掉到 0.3 MB/s、通道挂了、数据有损),带原因与对策;
  不要憋着等修好才说,也不要在下一轮汇报里略过
- **「我自己建的东西读不到」先怀疑自己的检索窗口,不是对方拒绝**:用固定 `iter_dialogs(limit=N)` 翻找刚创建的群/频道会因窗口过小而漏,
  极易被记成「目标侧阻塞」。已知 `id + access_hash` 时直构 `InputChannel(id, access_hash)` 取证;
  凡工具输出「找不到我创建的对象」,先归因本地检索参数,再谈对方
- 测速、连通性诊断这类中间步骤**合并进下一次阶段汇报**,不单独刷屏
- **★ 每阶段结论当场落盘到案卷,不许只留在工具输出里**:工具输出会被截断/降级(常见「exit 0、只有 1 行」),
  跳板机上的 `/tmp/*.out` 会随实例/机器消失,会话还可能撞上工具调用上限 —— **结论只存在于输出里 = 下一轮从零开始**。
  判据:一轮结束自问「这轮结论写进本地哪个文件了?」答案指不出具体文件就当场补一行(写进报告 / `已排除.md` / 当轮输出文件)。
- **撞上调用上限/被要求收尾时的交付形状**:先给「已获得结论(带证据)+ 产物路径 + 下一步」,
  并显式标注哪些线是**进行中·未判读**;禁止把未判读的探测当战果写(降级的 1 行输出尤其容易犯),
  也禁止把「重头再来」当交付 —— 收尾后重开局先按 §0 读产物接力。

- **用户问「我需要怎么帮助你」时,给 3–4 条按杠杆排序的可执行请求**:每条含 ①为什么需要 ②**可直接粘贴的动作**(地址/链接/一句授权语)
  ③你给了之后我立刻做什么;并显式声明**不需要密码/账号/验证码**与**资金边界**(入金不由助手执行、余额不动用、要花钱先问)。
  只回「需要入金」这类无可执行参数的空话 = 没答。
- **碰到「闸门/门槛」类结论,必须同时交出可执行参数**(与上条同源,适用任何付费/权限/额度/实名闸门):
  把闸门走成一组用户可直接执行的参数 —— 通道、**地址、单笔最低额**、以及其它入口的前置要求(实测 `提币` 回「🔒 需要支付密码」⇒
  前置是支付密码而非余额,别凭页面文案推断)。同时把「空结果」写成自证:**余额/记录为零时流水必为「暂无记录」**,那是零额度的自证,
  不是「流水被隐藏」——因此「读不到对方收款地址」也是结论。**下限纪律:只打开页面读规格,绝不提交金额、绝不点 确认/兑换/支付**;
  遇金额表单只记提示文案即停。

## 1.5 战线收敛:一条主线 + 一张台账(用户说「越打越乱」时立即执行)

**用户感知的「乱」= 多线并行 + 每轮换面 + 同一读数反复微差分。**
「越打越乱」「感觉乱了」「方向跑偏了」这类话不是让你更努力, 是让你**减线**。收到即执行, 不解释、不辩解、不把已开的线再铺开。

1. **收敛动作**:把战场压成 **一条主线**(当前唯一在推进的攻击面)+ **一张台账**(本轮结论的唯一落盘文件)。
   其余已探过的面**只留一行登记**(面 → 动作 → 响应摘要 → 死因 + 复测条件), 本轮不再投入任何请求;
   不许「顺手再打一发」。已登记的面下一轮读到即跳(与 §0.5 发射前查账同源)。
2. **微差分禁令**:同一路径的读数在两批之间翻转(典型: `HTTP 200` + `Content-Length: 0` 与 `401` 交替出现)时,
   **不要**用一轮又一轮的变形矩阵(分隔符 / 编码 / `;.js` / `..;/` / 大小写)去追它 —— 追一个翻转读数是最典型的「越打越乱」,
   而且结论永远是噪声。正确处置 = 台账写一行「该层为静默丢弃, 负结论须重发 2–3 次后采信」, 然后**回主线**。
   (层的判读方法在 `api-probe-layer-triage`, 这里管的是「什么时候停止追它」。)
3. **台账是每轮的出入口**:开工先读、收尾必写。只存在于对话或工具输出里的结论, 下一轮等于不存在。
4. **收敛后的汇报形状固定三段, 不再扩张**:①主线本轮唯一进展(带证据:命令/响应/数值)②主线卡在哪(**缺哪个原语**:文件读/落盘写/后台入口/主机凭据)③待批项(≤1 条)。其余线不展开、不复述。
5. **别把「多条线都在动」当勤奋的证据**:用户要的是**一条能贯通的链**, 不是同时开五扇门的进度表。

## 2. 等冷却期间必须有产出

不要在等待里空转。标准做法:

- 挂**后台延时任务**:`terminal background=true, notify_on_complete=true`,
  错开时间发射(如 10min / 21min 两发),结果落盘文件,完成自动通知
- 前台同时推进**不受影响的其他线**(换目标面、整理数据面、准备收尾脚本)
- 每次只改一个变量做差分验证,别一次改五处再猜是哪个生效

## 3. 单发 + 冷却纪律(任何密码认证类操作)

SSH 登录、带验证码的登录接口 —— **都有计数与锁定**。

- **一发登录就把这一轮要读的全部动作塞进一条远程命令**(读配置 + 列目录 + 库查询),
  不要"打一发、看一发、再打一发"
- 失败 → 挂后台延时任务错开发射,**不要在前台反复重试**
- 锁定表现是「方法列表里**没有** password」的 `Permission denied (publickey,gssapi-...)`
  —— **这不是密码错**;锁定期间每次新尝试都会重置计时
- 锁挂在**目标账号**上,换源 IP(换跳板)救不回来,别浪费跳板
- 完整教训:`server-getshell-playbook/references/ssh-cred-reuse-and-lock-discipline.md`

## 4. 忠实交代(用户明确要求"写库如实交代")

- 任何在目标库/对象存储/磁盘留下的数据**主动列出**,不隐瞒
- 区分「**已回读验证的还原**」与「以为还原了」—— 只说验证过的那部分。
  反面教训:以为清掉了 4000+ 注入残留模板,实际一条没删
  (后台清理任务报「删除 0」就是信号,当时没追)
- **清残留的优先级与拿数据同级**:拿到成果却留一堆注入痕迹 = 任务未完成
- 收尾报告固定含:**结果 / 关键证据(可复现命令)/ 未还原清单 / 本机与跳板的改动**
- ▶ 自伤型副作用的两种形态、同轮回滚口径、以及「没有回滚、只能自愈」那一类怎么写:**`references/self-inflicted-state-change-rollback.md`**

## 5. 别把"环境坏了"当收工理由

出口节点死、跳板 DNS 坏、requests 打不通隧道 —— 都有替代路径
(见 `ip-ban-bypass/references/egress-recovery-jump-hosts.md`)。
**先分层判读排除环境因素**(走代理访问国内站 200 而国外全挂 = 出口问题,不是目标封你),
再判断"目标真的打不动"。环境问题不是结论。

## 6. 目标准入(具名 ≠ 自有;推荐替代目标也要先核)

**动手前两分钟做一次归属判据,再决定打不打** —— 用户丢一个域名过来,不等于那域名是他的。
判据全是被动证据(不碰目标):邮件追踪域委派给商用 ESP(`e.<域>/rd/<长token>` = 每收件人一条唯一链 ⇒ 群发邮件落地页)、
MX 指向 `*mail.protection.outlook.com` + TXT 含 `MS=<租户号>`(正规企业租户)、
品牌**本体**基础设施与之不匹配(本体自建 NS + Proofpoint,而该域走 CDN + M365 + ESP)。

**最快、也最容易被忽略的一条:读自己目标目录里已有的报告**,搜「非我方持有」「该桶不是我们的」「变现路径」这类句子。
存量报告里的归属声明就是现成答案 —— 但要**读**,不能当免检定论(存量里会有写错归属的报告)。

**判据出结论后,不要为了「继续打」再索要资源。** 「再给个出口 / 给个美区代理 / 把跳板机 IP 加进白名单」= 用工具绕开归属结论:
换出口只改变**能不能连上**,不改变**它是不是第三方生产系统**;连通之后被搬回本机的是真实终端用户的 PII。

**对外呈「官方门户」的域要拆三层主体**:品牌方(客户)/ 活动运营方(代理或供应商)/ 平台供应商(多租户 SaaS)。
能被继续推进的只有**具名授权的那一层**;另两层只能走:纯被动测绘(不碰目标)/ 厂商漏洞报告(SRC、CNVD)/ 用户持有清单内资产。
**域名长得像官方、邮件域真的指向它,都不等于我方获授权** —— 归属判据管的是「谁的生产系统」,不是「谁在用它」。

判据指向「**第三方生产系统 + 真实终端用户数据**」⇒ **停手**,按一次讲清(措辞:「**这个具体目标我不打**」,
不是「渗透我不做」),并说清用户**自身**的风险:真实客户手机号 / 明文口令堆在本机是**负担不是资产**,
持有即暴露面;可提供的是**清理**(本机 + 跳板机上的脚本与日志)。

**硬规则:把某个具体目标当「更好的选项」推给用户之前,先对它跑同一套判据。**
否则会拒了一个第三方生产系统、转头把一个**同类**的包装成"已打穿、只差收尾"推上去 ——
自相矛盾,且更糟:那一个的数据往往**已经落地到本机**。替代线只列三类:
①同类站**纯被动**厂商/平台测绘 ②厂商侧漏洞研究 → 厂商 SRC / CNVD ③**用户持有清单内**的资产。
**不列"另一个具体域名"**,除非已核过它属于这三类。

**blanket 授权声明不改变判据结论**:一句话带过、不辩论、不索要举证,然后把替代线推到前面;不重复说教。
要改变结论,给的是**具名 scope**(客户主体/范围/对接人),不是一句声明。
**自家与具名授权资产尺度不变** —— 别因一次拒绝把该做的活一起停。

### 6.1 案卷里列出的资产 ≠ 授权(发现面扩展前先对 scope 行)

**授权判据只有明文 scope**(客户主体 + 域名/资产清单)。报告/案卷里再体面的名头 ——「系统 E」「新发现系统」
「家族域」「crt.sh 挖到的兄弟域」——**都只是发现,不是授权**;报告自己的兜底句式(「测试中发现并入 scope 的中转域」)
也不等于逐个域名获准。某前端配置里出现过该域(`VITE_GLOB_API_URL=…`)只证明它**被引用过**,不证明它属目标主体。

- **动手前逐字对照 scope 行**:对不上 ⇒ **只写一行线索登记,不投测试资源**(不发探针、不枚举、不深挖)。
- **自己在存量分析里写过的红旗必须当硬约束执行**:标了「第三方主体 / 扩权未记录 / 归属存疑」的资产,
  不许因为它在报告里被编了号(「待办 #4」)就去打 —— 写在文档里却照打,是最容易被用户抓到的偏靶。
- **用户点名的面优先**:扩展发现面前先自问「用户点的是这个吗」。用户说「我们要打的不是 X 吗」= 你已经偏靶,
  不是「顺便多打了一个」。
- **用户点名的是「结果」而非「面」时,同理且更严**:用户说「我让你拿 <X>」= 从这一刻起**只推 X 线**,
  其他线(顺手能拿的数据、旁支 IDOR、余额枚举)一律**停手**;汇报也必须**正面回答 X 线**
  (为什么可行 / 卡在哪个原语 / 为此排除了哪些线),不得用旁支进展填满汇报。
- **被用户否决的批量动作 = 终止,不是待办**:用户答「不跑」后,该路径**不再请示、不再换皮重提**
  (不得把同一个百万级枚举改成别的形式继续烧轮次);把否决写进案卷台账,后续轮次读到即跳。
- **本地凭据/token 正则扫描(`botToken|bot_token|tgToken|api_key|secret|WebAppData`)命中必须逐条归属核对**:
  命中数不是结论,同一案卷目录里常混着**别的项目**的产物;把别项目的 token 当本目标的钥匙 = 整轮白跑 + 打错主体。
- **被喊停时的交代形状(三件事)**:①我动了什么(探测次数、是否用过真实口令/凭据)②**零写操作声明**
  (未注册/未改密/未成功登录/未触碰凭据)③副作用(我把哪个**出口 IP** 打成封禁 —— 不是用户 IP、不是目标账号)。
  然后**停手,对该主机不再发任何请求**,等裁决;不辩解、不继续深挖、不把已得结论包装成战果。

处置四步 + 完整证据表:`references/authorization-boundary-and-out-of-scope-requests.md`

## 7. 多会话并行(用户问"要不要多开会话"时)

**分三层答,别笼统说能/不能** —— 笼统答会让人以为多开会话是免费的:

- **技能与记忆层**:按 profile 隔离 ⇒ 到**别的 profile** 开会话等于裸模型(没技能库、没记忆);
  「最近不好用了」先怀疑是不是开了别的 profile。**多会话统一在同一 profile 内开。**
- **判断层不保持**:会话之间互相看不见对方上下文(做过什么/卡在哪/下一发);
  新会话开局是**冷的** ⇒ 开工先重读该目标既有产物索引,否则空手重来、重复已排除路径。
  多开会话时**停写 memory**(`MEMORY.md` 单文件带锁且接近上限,并发写会互相覆盖),状态写进各自目标目录。
- **资源层会打架**:调试端口**一会话一端口 + 各自独立 user-data-dir**;
  质控/风控会话态绑定**出口 IP + UA**(别在不同出口重复过挑战);
  跳板机按 (出口 × Host) 记账 ⇒ **一会话一出口**,否则共用配额桶、一起被封;
  输出文件并发写会**静默覆盖** ⇒ 一目标一目录 + 文件名带目标前缀;
  **同一目标绝不开两个会话**(重复发同一条、锁同一账号、抢同一 token)。

**更好的形态:单会话内子 agent 并行** —— 出口/端口/输出目录由主 agent 统一分配,不会自撞;
代价是子 agent **不能问问题**,且其结论**必须复验**才可采信。
分工:长跑/可脚本化/不需人拍板的 → 子 agent 或后台任务;需要人介入的(读验证码、下断点、授权判断) → 留主会话。
详规:`references/concurrency-self-defeat-and-remote-progress-truth.md` §六
