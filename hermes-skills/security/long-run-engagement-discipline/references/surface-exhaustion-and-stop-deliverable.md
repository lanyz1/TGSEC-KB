# 被点名攻击面:穷尽纪律 + 「先停」时的总索引交付

## 触发
- 用户指定了单一攻击面(「我让你从前端下手」/「从前端做渗透逆向」)
- 用户说「先停,我要看已有全部报告和证据再决定」

---

## 一、用户原话:「我让你从前端下手,你开工了吗」

被抓到的两点(实测记录):

- 抓取动作做了,但**产物只记了文件大小、没读内容** —— 一个 8.8KB 的前端模板
  (`tpl/_bch.html`)在清单里挂了很久,只知尺寸、从未下载内容
- 接口清单**只抽样测了约 15 个**,就对外输出「全部接口都需要会话、没有缺口」

补做之后差在哪:

- 全量 43 个接口逐个验证 → **结论没变,但性质从「外推」变成「穷尽」**
- 那份漏读的模板里**炸出 7 个从未测过的接口**:
  订单详情 HTML、批量打印数据 JSON、波次移除、标记已打印、发货校验、批量发货
- 同一批模板/JS 还顺手给出了**参数结构**,那是"拿到会话之后"的利用蓝图:
  `edit.userpass → id,pass`(按 id 改任意用户口令)、
  `get_order_print_data → bch,list,bch_type`(批量取收件人 PII)、
  `daochu → 16 个筛选参数`(订单全字段导出)

## 二、规则

1. **凡已抓取/已知存在的产物,必须读完再判。** `ls` 出来的尺寸不是证据;
   清单里有但没读 = 未覆盖。**抓完就地读,别攒着。**
2. **普适结论必须全量枚举 + 全量验证。** 「全都需要登录」这类话,
   抽 1/3 样本就说是最容易被点破的一类。判死一条面时,把清单列全、逐项打钩。
3. **先产出该面的完整清单,再谈判死。** 清单本身是交付物 ——
   后续拿到任何凭据,它就是直接可用的攻击面地图(门是锁的,但钥匙孔全画出来了)。
4. **收口话术只说两种话**:「**已穷尽,结论是 X**」/「**已做 A/B,尚未做 C**」。
   不要用「全都不行」这种听起来像偷懒的概括 —— 它会让用户怀疑整条线的工作量。

## 三、「先停,我要看已有全部报告和证据」= 交总索引

**不要回一句总结。** 标准动作:

1. **全部轮次报告** → 一张表(轮次 / 讲什么 / 字节数 / 路径)
2. **关键证据文件** → 源码包、phpinfo、导出的 CSV、日志原文(标注"可复现")
3. **脚本清单** → 每个干什么、怎么复跑,注明必须经跳板的执行形态
4. **补齐桌面副本**(用户默认在桌面看东西),必要时打开预览
5. 附一句 **实际卡在哪** + **弹药损耗**(出口/桶还剩多少)

索引不全,用户会认为你在藏东西,并据此做出错误的方向决策。

## 反面清单(不要做)
- 攒一堆产物到最后再读 → 结论下早了,得回炉
- 用「已覆盖 / 已确认」描述抽样结果
- 用户要证据时给结论摘要,不给文件清单
