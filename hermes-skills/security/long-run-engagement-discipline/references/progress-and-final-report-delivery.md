# 过程汇报与最终报告交付(2026-09 leader.co.il 长时段战役定型)

本文件记录**用户要什么形态的汇报/报告**。这些是偏好,不是建议——照做可省掉整轮返工。

## 1. 用户会在无人值守推进中插话要进度

原话:「汇报一下进度再继续」「汇报一下进度」。此时**给结构化状态表,不要长文散文**:

| 项 | 内容 |
|---|---|
| 已确认战果 | **只写有实测证据的**,逐条带响应/命令 |
| 进行中 | 当前批次 + 预期产出 |
| 待测清单 | 按优先级,每条写明**前置条件** |
| 阻断 | 现象 + 判据 + 我方正在采取的措施(不要只说"卡住了") |
| 诚实底线 | 未取得数据 / 未取得 shell —— 该说就说 |

**不要为了显得有进展而美化**。用户接受"没打穿",但极度反感虚报;发现方向偏了会直接喊停
(「方向搞歪了」「暂停所有任务」),那时必须立刻停手等指示。

## 2. 报告是迭代的,但最终交付必须"整合"

一场战役里用户**连要三次**报告:完整版 → 最新版 → **「整理分析渗透报告」**。
正确形态:

- 维护**单份权威报告**,历次版本留档(v1 侦察 / v2 机理 / v3 验证 / **整合分析版**)
- 用户说"整理分析"时,交付的是**单份可独立阅读**的文档 + 一层**分析**;
  **绝不能**回"请按顺序看 v1–v4"
- 交付路径:`D:\渗透\<目标>_recon\` **并复制桌面**(用户默认看桌面)
- 同时给 **HTML 网页版**(用 `markdown` 的 `tables`/`fenced_code` 扩展渲染 + 内联 CSS),
  生成后用预览窗格直接打开,比让用户找文件省事

## 3. 整合版必须补的"分析层"

摘要/目标/方法论/攻击面之后,用户最看重这四段(缺了会被要求重做):

1. **防御有效性评估** —— 逐条攻击面给出**被什么机制挡住**的归因(不是"打不通"):
   参数强类型化 / ViewState MAC / EventValidation / 统一过滤层 / 目录防护 …… 并给一句总体水位判断
2. **利用可行性矩阵** —— 每条链:前置条件 / 成本 / 收益 / **可行性评级(★☆)**;当前无入口就写无入口
3. **数据路径分析**(目标含"拿数据"时必写)—— 数据**全部落点** + 每条读取所需前置条件 +
   明确指出哪条链是"从 0 到 1"的那一步
4. **根因归因** —— 为什么没打穿:目标侧硬度 / 我方出口与环境 / 时间被拦截对抗吃掉,
   **用时长或百分比量化**

## 4. 诚实性硬约束(写进报告声明)

- 无确证的一律标 **【待验证】** 并附复现方式
- **负面结论单列成表 + 带复现命令**:它们的价值不亚于漏洞,让接手方不必重跑
- 执行摘要用**达成度表**明写"拿数据 ❌ 未达成 / 拿 shell ❌ 未达成"
- 开篇一句结论句(如"防护强于同类、但存在一个高危逻辑缺陷")
- 声明节写明:未获取数据、未植入持久化、**未使用口令爆破/撞库**
- 证据目录里 **★ 标出关键证据文件**(如 A/B 对照实验、二值化 oracle 的两侧样本)

## 5. 一页纸交付清单(用户会单独要)

报告索引(标注"只看整合版")· 漏洞清单表 · 证据目录逐个说明(★ 关键)· 脚本用途表 ·
未完成事项(带前置条件)· **环境阻断记录表(含一次性根因,如"订阅到期域名已释放"这类永久性结论)**。

## 6. 路径穿越类交付的注意点

报告文件与证据体量大(本例 1.5MB / 58 文件),**别把每个中间产物都堆进 evidence**:
只留可复现/可对照的(原始响应、对照实验输出、探测实录),脚本与日志分开放,并在清单里说明每个文件是什么。

## 7. 「先扒数据」型请求的交付形状(未打穿阶段)

用户会在推演中途插一句「**先扒数据你能扒下来什么**」—— 这是在要**能力实证**,不是要打穿计划。
按四段交付,**不要以方法论/计划开头**:

1. **扒到的数据**(有实证,带数值与落盘绝对路径)
   - 未授权接口拉回的原始 JSON 要转成人看的表:商品 / 价格 / **库存数值**(库存条数 = 待售卡密条数,直接就是定价依据)
   - 整站镜像写清单:页面数 / 图片数 / 目录绝对路径 / 索引文件
   - 平台及上下游站的主体信息单列一节(运营公司名、备案号、客服、结算公告、公告时间)
2. **实测打穿的攻击面** —— 每条一句判据(请求 + 响应片段),**已确认**(有真实响应)与**理论**(尚未打通)分栏
3. **卡在哪** —— 具体到机制,不写「遇到困难」:需要有效订单号 / 需要商户权限 / WAF 按 IP 记账
   (把「我已把哪个出口 IP 打成封禁」这类**副作用**也写出来)/ 注册需邀请码 + 短信
4. **下一步按收益排序** —— 3–4 条,每条一句可执行动作;并附**产物路径清单**(本地目录 + 跳板机目录)

纪律:

- **扒数据不等于可以下单**:为拿订单号去买一件商品属**资金操作** ⇒ 停手问用户,改用只读 oracle(存在性查询接口)
  或站外索引(搜索/客服贴出的订单截图)去拿 1 个真实单号
- **不要用「计划」填篇幅**:每条结论必须带货(数字 / 表 / 路径),没有的就写「未取得」
- 开头先给结论句(能拿到什么 / 拿不到什么),再展开;报告落盘到 `D:\渗透\<目标>_recon\` 并复制桌面
