# 长链路作业的脚本工程纪律(小步调用 + 助手模块)

长时渗透作业的瓶颈常常不是目标, 而是**自己的脚本工程**: 一条链要跑几十轮,
每轮都重写一段几十行的脚本, 于是频繁踩下面这两个坑, 把时间烧在皮毛上。

## 1. 两个反复出现的症状

| 症状 | 表现 | 根因 |
|---|---|---|
| **提交的代码被截断** | `execute_code` 回来的不是结果, 而是 `SyntaxError: unterminated string literal`, 报错行里能看到一个字面量 `...[truncated]` | 单次提交的脚本太长(经验阈值: 约 40+ 行 / 2KB+ 且含长字符串)⇒ 代码在到达解释器之前就被截断 |
| **输出被折叠** | 明明 `print` 了完整 JSON, 回显只有 `(1 lines output)` 或几百字符 | 单次回显过大被折叠 ⇒ **证据丢失**, 于是基于半个 JSON 下结论 |

⚠️ 危险点: **症状 2 会伪装成"工具坏了"**。实际是回显预算问题 —— 你把 `print(r.json())` 整个大对象
打出来, 系统只能给你一个摘要。**这不是通道损坏, 是打印方式不对。**

## 2. 正确姿势: 逻辑进模块, 调用只留一行

```
① 用 write_file 把可复用逻辑写成模块(单次 ~2KB 以内是安全的):
     dj.py    — 会话/取票/api()/配置读写/presign()  等通用件
     dj2.py   — 本目标的动作(装包/触发/查状态/列对象)  from dj import *
② 每次 execute_code 只写两三行:
     import sys; sys.path.insert(0, D); import dj2
     print(dj2.set_web("/abs/path"))          # 只打印一个结论字段
③ 需要看结构时, 单开一次调用只打印那一个小字段/短列表
```

- **长字符串(脚本正文、payload、大 JSON)一律先落盘再读**: 用 `write_file` 写文件,
  脚本里 `open(path).read()` 再去替换占位符。**不要把长正文塞进提交的代码里**
- **每次回显控制在一行、一个字段**(经验: 数百字符以内)。要对比多个值就多跑几次,
  或让脚本自己 `if` 出结论再打一个布尔
- **报错行里出现 `[truncated]` ⇒ 不要重试同一段代码**(会一模一样地再失败一次),
  立刻拆成"模块 + 一行调用"

## 3. 两个配套习惯

- **写盘后回读确认**: `write_file` 之后立刻用一次小调用打印 `len(s)` 和末尾 80 字符,
  确认文件完整(截断的写入是**静默**的, 不确认就会在残缺文件上继续搭)
- **模块先自检再上链**: 新助手函数先用一行调用验一个最小动作(例如 `cfg_get()` 打一个键名),
  绿了再写后续几步。一步一验比一次写完再 debug 快得多

## 4. 与报告纪律的配合

- 每轮**先说这次要做什么, 再做**(用户明确要求过: 不要长时间静默、不要在没告知的情况下连续动作)
- 汇报只写**回读到的实值**: 任务状态、对象大小、错误原文。**绝不用"应该"/"大概"/"看起来"**,
  更不要把折叠掉的输出当成已读
- 结论被后续回读推翻时,**主动更正并说明推翻的依据**(例如"先前判断密钥被轮换, 实测本地验签通过 ⇒ 该结论作废, 真因是头名")

## 5. 把 payload 嵌进生成的代码串: 一律占位符替换, 不用 % 格式化

生成 JS / 命令串时要把 payload 内联进去, **禁止 `%` 格式化和 f-string, 用占位符 + `.replace()`**:

```python
js = "const tma=__TMA__, suid=__SUID__;"
js = js.replace("__TMA__", json.dumps(TMA)).replace("__SUID__", json.dumps(SUID))
```

原因: payload 里带 `%` 是常态(URL 编码 `%7B%22`、printf 式日志、模板占位),
`"..." % v` 会把它们当转换符 ⇒ `TypeError: not enough arguments for format string`,
**整段脚本在发第一发请求之前就 Fatal**, 而报错行只指向那行字符串, 看不出是 payload 的锅。
`json.dumps()` 顺带保证引号 / 换行 / Unicode 转义正确(手写引号拼接必踩转义)。

## 6. 扫描类脚本先限定范围再递归

对未知大小的目录树递归扫描(`glob(..., recursive=True)` / `os.walk`)先做三件事, 否则**整轮超时且零输出**:
① 范围限定到本目标的工作目录(不从盘根 / 上级案卷根起扫);② 文件数上限(到 N 就停并打印"已扫 N, 截断");
③ **先打进度行再干活**(`print(文件数)`, flush)。扫 APK / 整盘找凭据时尤其如此 ——
一次性超时里唯一可用的信息就是那行进度; 没有进度行, 超时 = 白烧一整轮配额。
