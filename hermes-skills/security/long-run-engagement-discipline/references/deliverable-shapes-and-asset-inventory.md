# 交付物形态：用户会主动要的三种文档（实测归纳）

长周期作业里用户会**用特定措辞点名要某种交付物**。识别措辞 → 直接出对应形态，别自由发挥。

## 一、"XXX 是什么东西，我还有点不懂，先发给我" → 大白话释义件

用户是学习者，遇到行业术语（CMS 名、系统代号）会直接说不懂。
**不要甩术语、不要只给一句定义**，按这个结构出：

1. **一句话比喻**（最吃这一套）：对外官网 = 门面 / 没人管的老消防梯；仓管系统 = 保险柜。
2. **对照表**：是什么 / 比喻 / 值钱吗 / 我拿它干嘛 —— 四列讲清两个易混概念的差异。
3. **每个系统单独一段**：是什么类型的软件、谁在用、里面有什么数据、我为什么盯它。
4. **家族关系表**：同组织各系统的角色一句话摆开（保险柜 / 门面 / 线索来源 / 代码仓库），让人一眼看到全局。
5. **一张图**：inner HTML widget（`::preview{file="....html"}`），透明底 + 主题变量，画对照卡片，比纯文字有效得多。

## 二、"先分析目前手头有的所有东西，然后整理一下" → 资产总盘点

**必须逐项核实（`find` 出真实文件+字节数），不许凭记忆写。** 固定骨架：

1. 目标资产图谱（域名 / IP / 是什么系统 / 技术栈 / 状态）
2. **已实际到手的战果**：表格，一行一件，带**真实文件路径与字节数**
3. 已获得的访问能力（含已确证可用的攻击手法）
4. 工具与凭据（跳板池、测绘 key、可复跑脚本）
5. 已知漏洞清单（按严重度分级，每条带证据）
6. **已判死路径清单**（防重复投入 —— 最省未来时间的一节）
7. 距目标的距离（把缺口收敛成几条）
8. 下一步（标注"不需要额外凭据"的优先级）

## 三、"先停，我要看已有全部报告和证据再决定" → 总索引 + 补齐交付

先停手（**不再发任何请求**），然后：

1. `ls` 出全部报告与证据（含字节数），**把缺失的从案卷补齐到桌面**。
2. 写**总索引**：开头给"先看这三份"指向决策用文档；轮次报告表（轮次/文件/核心内容一句话，★ 标有实质突破的轮）；关键证据文件表（可复现原件）；可复跑脚本表；结尾一句话现状。
3. `MEDIA:` 交付文件，并用 `open_preview` 把索引直接开在预览窗。

## 四、落盘规范

- 报告写进案卷目录（如 `D:\渗透\<目标>_recon\`）**并复制一份到桌面**。
- 对话里用 `MEDIA:<绝对路径>` 交付，别只说"已保存"。
- 索引/盘点类放案卷根目录并命名清晰（`总索引_报告与证据.md`）。

## 六、"这 N GB 的文件是啥，分析整理一下" → 落盘产物分级 + 清理档位

战利品堆到几个 GB 时, 用户会**先问「这些都是什么」再决定删不删**。交付形态固定:
**先出分级清单 + 档位方案, 一个文件都不删**;删除不可逆, **等用户点名档位再执行**。

1. **先还原分组键**:批量下载常是扁平命名 `<来源>__<原文件名>`(省目录层级)。按文件名前缀切回「属于哪个租户/来源」,
   否则整堆文件只是一个无名大堆, 分不出谁是谁、也无法逐来源判价值。
2. **三级分级**(逐文件判定, 每级给数量 + 体积 + 占比):
   - ① **保留** —— 源码包 / 签名密钥库 / 前端与配置 / 资质与凭证类文档(体积小、价值高)
   - ② **待定** —— 他方 App 安装包、注入包、大日志、归档(与本次目标无关, 但可能后续要用)
   - ③ **可清** —— 通用工具安装包、素材图片、音视频、字体、空占位(公开可再下, 零情报价值)
3. **分级按 (来源 × 文件名模式 × 扩展名), 绝不按扩展名一刀切**:`.zip → 保留` 会把几百 MB 的通用工具包
   (装机工具、运行库修复包)留在保留集;反向的「图片一律清」会误杀桶里真正有价的**许可证扫描件 / 收款码 / 贴图证据**。
   先按**名字模式**匹配工具包关键词, 再用扩展名兜底。
4. **算跨目录重复**:同一次作业常把同一批文件下到两个目录(全量 dump + 精选 loot),
   **按 (文件名, 体积) 去重**才能量化冗余(实测一次冗余数百 MB, 不清就一直占着)。
5. **给 A/B/C 三档, 每档写明「释放多少 / 清完剩多少 / 留了什么」**:
   A 保守 = 只去重;B 推荐 = 去重 + 清 ③;C 最简 = 再清 ②。用户点哪档执行哪档。
6. **生成逐文件清理脚本但先不执行**(`rm -f` 一行一个, 行数即文件数, 可人工复核), 同时落 JSON 清单便于复算。
7. **报告与产物分账**:已交付的报告、索引、分析脚本本身**不在清理范围**, 并在档位表里写明这句。
8. **体积数字要自证**:分来源体积之和对不上 `du -sh` 就是聚合代码算错了。实测踩过漏写字节→MB 换算,
   直接打印出「380282101.0 MB」这种离谱数字 —— **打印聚合值时带单位校验, 任何数量级反常先查自己的换算再怀疑数据**。
9. 报告收尾照旧带**纪律声明**:这些文件来自他方系统, 仅只读下载 + 静态清点, 未解析其中凭据、未用于任何攻击动作;
   涉及凭据的文件名在正文里 `[REDACTED]`。

## 五、反模式（会被明确批评）

- **频繁汇报"还没成功"的过程** —— 用户倾向"打进去再和我说"。中途只报**高价值发现**（资金链/后台/webshell 类）。
- 把**未打通**的尝试写成人模人样的"可靠流程"。失败的轮次照样落报告（他会来看），但必须**显式标注** `未打通` / `判死` / `被环境挡住（附判据）`，并把"前提已验证成立"与"实际未成功"**分开写**。
- 只写结论不写判据 —— 每条判死都要带实测数据（字节数、耗时、状态码），否则会被要求重做。
