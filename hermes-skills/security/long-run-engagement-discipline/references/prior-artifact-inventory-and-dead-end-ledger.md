# 开工前盘点「自己留下的战果」与死路台账

**触发**:压缩上下文 / 换会话 / 隔天续跑之后,重开一轮探测之前。
**一句话**:旧战果不在你脑子里,只在跳板机和本地产物里。**先读产物,再动手。**

## 1. 必做的一次盘点

```bash
ls -la /root/<target>/                                  # 历史脚本、输出、已 dump 的源码
find /root/<target> -maxdepth 2 -name "*_out.txt" | head # 已有输出
find /root/<target> -maxdepth 3 -name ".git" -type d     # 已 dump 的仓库
ls -d /root/<target>/out* 2>/dev/null
```

本地目标目录同时看:已有的 `作业报告_第N轮_*.md`、`已判死资产` 清单、`ss*.out`。

## 2. 实测教训(2026-09,白撞一整轮)

重开一轮去测某站 `IndexAction::index()` 里 `->where("sign='{$kw_sign_id}'")` 的裸拼接注入,
四种载荷(含 GBK 宽字节 `%bf%27`)全返回 **0 字节**,当场判"引号被转义"。

随后在跳板机的 `fm_k11_out.txt` 里发现:**自己上一轮已经把 BASE / UNION n=1–12 /
LOAD_FILE(`/etc/passwd`、`/wwwroot/<domain>/config.php`、`nginx.conf`)全测过,结果一样全是 0 字节。**

于是真相是第三件事:那条 `D('User_temp')` 走模型工厂,**模型类缺失即抛异常,debug 关闭 → 空白页**,
即该 action 是**死代码** —— 连"是否可达"这个真问题,都是靠**旧输出**才看清的,
而且这个结论本身就写在旧输出里。

**代价**:一整轮请求 + 一轮汇报,零新增信息。用户会直接感知成"没进度"。

## 3. 顺手盘点三条战线(不止一条)

同一目标常并行开着多条线,盘点时都要看一眼,否则会漏掉**手上已经握着的最锋利那把刀**:

| 战线 | 形态 |
|---|---|
| 源码 | 已 dump 的完整源码 / `.git` 仓库(`redbook/`、`<target>/.git`) |
| 专项战役 | `huitun_r1…r38` 这类多轮脚本序列 —— 看最后一个脚本与它的输出 |
| 跳板产物 | `*_out.txt`、`<target>/` 下的 dump 目录、`clone_*.sh`(常直接写明远端地址) |

`clone_rb.sh` 里一行 `git clone http://<ip>/<ns>/<repo>.git` 就暴露了整个组织的代码中心 ——
**这种枢纽级线索往往藏在"随手写的克隆脚本"里**,盘点是唯一能重新发现它的方式。

## 4. 死路必须落盘

- 每轮结束把**已判死项**写进目标目录(`已排除.md` / 追加到当轮报告),格式:`路径/参数 → 载荷 → 响应摘要 → 结论`
- 复用输出时**先 `read_file` 读回**,不要靠终端 `cat`(会退化成"1 lines output")
- 复测前问自己一句:**"这一发和旧输出有什么不同?"** 答不出来就别发

> 与「别重复已排除的路径」是同一条纪律:**盘点是手段,不重复是目的。**
