# 证据在场自检:别把「命令跑了」当成「我看到了」

补充 `long-run-engagement-discipline` §4(忠实交代)。这是一条**过程纪律**,不是工具问题 ——
它管的是:长跑几十轮之后,你怎么保证写进战报的每个数值都是**真观测到的**。

---

## 1. 违规长什么样

长跑里连续几十轮工具调用,极易把「命令执行完了(exit 0)」误当成「我看到结果了」,
于是把**推测/预期的结果**当成**观测**写进战报。对用户这是最严重的违规:

- 用户原话:「**不要欺骗我** —— 永远说真实情况,不给虚假希望」
- 用户原话:「**严禁偷懒/偷奸耍滑** …… 事事有依据,事事要落实到位」

**危险信号:你正在写一段层次分明、数值具体的表格或清单,但回想不起来是哪个返回里有这些数字。**
这种「读起来很合理」的内容,极可能是你自己补全出来的。**停下来重取,不要靠合理性过关。**

---

## 2. 自检那一问

> **这条结论里的数值/字符串,是我在本轮工具返回里亲眼读到的吗?**

判定标准(要逐字节可复现才算证据):

| 算证据 ✔ | 不算证据 ✘ |
|---|---|
| `200 / 58B` | 「应该是 200」 |
| `{"err":"-99","err_msg":"登录超时"}` | 「返回了登录超时之类的」 |
| `<title>K11系统</title>` | 「标题看着像后台」 |
| `403 ATD_FORBIDDEN/101.200.225.184/c24685` | 「被 WAF 拦了」 |
| 两个文件的字节数差 `39823 vs 45967` | 「版本不一样」 |

---

## 3. 占位返回 = 这一轮什么都没观测到

某些调用形态的返回**只有摘要、没有正文**(例如只有一行 `N lines output`,
或只有 `read X (N chars)` 而正文缺失)。看到这种返回:

1. **这一批结论全部作废** —— 不是「大概也对」,是**没有证据**;
2. 换成**你能读到正文**的调用方式重取;
3. 若这些结论**已经报出去了** → **下一轮开头主动收回并重新验证**,
   不要装作没发生,也不要让它继续躺在报告里。

**实战踩点(2026-09,同一目标)**:一轮里十几次远程探针都走了「外层脚本包一层再打印」
和「命令接管道(`| tail` / `| head`)」两种形态,拿回来的全是单行摘要;
期间产出的「字节数 / 状态码 / 模板字段表」等细节**均未真正读到**。
改为**直接执行、不套管道**后,同样的脚本立刻返回完整正文,结论才落地。

**可操作结论:远程探针脚本直接跑、不要接管道;需要裁剪输出就让脚本自己在内部裁剪。**
(「看不到正文」是调用形态问题,换一种形态即可 —— 不是某个工具不能用。)

---

## 4. 与「单发冷却」的联动

§3 要求「一发就把这一轮要读的全部动作塞进一条远程命令」。发射之后**必须确认这一批的
返回正文真的读到了**,再下结论 —— 否则等于花了配额却没拿到证据,下一轮还要重发,
在按发数计费的 WAF 配额下这是双重损耗。

**推荐顺序:发射 → 读正文 → 逐个数值核对出处 → 再写进度报告。**

---

## 5. 与本文件配套的写法

进度报告固定三行,每行的数值都必须来自本轮真实返回:

```
本轮拿到什么:<数值 + 出处(命令/响应片段),不要"已突破"这种空话>
卡在哪:<具体原因>
下一步:<具体动作>
```

拿不到就写「没拿到」—— **"K11 数据本轮一条都没拿到" 远比一个漂亮的假表格有价值。**
