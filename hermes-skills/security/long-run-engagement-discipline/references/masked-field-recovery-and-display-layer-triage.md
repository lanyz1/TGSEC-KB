# 脱敏字段(PII)的还原:多接口字段级并集 + 脱敏层定性(2026-09-14 K11 实测)

> 适用于任何「免登录口返回的字段被打码(`186*****745`)」的场景:
> 先判断能不能拿明文,再决定怎么拿最多。配套 `recovered-data-acceptance-gates.md`。

## 一、★先定性:脱敏在「展示层」还是「数据层」

**最强判据:拿客户系统自己的导出表,与免登录口对同一条记录。**

同订单 `260308083418915`:

| 来源 | 收件人电话 |
|---|---|
| 客户系统 `daochu` 导出(xlsx,34 列) | `<PHONE-REDACTED>`(明文) |
| 免登录 `api.php?ac=xp` | 无电话字段 |
| 免登录 `api.php?ac=zt` | `186*****745`(掩码) |

⇒ **库内存明文,打码只是免登录口的展示逻辑** ⇒ 定性为「权限问题」,不是「数据缺失」。

**这条判据一次性决定后续投入方向,比任何 payload 试探都值钱。**
**优先向用户索取客户侧的导出/报表** —— 它一击回答这个问题,且自身就是明文数据。
反面教训:在没做这个定性前,把「打码能不能靠参数/UA/头解开」当成主攻方向,白烧一整轮。

## 二、接口 × 字段打码矩阵(实测,决定采哪些口)

| 动作 | 内容 | 姓名 | 电话 | 地址 | 备注 |
|---|---|---|---|---|---|
| `ac=xp` | 波次订单明细 | 明文 | **无** | **无** | 主数据源,200 单/波硬上限 |
| `ac=zt` | 中通面单 | **明文** | 部分掩码 | **明文(精确到门牌)** | 姓名/地址最佳源 |
| `ac=sf` | 顺丰面单 | 部分掩码 | **明文** | 部分掩码 | **寄件人电话全明文** |
| `ac=jd` | 京东面单 | 全 `***` | 全掩码 | 全掩码 | 给 `query_address` 令牌(内部域名,不可达) |
| `ac=ems`/`ac=yt` | — | — | — | — | 恒 54B 空 |

**关键:`zt` 给姓名明文而 `sf` 给电话明文 ⇒ 打码字段在接口间互补。**
**⇒ 先枚举「接口 × 字段」矩阵,再决定采几路;不要只采一路就下结论说"数据没有电话"。**

## 三、★还原手法:业务键 JOIN + 字段级「星号最少者胜」

多路并行采集,以业务键(此处 `wuliu` 运单号)JOIN:

```python
def better(a, b):
    if not a: return b
    if not b: return a
    if a.count("*") < b.count("*"): return a
    if b.count("*") < a.count("*"): return b
    return a if len(a) >= len(b) else b
```

实测(面单记录 57k→120k):姓名明文 28.9k→61.1k、寄件人电话明文 7.0k→74.6k。
**并集是净赚,不是零和。** 落库时把"半明文"和"全明文"分开计数,别只报一个总数。

**诚实边界**:部分订单在**五个口全掩码** —— 源数据属性(典型为电商平台**隐私号**)。
**外部无解,别当"再试就能出"的坑反复烧配额**;在交付说明里写明这类不可还原,别虚报覆盖率。

## 四、判死清单(带证据,别重走)

| 线 | 证据 |
|---|---|
| `sys` 档位控制脱敏 | `sys=0..20` 对同一波次响应**逐字节相同**(6708B、同掩码) |
| 身份参数解锁 | `uid/userid/user_id/admin/is_admin/level/utype/type/role/sid/op/u/all/full` 14 个 → **零变化** |
| 其他 dispatcher | `api2/api3/api_bch/print/pda/app/mobile/scan.php` → 全 404 |
| 用户类动作 | 12 个(`userlist/users/staff/account/admin/list/…`)→ 全「方法不存在」 |
| `data.php` 未授权 | 全 action `{"err":"-99","err_msg":"登录超时"}` |
| 配置/备份文件 | `/config.php` `/inc/config.php` `/config.bak` `/1.txt` `/data.txt` 等 **18 种绕过**(大小写/`%6E`/路径规范化/`%00`/`;`/尾点/`//`)**全 403** |
| 内部域名 | `kd-query.jxslsmd.com` + `jxslsmd.com` 17 个子域 → 公网全 NXDOMAIN(仅根域/www 有) |

## 五、★免费副产物:403 vs 404 = 文件存在性 oracle

nginx 对**存在但被规则拦**的文件回 `ERROR: ACCESS DENIED`(403),
对**不存在**的回标准 404。据此直接反推真实目录:

- 403(存在):`/config.php` `/conf/config.php` `/inc/config.php` `/application/config.php`
  `/admin/config.php` `/config.inc.php` `/nbs/db.php` `/inc/db.php` `/1.txt` `/data.txt`
- 404(不存在):`/include/config.php` `/data/config.php` `/nbs/config.php` `/app/config.php` `/.env`

⇒ **命名空间测绘免费拿到**(`/conf/ /inc/ /application/ /admin/ /nbs/` 真实存在)。
⚠️ PHP 类配置即使绕过也只会**被执行**(返回空),要源码得找编辑器备份 —— 备份面常被同规则覆盖。

## 六、一般化结论

1. **多接口字段级并集**:同一系统的兄弟接口(不同快递/渠道/打印模板)打码字段常互补;
   按业务键 JOIN + 「星号最少者胜」能白捡大量明文。
2. **客户自己的导出/报表是最强定性证据**,优先索取。
3. **403-vs-404 差值**是免费的目录测绘 oracle。
4. **打不动的内部域名早判死**,别在 NXDOMAIN 的服务上反复烧配额。
5. **打码 ≠ 无数据** —— 报交付时区分「已还原明文」「半明文」「源数据即掩码」三档。
