# 长时作业的证据核对纪律(血泪版)

## 1. 终端摘要行不是证据

- 现象:长命令跑完只回显 `-> exit 0, 1 lines output`,看不到正文。
- **必须**:`cmd > xxx.out 2>&1` 落盘 → `read_file xxx.out` 回读原文 → 再下结论。
- 轮次代价(真实教训):两次仅凭终端摘要就宣称「ZIP slip 打穿了」,回读 `.out` 原文实为
  `{"code":7,...,"msg":"非标准插件"}` + 站点根返回 SPA(即**根本没落地**)。结论完全错误,只能向用户显式更正。
- 规则:任何「打穿 / 拿到 / 成功」的判定,都必须能指到一条**原始证据行**
  (HTTP 状态 + 内容匹配 / 数据库回读值 / 文件落点回显 / 命令输出)。指不到就只能说「疑似,待验证」。

## 2. 自我更正要显式、要放第一条

发现前轮结论错误时,下一条消息**开头就写「纠正」**,给出原文对照,不要静默改口、
不要把新结论混进正常汇报里。用户明确要求「不要欺骗我」—— **错报比慢报严重得多**。

## 3. 「接口被摘了」先自证三条

1. 方法是 GET 还是 POST?
2. 大小写 / 前缀对不对(`exportTemplate` vs `ExportTemplate`;`/autoCode/mcpTest` vs `/mcp/test`)?
3. 同批里有没有**已知可用的对照路由**返回 200?

三条全过了再判「被摘除」。本轮就因为方法/大小写错误,两次误判「对手在实时摘接口」,
实际是对手没动、我路径写错。**权威路由表 = 目标自己的 `sys_apis` 表(method + path 逐字照抄)。**

## 4. 被护栏拦下 = 停手上报,不重试不绕路

- 改配置、写公钥、持久化这类**改真实状态**的动作会触发审批护栏;无人确认时直接返回
  `BLOCKED: ... Do NOT retry, do NOT rephrase ... Silence is not consent`。
- 正确动作:**立刻停**,向用户给出 ①要做什么 ②几个请求 ③怎么还原 ④为什么值得,然后等明确放行。
  不要换工具、不要改写法重试、不要静默丢下这条线继续推进别的(要说明这条线被搁置)。
- 自己先做**风险分级**:纯读探针随便打;写类动作一律先报备。

## 5. 汇报格式(用户偏好)

分段固定:
**① 已验证(带原始证据) ② 判死(带机制 + 原文) ③ 待验证 / 剩余打法 ④ 本轮写入账(表 + ID + 对象存储 key,逐条可清)**。

- 用户反感长时间沉默,也反感「未成功过程」的碎碎念,但**要求任何进一步动作前先说明要做什么**。
- 结论先给、证据随后;只推本次变更,不夹带无关内容。
- 判死项要写清**机制**,不要只写「不行」—— 下次才不用重复试。

## 6. 长脚本写入会被截断

- 单次 `write_file` 正文过长会被砍成残片(几十 ~ 二百字节),脚本直接语法错。
- 对策:脚本**写短**(几十行为宜)、拆成多次小写、或改用 `execute_code` 内联执行;输出一律落盘再回读。
- 同机并发会话还会互删/覆盖同名脚本 ⇒ 用唯一文件名。

## 7. 收尾账要能逐条还原

每个在目标上留下的东西都要登记:**数据库表 + 记录 ID、对象存储 key、磁盘文件、配置改动(含原值)、
进程 / 监听端口、定时任务**。「没能力清掉的」要明确说清,不能含糊带过。
