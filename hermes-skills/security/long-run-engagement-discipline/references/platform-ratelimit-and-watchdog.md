# 长跑扫描的平台限流处置与哨兵设计(2026-09 灰豚数据实战)

> 长时作业里最容易犯的两个错:①把**平台限流**当成"目标封我/会话失效",然后沿着错误结论折腾;
> ②长扫在**前台**跑,被工具超时切断,以为"没跑成功"。本页给出实测可用的处置与哨兵形态。

---

## 1. 平台限流的识别(**账号级** vs IP 级)

实测响应(账号级,高频探测触发):

```json
{"path":"/error","total":0,"code":-100102,"data":{"appId":"..."},
 "roleId":2,"nextRole":0,"message":"请求过于频繁，已被限制访问,请完成验证","status":200}
```

要点:

- **HTTP 仍是 200**,靠 `code:-100102` + 中文 message 识别;所以**分类器不能只看状态码**。
- 这类响应**顺手泄露档位**(`roleId` / `nextRole`),是意外情报。
- 与「登录失效」(`-200 登录状态已失效`)、「缺参数」(500 系统异常)是**三种不同状态**,必须分开归类,
  否则会把限流误判成"掉登录",白白重登一次。
- 触发后**立刻停手**,冷却数分钟后再来;不要在限流窗口里继续打(会延长/加重)。

## 2. 长扫的节奏与运行位置(硬规矩)

- **间隔 1.1–1.3s/请求**;上千条路径的清单按这个节奏设计(1,340 条约 25–30 分钟)。
- **长扫一律放后台**:`setsid nohup python3 sweep.py >> sweep.log 2>&1 < /dev/null &`,
  进度与命中**写文件**(TSV/JSONL),前台只做"轮询 + 读文件"。
  - 前台工具调用有超时上限(本次 420s/600s),长扫在前台必被切断;**但远端进程其实还在跑** ——
    所以正确姿势是"启动一次 + 轮询",而不是反复重跑(重跑会产生重复请求,触发限流)。
  - Python 输出重定向后会**缓冲**,`log` 可能长时间空白;判断进度要看**写盘的文件行数**(如 `wc -l hits.tsv`),
    不要因为日志空就断定卡死。
- **命中是稀疏的**:千条路径里"真有数据"的通常只有几十条;把"命中率低"当成正常,不要因此推翻清单质量。

## 3. 哨兵(监控脚本)设计:必须区分三态

长跑期间挂一个定时哨兵(如每 30 分钟一次只读校验),它必须能区分:

| 状态 | 判定 | 哨兵该做什么 |
|---|---|---|
| `OK` | 正常返回业务数据 | **静默** |
| `RATELIMIT` | `code == -100102` / 含"请求过于频繁" | **静默 + 计数**,不告警(否则每 30 分钟给用户一次假警报) |
| `BAD` | 连接失败 / 登录失效 / 跳板不可达 | **告警**(这才是需要人工介入的) |

最小实现(伪代码):

```python
j = json.load(open(resp_file))
if isinstance(j, dict) and j.get("code") == -100102:
    print("SESSION=RATELIMIT"); raise SystemExit      # 限流:不告警
d = j.get("data")
if not isinstance(d, str):
    print("SESSION=BAD"); raise SystemExit            # 真失效:告警
...
```

**静默型 watchdog 的正确形态**:`no_agent=True` 的 cron + 脚本,**无输出即不打扰**;
只有"等级变化 / 会话失效"这类需要人工决策的事件才打印一行,由调度器推给用户。
(本次实现:`profiles/<p>/scripts/<target>_watch.py`,每 30 分钟,`deliver=all` 以便推送到已连的网关。)

## 4. 会话资产的长跑保管

- 会话 cookie **存在跳板机**(`/root/<target>/jar.txt`)**并备份回本机**;哨兵持续做只读校验,兼当"会话保活+失效探测"。
- 登录链路(短信码/图形码)一旦跑通,**把整条链脚本化**(`login_stepN.py`),失效时能 1 分钟重登,
  不必重新逆向前端。
- 重登前先分清 §1 的三态 —— **限流时重登是无效动作**。

## 5. 交付物里要写的一行

> 「期间触发过一次**账号级限流**(`-100102`),已停止并冷却;后台哨兵恢复为每 30 分钟一次只读校验。」

主动披露限流与处置,比让用户从日志里发现"你的请求被拒了"要好。
