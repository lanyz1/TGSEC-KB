# 脱敏数据恢复类交付的验收闸门(2026-09-14 实战)

> 适用:把"被打码/被脱敏"的数据恢复出明文后**交付前**的验收。
> 核心:行数不是验收指标。**假阴性陷阱 + 两条独立闸门 + 机制相关性**才是。

## 一、先证"探针写法",再证"数据对不对"(假阴性陷阱)

拿回读到的明文**反查生产库**做验收,本次得到**全 0**,第一反应是"采集的数据是错的"。
**错的是探针,不是数据。** 三组对照(同一条 `offset=448` 的行):

| 对照 | 语句 | 结果 | 判读 |
|---|---|---|---|
| A | `select card from fm_staff where <WHERE> limit 448,1` | `<IDCARD-REDACTED>` | 与采集值**逐位一致** ✓ |
| B | `select count(*) where card=0x<hex>` | **0** | 写法失效(假阴性) |
| C | `select count(*) where card=(select card … limit 448,1)` | **1** | 阳性对照 ⇒ 真值确实在库 ✓ |

**纪律:凡要下"取到的数据是假的 / 不存在"的结论,必须先跑通一个阳性对照。**

- 字符串列与裸 `0x<hex>` 字面量比较,MySQL 按二进制串/字符集语义会**静默不匹配**
  ⇒ 用 `col=(select col … limit N,1)` 自比较,或 `col=unhex('<hex>')`
- 最强验收形态 = **重查同一游标位置,与采集值逐位比对**(复现性证明,不依赖任何比较写法)
- 对照 A 命中后,**早先那几个 0 必须显式更正**("这是我探针的假阴性,不是数据错"),
  不能让假结论留在记录里(见 `evidence-verification-discipline.md` §2)

## 二、闸门 1:格式校验位(可离线全量)

中国大陆身份证 = **mod-11 校验位**,末位可为 `X`:

```python
W  = [7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]
CK = "10X98765432"
ok = CK[sum(int(c[i])*W[i] for i in range(17)) % 11] == c[17].upper()
```

本次:9,603 条里 **241 条失败(2.4%)**。
⇒ 要么源数据本身填错、要么采集有瑕。**必须给比例,不能只说"通过"。**
(同理:手机号、银行卡、统一社会信用代码都有各自的校验位,优先用它做零成本全量闸门)

## 三、闸门 2:独立来源交叉校验比(交付可信度就是这个数)

用**与采集通道完全无关**的另一路数据去撞,报告 **match : mismatch**:

- 本次独立来源 = **系统自身的导入流水**(1050 条明文,来自应用自己的日志/流水文件)
- 撞击键 = "可见片段键"(本次 = `前4位 + 后4位`,即打码后**仍然可见**的部分)
- 结果:**match 251 : mismatch 10 = 96.2%** ⇒ 这就是交付可信度,写进报告

**mismatch 不等于"我错"**:也可能是**不同人共享同一片段键**(前4+后4 巧合相同)。
如实写"疑似键碰撞,未逐条定性",**不要为了好看硬报 100%**。

## 四、验收态三分(别把"还没取"写成"已销毁")

逐行标注三态,**不要用会被误读的标签**:

| 标签 | 含义 |
|---|---|
| `PLAIN_RECOVERED` | 明文已到手 |
| `NOT_RECOVERED` | 显示为打码、**尚未取回**(其中可能大部分是可取的!) |
| `ORIG_PLAIN` | 源本身即明文 |

坑:本会话一度用 `DB_DESTROYED` 标"打码且未取回",结果把**12,713 行可恢复的**也标成"已销毁",
报告结论会被完全误读。**中性标签 `NOT_RECOVERED`,等采集跑完再把其中真不可恢复的单独算出。**

## 五、用"状态字段相关性"证明因果机制

要论证"某业务动作造成了数据被改",别停在"我推测",去**量规模相关性**:

```
被打码行 ∩ 离职 = 19,608   (94.6%)
被打码行 ∩ 在岗 =  1,061
```

⇒ 机制成立(离职流程把打码值回写字段),**同时异常项自己浮出来**(1,061 行在岗却被销毁)。
**机制 + 反例两个都要写进报告。** 只报 94.6% 而不提那 5.4% 属于选择性汇报。

## 六、交付前最后一问

> "这个数字,如果是对手/客户来复核,他第一步会做什么?"
> 能答出(重查游标 / 查校验位 / 撞独立来源)且都通过 = 可以交付。
