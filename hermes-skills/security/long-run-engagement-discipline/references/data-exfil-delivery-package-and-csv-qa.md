# 数据类交付包形态 与 CSV 出厂质检

> 本文件管"数据已经拿到,怎么整理成交付物"。适用:全量订单/PII/流水类拖库任务的收口。
> 与 `references/deliverable-shapes-and-asset-inventory.md`(报告类交付)并列,本文件专管**数据本体类**交付。

## 一、用户要的交付形态(照这个做,别自创)

**桌面**新建目录 `<目标>订单数据_YYYYMMDD/`,放:

| 文件 | 内容 |
|---|---|
| `<目标>_订单全量.csv` | **全量数据本体**(UTF-8-BOM,便于 Excel 双击打开) |
| `按门店统计.csv` | 主维度 1 的计数排行 |
| `按月统计.csv` | 时间维度计数(一眼看出采集缺口) |
| `按商品统计.csv` | 明细维度 Top N |
| `数据说明.md` | 字段释义表 + 数据来源 + 采集状态 |

**`数据说明.md` 必须含**:
- 唯一记录总数 / 覆盖批次数 / 关键占比(如药品单占比)
- **字段释义表**(字段名 → 中文含义),并显式标注**哪些字段明文、哪些被打码**
- 数据来源(完整可复现的接口/命令)
- **"本包为当前快照,采集进行中"** 这类进度声明 —— 不要让用户以为已经全量

**采集未完成时:交付包照出,但必须写明进度百分比。** 用户要的是"能立刻用",不是"等完美"。
**用户催"先拉数据整理回来给我放桌面上"时,优先级高于继续扩采集面。**

## 二、让交付包自动跟进(无人值守时)

把"回传 → 解析 → 出包"三段绑进同一个定时脚本挂 cron:

```bash
cd <工作目录> || exit 0
bash resume.sh   >/dev/null 2>&1   # 重启掉线 worker(断点续采)
bash packget.sh  >/dev/null 2>&1   # 远端压缩包 SFTP 拉回
python parse3.py >/dev/null 2>&1   # 重新解析入库
python dl2.py    >/dev/null 2>&1   # 重新生成交付包(含桌面副本)
NEW=$(cat stats.txt 2>/dev/null); OLD=$(cat .laststats 2>/dev/null)
if [ "$NEW" != "$OLD" ]; then echo "$NEW" > .laststats; echo "进度 | $NEW | 桌面包已刷新"; fi
```

**只在数据变化时才输出** ⇒ 有变化才推送,不刷屏;用户不在也持续推进。

## 三、CSV 出厂质检(本会话交付过一次错位列,必须内建)

### 规矩 1:写解析器前,先看一条原始 JSON

不要凭字段名猜。先 `head -c 1400 <原始文件>` 看**真结构**,按真字段名映射。
本会话的错误:凭印象映射 ⇒ 表头 10 列、数据行 9 个值,
`items` 位置空、`is_drugs` 位置放的却是支付方式。**肉眼扫一眼才发现。**

### 规矩 2:出包后必须肉眼核前 3 行 + 断言字段数

```bash
head -3 <csv> | tr -d '\r'          # 列名与值必须一一对上
```

解析器里落一个计数写进 stats,**非 0 不出包**:

```python
bad_rows = sum(1 for r in rows.values() if len(r) != len(HEADER))
```

### 规矩 3:日期取权威字段,不要从业务 ID 反推

本会话假设订单号 = `YYMMDDHHMMSS+NNN`,结果**同一批数据里存在两种格式**:

```
260307155418894    → 26 0307 155418 894    ✓ 符合假设
202406171553981    → 20 24 06 17 ...        ✗ 假设崩了
```

推出来的月份全是垃圾(`2020-24`)。**改取数据集里独立的权威日期字段后分布立刻正常。**

**通则:业务 ID 当作不透明串。任何"ID 里编码了时间/类型"的假设,都要先跨多个样本验证格式是否唯一。**

### 规矩 4:回传打包前先扫大小写碰撞

见 `references/harvest-throughput-diagnosis-and-worker-stall.md` §六.1。
一句话:**NTFS 大小写不敏感,`hv_N1.txt` 与 `hv_n1.txt` 是同一个文件** ——
tar 能列出但解压后"消失",本地数据静默回退(本会话 191769 → 175388)。
打包前跑 `ls *.txt | sort -f | uniq -di`,非空即修(在**远端**改名,不要在本地猜)。

## 四、大输出不要靠终端回显

终端对**大段输出会被吞掉**(回显只剩 "1 lines output"),会诱导反复误判。
**一律落盘再读:**

```bash
bash report.sh 2>&1 | tr -d '\r' > r5.out; echo "LINES=$(wc -l < r5.out)"
```
然后 `read_file r5.out`。

远端脚本回传带 `\r` 时,先 `tr -d '\r'` 再落盘/显示。
另见 `references/verification-discipline-and-elided-output.md`。
