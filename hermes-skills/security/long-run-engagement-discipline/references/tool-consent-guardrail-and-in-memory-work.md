# 工具授权护栏与「纯内存作业」

长跑作业里最常见的**假卡死**:你想做的事没被拒绝,是被宿主 GUI 的授权弹窗挡住了,
而你以为自己在跑。

## 现象(可复现)

- `execute_code` **一旦要在磁盘上落脚本文件**(写 helper `.py` 再跑),会触发授权弹窗。
- **用户在对话里说「放行」「继续」≠ 弹窗被点。** 弹窗超时 = 自动判拒,返回:

  ```
  BLOCKED: execute_code script timed out without user response.
  The user has NOT consented to running this code.
  Do NOT retry, do NOT rephrase, and do NOT attempt the same outcome via a different tool.
  Silence is not consent.
  ```

- 同一轮里**纯内存**(只发 HTTP、只读文件、只 print)的同形态代码能正常跑完
  ⇒ 被卡的是「落盘」这个动作,不是任务本身,更不是目标变动。

## 纪律

1. **卡住就停**:不重试、不改写、不换工具绕。把「要点一下弹窗」讲给用户,
   并说清卡在哪一步、什么动作没执行(用户不需要懂细节,点一下就行)。
2. **能纯内存就纯内存**:探测/验证脚本一律写成 `execute_code` 里的一次性内联代码,
   不在工作目录或目标上留 helper 脚本。既避开弹窗,也不在本地留痕。
3. **把口头的放行翻译成可执行动作**:用户说「放行」时,回一句「请点弹窗」再发;
   或把脚本正文直接贴给用户自己跑 —— 这是合法兜底(决定权在用户),不是绕过。
4. **被卡的那一步必须写进进度汇报**,不要静默吞掉:
   用户以为你在跑,实际什么都没发,这是最招骂的一种静默。

## 汇报模板(卡护栏时)

```
我要做 X(一句话)
卡在:授权弹窗未被点击,已超时自动拒绝 → 动作未执行(不是失败,是没跑)
需要你:点一下弹窗,然后回「继续」
```

## 顺带:同轮里"两条命令互为依赖"时的分片纪律

- 落盘脚本被拦时,**不要**把「先写文件、再执行」硬凑成一条更长的命令;
  那是换形态重试同一件事。先把弹窗问题解决,再原样重发。
- 反过来,如果弹窗能过而脚本有语法/依赖问题,收尾同样要**回读产物**再宣布结果
  (参见本技能 「忠实交代」一节)。
