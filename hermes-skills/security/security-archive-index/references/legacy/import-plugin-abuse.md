# import-plugin-abuse

适用：目标后台/商户端有「搬家」「一键导入」「采集」「同步其他站点」「上游对接」类插件或配置页（自研 CMS/发卡/商城、SaaS 二开最常见）。目标是找**写原语**（写库、写文件、免审核上架）或把多阶段服务端出站流程跑完。

## 核心判断

导入类插件 = 服务端「按远端协议取数 → 写进本站」。**上游在你手上 ⇒ 写进本站的内容在你手上。**跑通它通常一次拿到四类收益：

1. **免审核写入原语** —— 导入路径常直连 DB/模型，绕过内容审核位、上架位、字段长度校验。
2. **任意 HTML/URL 落库** —— 标题/描述/图片字段原样存 ⇒ 存储型 XSS、二次 SSRF、内容注入。
3. **情报外泄** —— 任务记录常回吐源站账号口令（加密态）、内网实例地址、迁移范围、阶段与错误日志（= 进度神谕）。
4. **新的写面候选** —— 插件参数、主题/样式名（见"通用坑"）。

## 步骤

### 1. 摸协议（只读优先）

- **先从插件目录/插件页取真入口，别用 `/plugin/<Code>/api/*` 的 404 判「未安装」**：真入口路径在插件目录与插件 UI 返回的 `src`/`url` 类字段里（`Plugin/list`、`PluginLocal/menuList` 一类端点）。实测同一目标上不同插件的命名空间前缀并不统一（`/plugin/<Code>/merchant/index` 与 `/plugin/<Code>/api/<action>` 并存）⇒ 走错前缀会得到满屏 404，把已装插件误判成未安装。
- **契约在插件页的「内联」`<script>` 里，不在它引用的外部 JS 资源里**：插件页 HTML 自带 Vue/element/axios 内联脚本（实测 30KB 页面内联即含全部 action 名），而它 `<script src>` 指向的静态资源常 404 或回 0 字节 ⇒ 直接抓页面 HTML 抠 axios/fetch 调用点、请求体字段名、路由族（如 `/plugin/<Code>/<merchant|api>/<action>`）。别猜字段名，去 JS 里抠。
- **插件有自己的响应信封，别用宿主平台的约定判成败**：本族插件判据是 `code===200`（异次元/ACG-FAKA 生态口径），宿主平台却是 `code:1` ⇒ 按平台口径读会把成功读成失败/异常，进而误判端点不可用。先在该插件 JS 里抠出它自己的成功码与错误形状。
- **请求内容类型逐插件从各自 JS 抄**：同一目标实测一个插件是 `axios.post` JSON、另一个是 `application/x-www-form-urlencoded` ⇒ 用错类型回的是让你误判「字段名不对」的错。
- **未知 action 常被「接住」而非 404**（回 200 或业务错误）⇒ 按 JS 里的字面量逐个试隐藏动作，别只看 404 结案。
- 先打只读端点：`detail` / `list` / `tasks` / `config` / `params`。任务记录字段常见 `stage` / `error_msg` / `log` / `source_url` / `source_username` / `source_password`。
- 记录它请求上游的**完整形态**：方法、路径、头、表单体或 JSON、期望响应形状。

### 2. 起假上游（三件套）

- **任意方法原始记录器**：raw socket（不要 http.server 只分 GET/POST 的写法），逐字节记 request line + headers + body；否则漏掉 PUT/OPTIONS/自定义方法。
- **路由表热更新**：「路径 → 响应体」放外置 JSON，改文件即生效，不必每次改脚本重传。
- **响应形状对齐**：上游解析失败通常只回一句模糊话（「源站登录失败…返回：ok」）⇒ 把记录到的原始响应按插件期望的 JSON 形状重包一层。

骨架见 `references/jingsoft-migrate-shop-pro.md`。

### 3. 迭代循环（每次只加一个端点）

跑一次 → 读**上游日志**看它下一个请求哪个路径 → 给该路径加响应 → 再跑。**错误文案会点出缺什么**，按字面修，别猜：

- `请填写源站账号和密码` ⇒ 请求体字段名错；去 JS 抠真名。
- `源站登录失败…返回：X` / 连接超时 ⇒ 响应形状或状态码不对。
- `原因：请先登录！` / `缺少商家登录态，无法通过系统接口导入卡密`（本地口径）⇒ 该阶段用的是**平台本地特权 API**（需管理员身份），与上游令牌无关 ⇒ 此链到此为止，不要再把上游令牌换来换去。
- **登录常要两跳**：先预检（安全模式一类）再真登录，**第二跳必须回令牌字段**（实测缺 `merchant_token` ⇒ `新版登录成功但未返回 merchant_token`）。只回 `code:1`+`msg` 会停在第 2 跳；按报错里的字段名补。
- **抓取阶段 = 候选端点试探，判据是「列表非空」**：它依次试一组同族候选路径（多样拼写，每个先 POST 再 GET），**第一个 `code:1` 且列表非空者被锁定**，后续阶段沿用同族前缀。⇒ 假上游的 default **别统一回空列表**，否则只报 `接口已匹配但列表为空` 并卡死（它不会接着试下一个候选）；未知路径宁可回 404/错误码。

### 4. 结果判定（别自我说服）

- 用目标站**自己的读接口**回读阶段产物，确认真落库，并确认**绕过了哪些校验**（审核位、上架位、字段长度）。
- **附件/图片字段先判"服务端下载写文件"还是"原样存 URL"**：读回落库值即可判。原样存 URL ⇒ 不存在服务端文件写，「图片迁移 = 写文件」假设证否，该字段转而用于 HTML/URL 侧信道或存储型 XSS。
- **单条最小化投递**，跑完清理产物（商品/分类/任务记录），并如实记录残余（接口日志、加密的源站口令字段往往清不掉）。

## 通用坑

- **插件自带 localhost 黑名单**：`[::ffff:127.0.0.1]`、十进制、短写等变体常能绕；但 **SSRF 插件的 Host 由插件固定** ⇒ 只能命中它硬编码的路径，打到内部 vhost 会返 403。**403 ≠ 内部服务不存在**（Host/vhost 不匹配），先用路径与主机名差分判层。
- **内网探测先分三态**：`status:0` = 无监听；`403` = 有服务但 Host/vhost 不匹配；`200` = 命中。任务记录里的内网地址可能是历史残留，实探为准。**再细分**：`Connection reset by peer` 多为**对 TLS 端口说了明文 HTTP** ⇒ 换 `https://` 复打（对明文端口说 TLS 则报 `wrong version number`）；全部路径**连 `favicon.ico` 统一 401** = 最外层认证闸 ⇒ 只值得找**豁免 location**（返异常 404 的那条路由，说明它没挂认证），在闸内枚举路径是白工。
- **出站探测的端口 oracle —— curl 级错误本身就是判据，不必等 200**：`Could not resolve: <host>` = DNS 不通；`Connection refused` = 无监听；`Empty reply from server` = **有非 HTTP 服务在听**（实测 6379 Redis）；`Received HTTP/0.9 when not allowed` = 裸协议/MySQL（实测 3306）；`HTTP 404` = HTTP 服务在（只是路径 404）；`HTTP 403` = 在但 Host/vhost 不匹配。同机实测：`:80`→404、Host 换 `localhost`→403、`:6379`→Empty reply、`:3306`→HTTP/0.9、`:9000`/`:8080`→refused。
- **WAF 403 ≠ 应用层拒绝**：请求体里的 `../` 系列（`../`、`..%2f`、`%2e%2e%2f`、`..;/`、`....//`）被边缘 WAF（宝塔「网站防火墙」页一类）拦死时，**应用层从未被走到** ⇒ 既不能据此结案，也不能当成"应用不允许穿越"的证据；换编码/换字段重试，或明确记为「未测到应用层」。
- **插件参数写面**：`Plugin/paramsUpdate {code, params}` 一类端点常"写生效且持久"，但 `code` 是**存储键而非路径变量**，穿越要靠编码绕过，成本高；安全探针 = 把 `detail` 返回值**原样回写**（无副作用）。
- **插件参数里填「上游域名」= 可控出站 host:port**：配置类端点（`save {api, app_id, app_key}` 一族）把出站目标交到手里，随后 `get_category`/`get_goods_list`/`testConnect`/`detect` 都会真去请求它（实测打我方信标回 `HTTP 204`、未注册域名回 `Could not resolve`）⇒ 可当**内网端口扫描器 + 内部 HTTP 服务分诊**，源 IP = 服务器本机、免边缘 WAF/CDN。测完把参数**原样还原**并用只读端点复核。
- **★ 基址末尾补一个 `?` ⇒ 这个通道立刻从「只能控 host:port」变成「任意路径 + 任意 query」SSRF。** 插件会往 base 后拼固定尾巴（`{api}/shared/authentication/connect`、`{api}/shared/commodity/items` 一族）：不带 `?` 时实际路径 = `<你的路径>/shared/...` ⇒ 满屏 404；**带 `?` 后尾巴落进查询串被目标忽略，命中路径恰是你的路径**（实测 `api="https://<站>/merchantApi/user/userinfo?"` 回该端点真业务响应「请先登录！」）。优于 302 跟随：不依赖跟随、不把 POST 降级成 GET、不经我方作源。⇒ **凡得出「固定子路径打不通」，先回看 base 是否漏了 `?`；漏 `?` 的满屏 404 会被误读成协议硬限。**
- **同一通道的控制面：路径 + query 可控，body 不可控。** body 由插件按自己的字段名拼（`app_id=<你的值>&app_key=..&sign=md5`）；**在 `app_id` 值里塞 `&username=..&password=..` 不会注入新字段**（实测被编码/过滤，端点仍回「用户名或密码不能为空」）⇒ 只吃 POST body 的端点（后台 `auth/login` 一族）经此通道喂不进参数，别再耗轮次。**验证姿势：把带 `&` 的值打到自家收集器，读它记下的原始 body**，不从插件 UI 推断。
- **读回只有「映射字段」通道 —— 按它设计判据。** 插件把上游响应塞进自己的信封再取字段：稳定可读的只有 `msg`（原样透传目标文案）与被映射的 `data` 形状（`testConnect` 只吐 `data.website` 的几项、`get_category` 只吐它认得的分类数组）⇒ **鉴权/存在性判据用 `msg` 差分**；非 JSON 正文只会得到 `HTTP <状态码>` 或「响应解析失败」，**拿不到原文** ⇒ 要读文件/正文另找外带面。
- **探测响应会被插件按 host+path 缓存 ⇒ 端口扫描必须给唯一路径。** 同 host、同 path、不同 port 的多次探测可能命中同一份缓存（实测序列后半段全部回前半段某端口的文案，`msg` 里回显的端口号与请求端口不一致）⇒ 每次探测用唯一路径（`/pp<port>?`），并把 `msg` 里回显的端口/状态与请求值对一遍再落结论；否则把「缓存」记成「服务存在」。
- **Host 决定鉴权闸分支 —— 用文案差分知道自己过了哪道闸，但插件改不了 Host/头。** 同一后台路径：`Host: <站点域>` ⇒「请使用正确的后台路径访问」（路径白名单闸）；`Host: <内网IP / 127.0.0.1>` ⇒「系统未授权或已过期」（token 闸）⇒ **经此通道打 `127.0.0.1` 能越过路径闸、但仍卡 token；且插件不给设头 ⇒ 依赖 `X-Forwarded-Host` 一类头部的绕过在此通道不可达**。免鉴权面通常极窄（实测全站仅 `System/config` + `auth/login`）；`System/config` 常免票回吐运营主体/备案/菜单/插件静态资源 URL，先榨干它。
- **静态资源路由收 base64 文件名 ≠ 任意文件读**：插件把资源名 base64 化（`/plugin/<Code>/static/<b64>`）只说明它做解码；实测喂 `../` 的 base64 与裸 `%2f` 穿越均回 **403**（有校验）⇒ 记一条「已测：有闸」即可，别再往这条线投轮次。
- **缺租户参数会被误读成「401 / 鉴权完好」**：插件读端点无票时若回的是「未找到商家信息」一类**业务错误而不是 401**，说明它要的是**租户 id 参数** ⇒ 补 `merchant_id` / `user_id` / `token` 再测，很可能就是**免票跨租户读取**（实测 `{merchant_id:N}` 免票读出另一租户的内容；带 id 回 200、不带回业务错误）。反过来：**列表端点在每个租户参数值下都回同一批 id = 参数被静默忽略，不是越权成功** —— 越权要靠**跨参数值 diff 返回的 id 集合**来证，集合完全相同即判负。
- **别把「任务记录里能看到凭据」当横向证据**：列表端点常按当前身份隐式过滤（返回的本就是自己那几条），详情端点跨属主回「任务不存在」⇒ 凭据回吐是**自己的**任务记录。横向结论只能靠跨参数值 diff，不能靠字段里出现了凭据就下。
- **主题/样式名面 = LFI 候选**：商户/运营可指定前台主题/样式名时，若前台按名 include，样式名即可穿越读文件。**判据先用不存在的名字**：前台照常渲染 = 名字被白名单校验/忽略；崩/500/空白 = 走了 include 路径 ⇒ 再试穿越。改完立刻还原。
- **别把"内容已到手"当"任务已完成"**：写入原语 ≠ 服务器执行权。拿不到执行权就如实说明，别把导入建品、存储型 XSS 写成 RCE。
- **判死某个协议前先排除应用层 URL 规范化**：`file://`/`dict://`/`gopher://` 打不通且回边缘 WAF 页时，先看应用是否对无 scheme 或陌生 scheme 的输入做了强补（实测 `file://` 被规范成 `https://file/…`）。**边缘 WAF 页 ≠ 应用层拒绝；应用层规范化 = 真判死**，不必再换编码试。
- **假上游用外置配置文件按请求热读**：响应表放 JSON、每次请求重读 —— 迭代时只改配置，不必重启（也就不会去杀监听进程）。
- **数据文件别走「上传即执行」的投递器**：那种远程执行器把上传的 JSON 当脚本跑（一堆 shell 语法错）。让远程脚本自己写配置，或用一个 .py 包装写入。
- **★ 先测「抓取客户端是否跟随 302」—— 这一步能把「路径被规范化/只有固定路径」的 SSRF 重新打开。** 让假上游对抓取阶段的候选路径回 `302 Location: http://<host:port>/REDIR_MARK`（或任意 URL），再看上游日志里是否出现 `/REDIR_MARK` 的请求；出现即跟随 ⇒ **可把服务端出站引到任意 host:port + 任意路径，含 `http://127.0.0.1:<port>/<path>`**，且**源 IP = 服务器本机**（免边缘 WAF、免 CDN、免 Host 黑名单）。302 会把 POST 降级为 GET（只读原语；要写就赌内部服务的 GET-sink）。回显通道 = 任务 `detail` 的 `log`/`error_msg` + 落库产物回读。**口径：URL 路径规范化只证明「直接注入路径不通」，不能写「任意路径 SSRF 判死」——跳转是绕过它的第二条路，必须单独测。**
- **假上游同时是连通性 oracle（两个方向分开判）。** 「我方→目标」超时 ≠「目标→我方」不通：目标往往只封来源 IP 的入站，出站照连我方 ⇒ 用插件自己的 `detect`/抓取动作去探「目标能反连哪些 host:port」，别因为自家入口被封就推翻整个上游方案。端口探不通时先确认监听器真在跑（下一条），再怀疑被墙。
- **长时间监听器必须在脚本内自我 daemon 化**（`fork` + `setsid` + `dup2 /dev/null`）：远程执行器是「上传即执行、会话断连时子进程一并带走」，前台起的监听器随会话消失 —— 表现成「端口不可达」，极易误判为被墙。启动器也只能拉起**已投递到那台机器**的脚本：跨机没上传 ⇒ 起来即死（`alive=False`），先看它自己的日志再改方案。
- **鉴权探针必须显式清空会话 cookie。** 探针助手默认挂载登录态时，会把「带票的 200」读成「免票未授权写入」（实测同一动作：挂 cookie 的会话 200「保存成功」，干净会话 401「请先登录」）⇒ 判未授权前用**新建空会话**复测一次，401 才是免票基线。
- **探插件上传口（`form_fields` 里的 `{"type":"upload","url":"/…/upload/file"}`）前先看出口纪律**：在边缘 WAF（宝塔「网站防火墙」/云 WAF）后面，**一个 `.php` 文件名就足以触发 IP 级封禁** —— 本机经代理打目标仍 200（站活着）而出口机连目标 443/80 全超时 ⇒ 那台出口报废、只能换机（本族实测连烧两台）。顺序：**无害扩展名（`.txt`/`.jpg`/`.mp3`）摸字段名与存在性 → 读类型白名单报错文案（如「文件类型受限，请在后台配置规则！」）→ 最后才谈 `.php` 且用最不值钱的出口**；空传报错（「未获取到上传的文件对象」）用来确认字段名。
- **★ 上传/写路径的安全信道 = `Transfer-Encoding: chunked`**：带 `Content-Length` 的普通 POST 一命中 WAF 就**把整个出口 IP 对整站封禁**（此后连 `GET /` 都返 WAF 页）；同一载荷按 chunked 分片发即**直达应用层、不触发封禁**（实测同一上传口：普通 POST ⇒ 出口报废；chunked ⇒ 拿回应用 JSON，连发 6 发无恙）。⇒ 写路径一律 chunked、每发留间隔；**封禁排查 = 每台跳板机各跑一发无害 `GET /` 对照**（200=干净、WAF 页=该出口报废），别拿还在用的生产链路出口去试险。
- **WAF 拦截页会伪装成 502**：宝塔 WAF 用 `502 Bad Gateway` HTML（随机样式表路径 + 时间戳）拦人 ⇒ 见 502 先跑对照（同出口 `GET /` 也 502 = 出口被封；只该路径 502 而根路径 200 = 真上游问题）。反向也成立：**服务端请求自己 CDN 域名的自环出站**（302 跟随链）可能被 WAF 当自环拦成 502，此时必须用**外部直测 + 直连源站 IP 带 `Host:` 头**才能判「站是活的、只是自环被拦」，不要据此宣布 SSRF 链失效。
