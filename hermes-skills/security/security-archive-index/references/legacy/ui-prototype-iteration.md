# HTML UI Prototype Design & Iteration (for this user)

## When to use
- User asks to design / redesign / "重新设计" a web UI: dashboards, admin consoles, seller/merchant backends, e-commerce platforms
- User wants a "先做个简单的看看" → "出样图对比" → "挨个页面调整" iteration flow
- Deliverable is a clickable HTML prototype, not production code

## This user's design taste (hard-won — do NOT re-litigate the palette)
Rejection history: ① generic SaaS palettes (gold/indigo/teal/black) → "太老套" ② tech/neon (glow, gradients, grid lines, glass) → "AI 味道太重" ③ TikTok style (black sidebar + pink) → "还是不满意". **Approved: Apple HIG style, variant "A2 纯白极简"** (full token set in `references/seller-center-design-iteration.md`).

Approved direction (Apple HIG: 清晰 / 遵从 / 深度):
- Light theme: white/near-white bg, white surfaces. NO gradients, glow, grid lines, glassmorphism
- Sidebar: light gray `#F9F9F9`, gray text `#6E6E73`; active item = subtle dark bg + black bold text, NO left color rail
- Primary buttons: **black** (`#000`, hover `#2E2E30`), capsule `border-radius:999px`; secondary = thin-border outline capsule
- Accent blue `#0071E3` only for links / login slogan emphasis; KPI & balance numbers plain black
- Status badges: Apple system colors as capsule pills on 12% alpha tints — green `#34C759` / blue `#007AFF` / orange `#FF9500` / red `#FF3B30` / gray `#8E8E93`; text uses deep variants for contrast (`#248A3D`, `#0A60C0`, `#B25A00`, `#D70015`)
- Type: system font stack (SF Pro / PingFang), big page titles (26–28px bold), `tabular-nums` for figures, mono for order/ID numbers
- Radii: cards 16px, controls 10px, badges/buttons capsule; hairline borders `rgba(0,0,0,.07–.09)`, near-zero shadow; generous whitespace; table header bg `#FAFAFC`
- Login page: black brand panel + white form panel, white logo block on black, blue accent
- Single accent hue; semantic colors only for status/abnormal states

## Reference-image-driven refinement (user sends a design reference)
- When the user says a direction is drifting ("越来越歪了,等我给你个对比的") and offers a reference, they will paste an image or a text list. **The reference IS the spec** — copy row text verbatim, preserve row order, don't invent or rename rows. Two rejections on the same module = ask for the reference instead of iterating blind.
- If the reference is an **image** and no vision tool is available (`tool_search` finds nothing), OCR it — this works reliably for UI screenshots:
  ```
  pip install rapidocr-onnxruntime onnxruntime
  python -c "from rapidocr_onnxruntime import RapidOCR; ocr=RapidOCR(); res,_=ocr('<img path>'); [print(l[1]) for l in res]"
  ```
  (pytesseract may be pre-installed but needs the tesseract binary, which is usually absent on Windows; rapidocr is self-contained and bundles a Chinese model.)
- Extract the full field list from the OCR text (title/subtitle, inputs, buttons, checkbox copy, helper lines, summary cards) and rebuild the form field-for-field — the user compares against their screenshot, not against your paraphrase.

## Dashboard structure (user-approved, Shopify/TikTok Shop model)
KPI row (4 numbers + trend) → sales trend chart (7/30-day toggle) + todo list (items carry action buttons) → recent orders table. Cut: "常用功能 8 入口" tile grids, side wallet cards, recent products — those belong in their nav pages. Clutter is the #1 complaint; every module must earn its place.

## Prototype architecture: single-file HTML SPA
- One HTML file: all CSS in `<style>`, all JS in `<script>`, zero external deps (user is in China — Google Fonts/CDNs are blocked)
- Views: `<section class="view" id="view-<route>">` inside `<main>`; `show(route)` toggles `.active`; `body.auth-mode` hides `.nav`/`.topbar` for login/register/onboarding screens
- Hash routing: `history.replaceState(null,'','#/'+route)` + `hashchange` listener so refresh keeps the page
- Shared shell: sidebar + topbar; each page has its own `.page-head` (h2 + action buttons)
- Include working interactions: toasts, modals (delete confirm, cashier), countdown, inline stock steppers, batch-action bar, chat session switching, tab panels, step wizards (JS show/hide), SVG chart with range toggle + hover tooltip
- Verify: `browser_navigate file://…` → sweep every route via `browser_console` (`routes.forEach(r=>{try{show(r)}catch(e){…}})`), confirm `js_errors` empty → `open_preview`

## Theme exploration: variant comparison page (user's preferred way to choose)
- User wants FULL-PAGE renders side by side ("四组都出一下样图"), not component cards or hex swatches alone
- Build ONE comparison HTML: N variants each render the SAME complete dashboard template (sidebar + topbar + KPI + chart + todos + orders table)
- Theming: define all colors as CSS vars inline per variant frame — `<div class="frame" style="--brand:#000;--nav-bg:#F9F9F9;…">` with one shared JS template string rendered N times
- Scale down full-size mockups: `.frame{width:1100–1240px;transform:scale(.36–.55);transform-origin:top left;pointer-events:none}` inside an overflow-hidden wrapper
- Each card: name + one-line description + color swatches with hex + click-to-select highlight; user replies a letter, then roll that variant's token set out globally

## Theme roll-out procedure (palette/light↔dark swap)
1. Patch the `:root` token block wholesale (colors, radii, shadow)
2. Sweep hardcoded colors that no longer fit: nav `color:#fff` text, avatar backgrounds, `#FBFCFE` table/chat headers, SVG chart stroke/fill hex + grid + hover-line colors, login brand panel, leftover old-hue hovers (e.g. green hover on buttons)
3. Re-point semantic classes (`.st.green` etc.) to the new tokens — don't let badges keep referencing brand vars after the accent changed
4. Re-verify: route sweep + computed-style spot check (`getComputedStyle` on nav bg and primary button bg) via browser_console

## Product-list table patterns (verified on 商品管理页)
- **Row sorting**: `<th data-sort="price" onclick="sortBy('price',this)">`; rows carry numeric `data-price/data-stock/data-sales` + ISO `data-updated`; `sortBy()` reorders DOM rows, toggles `sort-asc/sort-desc` classes (▲▼ via CSS `::after`). **PITFALL: `parseFloat()` on a date string (`"2026-07-31 09:12"`) silently parses to `2026` (year), so all rows compare equal and sorting appears dead.** Gate on pure-numeric regex: `/^-?\d+(\.\d+)?$/.test(av) && /^-?\d+(\.\d+)?$/.test(bv)` → numeric compare, else `localeCompare` (ISO dates sort correctly as strings).
- **Row ⋯ menu**: `.op-menu > .op-btn("⋯") + .op-drop` absolute dropdown; `toggleMenu(btn,e)` stopPropagation + close others; one document-level click handler closes all. Keep 1-2 primary actions visible as links (下架/编辑), push 预览/复制商品/删除 into the menu.
- **Stock warning synced to stepper**: `.stk-warn` line under `.qty`; 0 → red 数字 + "缺货", <10 → orange 数字 + "仅剩 N 件"; `qty()` rewrites number color AND warn line on every +/- click (set in initial HTML AND in the JS path).
- **Batch bar**: appears on row check — price/stock inputs + black `.b-act` apply buttons, 批量上架/批量下架/批量删除 + 取消; neutral `#FAFAFC` bg, never the accent color.
- **Rejected/已驳回 status**: dedicated filter tab + row-level red reason line under the title ("驳回:标题含违禁词…") — mirrors TikTok Shop/Temu; never hide rejection reasons behind the edit page.
- **Entry-point parity**: page-head buttons = 导出 CSV / 批量上传(Excel)/ 发布新品; 复制商品 lives in the row menu.

## Batch & export module standard (user-mandated, applies to EVERY page)
User rule, hard requirement: all batch operations and export dialogs across every page must follow the 商品管理页 (product-list) pattern. **NEVER stub a modal-grade action with a toast** — user explicitly caught this ("批量发货怎么没有下载模版", "批量导出也没有导出弹窗", "批量取消也没有风险提示", "不要偷懒") and made it an execution rule.
- **Batch upload / batch ship**: 3-step modal — ① 下载模板 (Excel 模板 + 示例数据 buttons) ② 上传文件 (drag-drop `.upload` area, format/size hint) ③ 校验结果 (success/warning/fail pills + line-level error details in red box) → confirm button
- **Batch export**: export-setup modal — 格式 (Excel .xlsx / CSV radio) + 范围 (当前筛选结果 vs 全部, with counts) + 字段勾选卡 (`.fld-grid` of checkbox chips, 7–8 fields) → 导出 (async-task toast: "任务已提交,完成后可在消息中心下载")
- **Destructive batch ops** (批量取消/批量删除/升级仲裁/批量退款): risk-confirmation modal with `.risk-box` (red-tinted panel listing consequences: auto-refund, cancellation-rate impact, lock-during-arbitration, audit log) + required reason dropdown where relevant + danger confirm button
- Reuse one `batchbar` component + one export-modal shape everywhere; only field lists differ per domain
- Every page's batch/export live under the same markup: `batchbar` (已选 N 项 + sep + actions + 取消), `modal-export-*`, `fld-grid` fields

## Order-list & order-detail patterns (verified on 订单 pages)
- **Countdown timer**: pending-ship rows carry `<span class="odl" data-sec="…">`; one global `setInterval(tickOrders,1000)` decrements and reformats HH:MM:SS; <1h turns red, 0 → "已超时,请尽快发货". Use a GLOBAL selector `document.querySelectorAll('.odl')` so list AND detail pages tick in sync (detail page embeds the same order's timer)
- **Data-loop design**: the 发货时限 (ship-by limit) set in the product publish form (step 4) is the SOURCE of the order countdown — keep demo data self-consistent across pages
- **Order detail timeline**: 5-node status timeline (下单→支付→待发货→发货→签收) with `.tl-item.done` (filled dot) / `.cur` (ring dot) / pending; separate logistics-trace timeline (揽收→干线→清关→派送→签收) lives INSIDE the 物流信息 card, collapsed while unshipped with a 查看物流轨迹 toggle

Switching carrier updates the input `placeholder` only. **User rule: NO inline error-text line under the field** ("不用在方框后面提示") — invalid input gets the red `.inp.err` border and the submit is hard-blocked with a toast naming the carrier rule.
- **Ship-by deadline alert**: orange-bordered box (`.ship-alert`, `border:1px solid rgba(255,149,0,.4)` + 12% orange tint, 12px radius) with three-part layout: clock SVG + "发货时限" label + countdown `<b class="odl">` 16px bold red (ticks via the global `.odl` interval) + right-aligned muted tip. User asked to re-layout it as a bordered, structured bar — not a flat text line.
- **收件人核对 card** (recipient verify) on the right rail: 收货人/电话/地址 + "发货前请核对" hint — mainstream shipping pages always show it to prevent wrong-ship.

## Shipping-fee template module (3-place closed loop, verified)
Mainstream parity pattern (Shopify template reuse / TikTok Shop product-bound templates / 淘宝 首件+续件+满额包邮):
1. **Sidebar menu** (商品订单 group, box icon) → dedicated management page: template table (名称/计价规则/满额包邮/状态(默认|启用)/使用商品数/操作 编辑·复制·删除), 新建模板 modal (名称 + 计价方式 radio 包邮|按件计费 → 首件/续件/满额 inputs + 设为默认 checkbox), delete risk modal (关联商品自动改用默认模板 warning).
2. **Product publish step 4 运费设置**: three mutually-exclusive radios — 包邮 / 运费模板 (dropdown of store templates) / 自定义运费 (首件+续件+满额) — each reveals its own conditionally-shown block (`tplSelBox` / `feeBox`); hint text switches per mode.
3. **Ship page**: read-only line "运费模板: 包邮模板(订单商品采用包邮,买家免运费)".
4. Cross-links: publish page hint points to the template page ("修改模板后全店生效"); demo data stays consistent across all three places.
5. **New-template modal (upgrade, user: "太简陋了")** must be a full form, not 3 inputs: 模板名称 + **适用地区 chips** (9 region pills 全球/北美/欧洲/东南亚/中东/大洋洲/日韩/南美/非洲, checkbox inside pill, `.chip:has(input:checked)` = black border + tint — no-JS selection styling) + **计价方式 3-way radio** 包邮 / 按件计费 (首件+续件+满额) / **按重量计费** (首重 ≤1kg + 续重每 500g + 满额) + 设为默认 checkbox.
6. **运费试算器 (fee calculator)** inside the new-template modal — mainstream TikTok/Temu touch: two inputs (数量 + 订单金额) → live `<b id="calcResult">` fee; qty mode `first + more×(q-1)`, weight mode treats qty as kg → `first + more×ceil((q-1)×2)` (500g steps), `cap>0 && amt>=cap → 0`. Recalculate on radio switch AND on every input (`oninput`).
7. Region/pricing/fee-calculator names must not collide across the two template modals (publish-page selector uses `tplSelBox`; creation modal uses `tplFeeBox2`/`tplQtyBox`/`tplWtBox` + `tpltype2` names) — or radio groups and boxes will cross-wire.

## Funds center (资金中心) patterns (verified on 资金中心页)
- **Business-data consistency is USER-AUDITED — treat it as a hard requirement**: this platform has NO sales commission. Order proceeds = 商品金额+买家运费 in FULL (预计收入); the only fee is 1.5% withdrawal fee (min 50 USDT), charged at withdraw time, never on the order. User caught leftover "实收 +84.05" (5% commission deducted) figures in the funds ledger AFTER order-detail was fixed to 89.90 — a classic cross-page stale-number bug. Rule: order-detail 预计收入 == funds-ledger 订单入账 == order-list amount, and the balance column must be re-arithmetic'd top-down when any figure changes. After fixing one page's money model, `grep -nF` the OLD numbers across the whole file to sweep stale derived amounts (mind: regex `.` in grep patterns matches anything — use `grep -F` for literal).

## Pitfalls
- Do NOT set `max-width` on `.content` — user complained "只占了一半多一点"; fill the canvas
- When patching a generic class, keep the generic selector: replacing `.thumb{…}` with `.prod .thumb{…}` silently broke every other `.thumb` (had to re-add the generic rule)
- Emoji placeholders (🖼🎥) read as slop; use neutral geometric placeholders
- AI-slop tells this user hates: glow/neon, gradients, grid lines, glassmorphism, oversized rounded rectangles, icon-topper cards, rainbow accents, feature-tile grids
- **Feature-bragging copy is banned** — "自动翻译 7 语 / 一键铺全球" style marketing text never goes into page copy (user: "后面的设计里面也不要带这种话"). Write only functional facts ("≤60 字", "多语言商品页即时生成" is the max allowed). Sweep whole file for the banned phrasing when fixing.
- After color approval, user iterates page-by-page: present a numbered page list with predicted per-page detail issues and let them pick the start
- Before asking "which direction", always offer visual variants — this user rejects on sight, so cheap iteration beats one big guess
- **SVG charts must re-render on window resize**: a fixed `viewBox` only scales proportionally — coordinates/labels don't reflow and hover math breaks ("缩放屏幕时趋势图不跟着动" was a user-reported bug). Keep `let curW` (init to viewBox width) + `window.addEventListener('resize', …)` that reads the container `clientWidth`, updates `viewBox`, and calls `drawChart(curN)` (remember current range in a global). Use `curW` everywhere inside the draw + hover handlers, not the old constant.
- **When the user says a direction is drifting ("越来越歪了") and offers to send a reference, STOP and wait — do not ship another variant.** The funds/payment-channel design was rejected 3× (RMB/alipay → USD-only wire → multi-currency bank accounts) before the user supplied the Stripe-style payment list; the reference text IS the spec (copy verbatim, preserve row order). Two rejections on the same module = ask for the reference instead of iterating blind. Also: in a cross-border-mall context, "支付通道/充值渠道" defaults to a payment-method selector (USDT/PayPal/Wise/cards/wallets), NOT bank-account management (Payoneer 收款账户/电汇) — do not design the latter unless the user explicitly asks for it.
- **Every new view must be registered in the `ROUTES` object**: `show(route)` silently falls back to `dashboard` for unregistered routes. The batch-ship page was added without a ROUTES entry and initially "worked" only because the DOM existed — it actually never displayed.
- **Verify view visibility with `classList.contains('active')`, NOT `style.display`**: `.view` visibility is driven by the CSS `.active` class (`display:none` default), so `style.display` reads `'none'` even for a visible page — a false-pass test. Same trap applies to checking modals (`.modal-mask.show`).
- **Hidden tabs measure 0×0**: `getBoundingClientRect()` returns all zeros for any element inside a `display:none` parent — you must ACTIVATE the tab (`setFundTab('recharge')`) before measuring widths/layout, or every number reads 0 (looks like broken layout when it's actually a hidden tab). Also remember the ledger strip is `view.children[0].children[2]` (a grid child), not `view.children[1]` — index against the grid container.
- **Stale browser DOM after patch**: after `patch`/`sed` edits, `browser_navigate` can serve a cached page; if a verified change (e.g. `grid-column:1/-1` in the file) is absent from the DOM, run `location.reload()` in browser_console and re-check before debugging the HTML.
- **patch() old_string must not be a shared base class**: replacing `.hint{…}` while intending to ADD `.title-tip{…}` silently deleted the `.hint` rule used by every other page — re-add the generic rule in the same patch
- **When replacing a JS function with patch, re-check neighbors**: one patch swapped `fakeShip` for the new `toggleTrace` (both one-liners near each other) and silently killed the batch-ship demo — grep the function name after editing
- **sed bulk-replace safety**: before `sed -i` on glyphs/short strings across a big HTML file, `grep -c` the target first to confirm it doesn't appear inside JS strings; after the run, grep again to confirm 0 leftovers. Verify rendered DOM via browser_console after any sed pass (a stale browser cache can show old content — `location.reload()` if snapshot looks stale)
