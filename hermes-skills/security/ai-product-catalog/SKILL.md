# AI 产品图册生成(批量场景图 + HTML 画册)

用户要"厂家报价图 / 产品图册 / 左边产品图右边价格"时的完整工作流。核心:
**拿真实产品素材图 → gpt-image-2 图生图换科技感场景 → 数据填充 A4 画册 HTML → 逐页验证 → 交付**。

## 触发场景
- "把商品做成厂家报价图/产品图册,左边产品图右边规格+价格"
- 大量商品(几十个)批量生成统一风格报价卡
- 用户提到"AI 生图"做产品展示图

## 用户偏好(踩过坑,直接照做)
- 用户明确要求用 **gpt-image-2**("用 image2.0 生成"),不要擅自换 1.5 或其他模型
- 版式:**左边 AI 场景图 + 右边信息**(SKU/拿货价/运费/总价),不做扁平卡片模板(第一版纯 HTML 卡片被否)
- 价格条**只保留批发价大字**,右下角"厂家拿货价/运费"小块会被要求删掉
- 产品页底部(2026-08-15 终版):**价格条已全部删除**——用户先后要求删"厂家拿货价"条、再删"邮费"条("把邮费也删了吧"),详情页底部只剩**居中页码行**(10.5px 灰字,`01 / 47`);所有价格信息集中在末尾价目总表。历史样式(勿再默认启用,除非用户点名要):邮费+拿货价同款窄条(浅灰圆角 14px、蓝点+标签在左、USDT+数字在右、padding 3.2mm 5.5mm、拿货价 26px/邮费 19px 统一后 19px;邮费从 `moq` 字段正则 `/运费\s*([\d.]+)\s*USDT/` 提取)
- SKU 明细**永远单列**宽松排版,一行一个;宁可多拆几页,不双列/三列(用户原话:"只留一列,可以多占几页,别挤,我们不缺物料钱")
- **单 SKU 产品也要显示明细卡**:只有一行自己的 SKU(label|码|拿货价),分块条件用 `skus.length > 0` 而非 `> 1`(用户纠正:"单sku只放一行自己的就行")
- **SKU 排序规则**:块内按价格**低→高**(最上面最低、最下面最贵;用户先要"高到低"后纠正反了),价格相同则 **label 字符串短的在前**;排序用原始售价(精确),展示用拿货价(÷2 取整)
- 先出 1 张样板给用户确认,再批量(避免 47 张全错)
- 大下载/长任务要进度可见(日志文件 + 阶段性汇报)

## 步骤

### 1. 准备数据
- 商品清单 xlsx:标题/分类/价格/SKU明细(格式 `规格|SKU码|价|库存;...`)
- 素材图:每品主图路径(本地)
- 采集原链接:素材目录 `商品信息.txt` 里有 `商品链接:` 字段;SKU 码 = 素材目录名 + `-01` 后缀(整机套装是 ASIN 无后缀)

### 2. 批量生成 AI 场景图(apimart 中转)
端点与坑详见 `references/apimart-api.md`。核心:
- 提交 → 拿 task_id → 轮询 `/v1/tasks/{id}` → 下载图片
- **必须带浏览器 UA 头**(否则 403 Cloudflare 1010)
- **字段是 `image_urls`**(data:image base64 前缀),不是 image
- **素材图先压缩**(>500KB 就 PIL thumbnail 1024 + JPEG q82;实测 800KB-1.4MB 直接提交会 413)
- **3 并发**(ThreadPoolExecutor max_workers=3),同 key 并行不排队,47 张约 15-20 分钟
- 断点续跑:已存在 >50KB 的文件跳过;进度写日志;单张失败重试 3 次
- prompt:整机=科技感办公桌;耗材=打印机旁工位,均"keep the product design exactly the same"

### 3. 填充 HTML 画册模板
- 用户提供的 A4 画册模板结构:封面 + 一页一品 + 价目总表(PRODUCTS 数组驱动)
- 用脚本替换 `const PRODUCTS = [...]` 段,生成 47 项
- SKU 明细解析:`"规格|码|价|库存"` 分号分隔 → `[{label,sku,price}]`;label 只取颜色名(`Blue (10601) / Refill / 1 kg` → `Blue (10601)`),否则换行撑爆行高
- **SKU 明细行的价格必须换算成拿货价**:注入的 `skus[].price` 是店铺售价,用户会核对("你是不是没重新计算,直接按店铺上品价格注入了")——显示 `Math.floor(parseFloat(s.price)/2) USDT`,与主价格条/价目表同口径;排序用原始价
- 币种:模板 ¥ 改成 USDT(拿货价=售价/2 取整,运费按品类 60/8——具体口径先问用户)

### 4. SKU 明细排版与防溢出(多 SKU 必踩;2026-08-15 用户两次迭代后最终拍板)
- **SKU 明细永远单列**,一行一个宽松排;双列/三列都被用户否决("别挤到一起去" → "只留一列,可以多占几页,别挤,我们不缺物料钱")
- 拆页规则(**2026-08-15 终版**):SKU 按 `PER_PAGE = 9` 行/页切块,**每页都是完整版式**——产品图/型号/标题/slogan/规格表全部重复,只是 SKU 明细换成下一段(用户原话:"新页保持上面图片那些不变,只是sku变动";先做过"无图续页"版被否,后做过"每页 12/20 行+底部价格条"也被否)。单 SKU(`length>0`)也显示 1 行明细卡
- 页眉/页码:首页页眉 `01 / 47`(块内序号);续页页眉 `SKU 明细 · K / N`;底部页码首页 `01 / 47`、续页 `01 / 47 · K / N`
- 底部**无价格条**(拿货价/邮费条均已删,只剩居中页码);价格集中在末尾价目总表
- 总页数自检:1 封面 + 2 章节页 + Σ产品页(含拆页)+ 价目表页数;47 品实配 70 页(PLA Basic 43 色→5 页、PLA Matte 31→4 页,整机 12 款 1 页/块)
- 零溢出参数(Apple 风版):主图 58mm、specs padding 2.1mm、sku-row padding 1.35mm;9 行已是实测上限(固定部分 175.7mm + 9 行 ≈ 临界,10 行溢出)
- **逐页验证(无需 puppeteer/browser-use)**:`scripts/verify_catalog.py`(注入检测脚本 → chrome --headless --dump-dom → 解析 title JSON;含溢出/坏图/**价格条与 SKU 重合**检查);SKU 排序规则(价格低→高 + 同价 label 短→长)也可程序化逐对校验(`badPairs:0`);**每次布局改动(加行/改 padding/拆页参数/排序)必须重跑**——43 色页是压力上限,改完先验证再交付
- **价目总表必须自动分页**:47+ 行远超一页 A4,而 `.page{overflow:hidden}` 会把溢出部分直接裁掉(PDF 里无声丢数据)。每页行数按实测调(11.5px 字体 + td padding 2.4mm ≈ 24 行/页稳;34 行会溢出 ~70mm)
- ⚠️ **分页 JS 陷阱**:先 `join("")` 成 HTML 字符串再 `.slice(0,N)` 是按**字符**切,会产生几百个残页(实测 47 行切成 230 页)。必须 `PRODUCTS.slice(i, i+N)` 按**数组元素**切,再在每页内 `map` 拼行
- 打印加 `@page{size:A4;margin:0}`,Ctrl+P 边距"无"即无缩放对齐;预览图:`chrome --headless=new --no-pdf-header-footer --print-to-pdf` + PyMuPDF 渲染 PNG(dpi 95 ≈ 786×1111)

### 4b. Apple 设计风格版式(2026-08 用户定稿;旧红色 #c0392b / 深蓝表头版被否)
- 封面:深空黑渐变 `#1D1D1F→#000`,顶部品牌眉标 + **居中** 56px 大标题(700 / `letter-spacing:-.02em`)+ 46×4px 圆角蓝色短线 + 英文副标题(字距 6-7px)+ 底部 2×2 联系信息网格
- 产品页:白底、细分隔线 `rgba(0,0,0,.08)`、图卡浅灰渐变 `#FBFBFD→#F5F5F7` 圆角 18px、SKU 卡 16px 圆角白卡、型号小字灰 `#86868B`、**底部只剩居中页码**(tabular-nums 10.5px;邮费条/拿货价条 2026-08-15 已全部删除)
- 价目表:表头浅灰 `#F5F5F7`(首尾圆角 10px)、斑马纹 `#FAFAFC`、价格列黑色右对齐
- 字体栈 `-apple-system,BlinkMacSystemFont,"SF Pro Display","SF Pro Text","PingFang SC",sans-serif`;唯一强调色 `#0071E3`;禁发光/渐变网格/AI 味
- 数据驱动不变:PRODUCTS 数组原样注入,只改 `<style>` 与渲染函数;改版前先 `cp catalog.html catalog-v1-original.html` 留旧版备份

### 4c. 分块章节页 + 块内排序(2026-08-15 用户要求"整机一块、耗材一块,按价格重新排序")
- 渲染前把 PRODUCTS 分两块:`SECTIONS = [{cn:"整机",...},{cn:"耗材",...}]`,按 `cat` 字段归类,块内 `sort((a,b)=>a.price-b.price)` 价格**低→高**
- 每个块前渲染**章节页**(Apple 风浅色大留白):`PART 01` 眉标 + 52px 标题 + 蓝色短线 + 英文副题 + 描述 + "共 N 款"(用户删掉了"价格由低到高"字样,保留"共 N 款";款数文案有反复,默认只留数量)
- 页码改为**块内编号**:整机页 `01 / 12`、耗材页 `01 / 35`;多 SKU 续页 `01 / 12 · 2 / 5`
- 价目总表也**分块**:`Price List · 整机` / `· 耗材` 各自独立分页(24 行/页),注脚只在最后一块最后一页
- 分区判断用 `cat === "整机块名"`(数据 cat 值被替换为英文时判断串要同步改)
- 布局顺序:封面 → PART 01 章节页 → 整机产品 → PART 02 章节页 → 耗材产品 → 价目总表·整机 → 价目总表·耗材

### 5. 交付
- 本地 HTTP 服务(如 `python -m http.server 8766`)打开 HTML 预览(file:// 中文路径可能打不开/图加载失败,优先 http)
- Chrome 打开给用户看;Ctrl+P → 另存 PDF(边距"无"、背景图形"开")
- 单张替换:文件名不变覆盖 images/ 下同名文件,HTML 无需改

### 5b. 分享给客户(2026-08-15)
- **单文件版(推荐微信/邮件直发)**:图片路径在**数据字段** `img:"images/xxx"`(不是渲染后的 src 字面量,正则要匹配数据),脚本替换为 `data:image/jpeg;base64,...`(PIL 最长边 1000px q82 → 47 张约 4.7MB/文件;58mm 图区 ≈ 440dpi 印刷够);产物 `catalog-单文件.html`,对方双击即开,验证 brokenImgs=0
- **zip 包(原图无损)**:完整文件夹(HTML + images),对方解压后打开;适合印刷/出片
- **英文版**:复制后脚本替换(翻译映射表:BRAND/SECTIONS/cat/slogan/specs 键值/页眉页脚/价目表/注脚;SKU 颜色名本身是英文不用动);命名 `catalog-en.html`
- ⚠️ 英文版生成坑:①提取 JS 用 `lastIndexOf('<script>')`——文件头部注释里有 `<script>` 字样,`match` 会取到注释导致误报语法错误 ②字符串替换(如"第 X 页")容易丢闭合引号 → 生成后必须 `node vm.Script` 或 `node --check` 语法验证 ③残留中文检测只查渲染文本(`document.body.textContent`),代码注释里的中文不算

## Pitfalls
- **不要用扩散 AI 生成文字/数字**:报价单数字必须准,用程序排版(HTML→截图)拼价格,AI 只做背景图
- apimart 是异步任务模式,不是同步返回;没有 task_id 的响应 = 参数错误
- 素材图大的商品(Amazon 原图 1-3MB)必须压缩;压缩阈值宁低勿高(500KB 稳)
- 图册模板规格字段是描述文本时,用品牌/材料/SKU/发货等实用字段,别硬解析描述
