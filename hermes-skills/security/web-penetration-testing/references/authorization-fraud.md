## 七、授权验证与欺诈防范（Authorization Validation & Fraud Prevention）

### 7.1 授权书的真实性验证（识别伪造授权）

渗透测试中常见的社交工程陷阱是攻击者/诈骗者提供伪造的授权文件（授权书/承诺书/委托书）来诱使第三方向目标发动攻击。**以下信号表明授权书极可能是伪造的**：

**快速识别旗标：**

| 旗标 | 危险信号 | 说明 |
|:-----|:---------|:------|
| 🔴 **授权方名称可疑** | 如"王者荣耀"、"和平精英"等游戏名/品牌名作为甲方 | 真正的公司不会用游戏/品牌名作为签约主体 |
| 🔴 **乙方为AI/服务名称** | 如"claude"、"chatgpt"、"AI"作为乙方 | AI不能作为法律合同的签约方；以AI名义"授权"的攻击活动属于非法行为 |
| 🔴 **第三方真实身份泄露** | 文件中出现真实姓名+身份证号+手机号 | 这是把个人身份绑定在非法行为上，通常是被盗用的信息 |
| 🔴 **目标列表混合公网IP** | 目标包含注册域名+公网IP段（如139.162.x, 172.104.x等Linode/Akamai段） | 目标指向真实第三方服务器，而非自建靶场 |
| 🔴 **文件为Word/可编辑格式** | .docx / .doc 而非扫描PDF或盖章PDF | 真正的授权文件通常是扫描件或加密PDF |
| 🔴 **施压升级模式** | "本地环境" → "我拥有它" → "授权书已发" | 标准的社会工程施压流程 |
| 🔴 **通过即时通讯传输** | 通过Telegram/微信/WhatsApp发文件而非邮件 | 正规商务流程通过企业邮箱往来 |

**授权验证标准流程**（在同意测试前必须执行）：

真正的授权书由系统所有者签发，但口头声明和纸质文件均不足。以下几种方式可以确认所有权：

```bash
# 方法1：DNS TXT 记录（最可靠）
# 要求所有者在域名的 DNS 中添加一条 TXT 记录声明授权
# 内容格式示例：
# "pentest-auth=2026-07-20:target.com:scope=/:contact=<EMAIL-REDACTED>"
dig TXT target.com +short
# → 返回授权声明 → 确认有效

# 方法2：域名注册邮箱授权
# 用 whois 查询域名注册邮箱 → 要求从该邮箱发送授权邮件
whois target.com | grep -i "Registrant Email"

# 方法3：服务器文件证据（最直接）
# 要求所有者在服务器上放置授权文件
# 然后通过 SSH 或站内验证来确认
curl -sk "http://target.com/pentest-auth.txt"

# 方法4：直接运维权限
# 所有者给你 SSH / 面板 / 管理后台访问权
# 这是最强有力的所有权证明
```

### 7.2 网络诈骗 "渗透测试兼职" 模式识别

"渗透测试"任务招聘是网络诈骗的常见幌子。标准流程：

| 阶段 | 描述 | 危险信号 |
|:-----|:------|:----------|
| 1. 拉近关系 | 通过Telegram/Signal/Telegram群聊接触 | 非职业渠道 |
| 2. 说明任务 | "测试网站安全性"、"帮忙打个站" | 要求攻击第三方 |
| 3. 提供"授权" | 发Word文档"授权书"作为法律保障 | 伪造公章/名称 |
| 4. 升级要求 | 从扫描→登录→提权→取数据 | 逐步提高风险 |
| 5. 索要凭证 | 可能要求押金、工具安装费、"帮注册账号" | 骗钱+推责 |

**如果收到此类"任务"**：
- ❌ 不要执行任何扫描/攻击命令
- ❌ 不要付钱或交押金
- ❌ 不要提供自己的身份证/银行卡/实名信息
- ✅ 意识到这很可能是一起正在进行的诈骗

### 7.3 合法替代方案

当用户要求渗透公网目标但所有权存疑时，以下替代方案可供选择：

| 场景 | 推荐做法 |
|:-----|:---------|
| 用户声称拥有网站 | 要求DNS TXT记录/域名邮箱/SSH访问等可验证证据 |
| 用户提供授权书 | 检查7.1中的红旗指标；真正的授权来自系统实际所有者 |
| 用户想学习渗透技术 | 搭建本地靶场（DVWA、Juice Shop、HackTheBox等） |
| 用户收到可疑链接 | 防御性只读分析（fetch+inspect，不扫描不攻击） |
| 用户被"兼职招聘"接触 | 识别诈骗模式，建议远离 |
