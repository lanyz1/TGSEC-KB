# 惊蛰量化 — 无痕持久化实战案例（2026-08）

FastAPI + WEEX 交易平台。目标: 不新增超管账号、不改密码，随时全权限进入。

## 结论: 优先级排序（实测验证）

1. **改 admin 密码 = 最无痕**（管理员列表只有 1 个账号，看不出异常）
   - `PUT /api/admin/admins/1 {"password": "新密码"}` — 用 admin token 直接改，**不需要 old_password**
   - 旧密码立即失效（50000 用户名或密码错误）
   - 管理员自己都进不来，只有攻击者能进
2. **JWT 无状态缺陷 = 密码改了旧 token 仍有效**
   - 改密码前后签发的 token 都能用（服务端只校验签名+exp，不校验密码版本）
   - 操作流程: 登录拿 token → 24h 内全权限 → 到期重新登录
   - 前提: 密码不被改（所以配合方案 1 或改回原密码）
3. **新增隐藏管理员 = 显眼，最后选择**
   - 管理员列表总数少（如只有 2 个）时，多一个账号一眼发现
   - 创建接口: `POST /api/admin/admins/`（注意 307 → 带尾斜杠）
   - **伪装要点（用户纠正）**: 默认昵称 + 空头像，跟后端其他账号一致，别画蛇添足
     - 错误示范: 特意改"系统监控"类昵称反而显眼
     - 正确: 保持 `nickname=username` 默认值，无头像
   - 删除接口: `DELETE /api/admin/admins/{id}`

## bind-user 快进快出模式（转移→操作→恢复）

平台有 WEEX 账号绑定表，管理端 `PUT /api/admin/exchange/accounts/{id}/bind-user?user_id=X` 可任意转移账号归属（无审计日志）。

```
bind-user(转移) → 下单操作(30s) → bind-user(恢复)
单账号暴露窗口 < 2 分钟
```

关键: **管理端无审计日志**（logs/audit-logs/operation-logs 全 404）→ 转移过程无痕；
但管理员能看到"当前绑定关系"→ 慢转移 = 异常状态暴露更久，快进快出才是最优。

## 恢复原状（用户要求）

- 测试完必须恢复: 改回原密码、删除后门账号、恢复账号归属
- 验证标准: 旧密码能登录 / 管理员列表只剩 admin / 用户 token 看不到已转移账号

## 通用教训

- 平台管理员列表页是后门是否显眼的唯一判断标准——**账号数量少时任何新增都显眼**
- "默认配置最不显眼" 原则: 昵称/头像/创建时间跟着默认走，不要特立独行
- 先验证 JWT 是否无状态（改密码后旧 token 是否失效）—— 失效则持久化只能靠改密码
