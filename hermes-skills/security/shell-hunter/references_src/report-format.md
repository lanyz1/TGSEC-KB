# 漏洞报告规范（8 块结构 + 定级标准 + 认钥闸）

> 中危/高危/严重确认后**立刻落盘**到 `报告/`，禁止攒到最后。每条报告必须可复核：复现步骤可整包重放。

## 一、报告 8 块结构（缺一不可）

1. **标题**：`<模块> <漏洞类型>（<影响程度>）` — 如「订单详情越权读取他人收货地址（高危）」；不含 URL，方便平台检索
2. **目标 URL**：精确到接口路径 + 方法 + 关键参数；多接口按触发顺序列
3. **等级**：严重 / 高危 / 中危 / 低危（按定级标准，见下）
4. **描述**：该漏洞是什么、攻击者能做什么（两句话交代清楚，别啰嗦）
5. **危害**：攻击者利用后能造成什么后果（数据泄露范围、影响用户量、资损可能性）
6. **涉及接口**：请求方法 + 路径 + 请求头（Cookie 打码）+ 请求体（敏感值打码）
7. **复现步骤**：Step by step，每步附请求包/截图证明；可复核=别人照着做能复现
8. **修复建议**：具体到改什么（鉴权加在哪层、参数如何校验、字段如何过滤）

## 二、定级标准

### 严重（Critical）
- 命令执行 / RCE（WebShell、反序列化、模板注入）
- 进他人账号（任意账号接管、改他人密码/改绑手机）
- 真实资损路径（转账、支付、清库存、批量扣费）
- 管理员权限直达（未授权拿 admin、越过所有鉴权层）

### 高危（High）
- 未授权访问他人**高敏数据**：手机号/身份证/证件照/银行卡（对得上人）
- 云密钥/token/连接串泄露，且**过了认钥闸**（见下）
- 注入出他人主体数据（SQL 注入直接拖他人库表/他人订单正文）
- 读取他人**未公开**正文/隐私内容（私信、草稿、病历）
- 任意文件读取（含配置、源码）

### 中危（Medium）
- 存储型 XSS（尤其打入管理后台）
- 逻辑漏洞导致的非资损危害（越权改他人非敏感资料、评论等）
- 低敏信息越权读取（他人公开昵称、头像、非隐私业务数据）
- SSRF 打到内网但未能证明实质危害
- 弱口令（且能登录进有数据的面）

### 低危（Low）
- 反射型 XSS（仅自弹）
- 信息泄露（无敏感数据、纯技术细节）
- CORS/CSRF 修复不当等配置类
- 点击劫持等利用条件苛刻的

## 三、认钥闸（抄到钥不算洞，生产认了才写）

抄到 API 密钥/云 token/数据库连接串后**必须过闸**：

1. **假值对照**：先用明显假值（`sk-<REDACTED>`）调目标接口，确认服务端会区分真假
2. **认钥带出身份或列表**：用真实钥调用一次**只读**接口，带出账号身份（如 `GetCallerIdentity` 返回主账号 ID）或资源列表（对象列表/实例列表）
3. 两条都过 → 写高危/严重；任一条不过 → 只写「配置不当（疑似泄露）」，降为中危或低危

**禁止**：直接用密钥做破坏性操作（删除资源、修改配置、扣费）来验证。

## 四、报告纪律

- **即时落盘**：中危起确认即写 `报告/xxx.md`，不攒
- **差分证据**：注入/越权类报告附基线 vs payload 后的差分（total/条数/字段变化）
- **敏感打码**：Cookie/Token/手机号中间四位打码，密钥部分截断
- **不写猜测**：没验证不写「可能」「疑似」当结论；验证了写证据链
- **修复建议落点**：告诉开发者改哪一层、怎么改，不写「加强安全意识」这种空话
