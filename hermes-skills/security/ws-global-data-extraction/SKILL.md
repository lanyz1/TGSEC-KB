# WS 协议全局数据接口批量提取 Skill

针对**WS 二进制协议平台存在"全局数据接口"**(任意登录账号可查全局库,如 GetMobiles 返回全平台手机号)的目标,通过**批量注册 + 并发提取**大规模拉取用户数据。适用于 HXWS/白标博彩/棋牌类平台(注册验证码可绕过时威力最大)。

## When to Use

- 已逆向 WS 协议(参考 wasm-ws-protocol-crack),发现某查询接口返回的数据**与调用账号无关**(全局库特征)
- 注册接口验证码可绕过(如 checkCode="123456" 被接受)或注册无限制
- 目标有敏感全局数据(手机号/邮箱/支付记录)
- 需要大规模提取但单次接口只返回少量数据

## 核心原理

```
全局库接口特征: 任意账号调用返回相同结构的随机/全局数据
+ 注册无限制 = 用 N 个新账号调用 N 次 = 累积 N 份数据
+ 并发 = 速度 × 并发数
```

**验证全局库**(关键判断):
1. 用已攻破的老账号调用 → 记录返回数据(如 45 个手机号)
2. 注册全新账号调用 → 若也返回同样数量的数据(如也是 45 个) = **全局库!**
3. 若新账号返回空/少 = 个人数据(需业务活动才有),此方法无效

## Procedure

### 第 1 步: 确认全局接口 + 注册模板

- 从 main.js 提取注册模板(`SUB_MB_REGISTER_ACCOUNTS` 等)和全局接口模板
- 注册模板要点: logonPass 通常是 **MD5**(char16),checkCode 是 char16
- 验证注册: 单账号注册成功 + 登录 + 调用全局接口,确认返回数据

### 第 2 步: 批量注册 + 提取脚本(串行验证)

```javascript
// 核心流程: 连接 → REGISTER → (自动登录) → RELOGON → 全局接口 → 下一账号
// 每账号约 1.8 秒 (注册+登录+RELOGON+提取)
```

- 账号生成避免重复: 时间戳后4位 + 序号
- 保存每账号的提取结果到 JSON

### 第 3 步: 并发加速(关键)

```
Python 包装器: subprocess.Popen 拉起 N 个 node 实例
每实例: node script.js <count> <start> <outPrefix>
⚠️ 每实例必须写独立输出文件(m9600_mobiles_<prefix>_<start>.json)
   ← 所有实例写同一文件 = 后完成覆盖先完成 = 数据丢失!
```

- background 模式 node 直接启动必挂("stdin is not a tty")→ 必须 Python 包装器
- 5-6 并发 = 20 分钟 8000+ 条(单线程 3 倍时间)

### 第 4 步: 池子大小估算(去重率法)

```
采样 N 次(每次 K 条), 唯一数 U:
池子大小 ≈ 解方程: U = N_total(1 - e^(-采样数/N_total))
实战: 6750 采样 → 3539 唯一 → 池子约 4500-5000
     14000 采样 → 8133 唯一 → 池子约 1 万
```

**池子小(~1万)= 很快拿全;池子大(百万)= 此方法只拿部分,需找分页/其他口**

### 第 5 步: 数据分层(客户价值)

- 全局接口数据(手机号)= 支付/绑定用户
- 排行榜/榜单数据 = 投注/高净值用户
- **两个群体通常不重叠**(独立用户分层!)
- 合并输出: 高净值(账号+投注额+档位) vs 普通(手机号+城市)

## Pitfalls (血泪教训)

1. **并发实例必须独立输出文件**(最大坑!): 所有实例写同一文件 → 后完成的覆盖先完成的 → 200 账号数据丢失。输出文件名必须含 start 偏移。
2. **background node 必挂**: "stdin is not a tty" → 用 Python `subprocess.Popen` 包装。
3. **全局接口忽略参数**: 测过 count/offset/index 全部无效(每次固定 K 条随机抽样),只能靠反复调用累积,无法分页一次拉全。
4. **注册模板易错**: REGISTER 与 LOGON 结构几乎相同但多了 checkCode/nickName/faceID/adID;logonPass 是 MD5 不是明文;字段顺序错 → 注册失败(scmd=101)或解析偏移错。
5. **池子估算防误判**: 别把"已拿数量"当全量。用去重率算池子大小,判断是否值得继续提取(收益递减)。
6. **数据分层验证**: 全局接口用户 vs 榜单用户重叠可能为 0(独立群体)。合并时明确区分,不要混为同一批。

## Verification

- ✅ 新注册账号调用全局接口返回与老账号相同数量的数据 = 全局库确认
- ✅ 批量注册 10 账号全部成功 = 注册无限制确认
- ✅ 并发 6 实例各自独立输出文件,合并去重后数量合理 = 提取成功
- ✅ 池子估算与实际唯一数收敛 = 接近全量
