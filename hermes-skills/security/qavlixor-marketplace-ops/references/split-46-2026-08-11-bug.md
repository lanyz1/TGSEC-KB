## 买家支付链路规则（2026-08-11 多 bug 修复实录）
- **checkout 金额必须按所选 SKU 取价**：URL `sku` 参数匹配 `operation.skuItems`（skuItemsJson 优先）；此前用 `product.price`（=variants[0] 首变体价）导致"选默认款 19.9 却按首变体 39.9×数量"显示。列表/详情价不一致同源（列表曾用 variants[0]、详情用 skuItemsJson[0]）——**统一口径：展示价一律优先 skuItemsJson[0]**。
- **禁止 fallback 商品**：checkout 无 product 参数时曾 fallback 到目录第一个有库存商品（水豚 39.9）→ 任何丢参入口都显示 39.9×qty（用户报"不管多少商品支付金额都 39.9"）。**无参数直接提示"请先选择商品"，绝不悄悄塞商品**。
- **支付死循环模式**（收银台返回 → 订单列表 → 去支付 → 回收银台）：订单列表"去支付"（PayNowButton）固定 USDT 通道重建 intent → 收银台返回写死 `/account/orders` 列表 → 循环。**修复模式：① 收银台加"更换支付方式"按钮（order kind 且 refs 非空时）→ 跳订单详情 `?changePay=1`；② 订单详情 changePay=1 时 PayNowButton 渲染通道选择（USDT/余额/其他→风控页）；③ 余额补付 API（订单已建后用余额支付）：原子条件扣减 `updateMany where {userId, availableAmount:{gte:total}}` → 订单 `paymentStatus:paid + orderStatus:awaiting_shipment` → `syncPaymentForOrder(method:balance)` → 销量+ → 通知**。完整链路见 `references/checkout-payment-chain-2026-08-11.md`。
- **paramiko 直查生产 DB**：sftp 写 `_q.mjs`（读 .env.local 注入 env → 动态 import Prisma）→ `node _q.mjs` → 删。坑：**OrderItem 无 createdAt 字段**（orderBy 会报错，用 id）；**删除 Product 必须先删子表**（ProductVariant/ProductImage/ProductOperationMetric 外键 23503）。**ProductOperationMetric 不是 Product 的 include 字段**（schema 无反向 relation），单独 `findUnique({where:{productId}})` 查。**对生产做"模拟写入验证"一律 `$transaction` + 末尾 `throw new Error("ROLLBACK_NOW")` 回滚，零副作用**（捕获后确认原值未变）。
- **paramiko 环境坑（2026-08-12 实测）**：hermes venv 的 paramiko 已坏（cryptography 50.0.0 vs 共享对象 48.0.1 不匹配 ImportError），且**全局 PYTHONPATH 指向 hermes site-packages 会污染所有 python 调用（连新建 venv 也中招）**——用 paramiko 前必须 `unset PYTHONPATH` + `python -m venv` + `pip install paramiko`（复用 `scripts/qav-prod-query.py`）。**服务器脚本一律 `.mjs`（ESM）**：`require` 报 ReferenceError，用 `await import("@prisma/client")`；`.env.local` 正则逐行注入 env。连接配置从 scripts/deploy.py 读取，勿硬编码（红线：禁凭证入 memory）。
