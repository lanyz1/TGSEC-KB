## 支付图标三改:裁切 + 无尺寸 SVG 坑(2026-08-13 收尾,commit 448f1f5/8e7c422)
- **坑1 裁切**:图标盒 `.pm-logo2` 原 `width:38px;overflow:hidden` —— 横向长 logo(PayPal 自然宽 41px、Wise 4:1 自然宽 107px、Google Pay 横版)全部被裁。修复:`.pm-logo2` 改 `min-width:38px;max-width:118px;padding:0 8px` 并**去掉 overflow:hidden**(注意这个类在 seller-proto.css 全局,充值/提现共用)。
- **坑2 无内在尺寸 SVG 渲染 0×0**(最坑):BrandImg 用 `height:auto;width:auto;maxHeight/maxWidth` 等比策略后,`usdt.svg`(cryptologos,只有 viewBox **无 width/height 属性`)和 `visa.svg` 直接渲染 **0×0**(元素盒 0 尺寸,complete=true 但 rect 0)——用户反馈"USDT 显示不出来,返回刚刚的那个"。**最终方案 = `height: size` 固定 + `maxWidth: 34` + `objectFit: contain`**:有内在尺寸的横向 logo 被 maxWidth 压进盒内(元素盒 34×26,内容 contain 居中不变形),无尺寸 SVG 按固定 height+viewBox 比例正常渲染。**判据:改 img 尺寸策略时,先确认 svg 文件有没有 width/height 属性;只有 viewBox 的一定要 height 固定。**
- **坑3 PayPal png 加载不出**:paypalobjects 的 `paypal.png`(1108B)部署后浏览器加载不出来 → 换 Wikimedia `PayPal.svg`(Special:FilePath/PayPal.svg,5.5KB),加载正常。png 换 svg 时记得同步删旧文件 + 改组件 src。
- **用户回退指令模式**:用户对图标类迭代会精确指定"**usdt 的返回刚刚的那个,然后 paypal 的重新下载个图,剩下的别动了**"——改图需求做版本化,每次改动范围最小化,记住每个版本效果以便回退;被否决的版本(手绘 SVG)永不再用。
