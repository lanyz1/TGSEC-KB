- 修复三层:
  1. 新增 `lib/aftersale-status.ts` `cnAfterSaleStatus()`:`seller_reviewing`/`seller_processing`/`pending`→商家处理中;`platform_reviewing`→平台介入;`rejected`→已拒绝;`refunded`→已退款;`closed`→已关闭;其他原样返回
  2. 读取端全走映射:卖家端 `app/seller/aftersales/page.tsx`(handling/platform 统计 + rows.status/statusTone/timeoutText/locked 全部先归一)、详情页 `asCase()`、管理端 `app/admin/aftersales/page.tsx`(platform/seller 统计)

- 验证:列表"待商家处理 0→1"、详情状态"商家处理中"、页面无 `seller_reviewing` 残留
- **通用教训**:状态/枚举字段必须单一词表。两个信号 = "统计 0 但明明有数据" + "页面显示英文码" → 先查 DB 该字段的值分布(SELECT group by),再定 读取端归一(兼容历史)+ 写入端归一(防再混)。同字段买家端 rma 页早有映射而卖家端漏 → 排查时**同字段两端展示一致性都要查**。

## 售后/退款订单物流轨迹缺"已发货"(commit b9ee033 + e56b2b5)
- 症状:已发货过的售后中/已退款订单,详情页"订单状态"时间线(5 段步骤条)只有"—",看不到"已发货";物流信息卡却显示"运输中"
- 根因:`app/seller/orders/[id]/page.tsx` 的 `orderTimeline(order)` 里 `shipped = ["运输中","已签收","已完成","已关闭"].includes(status)` —— **不含"售后中"/"已退款"** → 已发货过的售后订单 shipped=false → 发货节点 time="—" 无 done 标记
- 修复:`orderTimeline` 加 `trackingShipped` 参数(调用处传详情页已有的 `shipped = Boolean(fulfillment.trackingNo && fulfillment.trackingNo !== "待填写")`),`shipped = trackingShipped || 状态列表命中`;未发货售后订单仍显示"—"(不误标)
- TS 坑:`fulfillment.trackingNo && ...` 返回 `string | boolean`,传 boolean 参数报 TS2345 → 包 `Boolean()`
- **通用教训:判断"已发货"这类物流事实用物流单号(事实),不要用订单状态(状态会因售后/退款流转偏离物流事实)**;发货页(`/logistics`)"物流轨迹"卡本来就基于单号判断,本次只修详情页"订单状态"时间线——两端时间线判断口径要一致。
