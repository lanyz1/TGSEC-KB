## 生产部署与验证（2026-08-08 实测，多轮踩坑后固化）
**一键部署（2026-08-09 起，98 秒全自动，替代手动多步）**：`python scripts/deploy.py "改动说明"`——自动完成：①本地 `npx tsc --noEmit --incremental`（tsconfig 已有 incremental → 2 秒）②git commit ③`git archive | gzip` ④paramiko SFTP 上传 ⑤服务器 `tar xzf` + `pnpm exec next build --no-lint` ⑥`pm2 restart ×2` + curl 200 探测。**提速前提**：`next.config.ts` 已加 `typescript: { ignoreBuildErrors: true }`（本地 tsc 把关后 build 跳过重复 typecheck，build ~3min → ~1.5min）。**注意**：`next build` 默认跑 typecheck+lint，跳过必须显式配置。
**部署四步清单（每轮部署照做）**：
1. **验证 tar 包内容**：`git archive --format=tar HEAD -o qav-deploy.tar` 后必 `tar tf qav-deploy.tar | grep <本次改的文件>`——**gitignore 误伤会让目标文件不进包，生产永远旧版**（本轮实坑：`.gitignore` 第 29 行 `uploads/` 匹配了 `app/api/uploads/` 目录 → 上传 API 从不进 git → 生产一直 7/30 旧文件 → 修复 3 次部署都不生效）。**修复模式：gitignore 规则加根锚 `/uploads/`（只挡根目录存储），`git add -f` 强制跟踪被误伤的路由**。
2. **build 等完成再 restart**：`(nohup pnpm run build > log &)` 后**必须轮询日志确认 `Compiled successfully` 且 build 进程退出**，再 `pm2 restart`——**build 未完成就 restart = 进程加载旧产物**（本轮实坑：restart 后新 API 404，二次 restart 才生效）。**产物比进程新的诊断**：`ls -la .next-build/server/app/api/<new>/route.js` 时间戳 vs `ps aux | grep next-server | awk '{print $2,$9}'` 启动时间；BUILD_ID 新 ≠ 进程加载新。
3. **增量编译异常 → 清缓存重建**：`rm -rf .next-build && pnpm run build`（本轮实坑：增量 build 产物一半新一半旧——server 产物新、static chunks 旧，前端 UI 看不到新功能）。重建后**验证产物含新代码**：`grep -c <关键词> .next-build/server/chunks/*.js`（中文关键词用 unicode 转义 `\uXXXX` 或直接 grep 服务端源码；客户端组件文案在 SSR chunk 里）。
4. **生产验证用服务器本地 node 脚本**（本机 curl 被出口 IP 限制）：sftp 传 verify-*.cjs → `node verify.cjs` → 删——模式：登录拿 cookie → 调 API 断言 → 抓页面 HTML grep 关键词（`html.includes('中文')` 用 `\uXXXX` 转义防编码问题）→ DB 直查对照。**改测试账号数据必清理/回补**（测试单删除+余额回补）。

**🔴 生产 DB 静默全挂事故（2026-08-08，本会话最大坑）**：生产 `.env.local` 首行带 BOM 的 `DATABASE_URL="file:./dev.db"`（sqlite 历史遗留）→ **Next.js 加载 .env.local 优先于 .env** → PM2 进程 Prisma 初始化失败 → **所有 DB 操作静默失败**（API 里 `.catch(()=>null)` 兜底降级，页面"假正常"，登录只走硬编码分支）。**症状**：新密码登录 401 旧密码 200、pm2 日志 `prisma:error ... URL must start with postgresql://`、所有 DB 查询空。**修复**：删 .env.local 的 DATABASE_URL 行（**带 BOM 时 `sed '/^DATABASE_URL=/d'` 不匹配，用 `sed '/^\xEF\xBB\xBF*DATABASE_URL=/d'` 或 python 处理**）→ pm2 restart。**教训：生产部署包里的 .env.local 是 dev 遗留，检查它有没有覆盖 .env 的键**。

**角标/通知体系（2026-08-08 三端修复）**：
- 通知体系原本**无已读概念**（count=7天总数、无 readAt 字段）→ 角标永不减。修复模式：schema 加 `readAt DateTime?` → 已读 API（`POST /api/notifications/read` 按 email 批量 updateMany）→ notifications-recent 改未读口径（`readAt: null`）→ 前端打开面板即调已读+本地清零 → 通知中心进入即已读。
- **侧栏角标口径**：管理端 nav-counts/KPI 原用 `status notIn [approved,rejected]` / `in [submitted,draft]` → **draft 草稿商户（注册未提交资料）永远计入，角标永不减**。修复：只算 `status: "submitted"`。**规则：待办角标口径 = 该队列页真实可操作状态，草稿/终态一律排除**。
- chat 消息角标（readAt 口径 + 15s 轮询 + 打开会话调 read）本就正确，用户报"不减少"多为通知铃铛或 draft 口径——先核对计数 API 口径再动代码。

**状态词 DynamicText 词级半译坑（2026-08-08 售后页实测）**：DynamicText 对翻译表**无键的中文词**做词级半译（"未发货"→"未Shipping"），英文值同样半译（"Unshipped"→"Un已发货"）。**修复：状态词必须用翻译表已有键的中文值**（如"待发货"匹配 `account.status.unshipped`，各语言正确输出）——订单详情页 `statusText` 词表（待付款/待发货/待收货/已签收/交易成功/售后中/交易关闭）是金标准，新页面直接复制。**排查：页面状态出现中英混合 = 词不在翻译表，改成表内已有中文词**。

**买家余额支付模式（2026-08-08 上线）**：结算页支付方式加 balance 选项（显示可用余额，新 API `GET /api/buyer/wallet`）→ 下单 API balance 分支：`$transaction` 内**条件原子扣减**（`updateMany where { userId, availableAmount: { gte: total }, data: { availableAmount: { decrement: total } } }`，count===0 即余额不足）→ 订单直接"待发货"（不走收银台、不建 intent）→ 失败回滚已落库订单+回补库存。**前置：PaymentMethod enum 加 balance 值 + db push 生产**。资金记录面板加消费条目（查 paymentTransaction method=balance status=paid by buyerEmail）。
