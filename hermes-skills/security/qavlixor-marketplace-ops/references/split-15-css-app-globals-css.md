## CSS 架构坑(app/globals.css — 最重要,改了不生效先查这)
1. 买家 `bac-*` 类**真源在 `.buyer-portal` 作用域**(特异性≥0,3,0),压过 `.sap .bac-*`(0,2,0)覆盖 → 买家黑白化**必须改 `.buyer-portal` 真源**,在 `.sap` 里写覆盖会静默失效。
2. 全局表单重置块 `.buyer-portal button,...{border-radius:8px !important}` → 买家端任何胶囊按钮必须加 `!important` 对冲(例:`border-radius:999px !important`)。**⚠️ !important 军备赛(2026-08 实测,两轮)**:重置块本身带 `!important`,普通 `!important` 在同特异性下按**级联顺序**仍输给它(如 `.qx-market-search button{999px!important}` 敌不过 `.buyer-portal button{8px!important}`——后者选择器里含 .buyer-portal,特异性(0,1,1)+!important 压过(0,1,1)+!important 且顺序靠后)。**解法 = 提特异性**:`grep` 目标元素祖先链拿到 portal 包裹类,写 `.buyer-portal .qx-market-search button{border-radius:999px !important}`(0,2,0)才稳赢。搜索按钮就是靠这个改成功的。**第二轮更深的坑(Apply 按钮 `.cct-price-confirm`)**:重置块选择器列表**包含 `.buyer-portal .button`(0,2,0)**——按钮 class 是 `button secondary cct-price-confirm`,同时匹配两者;同 important 同特异性(0,2,0)**靠文件顺序赢**,而重置块在文件更靠后 → 光提特异性到 0,2,0 没用。最终解法:**`button.cct-price-confirm`(0,2,1,含元素选择器)+ 背景/字色/边框/圆角全属性 `!important`**(只给圆角加 important 时 bg 仍被 `.button.secondary` 白底压住)。**教训:胶囊按钮遇到 `class 含 button` 时,选择器写 `button.类名` 提特异性到 0,2,1,且 bg/color/border/border-radius 四个属性全加 !important。**
3. **CSSOM 枚举调试法(改圆角/阴影/字重不生效时)**:浏览器控制台枚举所有样式表规则,找出元素实际命中的全部规则及 !important 优先级:
   ```js
   [...document.styleSheets].forEach(sh=>{try{[...sh.cssRules].forEach(r=>{if(r.style&&el.matches(r.selectorText))console.log(r.selectorText, r.style.borderRadius, r.style.getPropertyPriority('border-radius'))})}catch(e){}})
   ```
   比盲目加 !important 快——直接看到"谁赢、为什么输"(同值 !important 比特异性,同特异性比顺序)。查字重同理:浏览器默认 h1/h2 是 700 且**无显式规则命中**,须显式写 font-weight 覆盖。**字号同理(2026-08-04 实测)**:全局 `h1{font-size:clamp(38px,6vw,68px)}` 会把列表页/商详标题顶到 68px(首页 hero 最大才 42px)——用户嫌标题大时,先 CSSOM 枚举看是否命中全局 clamp,再局部覆盖小字号(如 `.buyer-portal .catalog-heading h1{font-size:32px}`),别只调字重。
4. 两个 portal 并存:`.marketplace-portal`(外壳)+ `.buyer-portal`(内层);首页用 `bk-*` 类(bk-hero/bk-section/bk-tile + market-product-card)。
5. 全局 `.button` 基类影响面大(如粉色发光 box-shadow 在基类),局部覆盖优先于删全局,避免波及非买家页。
6. **买家端橙/红残留是"一族多拼写",别用单值 sed** — 同族色在不同页有不同拼写:`#fff7f4`(asf-choice)、`#fff7f5`(catalog-cat-tree cct-link)、`#ff4f16`、`#fdf1f1`、`#f0b7b7`、`#b42318`。C1 只按已知值清,漏了 C2 /products 的 `#fff7f5`。**清残留必须全库扫族**:`grep -nE "#fff7f[45]|#ff4f16|#fdf1f1|#f0b7b7|#b42318|#fe2c55" app/globals.css` 一次列出全部出现点再逐个改,不能只改已知页。\n6.5 **⚠️ 饱和色探针有"近白浅粉盲区"(2026-08-05 C3 实测)**:`.buyer-portal *` 扫饱和色的探针按 max-min<45 过滤近白——但浅粉/浅橙底(`#fff0f3` add-cart、`#fff8f9` sku-option.selected、`#fff7f5` favorite.is-active)的 max-min 只有 8-18,**全部被当近白放过**,肉眼却是明显粉底。**巡检必须加浅粉系专项探针**,不能只扫饱和色:\n   ```js\n   // 浅粉/浅橙残留: r 高、g 居中偏低、b 低、r-b>8\n   const m=s.backgroundColor.match(/rgb\\((\\d+), (\\d+), (\\d+)\\)/);\n   if(m){const [r,g,b]=[+m[1],+m[2],+m[3]];if(r>245&&g>230&&g<250&&b<245&&(r-b)>8)sat.push(...)}\n   ```\n   教训:C1 前几轮"残留清零"其实漏了 3 处浅粉,直到 C3 加强探针才揪出。**每次改完跑两遍:饱和色探针 + 浅粉系探针**。**⚠️ 探针盲区补充(2026-08-05 C3 价格条实测)**:① **必须同时扫 `borderColor`**——浅粉残留不只 bg,还有分隔线/边框(如 `.pdp-price-stats div` 的 `border-left:#ffe3e9`),只匹配 backgroundColor 会漏;② g 阈值 230 会漏 g=227 的浅粉(`#ffe3e9` g=227 不满足 g>230)→ 判别放宽为 `r>245 && b<245 && (r-b)>8`,且 border 与 bg 都跑。**教训:C1 前几轮"残留清零"其实漏了 3 处浅粉,直到 C3 加强探针才揪出。每次改完跑两遍:饱和色探针 + 浅粉系探针(含 borderColor)**。
7. **多语言/长文本溢出(grid 固定列被内容撑破,2026-08-04 实测)** — 切俄语/阿拉伯语后侧栏(价格区+分类树)溢出画进主内容区。根因链与修法:
   - **真源是 `.zcool-catalog-layout`(~7613)不是 `.catalog-layout`(~1398)**:页面类名 `catalog-layout zcool-catalog-layout` 双类,后者覆盖前者。固定列 `238px` → `minmax(0, 238px)` 允许收缩。**查 grid 列先 grep 页面真实类名,别改错源**。
   - **grid/flex 子项默认 `min-width:auto` 被长文本撑破**:溢出链上每层都要 `min-width:0`(`.catalog-filter > *`、`.cct-group`、`.cct-node`)。只给最深元素加没用,链条任一环的 min-width:auto 都会撑破。
   - **`width:100%` 元素是 content-box 时溢出**:输入框/按钮 `width:100%` + padding/border 超宽(Apply 262px 超 238px 容器)→ 加 `box-sizing:border-box`。输入对 `1fr 1fr` → `minmax(0,1fr) minmax(0,1fr)`。
   - **details 未展开的子节点仍在布局计算**:探针 `getBoundingClientRect().right` 报越界但元素不可见(offsetParent 非 null 但父 details.open=false)→ 以侧栏容器 `scrollWidth ≤ clientWidth` 为准,别被隐藏子节点读数误导。
   - 验证指标:侧栏 `scrollWidth <= width`、Apply/输入对宽度收进侧栏、`getComputedStyle(layout).gridTemplateColumns` 显示 minmax。
   - **⚠️ patch 截断坑**:`patch` 的 old_string 以规则块首行结尾时(如只贴到 `border: 1px solid var(--buyer-line);` 就收),会吃掉下一块的剩余行 → 产生孤儿 CSS 行。改 globals.css 后**必须 `read_file` 重读改动区确认块完整**,发现截断立即补回。宁可 old_string 多带上下文,别短。
8. **sticky top 影响初始渲染位置(2026-08-04 实测)**:`.catalog-filter` 曾 `position:sticky; top:126px`,实测**未滚动时**卡片 top=126px 而右侧内容正常流 top=83px(header 65 + main padding 18),左右顶部错位 43px——sticky 的 `top` 在初始渲染时就把元素推到"距视口顶 top 值"处,不只是滚动时的吸顶位。**修法:`top` 设成滚动时想卡的位置(如 header 下方 18px),初始位置自然回落到文档流与右侧对齐**。验证:滚动前 filterTop=headingTop=83 diff=0;滚动 100px 后卡 18px 不盖 header。**教训:两栏 sticky 布局顶部不对齐时,先查 sticky 元素的 top 值是否>内容起点(header+padding),把它改小到吸顶目标位即可,别加 margin 硬调**。sticky 元素比容器矮时滚动到底会贴容器底(正常终态,别当 bug)。
