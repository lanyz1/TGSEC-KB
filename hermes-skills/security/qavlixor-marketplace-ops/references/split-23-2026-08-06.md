## 批量脚本纪律与翻译键坑(2026-08-06 实测,两次踩)
- **execute_code 批量替换脚本必须确认写盘**:第一轮 i18n 脚本只 `print` 匹配检查结果、**漏了 `io.open(p,"w")` 写文件** → 16 处替换"匹配 OK"但没落盘,页面仍中文,排查半天。**规矩:批量替换脚本末尾必写盘 + 输出写盘确认;且替换后立刻 `grep` 目标文件验证 `data-i18n` 计数与预期一致**。锚点拼接小心引号:`zh_anchor` 已含尾引号时再拼 `'": "将导出'` 会变成 `"": "` 双引号重复导致 find=-1 静默失败(print"插入完成"但没插入)——锚点用完整键行 `'  "key": "值",'` 字符串替换最稳。
- **execute_code 每次调用是全新进程(2026-08-06 实测)**:跨调用不保留任何变量/import——大块数据(如 200 行 KEYS 表)要么单次调用内完成全部读写,要么第一次调用写盘、第二次读盘;本次第二段脚本想引用上段变量直接落空。同理 execute_code 与 terminal 互不共享变量,共享数据一律走磁盘文件。
- **工具输出脱敏 `***`(2026-08-06 实测)**:read_file/terminal/python print 的输出层会把疑似密钥样文本(如 `"17TRACK API Key"`)脱敏成 `*** API Key`——**文件本身没坏**,别误判为文件损坏去改文件;核对真实字节用 `python -c "print(' '.join('%02X'%ord(c) for c in ln))"` 十六进制输出(本会话用此确认 track17ApiKey 行真实内容为 `"17TRACK API Key"`)。
- **data-i18n 整段替换把 `{n}`/`{max}`/`{count}` 当字面**(坑 #28 变体,本会话 2 次踩:铃铛"Unread {n}"显示原样、划转面板"Max {max}"):**带变量的文案不能整段 data-i18n**——拆成 `<span data-i18n="key">未读</span> {count}` 数字单独渲染,键值只含无变量部分。全站统一模式:`<span data-i18n="seller.X.label">文案</span> {数字}`。
- **AppleSelect label/option 是数据值(仓库名/模板名/关闭原因)→ data-i18n-raw 豁免**(已有坑 #31);但**CLOSE_REASONS/状态数组等静态中文若走词翻译会半译("4 Pens"="4 笔"被词译),动态反馈(blockedReasons/message)统一 data-i18n-raw 保持中文**。
- **requireRole 返回 {ok, role, email},无 displayName** — 需要昵称时查 `prisma.user.findUnique({where:{email}})`。
- **⚠️ 整个键块被误删的\"键名泄漏\"症状(2026-08-06 S15 实测,坑 #32 第三种形态)**:组件里 data-i18n 键**在 translations.ts 里 0 个存在**(S15 商品编辑页 seller.productForm.* 58 键全无——被某次批量脚本整块删掉)→ 英文态 placeholder/按钮/标签全部**显示原始键名**(如 textbox placeholder 显示 `seller.productForm.titlePlaceholder`),中文态正常。**排查:英文态页面出现键名文本 = 键缺失(不是词翻译没翻),用 python 正则提取组件全部 `data-i18n(?:-placeholder)?="([^"]+)"` 键,逐个比对 translations.ts 是否有 `"key"` 行,列出缺失清单再批量补**。补键流程:① 从组件正则提取键+中文原文(文本节点 `data-i18n="key">中文<` + placeholder 两种属性顺序 `data-i18n-placeholder="key" placeholder="中文"` 与反序都要匹配);② zh=en 双区插入(锚点用完整键行);③ **⚠️ 组件中文原文里的英文双引号(如 `买家端"规格"按钮`)直接进 zh 值会炸 TS(坑 #32 第三次)——提取后先扫 `'"' in v` 的键,成对替换成中文引号「」**(`"规格"`→`「规格」`,别用 `replace('"','「」')` 会变 `「」规格「」`);④ tsc + 浏览器英文态验证键名消失。
