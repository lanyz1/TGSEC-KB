# 旁站归属否证闸(并案与计分之前)

**定位**:回答一个问题 ——「这个站 / 这台机器 / 这份数据,是我的目标吗?」
在把旁站战果**计入目标**之前先做否证。用户直接问「是目标站的吗」时,这就是唯一该走的流程。

**触发**:是目标站的吗 / 这数据是不是目标的 / 同一个运营方吗 / 顺手打下的旁站能不能并案 /
同套源码 / 同前缀桶名 / 同 IP 段 / 同一个支付回调形态 / 白标家族里的兄弟站。

**边界**:本卡只做**归属定性**(是/否/未证)与证据链;完成后的利用交对应打法卡。
**与 `operator-attribution` 的分工**:那张卡解决「怎么证明同一个运营方」;本卡是它的前置反向闸 ——
**默认假设「不是」,由证据翻转**。已并案的结论被推翻时,本卡还负责把旧定性收回。

## 0. 目标真身闸(先于一切并案)

操作员的**原始指令**就是目标定义。回答任何「这是哪个目标 / 拿到了什么权限」之前,
先把原话从案卷或 `state.db` 里摘出来,原样复述:

```sql
-- session_search 的 FTS 表缺失时直接查库(FTS 正常时用 session_search)
sqlite3 -noheader /root/.hermes/state.db "select id, substr(replace(content,char(10),' '),1,200) from messages where role='user' order by id desc limit 20;"
sqlite3 -noheader /root/.hermes/state.db "select id, role, substr(content,1,200) from messages where content like '%<关键词>%' order by id desc limit 10;"
```

以操作员自己发的那条 URL/域名为准 —— **不以案卷标题、不以技能卡名、不以记忆条目为准**。

**硬规则**

1. 侦察中**自己发现**的资产 —— 广告池/推广位里的下游站、白标租户、兄弟品牌、素材桶里的跳转域、
   技能卡里出现过的域名 —— 一律是**旁支**,只能进「旁支清单」,不得改名为主线,
   更不得在「你给我的目标是哪个」的回答里顶替原目标。
2. 旁支可以打,但必须**同时**保留主线目标与主线状态;旁支花掉的时间不算主线进度,单独记账。
3. 已跑偏时的处置顺序固定:**先收回**(说清哪个是我自己找的、哪个是你给的)→ 列证据(原话/时间戳)
   → 立刻回主线。不解释第二遍,不写「我以后会注意」。

**触发词**:「这是我给你的目标吗」「我给你的是 X?」「哪个才是目标」「你打的是哪个站」。

## 铁律

1. **默认「不是」**。旁站不并案、不计分、不进目标 PII 口径,直到证据翻转。
2. **两条目击为否 ⇒ 结论「不是」**;只有一条为否 + 业务对不上 ⇒ 写「未证」,不写「否」(见判读表)。
3. **同模板 / 同 CDN / 同 IP 段 / 同厂商 一律不算证据**。只认具体标识串命中、vhost 真响应、
   证书节点身份、回调域映射这类**点对点**证据。
4. **上一轮说错了要显式收回**。把旁站说成「目标的收款链/目标的数据」后反证成立,
   必须在报告和对话里写「收回 + 翻转理由 + 证据」,不能让旧定性留在案卷里继续指挥火力。

## 五条否证矩阵(按成本从低到高)

### 1. vhost 撞名 —— 最便宜、最硬
```bash
for h in <目标主域> <目标后台域> <目标API域>; do
  printf '%-30s ' "$h"
  curl -s -o /dev/null -w '%{http_code} %{size_download} ' -H "Host: $h" http://<候选IP>/
  curl -sk -o /dev/null -w 'https:%{http_code}\n' -H "Host: $h" https://<候选IP>/
done
```
判读:**必须看 body,不能只看状态码。**
- `403` + body 含 `Non-compliance ICP Filing` / 未备案提示 = 该机**没有**这个站(国内 IDC 默认拦截页)。
- `404` + 裸 nginx 默认页 = 该机没有这个站。
- 目标真在同机 ⇒ 该 Host 回目标自己的状态码/标题/接口结构。
- **但要先认清这台机器是什么**：备案拦截/默认页只能说明「该 vhost 不是目标」，**不能说明机器是死的**。
  实测：`http` 回 `dnspod.qcloud.com/static/webblock.html`、`https` 带域名直接 RST；改成
  `https://<IP>` + `Host: <IP>`（两者都用**裸 IP**、不带 SNI 域名）立即 200，拿到 9,541 字节真应用首页。
  不绕过这一层，你会把一台活主机写成「已下线」，或者反过来把一个无关产品当成目标继续打。
  先拿到首页与 chunk，再回答「它到底是谁」。

### 2. 证书 CN/SAN = 共享节点身份
```bash
echo | openssl s_client -connect <候选IP>:443 -servername <候选站域> 2>/dev/null \
  | openssl x509 -noout -subject -ext subjectAltName
```
证书里常直接是**共享主机节点名**(实测 `CN=kg002.apk5566.cn`,与该机 MySQL 用户名 `kg002_sql` 同源)。
⇒ 这台是虚拟主机,**节点级特征(开放 3306/8888、库用户名、面板指纹)不能推出站点级结论**。

### 3. 源码全量标识零命中测试
把旁站的泄露源码/构建产物,对目标的**全部标识**一次性 grep:
主域、后台域、API 域、静态桶名 + APPID、CDN 域、KYC 域、运营方姓名/手机号。
```bash
grep -rIoh "\(kkyfl\|pdoob\|zglw-ops\|nzctjvr\|1394740319\|运营商手机号\)" . | sort -u
```
- **零命中 = 非同源**,直接进第 4 步确认后收结论。
- 命中必须是**具体串**(桶名/域/APPID/姓名),不能是「都用了 Wanlshop/FastAdmin/宝塔」。

### 4. 数据面交叉 —— 注意伪装字段
字段级比对:商品/订单/商户/流水 vs 目标的业务模型。
- ⚠️ **支付/跑分网关的 `subject` 是伪装的商品名**(义乌小商品 / 充电器 / 羽绒服 / 视频会员卡),
  **不能靠商品文本否定关联**;充值入金就藏在这些假商品单里。
- 有效判据:**回调域是否指向目标 / 商户映射能否对上 / `out_trade_no` 前缀是否等于目标的下单号规则**。
- 三条都拿不到 ⇒ 结论写「**未证**」(证据不足),不是「否」。
- 反向取目标的收款通道用于对账:客户端侧找 `recharge/options` → 通道名;下单接口会回 `payUrl`,
  域名即网关。**幂等键字段名从 bundle 里挖**:搜 `idempotency` 附近 → 本例 `idempotency:'body-request-id'`
  ⇒ body 必须带 `requestId`;否则回「请求标识幂等键不能为空」。下单常被实名/风控挡(如实记录,别硬绕)。

### 5. 栈与段比对
`Cloudflare + AWS 微服务 + 自研签名网关` 与 `宝塔/nginx + PHP FastAdmin + 共享库` 属两个世界。
同段 IP、同 CDN 厂商、同 ASN 都不构成并案。

#### 5.1 云共享 `/24`：投字典前必须过的三道门（2026-10 实测代价）

拿到目标某台机器的一个旁站 IP 后，整段 `/24` 看上去都像自己人 —— **不是**。云厂商把同一个 `/24`
切给大量互不相干的客户。

实测：扫 `139.199.15.0/24` × 28 端口得到 **201 个开放端口**，SSH / RDP / 宝塔 / MySQL 各家的都有。
其中一个 `:3306` 的版本、字符集、报错页都像目标栈，直接投 rockyou **15,000 条，全零**；之后靠
端口分布才反推出它是另一家老 PHP 租户。整轮彻底白烧，还多了一个「疑似打过别人客户库」的口径风险。

**投任何字典之前的三道门（有一条不过就不投）：**

1. **归属证据只有三条算数**：同 A 记录 / 同证书 SAN / 首页或 JS 里**真连**的域名。
2. **端口分布自证**：一个租户很难同时开 201 个端口；分布极散 = 共享段，不是那台机器。
3. **库指纹先对**：版本号、字符集、业务表名/库名。即使过了门，也先跑 **20–50 条最小校准词表**
   验证「这个库到底是不是那个应用在用」，再决定上不上大字典。

> 口诀：**同 IP 归组靠主动证据；同 `/24` 归组从来不成立。**

## 判读表

| 观察 | 结论 |
|---|---|
| vhost 回未备案拦截页 / 默认页 | 目标**不在**该机 |
| 证书是共享主机节点名 | 节点级特征不可推到站点 |
| 源码对目标标识零命中 | **非同源** |
| 商品名与目标业务完全不同 | **不能**单独作为否证(伪装) |
| 回调域/商户映射对上目标 | **是**(唯一可翻转的硬证据) |
| 只有「同套源码/同前缀/同 IP 段」 | **未证**,不并案 |

三档结论写法:
- **是** —— 点对点证据(回调域映射 / 标识串命中 / 同一会话可跨站复用)+ 时间戳。
- **不是** —— 两条以上否证 + 命令与响应片段。
- **未证** —— 列缺哪一条证据,以及补证需要什么前置(如过实名才能下单拿 payUrl)。

## Pitfalls

1. **同 CMS/模板 ≠ 同运营方**。Wanlshop、FastAdmin、宝塔满世界都是;泄露源码只证明「同款软件」。
2. **同前缀命名不是证据**。`gtgm0906-<appid>` 与 `gtgmtong.*` 只是命名习惯,要 CNAME/桶级证据才作数。
3. **`403` 不等于「目标在这台」**。未备案拦截页也是 403,必须看 body。
4. **共享主机节点特征误当站点特征**:开放 3306/8888、`kg002_sql@localhost` 是节点级;同机还有几百个无关站。
5. **拿伪装商品名否定关联**。跑分单的商品名是假的,否证必须落在回调域/商户映射上。
6. **旁站战果污染目标口径**。两个盘子分开记账,报告里分节写;虚报比漏报更伤交付可信度。
7. **反证也要留证**。每条否证存命令 + 响应片段 + UTC 时间戳,否则下次又会被同一个「像」拉回去重打。
8. **自己挖的下游站会冒充目标**。广告池/推广位/白标租户里翻出来的站,域名像、业务同一套,
   但它是**客户**,不是目标。实测教训:从 navbox 广告池 404 条推广位里取出 `48.VIP`(租户
   `companyPageName=48.VIP`、`companyId=22036`),连打一整夜写成两份主报告,被操作员一句
   「我给你的是 48.VIP?」打回 —— 主线从头到尾是 `tx-h5.gxegdg.cn`。**租户名/品牌名出现在目标
   自己的配置里,不构成它是目标**。
9. **报告文件名是二次污染源**。`48VIP_深挖审计_*.md` 这种命名会让下一次会话 `grep` 时
   把旁支当主线捞出来。旁支文件一律带 `side-` 前缀(如 `side-48vip-*.md`),主线报告名只放操作员给的域名。
10. **一次答多个候选 = 等于没说**。被问「是哪个」时给单一结论 + 一句判定依据;
    列一串案卷名让操作员自己挑,下一轮必被骂。
11. **共享 `/24` 上看到一个「像」的数据库就直接投字典 = 给别人的客户白烧一整轮**(§5.1)。
    实测 15,000 条 rockyou 全零才发现是另一家租户。投词表前过三道门，永远先跑 20–50 条校准。
12. **防火墙级白名单不是应用层**。10 种来源头（`X-Forwarded-For` / `X-Real-IP` / `True-Client-IP` /
    `CF-Connecting-IP` / `Forwarded` / 无头 …）全部 TCP RST ⇒ 白名单在防火墙上，继续换头、换编码、
    换 Payload 全是无效功，立刻换线（找白名单内主机 shell 或 SSRF 打回环）。
