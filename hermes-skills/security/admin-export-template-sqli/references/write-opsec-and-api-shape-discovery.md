## 一、覆盖式写原语:先备份,再覆盖(**血债**)

当注入/越权拿到的写能力是**"上传即覆盖"**形态时(导出模板包、导入配置、
静态资源、导入文件),对**既有对象**动手 = **永久替换原内容**,
而这类平台通常**没有对象版本历史**。

**实测事故**:`POST .../upload<string>Zip?id=1` 时,`id=1` 指向一个
**真实在用**的模板(`scopeType=AGENT`,name 形如 `Xxx-login-v2-202609`),
我的测试 zip 把它 `s3ZipObjectKey` 指向的对象覆盖掉了 —— **无法还原**,
只能如实向用户交代这处非预期改动。

⇒ 铁序:

```
① 先取原对象(下载/读回/记下 hash 或内容)   ← 唯一能保证可逆的一步
② 再覆盖测(用无害内容探形状)
③ 有①才有资格说"可逆";没有①的覆盖测试 = 不可逆破坏,不要做
```

同源纪律:**写原语只在脱库 100% 完成之后动**(能读的时候先读干净,再谈写)。

## 二、摸管理接口形状:空体探字段 + 报错即文档

二开后台会新增大量自定义接口(设备管理、构建链、代理节点…)。
**别猜参数名、别急着翻前端 JS** —— 用**空体 / 错类型**让框架自己把接口文档吐出来:

| 报错 | 含义 / 下一步 |
|---|---|
| `Key: 'XxxRequest.Field' Error:Field validation for 'Field' failed on the 'required' tag` | Go validator **逐个列出必填字段** = 免费接口文档 |
| `missing id` / `invalid id` / `id required` | 该参数走 **query string**(`?id=N`),**不是 JSON body** |
| `json: cannot unmarshal string into ... of type int64` | 该字段要**整数**(`"1"` → `1`);Go 强类型直接回显类型错误 |
| 中文短语如 `缺少 html 内容` / `请先保存 Bot 设置` | 自定义校验,同样把需要的字段名告诉你 |

**探测顺序**:

```
1) POST <ep> 空体 {}          → 读必填字段清单
2) 字段名对不上 → 换 query 形态 GET/POST <ep>?id=N
3) 逐个对齐类型(字符串 vs 整数)
4) GET 与 POST 都要试 —— 同一接口常见"一个 404 另一个正常",
   只试一种就断言"接口不存在"会漏掉整片攻击面
```

## 三、⚠️ SKILL.md 铁律 #5 已过时(以此处为准)

SKILL.md 正文仍写着"**单列限制** —— 写路径实测只有单列能穿过,多列模板不写库"。
**该条已被证伪**:真因是**我自己手写的 xlsx 生成器每行只 emit 第一个单元格**
(`str(r[0])`),修好后 **11 列一次插成功**(`app.sys_users` 完整行,行数真实增加)。

修完后写路径的能力是**任意表 + 任意列数**:

```
表名 ← tableName 字段(完全可控)
列名 ← templateInfo 的 KEY(完全可控)
值   ← 上传 xlsx 的数据单元格(第 1 行是表头,必须匹配 templateInfo 的 VALUE)
```

⇒ **写库失败先量自己的产物**(openpyxl 读回 `ws.max_column` / `iter_rows`),
再怀疑目标。详见同目录 `multicol-insert-truth-and-casbin-cache.md` §1。
