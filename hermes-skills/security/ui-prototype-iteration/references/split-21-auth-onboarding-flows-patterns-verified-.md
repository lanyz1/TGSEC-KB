## Auth / onboarding flows (登录/注册/入驻/审核) patterns (verified 2026-08)
Four auth routes (`ROUTES` marked `:1` = auth-mode, hides nav/topbar): `login`, `register`, `onboarding` (4-step wizard), `status` (review progress). All four share `.auth-side` + `.auth-card` (centered max-width card on the right, or full-width for register/status).
- **Login**: brand panel (black, white logo block, blue-accent slogan "把生意做到全球 180+ 个市场", 3 point rows 商品一键铺全球 / **全球收款,多币种结算** (USER-CORRECTED 2026-08: the original "USDT 安全结算 · 链上收款" row was rewritten once multi-channel payment was shipped — sub-line now enumerates "USDT · PayPal · Wise · 信用卡 · Apple Pay · Google Pay,手续费透明", never sell a single method as the headline) / 平台担保售后) + form card. Add mainstream touches: `err-banner` (red demo error line), **记住我 checkbox + 忘记密码? link** (link → reset-email toast) between password and the 登录 button, 立即注册 link below.
- **Register**: 邮箱 + 邮箱验证码 (`inp-row` + `code-btn` sendCode) + **密码 with live strength meter** + 确认密码 + 3 agreement checkboxes (服务协议/平台规则/隐私政策) + 注册并入驻 → `show('onboarding')`.
  - **Password strength meter** (`pwMeter(inp)` oninput): `.pw-meter` 4px track (`#E5E5EA` bg, `border-radius:999px`) + `<i id="pwBar">` (width% + color transition) + `#pwHint` text. Branch order: empty → gray 20% "至少 8 位…"; `length<8` → red 25% "长度不足 8 位"; has lowercase+uppercase+digit → green 100% "强度强,密码安全"; has lowercase+digit → orange 70% "强度中,建议加入大写字母与符号"; else → orange 50% "强度一般…". PITFALL: don't gate the green tier on length≥10 — a 9-char mixed password should still read 强; `<8` is already filtered, so the strong branch needs no length check.
- **Onboarding 4-step wizard** (steps bar 企业资料→法人信息→联系人→确认提交, `onbStep(d)` + `onbCur` state): step 1 企业资料 — 店铺名 / **注册国家 dropdown MUST cover global markets** (中国/中国香港/新加坡/美国/英国/日本/德国/法国/澳大利亚/加拿大/阿联酋/其他 — a 3-option China/US/UK select was too narrow for a 180-market platform) / 营业执照 `.upload` box / 主体名称(本地语+英文) / 注册号 / 注册地址 / 执照到期日 + 长期有效 checkbox; step 2 法人信息 — 证件正反面 upload + 签发国 + 姓名/证件号/出生日期 + 证件展示项 radios (国籍/地址/两者) + 关联证明; step 3 联系人 — 姓名/邮箱(验证码)/首选语言/电话; step 4 确认提交 — **three `.review-card`s (①企业资料 ②法人信息 ③联系人) each with 编辑 link calling `onbStep(<stepIndex>)` back-jump** + rv rows (label/bold value pairs) + 真实性承诺 checkbox → 提交审核 → `show('status')`. 保存草稿 on step 1.
  - **Country-scoped document requirements (USER-CORRECTED 2026-08: \\\"每个国家的营业执照,证件这些,需要提交的东西不一样呀,帮我完善这里,要相互对应\\\")**: picking a different 注册国家 must re-spec the whole document package. One `ONB_DOC` map keyed by country name drives it (`onbCountry(sel)` on the select's `change`): ① 上传区 label + button text + format hint (中国=营业执照 / 中国香港=商业登记证(BR) / 新加坡=ACRA 注册证书 / 美国=营业执照·EIN 证明 / 英国=Companies House 注册证书 / 日本=登記事項証明書 / 德国=Handelsregister 摘录 / 法国=Kbis 证明 / 澳大利亚=ABN 注册证书 / 加拿大=营业执照·CRA 编号 / 阿联酋=贸易许可证(Trade License) / 其他=公司注册证明) ② 编号 field label + placeholder sample (中国=统一社会信用代码 91440300MA5… / 香港=商业登记证号 71234567-000 / 美国=EIN 税号 12-3456789 / 新加坡=UEN 202101234G / 德国=HRB 123456 / 阿联酋=许可证号 CN-123456 …) ③ **执照到期日 visibility: countries with indefinite-validity documents (中国/新加坡/美国/英国/德国/法国/澳/加/其他) hide the expiry input and auto-check 长期有效; 香港/日本/阿联酋 show the expiry field** ④ 法人证件类型 label (中国=法人身份证 / 美国=驾照·护照 / 日本=个人番号卡·护照 / 阿联酋=护照+签证 …) ⑤ 签发国 select auto-syncs to the chosen 注册国家. Wire ids: `onbDocLabel/onbDocName/onbDocNote/onbNoLabel/onbNoPh/onbExpBox/onbForever/onbLegalLabel/onbCountry2`. Include a hint line under the country select (\\\"证照类型与字段将按注册国家自动匹配\\\").
  - **Country list ordering + default-country consistency (2026-08)**: the country dropdown is sorted by ENGLISH name (澳大利亚 Australia → 加拿大 Canada → 法国 France → 德国 Germany → 中国香港 Hong Kong → 日本 Japan → 新加坡 Singapore → 阿联酋 UAE → 英国 UK → 美国 US → 其他 Other) — user asked for A→Z once a global market list existed. The DEFAULT option gets the `selected` attribute (user flips it: 中国香港 → then 美国), and the hard-coded initial field values in the step-1 HTML must match that default country's ONB_DOC entry (证照 label/上传文案/EIN 或 BR 编号/主体名称/地址/到期日显隐/长期勾选/法人证件/签发国) — `onbCountry()` only fires on `change`, so first-load consistency is HTML's job, not JS's. Demo data (主体名称/地址/证照号) also appears in the step-4 确认提交 review cards — update those rows when the default country changes. Note the country list itself is business data that the user edits freely (删中国、默认美国) — keep the mechanism generic, treat the member list as user-controlled.
