# 令牌/凭据消费方映射

手里有一枚 accessToken / JWT / accessKey（来自登录响应、日志索引、客户端 bundle、审计日志），
在宣布「这枚令牌没用」之前，先把「谁认它、给什么权限」画成地图。
**多数高权令牌不是没用，是消费方不在公网。**

## 0. 先固定令牌身份

- 只做 base64 解码 payload，读出 `scope` / `grand_type` / `role` / `uid` / `exp`，不解密、不外发。
- 记录签发端（host:port + 路由）—— 它是后面所有对照实验的基线。
- 不同服务可能共用同一签名密钥，但**共用密钥 ≠ 共用 scope**，必须逐服务验证。

## 1. 状态码三角定位（核心方法）

同一枚真令牌打每个候选端点，读回包，状态码本身就是证据：

| 响应 | 含义 | 动作 |
|---|---|---|
| `403` / `{"code":403}` | 签名有效、**scope/角色不符** | 换 scope 或换该服务的用户态令牌；**别换端点** |
| `400` / `{"code":400}` | 签名或格式无效 | 该服务确实验签；伪造路线掐掉 |
| `410` / `invalid token` | 不是该协议/会话类型的令牌 | 该服务只认业务会话，不是管理令牌 |
| `404` | 路由或模块不存在 | 换路由名，不是换令牌 |
| `200` | 该端点接收此令牌 | 立刻只读验证自作用域，再测跨 tenant/跨 uid |

**对照实验是判定的前提。** 真令牌拿到 403 之后，必须再用 `alg:none`、空密钥、厂商名密钥各伪造一次：

- 伪造件 → `400`：验签在，只是 scope 不够 ⇒ 换 scope。
- 伪造件 → `200`/`403`：**根本没验签** ⇒ 改 claims 提权。这是洞，不是噪音。

## 2. 消费方枚举顺序

1. 签发端自身（`/`、`/api`、`/ws`、`/socket.io`）—— 常只有 `/login`，其余全 404。
2. 同族 HTTP 后端（H5 / APP / 网关 / 支付）—— 载体要全试：header `access-token` / `Authorization: Bearer` / `token` / cookie，**以及查询串 `?token=` / `?access_token=` / `?apiToken=`**（FastAdmin 类 PHP 后端只认查询串），每个只试一次。
3. WebSocket 网关（pomelo / socket.io）—— 管理令牌通常被拒（410/500），只有玩家/业务令牌进得去。
4. 管理控制台（独立会话，401「请登录后操作」）—— 与业务令牌体系常常完全隔离。
5. **内网管理口**（master / admin port）—— 以上全灭时消费方大概率在这里，且只监听 `127.0.0.1` 或内网 IP。

## 2.5 批量令牌：先离线筛，再一次一枚

- 日志/埋点索引（`userlogger` 类）常把完整 JWT 存在 `context.token`。用 `filter_path` 只取该字段，**按字节分页**：GET 转接链路在 32–88KB 处截断，**整页 JSON 解析失败就减半 `size`**（解析失败 = 截断，不是空页）。
- 抽出后本地解 `exp` 去重，并按 `from`/`grand_type` 分层：`virtual` = 游客自建号，价值低，不要混进“真实用户接管”的结论。
- 只对 1–3 枚未过期样本做线上验证；成批重放既烧请求又不产生新证据。旧构建的 token 会整批 `400`/`410`（签名轮换），判死后不要换构建重试。

## 3. 管理面动作集从审计日志挖，不要猜

审计/操作日志索引通常是明文的。只读地按 `moduleId` / `method` / `msg.action` / `msg.signal` 分组，
就是全量管理动作清单（terms 聚合 + 少量样本，**不重放日志里记录的参数**）。

判定规则：

- 清单里有 `query` / `search` / `list` / `export` → 找参数，走只读导出。
- 清单里只有写动作（发币 / 改模板 / 停服 / 重载）→ **该面板从设计上不具备导库能力**。
  立刻停止在这条线上找导出：问题不是「后台登不进去」，是功能不存在。
- 动作名是唯一常量，**禁止模糊匹配**：`update*` / `set*` 里混着资金写路由，误发一次就是真实破坏。

## 4. 封线判据（何时换方向）

三条同时满足就判死，转去打凭据（SSH / CI / 配置文件 / 备份）：

1. 令牌在所有可达端点都被拒，或只给自作用域；
2. 管理模块只挂内网端口，网关路由表里没有任何 `__` / admin 模块；
3. 没有能从外部执行命令的原语（SSRF 只能 HTTP，不能 raw TCP）。

**封线后的转向要换维度，不是重扫同一面。** 每个 origin 跑一次 1-65535 全端口
（`masscan -p0-65535 --rate 6000` + `nmap -sV` 复核）、证书 SAN、二级域 `crt.sh`、新 vhost，各给一次机会。
「业务端口段扫过」≠「扫过」—— SSH 往往就藏在这条缝里，而一个口令就是整台机。

## 坑

- **只测一个 header 名就下结论**：同一后端可能只认 `access-token`，别的名字全 404，看起来像「路由不存在」。
- **把 403 当成令牌无效**：403 是「认你但不够格」，跟 400 结论完全相反。
- **把「登录接口免密」当成能直接拿数据**：签发端免密只说明认证坏了；数据在消费方，仍要过消费方的 scope。
- **给只认 username 的签发口补 password 字段**：原本 200 的口补上 `password` 反而回 400，说明 schema 只收 username——这不是「缺口令」，是「签发端根本没有认证」。
- **拿令牌去打写路由验证**：验证作用域只用只读路由；发币/转账/改配置即使成功也破坏证据。
- **版本范围只读标题**：CVE 影响范围要核对 LTS 回溯版本，主线「≤x.441」不代表 LTS 的 x.440.z 也中招，
  否则会把已修补实例当目标烧掉一整轮。

## 纪律

只读验证；令牌值一律不外发；写路由一律不碰；一旦误发写请求，立即停机并如实记录发给了谁、发了什么、何时。
