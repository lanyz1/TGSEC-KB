# 源码有拼接注入,但打不通:三方法判定协议

配套 `vcs-repo-exposure` §4(「源码到手后:先验注入真假」)。

## 何时用

源码里明明写着字符串拼接:

```php
$id = I('kw_sign_id', '', 'trim');
D('User_temp')->where("sign='{$id}'")->find();
```

但无论怎么打都「没反应」(响应恒定 / 无差异)。**此时最危险的动作是凭源码推断
「它一定能注入」或「它一定被拦了」—— 实测过,读源码反推过滤器语义会推错。**

> 实证:因为看到 `I($name,$default,$filter)` 的第三参数传了 `'trim'`,
> 就推断「显式 filter 覆盖了默认的 `htmlspecialchars`,所以引号能过」——
> **推断错了。** 后来用下面三种方法实测,三种全否。
> **结论:源码只用来提出假设,判定一律交给实验。**

---

## 协议:三种独立方法(全做,不做单点结论)

### 方法 A —— 普通引号 + 时间盲注差分

```
payload: <随机串>' OR (SLEEP(3)+1)-- -
对照:    <随机串>
```

`SLEEP()` 在 **SQL 执行阶段**触发,发生在应用层任何「查询后校验 / die()」之前,
所以**理论上即使应用随后 die 了,时间差也会漏出来** —— 这是它比布尔盲注更通用的原因。

⚠️ **空表假阴性(最容易踩的坑)**:
查询形如 `... WHERE sign='...' LIMIT 1`。若**表里没有行**,MySQL 不扫描任何行,
`SLEEP()` **根本不会被求值** ⇒ **即使注入完全成立,也测不出时间差。**
> 所以:**方法 A 的「无差异」不能单独作为否定结论。** 必须用方法 C 消歧。

### 方法 B —— GBK 宽字节(一枪,验另一种假设)

```
payload: %bf%27 OR (SLEEP(3)+1)-- -
```

作用:区分「转义是 `htmlspecialchars`」还是「转义是 `addslashes` + GBK 连接字符集」。
后者的经典形态:`'` → `\'`,而 `%bf` 会**吃掉那个反斜杠**(`\xbf\x5c` 合成一个宽字符),
引号照样逃逸。

- 只需**一枪**。无差异 ⇒ 排除 addslashes+GBK 这条假设,**不要**再试其他编码变形。
- 注意构造:`+` 在 query string 里是空格,算术里的加号要写 `%2b`。

### 方法 C —— UNION 全列对齐(可消歧的决定性实验)

**思路**:让注入产生的行**通过应用层那道查询后的校验**,从而得到「响应变非空」这个正向信号。

典型形态(应用在查询后校验某一列,再决定 die 还是继续):

```php
$userinfo = D('User_temp')->where("sign='{$id}'")->find();
if(!strstr($userinfo['domain'], $arr_kw_url['host'])) die;   // 唯一的可观测点
```

难点:不知道列数,也不知道 `domain` 在第几列。

**解法:把 UNION 的每一列都设成同一个「能满足校验的字符串」,这样列位置就无关了。**

```
kw_sign_id=-1' UNION SELECT '<满足校验的串>','<同一个>',...,'<同一个>'-- -
                 ↑ N 列,全部同一个值
```

- 从 **N=1 扫到 20**,任一列数正确 ⇒ 注入产生的行会**通过**校验 ⇒ 响应由「恒定空(die)」**变成非空**。
- 信号干净:全空 = 注入不成立;某列数出现非空 = **注入成立 + 同时得到列数**。
- 实测形态:`UNION SELECT` 1–20 列、每列填同一域名串,响应**恒为空** ⇒ 引号确实到不了 SQL。

> 方法 C 的价值:**它不像时间盲注那样受「表为空」影响**(UNION 不需要原表有行),
> 所以它能给方法 A 的「无差异」下最终判定。

---

## 判定表

| A 计时 | B GBK | C UNION 全列 | 结论 |
|---|---|---|---|
| 有差异 | — | — | **注入成立**,按常规盲注推进 |
| 无差异 | 无差异 | 出现了非空响应 | 注入成立且**列数已知**(A 是被空表骗了) |
| 无差异 | 无差异 | 1–20 全空 | **注入不成立**(引号在入 SQL 前被过滤),止损 |
| 无差异 | 有差异 | — | 转义是 `addslashes` + GBK 连接集,按宽字节路线继续 |

**三种独立方法得出同一个否定结论 = 严谨的否定**,可以写进报告。
**只做一种就下结论 = 不可靠**,尤其是只做方法 A。

---

## 行为纪律

1. **不要在同一参数上反复换注释符**(`#` / `-- -` / `/**/`)刷轮次,那不是实验,是碰运气。
2. **不要因为「源码看起来能注入」就去调整结论**;也不要因为一次实验失败就换参数重来
   十几次 —— 三种方法各自一次,做完全部就定论。
3. **每个「不成立」的结论都要能说出实验形态**(什么 payload、什么对照、什么响应),
   否则报告里写「已测试」会被质疑,也不算真做过。
4. **固定的可观测点是设计的核心**:先找出应用在查询之后**唯一**会改变响应的地方
   (通常是某个 `die` / 某个 if 分支),再围绕它设计 payload。
   如果没有可观测点,就先造一个(见方法 C 的「让校验通过」)。
