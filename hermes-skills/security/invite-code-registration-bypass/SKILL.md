# 邀请码门：无凭据注册 → 用户数据面

适用：注册页强制填邀请码 / 推广码 / `spread` / `code`，且你没有账号。
典型载体：中国资金盘（民族资产解冻、共同富裕、国家追缴）、会员制分销盘、白标博彩/卡商、SaaS 分销后台。

**先做一次算术再决定打不打**——邀请码枚举的收益比爆破登录高一个数量级，但只在满足前提时成立。

**定位：这是「换面」工具，不是主线终点。** 当主后台被口令锁拖成几周的等待战（5 次/30 分钟那条路），同品牌家族里的**兄弟盘**往往还开着注册面——用邀请码进去拿一个**独立实例的 token**，就能在等待期里继续摸资产面/接口面。同一运方、不同产品名、不同域名、不同库。实测：主站后台锁死后，从 Expo/RN 包体挖出的注册接口 + 6 位邀请码，15 分钟内拿到兄弟盘活 token。

## 0. 判定（30 秒）

看注册请求，逐项确认：

1. 邀请码是否**纯数字及固定位数**（6 位最常见）。
2. 是否挂图形/滑块验证码（挂 → 先按 `captcha-ocr` 解）。图码三招：ddddocr 结果先 `.upper()` 归一（纯大写字母图常返小写，4 位全对也报「验证码错误」）；`len(code) != 期望位数` 就换图重取，别硬提交（错一次可能计入锁定）；**别开 `probability=True`**（会把整个概率矩阵打出来，实测刷屏百万字符直接打爆上下文）。
3. 是否**按手机号/设备/IP 频控**（发 3 次无效码，观察是否开始返 429 / 「操作过于频繁」/ 封 IP）。
4. 是否需要短信验证码（需要 → 走 `temp-email-verification-codes` 或换目标，别硬发）。

**命中率公式**：`p ≈ 用户数 / 码空间`。
6 位码空间 90 万：3.6 万用户 → 4%（≈25 次）；100 万用户 → 100%（必有重叠）。
**用户越多的盘越好进**，这跟直觉相反，先算再打。

### 码是顺序发的 —— 先取一个公开码当「用户数时钟」

这族平台的邀请码几乎都是**从固定起点递增发放**（常见 `100000` / `1000000`），不是随机。
所以：**任意一个真实码 − 起点 ≈ 当前用户数**，而当前有效码就密集落在 `起点 + 用户数` 附近几百个里。

1. 找一个真实码：分享/排行/`public-wins`/邀请页/落地页 JS/客服话术里通常都有明文。
2. `用户数 ≈ 码值 − 起点`（6 位码 147015 → 起点 100000 → 约 4.7 万用户）。
3. **只扫 `[码值−200, 码值+200]` 这个窗口**，不要扫 900,000 全空间。实测 `945150–945200` 窗口 51 发命中 1 个。

不知道起点时：先随机取 20 个码看回包，全部「不存在」且数值远低于任何已知码 ⇒ 起点更高，先把已知码向下二分找边界，再定窗口。

### 先用必填顺序做免费 oracle，再花邀请码

注册接口的字段校验是**串行**的，缺哪个回哪个错——这是零成本的字段字典：

```
缺 phone        -> 手机号不能为空
缺 loginPwd     -> 密码不能为空
缺 payPwd       -> 支付密码不能为空        # 资金盘特有
缺 captcha      -> 20006 请先完成滑动验证
缺/错 invite    -> 10007 / 邀请码不存在
全通            -> 200 + 直接回 token
```

**先发一个只带手机号的请求**，按回包逐层补齐，确认到「只差邀请码」再开扫——避免带着错字段白烧 50 个码。
另：**同产品的不同端校验面不一样**。H5 端要滑块（`20006`），同产品 Expo/RN 的 API 主机同接口**不要滑块**——优先打 App 侧接口。

### IP 注册限额是「第二道免费 oracle」，也是三头一行能解的闸

`IP_REGISTER_FAIL`（`IP已被限制注册`）这类**注册频控报文排在校验链的最后**：

```
验证码 -> 邀请码是否存在 -> 注册IP限额 -> 建成
```

后果有两个，都要用上：

1. **它本身是「邀请码正确」的铁证**。同一发请求，随机码回「邀请码不存在」，已知真码回 `IP_REGISTER_FAIL` ⇒ 码对、只是被 IP 拦了。**看到这条错误别以为码错了去换码**，那是在错误方向上烧探针。
2. **三头同发即可绕过**。只发一个 `X-Forwarded-For` 常被忽略；**三个头同时发**才生效：

```
X-Forwarded-For: <随机公网IP>
X-Real-IP:       <同一或另一个随机公网IP>
True-Client-IP:  <同上>
```

实测：6 位数字码那系在注册被全站 `IP_REGISTER_FAIL` 封死后，三头同发立刻回 `200 + token`，同一 TCP 源、同一个码。**注册频控按头信任，不按 TCP 源。**

排查纪律：注册连续失败时**先用一个已知有效的码打一发**。若回的是频控/限额类报文，说明整条链路一直是通的，问题在出口被判重——别再去改密码编码、confirmPassword、换码段。这条错误曾让整轮注册战卡了几十发探针。

## 1. 扫描器

`scripts/invite_scan.py`——参数化、三态判读、命中即停。

关键设计（每条都是踩出来的）：

- **三态 oracle**：`格式错误` / `不存在` / `成功`。只有「不存在」类文案才继续下一个码；任何未知文案立刻停手重读报文（可能是风控提示）。
- **手机号必须真 11 位**：`printf '%08d'` 生成后 8 位，别用 `$RANDOM*$RANDOM%N`（会拼出 8 位号，白扫一轮）。失败不消耗号，命中即停。
- **并发 8–16 线程**足够：实测 12 线程 19.5 req/s；再高先看是否触发频控。
- **命中即停**：拿到号立刻 `POST /auth/login` 验证能登录，再谈别的。
- 若注册接口回 token（很多资金盘直接回），省掉登录这一步。

## 2. 拿号之后立刻做的三件事

1. **抽真实路由**：别猜接口名（猜的大半 404）。从 H5/SPA 分片里抽——`grep -rhoE '/app/[A-Za-z0-9/_-]+' chunks/*.js`，或按 `api-contract-mining` / `spa-js-api-mapping` 走。
2. **全路由带 token 打一遍**，落盘原始响应（`all.json`），再按体积/条数排序找「像名单」的。
3. **按 ROI 排序读**：`home-config` / `auth-config`（未授权即可读，出客服域名、app_key、S3 桶、下载链）→ 各类 `records|list|members|rank|page|orders` → 业务写接口。

**名单越权高发点**：`/app/hdXX/records`（资金盘剧本模块）实测普通用户 token 就回 1,000 条**他人真实姓名 + 身份证后四位**，id 连号、无分页、服务端 `LIMIT 1000`。
通用形态：`<module>/records`、`<module>/list`、`export`。注册后第一件事就是把所有模块前缀 × 这些后缀全扫。

## 3. 一品牌一实例集群（同代码多部署）

一品牌一库一域名组是这族的常态，从任一实例可扩到全家族：

```
APK/前端配置 JSON → 主域
  ├─ hackertarget hostsearch(<根域>)  ← 免费无 key，一次吐十几个子域，前缀即品牌
  ├─ 各子域 /api/health = {"ok":true} → 同码确认
  └─ S3 桶 <brand>mini：ListBucket 关但 GetObject 公开
        └─ <brand>.json → 该品牌全部后端域名（换根域再跑一轮）
```

- **IP 封禁是按域名/实例的**：主域被 WAF 全灭 ≠ 兄弟域全灭。**被封先枚举兄弟域，别急着换出口/上代理**（实测代理池 160 条全死、Tor 无效，而兄弟域裸连就通）。
- S3 猜键样板 = APK 里引用的那个 JSON 名（`<品牌>.json` / `config.json` / `version.json`）。
- 邀请码**不跨实例通用**，每家重扫一遍（每家 5 秒级）。
- **码制可能逐家不同，别用一套探针扫全族**：同一运营方下，A 家是 6 位纯数字（密度高、可扫），B 家是 6 位字母数字、C 家是 10 位字母数字 —— 纯数字探针对 B/C 只能撞到历史遗留的数字码用户，**命中率掉到 0.4% 以下，看起来像「这家没用户」，实际是探针形状不对**。先看注册页/JS 里码的格式与长度，再决定探针。
- 舰队扫全族时给每台加**验证码连败熔断**（如连败 40 次放弃该主机），否则一台解析不了的主机会吃掉整轮配额。
- 模块也不同：某家 `hd13` 有数据、另一家 404 ⇒ 用各家自己分片抽的路由表逐实例重扫。

## 4. 停手边界（别浪费时间）

- **后台 2FA 是硬墙**：`googleCode` / TOTP 在口令**之后**校验 ⇒ 没有口令就没有 TOTP 面，先别想爆码。
- `请输入谷歌验证码` 这类文案是**全局前置校验**，对不存在的用户名同样返回 ⇒ **不是账号存在性 oracle**（曾据此误判）。
- 锁定的维度是**按目标而定的，必须实测**：同一族里既有「只按账号、XFF/`X-Real-IP`/`True-Client-IP`/`CF-Connecting-IP` 全无效」的部署，也有「IP 锁完全信 `X-Forwarded-For`、随便编个值就绕」的部署（实测：不带 XFF 回 `430 当前IP已被临时锁定`，带 `X-Forwarded-For: 8.8.8.8` 同一请求回 `10002`）。**别把任一侧当通例**，用两种方式各打一发看报文。测法见 `login-lockout-profiling`。
- 反复试探会升级成**实例级 IP 封禁**（`该IP已被封禁`）⇒ 登录面一次只打 1–2 发，别整排扫。
- `/api/admin/init|setup|register|bootstrap` 实测全 404，无初始化后门。
- 上传目录公开但 autoindex 关闭 + 文件名纳秒时间戳 ⇒ 不可枚举，别在这条路上磨。

到此为止的话，交付口径：**注册无凭据 = 认证缺陷；名单越权 = 他人用户数据；后台 2FA 未破 = 阻断项，不得写成接管。**
全量用户表要后台凭据或 TOTP 密钥 → 转社工线（客服会话里套运营账号，见 `autonomous-social-engagement`）。

## 5. 坑

- **假 token 爆不出密钥**：hashcat 无命中先验 token 完整性（是不是被 `head -c` 截断过）。
- **`curl_cffi` 可能被指纹拦而普通 `curl` 通**：探测不通用 bash/curl 复测一遍再下结论。
- **WAF 拦截页会伪造 HTTP 200**：按 body 判，不看 status。
- **长输出必被吞**：所有批量探测 `> file` 落盘再 grep，别直接看 stdout。
- **凭据只进案卷账号档**：测试账号口令写 `cases/<案卷>/accounts`，不进 skill、不进总结。
- **验证码应答有两种格式，解析必须双兼容**：一种套信封（`{"data": "<base64>"}` 里再解出 `{code,img}`），另一种是**顶层明文 JSON**（`{"code":..,"img":"base64.."}`，同代码基的另一条产品线）。只认信封时，明文那家会**每次都 `CAPTCHA_FAIL`，连败到熔断被误判成「打不动」**——实测因此白丢一家首页 241KB 的活租户。判据：captcha 响应能不能直接 `json.loads` 出 `img`/`code` 键。
- **注册回的 token 和「能登录」是两件事**：注册与登录常用**不同的 AES key** 加密口令 ⇒ 注册记账时存成乱码，随后 `LOGIN_PASSWORD_ERROR`。**别因为登不上就把注册拿到的 token 丢掉**，它照常有效（实测 7 天）。
- **新号 `isEffect=false` 会挡住数据面**：token 有效、接口 200，但列表/订单回 `UNKNOWN_IDENTITY`。`UNKNOWN_IDENTITY`（身份未激活/不在该库）与 `RECORD_NOT_FOUND`（记录不存在）**语义不同，别混判**——前者可能意味着数据在、只是号没激活；后者可以用来量表的边界。
- **表的硬上界用连号采样量，不用猜**：从 1 递增打到开始回 `RECORD_NOT_FOUND`，最后一个 200 的 id 就是行数上限（实测 2182 有效 / 2183 起空）。稀疏表先等距大步长探有没有记录，再回填。
- **脱敏是按表写死的**：同一 uid 在 A 接口是 `代*珍`、在 B 接口是 `代秀珍`，别急着高兴——先做变体矩阵（platform/version/vendor/UA/App 头，68 组）全部打一遍；**全同 ⇒ 服务端按表脱敏，换参数无解**，直接放弃这条面去换数据源（订单/导出/明细表），别在参数上磨。
