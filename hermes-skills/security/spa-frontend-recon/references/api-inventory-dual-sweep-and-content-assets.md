# 全量接口清单 → 未授权/授权双扫 → 数据与内容资产收割(2026-09 灰豚数据实战)

> 适用:**SPA/多端产品的 API 是"全局登录过滤器 + 白名单"模型**时,把前端包里的**全部**路径拉出来
> 逐条双扫,把"未授权可读面"和"可从 API 响应里拿到的对象存储直链"一次摸清。
> 本页是通用流水线;配套可复用脚本见 `scripts/harvest_unauth_surface.py`。

---

## 1. 为什么要"全量双扫",而不是挑着打

灰豚(Java/Spring)把**所有非白名单路径统一化**:未登录时任意路径都返回同一个 79 字节
`{"code":-200,"message":"登录状态已失效，请重新登录!","status":200}`。

后果有两个:

1. **单点探测毫无信息量** —— `/actuator`、`/swagger-ui.html`、`/.env` 看起来都"存在(200)",其实全是被过滤器兜住的同一响应。**必须带会话复测**才能区分"存在/不存在"(带会话后它们全变 404)。
2. **只有全量清单才能反推白名单** —— 拿 1,340 条路径跑一遍,凡是不回那 79 字节的,就是**白名单里的未授权面**。

**判据表(按响应签名分类,不看状态码)**:

| 响应签名 | 含义 |
|---|---|
| `{"code":-200,"message":"登录状态已失效…"}`(字节数固定,如 79) | 被登录过滤器拦 → **不是攻击面** |
| `{"status":200,"message":"系统异常","code":500}`(167 字节) | **已过过滤器进控制器**,只是缺参数 → **是攻击面**,去凑参数 |
| 明文/加密真实数据 | ★ 未授权数据面 |
| Spring 默认 404(带 `timestamp/status/error/path`) | 该控制器不存在 |
| 200 + 空体 | 空壳接口(见 §5) |

## 2. 清单从哪来(多入口都要拉)

| 来源 | 本次量级 |
|---|---|
| PC 端主包 `umi.<hash>.js` | **1,340** 路径 |
| 路由级异步 chunk(`<id>.<hash>.async.js`) | 页面级参数与字段名 |
| **APP/H5 包**(`/phone/static/js/main.<hash>.chunk.js`) | **174** 路径 |
| 兄弟产品各自的前端包(鲸投/小天订单/小天分销) | 420 / 92 / 275 |

**关键发现:APP 包的未授权白名单比 PC 端更松。** 在同一次双扫里,APP 包独有 3 个**未授权**接口:
`/common/dyCid`(**1.16 MB 抖音完整类目树**)、`/common/mobile`(APP 配置/版本/更新日志)、
`/common/festivalList`(大促日历)。
⇒ **PC 端扫完不等于扫完,凡是有独立包的端(H5/APP/小程序/代理后台)都要再拉一次清单重扫。**

**webpack chunk 哈希表的坑(务必注意)**:UMI 的包里有**两张 162 条的 `{id:"hash"}` 映射表**
(一张是 JS chunk,一张是 CSS)。用错那张会得到 **477 字节的 `NoSuchKey` XML**,
看起来像"chunk 不存在"。**校验方法**:先用一个已知能下到的 chunk(如 `36.b1af90f8.async.js`)
验证所选映射表里的对应项,**表选对了再批量下**。

## 3. 双扫怎么做(可脚本化)

```python
# 每个路径两次:不带 cookie / 带 cookie;1.1~1.3s 间隔(见 §6 限流)
for p in paths:
    for auth in (False, True):
        body = curl(D + p, with_cookie=auth)
        sig  = classify(body)          # 用 §1 的判据表
        if sig.real_data: record(sig)  # 只记录"有数据"的
```

- 命中是**稀疏**的:1,340 条里未授权有数据的约 30 条 → 别指望比例高。
- 加密响应要**先解密再判断有没有数据**:`encrypt:true` 的 `data` 是 base64 密文,不解开就只会看到一串乱码、
  误判成"没数据"。本次 22 个未授权接口里,加密的占多数。
- 分页参数不要无限 fuzz:见 §4。

## 4. 「服务端固定分页」的识别(什么时候该收手)

列表接口出现 `total=10001` 却只回 20 条时,先按顺序试参数名:
`page / pageNum / pageNo / pageIndex / current / currentPage / start / offset / begin / pn / p / pageSize / limit / rows / size`。

**判据**:
- 换了 **20 种参数名,返回的"首条记录 + 条数"完全不变** ⇒ **服务端写死的固定推荐集**,不是参数名没猜对。
  此时继续 fuzz 是浪费,**应写成"导出天花板"结论**:该接口只给固定 N 条。
- 只有**首条变了 / 条数变了**才算分页生效。

本次实战:达人榜 `?page=2` 等 9 种、报告列表 20 种,全部返回同一批 ⇒ 判定固定集;
反而是**同接口的分类参数**(`?reportType=1` / `=2`)给出了**不同批次**(total 21 / 14),
据此把可枚举资产从 10 份扩到 **20 份**。⇒ **参数 fuzz 优先试"分类/过滤"参数,而不是只试分页参数。**

## 5. 空壳接口与"看起来存在"的接口

- 带会话后一批路径返回 **200 + 空体**(如 `/report/task/*` 十个端点)⇒ **形同空壳**,无可控输入面,写进"已测无面"。
- 兄弟域返回 **Spring 兜底 JSON `{"appId":"199852179"}`** ⇒ 该路径**不存在**,是 catch-all,别当接口。
- 同一密文常量反复出现(如 `"dmb44wme81TgUfiq/Y38aw=="`,解开是 `[]`)⇒ 那是服务端的**"空结果"占位密文**,
  不是敏感数据,别误报。

## 6. 内容资产:API 响应里的对象存储直链(最容易漏的一环)

**凡响应里出现对象存储 URL(`*.cos.*.myqcloud.com` / `*.oss-*.aliyuncs.com` / `storage.googleapis.com`),
立刻不带 cookie 直接 GET 一次** —— 很多平台的直链**不做签名、不校验 Referer**。

本次:`/work/reportStudy` 的明文响应里带 `pdfReport` 字段 →
**20 份付费行业研究报告 PDF 全部 200 `application/pdf`(`%PDF-` 魔数),合计 184.9 MB**,未登录即可下载。
判定动作:**HEAD 全量拿 `Content-Length` 汇总体量 → 抽最小一份做 PoV → 写进交付物**。

> 这一环常被忽略,因为注意力都在 JSON 数据上;但"**内容资产(报告/白皮书/导出文件)本身就是要卖钱的东西**",
> 在变现分析里往往比字段级数据更直接。

## 7. 收割器应有的形态(只读 + 可重跑)

- 只做 **GET**;不提交写操作、不上传、不修改数据。
- **不带 cookie**(以证明"未授权");加密响应解密后落 `.dec` 文件,**保留 `.raw` 原样**做证据。
- 内置**限速**(1.3s)与**限流识别**(见 §8);输出 `INVENTORY.txt` + `REPORTS.tsv`(资产/体量/条数/字段)。
- 可复用实现见 `scripts/harvest_unauth_surface.py`(纯标准库 + openssl,零第三方依赖)。

## 8. 限流(账号级)与处置

高频扫描会让平台进入**账号级限流**:`{"code":-100102,"message":"请求过于频繁，已被限制访问,请完成验证",
"roleId":2,"nextRole":0}`(注意:这个响应还顺手泄露了当前档位)。

- **看到 `-100102` 立刻停手**、冷却后再来,不要在限流窗口里继续打。
- 扫描计划按 **1.1–1.3s/请求** 设计;长扫放后台(setsid nohup),进度写文件再轮询。
- **监控类脚本必须区分"限流"与"会话失效"**:把 `-100102` 单独识别为 RATELIMIT 并静默,
  否则哨兵会把限流误报成"掉登录",给用户制造假警报。
