# 运营方归属判定与自有基建溯源(跨域 · 跨账号)

**定位**:回答三个同源问题 ——「这些域是不是同一个运营方的?」「这个站的运营方到底是谁?」
「运营方自己的服务器/管理后台在哪?」。这三问在同一个现场里往往只需要走一遍流程。

**触发**:主体归属 / 同一主体 / 是不是同一个站群 / 运营方是谁 / 管理后台在哪 / CF NS 关联 /
供应商还是运营方 / 源码商 / 旁站归属 / 白标多品牌是否同源 / 公网域面打尽了要换线。

**适用边界**:目标公网域面已探尽(子域枚举 + CT + 被动/历史 DNS + IP 反查 + 证书全负),
或白标/SaaS 站只有「客户端 + 一个 API 域」看不出运维面时。
本卡做到**归属定性 + 入口定位**;拿到入口后的利用交对应打法卡。

## 铁律(先读)

1. **只读**。TG 侧只用 `GetFullUserRequest` / `GetFullChannelRequest` / `GetParticipantsRequest`;
   **不发消息、不加入、不建群、不点按钮** —— 运营方账号侧的任何互动都是即时暴露作业的足迹。
2. **归属结论必须有可复现证据**:NS 对逐字符一致 / 同一仓库被引用 / 同一前端 bundle。
   不接受「文案像」「名字像」「同一个 CDN 段 IP」—— 后者对 CF 站点毫无区分度。
3. **定性翻转必须写进报告**。把某主体从「第三方供应商」翻成「运营方本体」后,
   要显式写「翻转 + 三条相互独立证据」;否则读者沿用旧定性,要么继续把目标域当无关资产,要么打错对象。
4. **不为打通而降低纪律**。拿到运营方自建管理端后不提交凭据、不爆破、不调写接口。
   自建反扫描欺骗层(假登录页 + `/gotcha.html` 之类 whoami 采集)**是这类运营方的标配**,
   报告价值在证据链,不在拿到会话。
5. **结论带时间窗**。同一 URL 同形态请求跨时间窗可能是两条结果 —— 归属类结论必须带时间戳与复现窗口。

## 流程(按序执行,每步产出均可直接进报告)

### S1 先翻案卷,再上网
先抽干已落盘材料里的**主体线索**,再花流量:
客服号 / 公告落款 / 业务办理 @xx / 群管理员 / 官方频道帖 / 历史 dump(`*_posts.txt`、`shop*.log`、`tg/` 目录)。
- 常见情形:关键证据**早就在案卷里**,只是被当成「第三方样本」没读 —— 源码仓库地址、演示域、联系人常写在产品公告帖里。
- 线索先被动核实归属(WHOIS / crt.sh):配置里的域名常是历史残留或第三方停放,非同主体勿并案。
- crt.sh 502/超时时的替代 CT 源：certspotter(免 key)：`curl -sL 'https://api.certspotter.com/v1/issuances?domain=<域>&include_subdomains=true&expand=dns_names' | jq -r '.[].dns_names[]' | sort -u`——能挖到当前 DNS 里不存在的历史/新签发子域(app/player/tv/star 一类)，按「活面或历史基建」跟进。

### S2 运营方 TG 身份 → 产品目录
1. 取运营方账号(客服号/落款账号),只读 `GetFullUserRequest` 读 **bio**。
2. bio 里的 `@频道/@群` 推荐表 = 运营方的**产品目录**(多品牌/多业务线)。
3. 同时只读频道 about + `GetParticipantsRequest(ChannelParticipantsAdmins)` ⇒ 运营方的多账号矩阵。
- 无 API/无会话时兜底:`t.me/s/<channel>` 网页版可读**最近帖子**,免登录免 API。

### S3 产品频道帖挖掘(最高产出的一步)
逐帖翻运营方产品频道,专找四样东西:**开源仓库地址 / 演示地址 / 询价 @联系人 / 演示 BOT**。
公告帖的典型形态是「产品名 + 正式开源 + 仓库地址 + 联系 @xx」—— 这一行同时给出**源码归属 + 真人身份**。

### S4 源码归属 = 主体归属(定性翻转)
判据:**目标站跑的系统是否正是该账号发布的?**
- 是 ⇒ 该账号 = 运营方本体(**不是**第三方供应商);其自有域(产品域/演示域/管理域)**全部纳入同一目标**,
  不再按「供应商资产禁探测」处理。
- 不确定 ⇒ 宁可保持「疑似」并标注缺哪条证据,**不要**直接翻转写进结论。

### S4b GitHub fork 链 = 协同者身份与自建服务候选
运营方账号常以 fork 为主；**fork 之上的私改提交作者 = 其身边的协同者/开发者**，是主体链的第二节点：
1. `gh api repos/<owner>/<repo> --jq .parent.full_name` 取上游仓库名；克隆后 `git remote add up https://github.com/<parent>`。
2. `git fetch --unshallow up`（**浅克隆/浅 fetch 会把差异藏掉**）→ `git log origin/main --not up/main --format='%h|%an|%ae|%ad|%s'` 列 fork 独有提交；作者姓名/邮箱即对账锚点（与发布页邮箱、官方频道号交叉）。
3. 读推送时间线区分性质：`pushed_at` 与上游同日 = 纯跟随同步；fork 后仍有独立推送 = **真实协同/自用**，值得继续挖。
4. fork 集本身 = **自建服务候选清单**：父项目是可自托管工具（分析台/代理/解析类）时，按其默认部署子域形态回探运营方域面。

### S5 品牌 token 反用 → 定位管理后台
1. 从仓库 org / 产品名抽品牌串(形如 `TG<brand>` → `<brand>`)。
2. 用该串核运营方自有域:子域词表 + **只读 GET 标题**。
3. 管理端常直接写在标题里(形态:`<title><brand>-Admin</title>` / `<brand> 管理后台`)。
   **看标题比看状态码有效得多** —— 站群里的诱饵页也回 200。
4. 命中后只读看前端契约(静态 JS 里的 API base、路由表、页面名),**不提交任何凭据**。

### S6 CF NS 对 = 账号指纹(硬归属证据)
**Cloudflare 按账号分配 NS 对** ⇒ 两域 NS 对逐字符一致 = **同一 CF 账号 = 同一主体**。
```bash
for d in <目标域> <候选域...>; do printf '%s\t' "$d"; dig +short NS "$d" @1.1.1.1 | sort | tr '\n' ' '; echo; done
```
判读:
| 现象 | 结论 |
|---|---|
| NS 对逐字符一致 | 同一 CF 账号 ⇒ 同一主体(**可并案**) |
| NS 对不同 | **不可**据此并案(同一主体可注册多个 CF 账号) |
| 仅 CF 段 IP 相同 | 无意义(所有 CF 站点都如此) |
| 同一 NS 对 + 同一套前端 bundle | 成品源码站群 / 多品牌同运营方 |

### S7 辅助判读表
| 观察 | 含义 |
|---|---|
| 证书 issuer = Google Trust Services / Cloudflare Inc ECC CA | **CF Universal SSL 边缘证书**,不含源站信息 |
| 证书 issuer = TrustAsia LiteSSL RSA CA / DigiCert 等 | **源站自持证书**;国内云免费证书多为 TrustAsia 系 ⇒ 源站大概率在国内云 |
| 子域 `code=000` | ≠ 无服务,CF 回源握手失败也是 000 |
| 子域 `code=526` | CF 到源站 TLS 失败 ⇒ 源站**存在且持证书** ⇒ 值得继续追 |
| 无 MX / 无 TXT / 无 DMARC | **无邮件面** ⇒ 直接写死「无邮件旁路」,别再枚举 mail/smtp/imap |
| 域 `time_first` / CT 首见时间很新 | 新盘口/新品牌;老域的历史记录对它零参考价值 |

### S8 收束与交付
- **归属结论**:主体身份 + 自有域清单 + 每条的归属证据(NS 对/仓库引用/bundle 同源)。
- **入口结论**:命中的管理端 URL + 标题 + 前端契约摘要;未命中则如实写
  「**管理端未在公网可达**」,并给出程序形态(前端框架 / 登录路由 / API 前缀,来自公开源码或白盒)
  + 部署判定(CF 后源站 / 内网 / 未公开端口)⇒ **不写「已排除」**。
- **对账**:同一发现不要在两处重复计数;虚报比漏报更伤交付可信度。

## Pitfalls

- **测绘引擎在无凭据时不要反复重试**:CF 后目标在引擎里同样只以 CDN 段 IP 出现,产出天然为零
  ⇒ 立即转 S2/S6,把引擎留给有凭据的时候。
- **枚举循环的输出粘连会伪造归属**:`for ...; do printf '%s ' $s.x; dig +short A $s.x; done`
  在无解析项时会把几十个子域**粘成一行**,让人以为「都解析了」或把 IP 配错到别的名字上。
  每项固定一行、只打印有结果的行,并**用项数而不是行数**做命中统计(细则见 `remote-exec-script-harness`)。
- **本地 grep 自己脚本回显的日志时,脚本打出的 `$ <命令>` 行也会被匹配** ⇒ 命中数虚高、
  命中内容是一整条命令行。解析前剔掉 `###` / `$ ` 开头的行,或让远端只写结果文件。
- **批量深链/批量交互一律先判速率闸**:运营方侧 bot 深链常有分钟级 FloodWait,
  枚举式深链会把自己锁死几十分钟 ⇒ 只做「取数」而不是「遍历」;能读公开网页版(`t.me/s/`)就不调 API。
- **不要把「同一 CDN」当「同一主体」**,也不要用同族模板站的战果给本目标计分(先按目标指纹筛)。
- **链路中继主机先定「商用属性」再谈同源**:跳转链里拉到的 DEST 主机(典型组合:海外机房 + `Microsoft-HTTPAPI/2.0` 标头 + 一组非常规端口 + ZeroSSL 随机证书 + `<随机串>.xyz` 跳转域)= **商用跳转/防红服务**,ASN/whois 组织名多为 IDC 商(CloudRadium/CNServers、Netsec 之类)⇒ **非运营方自有基建,只做只读归属登记、降权不动**。判据只认 ASN/whois 组织名与证书签发者,**不认「它出现在目标跳转链里」**;打第三方跳转服务方 = 打错对象且报告归属写错。

- **RDAP 必须跟跳转（`curl -sL`）**：`rdap.org` 会 302 到各注册局端点，不跟跳转只拿到 **0 字节空 body** ⇒ 易误判「域名无记录」。域龄看 `events` 的 `registration`；「新注册 + 当下是停放页」= 域名已易主/弃用，勿再当运营方现行基建投入。
