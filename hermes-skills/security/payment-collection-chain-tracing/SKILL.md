# 支付收款链溯源(下单 → 收银台 → 二维码解码)

目标不是"测支付漏洞", 而是**把平台的收款账户、聚合商、清算路径摊出来**。报告里这是资金归集点, 跨境场景下就是洗钱层的硬证据 —— 比后台数据更能把"境内实施端"和"境外收款方"连起来。

## 何时用
- 资金盘 / 博彩 / 白标 / 发卡 / 仿冒投资平台的充值流程可达
- 用户问「钱进谁口袋」「收款账户」「资金链」
- 报告需要可核验的商户号 / 收单行 / 币种, 而不是"疑似诈骗"

## 前置
- **普通用户 token 足够**, 不需要管理员
- 只读原则: 下单不付款、不提交支付、不碰第三方收银台自身的漏洞
- 渠道表、下单、收银台三步属目标平台; 收银台之后是**他方系统**, 只读页面

## 六步

**1. 拉渠道表.** `GET /app/recharge-channels` → 渠道 id/name。顺手把 `withdraw-channels` / `banks` / `deposit-withdraw-config` 一并拉了(限额、日次数、最小额), 后面判断"哪条链能出大额"要用。

**2. 下最小订单.** `POST /app/recharge {amount:<正数>, rechargeChannelId:<id>, scene:"recharge"}`
- 小额(10/20)常被风控挡: `该金额10.00没有可用通道,请联系客服检查风控` ⇒ **直接换 100/500/1000 重试**, 别在 10 块上耗。
- 金额用整数标准额, 小数容易触风控规则。

**3. 失败回包就是情报.** 下单失败常把聚合商内部参数吐出来:
`无法取得可用的支付通道[productId=8888,mchId=20000034]` ⇒ 直接拿到**商户号**。
**每条错误文案原文记下**, 这是最省事的泄露面。

**4. 收银台.** 成功回 `{data:{url:"https://<收银台>"}}`。同一订单换渠道能拿到**多个**聚合商(实测一单四家: 微信 JSAPI / 收银台页 / 四合一 / 代付 API) ⇒ 逐个拉, 每条链独立记账。
拉页面后找 `qr_value` / `code_url` / `payUrl`:
`grep -o 'qr_value:"[^"]*"' page.html`
很多收银台把订单数据内联在 HTML 里, 不用再调 API。

**5. EMVCo 解码 = 收款方身份.** 用 `scripts/emvco_qr_decode.py '<qr串>'`。
关键 tag: `00` 版本 / `26`~`51` 商户账户(含 AID) / `52` MCC / `53` 币种 / `54` 金额 / `58` 国家 / `59` 商户名 / `60` 城市 / `61` 邮编 / `63` CRC。
AID 速查: `A000000615`=UnionPay, `A0000000031010`=Visa, `A0000000041010`=Mastercard, `A0000000651010`=JCB。
商户账户子串里出现 `RHBQR` / `DuitNow` / `PromptPay` 这类 = 当地收单行或本地清算网络。

**6. 记账表.** 每条链一行: 渠道 → 聚合商域名 → mchId → 收单行/清算网络 → 商户名 → 币种 → 金额比。
**本币:外币的比值就是汇率线索**, 顺带能反推结算时点。

## 坑
- **token 短 TTL**: 401「登录已失效」多是 token 过期不是封号 ⇒ 每请求前重登, 别当阻断。
- **订单有 TTL**: 收银台过期就空白页, 重新下单即可, 不用改参数。
- **一次性 / 单发写入端点**: 实名、邮寄、申请、绑卡、下单这类端点常按 (账号, 子类型) 唯一, 首次成功后一律回「该类型已提交，不可重复提交」。**这类端点上做注入/探测, 载荷必须打在第一发** —— 先发 baseline 探字段会把唯一机会用掉, 后续 payload 全被业务锁拦在 SQL 之前, 会误判成"过滤严格"。要对比就换另一个 `type` / 子资源 / 小号。判据: 回「已提交/不可重复」是业务锁, 既不是 WAF 也不是参数错。
- **二维码只有商户名没有账号**是常态; `26` tag 里若有 payment URL / 参考号, 原样保留进报告, 那是唯一可追的标识。
- 同一账号同一渠道可能有日次数限制 ⇒ 测多链时轮换金额或渠道。

## 输出
一张表 + 一句结论。例:
> ¥100 订单 → UnionPay AID `A000000615` + `RHBQR` + MYR 60.76 + 商户 `COOLING POINT NILAI` + 邮编 56000 ⇒ 人民币经聚合商在马来西亚落地为马币商户码, 属跨境归集层。

细节模板见 `references/case-foreign-acquirer-qr.md`。

## 边界
- 支付**逻辑漏洞**(负金额/并发重放/回调篡改/优惠券) → `business-logic-payment`
- **出金被拒**的错误阶梯 → `payment-gate-ladder-probing`
- 平台家族/漏斗话术 → `chinese-fund-scam-platform-pentest`

## 附带产出
收款链常和"下一层漏斗"绑在一起: 充值成功页/客服消息里会出现税费、保证金、解冻费的收款入口 ⇒ 把每个收费节点的渠道号单独记一行, 这些是二次收割的定价证据。
