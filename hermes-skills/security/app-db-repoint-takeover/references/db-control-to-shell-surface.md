# 数据面到手 → 往 shell 走的滥用面清单

已控制应用库(可读全量 SQL、可改任意业务配置、可插管理员行)之后,按命中率排序找 shell 面。
**每一条都先判定「校验粒度」再投入**,不要一上来就构造绕过。

## 1. 后台/管理 API 的上传端点(首选)
- **去哪找**: 后台前端 JS(`admin.js` 之类,常 100KB+)里的全部管理接口就是清单;搜 `FormData`、`append(`、`action=`、`type="file"`。
- **形态**: `POST /admin.php` + `action=upload_xxx` + 字段名(如 `bg_file`/`file`)。
- **先判粒度**: 纯扩展名白名单(改 `.phtml/.php5/.phar/.php.jpg` 就过) vs **真实类型校验**(报「仅支持 JPG/PNG/WebP 格式」= 看了内容)。
- 响应通常回吐落点路径 ⇒ 立刻用两种读法验证(直接 GET / 经应用包装页 GET)。

## 2. 可控删文件(用来解锁安装器)
- 面: `cache_clear_all` / `cache_clear_expired` / `cache_delete_single` / 备份删除 / 日志轮转 / 旧版本清理。
- **只在实测「删除路径来自你给的参数」时才成立**;若删除路径由代码按 key 重算(见 3),则不可控。
- 目标物: `install.lock`(解锁安装器重放)与旧占位文件。

## 3. 缓存类落盘(webroot 内的基础文件写)
- 面: HLS/m3u8 改写缓存、缩略图、背景图回写、日志、导出文件。
- 已验形态: 应用主动抓你给的 URL → 解析 → **重新序列化** → 落 `<webroot>/<app>/m3u8_cache/<md5(video_url)>.m3u8`,**可 HTTP 读取**。
- **判据**: 文件名 = 输入 URL 的 hash(**不可控**)、扩展名由代码固定(**不可控**)、`file_path` 之类的 DB 列**不被信任用于读写**(实测会被重算 ⇒ 改 DB 无效,别按猜测投入)。
- 结论口径: 这是「webroot 内固定名文件写」,想变 webshell 需要**文件名或扩展名可控** —— 没有就别在报告里写成任意文件写。

## 4. 播放列表/配置改写 = 内容可控
- 应用会解析你给的播放列表(或 JSON/配置)并回写: **非标准行被剥掉,但 URL 行原文保留** ⇒ 一旦第 3 条的命名可控,`<?php … ?>` 作为一行 URL 就会进文件并执行。
- 同理: 应用把配置字段拼进模板/脚本时,你能通过改库让**内容**落地。

## 5. 数据注入 → 同源 JS(存储型 XSS)
- 面: 插件/菜单项/广告位/公告/客服链接等字段被渲染成播放器页的 `<script src>` / innerHTML。
- 利用: 把值改成你自己托管的 URL(或内联 HTML) ⇒ 在**目标同源**上下文执行 ⇒ 打后台会话(后台与播放器常同源同 Cookie 作用域)。
- 验证: 直接 GET 渲染页,确认你的字符串出现在响应里(已验: 写库后站点页面出现自定义标记)。

## 6. 服务端下载型设置 = 带回显的 SSRF
- 面: 背景图/校验图/弹幕库地址/JSON 解析接口/广告过滤上游。
- 先看**是否回显响应体**(如去广告改写会把抓到的播放列表回吐)⇒ 能回显就是读内网服务的通道;要求响应必须是某类型时退化为端口/服务探测 + OOB。
- 白名单常与这些设置**同表**(你可控)⇒ 别因为第一次被拦就放弃。

## 7. 顺着后台发现的本机服务
- 后台里出现 `redis_*` / `redis_flush` / `db_test` 这类动作 ⇒ 本机有 Redis/DB 等原生服务 ⇒ 值得顺着打(未授权 Redis 可写文件/改会话)。
- 已验可用: NAT 重定向截获端口而不动原服务(见 SKILL 陷阱 7)。

## 8. 记录口径
- 明确区分: **数据面控制**(库/SQL/配置/后台) vs **代码执行**(shell)。前者不是后者。
- 每一条面都要写清「测了什么、判据、结论、未完成的部分」,别把未通的路写成已通。
