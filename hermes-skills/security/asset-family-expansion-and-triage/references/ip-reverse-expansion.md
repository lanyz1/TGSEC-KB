# 从具名域/已知 IP 反查扩资产族 + 新面服务初筛

## 0. 两个反查方向（都要做，产出不同）

| 查询 | 拿到什么 | 典型产出 |
|---|---|---|
| `domain="<已知域>"` | 该域族下**全部被测绘到的资产**（含未公开的子域/后台域） | 后台管理系统域、测试/预发域、同族新品牌域 |
| `ip="<已知IP>"` | 该 IP 上**全部域名 + 端口 + 服务 + 标题** | 同源站白标站群、暴露的非 HTTP 服务（Redis/MySQL/FTP/SSH/WinRM） |

一次查询就能拿到「这台机器上还挂着哪些站」+「标题里写明用途的服务」（实测标题直写「第四方支付系统」「后台登录」），
且全程第三方数据、不碰目标、无日志 ⇒ 优先于端口扫描。

**引擎侧注意**：官方 API 对**未实名/未认证**的 key 会直接拒绝（报错串里会明说），换引擎重跑即可；
把「引擎可用性验证」放在脚本第 1 步，不要让整批跑完才发现不可用。

## 1. 新面服务初筛（只做读一类）

按脆弱度排序，对 `ip=` 反查出的一批新 IP 逐台：

1. `6379 Redis` — 未授权 `PING`/`INFO`（一旦通，写 `authorized_keys`/计划任务即 shell）。
2. `3306 MySQL` — 握手 + 极少默认/弱口令（`root` 空、`root/root`、`root/123456`）。
3. `21 FTP` — banner + 匿名登录。
4. `5985 WinRM` / `22 SSH` — 只记存在性，**凭据到手再动**。

全部经跳板/代理出口（`socks5h://127.0.0.1:<port>`）。

## 2. ★ 判读表：区分「服务没开」与「出口被过滤」

| 观察 | 结论 | 下一步 |
|---|---|---|
| MySQL 握手回 `Access denied for user 'root'@'<IP>'` | ①握手通了（端口真开）②`<IP>` = 目标看到的**我方源 IP** | 只用弱口令表，别上大字典 |
| FTP 回 `220 (vsFTPd/Pure-FTPd [privsep][TLS])` banner | 端口真开 + 服务指纹 | 判匿名后收线 |
| 同机某端口可握手、其余全超时 | 路径通 ⇒ 其余是**逐端口/白名单过滤**，不是主机死 | 换出口复测 |
| 全端口 RST（空响应） | 可能由中间云 WAF/SLB 代答 | 配 banner 证据再下「主机存活」结论 |
| 集体超时且无任何 banner | 路径未知 | 换出口复测后再判，**不得**写成「服务已关闭」 |

两条硬推论：
- **用回显的源 IP 自证出口切过去了**（应是跳板出口而非本机公网 IP）；不一致 ⇒ 整批结论挂错出口，重跑。
- 集体超时的成因在**出口路径**（白名单/地域）：处置 = 换出口复测，**不是**把目标登记成「服务已关闭」。

## 3. 同源站白标站群（横向面）

同一源站 IP（常见 Tengine/nginx 反代）上常挂着一批**同构站**，命名族形如
`int.<品牌><NN>`（`int.rryl601`、`int.xbyl603`、`int.zzyl901`、`int.tbh701`…）外加若干短域静态站。

- 契约与后端常共用 ⇒ **一台的指纹/签名/风控闸打不动时，拿同一份契约横向打同族另一台**（各站配置松紧不一）。
- 静态站往往在**另一个短域**上（相对路径/懒加载 chunk 在 API 域 404）⇒ 用入口 HTML 字节数认亲后在该域取分片。
- 同族里优先挑：**新建的站**（配置未加固）、**测试/预发域**（校验更松）、**兄弟品牌**（风控策略可能未同步）。

## 4. 产出与归属纪律

- 落盘：`fofa_assets.json`（原始条目） + 归并表 `IP | 域名 | 端口 | 服务/标题 | 判读`。
- 新面按价值排序：**托管支付/账务** > **多站后台登录面板群** > **Windows+WinRM（等凭据）**。
- 每个新面在报告里都要写清「与已知目标同主体」的证据链；仅凭同 IP / 相似标题**不足以**认定归属，
  先做被动核对（WHOIS / 证书 / 页面文案）再开打——配置里的域名常是历史残留或第三方停放。
