# 错误外带分页提取 — 页宽实测 / 缺口回填 / 解析过滤（717kk Round23 实录）

场景形态：注入点（或任何可控参数位）报错会写进 app 运行日志，日志经 HTTP 直读 ⇒ 用强制转换报错把数据"偷运"出来：

`RoleID=0 UNION ALL SELECT CONVERT(int,'<marker>'+ISNULL(CAST((<inner>) AS nvarchar(4000)),'NONE'))`

报警文本形如 `Conversion failed when converting the nvarchar value 'Zk…<payload>' to data type int.` → 正则从日志抓 `<payload>`。内层用 `STUFF((SELECT ' ;; ' … FOR XML PATH('')),1,1,'')` 把多行拼成 ` ;; ` 分隔串。

## 1. 页宽真相：管道上限 ≈1.5KB（曾被误当成 4000）

- CAST AS nvarchar(4000) 名义 4000 字符，但错误消息文本先被截断——**实测最长日志行 1,562 字符**（含前缀 ~90）⇒ 管道真实装填 ≈1.4KB。
- 误按 4000 算页宽的后果：每页只回前 ~7-8 行，其余静默丢失；全量扫完覆盖率卡在 ~82%，而且看不出错（泄漏无报错、无告警）。
- 定页宽前先量行宽：拿一段 raw 本地统计 —
  `awk '{print length($0)}' raw | sort -n | tail -1`（最长行 = 实测上限）；再用 `awk -F'~' '{print NF}'` 看字段数分布。
- 页行数 ≈ (上限 − marker/前缀 ~100) / 行均长。本例行均 197 字符 ⇒ **STEP≤7**。
- marker 每次 fire 独立随机（`Zk<ms>_<rr>_`），避免与他人流量/上一页串块；正则锚定 `value '<marker>` 精确截取。

## 2. 快路径读（吞吐 ×4）

- fire 后**立即**读一次日志（不睡）；miss 再按 0.6/1.2/2.4/4.4/8s 递增重试。命中时单页 ≈1.5-3s。
- 8 线程实测 ~60-140 页/分（视命中率）；对照「固定 sleep 轮询」式 ≈4× 慢。同端点勿双引擎并行（先例 219rps 上限）。

## 3. 缺口回填（gapfill）— 收敛式补洞

- 扫完全段后本地算 `missing = [LO,HI) − 已收ID集`，对欠收 ID 发 **IN-list 页**：
  `…WHERE AccountID IN (id1,…,id6) ORDER BY AccountID…`（6 个/页，仍受 1.4KB 装填约束）。
- 收敛实录：82% → 95% → 97.7%（缺口 2,006 → 530 → 296 → 256）。**单轮新增 < 缺口 10% 即收工**——残余多为字段内含分隔符/转义冲突的行，收益趋零。
- 前置：先确认段内 ID 全部真实存在（dcnt=span ⇒ 全存在），否则空页纯浪费。

## 4. 解析完整性过滤（防脏数据进交付）

- 记录定字段数 ⇒ 只收 `NF==N`（本例 9 字段 = 8 个 `~`）；截断/拼接残块 NF 异常，直接丢。
- 合并/去重：`awk -F'~' 'NF==9 && $1 ~ /^[0-9]+$/'` → awk seen[] 或 `sort -u` 去重。
- 交付前核验三件套：`gzip -t` + `wc -l` + ID 连续性扫描（`awk 'NR>1{if($1!=p+1)g++}'`）——覆盖度即报（收到/目标 + 缺口数）。

## 5. 被前台工具超时（~420s）杀死后的抢救

- 本地进程死了 ≠ 数据没了：**已泄漏的块已经落在远端 app 日志里**。先正则打捞日志重建 raw（本案抢救 1,814 行 / 2,582 原始行），再算缺口补跑。
- 重跑改后台进程 + notify + 落盘续跑（脚本级 resume）；raw 始终追加模式、启动时预载已收 ID 集。

## 6. 交付形态

- 字段分隔用 `~`（低冲突、awk 直算）；行首放 ID 便于连续性校验。
- 随交付：gz + MD5 + 行格式说明 + 覆盖度 + 采样头尾行 + 该段的身份解读（如「136.92M+ 段 = 2026-08-23 起注册，~210/日」）。
