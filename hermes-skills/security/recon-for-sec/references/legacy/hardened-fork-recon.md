# 加固 / 二开分支侦察:先拿清单,再找残留

> 当目标明确是某开源/商业产品的**加固分支或二开版**(作者已经知道常见洞并修过),旧版本的 exploit 清单和注入 payload **大部分会静默失效**。此时最贵的动作是「拿旧清单硬打」,最值的动作是**把作者的加固清单直接取到**,然后只打清单之外。

## 触发场景
- 目标指纹命中某产品,但 README/部署文件/`.git` 残留显示是**私有加固分支**(如 `codex/<主题>` 这类分支名)
- 已知的注入点、回调伪造、上传点全部「响应一样、无差分」
- 目标跑过安全审计(有 `/tests/**`、`install/` 自检页、加固说明文档)

## 流程

### Step 1 取证分支身份(决定要不要换打法)
1. 从可读的部署残留取源,`.git` 四处都要摸:`config`/`packed-refs`/`refs/**`(分支名)、`logs/HEAD`(reflog,**逐字写出 clone 来源 URL + 每次 pull 的 commit SHA**,一举坐实「哪个私有仓的加固分支」)、`index`、loose 对象。
   - **★ 先扫 loose 对象再判死「源码拿不到」**:读 `/.git/index` 列出全部路径 + blob SHA(实测可上千条),对每个 blob 打 `/.git/objects/<前2>/<后38>`;命中的那一小撮 = **工作区被改动过、被 `git add` 过的文件** ⇒ 就是加固 diff 面本身,情报密度最高。
   - 取回的版本与本地同产品**原版**做 diff,直接读出加固者写了什么(策略类、守卫函数、白名单、by design 放行项)。
   - pack 对象(打包过的历史)通常整批 404,别在它上面耗;只有 index/loose 全 404 时才退回「靠部署残留推断」。
2. `/Dockerfile`、`/.dockerignore`、`/README.md`、`/.env`、`/nginx.txt`、`/IIS.txt` 常直接公开可读:得到**底座语言+版本**(如 `php:8.4-cli-alpine`)、**DB 驱动与容器服务名**(如 `DB_HOST=postgres`)、以及伪静态里**没生效的重写规则**(作者想 deny 但写错了 ⇒ 就是残留面)。
3. **本地那份源码 ≠ 线上那份**:私有加固分支不可得时,本地未加固副本只用来**解释行为**,不能用来断言线上有什么/没有什么。

### Step 2 ★ 拿作者的「已加固清单」——比逐个试快一个量级
- 目标若把**测试套件**留在 web 根下(`/tests/**`),`GET` 它返回的往往是**执行后的输出**(脚本真跑了)而不是源码 —— 一坨几十到几百字节的 `PASS` 断言串。
- 这些断言串逐条就是作者的加固点(策略类名如 `NotifyUrlPolicy` / `CsvExportTest` / `InstallerFormTest`)。**把它们当坑点字典用**:已堵的别去试,把轮次全投到**清单之外**。
- 判据:PHP 脚本经 HTTP 只会回**输出**,永远回不了源码 ⇒ 想读某 `.php` 的代码,换个途径(部署残留、镜像、同族仓),别在 HTTP 上耗。
- 危险项:同一入口下的**执行型脚本**(安装向导、自检页、导出、定时任务)可能有真副作用 —— 只取输出,不碰有业务/资金副作用的 act。

### Step 3 读加固的「两侧」:堵死的 与 **by design 松的**
加固分支的价值情报不止「哪些堵了」,还有「**哪些是设计上故意放行的**」:
- 典型:**外联 URL 策略只拒公网 HTTP,明放 HTTPS / loopback / 显式私有 HTTP** ⇒ 那是 **HTTP-only SSRF by design**,内部明文服务(docker API `:2375`、exporter、redis/mysql)才是目标,别因为「公网 SSRF 被堵」就整条线放弃。
- 另一类是**作者自己写的白名单**:弱口令/环回/内网段常在名单里(如 `127.0.0.1`/`::1`/`10.x`),拿它当绕过起点。

### Step 4 契约逐代取,别套旧契约(二开最常见的空转来源)
- **同一产品的两代/二开,接口与字段名都可能不同**:SPA 代 `POST /<m>/auth/login`(JSON)与壳代 `POST /<m>/?act=login`(form-encoded,多一个验证码字段)并存。
- 取法固定:**用真浏览器打开登录页,读内联 JS**(`onsubmit` 指向的提交函数)—— 一次拿到 URL、字段名、`enc` 语义、验证码字段名、以及「忘记密码」链接;比猜字段名快一个数量级。
- **`enc=0` 类开关是双代的共同点**:加密开关关掉时密码明文直传,探测阶段直接用它。
- **表单里有 TOTP/动态码字段 ≠ 登录要求动态码**:判据是**提交函数有没有真的把它放进 data**;很多二开版留了输入框但根本不发这个字段 ⇒ 别为它去搞 TOTP。

### Step 5 ★★ 残留弱面里最肥的一类:明文凭据的位置自己招了
- 登录页的「忘记密码」弹窗 / 帮助文案 / FAQ 常**直接说出管理员密码存在哪**:「进入数据库管理器(phpMyAdmin)…查看 `pay_config` 表即可找回管理员密码」⇒ **配置文件表里是明文**。
- ⇒ **开案先点一次「忘记密码」读原文**。它直接决定路线:**取库 ≫ 破 bcrypt**。同族常见明文落点:配置表(`pay_config`/`sys_config`)、`config.php`、`runtime/` 下配置、`.env` 里的初始口令。
- 取库通道优先从**内网服务名**想(gateway `DB_HOST` 指向的容器名、exporter 旁路、可 SSRF 的明文服务),而不是等外网暴露 phpMyAdmin —— 后者常根本不暴露(候选子域不解析也是同一结论)。

### Step 6 判死任何洞之前先做差分
- 加固分支常把已知注入点**参数化**:旧版有注入的 `?id=`/`?trade_no=`,加固版对 `1` / `1'` / `1' AND '1'='1` / `1' AND '1'='2` **四发响应逐字相同** ⇒ 才可判死。只发一发就下结论 = 假阴性。
- **HTML 页面面(curl)回空体 = 反爬过滤,不是应用死**:页面面的存在性判定一律用真浏览器(见 `api-probe-layer-triage` 的《空体的第四个成因》)。加固分支的运营方往往同时上了反爬。

### Step 7 代码级原语:找「无过滤拼接」而不是「找上传点」
- 插件/模板/主题类加载器是这类产品的通用原语:`include_once PLUGIN_ROOT.$channel['plugin'].'/'.$channel['plugin'].'_plugin.php'` —— **变量直接拼进路径**,且 `include` **先于** class/method 存在性校验执行。
- 攻击面不是「找一个上传点」,而是「**能否让那个字段落到可写位置**」(改配置表该字段 / 往 `/tmp` 落 `<name>_plugin.php`);先把该字段的**数据来源**(配置表 / 面板可改项)摸清,再谈落盘。

### Step 8 残留面 = 「可写」∩「可达」:两份清单相乘,别凭感觉找上传点
- **可写清单来自部署文件**:`Dockerfile` 的 `chown`/`COPY --chown`、compose 的 `volumes`、`.env` 落点 —— 逐条抄下来。加固者为了自更新常常把 `.env`、`install/`、`assets/uploads/`、`plugins/*/{cert,logs}` 全交给 web 用户。
- **可达清单来自 nginx/伪静态**:`deny all` 的 `location`(常见 `/plugins`、`/includes`)与其余目录取差集。
- **真面 = 可写 ∩ 可达 ∩ 存在写入原语**,三者缺一即判死;判死要写出是哪一条缺(可写但被 deny / 可达但后缀写死 / 都满足但没有 sink)。
- **加固站照样漏运维面**:`:9090` Prometheus 未授权时,`/api/v1/targets` + `/api/v1/status/config` 直接给出**内网服务名与网段**(各类 exporter、redis、mysql、docker 网络别名)⇒ 这是随后 SSRF/内网打点的靶单,优先取。
- **目标侧核验必须换出口 IP 复测**:端口是否开放、SSH 是否可达、白名单是否放行,都取决于**源 IP**;本机或上一轮的结论不能外推,必须经跳板机(不同出口)再测一次才算数(见 `ip-ban-bypass` 的直连隧道)。

## 铁律
1. **先拿清单,再打洞**:作者留下的测试/自检产物是免费情报,不读它就去逐个试洞 = 白烧轮次。
2. **本地源码只解释行为,不证明线上存在性。**
3. **整批同值先做对照**:整批 `200/0B`、整批同一句错误 ⇒ 先怀疑仪器(反爬/传输/前缀),不是目标。
4. **契约按部署逐代取,绝不跨代套用**(同名产品、同一模板都不行)。
5. **明文凭据的存储位置优先于口令爆破**:任何「找回密码」类文案都先读一遍再决定路线。
6. **有业务/资金副作用的 act 一律不触发**:定时任务(结算/转账/回调)、安装向导、导出 —— 只读形态才碰。
7. **残留物当真值前先自证来源**:仓里躺着的 token/候选文件很可能是**上一轮我方自造**的(实测真会话 64hex、自造候选 32hex md5)。解密样本后先问「这个值本地脚本能不能算出来」——能算出来就是自造物,不是目标的泄露。
8. **会话签名反推有止损线**:元素齐备(uid/key/口令 hash/各类 key)时,跑 `10^5` 量级构造(纯哈希 + HMAC + 嵌套 + hash-of-旧式 md5)仍 0 命中 ⇒ 判定存在**库内不可见 pepper**,结论写「无源码不可伪造」并收线换面,不再扩大排列组合。

配方细节(index→loose 取法、`authcode` 载荷结构、真/伪票判据)见 `references/git-residue-harvest.md`。
