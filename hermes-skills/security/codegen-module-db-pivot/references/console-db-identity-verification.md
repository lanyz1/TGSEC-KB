# 判定「这个控制台到底读哪个库」—— 多市场/多部署平台的必修前置

> 来源:一次真实踩坑。同一平台按市场部署了数套控制台,一台 MySQL 上并存多个市场的库
> (`xxx_compat_20260808` / `xxx_india` / `xxx_in_bd`),**互为镜像** ——
> 账号名、id、昵称、哈希语义全都一致。基于"库里有 admin|888"就投入跨库改密链,
> 最后发现**目标控制台根本不读那个库**,整条链白做。

**为什么必须单独立卡:** 这个判据决定了后面所有跨库工作有没有意义。
判错 = 全链路白费。而它**不需要写库、不需要爆破、几个本地 bcrypt 调用就能定论**。

---

## 一、判据强度分级(核心)

弱判据**只能用来提出假设**,强判据才能定论。

| 级别 | 观察 | 为什么不够 |
|---|---|---|
| ❌ 弱 | `getDB` / `autoCode` 某接口回"权限不足" | 只是**那个接口**权限没开,与库无关 |
| ❌ 弱 | 某账号登不进控制台 | 可能**口令本来就不对**,或该账号被软删 |
| ❌ 弱 | 某批表 `getColumn` 返回 `columns:null` | 可能那批表属**更新版 schema**,不代表库不同 |
| ❌ 弱 | 接口/页面 404 | **路由被裁剪**,与库无关 |
| ✅ **强** | **测试 B(下方)** | 离线可证、无替代解释 |
| ✅ **强** | **测试 A(下方)** | 需要写权限,但结论直接 |

**踩坑教训: 把一串弱判据堆起来当结论 = 自欺。** 每一条都有更平凡的解释。

---

## 二、测试 B —— 哈希↔口令交叉验证(离线、免费、最快,**优先做**)

```python
import bcrypt
H = "$2a$10$....".encode()          # 从"我以为的目标库"里读出来的哈希
for pw in ["123456", "qwe123123", "123123", "qwe123456", ...]:
    if bcrypt.checkpw(pw.encode(), H):
        print("该库中此账号的口令 =", pw)
        break
```

判定表:

| 库里哈希验证 | 拿该口令登控制台 | 结论 |
|---|---|---|
| **True** | ✅ 成功 | 控制台读这个库 → 可以继续跨库链 |
| **True** | ❌ 被拒 | **铁证:控制台不读这个库**(凭据在该库明明有效) |
| False | — | 口令未知 → **先爆哈希,别急着下"库不同"的结论** |

**注意第 3 行:** 哈希没爆出来时**不能**说"库不同" ——
本会话就犯过:只试了 1 个口令就断言库不同,后来验证发现口令其实是另一个值。

## 三、测试 A —— 写入反射测试(需写权限)

1. 用跨库写原语改一个**无关紧要的字段**(如某账号 `nick_name` → `PANGHUTEST`)
2. **回读确认写入真的落地**(跨库写可能静默失败,见 write-primitive 卡的坑 3)
3. 用该控制台**正常登录口重新登录**,看返回体里 `nickName` 是否变化
4. **没变化 ⟹ 该控制台不读这个库**
5. **立刻还原原值**

只做第 1 步不做第 2 步 = 无效实验(可能压根没写进去)。

## 四、GVA 系「按市场分库」的识别特征

```
biz_country_configs     country_code / currency_code / 货币符号,带 deleted_at(退市软删)
biz_live_host_markets   主机↔市场映射表(常为空)
biz_gateway_aws_active_regions  区域表(常只有 id 列有值)
luck_shop_<market>      按市场命名的业务库,同实例并存、结构相同
app / app_clean_<日期>  旧快照/镜像,极易被误当成"目标主库"
```

**看到这种结构,默认假设:控制台读的库不在当前能看到的那批里。**
先用测试 B 证伪这个假设,再决定投不投入。

> 反面教训: `app` 库里的账号/哈希/昵称与目标控制台**完全一致**(所以看起来"就是它"),
> 但改它毫无效果 —— 它只是镜像。

## 五、判错之后的正确表述

判错时**当场更正,不要粉饰**:
- 明确说"我上一条结论是错的,根因是 X"
- 给出**证据链**(哪几个实验、各自结果)
- 重新划出边界:"该控制台连的是独立库,不在可达范围内"
- 把**仍然成立**的成果单独列出来(别让一次判错抹掉全部战果)

用户会看证据;含糊其辞比承认判错代价更大。
