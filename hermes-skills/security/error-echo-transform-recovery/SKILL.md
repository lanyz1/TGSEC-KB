# 从报错回显反推服务端编解码变换

**触发**：服务端在报错里回显"解码/解密后的输入"（`The string '...' doesn't have a valid JSON format`、`illegal base64`、签名校验失败回显明文、`token 不存在` 带着一段乱码等）。这时服务端就是一个**黑盒变换 oracle**：喂输入、读回显、差分，可以把变换律完全推出来，再写求逆伪造 token/签名/参数。

**适用场景**：自研鉴权 token（非标准 JWT/JWE）、自定义签名、"加密"参数、网关/WAF 的编码层。前端 JS/APK 拿不到或太重时，这条路比逆向前端快得多。

## 铁律

1. **字节级捕获，绝不比对文本回显。** `curl -o` 落盘 → 二进制读响应体 → 把 `\uXXXX` 还原成字节。回显里的 `efbfbd`(U+FFFD) 是"服务端自己又做过一次 UTF-8 解码"的信号，不是原始字节。用正则直接比对文本会把不可打印字节渲染成转义，产生**假性命中**（可打印字节偶然对上），据此下的结论全是错的。
2. **长度扫描 + 固定 pattern。** 输入长度扫 0..12（必要时到 32），内容用 `01 23 45 67 89 AB CD EF 10 32 54 76` 这类逐字节可辨识的 pattern ⇒ 一次同时读出"结构"和"padding 效应"，不要一次只试一个长度。
3. **长度律里出现 `len%3`（或 `%4`）翻转 ⇒ 先怀疑 base64/padding 假象。** 判据：看输入段是否以 `==` 结尾（`n%3==1` ⟺ `==` 结尾 ⟺ 末字节保留，否则末字节被吃掉）。这是编码落地造成的，不是变换本身在丢字节。
4. **结论必须可求逆，并用第二个独立输入验证。** 只对上一条样例不下结论、不写进结案报告、不对外汇报。
5. **回显里出现与输入无关的固定头部 ⇒ 该路径判死，立刻转向。** 服务端在 parse 前拼接常量前缀时，parse 目标永远带垃圾头，**任何构造都进不去**；继续精修变换是纯沉没成本。出路只有两条：从前端 JS/APK 取真实构造算法，或换攻击面（见下）。
6. **分级差异 ≠ 鉴权放行。** `未登录` → `JSON 解析错误` → `400 业务参数缺失` 只说明失败点被推后，不代表身份被接受。别把"错误信息变了"当成"绕过了"。

## 停机判据（避免连烧十几轮）

出现以下任一，停止精修变换并转向：
- 变换律已能求逆且第二个独立输入验证通过 —— 变换本身已攻下，剩下的阻力在别处（前缀、密钥、真实契约），再测也不动。
- 回显里存在输入无关的固定前缀/后缀。
- 同一族假设（nibble-swap / CTR / RC4 / 压缩编码 / 长度律重测）已排除两轮以上。

## 转向：免鉴权命名空间收割

变换攻不下时，最赚的第二步是找**免鉴权的同族端点**（自研框架的鉴权常是**按路径前缀白名单**生效的，同族整片开放）：

1. 拉 Swagger/接口清单全量 path 落盘。
2. 按**顶层命名空间**分组（`/api/h5/*`、`/api/app/*`、`/mobile/*` …）。
3. 每个命名空间挑 **1 个只读端点不带 token** 打一次；返回业务数据（如 `{"code":"0","msg":"操作成功","data":...}`）而非 `未登录` ⇒ 整片免鉴权，再横向铺开同族。**逐个端点试是浪费时间。**
4. 探写原语/上传类端点时**不带文件、不带 body**，只验鉴权闸门，避免真实写入。

两个必踩的坑：
- **Swagger 契约 ≠ 线上映射**（path 名、参数名/类型都可能对不上）。以线上报错为准。
- **测试环境返 null/空不能证伪原语**（KV/配置库未灌数据）。必须找生产/预发主机重放再判定，否则会把可用原语误判成死路。

## 输出/取证纪律

- 大扫描结果务必 `> file.out 2>&1` 落盘，再 `sed -n "1,Np"` 分段读；**`| tail` 会丢输出**。
- **含非 UTF-8 字节的结果文件，grep 会报 `Binary file ... matches` 并静默吞掉匹配行** ⇒ 必须 `grep -a`（或 `LC_ALL=C grep -a`）才算真的读过，否则会把"没读出来"误判为"没有命中"。
