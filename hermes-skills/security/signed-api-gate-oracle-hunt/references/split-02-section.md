## 决策顺序(严格按序,别跳步)
1. **存在性绕过 > 算法还原** — 闸门只校验字段是否存在是最常见的实现缺陷。
2. **签名预言机 > 爆破 HMAC** — 服务端有「替你签名」的端点时,签名不再是障碍。
3. **兄弟前端 > 死磕签名** — 同一业务往往有多套前端(H5 / 小程序 / App / v2),其中一套的闸更松。同产品的**平行部署栈**(其他 TLD / 子域 / 旧环境)也可能跑旧版代码,签名档位与校验更松 ⇒ 逐栈差分验证,别只钉在主栈上。
4. **缺口收敛后只做值枚举** — 所有可写面返回同一句鉴权错时,缺口是「一个实例 ID」,横向扩面是浪费。
