## 3. 找签名预言机(★ 最高杠杆)
命名族:`re-route` / `pre-sign` / `clientQsPreSign` / `signature` / `getSign` / `signUrl` / `unionUrl` 类「给你个链接」的端点。
- 判据:`GET <端点>` 返回体里带 `?timestamp=<ms>&nonce=<hex>&signature=<hex>` 的**完整 URL**。
- **改请求参数看签名值是否变化**:变 ⇒ 签名覆盖该参数 ⇒ 载荷由你控制(可换实例 ID 生成任意用户的签名链接);不变 ⇒ 签名只覆盖时间/nonce。
- `GET` 该端点报 `缺少参数，名称：timestamp，类型：long` = 活预言机入口,补参后即可取签名。
- 取到后**按返回的路径直接请求**,别改路径:签名通常**路径绑定**,换端点必 `链接已失效/签名失败`,但**同路径换实例 ID 有效**。
- **nonce 是一次性还是可复用必须实测,别预设**:同一实现可能只消费一次,也可能在 TTL 内**可跳端点反复用**(实测某族一枚三元组连打 34 个不同端点全部被接受)⇒ 判「nonce 已消费/签名失效」前先重取一枚对照;长扫描循环一律**每 N 次重铸**,否则 TTL 到期后整批假阴性、整轮误判。
- **对照实验必做(用来区分「签名过期」与「作用域不符」)**:每铸一个三元组,先拿**它本来的消费端**(签名 URL 里那条路径,如 `render/order/<id>`)打一发——返回 302/200 证明该三元组当下有效;再用**同一**三元组打目标端点。对照通过而目标回 `链接已失效` ⇒ **是路径/流程作用域绑定,不是过期,也不是预言机坏了** ⇒ 立刻停手,不再跨端点复用同一个三元组(一端点一铸一用);若仍不通,缺口就不是签名,是**实例 ID**,转 §5。没有对照就下「预言机无效」的结论会白丢整条链。
- **别被端点名骗**:`pre-sign` / `signature` 这类名字的端点**自己也要 nonce + signature**(回 `缺少参数，名称：nonce`)⇒ 它们是**验签方/流程中间站,不是铸造器**。判据只有一条:返回体里带完整 `?timestamp=..&nonce=..&signature=..` URL 的才是铸造器(`re-route` 类)。同一个名字族里既有铸造器也有验签方,逐个实测,别按名字归类。
- **同主机上第二套命名空间常带更松的闸**:同一 IP 上出现不同错误信封(英文 `Method [GET] not allowed, allowed methods [POST]` / `Missing parameter, name: x, type: Long`,而非中文 `缺少参数`)即**另一个上游**,其 POST 路由往往**完全免鉴权**;新的顶级前缀(如 `/uranus-api/**`)要从兄弟 SPA 的 `app.js` 里抽,别只抽 `^/api/`。

- **★ 先确认凭据的「载体」,再判作用域**:同一个闸可能从 **JSON body** 读 `timestamp/nonce/signature`(独立命名空间常见),只放 query 会回「不能为空」,或直接回 `链接已失效`被你读成作用域不符 ⇒ **一处放错,整轮作用域结论作废**。三种载体(query / form / JSON body)各投一次:回「不能为空」= 载体错,回「失效」= 真无效。
  **★ 同一必填报错在全部候选键名 × 该载体下都不消失 ⇒ 判载体/键名族错,别再扩键名**:键名三系(camel `userId` / snake `user_id` / 缩写 `uid`)全投后仍无变化即为信号;反之 `<字段>不能为空` 是**正向 oracle** —— 它同时证明①该路由已注册②该字段名权威(required 校验在 handler 前),别当噪音过滤。且**相邻端点采纳的键名可能相反**(实测 A 端认 `userId` 忽略 `uid`、同族 B 端认 `uid`)⇒ 键名命中只能逐端点判,不能按族推。
- **★ 作用域地图用「一枚有三元组全量投递」一次拿到**:拿一枚已验证有效的三元组,按正确载体投给该命名空间**全部端点**,三元分类:`业务不存在/进件不存在/试算流水号不存在` = **闸已过(同作用域)**、`链接已失效` = 另一作用域、`不能为空` = 参数名/载体不对。比逐个猜快一个数量级,而且**吃签清单本身就是「只差一个实例 ID」的可用面清单**(实测 100 条中 34 条吃签)。
- **★ 铸造器改不了作用域**:给它塞 `path`/`route`/`type` 类参数想换作用域——**被忽略**(回 URL 里的路径不变);把目标路径塞进它会插值的 ID(穿越)→ 报错/500。⇒ 作用域只由铸造器自身决定,换作用域只能去找**另一个**铸造器。
- **★ 网关的类型绑定会挡在业务层之前**:`Parameter type mismatch, name: template-id, required type: Long`(常 `code 100012`)⇒ SSTI/穿越串(`{{7*7}}`、`../`)根本到不了 sink,**看到这类报错就换面,不要继续调 payload**;这也解释了「明明有服务端渲染器却没有 SSTI」。
- **★ 自己签不出来时,先用「建一张最小额未支付单」拿一对 (明文参数串, sign) 作离线起点**:支付/下单跳转页常把完整参数与签名一起回吐(`action` 真实网关域名、`pid`、`sign_type`、`money/out_trade_no/notify_url/return_url/type` 明文 + `sign`)⇒ 有已知明文样本才能离线验证密钥假设与编码细节(**中文参数是否 urlencode 会整体改变签名串**)。**建单属可接受的写操作**(未支付待付单、零资金变动、绝不付款);其余破坏性写一律不做。
- **★ 真实网关域名以「资金流出点」为准,不以品牌域名/兄弟域名为准**:同一厂商常有多个网关实例,`action` 指向的那个才是钱的去处;拿同厂其他域名当家开会白打一整轮。⇒ **从已授权站的资金流里新发现的网关域名,属于新目标,需单独确认一次授权**。

### ★ 上游供应商 HMAC API(密钥在下游客户手里时)

**第一步永远是把契约拿全,不是去猜算法**:这类「分销/供货 API」主机上通常同时挂着框架自描述文件 —— `GET /openapi.json`(path × method 全表 + 参数名)、`GET /docs`(**人可读文档常直接写出签名字典序拼接公式、时间戳/nonce 窗口、限流额度、产物保留天数**)。文档写着「API 客户由运营总后台人工开通」也照样拉:它是权威契约来源,比逆向省一轮。⚠ 同一主机可能对**客户端指纹**敏感:`curl` 默认 UA 吃到挑战页(1xx 字节 HTML)而 `python urllib`/浏览器 UA 直接 200 ⇒ 拿到小体积 HTML 先换 UA 重发,别写成「文档受保护」。
- **文档里的 callback 验签规范是「它对你的出站调用」**(校验它推给你的通知),**不是入站鉴权**;别把它当攻击面。
- **格式层 oracle 先于密钥层**:短键/乱写键回 `X-Api-Sign format is invalid` / `key format is invalid` = 服务端**先校验签名格式、再查密钥表**。要拿「密钥是否存在」的 oracle,必须先按文档算出**格式合法**的签(定长 hex)—— 否则你测的永远是格式层。分档:`format invalid` = 格式层、`sign invalid` = 密钥/签名层、`app key not found` = 键不存在 ⇒ 键名存在性可枚举,但**拿到存在性也进不去**(无 secret 造不出合法签)。
- **键名可枚举 ⇒ 仅当键名是人工命名的短串时才值得跑靶向小列表**;随机长串直接止损。
- **★ 免密钥触达上游的唯一读面 = 下游付费客户自己的后端**:客户服务端会用自己的 key 调上游,且常把你给的路径参数**原样拼进上游 URL**。判据(一条对照即可):**发一个肯定不存在的 id,回的是上游的错误体格式**(如 FastAPI `{"detail":"..."}`)而非本应用文案 ⇒ 参数透传 + 客户就是签名代理 ⇒ 可借它反推上游契约/错误语义、并试 `../` 穿越触达上游其它端点(含下载类)。
  ⚠ **穿越在 Spring 目标上从入口就死**:`StrictHttpFirewall` 拒 `%2f`/`%5c`/双重编码(400,body 回显**未解码** path),浏览器又会把 `%2e%2e/` 归一化 ⇒ 别烧编码变体。此形态的价值在**透传证明与契约**,不在接管。
- **★ 终局判据(该收线时收线)**:契约+公式+格式 oracle 全拿到,而密钥「在下游服务端 / 总后台人工签发」⇒ 纯技术面的密钥路已封;再往上只剩 ① 打穿下游客户自己的后端(拿它的 key)② 真下单一笔(资金写操作,须用户点头)。把这两条写清即可,**不要回头再枚举键名或换编码**。
