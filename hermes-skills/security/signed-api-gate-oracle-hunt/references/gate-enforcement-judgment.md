# 闸门强制性与状态变更归属:判决实验协议

适用:目标存在「先决条件闸门」——必须先完成若千验证步 / 先置某状态 / 先过某签,才允许产生状态变更(提交/领取/下单/入账)。
目标:用**最小且可逆的代价**判定闸门是否真在服务端强制,并把每一次变更准确归因到某次会话。

## 1. 判决矩阵(缺最后一档则整轮无效)

| 档 | 送法 | 到场意味着 |
|---|---|---|
| ① 零步 | 过闸后**不完成任何**验证步,直接提交 | 闸门形同虚设,可脚本化抢资源 |
| ② 部分 | 只完成 1/N 步后提交 | 服务端只查「会话活着」不查「是否完成」 |
| ③ 显式放弃 | 某步回放弃标记(如 `SKIP`)后提交 | 客户端可单方面跳过 |
| ④ 全完成 | N/N 后提交 | **阳性对照**,必须到场,否则前三档的「命中」可能只是接口坏了 |

- ★★ **强制零步/放弃必须打脚本补丁**:交互驱动的模板往往在「本地自动解出答案」时 `val=<答案>` **覆盖**你喂的放弃标记 ⇒ 在**解得出的步**上推 `SKIP` 是无效实验(静默变成正常提交)。正确做法 = 加一个编译期/ env 开关,在模板内把 `val` 强设为放弃值后再 `break` —— 单变量,复用全部管道。
- ★★ **一次拒绝 ≠ 闸门成立**:同形态两次尝试可能给出相反结论(放行 vs `400 会话已失效`)。先拉齐其它变量(同一出口、同一凭据新鲜度、同一管道),再单独变「间隔秒数」。

## 2. 会话时效是最常见的混淆项

- 带挑战会话的接口普遍有短 TTL(实测 **60–73s**):`开闸→完成步骤→提交` 全链必须在**同一进程一条命**内跑完,人工看图必经会话失效。
- ⇒ **每发带时间戳**,并记录关键动作间隔(`开闸→提交` 秒数)。实测 `≈40s` 放行并真的产生业务记录、`≈80s` 回 `400/40705` ⇒ 决定变量是**会话年龄**,不是「验证完整度」。把 `completed=false` 仍放行写成「验证码只是装饰」,并附服务端记录,而不是「理论风险」。
- 凭据(如一次性登录票据)一律**铸新与使用同一次运行内完成**,跨调用必过期;过期表现为握手失败/专用 TTL 码,极易误读成协议错。

## 3. 状态变更归属:只认服务端三件套

```
① 业务记录数组   如 claims[] = {seq, amount, user_id, ...}
② 流水/账单     带**分钟级时间戳**的入账记录(定位「哪次会话产生了这笔」的决定性证据)
③ 余额/持仓     变更后的权威数值
```
- **不要拿本地日志当证据**:下一次运行会覆盖,且驱动常未序列化后态字段。
- 三条必须**逐笔对齐**(金额、序号、用户 id、时间归一到同一个分钟窗),一致才写结论。

## 4. 实验对象设计(四个硬约束)

1. **新鲜**:已被消耗完的对象(剩余 0 / 已结单)无法再验闸门 ⇒ 另建一个**专门用于判决**的对象。
2. **可回收**:只在自有账号/自有资产间流转,金额取**最小值**,到期原路退回;事先答两问——最坏损失多少、能否原路取回。
3. **受余额硬限**:建对象的额度门槛由**当前余额**决定,会先于任何「最小额」声明触发(余额不足直接回绝)。先看余额再选额度。
4. **单变量**:一次只改一个开关,其余管道/凭据/出口全部复用。

## 5. 判定前的读码纪律(避免两段白烧)

- **env 开关名常与语义相反**:`MINT_SKIP=1` 类名字可能表示「复用现有凭据」而非「跳过校验」⇒ `grep` 驱动脚本里该 env 的读法再用;用错会静默复用过期凭据,把 TTL 码读成鉴权/协议错。
- **前缀/载具不要猜**:同一对象通常有五套载具(裸载荷 / 动作前缀 A / B / 列表前缀 / URL 深链),各自只贴在特定入口;前缀**几乎只出现在客户端渲染物**里 ⇒ 读渲染出来的按钮 URL 与其 query 拿真前缀(实测:猜前缀一律回「链接无效」,读到真前缀后一击命中)。URL 型按钮通常无 click API,等价复刻 = 把 URL 里的参数**原样取出、原样送回**给对应深链接口。
- **状态异常类错误先查前置状态**:对象未置位时下游会回专用码;先置位(前置动作)后同请求转 `200` ⇒ 遇「状态异常」别先怀疑签名/凭据。

## 6. 拉取远端新材料时的本地缓存坑

远端文件名每步相同而本地按路径去重 ⇒ 取件会跳过下载,表象是「服务端不再下发材料」。取新件前先清 `seen`/`fetched` 缓存或按时间戳改名。
