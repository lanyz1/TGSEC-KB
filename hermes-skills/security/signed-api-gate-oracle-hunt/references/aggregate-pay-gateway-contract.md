# 聚合支付（易支付/彩虹系）网关端与商户端契约

适用：目标是自建聚合支付/四方支付平台（PHP 版，`submit.php` + `api.php` + `/user/` 商户端）。
用途：在**拿不到密钥**的前提下，用契约本身把攻击面摸完（ID 池、登录三要素、签名样本、配置载体）。

## 0. 先分流：同品牌两套实现，打法不通用
- **Vue3 后台族**：`/admin/` + `/admin/auth/login` + `index-*.js` 分包。契约在**外链 JS 分包**里，用 `grep -hoE '"url":"[^"]+"'` 抽全量 API。
- **PHP 二开族**：`/user/login.php` + `/user/ajax.php` + `submit.php` + `api.php`。契约在**页面内联 `<script>`** 里（常 3–10KB）。
两者同品牌但路径/参数/鉴权全不同，**先看入口形态再选路**。

## 1. PHP 二开族：先读内联 JS，再动手
内联 JS 里直接写着 `$.ajax({url,type,data})` ⇒ 方法 + 参数名 + 开关常量全在里面。
**铁律：动手 fuzz 之前先 dump 内联 script。**

关键判别式：**同一端点换 3+ 个参数值，错误文案一字不变 ⇒ 传错方法/参数名，不是值错。**
典型陷阱：只读 `$_POST['type']` 的端点用 GET 查询串打，恒回 `msg:"no type"` —— 换成 POST body 同参立刻回真业务结论。

**缺 `Referer: https://<host>/user/login.php` 时，AJAX 入口回 `{"code":403}`** —— 那是入口拦截，不是权限不足；补 Referer 即通。

## 2. act 表（`/user/ajax.php`）
| act | 作用 | 契约要点 |
|---|---|---|
| `login` | 登录 | POST `type,user,pass,enc,csrf_token` + 验证码字段 |
| `captcha` | 取验证码 | 回 `{success,gt,challenge,new_captcha,version}` |
| `connect` | **切换登录方式**（不是登录） | 只吃 POST `type`；`type=1` 账密 / `type≠1` **ID+密钥登录**；回 `未开启当前登录方式` = 站方关闭了密钥登录 |
| `findpwd` / `sendcode` | 找回密码 / 发码 | 存在性校验常排在 code 校验之前 = 账号枚举 oracle；`sendcode` 关闭则链断 |
| `reg` | 注册商户 | 常回 `未开放商户申请` |

- **密钥登录（`connect`）是否可用必须实测**：后台可一键关闭，开了才谈 pid+key 直登。
- `pwd`/`enc` 语义见下节。

## 3. 登录三要素速判（开局先跑，避免整轮白做）
1. **`enc` 语义**：页面 JSEncrypt 且 `PUBLIC_KEY_PEM` **非空 ⇒ `enc=1`**（RSA 加密密码；公钥是公开材料，取回来自己加密即可，**不是障碍**）；为空 ⇒ `enc=0` 明文。
2. **验证码是否服务端强制**：页面里的 `captcha_open` 只表示 **DOM 里有 `#captcha`**，**不代表服务端校验**（该值可为 0 而服务端照样拦）。用登录报错判别：
   - `验证加载失败` = 缺字段 / 取号接口瞬时抖动（补字段或重试）
   - `验证失败，请重新验证` = **服务端真校验**
3. **CSRF 是否强制**：去掉 `csrf_token` 再打一次，报错一致 ⇒ 未强制（校验顺序常在验证码之后）。

## 4. 验证码（极验）判别与止损
- `version:0` ⇒ **v3**，字段 `geetest_challenge` / `geetest_validate` / `geetest_seccode`
- `version:1` ⇒ **v4**，字段 `lot_number` / `captcha_output` / `pass_token` / `gen_time`
- `success:1` = 服务器向极验取号成功（在线）；`success:0` = **离线模式**（此时才有字段绕过空间）

**服务端真校验时，字段绕过矩阵（`|jordan`、`md5(challenge)`、全 1、空字段、字段名变体…）全灭。** 先看报错措辞确认是不是真校验；是真校验就上真浏览器解题，或干脆改走无验证码的 API 面，别在字段矩阵上耗。

## 5. 商户 ID 枚举 oracle（零凭据）
`GET /api.php?act=query&pid=<N>` **不带 key**：
- `商户ID不存在` ⇒ 无此商户
- `商户密钥错误` ⇒ **该 pid 存在**（只差密钥）

⇒ 无需任何凭据即可**全量测绘商户池**（pid 的连续段常密集命中）。**先测绘再谈爆破**：拿到真实 pid 列表，靶向才成立。
- 同族 `api.php` act：`query` / `order` / `orders` / `settle`（均需 `pid` + `key`）、`refund`（回「未开启商户后台自助退款」= 功能存在但未开）。
- `submit.php` 缺 `pid` 回 `你还未配置支付接口商户！`。

## 6. 已知明文签名样本（离线破 key 的唯一正确起点）
从**商户面板侧**建一张最小额未支付充值单 → 跳转页回吐完整 V1 表单：
`action`（**真实网关域名，常≠你以为的网关**）、`pid`、`sign_type=MD5`、`money/name/notify_url/return_url/sitename/type` 明文 + `sign`。
⇒ 得到一对 `(明文参数串, sign)`，可离线验证密钥假设与**编码细节**（中文参数是否 urlencode 会整体改变签名串）。
彩虹 V1 算法形态：`md5(ASCII 升序参数串 + KEY)`。

**建单属可接受的写操作**（未支付待付单、零资金变动、绝不付款）；其余破坏性写一律不做。

## 7. 配置载体与安装残留
- 支付配置常落在同目录一个「哑」PHP 文件：**`[200]` + `len=0`**，而兄弟文件 `config.php`/`db.php`/`epay_config.php` 全是真 404 ⇒ **那个空体文件就是配置载体**（`<?php return [...]>`）。
  判据 = 「同目录兄弟全 404 + 它 200 空体」。确认存在但读不到就转 LFI / 备份名变体 / 源码包，**别在 `.bak`/`~`/`.git` 上耗**。
- `/install/` 常见回「已成功安装，如需重新安装请手动删除 install.lock」⇒ 安装目录残留存在。**重装会覆盖 DB 配置，属破坏性，不主动做**；优先看只读的 step 回显 / 安装 SQL。

## 8. 离线破 key 的止损线
- 候选集只从**站点派生 + 编码变体**构造（10⁴ 量级），**零命中即结论：密钥是随机串，不是弱口令** ⇒ 立刻转「读配置」路径（第 7 节）。
- **不要把候选扩到 10⁷** —— 大字典，须先请示，且大概率仍零命中。
- **别把每条记录里的随机 32hex 列当成站点主密钥**：一列 32hex 若几乎「一记录一值」，那是**每单独立密钥**；可以试一次，但不当主攻假设。

## 9. 权限模型
商户面板常见**代理级受限账号**：能登录、能建单、能看到自己的页，但订单/收款/网站子页全跳同一个 `mod=` 值 ⇒ **上游支付 KEY 属站长层，代理看不到**。
判据：同一 `x.php?mod=<v>` 换多个 v 回**同一字节数**的同一个页面 = 参数无效、权限封顶 —— 不是「还有没探到的取值」。
