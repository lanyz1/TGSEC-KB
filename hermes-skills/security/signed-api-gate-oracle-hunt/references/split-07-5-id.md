## 5. 缺口收敛:同一句鉴权错 = 只剩一个实例 ID
- 所有写面(上传/落盘/提交)都回同一句鉴权错 ⇒ **不要再找新端点**,改为枚举那个能解锁一切的实例值。
- **免费存在性预言机**(无鉴权、无签名、响应区分存在与否):`orders?orderNo=X → 进件不存在`、`verify{userId} → 会员N不存在`、`getcontract?order-no=X`、`getXxxByCustId`。响应带格式化数字(`会员1,000不存在`)= 服务端真读了你给的值。
- 值从哪来(并行三路):① 未鉴权的 CRUD 表端点直接读;② 签名预言机生成带真实实例 ID 的链接;③ 短信/验证码链中的手机号或用户 ID 字段。
- 短信链的字段名与顺序全靠报错驱动:`{phoneNo}` → 再要 `{orderNo|applyNo}` → 再要 `{smsCode}`;**先试固定测试码(123456/888888/000000)再谈爆破**。
- **★ 缺凭据时的「ID 池测绘」形态**:同一端点只补唯一必填 ID 而不给密钥,服务端回**两句不同文案**即构成零凭据存在性 oracle —— 例:`api.php?act=query&pid=N` 回 `商户ID不存在`(无) vs `商户密钥错误`(**存在**,只差密钥)。此类 oracle 可**全量测绘 ID 池**(连续段往往密集命中),先拿到真实 ID 列表再谈任何爆破与靶向,否则爆破没有靶。
- **★ 权限封顶的判据**:同一端点换多个取值(如 `x.php?mod=user|site|order|...`)回**完全相同字节数的同一个页面** ⇒ 该参数无效 / 该身份无此权限,**不是「还有没探到的取值」**;停止枚举该参数,改换身份或换面。
- **★ 读『他人数据』的身份参数:全零/默认载荷 ≠「目标余额为 0」**。判据 = 补一组**随机/不存在 ID 对照**:目标ID 与随机ID 载荷逐字节一致 ⇒ ID 参数被忽略(handler 只认会话身份)——带自身会话时它返回的其实是**你自己**的账号数据;不带会话的 app 上下文则可能恒全零。⇒ 先补对照、再用响应字段核对结果归属,别把「参数没生效」写成「目标为 0」(与 `*ForThirdParty` 标定同一机制的常规端点版)。

- **★ `*ForThirdParty` 端点族 = 免用户 token 的神谕候选**:规格/命名里含 `ForThirdParty` 的口常为第三方集成面,其中部分**不校验用户 token**、按标识参数直接查库。**先标定再采信**:拿**已知真实标本**与**确不存在标本**各打一发——真标本返真实行、假标本返全零/默认 ⇒ 判别神谕成立,可枚举、可校验;**两者同返同一默认** ⇒ 两种解释先分清:① 该实例是桩/测试部署;② **ID 参数被忽略、只按会话身份作答**(带自身会话时载荷 = 你自己账号的数据)⇒ 换栈/换 ID 皆无效功,改换能代表目标身份的凭据或换读链族。
- **★★ 同族内必须逐端点做三值差分,严禁按族推广结论**:同一命名族(资产族 / `*ForThirdParty` / `getUser*`)里,**端点 A 丢弃 `uid` 而端点 B 认 `uid` 并返回目标数据**是常见的共存形态。做法 = 每个端点各取三发(**不带参数 / 目标值 / 随机垃圾值**),并核对响应体里**回述的对象标识字段**(`uid`/`userID`/`thirdPartyUserId`)是否等于你投进去的值。⇒「族内某个端点丢弃参数」只能写「**该端点**无越权读路径」,写成「该族无越权」会被同族兄弟端点整体推翻。
- **★ 免鉴权配置响应 = 标本库**:`getConfig` 族常泄露真实账号 id / 审核账号 / 样例主键——拿到就登记,后面一切神谕标定与差分实验都用它们当「已知存在」正样本。
