# 未授权攻击面全量测绘法:从 SPA 包拿到整站端点,再逐类分档

> 2026-09 灰豚数据(huitun.com)实战。适用任何"SaaS 后台 + 全局登录过滤器 + 前端包公开"的目标。
> 目标:在**没有凭据**的前提下,把"哪些接口未授权可读"一次性测干净,而不是靠猜路径。

## 0. 为什么先做这一步

SPA 的整站接口清单**就躺在公开的 JS 包里**。一个 2.3MB 的 UMI 主包,
用一条正则就能吐出一千多个路径 —— 比任何字典爆破都完整,而且零请求、零风险。
拿到清单后再做**一轮受控枚举**,就把未授权面钉死了。

```bash
# SPA(Vite): 主入口 + chunk
curl -s --compressed https://target/js/index-*.js -o main.js   # 必须 --compressed
# UMI/PC 端: /app/umi.<hash>.js(2MB 级,路由与接口全在里面)
grep -oE '/([a-zA-Z0-9_]+/){0,4}[a-zA-Z0-9_-]{3,60}' main.js | sort -u
```

过滤噪音后按"业务动词"排序:`user|order|pay|vip|shop|brand|anchor|export|list|detail|info|acc|auth|token`。

## 0.5 有端点映射对象时:一次拿全契约(比全量正则更准)

框架自带的**端点映射对象**是最完整的契约来源 —— 键=功能名、值=路径,含 `:id` 占位与 `:entityGroup` 这类集合型路由。
先找标记:`baseUrl:"` / `endpoints=` / API 前缀字面量(`"/webapi/"`)。

**用窗口正则,不要做花括号配对** —— 压缩代码里 key 不带引号、嵌套深、尾逗号多,配对必失败:

```python
i = js.find('baseUrl:"/webapi/"')
pairs = re.findall(r'([A-Za-z0-9_]+):"([^"]{1,120})"', js[i:i+30000])
```

一次可得数百条路径;键名本身就是靶单(SQL 查询/导出、子账号切换、导入导出模板、发送域设置、白标配置 = 高危候选)。
分类同 §2 —— **鉴权错误(如 `EAUTH`/`Unauthorized access`)与「该 build 不存在此路由」的框架 404 必须分开记**:前者是“存在且需鉴权”,两者合起来才勾出实际攻击面。
枚举与落盘同 §1,**大 minified 包拉回本地再 grep**,不要在远端反复改正则脚本。

## 1. 枚举姿势(受控,不爆破)

- **GET 逐个打**,串行 + 0.3s 间隔;结果**追加写 tsv**(`路径 / 状态码|长度 / 分类`),后台长跑
- 只当"**可达性探测**",不带 payload;单个接口一次
- 1310 个端点 ≈ 7 分钟,产出一张可复用的判据表

## 2. 分档判据(核心:别只看状态码,看 body)

| 响应特征 | 含义 | 后续动作 |
|---|---|---|
| `{"code":-200,"message":"登录状态已失效，请重新登录!"}` | 被**全局登录过滤器**拦(假 200!) | 记录,别在这条上耗 |
| `{"code":500,"message":"系统异常"}` | **已过过滤器**,控制器抛异常(缺参数)→ **白名单端点** | ★ 去 JS 抠参数,凑齐即可调用 |
| `code:0` + 真实结构数据 | **未授权可读** ⇒ 就是战果 | 取全量 + 解密 + 量化 |
| `{"code":-1001,"msg":"用户登录状态不可用!"}` | **第二层鉴权(在 body 内)**,与过滤器不同源 | 别当"未授权",换别的面 |
| `{"timestamp":...,"status":404,"error":"Not Found"}` | Spring 风格 404 ⇒ **不是同一套应用**(兄弟系统的自有错误页) | 说明该 host 无此路由,另建清单 |
| `405 Method Not Allowed` | 路由**存在**,只是方法不对(多为 POST-only) | 用 POST + `{}` 重测 |
| `400 Bad Request` / `422 参数缺失` | **鉴权已过**,在等参数 | ★ 高价值:抠参数 |
| 同 IP 换 `Host:` 头后结果一致 | 兄弟 vhost 共用同一应用(测试环境副本),**没有更松的过滤器** | 别在 Host 差分上继续投时间 |

**教训**:全局过滤器是**方法级 + 路径级**白名单 —— 同一路径 `GET /login` 被过滤,
`POST /login` 却直达 Spring Security(`Bad credentials`)。所以**每种方法都要单独测**。

## 3. 同品牌多 host:必须**各建一份清单**

一次实战里同一品牌下有 4 套后端,鉴权模型完全不同:

| Host | 返回特征 | 结论 |
|---|---|---|
| `dyapi.*` | 统一 `登录状态已失效` | 有全局过滤器(但有较宽白名单) |
| `jjapi.*` | 404 一堆 + 少数 SYSERR | 另一套应用 |
| `orderapi.*` | 405 一批 + `2048 登录状态已失效` | **自有会话校验**,`X-Session-Token` 头注入 |
| `fxapi.*` | `1002 用户信息无法解析` | 又一套(用户信息解析失败 ≠ 登录失效) |

⇒ **从 A 主机挖到的端点清单不能套用到 B 主机**;每台都从它自己的前端包挖。

## 4. 顺带白拿的 recon

- **Actuator 索引泄真实上游**:`GET /actuator` 的 `_links.self.href` = 内网真实后端
  (本次 `https://api.supsaas.com:9080/actuator`)—— 网关后面的服务名与端口白拿
- **`/v2/api-docs` 公开** = 完整接口 + DTO(含租户字段名、`data-view-id` 这类自定义租户头)
- **未授权接口里常有配置泄露**:本次 `work_config` 泄出企业微信机器人 **Webhook key ×2** + 内网 `172.17.0.145:8xxx`
- **文档/公告类接口**(`/work/notice` 之类)常明写**权限分级** ——
  "仅限豪华版及以上用户使用" 这类原文,是判定"数据在付费墙后"的**一手证据**,写进报告比推断有力

## 5. 陷阱

- **别用 md5/长度比对判断"参数是否生效"**:`encrypt:true` 的响应每次密文都不同(key 由时间戳派生),
  天然无区分度(见 `webapp-api-crypto-reverse/references/spa-static-key-envelope-cracking.md`)
- **SPA fallback 会让任意路径返回 200 + 首页 HTML**:先看 body 是不是首页,再判"路由存在"
- **分页参数无效也是一种结论**:`total=10001` 但 `page/pageNum/pageNo/current/offset/limit/pn/p` 九种全试仍回同一批
  ⇒ 这是**固定榜单接口,不是可翻页数据集**,别按"10001 条可拖"写报告
- 枚举结果里 `404/000` 要复测一次(偶发抖动),别一条即判死
