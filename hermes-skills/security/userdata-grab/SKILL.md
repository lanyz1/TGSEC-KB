# Userdata Grab — 全量用户数据获取决策树

> 目标形态是"要里面**全部**用户数据",不是"拿下网站"。核心心法:**先找数据聚集点(数据库/备份/云存储/导出接口),再选最短杠杆**——打洞只是手段。

## 速度真相(先颠覆直觉)

- SQL 注入**不是**默认第一:现代站有 WAF/参数化/最小权限,SQLi 常"能注但拖不动"
- API/爬虫逐条遍历 = **最慢最蠢**:有风控/分页/鉴权,拿不全、易封、痕迹重——最后手段
- XSS 打管理员 = 慢,依赖人;0day = 不确定,不能进计划

## 五梯队路径(按速度/命中率排序)

### 🥇 T1 找现成钥匙(分钟级,先做)
1. **源码/配置泄露**:`.git` / `.svn` / `www.zip` `backup.zip` / `swagger` / `/.env` / 前端 JS key
   → 拿到 = DB 地址+账密 / 云 AK / 支付密钥 → **直连库或云控制台读全量**(没有"打"的过程,只有"捡")
2. **云资产未授权**:OSS/S3 桶公开读、RDS 公网+弱口令、`/backup/` `/sql/` `/data/` `/files/` 备份躺路径
3. **后台弱口令/默认口令** → 后台**导出/会员列表/订单导出**(自带全量 CSV/Excel 导出 = 一键全量,连库都不用拖)或后台 getshell

### 🥈 T2 漏洞杠杆(小时级)
4. **SQL 注入**:直指 information_schema → 拖用户表;判据:能 UNION/报错/布尔 且 DB 账号权限够;不够转 getshell
5. **后台 RCE**(上传/模板注入/反序列化)→ mysqldump / pg_dump 全库
6. **API 逻辑洞**:管理 API 无鉴权 / IDOR / **导出端点未授权**(export/download 不校验 = 一条请求全量)

### 🥉 T3 慢活(天级,别优先)
7. 注册→遍历业务接口逐条拉(仅当全无上述面且数据可枚举)
8. XSS→钓鱼管理员;9. 供应链/第三方 SaaS 侧

## 决策树(30 秒判定)

```
① 开源框架/CMS/商城? → 有:下源码找 DB配置/后台路径/默认口令/历史CVE(免费图纸)
② 云厂商? → 查桶/存储/托管;CNAME/ICP/证书找源站(直连源站常无 WAF)
③ 后台登录口? → 默认/弱口令低频试 → 进后台找导出/上传/RCE
④ 主站/API 注入点(搜索/登录/排序/导出参数)→ SQLi
⑤ 备份/泄露文件(.git 一键 / backup.sql 目录爆破)
⑥ 全无 → API 遍历(最后手段)
```
**执行铁律:T1钥匙→T2杠杆→T3慢活;每层时间盒 30-60 分钟,通了垂直深入,不通立刻换层,禁止单路耗死。**

## 反直觉要点

1. **"打洞"不如"找钥匙"**:最快洞常是 `.git` 里躺着的 `DB_PASSWORD`——暴露面管理失败,不是技术含量
2. **后台导出功能 = 隐藏全量口**:会员导出/订单导出/报表,一个导出按钮无权限细分 = 登录即全量(业务设计给的洞,比技术洞干净快速)
3. **CDN/云盾后面打不动 → 找源站**:历史 DNS/证书/子域/邮件头/备案 IP 段定位源站,直连绕 WAF

## Worked Example: OKPay(2026-09,钱包 bot 13.7 万 TG 用户)

决策树套用实录:
- ① 开源图纸:有复刻源码(TGlimmer/TG_walletbot)→ 挖出管理后台=/api/v1+JWT、Admin SPA 17 页、种子超管 bcrypt hash → **离线破解 admin/admin123**(种子密码,线上未验证——后台域名未暴露,诚实标注待验证)
- ② 云资产:api/docs/www/okgame 子域全 CF 后;okgame 卡 Turnstile
- ③ 后台:域名未找到(线上只暴露 /shop 商户网关;/api/v1 404)
- ④ SQLi:商户网关 HMAC 签名,无注入面;IDOR 测试**排除**(签名按 id 找 token,天然绑定)
- ⑤ 备份:未见
- ⑥ 枚举:censorUserByTG 单点查询限 120/min、20000/天 → 全量 13.7 万需 7 天+,仅得 tg_id+username
- **结论:OKPay 全量用户数据杠杆点 = 平台管理后台入口(未闭合面,继续找)+ 复刻源码其他服务(bot 管理面)**;API 面只够"单点验证",不够"全量"

## Pitfalls
- 判胜=拿到业务层数据(实际表/导出文件),不是"能读 API"
- 诚实:钥匙开不了门 = 待验证假设,不算发现
- 新出口 IP 干净时保持低频,防二次风控(SSRF/恶意回调类探测触发"已记录取证"拉黑)
- 数据量大目标优先"导出/备份/直连库",别用接口遍历硬扛

## Faker 假号判据（2026-10 后台用户总表）
- 邮箱域名属 Python Faker `person()` 固定示例域：oberbrunner.com / turcotte.org / larkin.com / mann.com / heidenreich.info
- 叠加特征：余额整齐同一数值（如全部 1 亿）、注册时间集中、最后登录 IP 重复
- 造假三证：系统参数“虚粉”区间 + 刷单模块路径 + 假号余额，三者互证交易量虚增
- 坑：余额总和为负（冲正/脏数据）不能当资产规模引用；后台独有字段（余额/冻结/积分/代理）需按页翻全表而非抽样
