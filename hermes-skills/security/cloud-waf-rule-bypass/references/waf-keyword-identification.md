# 定位 WAF 在匹配哪个关键词

适用：已确认“被 WAF 拦”（拦截页 / 连接被切），但**不知道该改哪一部分**。
拦截页只回答“被拦了”，不回答“被哪个字拦的”。关键词猜错 ⇒ 在同一根因上反复换 payload，
既烧出口配额，又有把源 IP 打进硬封的风险。

## 1. 定关键词：异构入口共享子串法

**判据：若 N 个语义完全不同的入口同时被拦，而它们只共享一个子串，则 WAF 匹配的就是那个子串。**

实测（框架路由型目标，各入口分别覆盖输入过滤 / 模板 / 文件写 / 会话 / 异常处理五个不同子系统）：

| 入口 | 含什么 | 结果 |
|---|---|---|
| `…/Request/input` | 命名空间前缀 | 拦截页 |
| `…/view\driver\Php/display` | 命名空间前缀 | 拦截页 |
| `…/template\driver\file/write` | 命名空间前缀 | 拦截页 |
| `…/Session/set` | 命名空间前缀 | 拦截页 |
| `…/app/error` | 命名空间前缀 | 拦截页 |

5 个入口语义互不相干，**唯一公共子串 = URI 里的框架命名空间前缀**
⇒ 关键词是**命名空间**，不是那个公网流传的 gadget 函数名。
**⇒ “换 gadget 家族”在这一层上完全无效**（它们都含命名空间），不要再逐个试 —— 这是最常被浪费的一轮。

同时对照：同一目标的**正常路由**回真实业务页 ⇒ 证明是**特征匹配**而非全站封禁/IP 黑洞。

## 2. 关键词隔离矩阵（定位到具体词）

每发**换一个出口**，只看“拦截页 / 应用响应”二值：

| 探测 | 若被拦 ⇒ 关键词含 |
|---|---|
| URI 只含词 A（不带任何特殊分隔符） | 该词单独即触发 |
| URI 只含词 B | 同上 |
| 干净 URI，词全放 body | **body 是否也被查** ← 分水岭 |
| 干净 URI + 完全无关键词的正常路由 | 对照组：必须回应用响应，否则本批作废（§4） |

**“body 是否也被查”决定后续全部路线：**
- body 不查 ⇒ 关键词全搬进 body，URI 只留干净形态，路还通。
- body 也查 ⇒ 转 Host 行归一化（主卡 §2），或换攻击面。

## 3. URI 编码类绕过：实测全负，别再烧配额

**这类 WAF 先解码再匹配，编码变形对它是无效功。** 实测每发均回拦截页：

| 变形 | 结果 |
|---|---|
| `%255C` 双重编码 | 拦截页 |
| `%5C…%5C` 混合编码 | 拦截页 |
| 大小写变形（框架类名本不敏感） | 拦截页 |
| `//` 双斜杠 / `./` 路径噪声 | 拦截页 |
| overlong UTF-8（`%c0%af` 类） | 骗过 WAF，但**下游 web server 解不出路由 → 原生 404** |

两条教训：① 编解码层绕过是无效功（主卡 §3 的“一个字符、在关键词内部”是另一回事，两者别混）；
② overlong 类即使骗过 WAF，**下游解不出路由 ⇒ 没有可用性**（返回的是 web server 原生 404，不是应用响应）。
**把这几发省下来做 §2 的关键词隔离。**

## 4. 作废批次的读法（与主卡 §5 基线铁律配对使用）

一批里若**已知必定通过**的那一发也回 `000`（连接被切）/`520`（限速），则整批**无信号**。
- 症状：同批 `000`/`520`/200 混杂，且 200 只出现在**批的前几发**。
- 处置：记「本轮作废」→ 换新出口 → **先复跑对照** → 再复跑 payload。
- 反面：把作废批次里的“疑似可行”当已可用，或把“没回拦截页”当已绕过。

## 5. 关键词确实在 URI 路径且编码无效时的下一步（按性价比）

1. **关键词隔离**（§2）—— 2~3 发定死 body 是否被查，决定后续全部路线。
2. **换层面**：Host 行归一化换规则桶（主卡 §2）；挑战型则走 `challenge-waf-channel-ops`。
3. **找不含关键词的入口**：URI 保持干净形态、关键词全走 body。候选面窄，
   **且任何这类入口都必须先复跑对照组才算数**（§4）—— 未成批验证前不要写成结论。
4. **换面**：路由层被特征锁死时，转前端/接口层取数或换下一目标，别在同一关键词上持续消耗。

## 6. 记录纪律

- 判 WAF 层次**必须留原始响应类别**（拦截页正文长度 / 应用页 / `000` / `520`），
  不同层次的处置完全不同；把“被拦”笼统写成一个结论会误导后续。
- 拦截页可作指纹留存（标题 + 字节数），**不要整页贴进报告或上下文**。
- 只写**实测命中**的绕过行；通用绕过表上的行未实测不得写成结论（主卡 §3 的纪律同样适用）。
