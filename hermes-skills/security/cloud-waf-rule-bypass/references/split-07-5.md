## 5. 纪律与坑

- ★ **枚举期间周期性重打一条已知基线 URL,并信它胜过信结果**:云 WAF 的并发限流**不报错**,
  而是**换一个响应类别**(实测 ~10 并发时本该干净的 404 改回 **HTTP 200 + 0 字节**)。
  基线类别一变 = 正在收集**假阴性**,立即停并降并发(低并发 + keep-alive + 熔断退避 + 命中即时落盘)。
  ⚠ 「扫完 N 条零命中」只有在**全程基线正常**时才是对目标的结论,否则只是限流的自画像。
- ★★ **控制组也挂了 ⇒ 整批作废,不得当 payload 结论**(本类最贵的误判):一批探测里若**已知必定通过**的那一发
  (首页/正常路由)也回了 `000`/`520`,则出口桶已在批中途被烧,后面所有行(含本来会通过的那些)**全部无信号**。
  症状组合:同批内 `000`/`520`/200 混杂,且 200 只出现在**批的前几发**。
  正确处置:记「**本轮作废**」→ 换新出口 → **先复跑对照(首页必须回 200)** → 再复跑 payload。
  错误处置:把作废批次里那几发“疑似可行”当已可用、或把“没回拦截页”当已绕过 —— 两边都会写错结论。
- **别把"绕过"当成果**:绕过只是解锁面,成果必须是落到的东西(shell / 会话 / 数据)。
- 走跳板机架 OOB 监听时,杀监听用端口不用模式:`fuser -k 8899/tcp`;
  `pkill -f "http.server 8899"` 会匹配远端 shell 自己的命令行把会话带走(回空输出 + exit 0)。
- 源站 IP 直连是**授权范围内的验证动作**,不是漫无目的地扫全网端口;每 IP 先控制组再下结论。
- 全过程出口走跳板机,不暴露作业人本机 IP。
