## 6. ★ 修正：POST 通道存在于「分号后缀」形式（2026-09 实测，推翻 §3b 的旧结论）

实测隔离矩阵（同一出口、同一 URL、逐变量）：

| 请求形式 | 结果 |
|---|---|
| 裸 GET / 铸 token GET | ORIG（直达源站） |
| GET + 自定义头（无体） | CHAL　← **自定义头本身就是触发器** |
| GET/POST 无自定义头 + 体 | CHAL　← **请求体也是触发器** |
| **POST `/<真实路径>;x=.js` + 自定义头 + 体** | **ORIG（无质询）** |
| **同上，不附带任何 token** | **ORIG（仍无质询）** |

⇒ **路径分号参数后缀命中静态后缀白名单 ⇒【任意方法 + 自定义头 + 体】整体免质询，且不需要铸 token。**
Tomcat 把 `;x=.js` 当 path parameter 剥离后交给后端 ⇒ 后端仍拿到真实路径。
⚠ **「免质询」≠「能调用」—— 能否到业务 handler 完全取决于栈，必须用 404 形态实测判死，不得假定**:
Spring 栈落到真 handler 并回业务 JSON；**Servlet/JFinal 栈落到 DefaultServlet ⇒ 容器原生 404**
(实测同一真路径带 `;x=.js` 回 `404 Not Found Powered by JFinal`，而不带后缀回 JFinal 应用层 JSON)
⇒ 该通道在非 Spring 栈上**只是分层/存在性 oracle**，业务调用仍要另找运输层。
判据:两个 404 都是 404，唯一区分是**产出者署名**(容器 404 = `Tomcat/8.5.x`/纯 HTML；应用 404 = 框架署名如 `Powered by JFinal`，或 JSON 错误体)。
★ **后缀白名单优先于 header/体触发器 —— 别拿带后缀的请求去推断「触发因子是什么」**:
命中静态后缀时，header 与体的触发作用被整体绕过(实测同一目标裸 GET 加 `Origin`/`Referer`/`X-Requested-With` 全部仍 CHAL，
唯 `;x=.js` 变体 ORIG)⇒ 判「自定义头是不是触发器」必须用**不带后缀**的路径跑 header 差分矩阵，
否则会把"后缀优先"误读成"头无关"，并据此否掉整条绕过路线。

执行要点：
- 编码/头名**必须对照前端拦截器源码逐行核**（二手笔记会错）：编码器可能 `btoa`（b64）也可能是 hex，错一个就回 `Invalid encrypted request`。
- WebCrypto 的 OAEP hash 由 `importKey` 参数决定；`encrypt({name:"RSA-OAEP"},k,d)` 不带 hash 时用导入值，否则默认 SHA-1 ⇒ 两种都实试（成本极低）。
- 自定义头/体被拒时先做逐变量隔离，再决定换方法/换路径形态/换面。
- ★ **密文可能绑定 URI**：路径形态一变就 `Invalid encrypted request`（同出口下换后缀、换大小写均失败）⇒ 退回原路径 + 铸 token 的 GET 形式，或改用浏览器内 SPA 自发请求（钩子法）取合法签文后重放。
