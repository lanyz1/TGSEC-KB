# 加密闸 / 网关层:定层与证伪

链路为「云 WAF → 反代/网关 → 应用」时,同一个 JSON 错误体可由三层分别产生。
本文件给出定层判据、把"加密闸"证伪最省时的一发 A/B,以及**仅在确认闸门真解密时**才值得跑的算法对齐矩阵。

## 1. 响应头定层(错误文案判不了层)

| 响应 | 头指纹 | 层 | 含义 |
|---|---|---|---|
| `{"code":400,"msg":"Invalid encrypted request"}` | `Server: nginx`,**无** `access-control-allow-origin`,无框架头 | 网关/反代(加密闸) | **请求没到应用** ⇒ 应用的白名单/鉴权/路由全部与此无关 |
| 401 + 应用错误文案 | `access-control-allow-origin: <前端域>`(CORS 过滤器已跑) | 应用栈 | 已穿过网关 ⇒ 卡在 Security/鉴权 |
| 404/500 的 `{timestamp,status,error,path}` | Spring/框架头 | DispatcherServlet | ★**已穿过 WAF + 网关 + Security** ⇒ "打到最里面"的标志 |

做法:每个关键请求都 `curl -i` 记下发头,**先定层再定打法**。

## 2. ★★ 一发 A/B:这闸是真解密,还是只看路径形状

把 `X-Encrypt-Key` 换成明显非法的值(如 `AA`),其余请求原样重发:

| 结果 | 结论 | 该做什么 |
|---|---|---|
| 与完整合法信封**响应逐字节相同** | 该层**不解密**,只做结构/路径形状判定 | **立刻停手** —— 不调 OAEP hash/MGF、不查 iv/nonce 长度、不查 payload 字段名、不怀疑公钥轮换;改去枚举"哪些路径形状能过闸" |
| 响应**不同** | 该层真在解密 | 才值得跑 §4 |

## 3. 第三次对照:用页面自己的 WebCrypto 消灭"实现有偏差"

在目标页面的**同源上下文**里(CDP `Runtime.evaluate` + `awaitPromise`)用 `crypto.subtle` 按 bundle 里的参数
生成信封并发出,与本地 Python 实现的结果对照:

- 两者结果**相同**(同一种拒绝响应) ⇒ "我的加密实现有偏差"**整类假设作废**,禁止再逐参数对齐;
- 两者**不同** ⇒ 偏差在自己实现,bundle 参数值得再抠。

一次消灭一整类假设(字节序、base64 变体、字段包装名、iv 长度、nonce 是否参与派生)。

## 4. 算法对齐矩阵(仅在 §2 判为"真解密"时跑)

前端 `RSA-OAEP` + `SHA-256`,Java 后端常见默认 **SHA-1**(`RSA/ECB/OAEPWithSHA-1AndMGF1Padding`):

1. OAEP SHA-256 / MGF1-SHA-256(前端原样,基线)
2. OAEP SHA-1 / MGF1-SHA-1(Java 默认)
3. OAEP SHA-256 / MGF1-SHA-1
4. OAEP SHA-1 / MGF1-SHA-256
5. `RSA/ECB/PKCS1v15`(老代码)

命中判据只有一条:**响应类别是否变**。
**五连败 + §2 垃圾密钥同响应 ⇒ 结论是"不是加密问题"**,不是"再换一个组合试试"。

## 5. 路径形状判定(闸门只看形状时怎么办)

逐后缀 / 逐路径形状各发一发,把结果记成表。要点:

- 白名单通常是**精确后缀匹配** —— `;x=.js`、`/1;.js`、`/1/.js` 这类变形**不算命中**;
- **网关白名单 ≠ 应用 `permitAll`**:网关放行的前缀到应用仍可能 401。两份清单只能用**各自层的响应类别**分别实测,
  不可互相外推(把网关放行清单当应用白名单预测"免认证读文件"= 整轮白烧);
- 穿越类变形(`..`、绝对路径、`/etc/`、`.git`)在网关/风控层自有规则,大矩阵硬撞只换来拦截页或限流
  ⇒ 每个想法**只试少量代表变体**,先确认拦在哪一层,再决定是否值得铺开;
- 判据固定动词:**先定层 → 再定形状 → 最后才谈加密参数**。顺序颠倒就是白烧。
