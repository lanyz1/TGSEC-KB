## 对拍/手搓参考
- `references/handwrite-vs-prod-parity.md` — 手搓重写采集链与线上对拍纪律：不可变口径 / **十类必查差异**（键口径·观测时间·回填字段集·键名拼写·**输出契约两侧核（写点+读点）**·raw 扁平布局·产出侧归属·并库幂等计数·配置键权威在 ini 侧）/ 挂桩自测（**桩错 vs 码错判定**·干跑零副作用断言）/ ini 三坑 / 空集陷阱 / 收尾自检清单 / 交付形态 / **元素形状（容器对≠形状对）** / **真产物对拍三查（顶层容器+键风格 / 枚举找"缺失的腿" / 落盘格式化）** / **候选差异先证伪再实现** / **过滤型输入契约与桩的"诱惑项"** / 上机联调配方（只读·单台·小样本·**取活票**）。

- **「再核查有没有 bug」要拿可复现证据,不靠人眼**:`python -m pyflakes collector master bot tools` + `python -m ruff check --select E9,F,B --output-format concise …` 目标 **0 命中**(结果落临时文件,长输出会降级);一键版(含四个离线桩 + 非原子写/静默 `except: pass` 两处人工分诊 grep,只读不连网)见 `95306-data-collection-ops` 技能 `scripts/handwritten_static_audit.py`。**F841 未用局部变量先当「功能被静默丢掉」读,正确修法是「用它」而不是删赋值**(实例:取了 `pool.gaps()` 却从未使用 ⇒ 状态面板少显示「还漏多少」);B007 未用循环变量改 `_x`,F401 未用 import 删。lint 只盖语法层,语义级静默(桩喂假形状、字段被后写的腿覆盖、dry-run 真写盘)只能靠对拍+桩断言。
- **凡「另一个进程会读」的产物一律原子写**(temp+fsync+`os.replace`),审计姿势 `grep -rn "open(.*[\"']w" …` 逐处问「这文件被谁读」;**远端单文件裸跑的入口要自带 `_atomic_json`**(采集机上没有包可 import);多腿写同一份 json 用**字段级非空优先合并**,后写的窄字段腿会直接抹掉 `sellEnddate` 之类 ⇒ 阶段误判。
- **`--dry-run` 必须零网络 + 零落盘**:一轮正常流程含**建会话**动作(`login`/`serviceTicket`)⇒ 零网络模式只打印计划,判断全部来自本地 conf/状态/产物;要发请求的单列 `--dry-run-net` 并在启动横幅写明「会建会话」。落盘闸放**写原语内部**(模块级 `_DRY` + `set_dry()`,`atomic_json`/`atomic_text` 首行短路,`Store._dry()` 查 `self.dry or is_dry()`;**别逐函数加参数**——Store 之外还有十余处直调写盘点,加参数必漏一处,而 dry-run 真写盘是最坏失效)。
- **割接自证用「代码树内容指纹」**:对 `collector/master/bot` 按路径排序的 (相对路径+内容) 算 sha1 取前 16 位,**按内容算、不看 mtime**(tar/scp 改 mtime 不改内容);两侧一致 = 没有漏同步的文件,与逐文件 md5 台账互补(树指纹查漏文件,md5 查改了谁)。`--selftest`(离线)顺带打印 python 版本 / 指纹 / 锁路径 / conf 权限。
改手搓树时以下五条是**常驻纪律**（每条都烧过一轮自测或一次排障）：
- **被别的组件消费的产物，键名/嵌套就是外部契约**：健康/缺口/预算/传输台账这类文件，形状对而键名旧 ⇒ 消费端读到空值且不报错。**两侧都要核**：`grep` 消费端**读取点**（如 bot 里的 `machines[机]["status"]`）+ 产出侧写点，两者不一致时以**读取点的访问路径**为准（写侧多余的层级不算契约，读侧要用的层级一个不能少），再在离线自测里按读取路径逐键断言。
- **改文件名/形状/键名后，同批 `grep -rn '<旧键名>' tools/` 改掉假桩与断言**；新层要读的上游文件必须在假桩里真造出来，否则新层静默产出空结果、断言在别的名字上失败（看着像"新代码坏了"）。
- **判"缺口/名单为空"前先验 join 键的上游来源**：核对层恒空多半是**产端没记那个键**（本例报名操作只记时间、没记单位）。补在产端，不补在核对层；自测里放一条"必须被判中"的正样本，否则分支死了看不出来。
- **对拍扫描器报的每条"旧有新无"先 grep 新树核实一次再定性**（正则漏判会把真有的报成缺口）。
- **改函数签名前看清默认值，改完回读 def 行**：模糊匹配的 2 行锚点会把 `def f(a, b=None):` 悄悄改成 `def f(a, b):`（`py_compile` 查不出，运行期才炸）。
- **自测红灯先判“桩错还是码错”，禁止为了让桩变绿改生产代码**：红灯第一动作是回查线上权威口径（产出方写点 + 消费方读取点），再决定改谁；**桩的期望必须能指到老代码的具体行号，指不出行号的期望就是猜测**（常见桩错：把首轮当静默——线上基准为空时首轮本就出事件；把贪婪正则当非贪婪；绝对计数断言被前序断言污染 ⇒ 改比增量）。细节与三例见 `references/handwrite-vs-prod-parity.md` 第三节。
- **离线全绿 ≠ 形状对；手搓链的收尾必修是"上机联调（只读/单台/小样本）"**：离线桩会**迁就你喂的形状**（票池线上是 `list[dict]`、桩喂 `list[str]` ⇒ 离线绿、上机即 `IndexError`）⇒ 桩的 fixture 必须照真产物的**元素形状**造。联调在**主控**侧跑（本机从不直连采集机/目标）：`/tmp/<probe>/` 放两份手搓模块 + **只含通道键的极简 ini** + 探针，借 1 台采集机出口发个位数请求，只核**顶层键/容器路径/条数**；同一次请求 "直连 403 + 中继 200" = 架构红线的活体证据。全程不动进程、不写生产目录；崩溃在真形状上 = 联调的价值（记为对拍差异 → 修树 + 修桩 fixture → 复跑）。配方见 `references/handwrite-vs-prod-parity.md` 第十节，探针骨架 `templates/live-parity-probe.py`（首次用先 grep 本树核方法名/容器路径）。**取票必须取目标机"此刻的活票"**：票 TTL ≈6h，拿隔日票跑联调会全线 `code:100`，极易误读成"端点改了/权限不对"——只读载荷投到持票机上本地跑，票不出机。
- **收尾最后一步是"真产物对拍"，不是"源码对拍"**：`ls` 线上产物目录 + 逐个打印真产物的顶层类型/键风格/键集合（`type(doc)` + `list(doc)[:8]` 一眼定性），跟新树对照。**顶层是 list 还是 dict、键是 snake_case 还是 camelCase、落盘 indent 是多少，都算契约**，错一处该腿**静默全空**（不报错、日志干净、产物空）；源码里两边都能自洽，只有真产物能证伪。**从源码 grep 出的"线上有、我们没有"只是候选：先拿真产物证伪再动手**（真题里没有的键不要往新树加 —— 那是制造差异不是消差异）；反过来，判"有没有更新"的内容签名要容错地排除线上写入口会刷的运维水位键（混跑时会读到）。细节见 `references/handwrite-vs-prod-parity.md` 第十一至十三节。

### 上线这道关：时间尺 / 双级验收 / 分阶段割接

- **判态尺子用平台时间**：凡拿平台时间戳比大小的判据（票新鲜度、窗口、重查闸）一律 `bj_now()`（UTC+8），绝不用宿主本地 `datetime.now()` —— 同一行代码在 CST 采集机上恰好对、搬到 UTC 主控就 8h 偏差（重查闸恒不放行 = 静默漏采）。改完的闸必须**双时区跑**（默认 TZ + `TZ=UTC`），只在本机跑等于没测。细节见 `references/handwrite-vs-prod-parity.md` 第十四节。
- **验收分两级**：本机绿 ≠ 真机绿（解释器 3.10/3.11、时区 UTC/CST 都可能不同）⇒ 打包后必须 scp 到目标机、在**目标机自己的解释器**上复跑同一套关；自证三件 = 逐文件 sha256 清单全对 + 内容树指纹两侧**逐字一致** + 生产目录项数前后不变。汇报里写清“跑在哪台机 / 哪个解释器 / 哪个时区”。
- **动进程的动作留批准口**：割接工具拆 `--stage`（上包 + 解到 release 目录 + **在该机自己的解释器上**复跑全套关，只写 release 目录、不碰生产目录、不重启，默认跑这个）/ `--activate`（须显式 `--yes`，起不来自动回滚）/ `--rollback`；替换、重启、kill、改 systemd/sshd 一律先经用户同意 —— 没人答就停在只写 release 目录那一步，并在汇报里点明“就差你一句话”。
- **割接落点必须自洽：入口 + 版本化树 + 原子切链**（只装入口的割接必炸）：入口（`ExecStart` 指的那个文件）只做三件事——解析“当前树” → `sys.path` 插进去 → import 后跑；代码树放 `<根>/lib/<版本>/`，`<根>/current` 软链指过去，切链用 `ln -sfn <树> current.new && mv -Tf current.new current`（单条 `ln -sfn` 不是原子的）。**上线的那棵树必须是刚在“这台机”上跑过关的那一棵**（把 stage 目录 `cp -a` 过去，不是重新上传），否则“验过的”和“上线的”是两样东西。
  - 入口找不到树时**直接退 1 并打出回滚命令**：不猜路径、不进 systemd 重启循环（否则现场是“装了新代码的机器起不来还反复重启”，比装错更难判）；systemd 单元一个字都不用改（`ExecStart` / `Environment=<分片变量>` 保持原样）＝ 选这个布局的主因。
  - 回滚 = 老入口从 `<入口>.bak_<版本>` 拷回 **+** 旧指针切回（切链前把旧 target 存成 `current.prev`，回滚时 `mv -Tf current.prev current`），再重启自证；只做一条会留下“新入口 + 老树”的半截状态。
  - 工具三阶段、机队跑法/回读、`launcher` 契约、布局关、机队回读四行见 `references/fleet-cutover-entry-tree-symlink.md`；**主控侧变体（平铺老目录 / 无 systemd / crontab 混装受管块）+ 工装离线自证与反控 + 换常驻时 `pgrep -f` 的三层壳**见同文件后半。
- **crontab 割接只动受管块，认不出的条目一律拒绝割接**：只改 `# >>> <标记> >>>` … `# <<< <标记> <<<` 之间，块外一行不碰；开工前 `crontab -l` **全量取回逐行归类**（keep 逐字照抄 / stop / tmpl 供新条目继承 / pending 待拍板 / notes 注释 / foreign 别的项目），**别按记忆里的条数对拍**——实况常比记忆多（本次记忆 11 条、实测 19 条有效 + 1 DISABLED，多出 4 条大表拉取腿 + 反匿名/存档腿 + 运维守护）。keep 类命令行从线上**逐字**提取，`timeout 900`/日志重定向等环境一并继承，漏一项就是行为变更。逐字取回用 `ssh <host> 'crontab -l | base64 -w0'` + 本地 `base64 -d`，避开多行输出的换行/截断差。
- **自动回滚不是默认正确值，按波及面定**：无人值守机队＝起不来自动回滚；**用户可见的主控（动 bot 推送、写库、重启常驻）＝失败停在原地 + 打印人工回滚命令**（用户明确要求“不是 active 自动回滚”）。同一套工装两种语义都合法，差别在谁会吃到回滚的副作用。
- **“完全替换了吗”按层据实核**：每台/每角色**单独**查 `current` 软链指向 + 新树文件是否落地 + 老文件名是否仍被调用；**禁止用已置换的那半边推断另一半**（实况：采集端 12/12 已换、主控侧一个字没换）。
- **换常驻进程：一条角色常对应 2–3 个进程**——`bash -lc … setsid nohup …` 的**启动壳**（后台子进程继承了它的 stdout ⇒ shell 长期挂着不退）、`flock -n <锁> <命令>` 的**锁包装**、真进程。按角色 token 匹配后**全部停掉**，别把启动壳误判成“还有第二个实例”；新常驻启动命令**显式带锁**（新代码的锁名与老锁不同，漏锁＝老新各一份，bot 双实例抢 TG polling 的直接后果是两边都不回话）。
- **硬结构闸拦到自己人就抽模块，不改基线**：文件/函数超限 ⇒ 先抽 `case_x(chk, ...)`（`chk` 当参数，计数仍统一汇总），再抽伴生模块 `tools/<名>_cases.py`，主入口只留一行调用。**且 import 常是 `try/except` 两个分支**（导入失败回退另一路径）：**两个分支都要改**，只改一个 ⇒ 另一分支照旧导入旧名字、报 `NameError`，且只在跑到那条分支时才炸（实况：只改了 except 那半，夹具当场 NameError）。**加闸时不许让被棘轮冻结的入口函数变长**：N 行 `chk(*check_x())` 直接写成 `for c in (check_a, check_b, check_x): chk(*c())`，净增 0 行自然过闸（闸拦的是增长，不是新功能）。
- **闸必须断言“形状”，不能只断言“键存在”**：只查键在、值非空就收工的闸会放过真崩的形状错（例：把线上冷却表按数字播种，用它的代码却按 `{"day","n"}` 取值 ⇒ 取用点 `AttributeError`，闸还全绿）。规矩两条：①断言值的容器/类型/子键（`isinstance(v, dict) and {"day","n"} <= set(v)`）；②**至少一条端到端**——用真类实例跑真入口（真判冷却函数挡人、真取票函数跑一遍），不只调纯函数。
- **批量作业回读用“聚合计数”，不看单条**：N 台跑完看四行——完成分隔符计数 / 内容指纹 `grep -o '<指纹标记> [0-9a-f]*' | sort | uniq -c`（一眼看出哪台没换干净）/ 判定行 `grep -c 可以上` / 失败行 grep。**工具调用被中断、超时、无输出 ≠ 作业失败**：先 `pgrep -af` + 读日志核现场再决定是否重跑——批量上传类作业盲重跑会重复推送（实测工具超时，但读数显示作业早已跑完全队全绿）。
- **lint 结论必须带口径**：`python -m pyflakes <各层>` + `python -m ruff check --isolated --select E9,F <各层>`（`--isolated` 才忽略环境配置、可复现）；环境宽规则报的数百条风格项要明说“不在验收口径内”。
- **★换树后不许说「下一轮起生效」，先验「进程是不是换壳后启动的」**：bash 把脚本读进内存 ⇒ 换盘上文件对已在跑的进程无效（实况：守护 08:31:26 起、壳 11:10:46 才换）⇒ 两级判据 = 盘上壳新版（查**调用点** `$(read_sleep)`，别查函数定义）+ `/proc` 启动时刻晚于壳 mtime；取不到证据一律保守，话术只许「等它下次启动」。
- **`pgrep -f` 自匹配要连工具代码一起治**：部署工具的「停老常驻」段 `pgrep -f <老脚本名>` 会匹配**它自己那条 `bash -lc` 外壳**（症状：每个角色各一个假 PID、彼此差 12；"事后 ps 零残留"即自证）⇒ 修法三件 = 模式首字符包字符类 `[m]erge_…`、命令行里给模式加引号、`still_alive` 的 grep 用 `re.escape()`；取证要「同机同时刻 `OLD_PIDS=<有> → NEW_PIDS=<空>`」+ `--activate` 摘要逐角色 `pids=无`。
- **「全线机制完整吗 / 数据有没有缺失·遗漏·不同步」按腿对账，别拿「守护在跑」当结论**：六层只读巡检 + 逐腿给数字，结论形态是「N 条在跑 / M 条跑着不出活 / K 条断」。三条最容易漏的判据：①**陈旧状态文件指标 ≠ 停采**（12 台 `LAST轮询` 停 20h 前，真机正在跑第 201 轮 ⇒ 用真机轮次 + `/data_raw` 近 1h 落盘数反证）；②**对账不能证明上游 feed 活着**（归档自证最新一条停 9 天，而对账照样「缺 0 落后 0」，因为权威就是归档本身）；③**发布树布局下的相对路径是固定炸点**（`conf` 里 `worker = master/bk_worker.py` + cron `cd /opt/v6` ⇒ 树化后 `/opt/v6/master` 不存在，每轮 12 台报错、`DONE 0`），派发到采集机的绝对路径还必须在**目标机**存在（`/opt/v6/tools/gap_once.py` 是主控专属 ⇒ 机器侧 `can't open file`）。脚本与判据表见 `references/leg-completeness-audit-2026-10-04.md`。
- **★路径断腿的修法与「修复会生效」取证**：修法 = 抽一个公共解析器（`tree_root()` 取**本文件所在树根**、`tree_path(rel)=normpath(join(树根,rel))`），**所有**调用点共用（worker 路径、派发命令、清单/矩阵路径）；判据落在**目标机**（主控有 `/opt/v6/tools/x.py` ≠ 采集机有，采集机是树内 `<树根>/tools/x.py`）。上岗前**不动线上就能拿最强证据**：主控 `cd <树根> && python3 - <<'PY'`（带 heredoc 的 ssh 探针**不能加 `-n`**）import 在役模块，打印「实际会发的命令串 + worker 解析后绝对路径 + `os.path.isfile()` 真假 + 清单条数」，并与**老写法复算的 `False`** 对照 —— 三条一致才算成立，**「文件已落盘/已切链」不算证据**。
