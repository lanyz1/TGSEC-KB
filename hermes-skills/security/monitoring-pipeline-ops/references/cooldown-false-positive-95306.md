# 95306 风控冷却误判完整排查链(2026-09-01 实录)

> 场景:v9 collector 修复后每轮新票处理量暴增,出现"处理 1 票 → 🧊 冷却 15min → business 域全暂停 → drain 队列永远空"的循环,症状极像代码 bug。

## 时间线(识别特征)

- 每轮审计抓到 50-73 新票,但"识别 0"——user/info 无失败日志、无成功日志
- 冷却日志 🧊 出现在"处理 1-2 票后 9-12 秒",节流从 1.5s → 2.5s → 4.0s 都拦不住
- 冷却结束恢复后第一轮又触发,周而复始

## 排查步骤(按序有效)

1. **先排除部署双进程叠加**:部署重启时旧进程刚跑完一轮、新进程立即又跑 → 请求叠加撞网关限流。部署后错峰等待,勿立即验证(16:07 部署后 16:09:46 即冷却,就是这个)。
2. **给通用请求函数加响应日志再进冷却**:
   ```python
   if _is_cool_resp(j):
       log(f"  ↳ 风控响应 [{path}]: code={j.get('code')} msg={str(j.get('msg'))[:40]}")
       _mark_cooldown()
   ```
   冷却触发瞬间日志会打出接口 path + code + msg——**不要猜限流阈值**。
3. **实测抓到真凶**(17:40:51):
   ```
   ↳ 风控响应 [/bidRoom/initProjInfo?projId=121c6947-...]: code=500 msg=您没有该功能的操作权限,请联系技术支持!
   🧊 触发风控冷却 15min
   ```
   根本不是限流!`try_fetch_bids` 用任意 ST 遍历全部 targets(88 个项目)调 initProjInfo 拉出价——企业没报名的项目返回 500 业务错误,msg 含特征词"请联系技术支持" → `_is_cool_resp` 误判 → 冷却。

## 修复(三件套)

1. `_COOL_MSG` 特征词删掉"请联系技术支持",只保留确定性风控语义:
   `("系统服务异常", "操作频繁", "访问过于频繁")` + `code==100`
2. `try_fetch_bids` 降频:30 分钟一次(`state["bid_fetch_ts"]` 时间戳),原来每轮 88 目标 × 4s 节流 = 6 分钟拖死主循环(轮询从 90s 变 7.5 分钟)
3. 部署后冷却期结束再验证(15min);心跳文件写 tmp+rename 原子写防主服并发读半文件
