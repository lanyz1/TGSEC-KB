# merger 合并类陷阱 + 部署后验证(2026-09 实录)

适用于:多源采集 → 主服 merger 合并 → 面板/告警推送 类管道。

## 同键多行必须"优先级聚合",禁止后写覆盖
- 上游一行 = 一个主体(报名者/子项)时,同键(项目×包件)会有多行携带不同状态;任意后写覆盖会把"终态"盖回"进行中"。
- 实测案例(95306 8515): 同包多行 01=通过/22=中标/03=拒绝/00 → 已决标(22)被 01 行覆盖成"竞价中"。
- 规则: 定义状态优先级(终态>进行中>拒绝>待处理),同级取时间最新;实测用 `22>01>03>00`, tie → 最新 check_time。

## 变更计数与落盘
- 变更计数只算真实值差;别把 `src`(来源文件名)计入——每轮全量重读同一批文件会把 src 当变化,报数万假变更(实测 81k→12k 降噪)。
- `if changed: 落盘` 模式 → 新增字段必须同时进变更判定,否则字段回填只更新内存、文件不持久化。

## 时区:与上游时间比较统一换算到上游时区
- 主服常为 UTC 而上游(平台)为北京时间:漏 +8 表现为"状态/时间窗切换晚 8 小时",像功能不生效。
- 落点必须齐全: 状态机/直播标记/分类导出等所有拿上游时间比较的位置,漏一处就有一处慢 8h。
- 主服 UTC 验证: `date` + `/etc/timezone`;修法 `(datetime.utcnow() + timedelta(hours=8))`(与服务器 TZ 设置无关,稳)。

## 回写类功能:首轮全量 + flag,其后变更清单
- 首轮全量扫描(flag 文件标记完成),其后仅处理变更清单。
- 变更检测函数应返回"完整变更清单"供回写使用;落盘通知文件保持 top-N 截断——两份用途别混(截断版给外发附推,完整版给回写)。

## 部署后验证:等"下一轮"落地(daemon 逐轮 spawn 时)
- daemon 每轮 spawn 新进程(改文件即部署,无需重启)→ 验证不能部署完立刻跑,可能正跑着旧代码的轮次。
- 正确姿势: 记录部署时间 → 轮询日志轮次开始行(如"开始合并流程")时间戳 > 部署时间 → 等该轮"完成:"行出现 → 才跑核实脚本。
- 先取证再改(本类任务用户铁律): 改前 read-only 检查脚本出 before 数据,改后同口径复测(before/after 对比表)。

## 批量补丁脚本模式(实测好用)
- 本地一次性脚本: 逐条 `assert s.count(old)==1` + 替换 + 备份(.bak_版本) + `py_compile`,全绿才部署;部署 = put /tmp → 远程 py_compile → `cp` 备份 → `mv` 就位。
