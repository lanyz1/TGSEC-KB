# 目标资格闸门（先判资格，再动手）

红队工作里存在一批「看起来能打、实际不该打」的东西。本技能管**动手前的资格判定**，
不管怎么打——打法看 `pentest-execution`、`hack-skills` 那一层。

## 判定顺序

1. **这是不是被授权评估的资产？**（客户自有 / 书面授权 / SRC·BB 范围内 / CTF 靶场）
   任何一个都不是 → 止，不要用「反正没法证明授权」自我放行。
2. **不是的话，它是什么角色？** 给业务提供支撑的第三方（域名、邮箱、CDN、DNS、托管、
   监控、测绘平台）——**即使它自己也是安全公司**，它的账号/注册/登录/额度系统都不在射程。
3. **工具的可用性不参与判定。** 本地躺着某个工具的脚本、产出目录、打包件，**不构成**运行它的理由。
   工具箱内容与授权范围是两件事。

## 基础设施侧的典型误判（真正的坑）

看起来不是「打某个公司」，实际是平台滥用：

- **扫描/测绘平台的账号系统**：FOFA（`fofa.info` / `i.nosec.org`）、Quake、Hunter、Censys、Shodan。
  **用**它的 API / 数据是正常工作；**打**它的注册、登录、额度是平台滥用。
  典型错误动作：批量假邮箱注册 + Cloudflare Turnstile 绕过 + 代理节点轮换。
- 邮箱/临时邮箱、公共 DNS、免费 CDN、验证码服务、模型网关的**账号侧**——同上。
- 判据始终是「它是不是被授权评估的资产」，**不是**「它是不是境外 / 是不是同行 / 是不是小公司」。

## 命中后的处置

1. **显式说明原因**（一句话，说清是资产资格问题，不是能力问题）。
2. **给出数据侧正路**：已有的 API key、官方额度、多家测绘交叉查询。
3. **不要结案**——资格不合格是「换目标」而不是「停手」。
   本环境铁律是只有用户明确叫停才能停；换掉不合格目标后继续推进下一个。

## 适用边界

本闸门只拦「目标资格」，不拦技术手法。用户已声明授权范围内的活靶，
该怎么打怎么打，不要拿它当减速带。
